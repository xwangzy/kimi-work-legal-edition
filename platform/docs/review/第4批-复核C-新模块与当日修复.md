## 发现摘要

| 编号 | 级别 | 发现 |
|---|---|---|
| R01 | 重要 | 控制面写盘失败时，错误分支里再次写盘再次抛错，成为未处理的 Promise 拒绝，进程退出、客户端收不到 500；内存状态已改而磁盘未改。磁盘满时第一个设备请求（记 nonce）就会触发崩溃循环 |
| R02 | 重要 | 评测器按写法计数并按比例分摊，不看位置：姓名同时嵌在未标注的字号里时，留在输出里的姓名会被记成“已替换、未泄露”，系统性低估人级泄露率 |
| R03 | 一般 | 诊断包兜底偏弱：版本形态正则带 `/i`，能放行 `1.0-ZhangWei`；自证比对区分大小写且不做折叠；任务目标与文件名不在比对表里；对 JSON 文本替换用户目录的做法在 Windows 上不生效 |
| R04 | 一般 | 改名之后不对目录 fsync，Windows 改名也不是直写：掉电后可能回到旧文件，已经回了 200 的吊销会回滚 |
| R05 | 一般 | 输出检查只看 `delta.content`：推理文字、工具调用参数（开放任务的主要产出）、只用 `\r` 的行尾、超长单行都不检查 |
| R06 | 一般 | 内容安全“类别:次数”按请求、带匿名事项编号与席位留存在中软，《中软看得到什么》没有写 |
| R07 | 一般 | 自助区间在比例为 0 或 1、样本少时退化为零宽；不同来源被合并成一个数 |
| R08 | 一般 | 误替换判定过宽，吞掉上下文的过度替换看不到 |
| R09 | 一般 | 恢复导入后的重启闩锁只拦 API，队列照常启动 Agent 任务：尚无工作区密钥的事项会用即将作废的临时公钥包裹第 1 代工作区密钥，重启后该事项的 Agent 永久无法启动 |
| R10 | 一般 | 留档证书回退没有时间边界：被替换下来的私钥泄露后，仍能签出被判为有效的新见证 |
| R11 | 一般 | “立即重启安装”先拉起安装程序、后关内核，安装程序 1–3 秒后就强制结束应用；Agent 宿主的 close 不等进程退出 |
| R12 | 建议 | 见证链同步校验约 34 万行就会挡住内核主线程 30 秒以上，子进程收不到心跳全部退出 |
| R13 | 建议 | 不可见字符过滤不全（U+034F、U+180E、U+202E、U+2066、U+FE0F、标签字符等插在词中间即可躲过） |
| R14 | 建议 | 控制面持久化工程缺口：每个签名请求（nonce）都整份重写；只有一份文件；未配密钥静默写明文；整体换成旧版本挡不住；没有启动入口接入持久化 |
| R15 | 建议 | 先启动内核、后台再做全量摘要核验，同样大小的被改依赖可能在核验完成前被装载；交叉构建只核对缓存版本号、不复核内容 |
| R16 | 建议 | 更新安装前复核与拉起之间仍有毫秒级窗口（按机器安装时是提权路径）；下载后再取清单遇网络失败会丢弃整包 |

其余核验成立：诊断包当前白名单字段没有找到泄露通道；Aho-Corasick 与朴素算法 3,000 组随机对拍零差异；`OutputTextTap` 任意字节边界切开都能还原；A12、A03、A05–A08、A16、A19 已关闭。
