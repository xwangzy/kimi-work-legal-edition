### 重要

**S8B-01 评测页类别按钮在深色下是浅底浅字（≈ 1.03:1），门禁的豁免规则正好把它放过**
- 位置：`apps/desktop/src/pages/RecallEval.tsx:243`（`className={\`ev-cat ev-tone-${c.tone}\`}`）；`styles.css:639`（`.ev-cat` 设 `--bg-surface`，不设文字色）、`:645-650`（`.ev-tone-*` 设纸面标注底色，同特异性、写在后面，覆盖 `.ev-cat` 的底色）；`test/style-tokens.test.ts:63` 对 `.ev-tone` 整类豁免。
- 问题：类别按钮位于 `.ev-catbar`（`--bg-main`），文字色继承正文 `--text-primary`。深色下按钮底是纸面浅粉/浅橙/浅蓝等（两套相同），字是 `#ecebe9`，几乎看不见。门禁注释说“标注只出现在纸面容器内”，但同一组类名也被用在纸面外的按钮上。
- 影响：深色（含“跟随系统”且系统为深色的默认用户）下，评测标注页选类别的按钮不可读；与文档“纸面区域一律同时写纸面文字色”的声明不符。
- 建议：`.ev-tone-*` 各条同时写 `color: var(--text-on-paper)`（或单写 `.ev-cat[class*="ev-tone-"] { color: var(--text-on-paper) }`）；门禁去掉 `.ev-tone` 豁免，只保留 `::after`。
- 补测：门禁改为“凡背景用纸面类令牌的规则，必须同规则写 `--text-on-paper`，或其选择器只能出现在 `.wb-doc`/`.ev-text` 等纸面容器后代中”；另加一条静态检查：TSX 里出现 `ev-tone-` 的元素必须位于纸面容器内或类名带 `ev-cat`（且 `.ev-cat` 写了纸面字色）。

**S8B-02 审查原文里的灰色提示字在深色下 2.41:1——门禁只查纸面容器本身，不查后代覆盖文字色**
- 位置：`ReviewWorkbench.tsx:262-263`（`.wb-doc` 内的 `<p className="muted">`：“正在载入合同原文…”与“这些意见没有关联到具体合同…”）；`styles.css:70`（`.muted` 用 `--text-secondary`）、`:421`。
- 问题：`.wb-doc` 设了纸面字色，但后代 `.muted` 把颜色改回语义层 `--text-secondary`，深色值 `#a9a59f` 落在纸面 `#fffdf9` 上只有 2.41:1。每次打开审查工作台载入原文时都会出现；未关联合同的意见集也一直显示。
- 影响：深色下审查工作台首屏的状态提示不可读；违背 V-10“文书区保持纸面白”的前提（纸面上的字必须是纸面字色）。
- 建议：在纸面令牌里增加 `--text-on-paper-muted`（两套相同，浅色值约 `#5c5850`），加 `.wb-doc .muted, .ev-text .muted { color: var(--text-on-paper-muted) }`；或把两句提示移出 `.wb-doc`。
- 补测：`tokens.test.ts` 的 `TEXT_PAIRS` 增加 `--text-on-paper-muted / --bg-paper`；`style-tokens.test.ts` 增加“纸面容器后代规则（选择器以 `.wb-doc `、`.ev-text `、`.vis-sent `、`.ev-quote ` 开头）不得使用非纸面文字令牌”，并人工列出纸面容器内会出现的通用类（`.muted` 等）逐一断言有纸面覆盖。按 Y4 §7.3 补一次深色 axe-core 对比度扫描（工作台载入态、评测标注态）。

**S8B-03 “在线更新”两种状态不如实：检查失败没有任何反馈；本机安装出错被说成“连不上更新服务”**
- 位置：`Connections.tsx:251-257`（`.catch(() => setResults([]))`）、`:260`；内核 `packages/kernel/src/services/content-updates.ts:259`（非 `Reject` 的异常一律记为 `outcome: "unreachable", reason: "internal"`）；`content-labels.ts` 的 `unreachable` 文案。
- 问题：① 调用 `content.check` 失败时 `results = []`，`lines` 为空，连原先显示的“最近一次检查”也被清空，按钮恢复成“检查更新”——律师点了没有任何结果。② 落位阶段的本机错误（磁盘满、写入失败、SQLite 错误、增量应用异常）走 `catch` 变成 `unreachable`，界面显示“暂时连不上更新服务……（稍后自动再试）”，把本机问题说成网络问题，管理员排查方向会错。
- 影响：状态不如实（本条为任务重点核对项）；可能让律所 IT 去查网络而非磁盘。
- 建议：① 失败时显示一行“这次没有检查成功，继续用当前版本，可稍后再试”，并保留上次结果；② 内核增加 `outcome: "failed"`（本机出错），文案“这次更新没有装上，继续用当前版本；如反复出现请联系管理员”，`unreachable` 只留给网络/HTTP。
- 补测：`batch8-lib.test.ts` 增 `failed` 文案；`content-updates.test.ts` 增“落位阶段抛错 → outcome 为 failed 而非 unreachable、当前版本不变”；界面纯函数抽出“检查失败时的行”并单测。

**S8B-07 V-4 两类小标签只落地了一半；交互元素悬停/按下态不全**
- 位置与问题：
  - 文档与 `styles.css:5` 声称 `.alias-chip`“有悬停与按下态”，实际 `.alias-chip`（`:316-317`，`Parties.tsx:64-81` 是 `<span>` 内放按钮）没有任何悬停/按下样式；

**S8B-08 门禁容易绕过，且测试名比实际检查宽**
- 位置：`style-tokens.test.ts:37-41`、`:45`、`:79-93`；`tokens.test.ts:108`。
- 可绕过的写法（当前代码里都没有，但都能通过门禁）：
  1. 具名色只列 20 个，`crimson`、`tomato`、`whitesmoke`、`lightgray`、`darkgray`、`ivory`、`beige`、`cyan`、`magenta` 等都不拦；`lightgray`/`whitesmoke` 这类复合名因为 `\b` 不成立，连 `gray`/`white` 也匹配不到；
  2. 新式颜色函数 `oklch()`、`lab()`、`lch()`、`hwb()`、`color()`、`color-mix()` 不拦；
  3. TSX 只拦“引号内的十六进制或 `rgba(`”：`style={{ color: "red" }}`、`hsl(`、`fontSize: 11` 都不拦；
  4. `src/` 下新增另一个 `.css` 文件写 `color: #fff`（没有引号）不拦——非 styles.css 的 CSS 只走 TSX 那条正则；
  5. 去注释用 `\/\/[^\n]*`，同一行出现 `https://` 时其后的内容被一并去掉；
  6. `safe-preview.ts` 整文件豁免，`electron/main.cjs` 不在扫描范围（两处都有手抄的令牌值，见 S8B-11）；
  7. 字号允许任意 `em`/`%`：`.token-chip` 的 `0.92em` 在 16px 下是 14.72px、13px 下是 11.96px，与 V-1“不用半像素”相悖；
  8. `opacity`、`filter: brightness()`（`.wb-mark.mark-hover`，`:713`）会改变实际对比度，门禁看不到。

### 建议

**S8B-14 小处视觉**：图标栏计数徽标 12px 配 15px 行高、右上角绝对定位，两位数时更易压住图标（`styles.css:56`、`:371`），可改 `top:0; right:-2px; line-height:16px` 或改用小圆点；`.token-chip` 的 `0.92em` 改为显式 `--fs-sm`/`--fs-base`。

**S8B-15 纸面区域的滚动条与原生控件**：根上 `color-scheme: dark` 会让 `.wb-doc`、`.ev-text`（`overflow:auto`）出现深色滚动条压在纸面白上；建议纸面容器加 `color-scheme: light`。

**S8B-16 令牌借用与语义错位（不影响当前取值，影响日后改色）**：`.dot-off` 用 `--border-hover` 作填充（`:50`）；`.vis-local/.vis-transit/.vis-stored/.vis-direct` 色条用 `*-text` 而非 `*-solid`（`:676-678`、`:714`）；骨架屏用 `--status-neutral-bg`（`:701`）；`.tag-demo`、`.pill-blue` 借“法规效力”的 `--status-amended-bg`，`.pill-*`、`.tag-beta`、`.todo-strip`、`.suspect-mark` 借“风险分级”的 `--risk-*-bg`；计数徽标用文字令牌 `--accent-text` 当底色（`:39`）；`tr.row-link:hover` 用 `--bg-sidebar`，浅色 1.04:1、深色 1.05:1 几乎看不出悬停（`:186`），应改 `--bg-hover`。建议状态类一律直接用 `--status-*`，组件层令牌只给其本义组件用。

**S8B-17 令牌命名与 Y4 不一致**：Y4 §6.3 的 `--text-tertiary` 是最弱一级（`#8a8a8a`，只用于 ≥ 18px 或装饰），实现中 `--text-tertiary #555` 比 `--text-secondary #666` 更深，层级为 primary > strong > tertiary > secondary，按名字选用容易选反；建议改名（如 `--text-label`）或在 tokens.css 写明顺序，并在偏离登记表记一笔。`--focus-glow` 已定义但没有任何样式使用（V-9 的输入框聚焦光晕未落地），要么用上，要么删去。

**S8B-18 打印浅色的兜底与外观偏好的单测**：打印只靠 `beforeprint` 事件；建议把深色块包进 `@media screen { :root[data-theme="dark"] {…} }`，这样任何打印路径（含将来主进程 `printToPDF`）都按浅色。`applyUiTheme` 目前只测了 `resolveTheme` 纯函数，建议用假 `window`/`document` 补测：持久化（跟随系统删键）、系统切换只在“跟随系统”时生效、`beforeprint` 置浅、`afterprint` 还原到显式选择。

**S8B-19 外观设置的可用性**：“跟随系统”选中时不显示当前实际明暗，建议“跟随系统（现在是深色）”；`role="radiogroup"` 缺方向键切换与 roving `tabIndex`，与字号单选一并补。

## 总体判断

令牌三层、字号 7 级、圆角 5 级的收敛与 Y4 V-1～V-3 一致，styles.css 的颜色映射逐条核对基本正确，并顺带修掉了浅色下的既有对比度缺口；深色令牌本身在门禁列出的组合上全部达标，打印、iframe 预览、驻留清单登记都如实落地。主要问题集中在“门禁之外”：纸面规则只查容器不查后代、又对 `.ev-tone` 整类豁免，导致审查原文提示字（2.41:1）和评测页类别按钮（≈ 1.03:1）在深色下不可读；V-4 的 Chip 一侧只落地一半且文档声明超出实际；“在线更新”在检查失败与本机安装出错两种情况下状态不如实。没有阻断项。建议 S8B-01～03 修复并补测后再把深色模式作为“跟随系统”的默认行为对外发布；S8B-04～13 可随第 9 批收口。

统计：阻断 0 · 重要 3 · 一般 10 · 建议 6。
