## 4. 问题清单

### S5-A01（阻断）对外口径与检索“原文放行”行为不一致

- **方案出处**：02 §12“说”列与“中软看得到什么·启用联网检索”行；03 §8.4、§8.5；06 T20（“‘中软看得到什么’每一行与抓包、日志抽查一致”）。
  同篇 02 §8.2（L2 联网检索“含当事人实体须确认或泛化”）、§8.3（“请律师确认”）允许经确认后放行——方案内部本就存在张力。
- **行为**：W1 新增“本次允许 = 原文放行”，保留明文机构当事人名称发往中软检索服务——
  `packages/egress-gate/src/search-guard.ts:90-99`；`packages/egress-gate/src/server.ts:455-463`；`packages/kernel/src/services/interaction-cards.ts:111-113`；`apps/desktop/src/components/Cards.tsx:101-103`。
- **文字**（均称检索“只发出令牌化并去除已知当事人名称的查询”或等义表述）：
  - `apps/desktop/src/pages/Connections.tsx:174-179`（“中软看得到什么·启用联网检索”：中软看到“令牌化并去除已知当事人名称的查询原文”）、`:209-212`（页首说明）、`:52`（数据与连接页）；
  - `packages/kernel/src/api/index.ts:571`（告知函：“联网检索只发出令牌化并去除已知当事人名称的查询；含当事人名称的检索须经办律师逐次确认”——前后两句已互相矛盾）；
  - `packages/kernel/src/api/index.ts:657`（估价预览：“联网检索只发出令牌化并去除当事人名称的查询（含当事人须你确认）”）；
  - `packages/kernel/src/services/egress-summary.ts:116-119`（数据去向一句话把原文放行也计为“令牌化查询”，只写“经你确认”，不写“含机构当事人名称”）。
- **证据**：`packages/kernel/test/w1.test.ts:75,85,88`——“本次允许（original）”后检索服务实际收到含“甲科技有限公司”（事项相对方）的查询，本次运行通过；
  进度文档 `docs/v9-开发计划与进度.md:244-245` 亦记“‘本次允许’发出原文（机构名称保留）”。
- **影响**：“中软看得到什么”页按设计可截图给客户；告知函是“委托/保密授权”依据的来源。两者对检索的描述与实际出站不符，T20 必然不通过，
  依据记录建立在不实告知之上。
- **建议处置**：
  1. 统一改写为“默认只发出令牌化并去除已知当事人名称的查询；经办律师逐条确认后，可按原文发出（保留机构当事人名称；已识别的自然人姓名与证件号不发出）”，
     同步改 Connections 三处、告知函模板（升模板版本号）、估价预览；
  2. 数据去向一句话单列“其中 N 条经你确认按原文发出（含机构当事人名称）”，`summarizeEgress` 增加 `confirmed_original` 计数；
  3. 请方案负责人在 02 §12 对齐 §8.2/§8.3，并在偏离登记写明本处口径；
  4. 补测试：以原文放行场景断言三处文字与告知函含“经确认可含机构当事人名称”，并断言去向汇总区分原文放行条数（T20 对应）。

### S5-A02（重要）检索卡“本任务内允许”按原文放行本任务内后续全部含当事人检索（未登记）

- **方案出处**：02 §8.3 检索查询行（“L2 可在任务开始时一次性批准‘本任务泛化后放行’；L3 逐条确认”）；02 §9.5、03 §8.2 通用按钮；告知函承诺“逐次确认”（`api/index.ts:571`）。
- **代码位置**：`apps/desktop/src/components/Cards.tsx:104-108`（“本任务内允许”发送 `variant: "original"`）；`packages/kernel/src/api/w1.ts:83-101`（task 范围 `digest=null`，变体取界面所送）；
  `packages/kernel/src/services/egress-approvals.ts:39,154-159`（task 凭据在同一运行、同一用途与目的地对任意查询复用，最长 8 小时）；`packages/egress-gate/src/server.ts:460`（按凭据变体放行）；
  `packages/kap-host/src/policy.ts:224-230,386-392`（`search_entity_requires_confirmation` 不在逐次清单，宿主同时按任务放行、不再出卡）；`packages/kap-host/src/runtime.ts:727-728`。
- **证据**：代码路径闭合；没有端到端用例（`w1.test.ts:153-158` 只测 `variant: generalized` 的任务凭据复用）。
- **影响**：律师在第一张检索卡点“本任务内允许”后，本运行内所有含任一机构当事人（含客户自身）名称的后续检索都按原文发出且不再询问，
  超出 §8.3 的任务级授权（只允许“泛化后放行”），与告知函“逐次确认”矛盾；按钮提示只写“不跨任务、不跨事项”，没有说明放行的是原文。
- **建议处置**：检索卡的“本任务内允许”只签发 `generalized` 变体（或检索卡不提供任务范围），原文放行只保留“本次”；如产品决定保留，须登记偏离、
  在卡片与告知函写明并在去向卡标出。补测试：L2 检索卡选“本任务内允许”后，同一运行再发含另一当事人的检索，断言发出的是泛化查询（或重新出卡）；跨运行不复用。

### S5-A03（重要）确认卡绝对化承诺“自然人姓名与证件、账号永远不会发出”

- **方案出处**：02 §12 禁用词（“从来没有”“绝对”同类）；02 §8.3“漏识别的姓名仍会出站”；02 §9.2 ④“挡不住…词典与识别漏掉的姓名”。
- **代码位置**：`packages/kernel/src/services/interaction-cards.ts:118`；对照 `apps/desktop/src/components/Parties.tsx:47-50`（同一界面写“漏识别的姓名仍会出站”）。
- **证据**：`search-guard.ts:85-99` 只替换词典命中与规则识别的人名，未识别的人名不会被替换；同一产品两处说法互相矛盾。

### 8.3 新问题

#### S5-A15（阻断）拒绝记录 + 私有端点时，联网检索与网页抓取仍被放行；与事项头“不联网”、告知函回执和方案 L3b 行不符（静态推断）

- **方案出处**：02 §8.1 L3b 定义（“当事人书面要求不上云或不用 AI”）；02 §8.2 L3b 行（推理（私有）✓“当事人只拒绝云端时”；**联网检索 ✗**、法源查询 ✗、网页抓取 ○）；02 §13 第 3 条“L3b 零出站”。
- **代码位置**：`packages/kernel/src/egress/gate-host.ts:59-63`——`consent_status = refused` 且端点为私有时，`basisCompleteOf` 返回齐备，旧事项（未记录四项）一律返回齐备；
  闸门 `gate-host.ts:121` 与宿主 `kernel/src/index.ts:450` 都用这个值作为 `basisComplete`；检索只在 L3b 数据级别时拒绝（`kap-host/src/policy.ts:325`、`egress-gate/src/search-guard.ts:52`），拒绝记录的事项数据级别是 L2，所以宿主 T4 与闸门 `/search`（`server.ts:486-492`）都放行，抓取同理（`server.ts:552`）。
- **界面与对外文字**：事项头写“当事人拒绝云端处理（记录）：本事项不调用云端模型、不联网…”（`MatterHeader.tsx:65`）；告知函回执选项写“拒绝云端处理（仅本机能力或本所私有模型）”（`api/index.ts:613`）；
  而估价预览对这类事项的开放任务会写“…联网检索默认只发出…（确认后可按原文发出，保留机构当事人名称）”（`api/index.ts:696-702`）。律师在这类事项中还可以对含当事人的检索点“本次允许”，把机构当事人名称发往中软检索服务。
- **与处置的关系**：处置前，旧拒绝记录（未记录四项）一律不齐备，闸门上推理、检索、抓取全部拒绝；本轮“拒绝记录优先、只允许私有端点”把这类事项在私有端点下改为齐备，推理按方案放行，但检索与抓取一并放开——属本轮引入的放宽。
  `matters.test.ts:76` 断言这类事项 `basis_complete = true`，没有任何用例检查其检索。
- **可达性**：W1 界面不能新建拒绝记录，只能清除；受影响的是旧事项与经业务 API 写入的记录。但对“拒绝云端、改用私有模型”这一类客户，这正是预期的主要路径。
- **建议处置**：把拒绝记录按 L3b 处理，二选一——(a) 拒绝记录统一迁移为 L3b（`confidentiality = strict`），复用 L3b 已有的全部强制；(b) 给闸门与宿主增加“拒绝云端”标志：检索、法源一律拒绝，抓取按 L3b 行“○”须确认。
  同时改估价预览（这类事项不写检索），并给“拒绝云端处理”回执提供记录入口（落为 L3b）。
  补测试：拒绝记录 + 私有端点的事项，开放任务的 WebSearch 被宿主与闸门拒绝，估价预览不含检索说明。

#### S5-A16（一般）四项依据“不适用”的约束可通过改端点绕过（业务 API）

- **代码位置**：`packages/kernel/src/api/index.ts:426`——只在提交 basis 时调用 `basisFrom`；`:453` 单独改 `model_endpoint` 时不复核已存的四项。
