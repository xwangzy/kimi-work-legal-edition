依据：方案 v5.0 第 4 篇 §16.2（周 5–6 演示脚本与录像；标准演示用例）。每一镜注明**证据锚点**（自动化测试 / `npm run demo:e2e` 输出），录像是人工工作（本文不宣称已完成）。

话术红线（第 1 篇 §11.7）：不使用「零风险」「法院认可」「绝对安全」等表述；演示材料全部为合成文本并标注「示例」。

```bash
npm run demo:e2e   # 自动构建法规库与签名 profile 后跑 ①–⑦ 核心链并打印证据 JSON，退出码非零即失败
```

输出证据：核验拦截 JSON（第三十八条 → 改引第四十一条、`where=本机（离线核验）`）、时点对照（2026-08-31 拦截 0 条）、去向卡摘要（唯一记录 `mock_local / （本机，未外发）`）、签发证明包字段、改一字节 invalid/还原 valid、`audit.verifyChain` ok。

## 分镜

### 镜 1 安装与首日激活（目标 ≤ 30 分钟）

- 画面：安装包双击 → 首次启动 → 创建律所/本人身份 → 新建示例事项「股权转让（受让方）（示例）」。
- 讲述要点：全部数据在本机工作区；未配置真实 MaaS 时为离线 mock 提供方并如实标识。
- 证据锚点：`packages/kernel/test/e2e.test.ts`（事项创建字段与端点策略）；`npm run demo:e2e` 镜 ① 输出。
- 人工部分：Windows 安装包形态与首日激活计时属探针 13（需 Windows），本脚本不宣称已验收。

### 镜 2 拖入合同 → 计划卡 → 执行

- 画面：拖入《股权转让协议-示例.txt》→ 估价卡（点数与假设）→ 开始执行 → 事件流（计划/材料载入/核验/模型/草稿）逐条出现；本机步骤与模型推理分开显示，执行位置徽标「本机 / Kimi（经中软 MaaS）」。
- 证据锚点：`e2e.test.ts`（事件序列 `run.started→plan.created→materials.loaded→citations.verified→model.completed→artifact.drafted→run.succeeded`）；`demo:e2e` 镜 ③。
- 备注：mock 演示链路的模型步为「本机模拟」徽标；真实 MaaS 链路属探针 10 验收后启用。

### 镜 3 审阅（修订卡键盘流、引用回链）

- 画面：复核台打开草稿 → 键盘逐条过修订卡（接受/拒绝）→ 点击引用跳回原文锚点。
- 证据锚点：`packages/kernel/test/review.test.ts`（提交复核 → 完整性单 → hash 绑定批准 → 版本失效 → 外发门禁 → 待我处理）；`packages/kernel/test/tools.test.ts`（锚点/引用工具层）。
- 人工部分：桌面端键盘流与回链的界面呈现属 W1 界面工作，内核语义已自动化。

### 镜 4 断网法条核验（标准演示用例核心）

- 画面：断开网络 → 对引用「《律师法》第三十八条」的保密条款执行核验 → 拦截卡：该法 2026-09-01 修正施行，所引条号现为第四十一条，提示改引 → 把适用时点调到 2026-08-31 → 同一引用核验通过（当时有效）。
- 证据锚点：`demo:e2e` 镜 ③④（拦截 JSON 与时点对照）；`e2e.test.ts`（`where=本机（离线核验）`）；`tools.test.ts`「同一引用在修正施行前（2026-08-31）适用旧版，核验通过」。
- 讲述要点：法规库随包本地，核验不依赖网络；「断网」在机跑版以零外联计数器佐证。

### 镜 5 数据去向卡

- 画面：打开数据去向卡 → mock 演示链路只有一条「（本机，未外发）」记录；切到 IM 支线后可见 `im_inbound/im_outbound` 记录（发送对象已哈希化）。
- 证据锚点：`demo:e2e` 镜 ⑤；`e2e.test.ts`（mock 链路唯一 `mock_local` 记录）；`packages/kernel/test/im.test.ts`（IM 流转入去向记录）；`packages/kernel/test/egress.test.ts`（探针 4 v0：化名拦截/拒绝云端/端点未配置不静默降级）。

### 镜 6 签发（设备签名、完整性单、离线验证）

- 画面：复核通过 → 签发（设备签名）→ 出具完整性单与证明包 → 离线验证通过 → 后台改成果一个字节 → 验证转 invalid → 还原 → valid。
- 证据锚点：`demo:e2e` 镜 ⑥；`packages/kernel/test/approvals-sign.test.ts`（证明包离线验签、篡改 invalid、签发后吊销 `revoked_after_signing`）；`packages/kernel/test/keys-chain.test.ts`（链篡改可检出 `first_bad_seq`）。

### 镜 7 IM 支线（模拟器）

- 画面：从 IM 模拟器把合同转给机器人 → 节点回卡片（事项候选只列已授权、文案脱敏：序号+短 ID，无客户名/标题）→ 选事项 → 审查完成回执 → 合伙人 IM 确认（节点见证 `im_witnessed`，较低保证等级，verify 附 `assurance_note`）→ 演示门禁：法院版/对外版只认 `device_signature`，`im_witnessed` 一律 409。
- 证据锚点：`packages/kernel/test/im.test.ts`（探针 14 v0 全链；2 秒硬限；群转发不扩权；外发门禁 409）。
- 讲述要点：模拟器不是平台；真实平台联调与凭据属部署工作（README 阶段 6a 边界声明）。

### 镜 8 所内节点支线

- 画面：桌面授权事项到所内节点 → 材料经共享文件夹同步 → 「转到所内节点」转交执行 → 节点完成成果同步回桌面 → 节点管理控制台（只读：/status、/matters 脱敏、/audit/tail；POST 一律 405）。
- 证据锚点：`packages/kernel/test/firm-node.test.ts`（同步→转交→回传全链；租约并发恰好 1 胜）；`packages/kernel/test/node-authz.test.ts`（strict 拒绝授权、撤权即不可解）；`packages/kernel/test/sync.test.ts`（撤权设备旧纪元段拒收、冲突副本命名告警）。
