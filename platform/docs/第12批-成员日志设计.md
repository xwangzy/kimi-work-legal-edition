# 第 12 批：带因果链的成员日志（设计）

> 用户 10-16 拍板：第 11 批收口，第 12 批专做带因果链的成员日志。本文是实现依据；进度与复核处置记在 `v9-开发计划与进度.md`。

## 1. 要解决的残余（第 11 批登记）

| 残余 | 第 11 批的缓解 | 本批做法 |
|---|---|---|
| R-a 签名不带新鲜度：转发者可给出某成员行的旧版本；被移出者用同号轮换塞密钥 | 告警 + 暂停发出 | 成员关系不再是“每行较新者胜”，而是全部事件按因果合并；旧事件只是链上的祖先，不能盖过后代 |
| R-b 交接后原负责人设备被吊销时离线的成员认不出新负责人 | `owner_unverifiable` 告警 + 暂停 + 找客服 | 吊销按链上位置判断：在用负责人设备得知吊销后自动写一条“吊销标记”事件，标记之前（祖先）的事件照收 |
| R-c 升级前同步过、作者设备已吊销或再没导出过的成员行没有签名 | 无 | 存量事项由在册负责人重新签署一次“锚定”事件作为链的起点 |
| R-d 同号纪元并发轮换不能自动解开 | 告警 + 负责人手工再轮换 | 纪元由链上事件声明（纪元号 + 签发者 + 密钥指纹 + 各包裹摘要）；分叉按链上全序确定胜者，输家自动再轮换 |
| R-e 两位共同负责人并发轮换后其中一位的移出可能丢失 | 如实登记 | 移出是成员事件（并发时移出优先），合并后当前纪元的包裹若仍含已移出成员的设备，负责人自动轮换，其他设备暂停发出 |
| R-f 吊销没有时间依据 | 如实登记 | 以链上位置代替时间（吊销标记）；标记写出之前的窗口仍是残余 |
| D-94 控制成员只能是第一个登记者 | 找中软客服 | 控制成员移交：链上 `control` 事件 + 中继新接口（只有当前控制成员可调用） |

不在本批：控制面见证创世与成员日志（G1）；共享文件夹介质上首个创世的抢先投递（G1，既有残余）。

## 2. 事件

每个团队事项一条有向无环图（DAG）：每个事件引用作者写它时本机的“链头”（没有后代的有效事件），按引用形成因果关系。

```
payload = {
  v: "kwl-member-event/1", tenant, matter_id,
  kind: "genesis" | "anchor" | "member" | "rekey" | "wrap" | "mark" | "control",
  prev: [事件编号…]（升序；起点为空），
  lamport: 起点 1，其余 = max(前序的 lamport) + 1（按事项合并的逻辑时钟），
  author_device, at（ISO，仅供展示，不参与判定），
  body: {…}
}
event_id = SHA-256(canonicalJson(payload))（十六进制）
sig = 作者设备签名(UTF-8("kwl-member-event/1\n" + event_id))
```

随事件存作者设备证书（律所根签发，`deviceId = author_device`），作者成员取证书里的 `memberId`。

| kind | body | 作用 |
|---|---|---|
| genesis | `{creator, members:[{user, role:"owner"}], key}` | 新建团队事项的起点；作者成员须等于 `creator` |
| anchor | `{members:[{user, role, removed}], key}` | 存量事项的起点：在册负责人把现有成员关系与当前纪元重新签署一次 |
| member | `{user, role \| null, key?, wraps?}` | 加人、改角色（`role`）、移出（`role = null`，通常带 `key` 轮换） |
| rekey | `{key, reason}` | 纯轮换（恢复演练轮换、分叉后的再轮换、移出遗留的补轮换） |
| wrap | `{wraps}` | 给已有成员的新设备、或节点补当前纪元包裹 |
| mark | `{device}` | 吊销标记：链上此处起，该设备写的、不在本事件祖先里的事件不收 |
| control | `{to}` | 中继控制成员移交（D-94），作者须是当前控制成员（中继另行核对） |

`key = {epoch, fp, wraps}`：声明一个新纪元。`fp = SHA-256("kwl-matter-key-fp/1" ‖ 事项密钥)` 前 32 位十六进制；`wraps = {设备编号或 "recovery": SHA-256(包裹密文)}`。`wraps = {epoch, wraps}`：在已声明的纪元上追加包裹。

## 3. 核验（接收方，确定性，与到达顺序无关）

本机存下所有签名与证书核验通过的事件（`member_events`），每次变化后对该事项重算“有效集”：

1. **结构**：前序都在本机且都有效；lamport 正确；`tenant/matter_id` 对得上。缺前序的事件待定（`missing_parents`）。
2. **起点**：每个事项只有一个起点。本机已有起点时，不同的起点一律不采用、同一作者的也不换（复核 S12A-01）；按本机投影作者是在册负责人的另一个起点记 `root_conflict`；“本机重新引导该事项”可人工放弃本机起点。首同步与重新引导只从**本段带来的**起点里挑；非首同步（含重新引导）时起点作者须是本机成员行里在册的负责人。
   - genesis：作者成员 = `creator`；本机已有事项行时另须 = 事项行 `created_by`。
   - anchor：作者在 anchor 自己列出的成员里是负责人；本机已有该事项（旧规则下的成员行）时，作者另须是本机旧成员行里的在册负责人（不满足即待定，旧规则下本机之后可能认出他）。
   - 本机还没有该事项（首同步）：起点规则同上，另加介质规则——中继只从控制成员签发的段引导（沿用），共享文件夹沿用“首个有效起点”（G1 残余）。
3. **作者资格**：除起点外，作者成员在该事件的**因果过去**（全部祖先按第 4 节投影）里是未移出的负责人。按因果过去而不是按到达顺序判。
4. **吊销按链上位置**：作者设备在本机已知被吊销（设备行或吊销墓碑）时：本机在吊销时刻之前收下的照收（复核 S12B-06）；之后才收到的，只有在是某个“在用设备写的有效事件”的祖先时才有效（被在用的负责人设备认可过）；否则：链上已有给该设备的有效 `mark` → 拒收，没有 → 待定。待定只用于暂停发出，不改本机成员行。
   在用负责人设备在**任何成员链写入之前**先补写到期的 `mark`：把该设备写的、本机在**吊销时刻之前**收下的事件按在用对待、取此刻的链头——这些事件由标记固定；吊销时刻之后才收到的不固定。判断本机是否负责人也按“吊销之前收下的仍有效”（交接给本机的那条事件可能正是被吊销设备写的）。
5. **移出优先于被移出者的并发操作**（实现中补充，见第 11 节）：按第 1～4 步的投影，最终不是负责人的成员，他写的、与降级或移出他的事件**并发**（互不为祖先）的事件拒收（`author_demoted_concurrently`），后代随之。迭代到不动点（每轮只用上一轮存活的事件找降级，复核 S12B-01），不收敛时取保守结果：全部降级都成立、被降级者与之并发的其他事件拒收（复核 S12B-19）。例外（报复）：把“降级他的那个人”降为非负责人，或移出他（只在对方于该事件因果过去里已不是负责人时）——互相降级时**两条都成立**（失败即关闭，复核 S12A-02）；报复事件里的纪元声明与包裹一律不算（复核 S12B-23）。报复另须**看见了降级者在第一次降级他之前的全部作为**（第五轮复核 S12A-26）：前序选在降级者更早事件处的“回溯报复”不算报复，在迭代之前就直接拒收——否则降级者那条更早的事件按“移出优先”被拒收，降级他的事件作为后代一并失效。第三位负责人看到降级之后已对这两人之一做过成员操作的，此后才出现、不在其因果过去里的报复同样拒收（第五轮复核 S12A-28：不能反复制造冲突，也不能在第三位负责人的决定之后悄悄翻案）。
6. **纪元声明**：同一纪元号有多个有效声明时，按 (lamport, event_id) 最小者为胜者，与之后的成员变化无关（复核 S12B-03）；其余为“落选”。
7. **本机写入核效**：本机每写一条事件即按链核一次，不成立即删除并让事务回滚、接口返回失败（复核 S12B-01/02）。
8. **加密纪元**：链上已声明、本机持有胜者密钥的最高纪元；本机写过、合并后不成立的轮换不删密钥（可能重新成立），只停用，用它发出过的内容重发一次（复核 S12B-20）；本机没有链上最高纪元的胜者密钥、或本机加密纪元里有已移出成员的设备即暂停。
9. **认可与标记**（第三轮复核 S12A-09/14、S12B-35）：使被吊销设备 d 的事件 x 有效的“认可”只算未吊销设备写的、最终成立的事件 v，且 v 的因果过去里没有给 d 的在用标记、或 x 在其中某条标记的祖先里（标记的链上位置）；“在用标记”同一判据（作者设备未吊销）。是否吊销只看本机的吊销记录与控制面墓碑，链上的标记本身不算吊销依据（第四轮复核 S12A-19/S12B-43：第三轮曾把“链上有在用标记”当作吊销，负责人——包括正被移出的——借此能撤销同事的移出，已撤回）。每台在用负责人设备只要持有 d 写的、成立却不在任何在用标记祖先里的事件，就补一条标记（S12A-10）。
10. **材料块**按链模式的加密纪元封（第三轮复核 S12B-31/32）；**发出前按段的纪元重封**（第四轮复核 S12B-44/45：暂停期间、用落选或不成立纪元封的块都重封；同号纪元换过密钥的也重封）。第五轮收窄：
    - 只重封**本机写的行引用的块**，或**块头纪元在链上没有声明**的块；别人按已声明纪元封的块原样转发（S12B-56：否则一次全量重发就把整事项的块改写一遍）；
    - **只向上**：块头纪元高于此刻的加密纪元时不动，绝不降到被移出者仍持有的低纪元（S12A-27）；
    - **重封失败即关闭**：本事项本轮不发、不推进水位，记入导出错误，下一轮再试（S12B-54）；
    - 本机某纪元的密钥被胜者替换时，原先那把留在 `matter_key_history`，旧块仍解得开；恢复演练覆盖本机包裹前同样留历史，且托管包裹须是链上该纪元胜者那把（指纹核对，S12B-57）；
    - 共享文件夹上同名块内容不同、且已有副本的纪元不高于本机这份时才覆盖（S12A-27）；
    - 中继出件箱里引用了已重封块的段作废，水位退到段里最早一行的时刻、重新导出（S12B-55：原先退到段的生成时刻，段里的行永远不再发出）；`local_blob_changed` 只认本机产生的，中继发来的同名错误码不认（S12A-29）。
11. **互相降级或移出**未解除时不自动处置（不补轮换、不补包裹），解除只认第三位在册负责人在两条之后亲手做的成员操作（第四轮复核 S12B-46）。

有效集对祖先封闭（一个事件无效，其后代都无效）。

## 4. 投影（成员关系由链推出，`matter_members` 只是投影）

对每位成员，取有效集中“关于他”的事件（起点里列出他、`member` 事件的 `user` 是他），去掉其中被另一条关于他的事件作为祖先的（只看“最新的并发集合”）：

- 其中有移出 → 已移出（**并发时移出优先**，伦理墙不被并发的加回冲掉）；
- 否则取 (lamport, event_id) 最大者的角色。

投影写回 `matter_members`（`author_device`/`row_lamport` 取决定该行的事件；`author_sig/author_cert` 置空——链模式下成员行不再单独签名，也不再按行采信）。

## 5. 密钥包裹

链模式下包裹行（`key_rows`）不再看“段签发者是不是负责人”，而看链：

- 包裹 (事项, 纪元 e, 设备 d, 密文 w) 落库，当且仅当 e 的胜出声明或该纪元上有效的 `wraps` 追加里有 `d → SHA-256(w)`；
- 面向本机的包裹另须解开后指纹 = 胜出声明的 `fp`；本机已有该纪元的另一把（输家）且收到胜者的包裹 → 替换，并把本机导出水位退回到输家声明之前，重发本机写的内容；
- 包裹摘要绑定在链上，任何成员都可以转发包裹，介质与转发者都改不了。

## 6. 暂停发出与自动处置（链模式下取代 `epoch_conflict` / `owner_unverifiable`）

告警仍记在 `sync_alerts`（迁移 0042 放宽种类），有告警即暂停发出（失败即关闭，沿用）：

| 种类 | 条件 | 自动处置 |
|---|---|---|
| `chain_pending` | 被吊销设备写的事件待定（尚无在用负责人认可）；或缺前序的事件——作者是本链在册负责人、且经本链在册成员转发 | 收到缺的前序或 `mark` 后自动解除；长期不解 → 本机重新引导 |
| `rekey_needed` | 当前最高纪元的包裹里仍有已移出成员的设备（两位负责人并发移出与轮换合并后） | 处置者（见下）自动轮换；其他设备等待 |
| `epoch_superseded` | 本机持有的最高纪元密钥是分叉的落选者 | 等胜者的包裹（收到即替换、退回导出水位重发本机写的内容）；不自行再轮换（否则几方同时再轮换又分叉） |
| `root_conflict` | 收到与本机不同、且本身按起点规则可以采用的起点（另一位在册负责人的锚定） | 人工：确认后“本机重新引导该事项” |
| `member_conflict` | 两位负责人互相降级或移出（两条都成立），尚无第三位在册负责人在两条之后、**针对这两人之一**亲手做过成员操作（第三轮复核 S12B-33/36；第五轮 S12A-28/S12B-58：给无关的人改角色、授权节点不算） | 第三位负责人把应留下的那位重新设定角色；期间不据此移出本机成员行（不擦除）、不自动轮换 |
| `revoked_change` | 被吊销设备写的移出或轮换因吊销标记拒收、经在册成员转发而来（第三轮复核 S12A-10） | **只提示、不暂停**：负责人核实后重做。移出类：另一位在用负责人以该事件的全部前序为祖先、对同一成员做过成员操作即不再提示（被移出者本人不算）；轮换类：出现以其前序为祖先、且没有包给它所排除设备的更高纪元即不再提示（第五轮复核 S12A-30/S12B-60：按因果，不按 lamport） |

- **处置者只有一位**：中继事项为控制成员；否则为当前纪元胜出声明的作者（仍是负责人时），再否则成员编号最小的负责人。处置者另负责给在册成员后登记的设备补当前纪元的包裹（`wrap` 事件；取代“对方设备登记后须重新执行补包裹”）。
- **暂停期间只发成员链**：有告警的事项仍发成员链、成员行、用户行与本机设备行（不带事项行与 IM 绑定，复核 S12A-06），链没变不重发（`chain_paused_export`）——负责人要收到链才能处置。这些行以本机当前纪元加密：仍持有当前纪元密钥的被移出者能读到成员关系（不是事项内容，如实登记）。
- 成员或所内任意设备伪造的缺前序事件、伪造的起点只计、不暂停。

## 7. 存量事项的锚定（迁移路径）

- 升级后，事项没有起点时仍按第 11 批的旧规则收发成员行（旧代码保留，只对未锚定的事项生效）。
- **锚定者**：中继事项为控制成员；只经共享文件夹的事项为本机认得的在册负责人中，事项创建者（仍是负责人时），否则成员编号最小者。锚定者的设备在下次导出前自动写 anchor（列出全部成员行含已移出的、当前纪元与本机全部包裹的摘要）。
- 锚定之后，旧成员行在本机只作投影，收到的成员行一律不采信。
- 两位负责人各自锚定（看法不一致的罕见情形）→ 第二个设备记 `root_conflict`，人工处理。
- 混合版本：旧客户端不认链，锚定事项上的成员变更在旧客户端上不生效（部署说明：开启前全所升级，与第 11 批同口径）。

## 8. 本机操作写事件

| 操作 | 事件 |
|---|---|
| 新建团队事项 | genesis（纪元 1 的包裹含恢复托管） |
| 加人 / 改角色 | member（带对方现有设备在当前纪元的 `wraps`） |
| 移出 | member（`role = null`）+ 同一事件里 `key` 新纪元 |
| 恢复演练轮换 | rekey |
| 节点授权 | member（节点成员 viewer）+ `wraps` |
| 吊销得知（负责人设备） | mark（对每个该设备写过事件的、本机是负责人的事项） |
| 中继控制成员移交 | control + 调用中继 `POST /v1/relay/matters/<事项>/control` |
| 本机重新引导该事项 | 不写事件：清本机该事项的链、投影保留为旧规则视图、清已摄取标记与中继取历史进度，下次收到时按首同步规则重新引导 |

个人事项不写链（不同步）。本机成员操作在写事件的同一事务里重算投影。

## 9. 段与导出

- 链事件作为“总是附带的表” `member_events`（段体内加密）每段全量附带；接收方先处理链再处理其余行。中继介质上任何新的成员事件（不论谁写的）都触发出段，链由收到的成员转发、各设备一致后收敛。
- 段的内容因故延后（例如段里面向本机的包裹没有链上声明——并发轮换的落选方发来的段）时，段里的成员事件仍先存下：落选方的段里正有胜者需要的链。
- 链模式下，解这一段用的若是段里面向本机的包裹（本机没有该纪元的密钥，或本机那把落选），须是链上声明的那一把，否则整段延后——这是首同步的闸门，取代第 11 批的“签发者须是负责人”。
- 链模式下，`matter_members` 行仍随段附带（旧客户端兼容），但新客户端不采信。
- 首同步：本机没有该事项时，段体里有链即走链规则（第 2 节），没有链走旧规则。本机已有起点的事项，收到没有链的段不回退旧规则。

## 10. 中继控制成员移交（D-94 在链上表达）

- 中继新接口 `POST /v1/relay/matters/<事项>/control`，请求体 `{to}`（成员编号），只有当前控制成员可调用；接收者须登记过该事项的段、且有一台当前是读者、未被吊销的设备；原样重试（回复丢失）回成功；登记日志追加 `{k:"control", dev}` 记录；回复新的控制成员。
- 闸门中继通道增加该请求类型（只带事项编号与成员编号）。
- 客户端：`matters.relay_handoff {matter_id, to_user}`：本人须是控制成员、按链是负责人、事项没有同步告警，对方按链须是在册负责人；先调中继，成功后写 `control` 事件（中继是控制权的准绳）；写链失败时如实说明中继上已移交。中继回 `not_controller` 时本机清掉缓存的控制成员、重取历史。界面入口尚未做（第三轮复核 S12A-15，见残余）。

## 11. 实现中的补充与取舍（10-19）

- **移出优先于被移出者的并发操作**（第 3 节第 5 步）：纯按因果过去判资格时，被移出的共同负责人只要不去收移出他的那一段（他也收不到——那一段用新纪元加密、没有给他的包裹），此后做的成员变更与轮换永远“与移出并发”、一直有效。补此规则后，第 11 批 S11A-43/51/54 的场景里，被移出者并发的移出与轮换在链上拒收，滞后设备不再分叉、不再暂停。代价：合法共同负责人被降级的同时做的成员变更也不算（须由在任负责人重做）。
- **测试模拟升级前的客户端**：`ZR_MEMBER_LOG=off` 只在 node 测试运行器里生效（`NODE_TEST_CONTEXT`），用来覆盖仍在用的第 11 批行规则（`member-log-legacy.test.ts`）。
- **节点撤销**：链模式下包裹摘要已在链上、成员设备会互相转发，只删本机那一行收不回——改为移出节点成员并轮换（中继事项须控制成员操作）。
- **控制成员降级须先移交**：中继控制成员被降为非负责人之前，须先移交控制成员（否则此后谁都不能在中继上调整成员、轮换密钥）。
- **加本机用户的事件不成立时不擦除**（第五轮复核 S12A-26 第 3 条）：投影写回时，链上从未出现的本机行按已移出处理（锚定者的成员关系为准）；但本机用户自己的行，只要链上有过以他为对象的成员事件（只是不成立），就不标为已移出——本机行被标为已移出即触发本机擦除，擦除只凭成立的移出事件。他不在投影里，轮换与补包裹都按投影，不会包给他。

## 12. 残余（如实）

- 桌面界面还没有移交入口，也不显示链上的移交记录（第三轮复核 S12A-15）：控制成员须经接口办理，控制成员本人须被隔离时只能找中软客服。
- 吊销判定混用两套时钟（第三轮复核 S12A-16）：收下时刻取本机时钟，吊销时刻取本机吊销记录或控制面墓碑（控制面时钟）的较早者。本机慢于控制面不超过 5 分钟时，吊销后至多 5 分钟内收下的事件按吊销前收下处理、由本机标记固定；慢超过 5 分钟时设备目录被拒收，本机一直不知道吊销：本机在这期间采信被吊销设备的事件，本机写的、引用了这些事件的成员事件在知情的设备上不成立（须在知情后重做）；知情设备不因不知情设备之后写的事件而采信标记之后的事件（标记的链上位置，S12A-09）；本机快于控制面时，吊销前收下的合法事件被当作吊销后收到（待定、暂停）。按中继或控制面回告的时间折算在 G1。
- 恢复轮换特意排除的设备此后一直被排除（第三轮复核 S12B-39）：设备找回后须吊销并换新设备，没有撤回排除的入口。
- 只有负责人设备写标记：被吊销设备的事件若只被非负责人设备（编辑等）在吊销前收下，没有人能固定它（第四轮复核 S12A-10 余项）。
- 第二、三遍合起来至多迭代 4 轮，不收敛时取最后一轮的结果（罕见的多方循环降级加吊销，第四轮复核 S12A-23/S12B-49）；收敛到哪个不动点可能取决于先后，偏向更保守的一侧（第五轮复核 S12B-61）。不收敛时不告警（S12A-32 建议改记 `chain_pending`，后续）。
- 迁移 0043 曾在发布前原地改过（第三轮）：跑过那一版的开发库须删除重建（第四轮起改动另立 0044，0043 已还原为首次提交的内容）。
- 被吊销设备写的移出或轮换，若没有任何在用负责人设备在吊销前收下过，就无法与伪造区分：拒收，只提示（`revoked_change`，不暂停），须负责人确认后重做。
- 吊销标记写出之前的窗口：被盗设备在标记前伪造、且被在用负责人设备收下并在其上写过事件的成员事件，仍有效。
- 首同步的起点信任：共享文件夹介质“首个有效起点”；控制面见证创世在 G1。
- 在任负责人的合法权限防不了（含重新加回被移出者）。
- 起点冲突不自动解决（防抢占）；须人工重新引导。重新引导后共享文件夹介质按“编号最小的合格起点”采用，中继介质仍只从控制成员的段引导。
- 暂停期间只发成员链：仍持有当前纪元密钥的被移出者能读到成员关系（不含事项内容）。
- 合法共同负责人被降级的同时做的成员变更不算（移出优先于被移出者的并发操作）；真正并发的互相降级两条都成立，两人都失去负责人身份，须由第三位负责人或律所处理。被移出者仍可以在降级他的事件之前、看见降级者此前全部作为的位置补写一条报复，制造一次冲突（链是有向无环图，没有可信时间，无法区分“真的并发”与“事后补写”）：可用性受损（事项暂停）；机密性不受影响（冲突期间不自动轮换、不据此擦除，回溯到更早位置的报复直接拒收，第五轮复核 S12A-26）。第三位负责人处置之后，同一对人之间再补写的报复不成立（S12A-28）。
- 只有两位负责人的事项出现互相降级时，没有第三位负责人能解除，事项一直暂停，须律所处理（加第三位负责人须由在任负责人操作，此时没有在任负责人：只能按事项重新引导，第五轮复核 S12A-28）。
- 中继事项里，若控制成员是互相降级的一方，第三位负责人的成员操作被“须由中继上的控制成员操作”拦下，冲突在本机无法解除，须联系中软客服按事项重置控制成员（第五轮复核 S12A-28；重置会重新打开抢先登记的窗口）。
- 两位负责人的设备先后被吊销、又没有其他在用负责人时，事项一直暂停，须律所处理；放弃的起点（重新引导时）不可撤回；并发加人与轮换时，在新包裹到达之前可能短暂误报 `rekey_needed`（第四轮复核 S12B-53）。
- 负责人给在用设备写的吊销标记被静默忽略，不点名作者（第五轮复核 S12A-32/S12B-61 建议，后续）；块头里的事项编号在共享文件夹介质上不与存放目录核对（可用性，后续）；共享副本每次导出整份读回比对、`matter_key_history` 与块密钥缓存没有上限（性能，后续）。
- 重封只向上：本机加密纪元回落（自己的轮换改判不成立）时，按更高纪元封的块不动，读者以那一纪元的持有者为准（只会更窄）；本机此后写的块按回落后的纪元封，须由负责人补轮换。
- 锚定之前、按旧成员行认不出锚定者的未锚定设备（第 11 批 S11A-52 情形）不能采用锚定，须联系中软客服（复核 S12B-14）。
- 有效集取决于本机收下各事件的时刻（与吊销时刻比较）：同一组事件在吊销前后收下的设备可以得出不同结果——唯一负责人的设备被吊销后，新登记或此后才首次收到链的成员设备会停在 `chain_pending`（复核 S12B-18）。
- 报复事件里的纪元声明不算：互相降级后移出所带的轮换失效，须由其余负责人补轮换；若再无负责人，事项暂停发出，须律所处理。
- 唯一负责人的设备被吊销且未交接：吊销之前收下的成员事件照收、成员不受影响；但此后没有在用负责人能做成员调整与补轮换，须律所处理。
- 中继控制成员不是链上负责人（中继重建后被非负责人抢先登记等）时，补轮换与成员调整都做不了，须联系中软客服（复核 S12A-08）。
- 被吊销设备写的、本机在吊销时刻之后才收到的事件不被标记固定（即使它确实是吊销前写的），须由在任负责人重做；吊销时刻取本机吊销记录与控制面墓碑较早者，与本机收下时刻比较（两台电脑的时钟偏差影响这一判断）。
