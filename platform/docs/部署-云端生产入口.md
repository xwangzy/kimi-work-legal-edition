# 云端服务生产入口（第 13 批）

`scripts/cloud-serve.mjs` 是七个云端服务的生产启动方式（开发联调仍用 `scripts/dev-cloud-v0.mjs`）。每个服务一个进程、一个配置文件：

```bash
node scripts/cloud-serve.mjs --config /etc/kwl/control-plane.json
```

## 与开发脚本的区别

| 项 | 开发脚本 dev-cloud-v0 | 生产入口 cloud-serve |
|---|---|---|
| 传输 | http 回环 | 只接受 HTTPS（TLS ≥ 1.2）；`insecure_loopback_for_test` 只许 127.0.0.1 |
| 签名密钥 | 每次启动随机生成 | 从文件读（KMS / 密钥管理服务挂载为只读文件），不生成、不打印 |
| 吊销订阅 | 可选 | 网关、检索、分发、支持、通知、中继必须订阅；首次取到并核验签名后才对外服务 |
| 控制面状态 | 可不落盘 | 必须封装（state_key_file）、运营审计必须落盘 |
| 上游 | 缺省 mock | 网关、检索只接真实上游（api_key_file） |

## 签名服务（v9.3 A-8；`services/cp-signer`；设计 `design/云端持久化与KMS设计-v1.md` §4）

- **私钥只在签名服务**：控制面经 mTLS 申请签名（`connectRemoteSigner`），只提交结构——信封给种类与文档、席位令牌给租户/成员/席位/设备/受众/有效期；
  签名字节由与进程内签名同一个函数生成（逐字节相同，用例对照）。签名服务停了，控制面对设备回 503 `signer_unavailable`，不降级为进程内签名。
  生产形态下控制面的 `ops.seal`（进程内签任意文档）不可用；开通码胡椒必须另给文件。
- **按种类核对后才签**：只签登记过的 9 种信封（许可、设备目录、租户盐、律所策略、连接器目录、网关订阅、吊销通知、用量视图、操作记录分页）；
  签发时刻与签名服务时钟相差超过 5 秒、许可与目录有效期超过 30 天、盐短于 16 字节、策略或连接器文档不合格、请求里夹带种类与文档以外的字段，一律拒签。
  席位令牌：通用 72～96 小时，支持凭据至多 15 分钟，通知与中继凭据至多 6 小时。只核格式与时限、不判断宽严（宽严由律所根与管理员签名把关）。
- **调用方核对**：TLS 层只认 `client_ca_file` 签发的客户端证书，再按 `allowed_callers` 核对证书的 URI SAN（或 CN）；不在名单里的 403、不进签名账，只计数。
- **签名账** `<data_dir>/cp-signer/ledger.jsonl`：每次签名与拒签一行（时刻、请求编号、调用方、种类、租户编号、密钥编号、文档与签名结果的 SHA-256、结果与原因；**不写文档内容**），
  行与行哈希链相连；启动时整本核验，链断了不启动；**记不进去就不签**（503 `ledger_unavailable`）。外送 WORM 对象存储随 A-11 的对象存储接口，按批外送尚未做。
- **密钥编号按用途与环境**：`cp-<环境>-<编号>`、`seat-<环境>-<编号>`、`seat-support|notify|relay-<环境>-<编号>`，与 `environment` 不符即拒绝启动；只收 Ed25519 私钥；启动时用公钥自检一次。
- **席位密钥按受众拆分**：网关、检索、分发的 `seat_keys_file` 只放通用席位公钥；支持、通知、中继各放自己受众的公钥（控制面 `publicKeys.seatFor(受众)`）。
  一把受众密钥泄露或轮换只影响那一个服务；没有配受众密钥时回落到通用席位密钥（开发与测试）。
- **指标**：`kwl_signer_requests_total{op,kind,result}`（签名速率异常由告警规则对照 7 日基线，设计 §4.4）。
- **未做（外部条件）**：私钥静态形态仍是挂载的 PKCS#8 文件——KMS 信封加密解封（路径 A）、CSMS 凭据与跨区域副本、密钥仪式、mTLS 证书自动轮换都依赖云选型（设计 §4.2、§4.6、PoC-1）。

## 对象存储（v9.3 A-11；`packages/blob-store`）

支持服务加 `blob_store` 即把诊断包本体放进 S3 兼容对象存储（华为云 OBS 等），工单元数据仍在 `data_dir`：

```json
"blob_store": { "kind": "s3", "endpoint": "https://obs.cn-north-4.myhuaweicloud.com", "bucket": "kwl-prod-support", "region": "cn-north-4", "prefix": "support",
                "access_key_id_file": "/run/secrets/obs-ak", "secret_access_key_file": "/run/secrets/obs-sk", "kms_key_id": "<KMS 密钥编号>" }
```

- 每个对象写入都带 SSE-KMS 与密钥编号；回复里没有加密头即删掉刚写的对象并报错（不留未加密的对象）。桶策略另须拒收不带加密头的写入、只许 HTTPS（IaC）。
- 签名为 AWS 签名第 4 版（自写，用例对照 AWS 文档的公开示例逐字一致）；只走 HTTPS，私有化部署可给 `ca_file`。
- 到期删除仍由服务每小时清扫（先删本体、再删元数据；没有元数据的孤立本体超过 1 小时删除）；桶的生命周期规则设 8 天作兜底。
- 启动时列一次，连不上即拒绝启动；运行中写不进对象存储时上传回 500，工单不作废、同一令牌可重试。
- **中继密文块仍在本地目录**：中继属团队共享（R30 冻结，只修阻断），它的并发与配额语义依赖同步区段，改为异步对象存储要重做一轮复核；接口已就绪（同一 `BlobStore`），解冻后接（偏离 D-109）。

## 控制面一主多备（v9.3 A-7 第一段；`pg-state-store.ts`、`nonce-mirror.ts`；偏离 D-108）

控制面加两项配置即从“单实例文件”改为“PostgreSQL 一主多备 + Redis 防重放”：

```json
"state_store": { "kind": "postgres", "url": "postgres://kwl_cp@db.internal:5432/kwl", "password_file": "/run/secrets/cp-db-password", "ca_file": "/etc/kwl/db-ca.crt" },
"nonce_store": { "kind": "redis", "url": "rediss://cache.internal:6379", "password_file": "/run/secrets/cp-redis-password", "ca_file": "/etc/kwl/redis-ca.crt" }
```

- **一主多备**：每个实例启动时等数据库咨询锁，等到之前不监听端口（负载均衡的就绪检查不通过）；拿到锁的读回最新状态后才服务。主实例进程或连接断掉，锁随会话释放，备实例接手。
- **每个改变状态的回复之前已提交**（状态同一份 JSON 封装后写一行，带上一代序号做围栏：别的实例写过、连接断了即失去主实例身份，入口退出进程由编排重启）；`/readyz` 在失去主实例身份时回 503 `state_store_lost`。
- **防重放随机数**：仍在主实例内存里判定；每个新随机数异步写一份到 Redis（剩余有效期自动过期），换主实例时先读回——不再丢最近 30 秒的随机数。Redis 不可用时只计数、降级为状态快照里的随机数。
- **连接**：PostgreSQL 必须 TLS（只信 `ca_file`）+ SCRAM-SHA-256（明文口令与 MD5 一律拒绝、口令写在地址里即拒绝启动）；Redis 必须 `rediss://`。两个口令文件同其他密钥文件一样核“是不是随机生成的”。
  客户端是自写的最小实现（`pg-wire.ts`、`resp.ts`，只用几条固定语句、参数一律单独传），不引第三方驱动。
- **指标**：`kwl_cp_state_saves_total{result}`、`kwl_cp_nonce_mirror_total{result}`。
- **残余与未做**：整份状态一行（试点规模可接受；G2 按设计 §2 拆成按租户的关系表 + 行级安全 + 多写）；有库写权限的人把整行换成更旧的一代挡不住（与文件存储同一残余，靠客户端拒收回退的目录版本）；
  云数据库的同步复制、跨区域灾备、PITR 依赖云选型（设计 §6）；限流计数仍在主实例内存（换主实例后从零开始）。

## 密钥文件格式与网络前置（复核 A-15）

- `state_key_file`、`code_pepper_file`（开通码 HMAC 的胡椒，控制面必填，与签名密钥分开）、`meter_key_file`（支持服务）：32 字节十六进制；
- `service_secret_file`：至少 32 字节随机（64 位以上十六进制或 43 位以上 base64url），太弱即拒绝启动；`ops_secret_file`（共享运营口令）已停用，配置里出现即拒绝启动（v9.3 A-10）；
- 以上全部还核“是不是随机生成的”（第 14 批第二轮复核 A 余项，`scripts/lib/secret-strength.mjs`）：整串由同一片段重复、有 8 个以上连续递增或递减的字符、
  十六进制只有数字或只有字母、base64url 没有同时含大小写、含 changeme / password / secret 等占位词、解码后字节取值少于 16 种，一律拒绝启动。
  这只拦明显手填的值，不是熵估计——一律用 `openssl rand -hex 32`（或 KMS 生成）产生，不要手写；
- 服务器级参数：请求头 20 秒、整请求 60 秒（中继、分发、支持 300 秒）、keep-alive 5 秒、并发连接缺省 10,000（`max_connections` 可调）；畸形请求回 400 并断开、不记内容；
- 网络前置：TLS 必须终止在本进程，前面只能是四层负载均衡，且**必须保留客户端源地址**（直通；入口目前不解析 PROXY 协议，PROXY 协议待 G1）——控制面的兑换限速与运营接口的来源网段都按来源地址判断；
  放在七层代理或做源地址转换的负载均衡之后，每来源 10 次/分钟会变成全平台合计 10 次/分钟。

## 运营按人鉴权（v9.3 A-10；Y2 §3.12 运营控制台；`packages/ops-auth`、`scripts/ops-cli.mjs`）

共享运营口令（`ops_secret_file` + 自报的 `x-kwl-operator` 头）已停用。每位运营人员一把（或几把）自己的签名密钥，运营请求逐个签名；云端只存公钥。

| 角色 | 做什么 | 命令（`node scripts/ops-cli.mjs …`） |
|---|---|---|
| 安全管理员 | 生成名册签名密钥（**私钥离线保管，不放到任何服务上**；公钥合并进公钥表）；新建名册、登记（核对指纹）、改权限、吊销、续期；每次签发新版本名册 | `roster-keygen --kid sec-1 --out <离线目录> --keys-file ops-roster-keys.json`；`roster init --deployment prod …`；`roster add / add-key / perms / revoke / renew --roster <名册> … --sign-key <私钥> --sign-kid sec-1 --out <名册>`；`roster show --roster <名册> --keys ops-roster-keys.json` |
| 运营人员 | 在本人电脑生成密钥（私钥 0600、不覆盖已有文件，可用 `--passphrase-env` 加密）；把公钥文件与指纹交安全管理员（当面或电话核对指纹）；从运维网段调用运营接口 | `keygen --id op_0001 --kid k1 --out ~/.kwl-ops`；`call --url … --deployment prod --aud control-plane --id op_0001 --kid k1 --key … --method POST --path /v1/ops/tenants --body '{…}'` |
| 系统管理员（不在名册里） | 部署名册与公钥表、管理各服务的数据目录（含名册版本记录） | — |
| 审计 | 查访问审计、被拒记录与名册换版记录（位置见下）；控制面写操作另进律所可见的运营审计流水（执行者为运营编号） | — |

服务配置（控制面、支持、中继、通知；其他角色配了即拒绝启动）：

```json
"ops": {
  "deployment": "prod",
  "roster_file": "/etc/kwl/ops-roster.json",
  "roster_keys_file": "/etc/kwl/ops-roster-keys.json",
  "allow_cidrs": ["10.20.0.0/24"],
  "min_roster_version": 12
}
```

- **运营名册**（`kwl-ops-roster/2`，安全管理员签名）：部署标识（`deployment`，与服务配置一致才认）、版本、签发与到期时刻（**至多 31 天**，到期运营接口 503，须 `roster renew` 重签）；
  每人一个运营编号（`op_` 加数字工号，**不用姓名**——会进律所可见、不可删的流水）、权限、公钥（**只收公钥 PEM**，私钥放错位置即拒绝；Ed25519，名册格式也收 P-256）、状态。
  同一把公钥不能登记给两个人；名册签名公钥不能同时是运营人员的公钥。
- **权限**：`tenant.read`；`tenant.manage`（开通、续订）；`tenant.terminate`（终止订阅）；`activation.issue`（发与作废**创始**开通码，律所管理员发的成员邀请码不归运营）；
  `quota.manage`（加量，含开通时附带的点数）；`quota.cap`（代设月度上限，**只能调低**，调高或取消须律所管理员在客户端操作）；`device.revoke`（吊销设备与席位）；
  `support.read` / `support.delete`（诊断包查看 / 删除）；`relay.reset`（中继按事项重置）；`tenant.purge`（中继、通知按租户整体删除）。
  **同一人不能兼有 `tenant.manage` 与 `activation.issue`**（否则一个人就能开出并认领一个律所；双人复核未做之前的职责分离，D-106）。
- **吊销**：`roster revoke --id <人>` 把此人标为吊销（`--kid` 只删丢失的那一把密钥）；已吊销的人不能再改。新名册换上去即生效（服务每次运营请求都核对名册，文件有变化或满 30 秒重新核验），不需要重启。
- **回滚保护**：服务在 `ops/roster-seen.json` 记下见过的最高版本、摘要与名册签名公钥指纹；换回旧版本、同版本不同内容、单次跳过 1,000 个以上版本，运营接口整组 503，重启后同样不认；
  新实例或数据目录重建时用 `min_roster_version` 给版本下限。名册缺失、签名不符、过期、版本记录损坏时同样 503——**业务照常启动**，启动输出与错误日志（`obs/error-*.jsonl`，kind `ops_roster`）各记一条原因。
- **名册签名密钥轮换**：`roster-keygen` 把新公钥合并进公钥表 → 部署到各服务 → `roster renew --keys <公钥表> --sign-key <新私钥> --sign-kid <新编号>` → 全部服务换上新名册后**立即**从公钥表删掉旧编号（删除之前旧密钥仍能签名册）。公钥表变化记入名册换版记录。
- **请求签名**：头 `x-kwl-op`、`x-kwl-op-key`、`x-kwl-op-ts`、`x-kwl-op-nonce`、`x-kwl-op-sig`，签“部署/服务 + 方法 + 路径（原样）+ 请求体摘要 + 运营编号 + 密钥编号 + 时刻 + 随机数”；
  时刻偏差 ≤ 5 分钟；随机数落盘（`ops/nonces.jsonl`），重启后也不能重放。对外的拒绝原因不区分“未登记、已吊销、签名不符”（都是 `ops_auth_invalid`），细分原因只进被拒记录。
- **来源**：运营路径（`/v1/ops/…`、`/v1/support|relay|notify/ops/…`，原样或规范化后任一命中）只放行 `allow_cidrs` 里的来源（运维网段 / 堡垒机出口），其他来源与没有配置 `ops` 时在入口一律 404。
  每段前缀不短于 IPv4 /8、IPv6 /32，合计不超过一个 /8（/32）；不得包含回环、未指定、链路本地地址，**也不得包含任何负载均衡、NAT、代理或边车的地址**——入口只看连接的来源地址，前置做了源地址转换时这一道就失效了。
- **控制面运营接口**（最小集）：`POST /v1/ops/tenants`（开通，一律要求开通码；附带点数另须 `quota.manage`）、`GET /v1/ops/tenants/<租户>`（概要：只列创始开通码，成员邀请码只给计数，不含成员姓名与标识）、
  `POST …/activation-codes`、`POST …/activation-codes/<编号>/revoke`、`POST …/renew`、`POST …/terminate`、`POST …/points`、`POST …/cap`、`POST …/devices/<设备>/revoke`、`POST …/seats/<成员>/revoke`。先鉴权、后解析请求体。
- **审计与记录的位置**：
  - 控制面运营访问审计 `<data_dir>/control-plane/ops/access.jsonl`：每个通过鉴权的运营请求先记“已请求”（fsync，记不进去即不执行）、执行后补记结果，带运营编号、密钥编号与名册版本；
  - 支持、中继、通知的访问审计仍在 `<data_dir>/<角色>/access.jsonl`，运营访问记运营编号、密钥编号与名册版本；
  - 各服务 `<data_dir>/<角色>/ops/rejects.jsonl`：被拒的运营请求。签名核验通过之后才被拒的（越权、重放、双因素）一律记；未核验的（`claimed` 只是请求自称，**未经核验**）每分钟至多 60 条，超出的下一分钟补记条数；
  - 各服务 `<data_dir>/<角色>/ops/roster-history.jsonl`：每接受一版名册一条（版本、摘要、签名密钥编号、人数），名册签名公钥换了也记一条；
  - 被入口按来源挡下的运营请求不进以上任何一处，只在 A-9 访问日志（`obs/access-*.jsonl`，路径与状态码）里；
  - 律所可见的运营审计流水：运营写操作的执行者为运营编号；被拒的同一执行者同一动作每分钟至多 10 条。
- **未做**（偏离登记 D-106、D-107）：堡垒机、会话录像与真实双因素（名册 `second_factor` 只认 `none`，标了别的而服务没接核验器即拒绝；目前只有“持有私钥”一种因素加运维网段，等保“两种以上鉴别技术”未满足）；
  硬件令牌（USBKey）的接入路径（名册格式支持 P-256，但命令行只认私钥文件）；敏感操作双人复核与名册多人签名；运营接口独立监听；多实例共享随机数与名册版本记录；运营侧记录的保存期、防篡改与集中留存。

## 可观测性（v9.3 A-9；Y2 §6.1、§6.2；`scripts/lib/obs.mjs`）

每个角色都由入口统一记录，**只计量、不留内容**：

| 项 | 位置与内容 | 不记 |
|---|---|---|
| 访问日志 | `<log_dir>/access-YYYY-MM-DD.jsonl`（`log_dir` 缺省 `<data_dir>/obs`，两者都没有即拒绝启动）；每行只有 `at, role, method, path, status, latency_ms, client_request_id, net`：路径去掉查询串、至多 200 字；请求编号只认闸门的合格形状；来源只留网段（IPv4 /24、IPv6 /48） | 查询串、请求头（含 `authorization`、`x-kwl-sig`）、请求体与响应体 |
| 错误日志 | `<log_dir>/error-YYYY-MM-DD.jsonl`：进程级未处理异常只记 `at, role, kind, code`（错误代码或类别），随后进程退出由编排重启 | 异常消息、堆栈（可能带用户输入） |
| 保留期 | `log_retention_days`（缺省 190 天，满足计量与访问日志 ≥ 6 个月）；启动时与每 6 小时删除过期文件（只删本模块写的文件名） | — |
| 健康检查 | 服务端口上的 `GET /healthz`（进程活着）、`GET /readyz`（控制面以外的角色：2 分钟内取到过控制面吊销集，否则 503 `feed_stale`） | 不需凭据、不含内容 |
| 指标 | 单独的监听 `"metrics": { "host": "127.0.0.1", "port": 9464, "token_file": "..." }`；`GET /metrics` 为 Prometheus 文本格式；监听回环以外的地址必须配置令牌（至少 32 字节随机，`Authorization: Bearer`） | 路径、请求编号、地址、租户 |

指标与 Y2 §6.2 告警的对应（告警规则由运维在监控系统里配置）：

| 告警（Y2 §6.2） | 指标 | 建议规则 |
|---|---|---|
| 网关 5xx 比例 | `kwl_requests_total{role="gateway",code_class="5xx"}` / 全部 | > 2% 持续 5 分钟，P2 |
| 订阅滞后 / 撤权传播时延 | `kwl_feed_age_seconds` | > 120 秒 P2；> 60 秒且控制面刚发吊销 P1（`/readyz` 同时变 503） |
| 证书到期 | `kwl_tls_cert_expiry_seconds` | < 30 天 P2；< 7 天 P1 |
| 进程异常 | `kwl_process_errors_total` | 任意增长 P2 |
| 日志写不出 | `kwl_log_write_errors_total` | 任意增长 P1（视同计量缺失） |
| 请求耗时 | `kwl_request_duration_seconds` | 按角色 P99 设基线 |

上游 429 比例、签名服务错误、额度租约拒绝、提醒投递延迟需要服务内部计数，随签名服务与 PostgreSQL 一起做（差距清单 A-8、A-7）。

## 与客户端钉住的关系

客户端按 `release.json` 钉住各服务证书的 SPKI（至少两把：当前 + 备份）。证书续期须复用密钥对或预置备用钉住；服务前不得放解密型 WAF/CDN（调研 Y2 §2）。
