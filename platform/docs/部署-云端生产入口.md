# 云端服务生产入口（第 13 批）

`scripts/cloud-serve.mjs` 是七个云端服务的生产启动方式（开发联调仍用 `scripts/dev-cloud-v0.mjs`）。每个服务一个进程、一个配置文件：

```bash
node scripts/cloud-serve.mjs --config /etc/kwl/control-plane.json
```

## 与开发脚本的区别

| 项 | 开发脚本 dev-cloud-v0 | 生产入口 cloud-serve |
|---|---|---|
| 传输 | http 回环 | 只接受 HTTPS（TLS ≥ 1.2）；`insecure_loopback_for_test` 只许 127.0.0.1 |
| 签名密钥 | 每次启动随机生成 | 从文件读（KMS / 密钥管理服务挂载为只读文件），不生成、不打印 |
| 吊销订阅 | 可选 | 网关、检索、分发、支持、通知、中继必须订阅；首次取到并核验签名后才对外服务 |
| 控制面状态 | 可不落盘 | 必须封装（state_key_file）、运营审计必须落盘 |
| 上游 | 缺省 mock | 网关、检索只接真实上游（api_key_file） |

## 配置样例

控制面：

```json
{
  "role": "control-plane",
  "listen": { "host": "0.0.0.0", "port": 8443 },
  "tls": { "cert_file": "/run/secrets/cp.crt", "key_file": "/run/secrets/cp.key" },
  "service_secret_file": "/run/secrets/service-secret",
  "data_dir": "/var/lib/kwl",
  "envelope_key": { "kid": "cp-prod-1", "private_key_file": "/run/secrets/cp-envelope.pem" },
  "seat_key": { "kid": "seat-prod-1", "private_key_file": "/run/secrets/seat.pem" },
  "state_key_file": "/run/secrets/cp-state.key",
  "code_pepper_file": "/run/secrets/cp-code-pepper.key"
}
```

网关（检索把 role 改为 search；分发 dist、通知 notify 不需要 upstream；支持 support 另需 meter_key_file；控制面、支持、中继、通知可加 `ops` 开放运营接口，见下文“运营按人鉴权”）：

```json
{
  "role": "gateway",
  "listen": { "host": "0.0.0.0", "port": 8443 },
  "tls": { "cert_file": "/run/secrets/gw.crt", "key_file": "/run/secrets/gw.key" },
  "service_secret_file": "/run/secrets/service-secret",
  "control_plane": { "url": "https://cp.internal:8443", "keys_file": "/etc/kwl/cp-public-keys.json" },
  "seat_keys_file": "/etc/kwl/seat-public-keys.json",
  "data_dir": "/var/lib/kwl",
  "upstream": { "base_url": "https://api.moonshot.cn/v1", "api_key_file": "/run/secrets/moonshot.key" },
  "content_safety_policy_file": "/etc/kwl/content-safety.json"

```

## 密钥文件格式与网络前置（复核 A-15）

- `state_key_file`、`code_pepper_file`（开通码 HMAC 的胡椒，控制面必填，与签名密钥分开）、`meter_key_file`（支持服务）：32 字节十六进制；
- `service_secret_file`：至少 32 字节随机（64 位以上十六进制或 43 位以上 base64url），太弱即拒绝启动；`ops_secret_file`（共享运营口令）已停用，配置里出现即拒绝启动（v9.3 A-10）；
- 以上全部还核“是不是随机生成的”（第 14 批第二轮复核 A 余项，`scripts/lib/secret-strength.mjs`）：整串由同一片段重复、有 8 个以上连续递增或递减的字符、
  十六进制只有数字或只有字母、base64url 没有同时含大小写、含 changeme / password / secret 等占位词、解码后字节取值少于 16 种，一律拒绝启动。
  这只拦明显手填的值，不是熵估计——一律用 `openssl rand -hex 32`（或 KMS 生成）产生，不要手写；
- 服务器级参数：请求头 20 秒、整请求 60 秒（中继、分发、支持 300 秒）、keep-alive 5 秒、并发连接缺省 10,000（`max_connections` 可调）；畸形请求回 400 并断开、不记内容；
- 网络前置：TLS 必须终止在本进程，前面只能是四层负载均衡，且**必须保留客户端源地址**（直通或 PROXY 协议）——控制面的兑换限速按来源地址计；
  放在七层代理或做源地址转换的负载均衡之后，每来源 10 次/分钟会变成全平台合计 10 次/分钟。

## 运营按人鉴权（v9.3 A-10；Y2 §3.12 运营控制台；`packages/ops-auth`、`scripts/ops-cli.mjs`）

共享运营口令（`ops_secret_file` + 自报的 `x-kwl-operator` 头）已停用。每位运营人员一把（或几把）自己的签名密钥，运营请求逐个签名；云端只存公钥。

| 角色 | 做什么 | 命令（`node scripts/ops-cli.mjs …`） |
|---|---|---|
| 安全管理员 | 生成名册签名密钥（**离线保管，不放到任何服务上**）；登记、改权限、吊销运营人员；每次签发新版本名册 | `roster-keygen --kid sec-1 --out <离线目录>`；`roster add / add-key / perms / revoke --roster <名册> … --sign-key <私钥> --sign-kid sec-1 --out <名册>`；`roster show --roster <名册> --keys ops-roster-keys.json` |
| 运营人员 | 在本人电脑生成密钥（私钥 0600，不交出）；把公钥与指纹交安全管理员（当面或电话核对指纹）；从运维网段调用运营接口 | `keygen --id op_0001 --kid k1 --out ~/.kwl-ops`；`call --url … --aud control-plane --id op_0001 --kid k1 --key … --method POST --path /v1/ops/tenants --body '{…}'` |
| 审计 | 查各服务 `<data_dir>/<角色>/ops/` 下的访问审计与被拒记录；控制面写操作另进律所可见的运营审计流水（执行者为运营编号） | — |

服务配置（控制面、支持、中继、通知；其他角色配了即拒绝启动）：

```json
"ops": {
  "roster_file": "/etc/kwl/ops-roster.json",
  "roster_keys_file": "/etc/kwl/ops-roster-keys.json",
  "allow_cidrs": ["10.20.0.0/24"]
}
```

- **运营名册**（`kwl-ops-roster/1`，安全管理员签名）：每人一个运营编号（`op_` 加工号，**不用姓名**——会进律所可见的流水，流水不可删）、权限、公钥（Ed25519；P-256 可放 USBKey）、状态。
  权限：`tenant.read`、`tenant.manage`（开通、续订、终止）、`activation.issue`（发与作废开通码）、`quota.manage`（加量、代设上限）、`device.revoke`（吊销设备与席位）、
  `support.read` / `support.delete`（诊断包查看 / 删除）、`relay.reset`（中继按事项重置）、`tenant.purge`（中继、通知按租户整体删除）。
- **吊销**：`roster revoke --id <人>` 把此人标为吊销（`--kid` 只删丢失的那一把密钥）；新名册换上去即生效（服务每次运营请求都核对名册，文件有变化或满 30 秒重新核验），不需要重启。
- **回滚保护**：服务在 `ops/roster-seen.json` 记下见过的最高版本与摘要；换回旧版本（被吊销者仍有效的那一版）或同版本不同内容，运营接口整组失败关闭（503 `ops_roster_unavailable`），重启后同样不认；名册签名不符、缺失时同样处理；启动时名册不可用即拒绝启动。
- **请求签名**：头 `x-kwl-op`、`x-kwl-op-key`、`x-kwl-op-ts`、`x-kwl-op-nonce`、`x-kwl-op-sig`，签“服务 + 方法 + 路径（原样）+ 请求体摘要 + 运营编号 + 密钥编号 + 时刻 + 随机数”；时刻偏差 ≤ 5 分钟；随机数落盘（`ops/nonces.jsonl`），重启后也不能重放。
- **来源**：运营路径（`/v1/ops/…`、`/v1/support|relay|notify/ops/…`）只放行 `allow_cidrs` 里的来源（运维网段 / 堡垒机出口；不许 /0），其他来源与没有配置 `ops` 时在入口一律 404。
- **控制面运营接口**（最小集）：`POST /v1/ops/tenants`（开通，一律要求开通码）、`GET /v1/ops/tenants/<租户>`（概要，不含成员姓名与标识）、`POST …/activation-codes`、`POST …/activation-codes/<编号>/revoke`、
  `POST …/renew`、`POST …/terminate`、`POST …/points`、`POST …/cap`、`POST …/devices/<设备>/revoke`、`POST …/seats/<成员>/revoke`。
- **审计**：控制面 `ops/access.jsonl`（每个通过鉴权的运营请求先记“已请求”、记不进去即不执行，执行后补记结果）；支持、中继、通知的访问审计记运营编号与密钥编号；各服务 `ops/rejects.jsonl` 记被拒的运营请求（声称的编号、原因、路径；每分钟至多 60 条）。
- **未做**（偏离登记 D-106、D-107）：堡垒机、会话录像与真实双因素（名册 `second_factor` 只认 `none`，标了别的而服务没接核验器即拒绝）；敏感操作双人复核；运营接口独立监听；多实例共享随机数与名册版本记录。

## 可观测性（v9.3 A-9；Y2 §6.1、§6.2；`scripts/lib/obs.mjs`）

每个角色都由入口统一记录，**只计量、不留内容**：

| 项 | 位置与内容 | 不记 |
|---|---|---|
| 访问日志 | `<log_dir>/access-YYYY-MM-DD.jsonl`（`log_dir` 缺省 `<data_dir>/obs`，两者都没有即拒绝启动）；每行只有 `at, role, method, path, status, latency_ms, client_request_id, net`：路径去掉查询串、至多 200 字；请求编号只认闸门的合格形状；来源只留网段（IPv4 /24、IPv6 /48） | 查询串、请求头（含 `authorization`、`x-kwl-sig`）、请求体与响应体 |
| 错误日志 | `<log_dir>/error-YYYY-MM-DD.jsonl`：进程级未处理异常只记 `at, role, kind, code`（错误代码或类别），随后进程退出由编排重启 | 异常消息、堆栈（可能带用户输入） |
| 保留期 | `log_retention_days`（缺省 190 天，满足计量与访问日志 ≥ 6 个月）；启动时与每 6 小时删除过期文件（只删本模块写的文件名） | — |
| 健康检查 | 服务端口上的 `GET /healthz`（进程活着）、`GET /readyz`（控制面以外的角色：2 分钟内取到过控制面吊销集，否则 503 `feed_stale`） | 不需凭据、不含内容 |
| 指标 | 单独的监听 `"metrics": { "host": "127.0.0.1", "port": 9464, "token_file": "..." }`；`GET /metrics` 为 Prometheus 文本格式；监听回环以外的地址必须配置令牌（至少 32 字节随机，`Authorization: Bearer`） | 路径、请求编号、地址、租户 |

指标与 Y2 §6.2 告警的对应（告警规则由运维在监控系统里配置）：

| 告警（Y2 §6.2） | 指标 | 建议规则 |
|---|---|---|
| 网关 5xx 比例 | `kwl_requests_total{role="gateway",code_class="5xx"}` / 全部 | > 2% 持续 5 分钟，P2 |
| 订阅滞后 / 撤权传播时延 | `kwl_feed_age_seconds` | > 120 秒 P2；> 60 秒且控制面刚发吊销 P1（`/readyz` 同时变 503） |
| 证书到期 | `kwl_tls_cert_expiry_seconds` | < 30 天 P2；< 7 天 P1 |
| 进程异常 | `kwl_process_errors_total` | 任意增长 P2 |
| 日志写不出 | `kwl_log_write_errors_total` | 任意增长 P1（视同计量缺失） |
| 请求耗时 | `kwl_request_duration_seconds` | 按角色 P99 设基线 |

上游 429 比例、签名服务错误、额度租约拒绝、提醒投递延迟需要服务内部计数，随签名服务与 PostgreSQL 一起做（差距清单 A-8、A-7）。
门禁：`services/control-plane/test/cloud-obs.test.ts`（访问日志与错误日志逐行只有白名单字段、内容不落盘；云端服务与入口源码里 console 输出不带异常消息、请求、请求头或请求体）；
`cloud-serve.test.ts`（没有日志位置拒绝启动、指标监听在回环以外没有令牌拒绝启动、HTTPS 上的健康检查、指标、访问日志不含查询串）。

## 与客户端钉住的关系

客户端按 `release.json` 钉住各服务证书的 SPKI（至少两把：当前 + 备份）。证书续期须复用密钥对或预置备用钉住；服务前不得放解密型 WAF/CDN（调研 Y2 §2）。
