# 诉讼成本与回收测算

## 1. 适用范围
- **交付**：①《测算说明》.docx（主交付物）——给律师与客户决策人读的说明，结论在前，一般两三页；②《诉讼成本与回收测算》.xlsx（附件）——由 `calc.litigation_budget` 带 `title` 直接生成（情景测算、请求与支持比例、费用明细、和解持平点、和解方案比较、口径与假设），数字由系统写入，主表带公式，不用 `xlsx.render_table` 另出。
- **做什么**：费用按《诉讼费用交纳办法》由工具算（一审受理费、简易程序减半、保全申请费、二审按上诉请求数额、被告被强制执行时的申请执行费）；律师费、鉴定费、公证费、保全担保费按律师给的或委托合同、报价单上的数；按情景并列净回收或总支出，算和解持平点与和解方案比较。
- **不做什么**：
  - **不给胜诉率、概率、期望值或加权平均**（工作准则第 7 条）。情景是“如果法院支持这些”的测算，每个情景写清是哪个争点怎样认定时出现，由律师判断哪个更接近。外部做法里常见的“争议金额 × 胜诉概率 − 成本”一律不用。
  - 不评估对方的履行能力、不推测对方财产：回收比例是假设，按材料里的保全结果、财产线索写；没有的写明是假设。
  - 不出律师工时单、费用单、预算执行报告（律所内部管理，不在本方法范围）。
  - 不起草起诉状、上诉状或和解协议（→ 对应方法）。本测算是给律师与客户的内部决策底稿，不作为任何递交文书的附件。

## 2. 输入与前置检查
1. **我方地位**（方法参数 `side`）：原告（申请人）或被告（被申请人）。没填的从事项立场判断；判断不了的问。
2. **阶段**（方法参数 `stage`）：尚未起诉 / 已立案一审中 / 一审判决后（考虑上诉）。已立案的受理费、保全费已经预交，属于已发生；一审判决后的，“请求”按判决与上诉范围写（见第 3 节第 2 步）。
3. **请求项目与金额**：从起诉状、仲裁申请书、律师函或判决的请求部分逐项摘（逐字摘录出处）；被告视角写对方的请求。利息、违约金只写了口径没写数的，先用 `calc.ledger` 按请求口径算到分析截止日，再把算出的数作为请求金额——不心算。请求里已有律师费的（合同约定由违约方承担），作为一项请求写进 `claims`，同时它也是我方要付的成本，写进 `costs`；两处都写是对的（一处是能向对方要回的，一处是要付给律所的），工具会提示复核是否重复。
4. **律师费**（方法参数 `fee_arrangement`）：按委托合同或律师给的写，分阶段（一审、二审、执行）；风险代理按收回金额比例的写 `contingency_rate`（如 0.1）。都没有的不估，按 0 计并在答复第一段写明“未计律师费，净回收偏高”。
5. **保全**：材料里有保全申请或裁定的，保全财产数额照写；担保费用律师给的保险保函报价，没有的按 0 计并提示。
6. **回收比例**（方法参数 `recovery`）：已保全到足额财产或对方明显有履行能力的，写 1；律师选“并列全部与一半”的写 [1, 0.5]；材料显示对方经营异常、有大量被执行记录的，写律师给的比例，没有的并列 [1, 0.5, 0] 并写明是假设、建议先做财产调查。
7. **和解金额**（方法参数 `offer`）：对方提议或客户拟提的和解金额，写进 `settlement_offers`；没有的只算持平点。
8. **我方对对方另有的请求**（被告视角必问，第 65 批真实验收：没问，测算写成“材料未载明我方债权”，而律师手里有 31 万未收货款）：我方对原告有没有未收款项、可反诉或抵销的请求——任务说明与材料里没有的，和律师费、回收比例等缺项合并成**一次**提问（工作准则第 6 条）；有的写进第六节，作为和解筹码与一揽子处理的考虑，不并入本案测算的数字。

## 3. 步骤
1. **读材料**（`materials.list` / `materials.read_excerpt`）：请求、合同里的律师费与违约金约定、委托合同、保全材料、和解往来、对方的财产线索；读一审判决的（一审判决后），判项与金额逐字摘。
2. **定情景**：情景要对应真实的争点，而不是机械的比例。先列本案决定金额的争点（如“质保金是否已到期”“违约金是否被调减”“质量问题是否成立、减价多少”），每个情景写清“如果这个争点怎样认定，支持哪几项、各支持多少”：
   - 至少有“全部支持”与“全部驳回”两端；中间情景按争点写，用 `items` 逐项给比例（如 `{"货款本金": 1, "逾期付款违约金": 0.3}`），不要只写一个笼统的“支持 60%”。
   - **履行期尚未届满的请求不放进“现在起诉”的情景**（第 65 批真实验收 v39-B1：未到期的质保金被算进“全部支持”，结论第一句的净回收因此偏高）：法院对起诉时尚未到期的债权不会判令给付。`calc.ledger` 汇总里“履行期未届满的本金”那部分，照样写进 `claims`，但标 `not_yet_due: true` 并写 `due_on`——工具会把它排除出本次诉讼的请求、受理费与各情景；对方的和解方案一并了结这部分的（一揽子了结，缺省），工具按“现在起诉的净额 ＋ 到期后另行收回”比较，和解不含它的写 `settlement_covers_not_due: false`。说明里写明这一项到期日、到期后追加请求或另诉，以及和解一揽子了结它对比较结果的影响（第 65 批真实验收 v39-B1：手工比较漏了这一点，有一个情景的比较方向因此反了）。
   - **金额本身有争议的请求要有“部分成立”的情景**（第 65 批真实验收两轮都缺：对方主张减价 115,800 元，只设了“全部成立 / 不成立”）：部分成立的数额要有来源——双方各自主张的数（对方的减价比例与我方可接受的比例）、材料里的检测或评估数、合同约定的计算方法；都没有的才用敏感性假设，并写明是假设和理由，不用没有来由的“50%”。
   - 违约金可能被调减的，调减后的比例按 `calc.ledger` 的 `penalty_check` 参照值写（合同编通则解释第六十五条“超过造成损失的百分之三十”的参照，是参照不是结论）；没有损失数据的写明按哪个假设。
   - 一审判决后：原告视角的请求写一审判决未支持而我方拟上诉的部分以外的原判金额与上诉部分，情景写“二审维持”“二审改判支持上诉请求”等；被告视角同理。`appeal: true` 时工具按我方就不利部分上诉计二审受理费。
   - 情景不超过 6 个；每个情景写进《测算说明》的“情景与对应的争点”表：情景名 / 决定它的争点与认定 / 支持哪些 / 主要依据或证据（逐字出处）。
3. **调用 `calc.litigation_budget`**（一次调用、带 `title: 诉讼成本与回收测算-<案件简称>`）：`side`、`claims`、`scenarios`、`costs`（stage 与 incurred：已付或已确定要付、和解也省不下的写 true）、`preservation`、`filed`、`simple_procedure`（律师说适用简易程序或明显适用的）、`appeal`、`collection`、`settlement_offers`；仲裁的写 `forum: "arbitration"` 与律师按机构费用表给的 `arbitration_fee_yuan`。要改数就改参数、用同一个 `title` 重新调用，不用 `xlsx.render_table` 重抄。
4. **写《测算说明》**（`docx.render_report`，title：`测算说明-<案件简称>`），按这个顺序（一～七节）：
   - **一、结论**（一段话，客户能直接读）：各情景下我方净回收（或总支出）各是多少；对方给的和解金额比各情景多得或少付多少；和解金额达到多少时与哪个情景持平。数字逐字照抄工具返回值。**不写**“大概率”“期望收益”“胜算”“建议接受和解”——写成“如……则……”，和不和解是客户的决定（工作准则第 6 条）。
   - **二、情景与对应的争点**（上面第 2 步的表）。
   - **三、费用**：逐项列费用、负担与依据（工具返回的 `basis`，条号照抄），写明“按《诉讼费用交纳办法》预估，以受理法院的交费通知为准”；部分胜诉时受理费按支持比例分担是测算口径，实际由法院决定（第二十九条第二款）。
   - **四、和解比较**：持平点与方案比较；已立案的，撤诉或调解结案受理费减半、调解结案的负担由双方协商（第十五条、第三十一条），工具已按“我方负担减半后的受理费”测算，写明这个假设。
   - **五、假设与还缺什么**：回收比例、律师费、担保费、仲裁费的来源；工具 `warnings` 里缺的数逐条列出，写明补上后会怎样变化（例如“未计二审律师费，二审情景的净回收偏高”）。
   - **六、会改变测算的程序节点**（已立案或已收到起诉的必写）：答辩期届满日（`calc.deadline` 程序期间目录 `defense_first_instance`）、要不要在答辩期内提管辖权异议、举证期限；我方对对方另有债权的（如未收的货款），写明可以反诉或另诉、和解时可一揽子处理或抵销——这些决定和解的时点与筹码，只列出、不替客户决定；尚未起诉的写诉讼时效届满日与对方先诉、转移财产的风险（是否保全）。
   - **七、不在测算里的因素**：时间（一审、二审、执行各需的周期按律师经验补）、资金占用、商誉与合作关系、对方可能的反诉或上诉——只列出，不量化。
5. **自查**后在最终答复里写：用了哪些假设、哪些数是律师给的、还缺什么。

## 4. 工具调用约定
| 工具 | 用途 |
|---|---|
| materials.list / materials.read_excerpt | 读请求、合同、委托合同、保全与和解材料（逐字摘录） |
| calc.ledger | 请求里的利息、违约金先算出金额；`penalty_check` 作违约金调减情景的参照 |
| calc.litigation_budget | 费用、情景、持平点与和解比较一次算完，带 title 直接成表 |
| calc.court_fee | 只单独问某一项费用时用；做本测算时不要另算一遍 |
| law.get_article / citations.verify | 《测算说明》里引的条文（工具 basis 之外另引的）按分析截止日核验 |
| docx.render_report / docx.edit_draft | 出《测算说明》；改几处用 edit_draft |

## 5. 输出规格
- 《诉讼成本与回收测算》.xlsx 由工具生成，不另建表，不手改数字。
- 《测算说明》.docx：标题、致（客户或内部）、一～七节；金额一律写到元或分并与工具返回值逐字一致；不出现概率、百分比形式的胜诉判断（支持比例、回收比例这类测算参数可以写百分数，并写明是假设）。

## 6. 质量自检
- [ ] 每个情景都写了对应的争点与认定，不是机械的“支持 X%”；两端（全部支持、全部驳回）都在；“现在起诉”的情景里没有履行期尚未届满的请求。
- [ ] 说明里每个金额都来自 `calc.litigation_budget`（或 `calc.ledger`）的返回值，没有心算、没有另算一套。
- [ ] 没有“胜诉率”“概率”“期望”“大概率”“加权”，也没有替客户决定和不和解、上不上诉。
- [ ] 律师费、担保费、仲裁费、回收比例写明了来源（委托合同、报价、律师告知、假设）；缺的列进第五节并在答复第一段写明。
- [ ] 已立案的成本标了已发生；和解测算写明了受理费减半与负担的假设。
- [ ] 请求与成本里都有律师费时，确认了一项是向对方主张、一项是付给律所，没有重复。
- [ ] 已立案的写了答辩期届满日与管辖异议、反诉或抵销的考虑；尚未起诉的写了时效与保全的考虑。
- [ ] 测算表没有列为任何递交文书的附件。

## 7. 禁止事项
- 不写胜诉率、概率、期望值；不按概率加权；不写“建议接受 / 拒绝和解”。
- 不估律师费、担保费、鉴定费；不推测对方财产或履行能力。
- 不把测算口径写成法院一定会这样分担费用。

## 8. 依赖缺失时的降级
按工作准则第 5 条处理；与之不同的：`calc.litigation_budget` 不可用的，用 `calc.court_fee` 逐项算费用，情景表用 `xlsx.render_table` 出，说明里写明“各情景净额为人工汇总，请律师复核”。
