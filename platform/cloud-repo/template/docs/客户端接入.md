# Windows 客户端接入本云端

面向两类人：**运维**（交付材料给客户端团队、确认接入是否成功）和**客户端构建人员**（把云端地址打进 exe）。

## 1. 原理：exe 只认打包时写进去的一份 `release.json`

- 云端地址、每个服务的 TLS 公钥钉住值（当前 + 备份，至少两把）、控制面文档签名公钥与席位令牌公钥，都写在安装包内的 `apps/desktop/electron/release.json`（打进 asar，受完整性校验保护）。
- 安装包形态下客户端**忽略一切环境变量**（`ZR_*` 全部剔除），改 hosts 或环境变量都不能把 exe 指到别处。
- **证书必须是公共 CA 签发的**：客户端只信任公共根证书，再核对钉住值；不认系统证书库、内部 CA 或代理证书。控制面、网关、检索用内部 CA 证书时，exe 一律“连不上中软服务”。
- **改这些要重打 exe**：控制面 / 网关 / 检索换域名或端口；服务证书换成钉住集之外的新密钥；控制面签名公钥轮换超出预置的“下一把”。
- **改这些不用重打 exe**（都在云端控制台）：上游模型 Base URL、型号、上游密钥、故障切换、套餐与额度、价目、注册策略、账号与权限。

## 2. 运维要交给客户端团队的材料

部署完成、三个对外服务都能从公网访问后，交这几样（都不是机密）：

| 材料 | 从哪来 |
|---|---|
| 控制面、网关、检索的地址（含端口），如 `https://cp.kwl.example.com:8443`、`https://gw.kwl.example.com:8444/v1`、`https://search.kwl.example.com:8445/v1/search` | 部署手册第 1 节的规划 |
| 每个服务的**备用 TLS 公钥**（`*.backup.pub.pem`） | 部署手册第 4 节“备份钉住”生成的 |
| `public/cp-public-keys.json`、`public/seat-public-keys.json` | `cloud-init-secrets.mjs` 的输出 |
| 内部 CA 证书（只有用内部 CA 签对外证书时；生产建议对外用公共 CA） | 部署手册第 4 节 |

样例说明文件：`deploy/client-release-spec.example.json`。

## 3. 客户端团队生成 `release.json` 并打包（在客户端仓库里做）

```bash
# 能连上线上服务的电脑上（在线取当前钉住值，再加上备份钉住；用客户端同一份校验代码核对，有问题不写文件）
node scripts/make-release-config.mjs --spec release-spec.json --out apps/desktop/electron/release.json
# 正式构建缺 release.json 会直接失败（第 46 批起）
node scripts/package-desktop.mjs
```

推荐用客户端仓库的 GitHub Actions `windows-desktop`：仓库变量 `KWL_RELEASE_JSON` 放 `release.json` 全文。

**不要再用 `--trial` 试用构建**（它把上游密钥封进 exe）。试用改为“开通码注册 + 试用套餐”，或运营在控制台把注册设为 `open`。

## 4. 律师第一次打开 exe 时发生什么

```
登录/注册页 ──邮箱+密码──▶ 控制面 /v1/auth/login|register
     │                          │ 返回会话 + onboarding.state
     ▼                          ▼
 needs_founder_setup  本所第一台电脑：本机生成律所根密钥、登记设备 → 重启 → 进入工作台
 needs_device_join    已有律所的成员 / 同账号的新电脑：本机生成设备密钥、提交入组申请 → 显示 12 位核对码
                      → 律所管理员在**他的电脑上**“设置 → 管理 → 成员”核对并批准 → 本机自动完成
 device_limit         这个账号的电脑数已满：先在网页控制台“我的 → 我的电脑”或另一台电脑上解绑一台
 device_mismatch      这台电脑已登记为另一位成员：用那位成员的账号登录
 ready                这台电脑本来就是这个账号的设备：直接进入
```

之后每次请求模型：

```
律师发起任务 → 本机内核（先检查：登录是否有效、本所额度是否暂停）→ 本机出站闸门（令牌化）
  → 席位令牌（控制面签、72～96 小时，每 10 分钟自动续）→ 法律模型网关 /v1/chat/completions（别名 legal/k3、legal/k2.6）
  → 网关按控制台里的路由选上游与型号 → 中软 MaaS → 网关逐请求记账 → 控制面账本 → 额度百分比回到客户端与控制台
```

- 首次登录进入首页时出现“上手清单”（建事项 → 加材料 → 发起第一个任务 → 看成果），可随时在 设置 → 通用 重新打开。
- 退出登录、会话过期（空闲 30 天）、账号被停用：AI 暂停、本机资料照常，顶部提示重新登录。网关在 15 秒内拒绝这台电脑的请求。
- 客户端版本低于控制面配置的 `clients.min_version`：登录与续席位令牌时提示“客户端版本过旧，请升级到 x.y.z 或以上”。
- 平台人员（中软运营）的账号不能登录 exe，只能用网页控制台。

## 5. 运维如何确认接入成功

1. 控制台“平台运营 → 设备”出现这台电脑，“最近报到”在几分钟内、客户端版本正确。
2. 让律师发一个小任务；控制台“平台运营 → 用量 → 逐请求明细”出现新行：律所、账号、别名、上游、上游型号、token、`usage_source = upstream`。
3. 律师端“设置 → 套餐与用量”（或左下角头像菜单里的额度一行）的百分比与控制台“客户 → 该律所 → 用量”一致；律师端“我的使用明细（最近 20 条）”的每一行（时间、问答或任务、模型、token、计入额度）能在控制台“平台运营 → 用量 → 逐请求明细”按时间对上（客户端 1.0 起；控制面 v1.0.6 起才有这一节，更早的控制面上律师端不显示）。

## 6. 律师看到的提示与对应原因

| 律师看到 | 原因（错误码） | 处理 |
|---|---|---|
| 连不上中软服务，请检查网络后重试 | 网络、防火墙、证书钉住不符（续期换了钉住集之外的密钥）、时钟偏差 > 5 分钟 | 先查律师网络与时钟；再查服务证书是否还是原密钥 |
| 登录已失效，请重新登录 | `session_invalid/expired`、`seat_session_inactive` | 重新登录；运营可在控制台看会话列表 |
| 账号已停用，请联系管理员（第 47 批起：AI 请求被拒的同时，律师端立即切到“需要重新登录”，不再等 10 分钟同步） | `account_disabled` | 律所管理员在网页控制台“本所 → 成员”启用；启用后律师重新登录即恢复 |
| 问答里“K2.6 这个模型暂不可用，请换 K3 再问” | 503 `price_unconfigured`、`model_not_routed` 等 | 控制台“平台运营 → 模型与路由”给 `legal/k2.6` 定价并配好上游；或让律师用 K3 |
| 本所本月 AI 额度已用完（首页输入框上方提示条同时变红：“新任务暂不能发起”） | 402 `quota_exhausted` | 运营加量或改套餐 |
| 首页提示条“本所本月额度已不足 10%，将于 MM-DD 重置” | 剩余比例 < 10%（不是错误） | 提前与律所沟通加量；律师可点“×”本期不再提示 |
| 已到律所设的上限 | 402 `quota_cap_reached` | 律所管理员在“本所 → 概览”调上限 |
| 最近 5 小时用得太快，hh:mm 起恢复 | 402 `quota_burst` | 等窗口滚动，或运营调套餐的 5 小时窗口 |
| 客户端版本过旧，请升级到 x.y.z 或以上 | 426 `client_outdated` | 发新版 exe |
| 这个账号的电脑数已满 | `device_limit` | 解绑一台，或律所管理员提高该成员的设备数 |
