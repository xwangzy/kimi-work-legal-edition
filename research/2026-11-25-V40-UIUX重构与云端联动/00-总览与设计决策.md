## 1. 判断与取舍（第一性原理）

| 问题 | 判断 | 决定 |
|---|---|---|
| 论点确认卡信息堆叠 | 律师在这一步要做的是“定哪些论点、依据能不能用、哪些事实我认”。原卡把依据核验、要件、事实、条文、反驳一次铺开，要律师自己在长页里找“要我定什么” | 三层：卡头（要确认什么 + 一句规则）→“需要你判断”（未核实依据、类推、待证要件、未确认事实，点一条展开对应论点）→ 论点列表（默认只显示论点与一行概况，细节按需展开）；底部固定操作区。决定的数据结构与内核接口不变 |
| 开始面板冗长 | 一列从上到下：材料、案情、当事人、要定的事、得到什么、用量、去向，主按钮在很远的地方 | 两栏：左边“你给什么、要定什么”（编号 1/2/3），右边“你得到什么、预计用量、发送什么”；材料清单收成细边框列表，用途标签平时只显示已标的；有材料时案情栏收成一行 |
| 成果页只是列表 | 律师要“找到 → 看一眼 → 决定下一步”，原来点一行就跳到复核页 | 工作区：左列表右预览（≥1100px），预览头给状态、版本切换、归属（事项 · 任务）、按状态给一个主操作；窄窗口仍直达复核页 |
| 文件与事项关系 | 事项是保密、授权、代号表、加密、生命周期的边界；文件的“归属”就是“落在哪个委托的保密范围里” | 不建独立文件 Workspace（会产生无归属文件与跨事项误用通道）；在事项体系上增强：首页 @材料 直接上传、没选事项先选或新建、同内容去重、可移除误放材料、材料↔任务↔成果互链（详见 audit-B 第 5 节、impl-B） |
| 模型写死 K3 | 网关早已按别名动态路由，缺的是“客户端看得到、能选、选了真生效” | 控制面签名下发模型目录（按套餐与路由算可用与原因，不含上游信息与密钥）；内核缓存校验；问答与任务都带所选模型；网关先判权限后判价格（详见 impl-M） |
| 设备批准与上限 | 新电脑要“另一台批准”是因为证书只能由律所根私钥签发；个人工作区本来各机独立，私钥不必搬 | 仅对个人租户由控制面签发设备证书、取消台数上限（保留防滥用硬上限与滚动吊销），团队功能仍只认律所根证书；补新设备提醒与可疑时暂停（详见 impl-D） |
| 企业概念与研发状态 | 个人律师不需要“本所本月已用”“本机运行 · 防护正常” | 菜单只留“套餐与用量 · 已用 x%”；状态行只在有问题时出现；套餐与用量页只讲个人（权益、%、剩余、周期、重置、按模型、明细）；本所额度与上限移到“管理 · 用量与上限”与云端控制台 |
| 首页页脚 | 一句固定的“试用中 · 须复核 · 数据去向” | 删除；这些说明在开始面板右栏、复核页与“设置 · 数据去向”按场景出现 |
| 设置页跳动 | 表单页签 860px、其余 1120px 且居中；滚动条时有时无 | 一个版心 920px 给所有页签；主区预留滚动条位置；大块内容撑满版心 |

## 2. 设计规范（本批新增，供后续沿用）

- 卡片外观：白底、1px 细边框、16px 圆角、轻阴影；标题 15px 半粗；说明 13px 次要色；确认类卡片不再用左侧色条。
- 信息分层：先结论与“要你定的事”，再概况，细节按需展开；同一屏只有一个主按钮。
- 状态表达：带色点的文字（草稿灰、待复核橙、已签发绿、退回红）；“需要你判断”用浅橙底块。
- 进度与用量：比例来自云端真实记录；进度条可按模型分段；只显示百分比，不显示金额与点数。
- 上传：任何上传入口都写明“存入哪个事项”，进度逐份显示，结果逐条说明（已存入 / 已在本事项未重复保存 / 失败原因）。

## 5. 遗留问题与风险（如实）

1. 评审认为的“首页事项条并进输入框”“设置页正式空状态”“材料超过 8 份时的筛选框”“成果列表加版本 / 复核人列”没有做。
2. Windows EXE 只能经桌面仓库的 Windows CI 构建（推分支、建预发布、触发工作流）——涉及推送，等用户同意；DMG 已在本机构建并签名清单。
3. DMG 冒烟卡在首次启动的 macOS 钥匙串授权（未签名副本必然出现，需本人点“允许”）；本批没有在 Windows 真机、也没有在线上云端（1.2.2）上验证 0.6.0。
4. 云端 1.3.0 需运维部署；部署前 0.6.0 对线上走兼容回退（内置模型、批准流程、个人页回退字段）。
5. 账号设备签发钥只存一把，轮换会让已签的个人电脑证书失效；自动登记的电脑做的恢复包恢复时仍被拒（impl-D §8）。
6. 同事电脑上的已移除材料副本不会随之擦除（既有同步问题，impl-B）；案卷文件夹同步对律师移除的文件仍提示“国家秘密标志”（说明文字不对，行为正确）。
7. 本批改动全部未提交；提交、合并、推送须用户同意。
