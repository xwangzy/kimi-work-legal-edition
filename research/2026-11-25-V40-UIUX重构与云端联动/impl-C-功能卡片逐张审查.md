## 一、统一卡片规范（V40-C）

布局由 `ScenarioStart` 决定（材料 → 当事人 → 这次要定的事 → 更多选项 → 补充要求；右栏 你得到什么 / 预计用量 / 发送什么）。卡片侧按下面的规范写：

| 项 | 规范 | 理由 |
| --- | --- | --- |
| `gives`（材料段说明） | 一句话 ≤ 40 字，只说“给什么材料”，可选的写“可一并勾选”“也可直接写案情”。**不写处理口径**（“事实已确认最好；未确认的正文写得保守……”） | 面板里已有事实计数行与发起确认；口径写在卡上把材料说明撑成两三行 |
| `gets`（交付件） | 文件名与方法 `outputs` 一致（b55 契约用例守着）；文件名后的括注只留 ≤ 8 字的定位（附件、内部用、可选、签署栏留空）；说明性长括注删掉 | 副标题 `得到：…` 与右栏都直接显示 `getsPlain`，长括注让副标题溢出（审合同原 92 字） |
| 主区字段 | 必填 ≤ 2；主区（不含补充要求）≤ 3，硬上限 4；必填排最前 | 首屏只放每次都要定、只有律师能定的事 |
| 更多选项 | 能从材料读出的（入职日期、生效日期）、有缺省口径的（利率口径、争议解决、担保方式）、事项层已有的（事件时点、地域）、成对出现的次要项（上诉范围 + 不服的判项） | 收起不等于不收：律师知道时照样能填，填过的自动展开 |
| 必填 | 只给不可补救的期限起算日、决定交付物形态或主请求的那一栏 | 第 55 批原则不变 |
| `label` | ≤ 8 字（标签列 120px，超出折行）；不带“（可空）”“（一句话即可）”等括注——可选是缺省，必填有 * | 原有 20 处标签折成两三行 |
| `help` | ≤ 30 字，只写“怎么填 / 不填会怎样”，句末不加句号；写“不填会……”的必须有方法正文或内核依据 | 原有 help 最长 56 字 |
| `placeholder` | 以“例如：”开头给真实示例；不写“可空”“可选”，用途说明进 `help` | placeholder 一输入就消失，说明放在里面律师看不到 |
| `steps` | 3～6 条，每条 ≤ 24 字，说做什么；口径细节不进步骤 | 折叠区展开后一屏看完 |
| `verb` | “开始 + 动词”（开始起草 / 审查 / 整理 / 核查…） | 已符合，未改 |
| 同义字段同名 | 诉讼地位一律“我方地位”；当事人身份（劳动者、买方、拟起诉）一律“我方是”；起算日一律“收到 X 日期 / 文书送达日期”并在 help 写“从这天起算” | 跨卡一致 |
| 不重复收事项已有的 | 立场 → `side` 按事项立场预选；合同类型按文件名预选；当事人存一次（D-224）；事件时点、地域在事项上（顶部补全提示，内核 `matterFactsLine` 带给助手），卡上的同类字段收进更多选项并写“事项里填过的不用再填” | 优先复用事项信息 |
| 不动的东西 | 字段 `key`、`options` 原文、`goal` 模板、`goalText`、`redirect`、`primary/primaryBy`、`args`、`needsParties`、`brief`、`minMaterials` 一律没改；没有删字段 | 这些与任务说明拼接、方法参数、主交付物核对相连 |

自动核对（改后）：52 张卡全部满足 gives ≤ 40、label ≤ 8、help ≤ 30、主区 ≤ 4、placeholder 以“例如：”开头、步骤 ≤ 24 字；唯一例外是“股东会与董事会文件”3 个必填（见第 36 行）。

## 三、给主会话的布局建议（卡片数据改不到的）

1. **必填项在首屏之外（8 张卡，1440×900，诉讼示例 5 份材料 + 当事人段）**：defense、appeal、preservation、enforcement、agency、labor-arb-application、labor-arb-defense-lit、demand-lit；pleading 的整个“这次要定的事”也在首屏外。律师第一眼只看到底部“先填写：不服的是、文书送达日期”，却看不到这两栏。建议：底部“先填写：X”做成按钮，点了滚到并聚焦第一个未填字段；或者卡片有必填项时，把“这次要定的事”排到“当事人”之前。
2. **材料列表多于 3 份时折叠**：只显示前 3 行 + “已选 5/5 份 · 展开”。段头的“已选 5/5 份 / 改为全部”与列表下“助手只读勾选的材料…”说的是同一件事，留一处即可。
3. **当事人段未填时只要一行**（现在灰框两行文字 + 段头按钮）。
4. **副标题与右栏重复**：`Modal subtitle` 的“得到：…”与右栏“你得到什么”是同一份列表。建议副标题改用 `cardGets`（去括注、一行），或去掉副标题。
5. **回稿重审也显示勾选顺序标签**：`ss-doc-row` 的“基线稿 / 对方回稿”标签目前只给 `s1b.draft_compare`，`redraft-review`（对方回稿：比对与重审）同样按勾选顺序区分两稿（`docArgsFor`），也应显示“上一稿 / 回稿”。
