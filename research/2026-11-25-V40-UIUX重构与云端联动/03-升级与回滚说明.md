# 第 66 批（V40）升级与回滚说明

版本：桌面端 **0.6.0**（原 0.5.1）、云端 **1.3.0**（原 1.2.2）。两边可以分开升级，任何先后顺序都能用（见 §3 兼容矩阵）。

## 1. 云端（运维部署）

### 1.1 变更
| 部件 | 变更 | 是否必须配置 |
|---|---|---|
| 签名服务 cp-signer | 新增“账号设备签发钥”`keys.account_device_ca`（Ed25519，kid `acct-ca-<env>-<id>`）；新操作 `POST /v1/sign/device-cert`；新信封 `kwl-model-catalog`、`kwl-usage-page`、`kwl-device-enroll` | **要**：没配时“个人账号换电脑自动登记”关闭，回落为原来的批准流程，其余照常 |
| 控制面 | `GET /v1/models`（模型目录，按套餐与路由算可用/原因，不含上游型号、地址、密钥）；`POST /v1/auth/devices/enroll`（个人租户新电脑登录即签发设备证书）；`GET /v1/quota/usage`（用量明细翻页）；`/v1/quota` 追加 `personal`、`own_models`、`plan.note/period/burst/models`（已有字段不变）；`/v1/meta` 在配置了签发钥时追加 `features: device_auto_enroll` 与 `account_device_ca.kid`；`/v1/auth/me` 追加 `personal`、`recent_logins`；模型路由记录加 description / sort / thinking / efforts / capabilities / scopes / client_visible / max_context | 否 |
| 网关 | 租约判断先判套餐权限再判价格（`model_not_allowed` 先于 `price_unconfigured`） | 否 |
| 控制台 | “模型与路由”表单加说明、排序、思考方式、档位、能力、入口、客户端可见；套餐页“电脑数”标注“仅多人律所” | 否 |
| 状态数据 | 无迁移脚本：租户 `personal` 标记、`account_device_ca`、`firm_bundle` 在读回状态时按规则补齐（一次性、幂等）；存量单人自助注册租户判为个人 | 否 |

### 1.2 步骤
1. 生成签发钥：新部署 `cloud-init-secrets.mjs` 会一并生成 `account-device-ca.pem` 并写进 `signer-keys.json.account_device_ca`；已部署环境用同一脚本的补钥方式生成一把，放到签名服务密钥目录（权限 0600）。
2. 按既有流程 `upgrade.sh` 升级到 1.3.0（自动备份、停用遗留定时器、重启 cp-signer 与控制面）。
3. 自检：`curl https://<域名>:<控制面端口>/v1/meta` 应见 `device_auto_enroll` 与 `account_device_ca.kid`；控制台“模型与路由”能看到新字段；`server_version` 为 1.3.0。
4. 如要上线“K3 高速”等新模型：在控制台“模型与路由”新增别名并选上游型号（须已在“价目”里定价），套餐“可用模型”里勾上。客户端不需要重新安装，登录后或窗口重新获得焦点时即拿到新目录。

### 1.3 回滚
- 只回滚代码：`upgrade.sh rollback`（回到 1.2.2）。新加的状态字段旧版本不读，不影响旧逻辑；已经自动签发的个人电脑证书（issuer=account_ca）在 1.2.2 的设备登记处验不过——这些电脑会要求重新登录并走批准流程。
- 签发钥目前只存一把：换钥会让已签的 account_ca 证书失效（对应电脑需重新登录）。

## 2. 客户端（桌面端 0.6.0）

### 2.1 本机数据迁移
- **0073**：`runs.model`（任务用的模型别名；旧任务为空、按 K3 处理）+ 表 `model_prefs`（问答 / 任务各记一个所选模型）。
- **0074**：`firm_identity.account_ca_public_key_pem`（个人账号设备签发钥公钥，用于本机校验自动签发的证书链）。
- 两个迁移只加可空列与新表；内核按迁移文件名补跑自己缺的迁移、不拒绝“更新的库”（`packages/kernel/src/db.ts`），所以 0.5.1 仍能打开升级过的工作区，只是忽略这两项。

### 2.2 安装
- macOS（Apple 芯片）：`KimiWorkLegal-0.6.0-arm64.dmg`，拖进“应用程序”覆盖旧版；数据、登录、事项保留。未经 Apple 公证，第一次打开用右键“打开”。
- Windows：`KimiWorkLegal-Setup-0.6.0.exe`，按用户安装，覆盖旧版。未经代码签名，SmartScreen 提示时选“仍要运行”。
- 校验：`SHA256SUMS.txt` 与发布方签名 `SHA256SUMS.txt.sig`（公钥 `release-signing.pub.pem`）。

### 2.3 回滚
重新安装 0.5.1（预发布 `installers-b64-20261125`）覆盖即可，数据、登录、事项保留。回到 0.5.1 后：任务一律按 K3 发起（记住的模型选择被忽略）；这台电脑若是控制面自动签发证书的个人电脑，0.5.1 的本机校验不认第二信任锚，会要求重新登录并走批准流程。

## 3. 兼容矩阵

| | 云端 1.2.2（未升级） | 云端 1.3.0 |

## 4. 运维注意
- 存量个人用户要先在**创始电脑**升级到 0.6.0 并联网一次（补传律所公钥包 firm_bundle），之后的新电脑才能自动登记；在那之前回落为批准流程。
- 自动登记有防滥用：每个账号最多 20 台在用，超过时自动移除最久未用的一台；24 小时内第 4 台或 1 小时内出现 3 个以上网段时暂停自动登记，要求短信验证码确认（短信通道须已配置）。
- 团队律所（多于 1 名成员或发过成员邀请）不受影响，仍走“另一台电脑批准”。
