# 现状审计摘要（基线 `bf5493a` = v18-b43 头，已含第 40～43 批）

两路只读审计的完整报告在会话 scratchpad（`audit-client.md` 333 行、`audit-cloud.md` 338 行，逐条带文件:行号）。这里只留结论。

## 1. 成熟、应当继承的

| 能力 | 位置 | 为什么不推翻 |
|---|---|---|
| 律所根签发设备证书、设备签名请求、防重放 | `packages/firm-trust`、`packages/keys`、控制面 `authDevice` | 团队共享的密钥分发与律所策略签名都建在它上面；云端只转运，云端被攻破也不能给律所铸设备 |
| 席位令牌（Ed25519、按受众拆分、72～96 小时）+ 网关验签 + 签名订阅吊销集 | `packages/seat-token`、网关 `auth`、`GatewayFeedSubscriber` | 离线可用、吊销 15 秒生效，账号闸只需在它前面加一道 |
| 签名服务独立（mTLS、签名账哈希链、按种类核对） | `services/cp-signer` | 控制面进程不持私钥 |
| 生产入口 `cloud-serve.mjs`（一进程一角色、强制 TLS、密钥强度检查、运营网段、CORS 白名单） | `scripts/cloud-serve.mjs` | 部署纪律已经固化在代码里 |
| 运营按人签名 + 安全管理员签发名册 + 访问审计 | `packages/ops-auth`、`scripts/ops-cli.mjs` | 比账号密码更强，且有职责分离 |
| 出站闸门是唯一出口、控制面通道白名单、出站登记表门禁 | `packages/egress-gate`、`docs/privacy/egress-paths.json` | 隐私承诺的执行点 |
| 网关的二次检查、内容安全、流式透传、预写计量日志 | `services/legal-gateway` | 与本批无关的部分不动 |

## 2. 缺口（本批要补的）

| 缺口 | 证据 | 本批处理 |
|---|---|---|
| **没有“登录”**：身份 = 本机设备证书，一台电脑一个成员；开通靠开通码 / 邀请码，律师不能自助注册 | `App.tsx:254` 只渲染激活页；`onboarding.ts:262-405` | 账号层（邮箱 + 密码、会话、设备上限）+ 自助注册接到现有创始开通 |
| 网关**只有一个上游、一把密钥**；型号只能用环境变量改，要重启 | `gateway.ts:87,110-131`、`cloud-serve.mjs:521-525` | 控制面路由登记 + 签名订阅下发 + 多上游切换 + 健康 + 本机白名单 |
| 计量按**固定折算**（`legal/k3` 每千 token 4 单位，输入输出同价、缓存不打折）；没有逐请求明细 | `gateway.ts:187-189,504`；`meter.jsonl` 只在网关本地 | 单位改为 tokens 或按价目表的金额；逐请求账本、按请求编号去重 |
| 控制面状态是一份整体快照，每次回报整份重写；明细放不进去 | `server.ts:363-369`、`pg-state-worker.ts:26-48` | 账本独立成只追加文件，额度与账单都从账本出 |
| 客户端断开时按预占收费（含 8192 缺省输出）；网关停机不做最终回报 | `gateway.ts:531-533`、`cloud-serve.mjs:673-683` | 断开后继续读完拿真实 usage；发件箱重放；SIGTERM 最终回报 |
| 第 40 批“Kimi 账号绑定”依赖未开放的官方接口 | `kimi-account.ts`、`KimiAccountRow` | 按本轮指令撤下 |
| 试用构建把 MaaS 密钥封进 exe | `trial-mode.cjs`（D-160） | 改为“自助注册 + 试用套餐”，手册写明不再用 `--trial` |
| 运营控制台没用桌面端设计令牌、没有路由 / 明细 / 账号页面 | `ops-console/console.css:1-30` | 重做（同源静态页 + 原生模块 + tokens.css） |
| 部署文档与代码不一致 4 处（计量顺序、断开计费、生产入口样例地址、429 指标） | `audit-cloud.md` §7 | 新手册按代码与演练重写 |

## 3. 改造边界

见主文 §0.3。最重要的一条：**不改律所根、策略签名门限与恢复托管的语义**；唯一放宽是“同一账号的新电脑入组”没有邀请码本机段，改为人工核对核对码（D-186）。
