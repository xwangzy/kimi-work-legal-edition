## 1. 腾讯 WorkBuddy（含 WorkBuddy Enterprise / WorkBuddy Managed Agents）

> 主要一手来源：腾讯云文档中心「WorkBuddy Enterprise」（product/1831）。目录显示 WorkBuddy 与 CodeBuddy、WorkBuddy Managed Agents（WMA）同属一个企业产品矩阵。抓取日期 2026-10-02。

### 1.1 关键事实（逐条带出处）

**A. Agent 循环与执行位置**
- 桌面端定位为「本地 AI 工作台」：「任务栏是 WorkBuddy 的 本地 AI 工作台入口，负责统一管理和执行所有任务」；需设置工作目录，「WorkBuddy 将在该目录中读取和保存文件」，未指定则自动创建独立目录；每个任务独立工作空间与上下文、多任务并行。【一手】https://cloud.tencent.com/document/product/1831/134391 （更新 2026-08-03）
- 工作模式三种：默认模式（高效执行）、问一问 Ask（仅问答，不修改文件）、想一想 Plan（先出计划确认后再操作）。【一手】同上
- 手机 App（2026-07-18 正式版，安卓/iOS/鸿蒙）提供两种执行模式：「连接电脑：直连本地设备，调用桌面端完整能力」；「云端工作：具备桌面端主要能力，开箱即用，支持 Skills、专家与专家团、自动化定时任务、产物下载与分享、项目管理等，并通过资料库打通腾讯文档、ima 知识库」。【二手，转述 WorkBuddy 公众号】IT之家 https://www.ithome.com/0/978/468.htm （2026-07-18）
- 鸿蒙 PC 版「支持云端工作和本机双模式运行」。【二手】爱范儿 https://www.ifanr.com/1673909 （2026-08-04）
- FAQ「是否支持云端部署或服务器安装」：「服务器端能力仍在完善中，正式支持以官方后续版本为准」。【一手】https://cloud.tencent.com/document/product/1831/134405 （更新 2026-09-07）
- 更新日志出现「云助理」（创建助理时可选仓库/分支）、「云端项目会话」「云端变更文件」「沙箱产物预览」「恢复历史会话时沙箱环境状态丢失」「子 Agent 编辑文件未走沙箱审批」等条目，说明已存在云端会话/云端沙箱形态，但官方未单独成文说明其边界。【一手】WorkBuddy 更新记录 https://cloud.tencent.com/document/product/1831/134324 （抓取 2026-10-02，含 5.2.x–5.4.x，2026-07~09）
- **WorkBuddy Managed Agents（WMA）= 云端托管 Agent 运行服务**：「提供云端托管的智能体运行服务……内置 Agent 内核编排与独立沙箱……通过控制台或 API 即可在云端运行复杂任务」。官方明确对比本地 Agent 的局限：「本地智能体‘人在电脑前才运行、单人单机、关机即停’，只能解决个人提效；满足企业级场景要求 Agent 常驻运行……被系统与事件唤醒（定时/触发式任务无需人在场）、可并发、可审计、可管理」。沙箱「1 Session : 1 沙箱」、存算分离、「7×24 小时云端运行」、「配置与运行均在云端，敏感产出物云端驻留，支持 VPC 私有网络」；网络形态「公网 / 云 VPC / 私有化」。状态：「已在腾讯云侧上线，当前在白名单内测阶段，预计10月份将同步完成 WMA 在 WorkBuddy Enterprise 管理端的升级」。「CodeBuddy / WorkBuddy 的 Agent 均可托管运行于 WMA 底座」。【一手】https://cloud.tencent.com/document/product/1831/134407 （更新 2026-09-30）
- WMA 使用说明：Agent 由 System Prompt、模型、Skills/连接器、行为约束构成，可「一键下发到 WorkBuddy 客户端供员工使用」；渠道接入「企微 Bot、QQ、钉钉、飞书等」；凭证「独立于 Agent 集中存储，运行时由连接器 / 网关换发短期令牌，Agent 不持有长期密钥」「Secret 加密存储」；自动化任务「让 Agent 按预设规则无人值守执行」。【一手】https://cloud.tencent.com/document/product/1831/138968 （更新 2026-09-30）

**B. 权限模式与沙箱**
- 两档：**默认权限**、**完全访问权限（Full Access/完全放开）**。默认权限下在工作空间内自动执行，以下操作二次确认：写入或修改工作空间外文件；删除文件或目录；执行脚本、命令或外部程序；调用敏感能力（系统级 API、权限操作等）。完全访问「会关闭上述二次确认」；从下拉切换时需「勾选风险确认」；官方建议「只在可信、隔离、可恢复的环境中短时间使用」「完全放开用完即关」，对「生产环境、重要设备、唯一文件副本」不建议开启。【一手】默认权限与安全沙箱 https://cloud.tencent.com/document/product/1831/134401 （更新 2026-09-07）
- FAQ「数据安全说明」：「Bash 命令沙箱：AI 操作与真实系统严格隔离」「文件系统隔离：只能访问预先授权的工作空间目录」「防沙箱逃逸：阻止对配置文件的写入」「默认安全设计：启动时仅拥有只读权限，编辑文件、运行命令需显式用户批准」「分层权限系统：支持 allow(允许)、ask(询问)、deny(拒绝)三种权限规则」。【一手】https://cloud.tencent.com/document/product/1831/134405 （更新 2026-09-07）
- 更新日志新增「安全中心文件修改自动备份功能」「拒绝单步权限时仅跳过当前步骤」。【一手】https://cloud.tencent.com/document/product/1831/134324

**C. 常在线能力**
- **助理（远程任务）= 本机执行的 IM 遥控**：「通过手机上的即时通讯软件（微信、企业微信、QQ、钉钉、飞书）远程控制电脑上的 WorkBuddy 执行任务」；远程任务「固定使用助理专属文件夹」「仅一个会话」「保留完整对话历史，不可清空」；注意事项「电脑需要保持开机并运行 WorkBuddy」。【一手】https://cloud.tencent.com/document/product/1831/134392 （更新 2026-09-16）
- **自动化（定时任务）= 本地客户端调度**：「自动化在本地客户端保存定时任务配置（任务名称、prompt、调度规则、工作目录、执行状态等），在指定时间以您当前的登录身份自动发起 Agent 任务」；「本地文件读写：仅在您指定的工作目录范围内访问」；可「推送到 WorkBuddy 小程序」；安全提醒「任务在无人值守下自动执行，请审慎设置涉及文件写入/删除/资金操作的 prompt」。关机是否补跑：**未查到**官方说明（WMA 文档反推本地「关机即停」）。【一手】https://cloud.tencent.com/document/product/1831/134399 （更新 2026-09-07）
- 更新日志：「新增开机自启动设置」「‘允许锁屏远程’」「提升移动端连接电脑的稳定性，改善弱网、休眠唤醒和网络切换后的同步与重连体验」「提升桌面端与移动端同步完整性，会话标题、置顶状态和顺序可正确同步」。【一手】https://cloud.tencent.com/document/product/1831/134324
- 手机「连接电脑」模式：桌面端须登录在线并允许连接；电脑关机/休眠/断网时手机显示离线、无法继续执行电脑上的文件任务。【二手】ToolNavs https://toolnavs.com/zh/article/2001-how-do-you-connect-a-workbuddy-phone-to-a-computer-remote-chat-resume-and-offlin （日期未标注）

**D. IM 接入方式**
- 企微助理：需在企业微信创建「智能机器人」（API 模式），两种接入：「长连接模式（推荐）：在 WorkBuddy 中填写 Bot ID 和 Secret 即可完成绑定……无需回填 Webhook URL」；「URL 回调模式……生成 Webhook URL 后再回填到企业微信」。也支持企微扫码「一键创建企业微信智能机器人」。普通成员可在客户端创建机器人，管理员在管理后台创建。【一手】https://cloud.tencent.com/document/product/1831/134441 （更新 2026-07-20）
- QQ 机器人：需在 QQ 开放平台（实名）创建机器人，AppID/AppSecret 填入 WorkBuddy，「WebSocket 长连接 / 使用 URL 回调」。【一手】https://cloud.tencent.com/document/product/1831/134442 （更新 2026-07-20）
- 官方口径：「通过主流 IM(企业微信、QQ、钉钉、飞书等)内置的 WebSocket 通道通信。非企业内网入侵方式，不需要在企业防火墙上开放额外端口」「内置安全通信网关，支持 Gateway Token 认证与连接鉴权」「不依赖 frp/ngrok/Tailscale 等第三方穿透工具」。→ 即**桌面端主动向 IM 平台建长连接（IM 平台云中转），无需腾讯自建中继、无需入站端口**；URL 回调模式下 Webhook 地址由 WorkBuddy 生成（推测为腾讯侧中继，文档未明说）。【一手】https://cloud.tencent.com/document/product/1831/134405

**E. 文件与数据**
- 官方口径：「数据本地执行不上传：所有数据在用户本地环境执行处理」「服务端仅处理数据片段：用后即弃，不保存，不用于模型训练」。【一手】https://cloud.tencent.com/document/product/1831/134405
- 但存在若干上云路径：产物/任务「分享」生成链接（数据管理页管理「我分享的文件/任务/发布的应用」）【一手】https://cloud.tencent.com/document/product/1831/134446 （更新 2026-09-07）；「资料库上传」、桌面端与移动端会话同步、「快捷键云同步」、企业旗舰版网盘【一手】更新记录 134324；企业版「AI 安全审计」「持续监测企业成员的 AI 会话日志……提供……完整会话回放」【一手】https://cloud.tencent.com/document/product/1831/138279 （更新 2026-09-16）→ **企业版会话日志在管理端可回放，与「数据不上传」口径并存，需区分「文件本体」与「会话内容」**。

**F. 团队与企业治理**

### 2.1 千问办公关键事实（一手：docs.qwenwork.cn，抓取 2026-10-02；文档页未标更新日期）

**A. 三端形态与执行位置**
- 产品简介：「已全面覆盖桌面端、网页端，并深度接入钉钉生态」；**桌面端**「可直接读取本地磁盘中的文档、表格、图片、视频等文件，无需重复上传或导入……处理完成后一键保存至原路径」；**网页端**「无需下载安装……使用钉钉账号或手机号登录」；「浏览器自动化……该能力目前仅客户端支持」；「云端定时任务：支持任务按设定时间在云端自动运行，并将执行结果推送至钉钉消息等指定渠道」。【一手】https://docs.qwenwork.cn/product-introduction.md
- 桌面端「安全工作环境」（高级设置）：「在你的电脑上单独开辟一块独立空间来跑任务……所有文件和数据都不会离开你的设备」「开启后，任务会在隔离的工作环境中运行，不影响你电脑上的其他文件，也不会触及真实系统」（即**本机隔离沙箱，可选开关**）。系统设置含「开机自启动」「保持系统唤醒：防止电脑在 Agent 工作时自动进入睡眠」。【一手】https://docs.qwenwork.cn/desktop/settings.md

## 6. 共性模式与对法律发行版的启示

### 6.1 主流产品的云地划分共性（归纳，依据见各节）

**放本地的（各家一致）**
1. **Agent 循环 + 本地文件读写**：WorkBuddy「本地 AI 工作台」、千问办公桌面端「直接读取本地磁盘……保存至原路径」、Kimi Work「通用型本地 Agent」、扣子桌面端、豆包工作「本地电脑」、AutoClaw/QClaw 本地 OpenClaw。均以「工作目录/工作空间」为边界。
2. **权限闸门在本机执行**：分 2–3 档（WorkBuddy 默认/完全访问；Kimi 默认/手动允许/全部），默认档对「工作空间外写入、删除、执行脚本/命令、敏感系统能力」弹确认；本机沙箱/隔离为可选增强（WorkBuddy Bash 沙箱与文件系统隔离；千问办公「安全工作环境」）。
3. **桌面定时任务本地调度，关机不跑、不补跑**：Kimi（明文「不会在下次开启时补跑」）、千问办公桌面（「睡眠或关机……无法触发」）、WorkBuddy（「在本地客户端保存定时任务配置」）。各家都用「开机自启 / 保持唤醒 / 熄屏保持运行」缓解，而非云端兜底。
4. **IM 遥控走「本机 → IM 平台」出站长连接**：WorkBuddy 明说「通过主流 IM……内置的 WebSocket 通道通信……不需要在企业防火墙上开放额外端口」「不依赖 frp/ngrok/Tailscale」；千问办公、Kimi Claw 飞书都用「长连接」。前提是**企业在 IM 平台建自建应用/智能机器人**（多数做成扫码自动创建），且**电脑必须开机在线**。
5. **模型密钥/自定义模型配置本地保存**（WorkBuddy models.json「不上传云端」、Ollama 本地模型）。

**放云端的（各家一致）**
1. **控制面**：账号与 SSO（OIDC/SAML/OAuth2 + 钉钉/飞书/企微/AD/LDAP/SCIM 同步）、席位与额度（Credits/积分，组织共享 + 个人限额）、模型目录与策略组（白/黑名单）、Skill/专家/连接器的企业市场与下发、IM 渠道开关、IP 白名单/可信设备、操作日志与用量看板——WorkBuddy Enterprise 与千问办公旗舰版几乎同构，都在厂商云后台。
2. **模型推理**：除 Ollama/私有端点外，提示词与被读取的文件片段都会发到云端模型（WorkBuddy 口径为「服务端仅处理数据片段：用后即弃，不保存，不用于模型训练」）。
3. **常在线/团队型执行**：云沙箱或云电脑（WorkBuddy 手机「云端工作」与 WMA、千问办公网页端与云端定时任务、豆包工作云电脑、扣子云电脑/云手机、Kimi Claw/MaxClaw 云 VM）——**专门用来解决「关机即停」和「多人共用一个 Agent」**。

**两端可选的**
- 执行位置（本机 vs 云沙箱）、定时任务（本地 vs 云端）、模型（厂商托管 vs 自带端点/本地模型）、部署（共享 VPC / 专享 VPC / 私有化，见 WorkBuddy 三版）。

### 6.2 「控制面在云、数据面在本地」是否普遍？
- **对带企业版的桌面 Agent 基本成立**（WorkBuddy、千问办公）：身份/策略/计费/分发在云，文件与执行在本机。Kimi Business 只做了控制面的最小子集（席位 + 管理员/成员），SSO/审计/策略**未查到**。
- **但「数据面在本地」只对「文件本体」成立，不对「会话内容」成立**，三处例外需要注意：
  1. 模型调用必然把提示词与文件片段送上云（除非私有/本地模型）；
  2. 企业审计会把会话拉到云端管理面——WorkBuddy「AI 安全审计」「持续监测企业成员的 AI 会话日志」并提供「完整会话回放」；
  3. 分享链接、资料库/云盘、移动端会话同步、网页发布都会把产物与会话放到厂商云（WorkBuddy 数据管理页、千问办公个人云盘与「我的网页」、WorkBuddy「桌面端与移动端同步」）。
- **2026-09 的新动向是「数据面也开始上云」**：腾讯 WMA（2026-09-30 文档，10 月进企业管理端）明确「配置与运行均在云端，敏感产出物云端驻留，支持 VPC 私有网络」；豆包工作伙伴以「独立组织身份」常驻群聊。厂商给出的理由是本地「关机即停、单人单机」无法满足常驻、事件触发、并发、审计。

### 6.3 对法律发行版的启示（结合律所场景）

**可以直接借鉴的做法**
1. **本机执行 + 工作空间边界 + 默认档确认**：与律所「卷宗不出所」诉求一致；确认清单可直接对标 WorkBuddy 的四类（空间外写、删除、执行脚本/程序、敏感能力）。
2. **IM 遥控走出站长连接、无入站端口**：适合律所 IT 薄弱、无公网 IP 的现实；用企业微信/钉钉/飞书**企业自建机器人**，由律所自己持有 Bot 凭证。
3. **企业 Hooks（千问办公模式）**：PreToolUse/UserPromptSubmit 由**桌面客户端调用律所自己的 HTTP 服务**——这是「控制面不经厂商云」也能做策略与审计的现成范式，契合「云端只供 token」的 v5 基线。
4. **模型策略组 + 自定义私网端点**（千问办公「私网 HTTP(S)、IP 和自定义端口」；WorkBuddy 管理员控制成员能否自带模型）：可映射为「只允许 MaaS 法律分组端点，禁止个人自带 key」。
5. **控制面能力清单**（SSO/SCIM、席位、额度、IP 白名单、操作日志、Skill 企业市场下发）是企业版的标配，律所采购时会被对标；若坚持「云端只剩 token 通道」，则这些能力需要放在**律所侧管理端**或做一个**不含业务内容的薄云控制面**——这是 v6 需要显式取舍的点（主流产品的普遍做法是放厂商云）。

**不适合律所、应禁用或改造的做法**
1. **「完全访问 / 全部」档**：WorkBuddy 自己写明对「生产环境、重要设备、唯一文件副本」不建议开启；Kimi 要求用户自担「文件被覆盖、误删……数据可能永久丢失」风险。律所卷宗常是唯一副本 → 法律版应**由管理员锁定、默认不可开启**。
2. **云端执行处理当事人材料**（手机「云端工作」、云电脑/云手机、Kimi Claw/MaxClaw 云 VM、WMA「敏感产出物云端驻留」）：与律师保密义务及「云端只供 token」基线冲突 → 法律版不提供云沙箱执行，或仅限不含当事人信息的公开检索类任务。
3. **厂商云上的会话全文审计/回放**（WorkBuddy AI 安全审计）：律所会话含委托人秘密与工作成果，审计数据应**落在律所侧**，厂商侧最多保留计量元数据（token 数、时间、席位）。
4. **公开分享链接 / 网页发布 / 个人云盘**：产物外链存在泄露风险 → 默认关闭，或仅允许律所内网/律所侧存储。
5. **IM「开放模式」与个人微信/QQ 渠道**：千问办公「开放模式：所有人和群可直接与机器人对话」会让群内任何人驱动律师电脑上的 Agent → 法律版应强制「配对/白名单」，并由管理员关闭个人微信、QQ 等消费级渠道（千问办公企业后台已有逐渠道开关可参照）。
6. **团队 Agent 拥有独立组织身份、跨群读取**（豆包工作伙伴）：律所需要案件级「信息隔离墙/利益冲突隔离」，跨群汇总信息天然冲突 → 若做团队 Agent，必须以「案件/项目空间」为权限边界，而非群聊。
7. **本地定时任务「关机不补跑」**：Kimi、千问办公均如此，对一般办公可接受，但律所的期限类任务（上诉期、举证期、诉讼时效提醒）静默漏跑不可接受 → 法律版至少需要**开机后补跑或显式提示漏跑**，或把「期限提醒」与「Agent 执行」解耦（提醒走律所侧日历/IM，不依赖 Agent 本地 cron）。
8. **从本机浏览器导入 Cookie/复用登录态**（Kimi Work 3.2.0 内置浏览器）：涉及法院诉讼服务网、裁判文书网、律协系统等账号，风险高 → 默认关闭并纳入管理员策略。
