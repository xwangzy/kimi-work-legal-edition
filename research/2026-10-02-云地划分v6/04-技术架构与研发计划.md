### 1.1 四条不可退让的工程约束（替代 v5 的三条）

1. **云端零明文持久化。** 控制面、中继、网关、公开沙箱的数据库、对象存储、日志、缓存、错误报告中不得出现客户内容、事项描述、文件名与关注名单明文（过境处理只在内存中进行）。CI 中对所有云端日志与表结构做“敏感字段与明文样本”扫描；红队每版验证。
2. **律所根信任不出律所。** 律所根私钥、事项密钥、签发私钥只在律所侧设备；控制面不能单方面生效策略、签发设备证书或解密任何东西。
3. **离开律所侧之前检查并记录。** 一切出站经出站闸门（v5 不变）；新增的中继同步、IM 直取、公开沙箱查询也写入数据去向记录。
4. **一个内核、一套语义。** 桌面、执行器、公开沙箱容器运行同一份内核与 Agent 宿主制品（v5 原则扩展到云端沙箱）。

## 2. 部署形态：同一软件，五种组合

| 组合 | 适用 | 律所侧 | 中软云端 | 说明 |
|---|---|---|---|---|
| **个人** | 专业版、单人 | 桌面 | 控制面、网关、（可选）中继作为本人多设备与备份 | — |
| **团队（零服务器，默认）** | 3–49 人团队、大多数律所 | 桌面 × N | 控制面、网关、中继、公开沙箱 | 协作、IM、手机签发、提醒全部可用；关机续跑除外 |
| **团队 + 执行器** | 有批量、夜间任务、内容型定时需求 | + 执行器 1～N 台（任何常开 Windows/Linux/NAS 容器） | 同上 | 执行器只出站；多台自动分担 |
| **律所自有存储** | 不愿任何密文出所的律所 | + 律所 S3 兼容存储（可与执行器同机） | 控制面、网关（中继不存数据，只发变更信令） | 远程办公需能访问律所存储（公网 OSS/COS 或 VPN） |
| **私有化** | 头部所、高敏律所、刑事等受限业务 | + 私有模型端点 + 律所侧网关组件；可选**控制面私有部署**（同一容器镜像） | 无（完全私有）或仅许可与更新 | 只有此组合可称“本地化部署 / 全链路本地化” |

## 3. 云端组件

### 3.1 控制面

| 服务 | 职责 | 存储 | 关键设计 |
|---|---|---|---|
| iam | 账号、登录、SSO、SCIM、MFA；签发席位令牌 | PostgreSQL | 基于 Casdoor（Apache-2.0，支持 OIDC/SAML/SCIM 与企业微信/钉钉/飞书社交登录）二次开发；律所可接自己的 IdP；**席位令牌为可离线验签的签名 JWT（有效期 ≥ 72 小时）**，网关不需要实时访问 iam |
| org | 组织、团队、角色、席位、许可 | PostgreSQL | 许可 = 中软签名的 JWT（律所 ID、版本、席位、功能、有效期），端侧离线验证，**离线有效 30 天**；过期进入“退出模式”（阅读、检索、导出、签名验证永久可用） |
| devices | 设备注册、证书目录、吊销 | PostgreSQL + tlog | 证书由律所根密钥或其签发的有期限子证书签发；批准须输入新设备显示的确认码（§7）；控制面只存储与分发；每张证书与吊销都进 tlog |
| policy | 律所策略、事项策略摘要 | PostgreSQL + tlog | 控制台编辑生成草案 → 持策略签名子证书的管理员设备签名（放宽类变更双签）→ 生效；策略带单调版本号与有效期，当前版本号进 tlog；端侧与网关只认签名且未过期的最新策略 |
| notify | 桌面推送、IM 服务商应用后端、移动 H5 | Redis/NATS | 订阅用“盲化主题”（由事项密钥派生），控制面不保存成员名单；消息体只含主题与事件序号；IM 卡片模板不含文件名、事项名与客户名 |
| queue | 任务信封 | PostgreSQL | 信封 = {任务 ID、匿名事项 ID、类型、发起设备、密文载荷引用、租约}；执行器长轮询领取；fencing 令牌防双执行 |
| scheduler | 提醒与触发 | PostgreSQL | 期限提醒由客户端注册（匿名事项 ID + 期限类型 + 时间 + 接收人）；公开监测按日触发沙箱，按全量或行业推送增量 |
| tlog | 透明日志 | 只追加存储 | Merkle 树，日签名树头；律所可下载与本所相关的条目和一致性证明离线验证。**防分叉视图**：律所内各设备经中继互相交换并比对所见树头（设备签名）；每日树头另提交第三方可信时间戳服务作见证；律所版可让执行器作为独立见证节点 |
| audit-ops | 运营审计 | PostgreSQL（≥ 6 个月） | 管理员、负责人、风控可查询与导出 |
| metering | 点数账本、额度、账单 | PostgreSQL | 网关先写本地预写日志再异步写入（控制面不可达时不阻断推理）；每日与 MaaS 消费记录对账 |
| sources | 法源服务 | 按授权缓存 | 只接受经网关第二道化名校验的 L0d 派生查询（律师确认、同意状态允许）；数据商凭据仅在此；按律所与事项匿名 ID 计量；Source Registry 规则在此强制（缓存、展示、送模型、导出） |
| cdn | 分发 | 对象存储 + CDN | 全部包签名；律所可设执行器为局域网镜像 |
| console | 管理控制台 | — | 见第 3 篇 §4 |

技术栈：TypeScript（Node 24，与本机内核同语言，共享 `domain`、`keys`、`ledger` 协议包）；PostgreSQL；NATS（信令与队列）；对象存储（中软所用境内云的 OBS/OSS，以 MaaS 现网所在云为准）；Kubernetes 多可用区部署。

### 3.2 密文中继

| 项 | 设计 |
|---|---|
| 写入 | 设备写入 `segments/{律所}/{匿名事项}/{设备}/{序号}`（只追加、不可覆盖）与 `blobs/{律所}/{sha256}`（内容寻址，幂等）；须同时带**设备证书签名**（证书有效、未吊销）与**事项写入密钥签名**（每事项一对，私钥随事项密钥分发给成员，公钥在建事项时登记到中继）。中继据此判断“这台设备持有该事项的写入权”，**不读取、不保存成员名单** |
| 读取 | 按游标增量拉取；须出示由事项密钥派生的读取令牌（中继只保存其 hash）；撤权时随事项密钥轮换一并更换 |
| 信令 | 写入后经 notify 推送“匿名事项 #m 有新事件到序号 n” |
| 删除 | 只接受事项负责人设备签名的删除请求；先由客户端轮换并销毁事项密钥（加密擦除），中继再物理删除；保全中的事项拒绝删除 |
| 配额 | 按席位计；超额提示归档 |
| 一致性 | 对象存储强一致读写（主流国内对象存储均提供写后读一致）；条件写防覆盖 |
| 律所自有存储模式 | 律所执行器运行**自托管中继**（与中软中继同一镜像，持有律所 S3 凭据），统一做签名校验、只追加与吊销；客户端只与自托管中继通信，不持有共享的 S3 凭据——否则做不到设备级写入校验与吊销；对象存储开启版本化与对象锁，防误删与勒索。中软中继不存数据，只发信令 |
| 导出 | 律所可随时全量导出本所密文与清单，用律所密钥离线解密（开放格式工具随客户端提供） |

**为什么用对象存储而不是 v5 的共享文件夹**：对象存储提供原子写入、条件写与写后读一致，没有网络文件系统的锁、乱序与同步盘冲突副本问题（v5 第 4 篇 §7.2 自己列出了这些问题）；同一套协议同时支持中软中继与律所自有存储。

### 3.3 法律推理网关

**定位**：位于中软 MaaS 法律分组之前的无状态服务，独立部署（与控制面故障隔离）。它看到的数据与 v5 中 MaaS 看到的完全相同——化名后的请求片段——但增加了五项能力。

| 能力 | 设计 |
|---|---|
| 接口 | OpenAI 兼容与 Anthropic 兼容（供本机 Kimi Code 与工作流使用）；每请求携带席位令牌、匿名事项 ID、任务 ID、步骤类型、客户端幂等 ID、出站记录 hash |
| **事项策略二次执行** | 按匿名事项 ID 取事项策略摘要（负责人设备签名，网关验签并本地缓存，TTL ≥ 72 小时）：拒绝“已拒绝云端”、L3b、L3a 未放开、“涉密”事项的请求；拒绝来自已吊销设备的请求。**能力边界**：挡得住误配置、旧客户端与吊销设备，挡不住冒报其他事项 ID 的被篡改成员终端（由异常检测事后发现）。负责人设备被吊销后，其签名的摘要有 7 天宽限，期间须完成负责人移交 |
| **占位符替换（方法资产服务端组装）** | 请求中的 `{{kwl:pack:<规则包ID>@<版本>#<段>}}` 在网关替换为中软 Playbook 正文（网关侧加密存储，按许可校验律所是否订阅该包）；客户端只持有规则 ID、标题、风险等级与展示用说明。工作流与 Agent（Kimi Code 的系统提示与 Skill 文件里放占位符）用同一机制。四项配套控制：①网关在响应头返回“展开后 token 数”，本机代理据此校正上下文用量与压缩阈值；②Agent 模式的上下文压缩作为特殊步骤由网关处理（摘要中的方法正文回写为占位符），做不到时 Agent 模式关闭客户端压缩、改为分段任务；③输出侧检测与 Playbook 正文的长片段重合（如连续 50 字以上），命中即截断并告警；④占位符带会话级 HMAC 前缀，只有本机代理注入的占位符才会被替换，客户材料中出现同样字样不会被展开。**如实评估**：方法资产仍可能经输出复述与摘要回流终端，风险为“中”，靠合同、水印与持续更新兜底 |
| **第二道化名校验** | 只用**无状态**检查：身份证号、手机号、银行卡号、统一社会信用代码、车牌、邮箱、案号等直接标识符的规则与校验位，加上通用的人名/机构名实体识别（只判断“像不像未化名的实体”）；命中即按策略拦截或回传告警。**不向网关上传任何事项的当事人名单或其 hash**——即使加盐，持有盐值的网关也能拿常见公司名、人名逐个试算，反推出“某公司是否为某事项当事人”。当事人词典只在律所侧第一道闸门使用 |
| **思考内容密封** | K3 等始终思考的模型要求下一轮原样回传 `reasoning_content`（v5 第 4 篇 §10.2），而思考内容可能复述 Playbook 正文。网关用自身密钥（按律所派生、定期轮换）把思考内容封装为不透明密文交给客户端，客户端原样存入事项账本并在下一轮带回，网关解封后转发上游——网关仍然无状态，律师电脑上没有可读的思考全文；界面只展示计划、步骤与结论依据。审计重放经网关解封（律所授权） |
| 路由与档位 | 按步骤类型选模型（K3 / K2.6 / K2.7-code），默认 `high`，按步骤下调；只在经评测等价的模型间切换；**不自动切换到其他厂商** |
| 缓存布局 | “系统提示 → 基础方法包（跨律所共享）→ 按律所派生的随机盐值块 → 本所覆盖层 → 材料片段 → 任务”；跨律所共享只到基础方法包为止（v5 审阅第 6 条） |
| **权威计量** | 按“任务模板点数 + 实耗校正”写入点数账本；平台原因失败不扣点；MaaS token 硬上限兜底 |
| 上游身份 | 以中软企业组织身份调用；不携带律所名称或律所 ID（对模型方隐去客户身份） |
| 日志 | 只记元数据；正文与错误体不落盘；配置与审计报告写入 DPA 附件 |
| **内容安全** | 中软作为生成式 AI 应用提供者（登记主体）须履行内容安全义务：网关在内存中对输入与输出做违法不良信息检测；命中时按类别处置（停止生成、拦截输出）并记录类别、时间、席位与命中片段 hash，不留存全文。律师业务中正常出现的违法事实描述（刑事卷宗、侵权事实）按“法律专业场景”策略只记录不拦截——该策略须在登记材料中说明并取得属地网信部门认可（附录 U17） |
| 模型真实性校验 | 透传 `X-Msh-Request-Nonce` 与响应签名。能用月之暗面公开的公钥离线验签时，在律师电脑本地校验、不连 Kimi（避免把律所出口 IP 与请求关联）；不能离线验签时，改为中软抽样校验 + 第三方审计报告，并删除“律所可自行验证”的口径。网关对请求与响应的改写须在签名覆盖范围之外，或在数据去向卡中注明“经网关改写”（探针 10） |
| 自带密钥与私有化 | 网关打包为“律所侧网关组件”运行在律所执行器上（律所侧服务角色，远程办公须能访问律所内网）；方法资产以律所许可绑定的加密包下发到执行器（不到律师电脑）；计量不需要（律所自付 token）；内容安全由律所侧网关组件同样执行 |
| 断云 | 席位令牌离线验签、事项策略摘要本地缓存、计量先写预写日志——控制面不可达时推理不受影响；网关与控制面分开部署 |

与中软 MaaS（new-api）的关系：网关作为独立服务经内网调用 new-api 的法律分组，**不修改 new-api 本体**——MaaS 的 AGPLv3 + 附加条款不因法律产品扩大适用范围（集团法务确认）。MaaS 侧仍需 v5 第 4 篇 §10.3 列出的少量开发（额度发放、按律所限流与优先级、幂等 ID 查询、正文不落盘审计），由 MaaS 团队估算。

### 4.2 设备与执行器的身份

| 设备类型 | 密钥 | 存放 |
|---|---|---|
| 律所根密钥、审计密钥 | P-256 | **软件密钥**，由生成设备的 TPM 封装保存，只在治理仪式与迁移时可导出；另由恢复门限备份（§7） |
| 桌面（Windows） | P-256 签名密钥 + P-256 加密密钥 | 优先 TPM 2.0（CNG 平台加密提供程序，不可导出）；无 TPM 时 DPAPI 包裹（v5 做法）；设备私钥备份只经“个人恢复包”（§7） |
| 桌面（macOS，G3） | 同上 | Secure Enclave（P-256，不可导出） |
| 手机（IM 内 H5） | P-256 签名 + 加密 | WebCrypto 不可导出密钥，存 IndexedDB（R3 核验 WebView 支持情况）；**移动子证书**由本人桌面设备签发（桌面证书带 `can_issue_mobile` 标志，由律所根签发），链为“根 → 桌面 → 手机”，每人最多 1 张、有效期 ≤ 90 天、用途限预览与签发；中继、网关与其他成员设备都按这条链验证 |
| 律所执行器 | 同上 | TPM / systemd-creds + TPM2；无 TPM 的 NAS 容器启动时需管理员解锁（v5 做法） |
| 公开沙箱容器 | 临时密钥 | 内存，任务结束销毁 |

算法套件 v1：ECDSA / ECDH P-256 + HKDF-SHA256 + AES-256-GCM；事项密钥包裹用 HPKE（RFC 9180，DHKEM P-256，`@hpke/core`，MIT，纯 WebCrypto 实现，桌面与手机同一套代码）。选 P-256 而不是 v5 的 Ed25519/X25519，是因为 **TPM、Secure Enclave 与浏览器 WebCrypto 的不可导出密钥都以 P-256 为公约数**——这让签发私钥可以真正“不可导出”，也让手机签发可行。算法套件 v2：SM2 / SM3 / SM4（国密），协议头带套件编号，按客户要求或密评要求切换（第 5 篇 §2）。**套件 v2 的代价要说清**：主流 Windows 笔记本的固件 TPM 与浏览器 WebCrypto 普遍不提供 SM2，启用国密的律所，设备与签发私钥退回软件密钥（DPAPI 包裹，或采购支持国密的 USB Key），手机签发改用纯 JS 实现的 SM2（不可做到“不可导出”，保证等级相应降低）；云侧传输按需提供 TLCP（国密 TLS）双栈端点（铜锁/Tongsuo），与国际 TLS 端点并存。

## 5. IM 与移动端

### 5.1 三种接入模式

| 模式 | 谁持有 IM 应用凭据 | 文件路径 | 适用 | 阶段 |
|---|---|---|---|---|
| **M1 中软服务商应用**（默认） | 中软（作为企业微信/钉钉/飞书服务商） | IM 平台 → **律师在线电脑或执行器直接下载**（中软下发一次性短期凭据或转交平台签发的限时下载地址，自身不下载）；平台不支持时退化为“过境加密转交” | 绝大多数律所，零 IT | G1 首家 |
| **M2 律所自建应用 + 执行器长连接**（v5 模式） | 律所 | IM 平台 → 律所执行器 | 要求中软完全不在 IM 路径上的律所 | G2 |
| **M3 个人机器人遥控本机**（可选） | 律师本人 | IM 平台 → 本人电脑长连接 | 习惯 WorkBuddy/千问办公“手机遥控电脑”的律师；只能遥控本人电脑，只处理本人事项 | G2 |

M1 的平台实现（R3 一手核验，细节见第 3 篇 §6.1）：

| 平台 | 事件通道 | 文件直取方式 | `im-isv` 服务存放的凭据 |
|---|---|---|---|
| 飞书 | 商店应用 HTTP 回调（长连接仅限自建应用） | 转发 `message_id + file_key`；客户端以律师本人 user_access_token（scope 收窄为只读）调 `GET /im/v1/messages/:message_id/resources/:file_key`；≥100 MB 分片 | 商店应用 app_secret、各租户 tenant_key |
| 钉钉 | 第三方企业应用 Stream（SuiteKey；多条连接随机投递，可多实例负载均衡） | 服务端调 `/v1.0/robot/messageFiles/download` 换签名 `downloadUrl`，只转发地址 | SuiteKey/Secret、授权企业令牌 |
| 企业微信 | 第三方应用回调（应用消息、模板卡片、H5 身份）；**收文件默认 M3**（每位律师的个人智能机器人，长连接在本人电脑上）或 M2（律所机器人 + 执行器）；“中软托管律所机器人长连接”待 U3 书面确认后才作为选项 | 机器人在律师电脑或执行器上收到预签名 COS 地址（5 分钟）+ 每地址唯一 aeskey，本地下载并 AES-256-CBC 解密 | 第三方应用 suite 凭据（`im-isv`）；机器人 BotID/Secret 只在律师电脑或执行器上 |

**企业微信的加密 userid**：机器人不是由超级管理员创建时，回调中的 `from.userid` 是加密 ID，需用自建或代开发应用的 access_token 调 `openuserid_to_userid` 转换（R3 Q1）。M3 下机器人只服务本人，无需转换；M2 下由律所授权一个只有“ID 转换”权限的代开发应用，凭据只在执行器上。

**为什么必须由云端做“唯一消费者 + 按人路由”**：三家平台对同一机器人/应用的多条连接都是随机投递或单连接（飞书每应用最多 50 条随机投递、钉钉多 Stream 随机投递、企业微信每机器人单连接，R3）。如果让每台律师电脑各连同一个机器人，消息会落到错误的人手里——v5 因此只能让所内节点当唯一消费者。v6 由 `im-isv` 作唯一消费者，按发送人 userid 映射到律所成员，再推送到该成员的在线设备；这也是 M1 不需要律所任何服务器的原因。M3（每位律师一个个人机器人、连在本人电脑上）是另一种规避方式，且是企业微信上唯一能让中软在密码学意义上完全不在文件路径上的做法。

所有凭据只在 `im-isv` 服务的 HSM/KMS 中；转交给客户端的只有单文件、短时效的下载句柄。M1 默认由律师电脑直接下载，文件字节不经过中软服务器（平台不支持直取时退化为“过境加密转交”，逐次记录）；但中软在短时窗口内具备下载能力，这一点在数据去向卡与安全白皮书中如实说明。三种模式共同的安全规则：

- **只允许配对**：机器人只响应已绑定律所成员身份的会话；不开放“所有人可对话”模式（千问办公的“开放模式”见 R1 §2，律所禁用）；群聊须 @ 且不收文件。
- **通知最小化**：卡片默认只含事项代号与动作，不含客户名称、案情与结论；律所可在策略中放宽到“事项简称”。
- **消费级渠道默认关闭**：个人微信、QQ 渠道不开通（个人微信材料用“转电脑后拖入”或 G3 小程序）。

### 5.2 手机签发（IM 内 H5）

| 步骤 | 设计 |
|---|---|
| 登记 | 合伙人首次在 IM 内打开“法律助手”H5 → 生成 P-256 不可导出密钥（WebCrypto；R3：ECDSA/ECDH P-256 与 AES-GCM 在仍受维护的 Android XWeb/系统 WebView 与 iOS WKWebView 中普遍可用，Ed25519/X25519 需 Chromium 133–137+ 或 iOS 17+，故不作基线）→ 桌面端扫码确认，由合伙人本人桌面设备签发移动子证书（§4.2 的“根 → 桌面 → 手机”链）。IM 内 WebView 的 IndexedDB 可能因清缓存、换机或系统存储回收丢失，**移动设备密钥按“可随时重新登记的短期设备”设计**（有效期 ≤ 90 天，到期前 14 天桌面端提醒续期，丢失即吊销重登），不作为长期身份 |
| 事项授权 | 合伙人作为签发人的事项，其事项密钥同时包裹给移动设备公钥（可按策略只包裹“待签发交付件”的单文件密钥，而非整个事项密钥） |
| 预览 | 从中继取交付件密文 → H5 内解密 → 完整预览（PDF 渲染；DOCX 由桌面端在申请签发时预渲染为 PDF 一并加密） |
| 签名 | 移动设备签名 {成果版本、文件 hash、受众、完整性单 hash}；**系统级确认**：IM WebView 支持 WebAuthn 平台认证器时，用指纹/面容做一次断言（挑战值为交付件 hash），恶意脚本无法在用户不知情时静默签名；签名生效后桌面端同步通知，对外受众设 **24 小时撤回窗口** |
| 回退 | 不支持系统级确认：移动签名须 24 小时内桌面复核；WebView 不支持所需 WebCrypto 或密钥丢失：降级为“IM 身份确认 + 24 小时内桌面补签”，补签前交付件标“待补签” |
| 代码完整性 | H5 静态资源版本化并签名，版本哈希写入 tlog；内容安全策略只允许连中继与控制面；**如实边界**：每次加载的脚本都由中软服务器下发，手机端无法逐次校验——被篡改的脚本可在解密后外传内容，或在系统确认时替换待签内容；L3 事项默认禁用手机预览；独立 App（代码经应用商店签名）G2 后评估 |

### 5.3 个人微信材料（G3）

小程序 `wx.chooseMessageFile` 选择聊天文件（每次 0–100 个，官方未写单文件大小上限）→ 小程序内用律师设备公钥（HPKE）加密 → 上传中继 → 律师电脑解密入库。中软只见密文。约束（R3）：

- 小程序官方加密能力只有 `getUserCryptoManager` 与 `getRandomValues`，未见 `crypto.subtle`——“用公钥加密上传”可用纯 JS 实现（加密不需要不可导出的私钥），但**签发不放在小程序里**，仍在 IM 内 H5 或桌面完成。
- 类目：“律所服务”类目需律所执业许可证，“法律服务平台”类目需营业执照含“法律咨询”——中软主体可能都不满足。可选做法：以“工具/办公”类目上架纯文件加密传输工具（须与平台确认），或由律所以自己的主体上架定制小程序（律所版服务项）。小程序备案按现行规定办理。G3 前完成类目确认。

## 6. 同步协议

沿用 v5 的事件模型（每设备只追加写自己的事件段、内容寻址密文块、Lamport 时钟 + 设备 ID 全序、业务冲突保留两个版本、撤权按密钥纪元而非时钟），只替换介质：

| 项 | v5 | v6 |
|---|---|---|
| 介质 | 所内节点 / 共享文件夹 | **relay（默认）/ 律所 S3 / 执行器缓存**，统一为对象存储语义 |
| 封口 | 临时名 → 刷盘 → 原子改名；忽略冲突副本 | 对象存储原子写 + 条件写（`If-None-Match`），不存在半写与冲突副本 |
| 通知 | 节点推送或轮询 | 控制面信令（匿名事项 ID + 序号） |
| 远程办公 | VPN | 不需要（relay 公网可达；律所 S3 模式取决于存储位置） |
| 成员关系 | 事项内签名事件 | 不变；中继据此校验写入权限（只验签名链） |

## 7. 密钥体系

```text
律所根密钥（治理仪式中由主任或管理合伙人设备生成；P-256 软件密钥，TPM 封装）
  ├─ 治理恢复（根私钥另包裹给独立的治理恢复公钥；门限 ≥ 3 人，或 2 人 + 72 小时冷静期）
  ├─ 策略签名子证书（≤ 2 名管理员设备，有期限；放宽类变更双签）
  ├─ 设备批准子证书（可委托给团队负责人，有期限，只能批准本团队成员设备）
  ├─ 审计密钥（治理仪式中生成；律所版由风控合伙人持有、团队版由主任持有；按年度与持有人变更分纪元轮换，新纪元密钥用旧纪元包裹，同时包裹给事项恢复公钥）
  │    └─ 只读导出子密钥（可选，给执行器向律所 SIEM 导出审计事件头）
  └─ 设备证书（成员桌面 / 执行器；桌面证书可带 can_issue_mobile → 移动子证书）
       └─ 事项密钥（每事项一把 AES-256；HPKE 包裹给成员设备、可选执行器、律所档案成员、事项恢复公钥）
            ├─ 事项写入密钥（签名用，私钥随事项密钥分发，公钥登记到中继）与读取令牌（派生）
            └─ 事件体、材料块、映射表、成果
事项恢复密钥（每把事项密钥另包裹一份；私钥 2-of-3 律所内分片：主任 · 第二位合伙人 · 律所保险柜；可选中软托管第 4 片，门限仍为 2）
个人恢复包（每位成员可选；客户端随机生成 ≥ 128 位恢复码，包裹本人设备私钥备份）
```

| 项 | v5 | v6 |
|---|---|---|
| 首日 | 合伙人 M-of-N 分持 + 演练 | **律所治理仪式**（约 10 分钟）：生成根密钥与审计密钥、打印 3 张恢复卡、签首份策略；向导拒绝中软或渠道实施账号执行；演练为 30 天内检查项 |
| 预配与首份策略 | — | 控制面只保存未签名的策略草案；首份根签名策略生效前，客户端按“中软基线 + 最严默认模板”运行 |
| 事项恢复 | M-of-N 合伙人分持 | **2-of-3 律所内分片**（主任 / 第二位合伙人 / 律所保险柜），不提供只有两片的配置；持片人凑齐门限可解密全部事项——对他们，伦理墙是内控与留痕而非密码学保证 |
| 中软托管片 | 无 | **可选的第 4 片**（门限仍为 2）：释放须两名不同合伙人在各自已登记设备上签名请求 + 72 小时冷静期 + 写入 tlog + 通知全体管理员与受影响事项负责人；**释放对象不得持有其他分片**；中软 HSM 加密保存 |
| 专业版（单人） | 恢复口令 | 中软托管片只能与客户端生成的随机恢复码（≥ 128 位）组合，不允许人选口令（防中软离线暴力猜测）；人选口令只用于本地备份 |
| 破窗记录 | — | 经客户端恢复向导动用时自动记录、通知、写入 tlog；持片人离线合谋可绕过记录，写入恢复卡保管制度，如实告知 |
| 持片人变更 | — | 生成新恢复密钥对 → 在线成员设备后台把事项密钥重新包裹给新恢复公钥（控制台显示进度）→ 旧恢复卡作废并写入 tlog |
| 防公钥注入 | 律所根密钥签发证书 | 不变 + 证书与吊销进 tlog（设备间比对树头 + 第三方时间戳见证） |
| 设备批准 | 管理员设备签发 | **确认码批准**：新设备显示由其公钥派生的 6 位确认码，批准人须输入当面或电话获得的确认码（或用已登记设备当面扫码），不提供一键批准；新设备 **24 小时观察期**后（或经本人另一台已登记设备确认）才自动收到事项密钥；同一成员其他设备与相关事项负责人收到通知；**吊销级联**：吊销设备时提示一并吊销它近 N 天内批准的设备 |
| 根密钥轮换 | 未设计 | **计划轮换**（管理员变更）：旧根签“迁移声明”写入 tlog，新根重签全部有效证书与当前策略，新旧根并行 7 天；**泄露轮换**：立即切换，由治理恢复门限签“旧根吊销声明”写入 tlog，客户端拒收时间戳晚于吊销声明的旧根签名；事项密钥不受影响 |
| 换电脑（坏机） | 依赖其他成员或恢复 | 个人恢复包恢复本人设备私钥，不触发律所破窗；共享事项也可由在线同事设备重新包裹 |
| 离职 | 吊销 + 轮换 | 吊销 + **事项负责人移交**（任一在线成员重签事项策略摘要；网关对已吊销负责人签名的摘要给 7 天宽限，控制台列出待移交事项）+ 后台轮换事项密钥（成员设备上线即完成，进度可见）+ 律所档案成员确认归档 |
| 律所档案成员 | — | 可选：档案管理员设备或执行器设为事项默认成员（伦理墙事项除外），保证律所保有业务档案 |
| 加人进事项 | 成员设备包裹 | 不变；管理员发起、成员设备完成 |
| 删除 | — | 轮换并销毁事项密钥（加密擦除） |
| 分片库 | — | `shamir-secret-sharing`（Privy，Apache-2.0，Cure53 与 Zellic 审计） |

## 8. 三种模型端点（沿用 v5，增加网关）

| 端点 | 数据路径 | 方法资产 | 计量 | 适用 |
|---|---|---|---|---|
| 标准 | 律师电脑 → **法律推理网关** → MaaS 法律分组 → Kimi | 网关占位符替换 | 网关权威 | 团队版、律所版、专业版 |
| 自带密钥 | 律师电脑 → 律所侧网关组件（执行器的律所侧服务角色）→ 月之暗面（律所直签） | 加密包下发到执行器 | 不需要 | 要求中软不在推理路径上的律所（须有执行器；远程办公须能访问律所内网） |
| 私有模型 | 律师电脑 → 律所侧网关组件 → 律所内推理服务 | 同上 | 不需要 | 私有化 |

自带密钥版因此需要一台执行器承载律所侧网关组件；没有执行器的小团队若要自带密钥，可接受“方法包加密下发到律师电脑”的降级（v5 做法），合同中写明。

**律所已有的私有模型**：部分大所已在所内部署大模型（锦天城 2025-02 官网披露本地部署 DeepSeek 671B、2024 年本地部署基于 Qwen 的利冲功能，R4 Q8）。私有端点优先使用 Kimi 开源权重（K2.6 级，v5 第 4 篇 §10.2）；律所坚持接入已有的其他私有模型时，作为“律所自有端点”接入律所侧网关组件，须先过 360 任务盲测才上架对应场景，且该端点不以 Kimi 名义宣传——是否允许由与月之暗面的品牌与渠道条款确认（列入第 5 篇谈判清单）。

## 9. 安全

### 9.1 新增威胁与控制

| 威胁 | 控制 |
|---|---|
| 控制面被攻破 | 拿不到明文与任何事项密钥；不能生效未经律所签名的策略，也不能回放旧策略（版本单调 + 有效期）；不能签发设备证书；不能伪造签发；tlog 使篡改可被律所发现。**能做到的**：读取元数据、扣留通知、拒绝服务、诱导批准假设备（由确认码挡住） |
| 控制面伪造设备申请 / 注入假公钥 | 设备证书须律所根（或子证书）签名，批准须输入新设备上显示的确认码；新设备 24 小时观察期；客户端在包裹事项密钥前验证证书链与 tlog 一致性；红队用例“控制面伪造申请 + 管理员远程批准”必须失败 |
| 透明日志分叉视图（对不同律所或设备展示不同日志） | 律所内设备经中继交换并比对所见树头；每日树头提交第三方可信时间戳见证；律所版执行器作独立见证节点 |
| 律所自有存储凭据泄露 | 客户端不持有共享 S3 凭据，凭据只在执行器的自托管中继；对象存储开启版本化与对象锁 |
| 中继被攻破 | 只有密文；写入须设备签名，无法伪造事件；删除须负责人签名 |
| 网关内部人员 | 看到化名片段（与 v5 中 MaaS 相同暴露面）；正文不落盘配置审计；双人运维、最小权限、访问日志；对模型方隐去律所身份 |
| 公开沙箱逃逸 | 容器级隔离（gVisor/Kata）；沙箱网络域内无任何事项数据与密钥；即使逃逸也只能触及公开数据 |
| 中软托管恢复片被滥用 | 单片无法解密；释放流程线下核验 + tlog + 全体管理员通知 |
| IM 服务商应用凭据泄露 | 凭据只在控制面 HSM；最小权限 scope；文件下载凭据一次性、短时效；律所可随时在 IM 后台停用应用 |
| 移动设备丢失 | 吊销移动设备证书；事项密钥轮换；移动端默认只拿“待签发单文件密钥” |
| 手机 H5 代码由中软下发（网页端到端加密的固有弱点：被篡改的页面脚本可在解密后外传，或在用户确认时替换待签内容） | 版本哈希写入 tlog（事后可查，不能逐次校验）；系统级确认（WebAuthn）防静默签名；桌面端通知 + 24 小时撤回窗口；内容安全策略只允许连中继与控制面；L3 事项默认禁用手机预览；如实写入安全白皮书；独立 App G2 后评估 |
| IM 文字指令经中软（M1） | 律师发给机器人的文字经平台推送到中软 `im-isv`，属于过境明文：只解析有限指令（选事项、开始、查进度），不落盘、不进日志；引导律师不在 IM 中输入案情；数据去向卡记录“IM 指令经中软过境”；不接受的律所选 M2/M3 |
| T2/T5 新能力被注入利用 | 计算沙箱无网络、无文件系统外访问；隔离浏览器无 Cookie、白名单、逐步确认；两者默认档位都需确认 |

### 9.2 沿用

### 11.3 十六项探针（G0 退出条件）

v5 的 14 项沿用（本机引擎、工具与隔离、注入、出站闸门、文书保真、Office 宿主、化名、本机 OCR 与资源、成本与时延、MaaS 法律分组、同步与恢复、签发与审计、分发与环境、IM），其中第 11 项改为“relay 介质下的断网、断电、并发、撤权、恢复”，第 14 项改为“服务商应用模式下 100 MB 文件由律师电脑直取”。新增：

15. **云端零明文**：对控制面、中继、网关、公开沙箱的数据库、对象存储、日志、错误报告做自动化扫描与红队抽查，客户内容、事项名称、文件名与关注名单零命中；IM 卡片模板不含文件名与事项名；网关正文不落盘（含异常路径）。
16. **信任锚**：未经律所签名、版本回退或过期的策略在端侧与网关被拒绝或回退到最严模板；“控制面伪造设备申请 + 管理员远程批准”失败；中软托管恢复片单独或与一张卡合谋都须经冷静期与 tlog；tlog 一致性证明可离线验证、设备间树头比对可发现分叉。
17. **手机签发（G0 争取，G1 退出条件）**：三平台 × Android/iOS 的 WebCrypto 不可导出 P-256 与 WebAuthn 平台认证器可用性；篡改 H5 资源后不经系统级确认无法产生有效移动签名，做不到则降级为“须桌面复核”。
