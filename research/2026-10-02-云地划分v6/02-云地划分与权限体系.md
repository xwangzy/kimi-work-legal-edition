# 第 2 篇　云地划分与权限体系（v6.0 核心篇）

版本 6.0 · 2026-10-02 · 本篇是 v6.0 的“宪法”：每一项能力放在哪里执行、能碰到什么数据、谁有权打开它、断网或关机时怎么降级，都以本篇为准。第 3–5 篇的产品、技术、合规与商业设计都从本篇推出。

---

## 1. 一句话

**控制在云，内容在所，推理只过境。** 账号、组织、席位、策略、计量、分发、通知、调度与运营审计放在中软云端的“控制面”；案卷原件、解析文本、化名映射、成果、签发私钥与内容级审计只在律所侧（律师电脑，或律所自己的执行器与存储）以明文持久保存；团队协作经中软云端的“密文中继”同步，中软在正常运行中不持有解密密钥；模型推理时，化名后的必要片段经中软“法律推理网关”过境发往 Kimi，网关不落盘，上游留存以与月之暗面签署的企业协议为准（签署前只处理合成或公开材料）。云端执行默认只开放给公开资料与律师确认的派生查询。

## 2. 为什么要重新划分：v5.0 的划分错在哪里

v5.0 用一条规则划分全部能力：“云端只提供 token，其余全部在律所侧执行”。这条规则把“**碰不碰案卷明文**”这一个维度当成了唯一维度，于是一批**根本不碰案卷、但天然需要云端**的能力也被压到了律所侧，产品为此多造了一整套律所侧基础设施：

| v5.0 压到律所侧的能力 | 它真正需要的 | v5.0 的代价 |
|---|---|---|
| 身份与登录 | 一个可信的第三方身份源 | 团队版身份只能来自“律所自建 IM 应用 + 所内节点”，单机版又要另一套账号；对抗式审阅第 8 条指出“没有 IdP” |
| 管理控制台 | 管理员在任何地方都能打开 | 完整版只能在所内节点的局域网 Web 上用，合伙人出差管不了 |
| IM 入口、手机审批、期限提醒、定时任务 | 常在线、可被外部唤醒 | 必须有所内节点或“指定一台常开电脑”；没有就不开通 IM——而司法部 2022 年度统计中 65.5% 的律所在 10 人以下、96.7% 在 50 人以下（R4），基本没有专职 IT |
| 团队同步 | 一个常在线、强一致的汇合点 | 自研“签名事件段 + SMB/NAS 共享文件夹”同步，要处理网络文件系统乱序、同步盘冲突副本、占位文件 |
| 方法资产（Playbook） | 不被复制 | 签名加密下发到每台律师电脑，“内存解密 + 水印”，v5 自己承认“不可能绝对保密” |
| 任务计量 | 一个律师改不了的计数点 | 本机账本扣点可被篡改，只能靠 MaaS token 硬上限兜底，点数与实耗口径打架（审阅第 10 条） |
| 数据商凭据 | 不下发到终端 | 无节点团队不开通案例核验（审阅第 13 条） |
| 密钥恢复 | 律所自己掌握、又不至于丢 | 开通第一天就要求“多名合伙人 M-of-N 分持 + 恢复演练” |

反过来，v4.0 与 astra 方案犯的是相反的错：把**案卷明文的持久保存与处理**放进中软云，中软因此成为案卷保管人。

v6.0 的判断：**v5.0 的方向（案卷在律所）是对的，划分维度是错的**。正确做法是按能力的多个属性逐项决定位置，而不是用一条口号决定全部。

## 3. 第一性原理：先问资产与威胁，再问位置

### 3.1 要保护什么、防谁

| 资产 | 例子 | 首要属性 | 主要防范对象 |
|---|---|---|---|
| **A1 客户内容** | 原件、解析文本、OCR 结果、成果草稿与终稿、化名映射表 | 机密性 | 中软、模型厂商、IM 厂商、外部攻击者；律所内伦理墙外的人 |
| **A2 事项描述** | 客户名、相对方、事项标题（“甲公司收购乙公司”本身就是机密） | 机密性 | 同上 |
| **A3 律所知识** | 本所覆盖层、范本、历史意见 | 机密性 | 中软、竞争对手 |
| **A4 签发与审计** | 谁在何时批准了哪一个确切文件 | 完整性、不可抵赖 | 律所内部篡改；中软篡改 |
| **A5 中软方法资产** | Playbook、规则包、评测集 | 机密性 | 被整包复制 |
| **A6 运营元数据** | 席位、设备、登录、用量、任务计数 | 准确性 | 律师绕过额度；误计费 |
| **A7 凭据** | MaaS 令牌、IM 应用密钥、数据商凭据、设备私钥 | 机密性 | 终端被攻破后的横向扩散 |
| **A8 可用性** | 律师随时随地能干活；关机后任务能继续；手机能审批 | 可用性 | 断网、关机、单点故障 |

### 3.2 决定位置的七个属性

每一项能力都按下面七问打分，位置由答案组合决定：

1. **碰不碰 A1/A2 明文？**（内容）
2. **是否必须常在线、可被外部唤醒？**（在线）
3. **是否需要一个律师改不了的信任锚？**（防终端篡改：额度、许可、方法资产、跨所内容）
4. **是否需要一个中软改不了、看不到的信任锚？**（防厂商：签发、伦理墙、密钥）
5. **是否需要跨律所聚合或分发？**（法规库更新、模型路由、方法资产版本）
6. **是否依赖本机资源？**（挂载文件夹、Word/WPS 宿主、系统钥匙串、离线）
7. **是否超出笔记本算力？**（大批量、长任务、私有模型）

### 3.3 七条划分规则

| # | 规则 | 由哪一问推出 | 典型能力 |
|---|---|---|---|
| **G1 内容不落云** | 客户内容与事项描述的**明文持久化**只发生在律所侧（律师电脑、律所执行器、律所自有存储）；云端只允许“过境”且不落盘——推理网关的化名片段、M1 模式下 IM 平台回调中的文字指令与文件名、律所显式开启的“过境执行”（§5.3），每一类都在数据去向卡中逐次记录 | 问 1 | 材料、成果、映射表、内容级审计 |
| **G2 控制归云** | 不碰明文、但需要第三方可信或常在线的能力放云端控制面 | 问 2、3、5 | 身份、席位、许可、策略、计量、分发、通知、调度、运营审计 |
| **G3 信任分锚** | 防律师篡改的锚在云（额度、方法资产、时间证明）；防中软篡改的锚在律所（签发私钥、事项密钥、律所根密钥）；云端只保存公钥、密文与 hash | 问 3、4 | 签发签名 + 云端透明日志；设备证书由律所根密钥签发 |
| **G4 执行随数据** | 任务在“它的数据所在、且已被授权”的位置执行：客户事项在本机或律所执行器；公开任务可在云端沙箱 | 问 1、6、7 | 合同审查在本机；法规追踪在云端 |
| **G5 在线不等于持有** | 需要常在线但不需要内容的环节（信令、排队、卡片、提醒），由云端承接，消息体最小化或端到端加密；需要内容的部分交回律所侧执行 | 问 1、2 | IM 收文件、手机审批、期限提醒 |
| **G6 层层只收紧** | 中软基线 → 律所策略 → 事项策略 → 任务档位，下层只能更严，不能放宽 | — | 权限体系（§7） |
| **G7 断云可用** | 云端控制面不可达时，本机能力照常可用（本机解锁靠设备密钥 + 离线有效 30 天的许可，不依赖 SSO 会话；策略、密钥在本地）；协作、通知与新设备登录不可用；推理在网关可用时不受影响（网关可离线验证席位令牌、缓存事项策略摘要、计量先写本地预写日志） | 问 6 | 降级模式（§9） |

## 4. 主流产品是怎么划分的（本轮一手核验）

本轮 R1、R2 调研（见同目录 `调研-R1`、`调研-R2`）覆盖国内外 14 个产品。共同模式只有一个：

> **控制面永远在云端；执行面“本机 / 厂商云沙箱 / 客户侧自托管执行器”可插拔；企业版对云端执行默认更保守。**

| 产品 | 控制面 | 执行面 | 定时与常在线 | 对受监管客户的让步 | 出处 |
|---|---|---|---|---|---|
| 腾讯 WorkBuddy | 云：SSO、IP 白名单、额度、操作日志、AI 安全审计（含会话回放）、模型白名单 | 本机（默认/完全访问两档，沙箱）+ **WMA 云端托管**（1 会话 1 沙箱，7×24，支持 VPC/私有化） | 本机定时关机即停；IM 遥控要求电脑开机；7×24 交给 WMA | 专享 VPC、私有化企业版 | R1 §1 |
| 千问办公（QoderWork 并入） | 云：SSO/SCIM、可信设备、敏感词、企业 Hooks、模型策略组、限额、审计 | 桌面本机（可选本机隔离“安全工作环境”）/ 网页云端 | 桌面定时睡眠不触发；**网页定时云端照跑** | 企业 Hooks 可拦截工具调用；自定义私网模型端点 | R1 §2 |
| Kimi Work / Kimi Claw | 弱：企业版只有席位与管理员/成员 | Kimi Work 本机（默认/手动允许/全部三档）；Kimi Claw 云端 VM / 本地 / 安卓 | Kimi Work 定时本地、关机不补跑；Kimi 云端定时另算 | 未见 SSO、审计 | R1 §3 |
| Anthropic Claude Cowork | 云：组织开关、自定义角色“最严者胜出”、合规 API、CMEK | **2026-10-06 起个人与 Team 默认云端执行**；本机 VM 仍可用；**Enterprise 默认关闭云端会话** | 定时任务一律云端；手机遥控本机的 Dispatch 已停止对新用户开放 | 企业默认关云、可要求可信设备；**自托管执行环境：控制面在云、执行在客户网络、只出站连接** | R2 A1 |
| OpenAI ChatGPT Work / Codex | 云：Agent Security 全局基线 + 本地覆盖，“要求”用户不可覆盖 | 协调（编排）可在云，执行可在本机或云容器；官方明说“本地执行不等于数据不出机” | Web 定时在云；桌面定时要开机；dots 常驻云端 | 企业默认不改本机/云开关；开数据驻留即禁用“云协调 + 本机执行”混合 | R2 A2 |
| Microsoft Windows Agent / Copilot Studio | 云：Agent 365、Entra Agent ID、Purview DLP | 本机 Agent 用独立 agent 账户 + 独立 agent 桌面；云端用 Windows 365 for Agents | — | 把 Agent 当受管员工/设备治理 | R2 A3 |
| Harvey / Legora（法律） | 云 | **全云 SaaS（Azure）**，Word/Outlook 只是前端 | 云 | 区域驻留、**BYOK（客户撤钥即不可读）**、模型侧 ZDR、伦理墙同步（不做 system of record）、内部零访问、SOC 2/ISO 27001/42001 | R2 B5–B6 |

对本项目最有用的四个先例：

1. **Anthropic 自托管执行环境**：“控制面在 Anthropic，执行面在客户网络；所有连接都是客户侧出站；Anthropic 从不连入客户网络。”——这正是 v6.0 对“所内节点”的重新定义（§5.2）。
2. **OpenAI“协调与执行分离”与“本地执行不等于数据不出机”**——我们沿用 v5 的如实口径，并明确协调（Agent 循环）对客户事项留在律所侧。
3. **WorkBuddy WMA、千问办公网页端、Kimi Claw**：国内用户已经接受“本机干活 + 云端 7×24”的双形态；v6.0 把云端 7×24 限定在不含客户材料的公开任务上（§5.3），客户事项的常在线交给律所执行器。
4. **Harvey 的伦理墙原则**：同步并执行律所既有的墙，但不成为墙的“系统记录”；以及 BYOK“客户撤钥即任何系统都不可读”——v6.0 的密文中继在设计上使中软在正常运行中不持有解密密钥（律所选择中软托管恢复片时，中软持有一片，单片无法解密，见 §10.3）。

同时要避免照搬的：Manus 等“本机浏览器扩展借用登录态、权限覆盖全域 cookie”的做法（R2 A4）——律师的浏览器登录态通向法院系统、客户邮箱和律所内网，被提示注入利用的代价极高；WorkBuddy 企业版“会话回放”把律师与 AI 的完整对话交给管理端——与伦理墙和律师保密义务冲突，v6.0 只做元数据级运营审计（§7.5）。

### 5.2 律所侧执行器：v5 “所内节点”的重新定义

v5.0 的所内节点同时是同步中心、IM 唯一消息消费者、定时与批量执行点、管理控制台与密钥持有者，是一个必须高可用的“律所内服务器”。v6.0 把其中**不需要明文的职责全部收回云端**（同步汇合点 → 密文中继；IM 消费者 → 控制面的服务商应用后端；管理控制台 → 云端 Web；定时调度 → 云端），执行器只剩一件事：

> **在律师电脑关机时，替已授权的事项执行需要明文的任务。**

| 项 | v5 所内节点 | v6 律所执行器 |
|---|---|---|
| 是否必需 | 5 人以上团队推荐；IM、定时、关机续跑、局域网管理都依赖它 | **完全可选**：所有核心功能（协作、IM、手机审批、提醒、管理）不依赖它 |
| 连接方式 | 局域网/VPN 双向；IM 长连接；律师电脑连它 | **任务执行器角色只出站**：向控制面领取任务、向中继读写密文，不开入站端口；**律所侧服务角色**（局域网同步缓存、更新镜像、律所侧网关组件、自托管中继）需要律师电脑连入，远程办公须 VPN 或零信任接入 |
| 密钥 | 逐事项授权的服务成员 | 不变：逐事项授权；伦理墙与高敏事项默认不授权 |
| 部署 | Windows Server / Linux 容器 / NAS 容器 / 常开电脑；律所版建议主备 | 同上任一；无状态可重建（数据在中继或律所存储），单台即可，多台自动分担 |
| 适用 | 几乎所有团队 | 需要“关机续跑 / 大批量 / 内容型定时 / 私有模型 / 自带密钥 / 不愿让任何密文出所”的律所 |

执行器因此有两种角色：**任务执行器**（只出站，零入站端口）与**律所侧服务**（需要律所内网可达）。只用前者的律所，律师远程办公不需要 VPN；用到后者（律所自有存储、自带密钥、私有模型）的律所，远程办公需要能访问律所内网。

### 5.3 四个执行位置

| 位置 | 能碰到的数据 | 典型任务 | 默认 | 谁能开启 |
|---|---|---|---|---|
| **E1 本机** | 律师有权的全部事项（明文在本机） | 合同审查、案卷整理、文书、比对、脱敏、Agent | 开 | — |
| **E2 律所执行器** | 已逐事项授权给执行器的事项 | 关机续跑、批量尽调、内容型定时（事项周报）、IM 转来的文件处理、私有模型 | 有执行器即可用 | 事项负责人逐事项授权 |
| **E3 云端公开沙箱** | 只有 L0 公开数据与 L0d 派生公开查询（§6），**不能访问任何事项材料** | 法规变更追踪、公开法源研究与类案初筛、上市公告与工商公开信息监测、培训材料 | 开 | 律所管理员可关闭 |
| **E4 云端过境执行**（G3，可选） | 律所显式开启的事项：任务所需材料以密文传入，在单任务隔离容器内存中解密处理，结束即销毁，ZDR 口径 | 无执行器的团队需要关机续跑或超大批量 | **关** | 律所管理员策略 + 事项负责人 + 当事人同意状态为“已同意”，三者同时满足 |

E4 是对主流产品“云端托管 Agent”的对标，但它让中软在任务期间看得到明文，所以：默认关闭；不进入 G0–G2 交付范围；上线前须完成等保三级测评、过境执行的配置审计、DPA 附件与律协指引对照；数据去向卡中以醒目颜色标记“本任务在中软云端处理（过境不留存）”。

### 5.4 三个平面的不变量

| 平面 | 不变量（违反即为缺陷） |
|---|---|
| 控制面 | 不保存 A1 明文；A2（事项描述）不以明文保存（IM 卡片不带事项名与文件名，§10.4），控制面只见匿名事项 ID；不持有任何事项密钥、签发私钥或律所根私钥。**控制面能看到的元数据**：账号与设备、席位与用量、匿名事项的任务类型与时间、期限提醒的时间与类型、通知路由所需的订阅关系——从流量可以推断“哪些设备在同一事项中”，如实披露 |
| 密文中继 | 只存密文与 hash；写入须同时带设备证书签名与“事项写入密钥”签名，读取须出示由事项密钥派生的读取令牌——中继据此鉴权，**不读取也不保存成员名单**；无法解密；不可篡改他人写入（只追加 + 签名校验） |
| 法律推理网关 | 无状态；正文不落盘（含错误日志）；只接受经事项策略签名允许的请求；记录元数据（席位、事项匿名 ID、模板、模型、token、耗时、请求 ID） |
| 公开沙箱 | 输入只有 L0 与 L0d；请求携带“公开任务 ID”而非事项 ID；与控制面、中继网络隔离；无事项密钥 |
| 律所侧 | 明文只在受策略约束的进程内；一切出站经出站闸门（模型、法源、时间戳、更新）或被记录（中继密文、IM） |

## 6. 数据分级

| 级别 | 定义 | 例子 | 默认标注方式 |
|---|---|---|---|
| **L0 公开** | 已公开、无保密义务 | 法律法规、公开裁判文书、公开公告、企业公示信息、律所官网文章 | 系统识别来源（法规库、公开源）；律师可标注 |
| **L0d 派生公开查询** | 由 L2 事项抽象出的检索问题，**经律师逐条确认**，不含直接标识符与当事人词典中的实体 | “股权转让中未实缴出资股东的补足责任，近三年上海地区判例” | 本机生成 → 律师确认 → 出站闸门校验；**只在当事人同意为“已同意/无需”时允许出站**；任务结束即删除，不进入 7×24 长任务 |
| **L1 律所内部** | 律所自己的、非客户的 | 范本、本所覆盖层、培训材料、内部制度 | 方法与知识库内的内容 |
| **L2 客户一般** | 委托事项中的材料与成果 | 合同、往来函件、案卷、意见书 | 事项内一切内容默认 L2 |
| **L3a 法定敏感** | 律协指引列明的敏感信息、高敏事项 | 生物识别、医疗健康、金融账户、行踪轨迹、未满十四周岁未成年人信息（上海律协居村指引第十五条）；刑事卷宗；事项负责人标为“高敏” | 化名引擎识别 + 事项密级 |

|---|---|---|---|---|---|---|---|
| L0 公开 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| L0d 派生公开查询 | ✓ | ✓ | ✓（同意为“已同意/无需”） | — | ✓（同左） | ✓ | 随所属事项 |
| L1 律所内部 | ✓ | ✓ | ✗（不变量：公开沙箱只收 L0/L0d） | ○ | ✓ | ✓ | ✓ |
| L2 客户一般 | ✓ | ○（逐事项） | ✗ | ○（三重开启，G3） | ✓（当事人同意为“已同意”或“无需”；“待取得”只用本机能力） | ✓ | ✓（律所可改为自有存储） |
| L3a 法定敏感 | ✓ | ○（逐事项，默认否） | ✗ | ✗ | ✗（律所管理员显式放开并留痕才可） | ✓ | ✓（律所可要求仅执行器/自有存储） |

“混合任务”按步骤拆分：例如“结合本案事实做类案研究”——本机把争点抽象成不含当事人信息的检索问题（L0d，律师逐条确认），公开沙箱做法源检索与类案初筛，结果回到本机再与事项事实结合起草（推理走标准端点、化名）。拆分点由工作流定义，不交给模型自行决定。

## 7. 权限体系

### 7.1 Agent 工具能力分级（T0–T7）

| 级别 | 能力 | 例子 | 放在哪 |
|---|---|---|---|
| T0 读取 | 读本事项派生文本、本地法规库、已授权的本所知识 | `matter.read`、`law.lookup` | E1/E2；E3 只读公开库 |
| T1 起草 | 写草稿与工作文件到事项工作区（版本化、可回滚） | `draft.write`、`table.fill` | E1/E2/E3 |
| T2 计算沙箱 | 无网络的代码执行（只读事项派生数据，输出到工作区）：利息与违约金测算、银行流水分析、股权结构图 | `compute.python`（WebAssembly 运行时，无文件系统外访问、无网络） | E1/E2/E3 |
| T3 授权外部源 | 授权数据商与连接器（去标识查询）、律所批准的 MCP | `case.search`、`company.lookup` | 经云端法源服务或律所批准的连接器 |
| T4 扩大范围 | 读事项外文件、跨事项检索：只限本人是成员的事项与 L1 本所知识（伦理墙由事项密钥保证——没有密钥就检索不到） | `firmkb.search`（跨事项） | E1/E2 |
| T5 浏览器辅助 | 在客户端**隔离的内置浏览器**（独立配置文件、不导入 Cookie、不登录任何账号）里访问白名单内的**公开官方网站**，每次导航与提交由律师确认 | 国家企业信用信息公示系统、中国执行信息公开网的检索辅助 | E1 |
| T6 改原件 / 覆盖正式成果 / 删除 | — | — | **不做成 Agent 工具**，只有律师在界面上操作 |
| T7 对外发送 / 签发 / 提交 | — | — | **不做成 Agent 工具**；签发须本人设备签名 |

说明：

- T2 是 v5.0 没有、主流产品都有的能力（WorkBuddy、Kimi Work 都允许执行代码）。v6.0 用无网络的 WebAssembly Python 运行时实现，**不开放 Shell，不开放本机任意进程**——解决律师真实的计算需求，又不把“任意代码执行”的攻击面带进律师电脑。
- T5 不驱动律师本人的浏览器、不借用其登录态：R2 记录了本机浏览器扩展借登录态被提示注入读取本机文件并外发的公开案例，律师浏览器里的法院系统、客户邮箱与律所内网登录态代价太高。也不复用律师在商业数据库的个人账号（北大法宝、威科等服务条款禁止，09-23 已裁决）。只覆盖政府公开网站，默认关闭，管理员开启后每一步需律师确认，Agent 不能输入验证码、不能登录；需要登录的网站（如中国裁判文书网）只提供“打开页面由律师手工操作”的辅助。
- 律所批准的 MCP（T3）：管理员在控制台登记连接器并标注“允许接收的数据级别”（例如“只收 L0 查询”），出站闸门按级别放行。v5.0 “只允许中软签名连接器”过严，律所自己的 DMS、利冲系统接不进来。

### 7.2 任务档位（律师选择，受上层约束）

| 档位 | T0 | T1 | T2 | T3 | T4 | T5 | 适用 |
|---|---|---|---|---|---|---|---|
| **只问不做**（问一问） | 自主 | — | — | 确认 | — | — | 咨询、解释条款 |
| **先出计划**（新用户与 Agent 任务默认） | 自主 | 计划确认后自主 | 计划确认后自主 | 确认 | 确认 | 确认 | 开放任务 |
| **标准**（结构化场景默认） | 自主 | 自主 | 首次确认，本任务内可“一直允许” | 确认 | 确认 | 确认 | S1–S6 |
| **放手执行（只产草稿）** | 自主 | 自主 | 自主 | 预算内自主 | 确认 | 确认 | 批量、夜间任务 |

**没有“完全访问”档。** WorkBuddy 的“完全访问”、Kimi Work 的“全部”都要用户自担风险声明；在律师的执业场景里，这种档位的风险不能靠一句声明转移（最高法《关于依法审理涉人工智能纠纷案件的意见》要求场景化说明与可举证的风险控制）。

### 7.3 四层策略：最严者胜出

```text
中软基线（硬编码，任何人不可改）
  T6/T7 不是工具 · L4 禁入 · 出站白名单根集 · 签发须设备签名 · 无“完全访问”档
    └─ 律所策略（管理员在云端控制台编写，律所根密钥签名后下发；端侧与网关双重强制）
         允许的执行位置 · 模型端点 · 工具上限 · 数据级别规则 · IM 与导出策略 · 批准的连接器
         └─ 事项策略（事项负责人在客户端设置，负责人设备签名，事项账本内保存，摘要同步到控制面）
              密级 · 当事人同意状态 · 允许的端点与位置 · 是否授权执行器 · 是否允许 IM 收发文件
              └─ 任务档位（律师在发起任务时选择）
```

五个关键点：

1. **律所策略要律所根密钥签名。** 控制面只是策略的编辑器与分发器；端侧只执行带律所根密钥签名的策略。这样中软（或攻破控制面的人）不能偷偷放宽某律所的策略——例如把“拒绝云端”的事项改成允许。
2. **事项策略摘要同步到控制面，由网关二次执行。** 摘要只含匿名事项 ID、密级、同意状态与允许端点，并带事项负责人设备签名。网关据此挡住误配置、旧版本客户端、已吊销或未授权设备，以及标为 L3/涉密事项的请求；**挡不住**被恶意篡改、冒报其他事项 ID 的成员终端——这类行为由运营审计的异常检测事后发现（例如某设备在 L3 事项长期零请求而其他事项请求突增），列为已知限制。
3. **律所 Hooks（大所可选）**：借鉴千问办公的企业 Hooks（R1 §2），律所可登记自己的 HTTP 服务，由**律所侧内核**在“发起任务、调用工具、出站之前、任务结束”四个时点同步回调（例如律所 DLP、利冲系统、档案系统），回调结果只能拒绝或加审批、不能放宽；回调发生在律所网络内，不经中软云端。
4. **策略有版本与时效。** 律所策略带单调递增的版本号与有效期（默认 30 天），当前版本号写入透明日志；客户端拒收低于已见版本的策略，策略过期未续签时回退到“中软基线 + 最严默认模板”，防止控制面扣留新策略或回放旧的宽松策略。放宽类变更（允许云端执行、放开 L3a、开启 E4）须两名持有策略签名子证书的管理员签名。
5. **终端管理通道（大所可选）**：律所可通过 MDM 或组策略（注册表）下发一份更严的本地策略，作为第五层叠加，云端无法覆盖（Anthropic 认为终端管理下发的设置安全保证更强，R2 C3）。

“管理员拒绝的，用户不能批准”（OpenAI Agent Security 原则，R2 A2）在四层中统一适用：上层设为“禁止”的能力，下层界面不出现“允许”按钮。中软基线中的“出站白名单根集”是**目的地类别**的上限（中软服务、模型端点、已登记数据商、律所自有服务与律所批准的连接器、IM 平台）；律所在“律所自有/批准”类别内登记具体地址须经签名策略，不能新增类别。

### 7.4 人的权限：按平面拆开

| 角色 | 控制面（云端） | 内容面（律所侧，由事项成员资格 + 事项密钥决定） |
|---|---|---|
| 律所负责人（主任） | 查看全部运营数据与账单；任命管理员；律所治理仪式中生成律所根密钥 | 只看自己参与的事项；持有一张恢复卡；团队版默认持有审计密钥 |

| 风控 / 合规合伙人（律所版） | 运营审计、合规报表 | 持有“审计密钥”：可读全部事项的**审计事件头**（谁、何时、对哪个事项代号做了什么动作、外发了多少字节），读不到正文与客户全称 |

| 律师 / 助理 | 个人设置与设备 | 自己是成员的事项；任务档位 |

| 中软支持 | 经律所逐次授权的运营元数据只读 | 无法通过系统取得事项密钥；只有律所在客户端逐次授权的远程协助能看到屏幕内容，全程留痕 |
| 律所执行器 | 作为设备登记 | 只对逐事项授权的事项持有密钥 |
| 律所档案成员（可选） | 作为设备或角色登记 | 律所策略可设为事项默认成员（伦理墙事项除外），保证律师离职后律所仍保有业务档案（律师业务档案归属律所） |

### 7.5 审计：可见动作，不见内容

| 层 | 内容 | 存放 | 谁能看 |
|---|---|---|---|
| 运营审计 | 登录、设备登记与吊销、席位变动、策略变更、模型调用元数据（席位、匿名事项 ID、模板、token、耗时）、连接器调用计数 | 控制面 | 管理员、负责人、风控 |
| 审计事件头 | 匿名事项 ID、**事项代号**（律所内部编号，不含客户全称）、操作人、动作类型（审查、导出、签发、无显式标识导出申请、外发字节数）、时间、对象 hash | 律所侧事项账本，用“律所审计密钥”加密后经中继同步 | 风控合伙人（审计密钥；团队版为主任）；可选由执行器持“只读导出子密钥”导出到律所 SIEM（限事件头字段） |
| 审计事件体 | 文件名、片段、化名统计明细 | 律所侧，用事项密钥加密 | 事项成员 |
| 链头 hash | 每台设备每日检查点、每次签发的 hash | 控制面**透明日志**（只追加，律所可下载完整日志自行校验） | 任何人可验证一致性 |

不做“会话回放”：律所管理端看到的是“谁对哪个匿名事项做了什么、外发了多少”，不是律师与 AI 的完整对话（WorkBuddy 企业版的“完整会话回放”见 R1 §1，与伦理墙冲突）。这既满足深圳律协 2026 指引第 22 条“保留使用记录”、上海律协对“记录输入、生成与修改过程”的要求（内容级记录在律所侧，事项成员可调阅），又不破坏伦理墙。

### 7.6 本机数据的集中保留、删除与终端可见性

Anthropic 自己承认，本机执行的 Cowork 会话历史“管理员无法集中管理或删除”，且执行用的虚拟机对终端安全软件（EDR）不可见（R2 A1）。律所侧执行必须补上这两块：

| 问题 | v6.0 做法 |
|---|---|
| 会话与任务记录散落在各台电脑 | Agent 会话、工具调用记录、模型请求的去向记录都作为事项事件写入事项账本，经密文中继在成员设备间同步——不存在“只在某台电脑上”的记录（个人事项除外，且可选同步到本人其他设备） |
| 保留期与删除 | 律所策略规定各类记录的保留期（审计不少于 6 个月）；到期删除用“**轮换并销毁事项密钥**”（加密擦除）实现，所有设备与中继上的密文同时失效；删除事件进入透明日志 |
| 诉讼保全 / 档案 | 事项负责人或风控可对事项设“保全”，保全期间删除与密钥销毁被冻结；结案归档导出为开放格式（事件 JSON Lines + 原始文件 + 签名）交律所档案系统 |
| 设备离职 / 丢失 | 吊销设备证书 → 其他成员拒收其事件；轮换受影响事项密钥；已解密到本机的明文无法远程收回，如实告知（可选“密钥租约”：设备每 N 天须联网续租，超期本地密文不可读） |
| EDR 可见性 | 不用虚拟机：Agent 宿主与解析进程都是带代码签名的普通 Windows 进程（降权、作业对象），律所 EDR 能看到其文件与网络行为；提供进程、域名与签名清单供律所 IT 加白；可选把审计事件头导出到律所 SIEM（syslog/HTTP） |

## 9. 降级模式：各种“断”的时候产品怎么表现

| 情况 | 仍然可用 | 不可用或排队 | 界面怎么说 |
|---|---|---|---|
| 律师电脑断网 | 阅读、检索、法条核验、比对、计算、脱敏、文书生成、签发（离线签名） | 模型推理、案例核验、同步、IM | “离线：模型步骤已排队，联网后自动继续” |
| 中软控制面不可达 | 全部本机能力（本机解锁靠设备密钥 + 离线有效 30 天的许可）；推理（网关离线验证席位令牌、使用缓存的事项策略摘要、计量先写本地预写日志） | 新设备登录、同步、通知、IM、期限提醒推送 | “协作服务暂不可用，本机工作不受影响” |
| 推理网关或 MaaS 不可达 | 全部本机能力 | 模型步骤 | “模型通道繁忙/不可用，已排队”；**不自动切换到其他厂商** |
| 律师电脑关机 | 公开沙箱任务、期限提醒、他人协作 | 本人事项的内容任务（无执行器时） | IM 卡片：“你的电脑离线，任务将在上线后处理”；有执行器则“已转律所执行器” |
| 律所执行器故障 | 本机执行全部能力 | 关机续跑与批量 | 管理控制台告警；任务回到发起人电脑排队 |
| 许可到期未续 | **退出模式**：阅读、检索、导出、签名验证永久可用 | 模型、同步、新任务 | “许可已到期：可继续查看与导出全部事项” |
| 中软停止服务（极端） | 同“退出模式” | 协作、推理（标准端点） | 见下方三项承诺 |

**停服与退出的三项承诺**（写入主合同）：

1. 停服或终止合作前不少于 180 天书面通知，期间提供只读与全量导出服务；
2. 客户端内置“退出模式”：停服或许可过期后，本机阅读、检索、导出、签名与审计验证**永久可用**，只停止模型与同步；签发验证所需的公钥、证书链与透明日志检查点随导出包提供；
3. 律所可开启“定期增量导出到律所存储”（每周，开放格式：事件 JSON Lines + 原始文件 + 签名）；零服务器律所在开通时默认提示开启——这样即使中软中继突然不可用，律所手里也有不超过一周的完整副本，可用律所密钥离线解密。

## 10. 关键流程

### 10.1 首日：律所治理仪式 + 零服务器开通

```text
① 律所治理仪式（只做一次，约 10 分钟）
   律所指定的主任或管理合伙人在自己的设备上登录 → 生成律所根密钥与审计密钥
   （向导检测到登录者是中软或渠道实施账号时拒绝生成）
   → 打印 3 张恢复卡（主任 / 第二位合伙人 / 律所保险柜），可选登记中软托管的第 4 片
   → 签署首份律所策略（此前客户端按“中软基线 + 最严默认模板”运行，界面显示“律所策略待签名”）
② 成员开通
   律师下载安装 → 企业微信/钉钉/飞书扫码或手机号登录 → 本机生成设备密钥
   → 新设备显示 6 位确认码（由设备公钥派生的短认证串）
   → 批准人（主任、管理员或获委托的团队负责人）当面或电话获得确认码并输入，或用已登记设备当面扫码
     （不提供一键批准；控制面伪造的申请拿不到正确确认码）
   → 设备证书签发；新设备进入 24 小时观察期（期满或经本人另一台已登记设备确认后，才自动收到事项密钥）
③ 第一份合同
   拖入合同 → 本机解析（秒级）→ 化名片段经推理网关 → 修订卡 → 在 Word/WPS 打开
```

v5 的团队负责人首日路径包含“选择所内节点或共享文件夹、完成多名合伙人分持与恢复演练、决定哪些事项允许节点执行”；v6 首日只有一次 10 分钟的治理仪式与成员扫码；恢复演练是开通后 30 天内的检查项。

### 10.2 团队协作

```text
律师 A 建事项 → 本机生成事项密钥与“事项写入密钥”→ 用成员设备公钥（证书链与透明日志校验后）包裹
→ 事件段与材料块加密后写入密文中继（带设备签名 + 事项写入密钥签名）
→ 成员设备按“盲化订阅主题”（由事项密钥派生）收到“有新事件”的信令
→ 律师 B 的电脑出示读取令牌拉取密文、本地解密、重建投影
```

加人进事项：管理员在控制台发起，事项内任一成员的设备完成密钥包裹（自动弹出确认）；管理员自己无法完成——这就是“管理员拿不到正文”的技术保证。中继与控制面都不保存成员名单；但从同步与通知流量可以推断“哪些设备在同一事项中”，这一点在“中软看得到什么”中如实列出。

### 10.3 密钥与恢复

| 项 | 设计 |
|---|---|
| 律所根密钥 | 治理仪式中由主任或管理合伙人设备生成；**软件密钥**，由该设备 TPM 封装保存，只在仪式与迁移时可导出（“硬件不可导出”只适用于成员签发密钥与设备密钥）；用于签发设备证书、策略签名子证书与律所策略；另由“治理恢复”门限备份（见下） |
| 策略签名子证书 | 根密钥给不超过 2 名管理员设备签发有期限的子证书，用于日常策略签名；放宽类变更须两名签名人（团队版只有一名管理员时，以“管理员 + 主任”双签或 72 小时冷静期替代） |
| 事项恢复密钥 | 每把事项密钥另包裹给律所恢复公钥；恢复私钥按 **2-of-3 律所内分片**：①主任恢复卡 ②第二位合伙人恢复卡 ③律所保险柜恢复卡（档案或行政负责人保管）。不提供“只有两片”的配置——向导强制生成第三张 |
| 中软托管片（可选） | 作为**附加的第 4 片**（门限仍为 2）。释放须同时满足：两名不同合伙人在各自已登记设备上签名请求；72 小时冷静期；写入透明日志并通知全体管理员与受影响事项负责人；**释放对象不得持有其他分片**。目的只是“律所丢了两张卡时还能恢复”，而不是给任何一个人加一把钥匙 |
| 治理恢复（根密钥） | 根私钥另包裹给独立的“治理恢复”公钥，门限不低于 3 人（或 2 人 + 72 小时冷静期），与事项恢复不共用私钥 |
| 个人恢复包 | 每位成员可选一个由客户端随机生成的个人恢复码（≥ 128 位，打印保存），用来包裹本人设备私钥的备份——**电脑坏了恢复本人事项不触发律所破窗** |
| 专业版（单人） | 中软托管片只能与客户端生成的随机恢复码组合（≥ 128 位，不允许人选口令，防止中软离线暴力猜测）；人选口令只能用于本地备份 |
| 破窗 | 经客户端恢复向导动用恢复密钥时自动记录、通知事项成员、写入透明日志。**如实说明**：持片人离线合谋可以绕过记录，这属于律所内控范围，写入恢复卡保管制度 |
| 持片人变更 | 生成新恢复密钥对，由在线成员设备把事项密钥重新包裹给新恢复公钥（后台任务，进度在控制台可见），旧恢复卡作废并写入透明日志 |
| 根密钥轮换 | **计划轮换**（管理员变更）：新旧根签名并行 7 天；**泄露轮换**：立即切换，由治理恢复门限签名“旧根吊销声明”写入透明日志，客户端拒收时间戳晚于吊销声明的旧根签名 |
| 中软 | 正常运行中不持有解密密钥；律所选择托管片时持有一片，单片无法解密 |

### 10.4 从 IM 转来一份合同（无执行器、律师电脑在线）

各平台默认路径不同（R3）：

| 平台 | 默认收文件方式 | 文件到达律师电脑 | 中软接触到什么 |
|---|---|---|---|
| 飞书 | 中软商店应用机器人（单聊） | 中软只转发消息与文件编号，律师电脑用本人授权令牌直接下载（U1 实测） | 消息事件（含文件名）过境；不下载 |
| 钉钉 | 中软第三方企业应用机器人（单聊，Stream） | 中软把平台签发的限时下载地址转给律师电脑直接下载 | 消息事件（含文件名）过境；短时持有下载地址 |
| 企业微信 | **M3：每位律师一个个人智能机器人，连在本人电脑上**（企业微信的服务商应用收不到文件，R3）；或 M2 律所机器人 + 执行器 | 机器人长连接就在律师电脑或执行器上 | **不经中软** |

```text
律师在 IM 单聊把合同转给机器人
→ 卡片：“已收到 1 个文件（DOCX，2.1 MB）”［在电脑上归档］［在手机上选择事项］
   （卡片不含文件名与事项名；选择事项在电脑上或手机 H5 解密后的列表里完成）
→ 律师电脑下载文件、归入事项 → 本机执行审查 → 结果卡片：“审查完成：高风险 3 项”（不含客户名与案情）
```

电脑离线时：飞书、钉钉按下载地址有效期排队；企业微信的 5 分钟下载地址等不到电脑上线，卡片提示“请在电脑上线后重新转发”（M3 本来就要求电脑在线）。平台不支持直取时，退化为“过境加密转交”：中软在内存中接收文件、立即加密给律师设备、不落盘，并在数据去向卡中逐次标明。

### 10.5 合伙人在手机上签发

```text
律师申请签发 → 控制面向合伙人 IM 推送审批卡片（只含交付件类型与时间）
→ 合伙人点开 → IM 内 H5（合伙人此前登记过移动设备，见第 4 篇 §5.2）
→ 从密文中继取交付件密文 → 在手机内解密并完整预览确切文件
→ 确认 → 系统级用户确认（IM WebView 支持 WebAuthn 平台认证器时用生物识别，挑战值为交付件 hash）→ 移动设备签名
→ 同时通知合伙人桌面端；**24 小时撤回窗口**结束前，对外受众的交付件显示“已签发（撤回窗口中）”
```

保证等级：桌面设备签名 > 移动设备签名（有系统级确认）> 移动设备签名（无系统级确认，须 24 小时内桌面复核）> IM 身份确认（只记录点击）。律所策略决定每类受众需要的最低等级（例如法院版、对方版只接受桌面设备签名）。

**如实边界**：H5 代码由中软下发。被篡改的页面脚本可以在解密后外传内容，也可以在用户确认时替换待签内容。缓解措施是版本哈希公开于透明日志、系统级确认、桌面端通知与撤回窗口、L3 事项禁用手机预览；彻底解决需要经应用商店签名的独立 App，G2 后按移动签发的使用频率评估。

### 10.6 法规变更、公开监测与类案研究

```text
公开沙箱每日比对官方公报、全市场公告与公示变更 → 按全量或行业推送增量
→ 每台律师电脑在本地用本所的关注名单与事项引用关系匹配 → 生成“受影响事项清单”（只在本机）

研究任务：本机把争点抽象成派生公开查询（L0d）→ 律师逐条确认 → 公开沙箱检索法源、筛类案
→ 结果回到本机 → 与事项事实结合起草（化名后经推理网关）
```

## 11. 对外如实口径（v6.0）

| 不说 | 说 |
|---|---|
| “本地化部署”（标准端点时）、“数据不出律所”“零外传” | “**案卷在律所本地处理和保存；团队协作经中软云端同步加密数据，中软在正常运行中没有解密密钥；模型推理只收到化名后的必要片段，网关不落盘，上游留存以签署的企业协议为准**” |
| “中软看不到任何东西” | “中软看得到账号、设备、席位、用量、匿名事项的任务与提醒时间、经 IM 发送的文字与文件名；看不到案卷、成果、化名映射与事项名称”（完整清单见第 3 篇 §4.5） |
| “云端执行”（笼统） | “公开资料与律师确认的派生查询可在中软云端运行；客户事项默认只在律师电脑或律所自己的执行器上运行” |
| “端到端加密，绝对安全” | “协作数据端到端加密；手机预览以中软下发的页面代码未被篡改为前提；化名覆盖率、恢复安排与剩余风险见安全白皮书” |
| “本地执行所以合规” | “提供落实律协指引的控制手段：告知同意、化名、事项级端点与执行位置开关、不训练承诺（以月之暗面企业协议为准）、审计留痕” |
| “中软不是处理者” | “中软对协作密文与推理过境按受托人义务管理” |

**禁用词**：“技术上不可能”“从来没有”“绝对”“零风险”“数据不出所”（私有化全链路组合除外）。

“本地化部署 / 私有化部署 / 全链路本地化”只用于“**私有模型端点 + 律所执行器 + 律所自有存储 + 私有控制面**”的组合（上海律协居村指引 4.7 的定义：系统运行、数据存储与处理完全在本地环境内完成）。

## 12. 本篇的验收（进入第 4 篇探针）

1. 控制面、中继、网关、公开沙箱四个云端组件的数据库、对象存储、日志、缓存、错误报告中，抽查不到任何客户内容明文、事项名称、文件名与关注名单（红队 + 自动化扫描）；IM 卡片模板中不出现文件名与事项名。
2. 未经律所根密钥（或子证书）签名、版本低于已见版本或已过期的策略，在端侧与网关均被拒绝或回退到最严模板。
3. 管理员账号在控制台无法让自己获得任何事项正文；加人进事项必须由事项成员设备完成；控制面伪造的设备申请在没有正确确认码时无法获批。
4. 恢复：三张律所内恢复卡中任丢一张可恢复；中软托管片单独或与任何一张卡合谋，都必须经过冷静期与透明日志；个人恢复包可在不触发破窗的情况下恢复本人事项。
5. 中软控制面整体停机 24 小时：本机全部能力与推理可用，联网后同步无数据丢失；许可过期后进入退出模式，阅读与导出可用。
6. 已吊销设备、未签名事项 ID、标为 L3 或涉密事项 ID 的推理请求被网关拒绝；冒报事项 ID 列为已知限制，由异常检测规则覆盖。
7. 公开沙箱的网络与存储中不存在任何事项密钥、事项 ID 与客户材料；L0d 查询只在同意状态允许时出站，任务结束即删除。
8. 篡改 H5 静态资源后，不经合伙人系统级确认无法产生有效移动签名；做不到时，移动签名降级为“须桌面复核”。
