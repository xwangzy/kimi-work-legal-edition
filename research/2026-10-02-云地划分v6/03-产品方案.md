## 1. 产品定义

### 1.1 一句话

**「Kimi Work 法律行业发行版」是中软国际与月之暗面联合推出的律所法律工作平台：像 Kimi Work 一样在律师电脑上干活——案卷在律所本地处理与保存；团队协作、手机审批、IM 入口与期限提醒由中软云端承接，协作数据在云端只以密文存在；模型推理只收到化名后的必要片段，网关不落盘，上游留存以与月之暗面签署的企业协议为准。律师得到有出处、有版本、经律师签名签发的 Word/Excel 交付件；律所零服务器即可开通，大所可加律所执行器、自有存储与私有模型。**

### 1.2 相对 Kimi Work 标准版的六个增量（v6 更新）

| 增量 | 内容 | v6 的变化 |
|---|---|---|
| 法律能力包 | 工作流、Playbook 与本所覆盖层、模板、确定性规则库、离线法规库、授权法源 | Playbook 正文不再下发终端，由网关组装；规则更新当天全网生效 |
| 可信交付 | 原生修订、回稿比对、受众分版与泄露检查、引用四态、签名签发、AI 标识 | 增加**手机端端到端解密预览与移动设备签名** |
| 机构治理 | 事项与成员、伦理墙、复核与签发、策略、审计、席位与额度 | 管理控制台上云（任何地点可用）；审计分三层，**看得到动作、看不到内容** |
| **律所持钥的数据主权** | 案卷明文只在律所持久保存；协作数据在中软云端只以密文存在、律所持钥；每次外发与过境记入数据去向卡 | 由“数据只在律所局域网”升级为“律所持钥”，不再需要所内服务器 |
| 入口 | Word/WPS、企业微信/钉钉/飞书、个人微信材料导入 | IM 由“律所自建 + 所内节点”改为默认零 IT 开通；新增 IM 内手机 H5 |
| 服务与生命周期 | 规则上线、培训、客户成功、LTS、合规材料包 | 中软能看到运营元数据，服务等级可兑现 |

### 1.3 与 Kimi Work 标准版的关系

| 类别 | 内容 |
|---|---|
| **沿用（已获授权）** | 视觉与版式；统一任务输入（`/` `@` `+`）；任务化会话；执行态三栏；挂载本地文件夹；本地 Agent 执行；Office 直出；看板与小组件；定时任务交互形态；手机远程查看与上传附件的交互（Kimi Work 3.2.14） |
| **增强** | 「项目」→「事项」；「技能」→ 签名法律方法包；「看板」→ 事项与团队看板；「定时任务」→ 云端期限提醒 + 公开监测 + 执行器内容任务（关机不漏）；运行权限三档 → 四档 + 四层策略 |
| **收敛** | 不开放 Shell 与本机任意进程；无“全部/完全访问”档；不驱动律师本人浏览器、不导入 Cookie；插件只允许中软签名连接器与律所管理员批准的连接器；Agent 集群改为内核控制的有界并行 |
| **新增** | 无网络计算沙箱；隔离浏览器辅助（默认关）；公开任务云端 7×24；律所执行器；密文中继协作；手机签发 |

### 1.4 它不是什么

不是法律数据库；不是律所管理系统（可对接）；不是自动出具法律意见的机器（律师签发）；不是通用编程或电脑操控 Agent；**不是中软托管案卷的云服务**（云端只有密文与元数据）；不向律师个人开放任意插件市场；不做判决预测与法官画像；**不提供“完全访问”档**。

## 2. 产品形态：五个入口 + 律所侧内核 + 云端协同

| 组成 | 主要用户 | 做什么 | 运行在 | 阶段 |
|---|---|---|---|---|
| **桌面客户端**（Windows 11 / 受支持的 Windows 10；macOS 2027-Q3） | 律师、助理、合伙人 | 主工作台；内嵌本机法律内核 | 律师电脑 | G1 |
| **Word / WPS 加载项** | 律师 | 文档内审合同、写修订、核验引用、比对、脱敏导出（v5 不变） | 律师电脑 | G1 |
| **企业微信 / 钉钉 / 飞书入口** | 律师、助理、合伙人 | 转材料、发起任务、查进度、收提醒、审批卡片 | 云端控制面 + 律师电脑或执行器 | G1 首家 |
| **手机 H5（IM 内）** | 合伙人、律师 | 端到端解密预览待签发文件、移动设备签名、查看任务结果摘要 | 手机 + 云端中继 | G1 |
| **管理控制台（Web）** | 管理员、负责人、风控、知识管理、财务 | 成员、设备、席位、策略、连接器、IM、执行器、用量账单、运营审计、合规材料 | 中软云端 | G1 基础、G2 完整 |
| **律所执行器**（可选） | 律所 IT | 关机续跑、批量、内容型定时、私有模型与自带密钥网关、IM 隐私最大化模式 | 律所任意常开设备 | G2 |
| 云端服务 | — | 控制面、密文中继、法律推理网关、公开任务沙箱、法源服务 | 中软云端 | G0 起 |
| 客户协作分享（端到端加密链接） | 律所的企业客户 | 接收交付件、反馈 | 中软云端（只存密文） | G3 |

不做独立手机 App：手机端能力由 IM 内 H5 承担；手机显示不全时转桌面签发。

## 3. 首日激活：零服务器，第一个交付件 ≤ 30 分钟

| 步骤 | 律师看到什么 | 设计要点 |
|---|---|---|
| 0 律所治理仪式（律所只做一次） | 主任或管理合伙人在自己电脑上生成律所根密钥与审计密钥，打印 3 张恢复卡，签署首份律所策略（约 10 分钟） | 登录者是中软或渠道实施账号时拒绝；签署前客户端按“中软基线 + 最严默认模板”运行，显示“律所策略待签名” |
| 1 安装与登录 | 一键安装；企业微信/钉钉/飞书扫码或手机号登录 | 云端身份；管理员预配的团队与席位生效 |
| 2 设备批准 | 新设备显示 6 位确认码 → 告诉批准人（当面或电话）→ 批准人在自己设备上输入确认码 | 不提供一键批准；确认码由新设备公钥派生，控制面伪造的申请拿不到；新设备 24 小时观察期后才自动收到事项密钥（本人另一台设备确认可提前） |
| 3 示例事项 | 虚构“股权转让（受让方）”事项与已完成交付件 | 标注“示例” |
| 4 第一份真实合同 | 拖入 DOCX 或挂载文件夹；同意状态默认“待取得”时只运行本机能力并提示一键生成告知函；选“已同意 / 无需”后使用模型 | 解析在本机即时完成；显示预计点数与数据去向预览 |
| 5 执行与审阅 | 计划 → 执行流（本机步骤与模型推理步骤分开显示）→ 修订卡键盘流 | 执行位置徽标常显 |
| 6 在 Word/WPS 打开 | 一键打开带原生修订的文件 | — |
| 7 客户版与签发申请 | 受众检查 → 预览 → 申请签发 → 合伙人手机收到卡片 | 首日可体验手机预览 |

团队负责人首日另一条路径：邀请成员 → 选择 IM 平台并安装（§6）→ 设定签发规则与手机签发允许的受众 → 下载告知同意模板 → 选择基础 Playbook → 选 3–5 份本所历史意见（属客户材料，按其所属事项的同意状态处理：未取得同意时只在本机用确定性规则与脱敏后的片段提炼，或改用本所范本）由规则提炼助手生成候选覆盖规则。**不再出现“选择所内节点或共享文件夹”**；恢复演练是开通后 30 天内的检查项。

## 4. 让律师看得见“在哪里执行、用了什么权限”

### 4.1 事项头（v6 增加两项）

客户 / 相对方 / 立场 / 法域 / 关键日期 / 保密等级 / 模型端点 / **执行位置**（本机 · 允许律所执行器 · 允许过境执行）/ 当事人同意状态 / **数据级别**（一般 · 敏感 · 涉密）。

### 4.2 执行位置徽标

| 徽标 | 含义 | 颜色（沿用 v5 令牌并扩展） |
|---|---|---|
| 本机 | 在这台电脑上执行 | 中性灰 |
| 律所执行器 | 在律所自己的执行器上执行 | 深灰 |
| 模型推理中 | 化名片段正在发往 Kimi | Kimi 蓝描边 |
| 云端公开任务 | 在中软云端处理公开资料（不含本事项材料） | 蓝灰 |
| 云端过境执行（G3） | 本任务材料在中软云端内存中处理、结束销毁 | 橙色描边，常显警示 |
| 等待联网 / 等待电脑上线 | 排队中 | 浅灰 |

### 4.3 任务档位选择器

输入框右下角的档位选择：“只问不做 / 先出计划 / 标准 / 放手执行（只产草稿）”。规则：

- 选项只显示上层策略允许的档位；被禁止的不出现（不显示灰色“申请开启”以免诱导）。
- 切到“放手执行”时显示本任务预算上限与将自动执行的能力清单（例如“计算、授权法源查询”）。
- Agent 请求确认时，卡片写明“它要做什么、为什么、会不会让数据离开这台电脑”，提供“本次允许 / 本任务内一直允许 / 拒绝”；“本任务内一直允许”不跨任务。

### 4.4 数据去向卡（v6 新增类别）

“本任务向 Kimi 模型（经中软法律推理网关）发送了 3 份文档的 42 个段落、共 18,240 字，其中化名 37 处；向中软法源服务发送 2 条去标识查询；协作数据经中软密文中继同步 14 个加密事件（中软无密钥）；经企业微信收到原件 1 份（下载地址经中软转交、未经中软下载）；原件与成果的其余副本未离开律所侧。”可展开到逐段落、请求 ID、同步序号。

### 4.5 “中软看得到什么”页

“连接”页新增一张固定表，律师与客户都能看懂：

| 中软看得到 | 中软看不到 |
|---|---|
| 账号、手机号、所属律所与团队、角色 | 案卷原件、解析文本、成果、修订 |
| 设备数量与公钥、登录时间与 IP | 事项名称、客户名称（不主动收集；但你在 IM 里输入的文字会过境，见左栏） |
| 用量：任务模板类型、点数、token 数、耗时 | 化名映射表 |
| 每个匿名事项的任务与活动时间、期限提醒的时间与类型；从同步与通知流量可推断哪些设备在同一事项中 | 事项成员名单（中继与控制面不保存）、审计事件内容 |
| 加密后的协作数据（正常运行中无解密密钥；选择中软托管恢复片时持有一片，单片无法解密） | 签发私钥、事项密钥、律所根密钥 |
| 推理时过境的化名片段（网关不落盘；上游以企业协议与审计为准） | 关注企业名单（只在本机匹配） |
| M1 模式下经 IM 机器人发送的文字与文件名（过境、不落盘；使用 M2/M3 时没有）；钉钉/飞书文件的短时下载地址或编号 | 经 IM 转来的文件内容（默认由律师电脑直接下载） |
| 律师确认后发往公开沙箱与法源服务的派生查询 | 手机预览的交付件（前提：中软下发的 H5 页面代码未被篡改，版本哈希公开于透明日志） |

## 6. 企业微信 / 钉钉 / 飞书入口

### 6.1 三种接入模式（律所在控制台选择）

| 模式 | 说明 | 文件是否经中软 | 律所需要做什么 |
|---|---|---|---|
| **M1 标准** | 中软服务商应用负责登录、通知、卡片与手机 H5；收文件由“律所机器人”承担（企业微信：律所在后台扫码一键创建智能机器人；钉钉/飞书：按 R3 结论用服务商应用或一键创建的自建应用），机器人连接由中软云端托管 | 中软云端只转交平台签发的**限时下载地址与一次性解密密钥**给律师电脑，由律师电脑直接下载；中软不下载、不留存（如实记入数据去向卡） | 管理员扫码安装与授权，约 5 分钟 |
| **M2 隐私最大化** | 律所自建应用/机器人，凭据只放在律所执行器，执行器以长连接收消息、下载文件 | 不经中软 | 需要执行器；管理员在平台后台建应用 |
| **M3 个人遥控** | 律师自建个人机器人，连在自己电脑上（WorkBuddy、千问办公同款） | 不经中软 | 律师本人扫码创建；只处理本人事项；电脑须在线 |

**M1 在三家平台的具体做法**（R3 一手核验）：

| 平台 | 中软服务商应用负责 | 谁收文件 | 文件怎么到律师电脑 | 中软能否技术上下载 | 待实测 |
|---|---|---|---|---|---|
| **飞书** | 商店应用：扫码登录、消息与卡片（事件只能走 HTTP 回调，长连接仅限自建应用）、H5 | 同一商店应用的机器人（单聊） | 中软只转发 `message_id + file_key`；**律师电脑用本人 OAuth 得到的 user_access_token（权限可收窄到只读消息）直接调资源下载接口** | 能（中软持有商店应用的租户令牌），但转发内容不含任何可下载凭据 | 本人令牌能否下载“本人与机器人单聊”中的文件 |
| **钉钉** | 第三方企业应用：登录、互动卡片、H5；机器人消息经 **Stream 长连接**（官方协议文档写明支持第三方应用 SuiteKey，中软一条连接服务全部授权律所） | 应用机器人（单聊收文件） | 中软用授权企业令牌把 `downloadCode` 换成带过期时间的签名下载地址，只把地址转给律师电脑直接下载 | 能（持有授权企业令牌） | 下载地址有效期；SuiteKey 建 Stream 实测 |
| **企业微信** | 第三方应用：登录、应用消息、模板卡片、H5（接口许可约 4–5 元/账号/年，20 人律所约 85 元/年） | 企业微信的自建、第三方、代开发应用都**收不到文件**，只有企业内创建的智能机器人能在单聊收文件（R3）。**默认 M3**：每位律师在企业微信里扫码创建个人智能机器人，长连接在本人电脑上；或 **M2**：律所机器人 + 执行器。“律所机器人由中软托管长连接”须等 U3 书面确认后才作为选项 | 机器人在律师电脑或执行器上直接收到 5 分钟预签名地址 + 唯一解密密钥，本地下载解密 | **不能**（M2/M3 下中软不在文件路径上） | 机器人非超级管理员创建时 `from.userid` 为加密 ID，按人路由需律所授权一个最小权限代开发应用做 ID 转换（第 4 篇 §5.1） |

共同点：飞书、钉钉 M1 下**中软默认不下载、不留存客户文件**，但在短时窗口内具备下载能力（持有平台令牌或短时地址），消息事件中的文件名会过境，数据去向卡如实记录；企业微信默认 M3/M2，中软不在文件路径上。要求“中软在技术上也碰不到”的律所在三家都可选 M2 或 M3。

### 6.2 对话流（单聊）

1. 律师把客户发来的合同转给“法律助手”机器人（单聊）。
2. 机器人回卡片：“已收到 1 个文件（DOCX，2.1 MB）”［在电脑上归档］［在手机上选择事项］。**卡片不带文件名与事项名**；选择事项在电脑上或手机 H5 解密后的事项列表里完成。律所可显式开启“卡片显示事项简称”，开启时提示“事项简称将以明文经中软与 IM 平台”，并记入数据去向卡。
3. 选好事项后：**电脑在线** → 电脑直接下载文件、归入事项、开始审查；**电脑离线且有执行器（事项已授权）** → 执行器处理；**都没有** → 飞书、钉钉按下载地址有效期排队，过期则请律师重新转发；企业微信 M3 本来就要求电脑在线，卡片提示“请在电脑上线后重新转发”。
4. 完成后卡片：“审查完成：高风险 3 项、需客户决策 2 项”［手机预览］［在电脑打开］。
5. 合伙人收到签发卡片 →［手机预览］在 IM 内 H5 端到端解密完整文件 →［签发］移动设备签名；律所策略要求桌面签名的受众只显示“到电脑上签发”。

安全规则：只响应已绑定的律所成员（配对模式，禁用“所有人可对话”）；群聊须 @ 且不收文件；卡片不含文件名、事项名、客户名与案情；引导律师不在 IM 里输入案情（文字会过境中软与 IM 平台）；个人微信、QQ 渠道不开通；L3a 事项默认“IM 只发通知”，L3b 事项禁止 IM 收发文件。

### 6.3 平台优先级

首发一家，按三家设计合作律所实际使用的平台定；钉钉与飞书的服务商应用能力差异见 R3。开通时间：飞书、钉钉约 5 分钟（管理员安装应用）；企业微信约 10–15 分钟（安装第三方应用 + 律师各自扫码创建个人机器人，或管理员建律所机器人并部署执行器）。开通时向律所说明各平台限制（企业微信文件只能单聊、下载地址 5 分钟有效；飞书外部群不能下载资源等）。

## 7. 手机：审阅与签发

| 能力 | 做法 | 保证等级 |
|---|---|---|
| 收到签发请求 | IM 卡片（交付件类型 + 时间，不含事项名） | — |
| 完整预览 | IM 内 H5 从中继取密文，在手机内解密，渲染申请签发时预生成的 PDF | — |
| 签发 | 手机上的移动设备密钥签名 + 系统级确认（IM WebView 支持 WebAuthn 平台认证器时用指纹或面容，挑战值为交付件 hash）；签发后桌面端同步收到通知，**24 小时撤回窗口** | **移动设备签名** |
| 退回与批注 | 退回原因 + 简短批注（加密写回事项） | — |
| 登记与续期 | 首次使用时由本人桌面扫码登记（移动设备证书由本人桌面设备在根证书授权下签发，有效期 ≤ 90 天，每人最多 1 张）；到期前 14 天桌面端在线时提醒续期 | — |
| 降级 | 不支持系统级确认：移动签名须 24 小时内桌面复核；手机密钥丢失（清缓存、换机）或出差无法重新登记：“IM 身份确认 + 24 小时内桌面补签”，补签前交付件标记“待补签”，不阻断交付 | 依次降低 |

律所策略示例：“内部稿、客户版：移动设备签名即可；法院版、对方版：桌面设备签名。”

如实边界：H5 页面代码由中软下发，手机预览与签名的安全性以代码未被篡改为前提；版本哈希公开于透明日志，L3 事项默认禁用手机预览。是否做经应用商店签名的独立 App，G2 后按移动签发使用频率评估。

## 8. 提醒、定时与公开监测

| 类型 | 运行在 | 关机时 | 例子 |
|---|---|---|---|
| **期限提醒** | 云端调度 | 照常提醒（IM + 桌面通知；专业版无 IM 时用桌面通知，可选绑定个人机器人或短信推送到手机） | 上诉期、举证期限、诉讼时效、合同节点；卡片只含期限类型与时间，事项名在手机 H5 或电脑上解密显示 |
| **公开监测** | 云端公开沙箱 | 照常运行 | 法规变更、全市场公告与企业公示信息的增量（按全量或行业推送）；**律所的关注企业名单只在本机或执行器匹配**，不上传——关注名单本身可能是并购标的等敏感线索 |
| **影响分析** | 律师电脑（收到“哪条法规变了”后在本机比对） | 上线后执行 | “《××条例》第 12 条修订，影响你的 3 个事项、5 份成果” |
| **内容型定时** | 律所执行器；无执行器时下次开机执行并提示“错过 1 次，已补跑” | 有执行器照常 | 事项周报、常年顾问月报 |

与 Kimi Work、千问办公桌面端“关机不跑、不补跑”的定时任务（R1）相比，期限类提醒与 Agent 执行解耦，提醒不依赖律师电脑。

## 10. 一个事项的一周（v6）

周一上午，客户在个人微信上把对方发来的股权转让协议发给经办律师。律师在企业微信单聊里把文件转给自己的个人机器人（M3）。律师电脑在线，机器人连接就在这台电脑上，直接下载文件；卡片上只写“已收到 1 个文件”，律师在电脑上把它归入事项“甲公司受让乙公司股权”，按受让方立场与本所覆盖层首轮审查——合同在本机解析，只有化名后的条款片段经中软法律推理网关发给 Kimi；网关在服务端填入中软的股权转让 Playbook，律师电脑上没有 Playbook 正文。15 分钟后企业微信收到摘要卡片。同组的助理在家里打开客户端，经密文中继同步到了最新结果，不需要 VPN。律师处理修订卡、在 WPS 里微调，保存后版本回传。周二合伙人在机场收到签发卡片，在企业微信里打开 H5，手机解密并完整预览客户版意见书，指纹确认后用移动设备签名签发；他的桌面端同步收到通知，24 小时撤回窗口过后交付件显示为“已签发”。周三云端提醒“补充协议约定的付款节点还有 7 天”。周四对方回稿，律师在高铁上断网，本机比对只重审被改动的 6 个条款、标出一处静默改动，法条核验离线完成；需要模型的 2 处排队，联网后续跑。当晚律师让 Agent 计算延期付款的违约金，本机计算沙箱给出明细表。客户问“你们用 AI 会不会泄露我们的交易信息”，合伙人打开“中软看得到什么”与数据去向卡：案卷在律所电脑上处理与保存，协作数据在中软云端只以密文存在，模型只收到化名片段，企业微信的文件是律师电脑上的机器人直接收的、没有经过中软，每一次都有记录。

### 10.1 离职、换电脑与出差：日常 IT 时刻

| 时刻 | 发生什么 | 产品怎么做 |
|---|---|---|
| 律师离职 | 管理员在云端控制台一键回收 | 吊销设备证书与席位令牌 → **事项负责人移交**（管理员发起，任一在线成员重签事项策略摘要；网关对已吊销负责人签名的摘要给 7 天宽限，控制台显示“待移交事项 N 个”）→ 后台轮换相关事项密钥（进度可见，成员设备上线即完成）→ 律所档案成员确认归档 |
| 电脑坏了换新电脑 | 新设备没有任何事项密钥 | 本人用**个人恢复包**（开通时打印的随机恢复码）恢复本人设备私钥备份，不触发律所破窗；共享事项也可由在线同事设备重新包裹 |
| 电脑丢失 | 设备上有加密的事项数据 | 吊销证书 → 其他成员拒收其事件 → 轮换事项密钥；静态数据加密，如实告知“已解密到本机的明文无法远程收回”；可选密钥租约 |
| 出差手机签发 | 手机密钥被清缓存或过期 | IM 身份确认 + 24 小时内桌面补签，交付件标“待补签”，不阻断交付 |
| 中软停服 | — | 退出模式：阅读、检索、导出、签名验证永久可用；律所每周增量导出副本可离线解密（第 2 篇 §9） |
