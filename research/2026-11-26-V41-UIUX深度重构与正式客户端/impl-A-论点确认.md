## 2. 设计判断

律师在这一步只回答三个问题：**这条论点要不要 → 依据靠不靠得住 → 哪些事实我认**。卡片按这个顺序排，系统文字只在需要时出现。

1. **卡头只留一行标题 + 一句话 + 至多一行汇总**。规则与三色含义收进“规则”弹出说明（点开看，点别处 / Esc 收起；“签发时须写明不确认的理由”仍在，D-151 相关用例照常通过）。汇总行每项可点：点“n 条论点有要件缺证据”展开这些论点并滚到第一条；点“n 条事实待你确认”展开底部事实清单并把焦点放到复选框。没有橙色整块（§2.3“浅橙底块同一视图最多一处”——现在一处都不用）。
2. **论点是主角**：序号、论点原文（14px/500，全卡唯一的 600 是标题）、一句结论信号、右侧“采用 / 改写 / 不用”三选一。
   - 结论信号 = 色点 + 最要紧的一件事 + 其余简称：如“● 4 个要件缺证据，如「原、被告之间存在有效买卖合同关系」；另有 1 条事实待你确认”。优先级：依据有问题（红）→ 条文未核实 → 类推 → 要件缺证据 → 事实待确认 → 都没有（绿“条文已核，要件都有事实”）。
   - 结论词（依据已核 / 有疑点 / 依据有问题）只给读屏，不显示：第二轮自评时五行都是橙色“有疑点”，重复的词抢走了焦点；那一句本身已经说清是什么问题，颜色不是唯一信息来源。三色定义在“规则”里。红色行的那句话用红字加重，是全卡唯一的强调色文字。
   - 三选一用分段控件（不是开关）：选“改写”就地出现编辑框（光标放在末尾），点“采用”等于原来的“恢复原文”，点“不用”划掉并说明“起草时不写这条”。
3. **展开后固定顺序**：法律依据（条文全称、核验色点、适用方式、按需“条文原文”、是否引用的复选框，下面一行“助手理由”）→ 事实依据（按法条短称分组的要件，右侧写“缺证据 / 事实 n · 待你确认 / 事实 n · 已确认 / 双方无争议 / 对方举证”；事实全文在本组末尾只列一次）→ 风险提示（但书与例外、对方可能这样反驳）。
   - 简报要的“AI 建议（为什么提这条论点）”：数据里没有论点级理由字段，只有每条依据的 `note`（怎么支持）。我把它作为“助手理由”放在对应法条下，没有另造一段系统生成的话；论点级理由需要内核加字段，列为 P3。
4. **底部真正固定**：去掉卡片 `overflow`；`bottom` 取任务页滚动区底部内边距的负值（`.exec-mid` 32px），否则 sticky 以内容框为界会在操作区下面露出 32px 正文（截图台实测）。核对声明“同时确认这 n 条事实（我已对照材料核过）”**缺省不勾**，旁边“逐条看”列出每条事实及引用它的论点；下面一行说明不勾的后果（写得保守、进核对清单）。
5. **口径统一**：每条论点的结论、卡顶汇总都由 `argVerdict` 一个函数算出；卡顶“n 条事实待你确认”与底部复选框用同一个 `unconfirmedFactsOf`（只算内核 `confirm_facts` 能确认的那些）。
6. **事实状态按现状**：`liveFactState` 以论点上那份（内核会刷新）为准覆盖要件里的快照（修 A8）。
7. 卡片按自身宽度换排（容器查询 ≤600px：三选一移到论点下方），右栏展开或小窗口时不挤。
8. 视觉：一层 16px 圆角容器（规范写 14px，但令牌门禁只允许 `--r-*` 六级，取 `--r-lg`）；行间用内缩 1px 分隔线；展开行用浅底色块而不是第二层边框卡；平铺不加阴影；色值全取令牌，深色模式随令牌。
