# 01 逐页问题与根因（改前截图：`evidence/before/`，第 66 批 b9e46f18，同一份真实工作区）

> A 论点确认、D 成果、E 预览的问题与根因由各自实施记录（`impl-A/D/E`）逐条写明代码位置；本文写主会话负责的 B、G 与跨页问题，并汇总全部工作线的结论。

## B 功能卡片（开始面板，52 张卡共用 `components/ScenarioStart.tsx`）

| # | 截图上看到的 | 根因 | 级 |
|---|---|---|---|
| B1 | 右栏“你得到什么 / 预计用量 / 发送什么、发给谁”占约三分之一宽度，常驻 | 第 66 批把“交付件、用量、去向”做成固定右栏（`ScenarioStart.tsx` 原 `ss-aside`，`styles-start.css` 原 `.ss-grid` 两栏）。这三块是**确认信息**不是**输入**：律师点开“起草起诉状”时已经知道交付起诉状；“按实际用量计入本月额度”对每张卡都一样，没有信息量 | P1 |
| B2 | “预计用量”只有一句固定话 | 内核 `runs.estimate` 的 `points_display` 在额度制下就是“按实际用量计入本月额度（本月已用 x%）”；卡片之间没有差别 | P1 |
| B3 | 去向五条要点全部展开，最重要的“发给谁、哪些换成代号”与次要的留存说明同权重 | `SendPoints` 原样平铺 bullets；披露是必要的，但放在离开工按钮最远的右栏底部，开工那一刻反而看不到 | P1 |
| B4 | 52 张卡同一个顺序：材料 → 要定的事 → 当事人 | 第 55/66 批的统一模板；只有“有必填项时把要定的事提前”一条例外（原 `decideFirst`）。起草类的核心是“请求 + 当事人”、审查类是“那份合同 + 立场”、比对类是“两稿先后”、研究类是“问题”，同一顺序让多数卡的关键输入落在首屏下方 | P1 |
| B5 | 段标题都叫“案情与材料 / 这次要定的事”，带黑色编号圆点 | 段名不随业务；编号圆点与主按钮同色（`--btn-primary`），视觉上抢主按钮 | P2 |
| B6 | 回稿比对：只写“依次勾选”，看不出哪份是基线稿、哪份是回稿，直到勾上才出现小标签 | 勾选顺序即先后（内核约定），界面没有“两个位置”的表达 | P1 |
| B7 | 回稿比对（不用 AI）也写“读取全部 1 份” | `scopeShort` 不分是否用 AI；确定性流程没有“可读全部”的概念 | P2 |
| B8 | 逐项请求：编号圆点在输入框外，输入框右端与其他输入框不齐 | `.ss-list-row` 三列网格（编号 / 输入 / 删除），与单行输入框宽度不同 | P2 |
| B9 | 模型选择在右栏中部，离开工按钮远 | 第 66 批把 ModelPicker 放在右栏“模型”块 | P2 |
| B10 | 补全提示（“这个事项还缺：事件时点”）是一整行浅底块 | `FactHints` 独占一行 + 背景色；不拦开工的提示占了首屏一行 | P2 |

## G 首页上传材料菜单（`components/Composer.tsx`、`MaterialPicker.tsx`）

| # | 截图上看到的 | 根因 | 级 |
|---|---|---|---|
| G1 | 选了事项时点“+”直接弹系统选择框，看不到文件会进哪个事项、也没有“选用已有材料” | `tool-plus` 的 onClick 在有事项时直接 `pickFiles()` | P1 |
| G2 | “@ 材料”弹层：标题一行 + 两句说明（原件只读、代号、可读范围）+ 清单 + 底部整条虚线拖放框 | 说明、范围、隐私三件事挤在标题下；虚线框常驻，清单只有 1 份时虚线框比清单还显眼 | P2 |
| G3 | 弹层只有虚线框那一条能接拖放 | 拖放只挂在 `.mp-drop` 上 | P2 |
| G4 | 弹层出现没有过渡，阴影与输入框不是一套 | 用的是通用 `.popover`（6px 圆角感、无动效） | P2 |

## H 主动发现的同类问题

| # | 问题 | 处理 |
|---|---|---|
| H1 | 开始面板的 Esc：弹层（模型、去向详情）打开时按 Esc 会把整个开始面板关掉 | 新弹层在捕获阶段截住 Esc（`useDismiss`） |
