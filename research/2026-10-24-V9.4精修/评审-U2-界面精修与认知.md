## 0. 一页结论

总体：主路径（首页 → 开始面板 → 确认 → 执行 → 交付件）已经是成熟产品的骨架，U1 的大项基本落地。剩下的问题集中在三类：**合伙人可见的“管理”层仍是研发现场**；**确认与不可逆操作的呈现方式会误导**；**设置等表单页没有统一的行、控件和保存规范**。以下按对律师的伤害排序。

1. **“管理 · 技术支持 · 诊断”把研发内部台账原样给客户看**（U2-13、U2-14）：约 40 行能力账本，含“待实现 · G0”“偏离 D-10”“复核 B4-B05”“kap-server”“HostProcessService.spawn”和“销售口径如实”。“管理”对合伙人开放，这一屏会直接让人怀疑产品没做完。P0。
2. **“核对码”一个词指三样东西，还有“安全码”这个别名**（U2-06）：电话核对时律师会读错那一串数字，管理员可能按错的批准。P0，改词即可。
3. **开始前确认卡的风险提示前面是绿色对勾**（U2-24）：“没认出的姓名也按原文”“服务方是否保存以企业协议为准”看起来像“已处理好”。确认卡也不回显律师写的任务原话（U2-23）；开始面板在 1280×720 下看不到主按钮（U2-22）。
4. **任务和成果没有可辨认的名字**（U2-28）：任务名就是原话（带尾部分号），成果统一叫“助手草稿”，分类叫“通用任务”；交付件页、首页“继续工作”、事项待办都靠这些名字认东西。
5. **设置表单不成体系**（U2-01～U2-03，用户点名）：“函头 / 正文”标签贴在按钮顶部，和按钮不在一条基线；内联标签和上置标签混用；原生复选框；三个同权按钮挤在一行；“用律所 Word 模板”其实是另一种来源，却和“保存”并列；同屏两个“保存”，改了不保存就静默丢失。
6. **不可逆操作的确认是行内一句长话**（U2-21、U2-18）：“停用这台电脑”的 60 字后果说明插在表格格子里；“移出律所”的确认卡出现在整张表下方；电脑只按“加入时间”区分，管理员分不清停哪一台。
7. **合伙人看得到的规则页仍是研发词**（U2-17、U2-15、U2-16）：“敏感事项（L3a）经标准端点”“抓取允许访问的网站追加”“回退最严模板”；设备表角色列是英文“admin”；技术版数据去向表在 1280 宽下右侧被裁掉。
8. **版面节奏**（U2-29～U2-31、U2-35）：事项概览自动流式排版留下空格子，“待办 / 待核”两张卡讲同一件事；同一行控件高度不一（26px 胶囊接 36px 下拉）；分段控件有三种样子；交付件 6 行 12 个蓝色链接。

## 1. 设计规范增补（只写新定或要改的；每条都能检验）

### 1.1 字号、行高、间距档位怎么用
- 正文、表单、按钮、设置说明：`--fs-body`（14px）/ 行高 1.6。`--fs-caption`（13px）只用于表格内次要信息、时间、计数和控件下方的一行说明；**多于一行的说明段落不得用 13px**。检验：`.muted` 以外，凡 `--fs-caption` 的选择器所渲染的元素，高度 ≤ 1 行（Playwright 抽查 5 页）。
- 标题：h1 `--fs-h1`（20px/600）；分区标题 `.section-h` 16px/600，上距 `--sp-5`、下距 `--sp-2`；卡片标题 14px/600。分区标题与卡片标题必须差一级（现在两者都是 14px/600，`styles.css:81`、`:434`）。
- 间距只用 `--sp-1…7`：同组控件之间 `--sp-2`；同一块里行与行 `--sp-3`；块与块 `--sp-5`；标签与控件横向 `--sp-4`、纵向（上置标签）`--sp-1`。卡片和面板内边距统一 `--sp-4`（现在 `.card` 13px 15px、`.panel` 16px 18px、`.banner` 9px 13px）。检验：本轮改动涉及的选择器里，padding / margin / gap 不出现 5、6、7、9、10、13、14、15、18px。

### 1.2 表单行布局
- 设置页一级行 `.device-row`：左列 120px 标签（`--text-primary`、500），右列控件。一级标签不比块内子标签浅（U2-03）。
- 一级行内有多个子项时用 `.form-grid`：`grid-template-columns: 88px 1fr; column-gap: var(--sp-4); row-gap: var(--sp-3); align-items: center`；子标签 ≤ 6 字、`--text-label`；多行控件（文本框、两条地址）这一格 `align-self: start`，标签 `padding-top: 7px`（等于输入框内边距）。
- 同一块里只用一种标签方式：要么全部左置（`.form-grid`），要么全部上置（`.field`）。字段说明一律放在控件**下方**，≤ 25 字，不放进标签括号里。
- 检验：同一行标签与控件的文字中线差 ≤ 1px；同一块左缘对齐线 ≤ 2 条。

### 1.3 设置行（只有一个动作的行）
- `.setting-row`：左“标签 + ≤ 25 字说明”，右侧控件或按钮，右对齐、垂直居中（Astra A1）。用于“导出诊断信息”“详细运行记录”“示例事项”等。检验：动作按钮右缘与面板内容右缘对齐。

### 1.4 分段控件、按钮、禁用态
- 全站只保留一种分段控件 `.seg`：外框 1px `--border-default`、`--r-sm`、高 32px；内部按钮无间隙，选中态 = `--btn-primary` 实心。2～4 个互斥选项、每项 ≤ 8 字时用；更多或更长用 `Select`。替换 `.settings-choice .q-option`、`.q-option.on`（`styles.css:325` 蓝底版本）、材料页“列表 / 表格审阅”的两个独立按钮。
- 分段控件所在行的标签与控件垂直居中（不是顶对齐）。
- 动作行：每块最多 1 个 `btn-primary`；次要动作用 `btn-ghost`；第三个及以后的动作改文字按钮或收进“⋯”。按钮间距 `--sp-2`，主次两组之间 `--sp-4`。
- 禁用主按钮不用 50% 透明，用 `--bg-muted` 底 + `--text-tertiary` 字，按钮下方一行写原因（≤ 20 字）。检验：所有 `disabled` 的 `btn-primary` 旁 40px 内有原因文字。

### 1.5 复选框与开关
- 设置里的“是 / 否”用开关 `.switch`（36×20，开 = 黑），标签写名词（“页码”），说明写在右侧或下方。
- 确认类勾选（“已交接完”“已核对”）用 16px 自绘复选框，整行可点，点击区高 ≥ 28px。
- 原生复选框只留在表格多选列。检验：设置 5 个标签页里 `input[type=checkbox]` 可见数 = 0（开关用 `role=switch` 的按钮实现）。

### 1.6 说明文字上限（在 U1 §3.3 基础上补）
- 行内确认的问句 ≤ 20 字；超过就用 `ConfirmDialog`（§1.7）。
- 律师层任一单段 ≤ 60 字，超过拆成列表或折叠。
- 折叠标题 ≤ 16 字，不写“（点开查看）”“点这里”。
- 同一规则在同一页只说一次（U2-37）。

### 1.7 确认卡结构
**开始前确认（RunSheet）固定五段**：
```
标题：开始前确认
事项      庚公司采购合同审查
要做的事  审查这份采购合同，我方为采购方，重点看付款和违约责任   ← 原话，≤ 2 行
材料      设备采购合同.docx 等 2 份
用量      约 20 点（最多 60 点）· 出错没做完的不扣点
发送      会发出  → 发给 Kimi AI：任务说明和用到的材料
                 → 公司名、案情、金额、日期、条款按原文
          已处理  ✓ 姓名、证件号、账号、电话先换成代号
                 ✓ 联网检索先去掉当事人名称，要带名称时逐条问你
          请注意  ! 没认出的姓名会按原文发出 [核对]
                 ! 服务方是否保存，以其企业协议为准；每次发送都有记录
          完整说明 ⌄（表格：内容 / 去向 / 处理方式）
[返回修改]                                   [开始审查]   ← 页脚吸底
```
检验：要点原文一字不少（与内核 bullets 比对）；对勾只出现在“已处理”组；主按钮写动词。

**不可逆操作（新组件 `ConfirmDialog`）**：标题“动作 + 对象？”（≤ 20 字，如“停用张律师的这台电脑？”）；正文 ≤ 3 条后果，每条 ≤ 30 字；需要律师声明时用一个必选勾选；按钮右对齐 [取消][动作]，动作按钮危险时红色实心，默认焦点在“取消”，Esc = 取消。检验：`ConfirmButton` 中 `question` > 20 字的调用点为 0。

### 1.8 空状态
- 卡片内：一行 ≤ 20 字 + 1 个动作，卡片高 ≤ 64px；不在卡片里居中放大段灰字。
- 页面级：一句话 + 1 个主动作，不重复页首已有的按钮（U2-36）。
- 检验：示例数据下概览、期限、交付件空状态各只有 1 个动作。

### 1.9 错误与异常
- 颜色：红 = 失败、已停止；橙 = 需要你处理；灰 = 信息。
- 句式：“{发生了什么}。{怎么办}。[按钮]”，≤ 40 字；后台会自动重试的写“会自动重试”和下一次时间。
- 内核错误原文、错误代码、英文 `kind` **不上屏**，统一放“复制详情”（复制内容：代码、时间、版本、事项匿名编号）。
- 检验：在团队共享、导出、诊断三处构造未知错误，界面文本不匹配 `/[a-z]+_[a-z]+/`。

### 1.10 开发者概念：“律师话 + 技术信息折叠”
1. 每个技术面板首层一句律师话结论（≤ 30 字）。
2. 技术细节只放进一个名字固定的折叠：“技术信息（给 IT）”。
3. **任何层级都不出现研发台账内容**：内部编号、复核编号、偏离编号、阶段代号、验收进度（门禁正则：`/\b[A-Z]{1,3}\d?-\d+\b|\bP[0-3]\b|\bG[0-2]\b|偏离|复核 [A-Z]|待实现|销售口径/`）。
4. 英文标识（API 名、进程名、环境变量）只能出现在折叠里，用等宽字体，且每个都配中文名。
5. “管理”标签页对合伙人开放，所以首层同样适用律师话规则。
- 检验：把 `lawyer-copy.test.ts` 扩到“管理”首层（折叠内容豁免）；内核加一条用例：`kernel.capabilities` 的 `customer_rows` 不匹配第 3 条正则。

### 1.11 小标签与图标语义
- 只读状态 Badge：一种形状（`--r-xs`、浅底、无描边），四种色调（成功、注意、危险、中性）；同一行 Badge 等高。资料来源、执行页、交付件现在各有一种样子（U2-32、U2-39）。
- 图标语义固定：✓ 只表示“完成 / 已处理”；! 表示“请注意”；→ 表示“发往 / 去向”。界面里不用字符图标（▸ ✓ · ✕），一律用侧栏同套 16px 线性 SVG。
- 检验：律师层 TSX 文本节点中 `▸|✓|✕` 字符 0 处。

### 1.12 弹窗
- `Modal` 三段：头、体（可滚）、脚（吸底）；最大高 `calc(100vh - 48px)`；页脚上方 1px 分隔线。检验见 U2-22。
