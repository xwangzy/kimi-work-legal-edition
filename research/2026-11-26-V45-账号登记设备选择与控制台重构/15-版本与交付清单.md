## 3. 升级（运维执行，云端先于客户端）

1. 按运维手册 §5 用 **v1.6.0 的** `upgrade.sh`：备份 → 切代码 → 补账号设备签发钥（失败不再静默）→ 按顺序重启 → 健康检查 → `verify-capabilities.sh`。
2. **部署后必做**：`sudo bash deploy/scripts/verify-capabilities.sh`，`device_auto_enroll`、`device_signout`、`account_switch` 三项都 ✓；缺 `device_auto_enroll` 按运维手册 §5.2 补钥后重启签名服务与控制面。线上 1.5.0 实测缺这一项——这是律师“等待批准”死路的服务端根因，**升级时一定要补上**。
3. 登录控制台“告警”：缺钥时有一条严重告警；补好后确认关闭。
4. 建议把试用套餐“每账号电脑数”从 1 调到 2（控制台“套餐”）：同时登录的口径下，1 台意味着律师每换一台电脑都要让上一台退出。
5. 客户端：0.10.0 覆盖安装，本机数据原样保留。

## 4. 数据迁移

- 云端：**无数据迁移**。名额口径由“登记过的电脑”改为“同时登录的电脑”只改判定，不改存量记录；新字段（会话的 `revoked_reason = signed_out*`、设备摘要的 `state`、`signed_out_at`）都有缺省。
- 客户端：**无本机数据库迁移**（下一号仍为 0076）。账号会话文件与“要重新登录”记录多一个可选的打码手机号字段，旧版读到会忽略。

## 5. 回滚

- 云端：`rollback.sh` 回到 1.5.x 代码即可。回滚后名额按“登记过的电脑”计——已退出登录的电脑重新占名额，可能有账号显示已满（按提示移除一台）；`signed_out*` 原因的会话在旧版里显示“登录已过期”。若要连状态一起回到升级前，用 `rollback.sh --restore <upgrade.sh 记下的备份>`（用量账本与审计链保留）。
- 客户端：重装 0.9.1 安装包即可（本批没有改本机数据格式）。

## 6. 已知限制

- macOS DMG 未经 Apple Developer ID 签名（ad-hoc）：首次打开须“仍要打开”，并会弹钥匙串授权（要本机登录密码点“允许”，只能由使用者本人操作）。
- Windows EXE 尚无代码签名证书：SmartScreen 会提示；对外分发须附 `SHA256SUMS` 及其签名。
- Windows 上“注册 → 任务 → 预览 → 导出”完整联调要真实手机号收线上短信验证码，且线上云端须先升级到 1.6.0 才能验证本批云端能力（见 00 §7）。
