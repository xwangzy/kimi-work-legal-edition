# 04 设备管理策略：独立论证与决定（D-298）

日期：2026-11-26

## 1. 先把“设备”拆清楚：这个产品里电脑不是一个会话，而是一份本机案卷

Kimi Work 法律版是“本地执行、云端只供推理”：事项、材料、成果都加密存在**那台电脑上**，云端只管账号、电脑登记（设备证书）、席位与额度。所以“让一台电脑不能用这个账号”有两种完全不同的后果：

| 动作 | 云端做什么 | 那台电脑上的案卷 | 能否回来 |
|---|---|---|---|
| **退出登录（下线）** | 撤销那台电脑的登录会话；网关随订阅暂停它的 AI 调用 | 原样保留，加密在那台电脑上 | 能：在那台电脑上重新登录即可（届时若满额再选一台退出） |
| **移除（吊销）** | 吊销设备证书、撤销会话；目录里标为吊销 | 仍在，但 AI、备份、导出停用（防丢失电脑上的案卷被复制） | 不能用这个账号再登录（为丢失、转手、不再使用的电脑设计） |

第 68～69 批（D-295 / D-297）在“电脑数已满”时只给了“移除”——律师只是临时在家里电脑用一次，就得**永久**吊销办公室那台，办公室电脑上的事项此后不能再用 AI、不能导出。这是现状体验差的一半原因；另一半是线上云端缺账号设备签发钥，个人账号退化成“等批准”（见 02）。

## 2. 三种策略的比较

评估维度：律师体验、账号安全、律师实际使用（办公室台式 + 笔记本 + 家里电脑，案卷在各自电脑上）、管理效率、商业化（防一号多人共用）、工程复杂度。

| | A 自动替换（新电脑挤掉旧电脑） | B 人工审批（等管理员 / 另一台电脑批准） | C 用户自主选择（满了由本人选让哪台退出或移除） |
|---|---|---|---|
| 体验 | 最省事，但被挤掉的电脑**在律师不知情时**掉线，可能正跑着任务 | 最差：被动等待；个人账号的“批准人”就是本人另一台电脑，电脑丢了或只有 1 台额度时**无人可批**（已复现的死路） | 多一步选择，但结果可预期，一次完成 |
| 安全 | 差：拿到密码的人能悄悄挤掉真主人的电脑，主人还以为是故障 | 强：多人律所由律所根签发成员设备证书，管理员掌握“谁进本所” | 好：让别的电脑退出要本人已登录（在用的电脑、网页控制台，或满额那次刚完成核对的登录凭一次性票据）——不超出持有密码者本来的能力；被退出的电脑如实告知是谁让它退出的（本人另一台电脑 / 律所管理员 / 客服），审计留痕 |
| 案卷 | 若“挤掉”=吊销，旧电脑案卷被锁 | 不涉及 | 默认“退出登录”不动案卷；“移除”是单独、明确、带确认的动作 |
| 商业化 | 无法防共用（两人轮流挤） | 能防，但成本落在每个正常律师身上 | 能防：同时在用的电脑数由云端卡住；轮流共用要反复主动挤对方，且每次都留痕 |
| 工程 | 简单 | 已有 | 中等：云端要把“上限”改成“同时登录”，并发绑定要原子 |

## 3. 决定（D-298）

**以 C 为主，B 只保留给它真正适用的场景，A 不采用。云端是唯一的判定方。**

1. **上限的口径改为“同时登录的电脑数”**：一台电脑占名额 = 未移除 + 有有效桌面会话。已退出登录的电脑不占名额，资料留在本机，回来时重新登录即可。另设“已登记电脑”的封顶（个人账号 20、团队成员 9，沿用现有常量），防止无限登记；到封顶时只能移除。
2. **满了时，由本人选择**：登录页直接列出这个账号的电脑（名字或类型、最近使用、状态：登录中 / 已退出登录 / 就是这台），默认预选最久没用的一台，主操作“让它退出登录，在这台电脑继续”；“移除”作为次要动作（丢失、不再使用），带确认。用的是**刚完成的这次登录**（10 分钟内、一次性票据），不必再输一次密码或再收一次验证码。
3. **注册 / 登录 / 换账号 / 已登记电脑重新登录**四条路径共用同一个选择卡与同一个云端判定：新电脑（个人账号自动登记、团队成员申请）在登记前判定；已登记的电脑重新登录时在会话绑定电脑时判定（原来这里不判定）。
4. **人工审批只留给多人律所的成员新电脑**（律所根签发成员证书，管理员决定谁进本所——这是安全属性，不是体验缺陷）；个人账号永不走审批。云端缺账号设备签发钥时不再让个人账号进入“等批准”的死路，而是如实报“云端暂时不能登记新电脑，请联系客服”，并在控制台告警；升级脚本补钥失败即中止并核对 `/v1/meta`。
5. **并发**：控制面单进程，判定与绑定放在同一段同步代码里；自动登记在等待签名服务期间按账号加锁，签名回来后再判定一次（原来先判定、等签名、再写入，两台新电脑同时登记会超额且撞同一设备编号）。
6. **生效**：退出登录 = 撤销那台电脑的桌面会话（原因 `signed_out`）→ 订阅版本前进 → 网关 15 秒内暂停那台电脑的 AI 调用；那台电脑下一次访问云端得到 `session_signed_out`，客户端转到重新登录页并写明原因。移除 = 吊销证书 + 撤销会话（原有）。

## 4. 对用户初步倾向的回应

用户倾向“保留云端数量限制、把选择权交还给用户”。独立论证后同意方向，但补了两处用户没有提到、却决定体验好坏的点：①“选择”的默认动作必须是**可逆的退出登录**，而不是现有的不可逆移除；②限制的对象应是“同时登录”而不是“登记过”，否则退出登录不释放名额、选择权形同虚设。
