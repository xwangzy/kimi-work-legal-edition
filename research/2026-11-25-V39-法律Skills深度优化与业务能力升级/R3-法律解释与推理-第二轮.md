**三、律师视角的价值判断**

可得利益是买卖、租赁、供应、技术服务合同纠纷里**金额最大、最难写**的一项。现状是模型在起诉状里写“可得利益损失约 50 万元”而无算式，或把剩余租期租金全额列为损失——后者正是合同编通则解释第 61 条第 2 款“人民法院不予支持”的口径（库内原文）。做成工具后：
- 起诉状 / 仲裁申请书的可得利益请求有算式、有口径、有所需证据清单；
- 替违约方答辩时，同一工具能算出“替代交易价明显偏离市场价按市场价”（第 60 条第 2 款后半句）与扣减项，形成反驳数字；
- 违约金调减（`penalty_check`）的“损失”不再靠手填，直接来自本工具，第 65 条第 1 款“以民法典第五百八十四条规定的损失为基础”的口径一致。

**四、工程落点：`calc.expectation` 设计**

新文件 `P/packages/kernel/src/tools/tools/expectation.ts`，注册在 `registry.ts` 计算工具组（与 `calc.ledger` 相邻），并加入 `CALC_RESULT_TOOLS`（registry.ts 第 1315 行）使金额勾稽能找到出处。金额按“分”整数算，沿用 `ledger.ts` 的 `cents` / `yuan`。

**输入**（模型只给事实与口径，不做算术）：

```
{
  side: "buyer" | "seller" | "lessor" | "provider",      // 守约方身份，决定差额方向
  contract: { unit_price_yuan?, quantity?, total_yuan?, place?: string },
  rescinded: boolean,                                       // 是否已依法解除（第六十条第二、三款的前提）
  methods: [                                                // 1～4 个口径并列（同 calcLedgerScenarios）
    { kind: "profit",     revenue_yuan | profit_rate+base_yuan, costs: [{label, amount_yuan, evidence}], profit_type: "production"|"operating"|"resale" },
    { kind: "substitute", price_yuan, quantity, date, evidence, market_price_yuan? },   // 第六十条第二款
    { kind: "market",     market_price_yuan, price_date, place, evidence },             // 第六十条第三款
    { kind: "periodic",   periodic_amount_yuan, period: "month", reasonable_periods, remaining_periods, cost_per_period_yuan, factors: string }  // 第六十一条
  ],
  deductions: {                                             // 第六十三条第三款；民法典第五百九十一条、第五百九十二条第二款
    avoidable_loss_yuan?, avoidable_basis?,                  // 未采取适当措施扩大的损失
    gained_benefit_yuan?, gained_basis?,                     // 因违约获得的额外利益或减少的必要支出
    own_fault_share?: number (0～1), own_fault_basis?        // 守约方过错相应部分（律师定，工具只乘）
  },
  mitigation_costs?: [{label, amount_yuan, evidence}],      // 第五百九十一条第二款：防止扩大的合理费用由违约方负担（加项）
  other_losses?: [{label, amount_yuan, foreseeable_basis}], // 第六十三条第二款：向第三人承担违约责任的额外费用等
  foreseeability?: { contract_purpose, transaction_type, negotiation, evidence }   // 第六十三条第一款
}
```

**判定与计算规则**（每条都按库内原文；违反的返回 422 或 warnings）：
1. `substitute` 与 `market` 都要求 `rescinded = true`（第 60 条第 2、3 款均以“依法行使合同解除权”为前提），否则拒算并说明；二者**同一口径内互斥**（“实施了替代交易”与“未实施替代交易”），工具拒绝同一口径同时给出——与准则第 4 条“同一情景前提不能互斥”一致。
2. `substitute` 给了 `market_price_yuan` 的，同时输出“替代交易差价”与“市场价差价”两个数，并写出偏离幅度；**是否“明显偏离”由律师判断**，工具不设阈值（库内原文无数值标准）。
3. `periodic`：仅限“以持续履行的债务为内容的定期合同”中对方不付价款、租金等金钱债务（第 61 条第 1 款）；计算期数 = `min(reasonable_periods, remaining_periods)`；律师要求按剩余期限全额算的，工具照算但在结论里写“第六十一条第二款：剩余期限少于合理期限的除外，否则不予支持”。
4. 难以按第 60、61 条确定的（没有可用的价格或利润数据），不出数，只返回第 62 条列举的考量因素（违约方因违约获得的利益、过错程度、其他违约情节）与需要的证据。
5. 扣减顺序写进 `assumptions`：毛额 − 可避免的扩大损失 − 因违约获得的利益 → × (1 − 守约方过错份额) → + 防止扩大的合理费用 + 其他可预见损失。顺序是口径，不是法律规定，律师可另选。
6. `foreseeability` 缺省时结果照出，但 `warnings` 写“可预见性未写依据（第五百八十四条但书、合同编通则解释第六十三条第一款）”，交付前检查据此提示。

**输出**：每个口径的金额、逐步算式（同 `calc.labor` 的 `steps`）、`assumptions`、`needs`（所需证据：替代交易合同与付款凭证、履行地市场价格的来源与日期、成本明细、解除通知送达证明）、`warnings`；另给 `loss_for_penalty_check`（可直接作为 `calc.ledger` 的 `penalty_check.loss_yuan`，`loss_basis` 自动写“calc.expectation 口径 X”）。

**衔接**：
- `calc.ledger` 的 `penalty_check` 增一个 `loss_from: { tool: "calc.expectation", params }`，内核内部调用、不经模型抄数（同 `xlsx` 计算表 `computed` 的做法，registry.ts 第 1080～1093 行目前只认 `calc.labor`，同步把 `calc.expectation` 加进枚举）。
- `amount-calc`、`pleading-draft`、`defense-draft`、`performance-check` 方法正文各加一句“可得利益用 `calc.expectation`，不手算”。
- `term-check.ts` 第 65 行 `PREDICTION_RE` 加“盖然性\s*[（(]?\s*[>≥＞]?\s*\d{1,3}\s*[%％]”一支（P2）。

**用例**（`P/packages/kernel/test/` 新增 `b65-expectation.test.ts`）：①买方解除后替代采购，替代价高于合同价，差价 × 数量；给市场价时两数并列；②未解除时 `substitute` 拒算；③租赁 12 个月剩余、合理期限 3 个月 → 按 3 个月扣成本；④扣减顺序与过错份额；⑤结果进入 `penalty_check` 后 130% 参照值与手填一致。优先级 **P1**（工具）/ P3（因果规则进 case-analysis）。

| C4 | 解除合同 + 继续履行（同一合同、同一债务） | **互斥**报 | 民法典第 566 条第 1 款“合同解除后，尚未履行的，终止履行” | 部分解除（解除部分订单、继续履行其余）、先位 / 备位写明的不报；“继续履行”指向另一份合同的不报 |

| C8 | 确认合同无效，但没有任何返还 / 折价 / 赔偿请求 | 提示“是否遗漏无效后果” | 民法典第 157 条 | 只请求确认无效（如消极确认之诉）是律师的选择，只提示 |
| C9 | 违约责任 + 侵权责任（同一损害） | **择一**，未写选择或备位报 | 民法典第 186 条“受损害方有权**选择**请求其承担违约责任或者侵权责任” | 两项对应不同损害（合同价款与人身损害）时律师忽略；违约之诉请求精神损害赔偿的，按第 996 条（人格权、严重精神损害）另提示依据，不按竞合报 |
| C10 | 补偿性违约金 + 赔偿损失（同一违约、同一损失） | 提示“写明两项各对应哪一违约行为与损失；违约金不足以弥补损失的，按第 585 条第 2 款请求增加，或依合同另行赔偿的约定” | 民法典第 585 条第 2 款“约定的违约金低于造成的损失的……可以根据当事人的请求予以增加” | 对应不同违约行为（迟延与质量瑕疵）不报；合同约定“违约金不足部分另行赔偿”的律师忽略 |

**三、律师视角的价值判断**

这是本组**最直接改善成果可用性**的一项：
- 起诉状同时请求“双倍返还定金 20 万元”和“支付违约金 30 万元”，立案庭或对方一眼指出第 588 条，律师当庭变更请求很被动；

**三、律师视角的价值判断**

- “简答只许已核依据”直接关系研究备忘录的可信度：合伙人只读简答，简答里一条未核依据就可能被直接用于客户沟通。价值**中高**、实现难度低（按节标题定位 + 现有引用核验状态）。
- 对方文稿模式：律师收到起诉状、答辩状后最想要的就是“对方依据哪里站不住”。价值**高**，但属于方法正文与卡片入口的改造（citation-check 的输出口径反转），不是内核检查。
- 前置验证 V2、V4 是补推理检查的漏洞，改动很小。

**四、工程落点建议**

1. **P1 `reasoningChecks` 补“零依据 / 零事实”两条**（上表第 1 条），与第 5、7 节的收紧一并做，同一组用例。

3. **P2 citation-check 对方文稿模式**：方法正文加模式参数，输出改为“可攻击点 + 我方回应要点 + 所需证据”，供答辩状、质证意见、代理词使用；可挂在现有“引用核对”卡下作为选项，不新增卡。
4. 复核“必须改”判据补全第一轮清单（`independent-review.ts` 第 505 行），P2。
