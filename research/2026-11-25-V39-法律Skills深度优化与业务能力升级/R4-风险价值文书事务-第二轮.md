1. **履行中的变更与补充约定**（出处：`特殊场景处理 / 场景一：合同已部分履行` 第 3 点“变更是否有书面确认”；`常见错误与防范 / 二、常见陷阱 / T-06 文义局限陷阱`）。吸收方式：`结构改编`。现行法（库内已核）：民法典第五百四十三条“当事人协商一致，可以变更合同”，第五百四十四条“对合同变更的内容约定不明确的，推定为未变更”；第五百一十条约定不明的先协议补充，不能达成的“按照合同相关条款或者交易习惯确定”。外部只说“关注是否书面确认”，没写法律后果：**变更约定不明推定未变更**，这直接决定按原约定还是按变更后的交期、单价判违约。产品 `performance-check` 全文没有“变更”“交易习惯”的处理（grep 第五百四十四条、交易习惯 0 处）。

### 2.2 可吸收内容（重点：反商业贿赂能否做成第二个合规模式）

外部关于反商业贿赂的内容其实很薄：`阶段二 / 步骤 4` 的对照矩阵里只有一行“反商业贿赂制度 缺失”，`步骤 6` 的问题卡依据写“《反不正当竞争法》第 7 条、第 19 条”。能借的是流程控制部分：

1. **应设未设的控制节点表**（出处：`阶段三 / 步骤 8：识别应设未设的合规控制节点`）。`结构改编`：外部七个节点（供应商准入、利益冲突申报、比价招标、合同法律审核、用印、验收、异常报告）里，与商业贿赂直接相关的是准入、利益冲突、比价招标、异常报告四个；按现行法重写为反商业贿赂的五个审查对象：①中间人、代理商、经销商的准入与背景核查；②折扣、佣金是否明示并如实入账；③礼品、招待、差旅赞助的登记与上限；④利益冲突申报；⑤举报、调查与处理记录。
2. **现行法依据（库内已核，2025-10-15 施行版）**：
   - 第八条第一款：不得贿赂交易相对方的工作人员、受托办理事务的单位或个人、“利用职权或者影响力影响交易的单位或者个人”；第二款：上述单位和个人“不得收受贿赂”（收受方也违法，这是 2025 修订新增的看点）。
   - 第八条第三款：可以明示支付折扣、佣金，但“应当如实入账”，接受方也应如实入账。——这一款是**可以逐项对照的硬义务**：销售政策、经销协议里的返利、折扣条款是否明示、是否约定入账与开票。
   - 第八条第四款：工作人员行贿“应当认定为经营者的行为”，但“经营者有证据证明”与为经营者谋取交易机会无关的除外。——**合规制度的法律价值就在这里**：制度、培训记录、员工承诺、第三方反贿赂条款是举证免责的证据。外部完全没提这一款。
   - 第二十四条：单位罚款十万至一百万元，情节严重一百万至五百万元并可吊销营业执照；第二款法定代表人、主要负责人和直接责任人员个人责任，一百万元以下。
3. **外部写错**：第 7 条（现为混淆行为）、第 19 条（现为监督检查部门的保密义务）都已错位，应为第八条、第二十四条；示例中的审批金额分级（5 万 / 20 万）是管理建议，不是法律要求（第一轮已指出）。
4. **库内缺的依据**：刑法对非国家工作人员行贿罪、单位行贿罪等，市场监管部门关于禁止商业贿赂的规章——**库内未收录、须律师核**。医药、招投标等行业规定同样未收录。

### 2.3 律师视角的价值：值得做，但排在 P2，并且本轮先做两件小事

- **需求真实**：医药与医疗器械、快消经销、工程采购企业的法务每年都要做反商业贿赂自查；并购尽调里“销售费用异常”“第三方返利”也是常见发现。
- **但它和个人信息保护审查的结构不一样**：个保法第十七条有法定告知事项清单，可以逐项判“有 / 无 / 不完整”，确定性强；反商业贿赂真正的法定义务只有第八条一条（外加罚则），审查内容大部分是管理建议——模型最容易犯的错恰恰是“把管理建议写成法律要求”。库内又缺刑法与规章，能核验的依据只有两条。直接做一张新卡，成果会显得厚、实际薄。
- **本轮最值钱的是两件小事**：①条号错位拦截（见下表），这在合规问答、合同审核、法律意见书里都会出现；②合同审核 / 审合同遇到经销、代理、采购合同时，按第八条第三款核“折扣、佣金明示与入账”与反贿赂条款——这是律师在合同上能直接改的地方。
- 第二个合规模式本身建议等两件事满足再做：法规库补录刑法相关条文与市场监管规章（P4）；企业法务线确认有客户在要。

## 6. administrative-value-judgment（行政价值判断）与“行政处罚应对”评估

### 6.2 可吸收内容

外部是给行政机关用的“裁量审查”，翻到相对人一侧，正好是陈述申辩书的论证骨架：

1. **九步审查顺序**（出处：`How to Use / Step 2 合法性 → Step 3 合理性 → Step 4 比例 → Step 5 平等 → Step 6 程序正当 → Step 7 诚信与信赖保护 → Step 9 裁量结论`）。`结构改编`为陈述申辩的五层：①事实与证据（违法事实是否清楚、证据是否足以证明）；②法律适用（适用的条款、违法行为定性、是否超出职权）；③程序（是否告知理由、是否告知陈述申辩与听证权利、是否履行法制审核等）；④裁量（处罚种类与幅度是否与情节相当、同类情形是否同罚、是否有不予处罚或从轻减轻的法定情形、是否已主动消除后果）；⑤请求（不予处罚 / 从轻 / 减轻 / 改变处罚种类）与整改证明材料清单。每一层的具体法条——**库内未收录、须律师核**。
2. **程序正当四问**（`Step 6`规则 1～4）。`结构改编`为程序核对表的四行：告知理由、听取陈述申辩、听证等补充程序、重大权益时的程序保障。可以做成表格，但条号与期间必须等行政处罚法入库。
3. **裁量结论五要素**（`Step 9`：推荐方向、核心理由、最小损害或缓冲措施、不宜采取的方案、需进一步核实事项）。`结构改编`为内部应对备忘录的结论段——“最小损害或缓冲措施”翻成相对人语言就是“主动整改、消除影响、补缴、提供担保”等能换来从轻的动作，这一条律师很需要。
4. **外部的问题**：全文不引任何具体条文，“价值衡量”成分过重；是机关视角，“推荐处理方向”对相对人没有意义。

### 6.3 “行政处罚应对（陈述申辩、听证）”卡：值得做，但不是本轮

**价值判断：企业法务线中高，诉讼线低。**

- 企业法务每年都会接到市场监管（广告、价格、产品质量）、生态环境、消防、税务、网信（数据与个人信息）的处罚事先告知书。陈述申辩和听证申请的期限短（以告知书载明为准，通常是数日），错过即丧失；陈述申辩书写得好不好，直接影响能否从轻、减轻。这是产品现有 52 张卡里**没有任何一张能接住**的场景：“收到起诉或仲裁：第一步”只管民事与仲裁，“合规问答”只答问题不出文书，“个人信息保护合规审查”是事前体检。
- 律所诉讼线的行政诉讼是另一套业务，产品暂不覆盖，不以此为卡的目标。

**要补的法（按必要性排序，施行日与条文待入库时核）**：

| 必要性 | 法规 | 用途 |
|---|---|---|
| 必须 | 行政处罚法（现行修订版） | 陈述申辩与听证权利、听证适用情形与申请期限、不予处罚与从轻减轻情形、追责时效、裁量基准、处罚决定期限 |
| 必须 | 行政复议法（现行修订版） | 复议申请期限、复议前置情形、复议机关 |
| 必须 | 行政诉讼法 + 最高法适用解释 | 起诉期限（直接起诉 / 复议后起诉）、被告确定、举证责任 |

### 12.3 新卡判断：**值得单独成卡**——“诉讼成本与回收测算”

**为什么值得单独成卡（而不是只做“金额测算”的一个选项）**

- 律师和客户问的是另一个问题。“金额测算”回答“我能主张多少”（本金、利息、违约金按日分段）；客户在立案前、收到一审判决决定上诉前、调解庭上真正问的是“**打下来要先掏多少、最后最多能拿回多少、和解到多少就不亏**”。这个问题现在没有任何一张卡接：`case-analysis` 明确不替客户定和解底线（第 75 行），`case-report` 的费用由律师提供（第 38 行），`amount-calc` 只给诉讼费一个数。
- 能做得可信，因为难点全是确定性计算：受理费、保全费、执行费、减半、上诉费由 `calc.court_fee` 算；判决支持金额由 `calc.ledger` 按情景算（已支持四个情景、违约金调减参照）；迟延履行加倍部分利息 `calc.ledger` 的 `doubled` 已有；负担规则在诉讼费用交纳办法库内原文。不需要任何概率。
- 路由上需要独立入口：“值不值得打”“和解底线”“打官司要花多少”这些说法与“测算违约金”完全不同，塞进“金额测算”的下拉框律师找不到。

**卡片定位**：诉讼线（企业法务线可复用同一卡，入口文案改为“这个案子值不值得打”）。在“金额测算”之后、“起草起诉状”之前，以及“裁判文书研读与上诉评估”之后（上诉划不划算）。

**输入**

- 必需：诉请金额或《计算明细》（“金额测算”的成果；没有的，律师直接写本金与请求）。
- 面板字段：我方地位（原告 / 申请人、被告 / 被申请人）；所处阶段（尚未起诉、一审中、一审已判拟上诉、仲裁）；判决情景（多选：全部支持、部分支持——写明支持哪几项或违约金调到多少、驳回）；执行情景依据（已保全财产金额、已查明可供执行财产金额、暂无已知财产，填金额不填比例）；律师给定的费用（律师费、鉴定评估、公证、保全担保或保函费、差旅，没填的写“待律师提供”）；是否适用简易程序；计算截止日。
- 材料：合同中“实现债权的费用”条款、保全裁定、财产线索查询结果（如有）。

**主交付物**：《诉讼成本与回收测算》.xlsx（主交付物，必须出）+《测算说明（内部稿）》.docx（一页：前提、口径、待律师提供的参数、不确定之处）。工作表：

1. **情景与前提**：情景名 / 前提（一句话写清这个情景成立的条件）/ 支持金额（引《计算明细》对应列）/ 诉讼费负担口径。
2. **费用**：项目 / 金额 / 来源（工具算出 / 律师给定 / 合同约定）/ 谁预交 / 各情景下最终谁负担 / 依据（诉讼费用交纳办法第十五、十七、二十、二十九、三十八条，财产保全规定第五条）。部分支持时按“支持金额占诉请比例”分担受理费，标注“测算口径，非法律规定；第二十九条第二款由法院决定”。
3. **回收与净额**：判决情景 × 执行情景矩阵，每格：判决确定可收（含应由对方负担的费用）/ 可供执行财产 / 实际回收（取小）/ 自担成本（从现在起的增量）/ 净额。已发生成本另列一行备查，不进净额。
4. **和解持平点**：每个判决 × 执行组合下，和解金额达到多少与该组合净额相同（计入调解或撤诉受理费减半，第十五条；免去的后续律师费、鉴定费、上诉费）。被告视角改为“最大敞口”与“和解上限持平点”（敞口 = 支持金额 + 应负担的受理费 + 对方列入请求的保全费 + 有依据的律师费 + 按律师给定履行日测算的迟延履行加倍部分利息，民诉法第二百六十四条、法释〔2014〕8 号第一条）。
5. **参数与假设**：每个数的来源；“待律师提供”清单。
