## 2. 升级（约 10 分钟，服务重启约 1 分钟）

```bash
cd /opt/kwl/app && sudo git fetch --tags origin
# 离线：sudo git fetch /path/to/kimi-work-legal-demo-cloud-v1.2.1.bundle 'refs/tags/*:refs/tags/*'

```

脚本自带：备份 → 切代码 → 共享契约包核对 → `npm ci` → 重建控制台 → 依次重启 cp-signer / control-plane / gateway / search → 健康检查（最后四个 ✓）。任何一步失败即停并打印回滚命令。

## 3. 升级后核对（5 分钟）

1. `curl -s https://legal.matetrip.cn:8443/v1/meta`：`features` 含 `phone_login`、`phone_bind`；短信已启用时 `registration_policy.phone_login` 为 `true`。

## 4. 回滚

| 情形 | 做法 |
|---|---|
| 只停用验证码登录（不回滚代码） | 控制台“短信服务”关闭“手机号验证码登录”；注册、找回、绑定不受影响 |

## 附：线上证书事故的修复步骤（11-25，已由运维执行并恢复）

### 紧急：legal.matetrip.cn 控制面（8443）与网关（8444）证书被“纯 IP 部署”的续期任务覆盖——修复步骤

发现时间：2026-11-25 07:50（北京时间）。影响：**所有已安装客户端（0.2.0 / 0.3.0 / 0.4.0）自 11-25 约 02:57 起连不上控制面与网关**（证书校验失败 `cp_tls_verify_failed`），AI 功能全部不可用；检索 8445 与网页控制台 443 暂未受影响（只是还没重载证书文件，一重启也会坏）。

## 现象（外部核对）

| 端口 | 现在的证书 | 应该是 |
|---|---|---|
| 8443 控制面、8444 网关 | Let's Encrypt 短期证书（签发者 YE2，生效 11-24 17:56 UTC、到期 12-01），**SAN 只有 IP 116.63.192.237**，公钥 sha256 `KmTQtN++q+8+BBfKtHyFe5HRi5LlRUrKxfDuxDGBI0Y=` | DigiCert 域名证书（legal.matetrip.cn，到期 2027-02-22），公钥 sha256 `VqxKS+dPG4yeq+KstjS4BCIefi1TKIk0bzlb2/y3omY=` |
| 8445 检索、443 控制台 | 仍是 DigiCert（进程还没重读文件） | 同上 |

客户端按域名连接并钉住 DigiCert 那把公钥（备用钉住 `6h66361w…`），所以新证书既对不上域名，也对不上钉住值。

## 原因

这台服务器早先做过“纯公网 IP 部署”（第 50～54 批），留着 `/etc/kwl/tls-ip.env` 与续期定时器 `kwl-cert-renew.timer`（每天 03:17、15:17 UTC 前后运行 `tls-ip.sh renew`）。改成域名 + DigiCert 后定时器没有停。IP 短期证书到了“过半”续期点，续期钩子把**IP 证书与 IP 私钥**装进 `/etc/kwl/tls/{cp,gw,search,console}.{crt,key}`（覆盖了 DigiCert 那份，不留备份）并重载了控制面与网关。
本次 v1.2.1 升级没有改部署脚本（`upgrade.sh`、`tls-ip.sh`、systemd 单元自第 53 批起未变），`upgrade.sh` 只在存在 `tls-ip.env` 时刷新单元文件、不会启用或启动定时器；时间上不能完全排除与升级同日的巧合，但触发源是这个遗留定时器。

## 修复（约 5 分钟，需要服务器 root）

```bash
### 1) 停掉并移除“纯 IP 部署”的证书续期（这台已经是域名部署）
sudo systemctl disable --now kwl-cert-renew.timer
sudo mv /etc/kwl/tls-ip.env /etc/kwl/tls-ip.env.disabled-20261125     # 以后 upgrade.sh 不再装这两个单元

### 2) 从 v1.2.1 升级前的备份取回 DigiCert 证书与私钥（备份里是升级前的 /etc/kwl，含 tls/）
ls -lt /var/backups/kwl/ | head -5                                      # 取 11-24 23:29（北京）前后那份
B=/var/backups/kwl/kwl-<升级时间>.tar.gz
mkdir -p /tmp/kwl-tls-restore && sudo tar -xzf "$B" -C /tmp/kwl-tls-restore etc/kwl/tls
for n in cp gw search console; do openssl x509 -in /tmp/kwl-tls-restore/etc/kwl/tls/$n.crt -noout -issuer -enddate; done   # 应为 DigiCert、2027-02-22

### 3) 装回（权限与原来相同）
for n in cp gw search; do
  sudo install -m 0644 /tmp/kwl-tls-restore/etc/kwl/tls/$n.crt /etc/kwl/tls/$n.crt
  sudo install -o root -g kwl -m 0440 /tmp/kwl-tls-restore/etc/kwl/tls/$n.key /etc/kwl/tls/$n.key
done
sudo install -m 0644 /tmp/kwl-tls-restore/etc/kwl/tls/console.crt /etc/kwl/tls/console.crt
sudo install -o root -g root -m 0400 /tmp/kwl-tls-restore/etc/kwl/tls/console.key /etc/kwl/tls/console.key
sudo rm -rf /tmp/kwl-tls-restore

### 4) 重载并核对
sudo systemctl restart kwl@control-plane kwl@gateway kwl@search
sudo nginx -t && sudo systemctl reload nginx
for p in 8443 8444 8445 443; do echo -n "$p "; echo | openssl s_client -connect legal.matetrip.cn:$p -servername legal.matetrip.cn 2>/dev/null | openssl x509 -pubkey -noout | openssl pkey -pubin -outform DER | openssl dgst -sha256 -binary | base64; done
### 四行都应是 VqxKS+dPG4yeq+KstjS4BCIefi1TKIk0bzlb2/y3omY=
```

若备份里找不到：DigiCert 证书与私钥的原件在当初申请证书的地方（与 443 控制台 nginx 配置 `ssl_certificate` 指向的那份是同一张证书时，可以直接用那份）。

修好后客户端不用重装：下一次请求即恢复（已登录的不用重新登录）。
