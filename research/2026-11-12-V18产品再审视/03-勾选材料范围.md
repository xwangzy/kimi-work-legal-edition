# 勾选材料范围：实施与验证记录（第 43 批续二，2026-11-13）

用户在“复核意见落实”之后选定做这一项。分支 `v18-b43`，接着前面的改动做，未提交。

所有分数都是 AI 预验收，不是执业律师的验收。

## 一、先核代码：是有意的设计，不是遗漏

首轮判断里这一条（B7）只有评分记录，没有核过代码。核的结果：

- 材料目录工具把本事项**全部**材料连同编号一起列给助手，只用 `in_this_task` 标出哪些是勾选的；说明里明写“其他材料可用 materials.read_excerpt 按 parse_version_id 读取”（`tools/tools/review.ts`）。
- 读取工具只校验“材料属于本事项”，不看是否勾选（`tools/tools/materials.ts`）。
- 这是 2026-10-14 阶段 7 的设计（提交 `54e8693`），早于开始面板的勾选界面。勾选界面做出来之后，两边没有对齐。

后果有三层：

1. 律师勾选了一份，助手可以读事项里的任何一份。真实回归里交割清单只勾了签署版，成果引用了章程第十八条、第二十三条和股东名册。
2. 独立复核只拿到勾选的材料，起草方却可能读了别的，两边看的不是同一批材料。
3. 发给 AI 的内容超出了律师在开始面板上选的范围。

## 二、做了什么

**规则：律师勾选了材料的，勾选的就是本任务的边界；一份都没勾的，不设边界。**

| 位置 | 改动 |
|---|---|
| 材料目录（`materials.list`） | 勾选了材料的任务：没勾的只列文件名，标 `not_provided`，不给材料编号、解析编号、字数与识别质量。说明改为：不能读取、不据文件名推测内容；与任务明显相关的在最终答复里点名提醒律师 |
| 读取（`materials.read_excerpt`） | 没勾的拒绝，并告诉助手该怎么办（在答复里说明，请律师勾选这份材料后重新发起）。拒绝时不带出材料内容 |
| 修订、比对、清理元数据、脱敏 | 同样只认勾选的材料（`docx.revise`、`docx.compare`、`docx.apply_revisions`、`docx.sanitize`、`redact.apply` 入口加同一道把关） |
| 别的事项的材料编号 | 照旧按“不存在”处理，不因为范围检查泄露它是否存在 |
| 一份都没勾的任务 | 不变：本事项材料都可读（只写一句话就发起的自由描述任务）；说明里写明“交付件里写明实际读了哪几份” |
| 工作准则 | 第 3 条加一句“材料范围以律师勾选的为准” |
| 开始面板 | 勾选框下面多一句话：“助手只读勾选的 N 份；没勾的 M 份这次不会读取，也不会发给 AI。”一份都没勾时写“助手可以读本事项的全部材料” |

登记为偏离 D-183。工具的入参没有变，工具锁没有新的改动。

**实现中踩到的一处：** 材料目录说明的第一版写“本事项里律师这次没有勾选的材料”，经本机的代号替换后变成了“本事〔自然人·7T6C4B〕律师……”——“项里”被姓名识别当成了人名。这句话是发给模型看的，等于指示被改坏。已换了说法，并在用例里加了“说明文字里不能出现代号”的断言。这是首轮判断里“姓名识别在打地鼠”（C3）的又一个实例：它不只影响成果，也会改坏系统自己写给模型的话。

## 三、验证

### 3.1 用例

全量 2,294 例，通过 2,289，失败 0，跳过 5；类型检查通过。

新增 `kernel/test/b43-material-scope`（3 例）：勾一份时另两份只有文件名、读取与修订比对被拒绝、勾了的照常读；一份都没勾时全部可读；别的事项的编号照旧 404。桌面端加一例开始面板的说明文字。

范围限制让 4 个已有用例失败，逐个看过，都是测试自己在没勾选的材料上修订或比对，按新口径改了测试的发起方式，产品行为没有为它们让步：

| 用例 | 原来怎么做 | 改成 |
|---|---|---|
| 修订稿作新材料后再修订（`b39-artifact-to-material`） | 同一个任务身份里直接修订新材料 | 产品里“作为底稿继续修改”是另起任务并勾上新材料，测试照此把勾选换成新材料 |
| 在没进快照的原件上修订，姓名仍是代号（`b41-source-known-only` 两例） | 勾了甲、修订乙 | 改为一份都不勾（这种情形现在只在没勾选材料的任务里发生），原有的隐私断言不变 |
| 回稿重审的方法契约（`skills-contract`） | 只勾一份、比对两份 | 勾两份（开始面板本来就要求勾上一稿与回稿） |

## 五、追问框补勾材料（第 43 批续三，2026-11-13，用户回复“加上”）

### 5.1 为什么要补

勾选即边界之后，律师漏勾一份材料只能勾上重新发起，等于整单重跑十分钟左右。追问本来就在原会话上继续，补一份材料接着做更省事。

### 5.2 先核代码

- 追问每一轮都按本轮自己的材料清单重写材料快照（宿主每次运行清空材料区再写），读取范围也按本轮任务的清单判定。所以只要把补勾的材料并进追问的估价与发起，快照和范围都自然跟上，不需要另造一条通路。
- 原来界面把上一轮的材料原样带进追问，没有选择的地方；内核对追问的材料清单也没有任何约束。

### 5.3 做了什么

| 位置 | 改动 |
|---|---|
| 追问框（`RunView.tsx`） | 输入框下面多一个“补充材料”，点开是本事项里上一轮没勾的材料，勾上即随这次追问一起给助手。下面一句话写明沿用几份、补充几份、还有几份仍不会读取。改了勾选要重新估价 |
| 追问前确认 | 确认行写“再次使用 N 份材料，补充 M 份”；发送前核对（换成代号的处数、字数）按“上一轮的 + 补勾的”一起算 |
| 什么时候不出现 | 上一轮一份都没勾的任务（本来就可读全部）；本事项没有别的材料 |
| 内核（`runs.start`） | 补了哪几份由内核比对上一轮的清单得出并记进任务输入，不信界面传来的说法。上一轮勾了材料的，追问一份都不带（等于把边界放开到本事项全部材料）被拒绝 |
| 给助手的提示 | 追问提示后面加一句，点名这一轮新增的是哪几份、上一轮没有提供、回答前先读；读后发现上一轮结论要改的直接改并写明依据 |
| 追问任务的材料清单 | 补的那几份标“本轮补充” |
| 助手被拒绝读取时的提示、材料目录说明 | 由“请律师勾选后重新发起任务”改为“请律师在追问时补勾，或勾选后重新发起任务” |
| 展开后看不到的问题 | 追问框在页面最底部，展开的列表和确认行都落在可视区之外；现在展开或出现确认行时自动滚到底（实测时发现） |

没有新的偏离登记：仍是 D-183（勾选即边界），边界只因律师自己的勾选而变。工具入参、工具锁、数据库结构都没有动。工作准则原文是“由律师决定是否补上”，不用改。

### 5.4 验证

**用例。** 新增内核端到端一例（`kap-a1.test.ts`“追问补勾材料”）：上一轮勾一份、追问补一份，新一轮快照两份都有且原来那份序号不变，模型看到点名新增的一句，没补的那份不出现在提示里，固定文字没有被认成姓名；上一轮勾了材料的追问不带材料被拒绝；不补材料的追问没有“本轮补充”。桌面端一例（说明文字三种情形、估价与发送核对都用合并后的清单）。新增的那句提示加进了“提示词里不能有被认成姓名的字”的检查。全量 2,296 例，通过 2,291，失败 0，跳过 5；类型检查通过。

**真实复验（1 单）。** 接着上面 3.2 的 m36 交割清单（事项 3 份、上一轮只勾签署版，成果里章程相关事项都写成缺口）。在真实界面的追问框里点开“补充材料”、勾上《目标公司章程（摘录）》、写一句追问后发出。高速档，约 5 分钟，成功完成。

| 核对项 | 结果 |
|---|---|
| 发送前核对 | “2 份材料约 5,883 字：27 处换成代号” |
| 本轮任务输入 | 材料清单 2 份；补充的 1 份是章程（内核比对得出） |
| 助手读了什么 | 读了材料区第 2 份（章程）；材料目录 1 次；没有读取股东名册的调用，也没有被拒绝的记录 |
| 成果 | 《交割清单》第 4 版。上一轮第 3 版里“章程第 X 条”出现 0 处，这一版引用了第八、十六至十八、十九、二十、二十三条；有改动的文字单元格 48 个 |

| 界限说明 | 答复写明“章程目前仅为摘录，末尾注明‘以下条款略’，因此未写成‘章程没有其他约定’” |
