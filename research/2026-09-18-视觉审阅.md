# Kimi Work 法律行业版：视觉与信息架构独立审阅

审阅日期：2026-09-18。依据：当前 app.css / app.js、legal-workspace.css / js、legal-skills.css / js，以及只读比较 backups/baseline-20260917-220222.zip 中旧版 app.css / app.js。未使用 computer use，未改应用文件；以下为代码结构与样式审阅，视觉结果须由主任务浏览器验收。

## 判断

保留当前 Kimi 左侧导航、黑白蓝灰工作区、项目上下文、技能与工具分层。这些是完整产品的骨架。需要改的是同屏竞争、信息排序及可读性，不宜另起一套大型营销页或全屏蓝色 AI 门户。

当前杂乱并非信息总量过多，而是太多并列的信息块、低对比小字和对齐边界混杂。主页以 840px welcome-block 居中，下一层场景和最近工作却按更宽的 home-v2 容器展开；同时出现「开始工作」「继续工作」「待我关注」三组内容，却没有明确主次。技能页由标题、宣传横幅、标签页、分类、搜索再到卡片，用户要越过五层才能选择技能。连接页类似。应把空间还给操作内容。

## 旧版值得保留

1. 旧首页同一宽度串联标题、输入、场景、任务列表，阅读轴稳定。旧版问候「今天有什么工作要推进？」比纯品牌口号更指向任务；新版品牌标题可保留，但副标题应承接具体动作。
2. 旧技能卡用「输入材料 → 输出成果」，例如「多份合同 → 可核验的条款矩阵与缺口清单」，信息效率高。新版卡片只有泛化说明和工具标签，律师不容易快速判断交付物。
3. 旧版卡脚保留「采购方审查标准 v2.4」等业务标准名称；新版只有 v2.4，丢失本所专业方法的识别。建议展示「采购方标准 · v2.4」，并在详情看全文。
4. 旧项目详情「材料 / 关联任务 / 交付成果」逻辑清楚，适合延续为真实内容标签页。新建项目也应遵循同一骨架，不能另成只支持文件名的分支体验。
5. 原有专业工作区（合同原文/风险建议、矩阵、证据时间线）比通用聊天界面更适合法律任务。不要为模仿竞品将这些退化成纯对话结果。

## 首页建议：一个任务入口、两层发现、一个续办区域

建议结构：小问候与主标题 → 业务大类（诉讼仲裁 / 非诉业务 / 企业法务）→ 常用场景 chips → 输入框（项目上下文、模板已选状态、材料、能力配置）→ 简短配置摘要 → 场景推荐与全部技能入口 → 继续工作。

- 场景 chip 点击先预填任务或打开预设提示词，清楚显示「你可以修改」，而不是突然直接进入运行配置。
- 在输入框底部将当前多个按钮整为「添加材料」「能力配置」「完善指令」三个动作；能力配置打开技能 + MCP 的关联视图。显示 1 个已选技能/2 个工具即可，不在首屏列长工具列表。
- 首页快捷场景只保留 4–6 个，按当前业务切换；高级场景在技能中心。三四十个能力不宜平铺到首页。
- 把 attention-panel 改为紧凑的「2 项需要复核」行或最近任务的状态列，避免与继续工作重复。确需右栏，宽度约 240px、无大边框，最多 2 条且不重复任务列表内容。
- 继续工作列：任务名 / 项目 / 状态 / 最近更新 / 继续。旧版更新时间值得恢复。
- 全部块左边界一致；推荐 home 最大宽度 1080px（含左右 32px padding），welcome-block 取消独立窄宽约束或输入区与其余区统一 960–1016px 可用宽度。

关键选择器：.home-v2、.welcome-block、.welcome-block h1、.scenarios-section、.v2-composer、.composer-context、.composer-bottom、.home-lower、.attention-panel、.recent-row、.compact-workflows。

## 技能中心建议：任务与成果优先，配置逐层展开

- 保留「技能库 / 本所技能 / 专家角色」页签，但缩小 .skill-hub-intro 为一行介绍 + 已启用数量，或者将数量并入标题右侧；不占一个大横幅。
- 若增加提示词库，页签可采用「场景模板 / 法律 Skills / 专家角色 / 本所资产」，避免模板、能力、角色被当成同一种卡片。
- 卡片固定顺序：分类（弱）→ 名称（强）→ 一行用途 → 成果形式 → 底部「使用」主操作 +「配置」次操作。工具名折叠为「2 个工具」，悬停或详情可展开；启用状态为次要角标。
- 预设提示词点击弹出宽面板：左侧填写变量（角色、争议、材料、目标），右侧完整可编辑提示词预览；底部固定「带入任务」。让用户看得到预设究竟做什么。
- Skills 详情保留概览/执行规则/输入输出/依赖工具，但增加「示例任务」「复制提示词」；技能指令以分段列表表达角色、输入、步骤、质量规则、输出，不使用一段长 prose。
- 搜索与分类同一行，卡片三列；小屏两列；每卡标题 16px、正文 13px、元数据至少 11–12px。

关键选择器：.skills-v2 .skill-hub-intro、.skill-nav、.skill-filter-row、.skill-tiles、.skill-tile、.skill-tile-top、.skill-tools、.skill-tile footer、.skill-config-rule、.skill-config-section。

## MCP 连接建议：先分清可用资源与配置状态

- 连接页标题直接「工具与数据连接」即可，英文 eyebrow 和长营销标题可缩减。
- 顶部一行「2 个已启用 / 4 个待配置 / 演示模式」取代大概览横幅。
- 两种信息分类不要混淆：业务类型用于筛选（法规/企业/项目/通用）；连接状态用于角标（已启用/待测试/待配置/失败）。卡片可分已启用与可添加区。
- 每张卡主要展示用途和「哪些技能使用它」，这比笼统「3 项工具」更帮助法律用户决策。
- 点击配置的顺序：服务与名称 → 访问范围 → 允许工具 → 测试结果 → 保存启用。高级传输、原始 JSON 放折叠区。
- 已有本地模拟文案应保留但统一出现位置；不必在每卡、每段反复解释，也不可把本地模拟标成真实已接入。
- 最近活动折叠为 3 条，配查看全部；不必争夺第一屏。

关键选择器：.connections-v2、.connection-overview、.connection-toolbar、.connector-grid、.connector-card、.connector-meta、.connection-activity、.connector-config、.tool-checks、.advanced-config。

## 项目与文件建议

- 保留三列项目卡，但卡内容增强清晰层次：项目名 → 客户/业务类型 → 下一待办（唯一强调色）→ 材料与任务数量 → 最近更新。
- 项目详情增加简洁上下文条：我方立场 / 当前阶段 / 已选审查标准。不要把这些隐去到模态框。
- 材料、关联任务、交付成果应是同一项目内真实 tab，切换内容仍保留项目头；目前原有按钮会跳到工作流或全局交付，容易丢失当前位置。
- 添加材料应放材料区域标题右侧，上传条目和预置文件使用同一表格样式。新旧项目保持相同主按钮体系。
- 首次创建项目空态提供「添加材料」「从模板开始任务」两个明确动作。继续显示当前演示只保存文件名的事实。

关键选择器：.project-list、.project-card、.project-topline、.tabs-line、.project-add-toolbar、.file-row、.project-draft-deliverables。

## 跨页面 CSS 应优先修复

1. .legal-shell .nav-item.active:before 采用 position:absolute，但 .nav-item 未定义 position:relative。应给 .legal-shell .nav-item 加 position:relative，标记 left:0 或 4px，避免脱离导航项定位。
2. 白底正文 #9299a5 对比约 2.87:1，#9ba4b1 约 2.52:1，#7d8592 约 3.72:1（按 sRGB 相对亮度计算）。当前这些颜色广泛用于实际任务描述。正文建议 #5f6876 或 #606670（约 5.78:1）；更浅文字只用于非必要装饰。
3. 建立统一文字层级：页面标题 28–32px；区域标题 17–18px；卡标题 15–16px；正文 13–14px；元数据 11–12px。当前 home 中 9/10/11/12/13/14px 层级过碎，字号不足以表达重点。
4. 按钮主次：每区域最多一个黑色主按钮；高频操作 34–38px 高，边缘留白一致。不要使「查看与配置」成为卡片唯一操作。
5. 统一 8px 间距阶梯：页面 section 32px、卡内 20/24px、行 gap 8/12px、卡 gap 16px。弱化几乎看不见的渐变、边框与微阴影叠加。
6. 目前 app.css + workspace override + skill override 再加后续补丁易产生特异性争夺。新视觉层建议集中新增版本 stylesheet，并覆盖具体页面 namespace；不要继续在单行 CSS 尾部散加不可追踪片段。
7. 保留专门的专业工作区宽度，不把合同、矩阵页面统一收窄到首页宽度。首页 ~1080px，普通库页 ~1240px，专业文书/矩阵区接近可用全宽。

## 验收关注点

浏览器至少看 1440×900、1280×800、390×844；确认首页首屏能完成场景选择和开始任务；卡片无截断；抽屉底部操作可见；长中文技能名和项目名不撑开布局；放大到 125% 仍可读。检查选中导航标记、弹窗焦点、搜索输入后光标、刷新后的已选技能与项目状态。
