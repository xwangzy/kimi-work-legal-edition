# 现状审计摘要与双控制台分析（基线 `9e79302`）

两路只读审计的原文在会话 scratchpad（`audit-cloud.md` 270 行、`audit-client.md` 206 行，逐条带 文件:行号）。这里只留结论与证据位置。路径相对 `platform/`。

## 1. 两个“控制台”到底是什么

| | 运营控制台（网页 `apps/ops-console`，本批改名 `apps/console`） | 律所管理（Windows 客户端 设置 → 管理） |
|---|---|---|
| 给谁 | 中软运营 | 律所管理员、合伙人 |
| 页面 | 总览、客户、账号、设备、模型与路由、用量、套餐与额度、计费、系统（9 页，`app.js:25-35`） | 成员、律所策略、用量、操作记录、技术支持、代号准确度（`Connections.tsx:686-712`） |
| 身份 | 运营名册（安全管理员离线签发，`ops-auth/index.ts:48-233`）+ 浏览器内私钥签名（`ops-sign.js`）或第 45 批密码（`ops-auth/password.ts`，凭据 JSON 文件） | 律所根签发的管理员设备证书（`requireAdmin` = 证书 role，`server.ts:1142`） |
| 接口 | `/v1/ops/*`（`server.ts:1721-2405`） | 设备签名接口：`/v1/quota/cap`、`/v1/invitations*`、`/v1/join-requests/*`、`/v1/drafts*`、`/v1/audit`（`server.ts:2906-3204`） |
| 数据 | 控制面状态 + 用量账本 | 同一份（经设备签名读写） |

另有一层命名混乱：部署文档标题叫“云端控制台（额度台）”，页面标题叫“运营控制台”；开发脚本两套（`dev-ops-console.mjs` 5480、`demo-launch.mjs` 8790）。

## 2. 两套并存的问题（证据）

1. **两套人员身份、两套密码机制**：`ops-auth/password.ts` 与 `control-plane/src/accounts.ts` 各有 scrypt、密码规则、会话令牌、锁定；数值不一致（运营 5 次锁/30 分钟/8 小时、内存会话；律师 10 次锁/12 小时/7 天、持久会话）。凭据文件有两个写者（`ops-cli password` 与控制面改密）且无锁（cloud §9-7）。
2. **运营权限无角色**：14 个平铺权限逐人列在名册里；所有读接口只要 `tenant.read`——账号邮箱、逐请求明细、账单、路由、访问记录一把钥匙（cloud §2、§9-8）。
3. **运营密码登录单因素、无复核**：`second_factor` 只是占位；Bearer 会话可直接执行 `route.manage`、`tenant.purge`（cloud §9-4）。
4. **律所管理员没有网页入口，且缺能力**：停用成员账号、下线、单账号设备数与个人上限只在 `/v1/ops/accounts/*`（`server.ts:1877-1925`），律所自己做不了；月度上限两个入口写同一字段（`/v1/quota/cap` 与 `/v1/ops/tenants/{tid}/cap`）。
5. **客户端扩展成本高**：客户端每多调一个控制面接口，就要改通道白名单（`egress-gate/src/cp-relay.ts:20-57`）与出站登记表并发新版（client §9-11）。
6. **私钥登录牵连面广**：浏览器 `ops-sign.js`/`keystore.js`、控制面验签、`ops-cli keygen/call`、`usage-backfill`、support/relay/notify 三个服务的运营接口（只认私钥，`ops-auth/index.ts:526`）。

## 3. 结论

合并为**一套云端控制台**（D-192，见 `00-架构决策与接口契约.md` §1）：一个登录页、一套账号、三个分区（我的 / 本所 / 平台运营），平台运营按角色出现子页；不保留独立运营入口。保留在客户端的只有“必须用律所根私钥、管理员设备签名或本机密钥纪元”的操作：批准入组、策略/连接器签名发布、停用电脑、生成邀请码、恢复包与备份、离所交接。

## 4. 成熟、继承不动的

律所根签发设备证书与设备签名防重放（`firm-trust`、`keys`）；席位令牌与网关离线验签、签名订阅 15 秒吊销（`seat-token`、`GatewayFeedSubscriber`）；签名服务独立 mTLS（`cp-signer`）；生产入口一进程一角色、强制 TLS（`cloud-serve.mjs`）；第 44 批的账号会话、路由登记与签名下发、上游密钥浏览器内 ECDH 加密 + 网关本机白名单、逐请求只追加账本按请求编号去重、额度 v2 与计费；第 45 批的首页、示例事项开关（`ZR_DEMO_SAMPLES` 进不了安装包，`release-config.cjs:26-33`）。

## 5. 缺陷清单与本批处置
