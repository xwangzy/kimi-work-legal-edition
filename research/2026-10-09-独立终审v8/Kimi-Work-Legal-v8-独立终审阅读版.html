Kimi Work 法律行业发行版：独立终审与可实施产品方案 v8

评审日期：2026-10-09（北京时间）。性质：产品与研发决策建议，尚非已批准基线或生产验收证明。

1. 最终建议

建设“中软运营的云地协同法律 SaaS”：共用一套法律业务模型、Kimi Code 运行时适配和质量标准，按事项授权选择境内云端执行或本地执行。桌面挂载不等于上传，模型推理不等于 Agent 执行，自动执行不等于自动签发。

不要继续在“云端只有 token”和“所有案卷必须上云”之间摆动。API token 是采购项目，不能推出整个产品的部署位置；SaaS 是交付与运营模式，也不要求所有代码都在云端。真正决定位置的是：数据许可、客户要求、本机资源、常在线需求、隔离能力、协作与总成本。

建议以标准协作事项 C + 本地保密事项 L作为两个面向律师的产品预设。C 支持已授权材料的境内托管、云任务、多人协作、手机审阅与关机续跑；L 默认原件与派生正文留在获准设备，可选密文同步，模型请求仍须逐端点授权。完全禁止数据出域的客户采用另行验收的私有部署 P，不能把 L 加一个私有模型地址就叫完整私有化。

这是一项相对 v5/v6 的明确产品取舍：允许在合同、政策与技术控制到位后托管客户材料，不把“中软绝不持有内容”作为全产品不可更改的前提。 如果管理层选择绝不托管，L 可以独立售卖，但无获准常在线执行器时，关机后的内容任务必须排队，不能同时承诺云端续跑、全功能移动处理和云端完全无法解密。

2. 本轮确认的前提与边界

  • 用户已明确取得 Kimi Work 法律行业发行版标识授权，允许借用设计、布局、配色、版式及部分能力。本方案接受该事实，不要求重复取得同一授权。
  • 当前已知采购为 Kimi API token。搜索、文件服务、Hosted Agents、Work 会员数据源、浏览器组件和企业数据条款各自确认，不从 token 或标识授权推定。
  • 用户补充确认：以内地律师为主、类似 Kimi Work 的桌面客户端、账号订阅制。桌面是主入口，Web是辅助管理与协作；个人可以购买，不强制三席起。中文民商事和合同业务为首发范围建议。香港上市身份不等于必须处理香港法，也不等于所有数据天然出境。
  • 本轮任务是独立评审与形成方案。没有改造 demo、上线服务、修改 MaaS 配置或联系供应商。
  • v5/v6 中关于以往“用户拍板”的转述作为历史背景，不替代本轮用户直接给出的要求。本文的云托管建议仍是待管理层决定的方案，不是已获得执行授权的部署。

4. 影响立项的五个发现

  1. 当前工程是 G0 原型。 内置文件/Shell/子代理等多项能力被禁，Skills 与提问链路也有缺口；不能称已完整接入 Kimi Code。独立源码审计与合成探针还发现路径隔离缺陷。详见调研 A。
  2. Kimi Code 的开源能力不等于 Kimi Work 服务权益。 默认搜索、数据源、遥控和外部浏览器组件存在独立依赖。通用能力要接通、替换或标注受限，不能靠关工具宣称完整，也不能直接带着会员凭据上生产。
  3. 本地执行仍可能发送大量案情。 模型上下文、压缩摘要、子代理消息、搜索词、截图、工具结果和诊断信息都应进入数据流清单。只检查第一次 prompt 不够。
  4. 安全承诺必须按路径限定。 C 模式云端会解密处理；L 模式密文中继不解密，但模型网关能看获准请求；删除旧密钥不能追回已导出的明文或离线备份；设备签名不自动成为可靠电子签名或司法存证。
  5. 商业不能靠固定席位无限调用。 模型、检索、沙箱、人工支持、文档保真和法源维护共同决定成本。本包提供透明的压力测算，不沿用旧稿精确到万元的多年盈利预测。

5. 完整接入与首发承诺

“完整接入”定义为：锁定 Kimi Code 版本，对其能力族逐项登记原生接入、适配替代、政策限制、待实现；验证规划、流式事件、提问、审批、文件工具、沙箱计算、Skills、MCP、子代理、长任务、取消恢复、用量与搜索路径。不等于让每个用户在每个渠道使用所有权限。

首发推荐三条完整业务链：合同审查与回稿；民商事材料整理与受限文书；获许可范围的法律研究与顾问答复。以原生 Word/Excel、来源、复核、签发、归档、账单和支持闭环定义完整，不要求第一天把全部 36 个演示入口做成生产能力。

Windows 桌面、Web 协作与管理、可编辑文件交付是主线；首家 Office 深度插件与 IM 由试点环境决定。任意桌面操控、法院提交、独立原生手机 App、所有平台同时上线不进入首发强制范围。未通过的能力保持不可售，不能藏在“自动模式”里绕过。

3. 对 Astra 的独立评价

最强部分是把错误后果写成系统语义。例如执行成功不等于律师批准；过期worker不只不得提交，还不得继续收费或读材料；来源存在不等于支持结论；审批不能跨文件版本。这些直接减少真实法律工作中的事故，应成为新架构共同内核。

云端统一编排也有成立的工程理由：集中撤权、多人协作、后台队列、移动处理、恢复与统一版本更容易运维。原稿把它用于允许境内托管的客户，并非天然错误。真正需要修正的是默认用户已经允许上传、弱化桌面本地资源，以及早期依赖未确认的上游 Work 平台接口。

不接受旧稿对 Astra 的简化描述：“它只会做网页，因此不适合律师”。09-22 原文已经提出本机Office桥、原生修订和适配器边界。评价应基于实际条文，不沿用上一轮方案对竞争稿的概括。

4. 对 Opus 的独立评价

最强部分是把通用 Agent 转为可购买的律师工作服务：角色、场景、交付件、规则生产、模板、Word/WPS、IM、试点、席位和内容运营之间有完整联系。应保留“原文—问题—建议—依据—处置”的审阅体验，以及从回稿回流到重新签发的闭环。

主要问题是“设计详尽”有时遮盖了证据不足：开通十分钟、各种平台五分钟接通、私有化只改配置、同用户进程安全、恢复卡无法合谋、固定日期可公开销售，都是需要实测或限定前提的目标。v5→v6→v7不断增加机制又沿用原排期，也说明架构尚未收敛。

不否定本地优势：文件夹挂载、Office宿主、低延迟比对、离线审阅及保密客户的材料控制很有价值。但无需因此牺牲所有云后台能力；反过来，也不应把端到端加密和复杂密钥仪式强加给只要求境内受托托管的小团队。

1. 第一性原理：先定义谁能处理什么，再选择位置

一个动作至少包含：人、所属组织、事项、输入对象及版本、处理目的、工具、执行环境、接收者、时间、预算、输出去向。只写“本地/云端”无法判定是否合法、可用或安全。

Agent编排 本机、律所执行器、中软worker 编排会接触上下文，不能当纯元数据服务

8. 数据流与降敏规则

以下全部属于受保护输入或派生信息：原件、解析文本、OCR、图片、截图、邮件头、搜索式、嵌入向量、长任务摘要、子代理上下文、工具回包、交付文件、文件名、事项名、用户反馈及日志。索引和摘要不是“没有原件所以不敏感”。

出站逐类记录目的地、用途、区域、来源对象、载荷类别、时间、审批/政策版本、用量、供应商请求ID。正文或原始搜索词按事项内容策略保存，运营日志只保留必要元数据；日志正文不再次复制到全局APM。

化名是减风险工具，不是数据出站合法性的证明。 只对已允许的目的和接收者外发。标识符和实体识别未命中不自动降级为公开。允许建立经律师批准的泛化查询模板，在范围内自动检索；企业名称查询确实必要时，向律师说明目的地和用途后明确授权，不偷偷删除名称导致查错主体。

严禁对Shell脚本、可执行参数或路径做模型返回后的自然语言替换。文件、实体和锚点采用稳定ID，文书渲染层按类型还原；模型要编辑某段时提交document_version + anchor + expected_text_hash + proposed_text，内核验证后生成修订。需要原始图像时独立判断并展示，不能隐藏在ReadMediaFile内。

网络强制包括HTTPS、DNS、IPv6、回环、重定向、WebSocket、下载器和子进程。抓取代理防SSRF：拒绝私网/链路本地/元数据地址，DNS解析和每次重定向重新校验，允许列表不能只看域名字符串。浏览器页面、搜索结果、材料中的指令均为不可信数据。

9. 沙箱最低标准与降级

每个活动任务/尝试独立隔离：只读输入快照、只读可信方法/配置、可写scratch/output、不可写正式交付库；不挂载用户HOME、凭据目录、Docker socket或其他事项。代码默认无网，合法联网由沙箱外broker代做，broker也不得接受任意HTTP透传。资源有CPU/RAM/时间/磁盘/子进程上限。

Windows选型通过PoC决定，优先少数可支持的强隔离实现；macOS/Linux分别验证。不把五种沙箱同时维护作为首发目标，不把某开源参考实现的存在当本项目已经可用。网络、文件和子进程是分别验收的能力，不给一个模糊“A级”替代实际测试。

不能达到最低隔离时：可信解析/比对/确定性工具可以运行；通用代码执行关闭。C事项可提示改在已验证云沙箱执行；L不得静默上传，也不得换成管理员权限裸跑。低配电脑默认并发1，16GB起验证2；更多子代理可排队，而非并发越多越“完整”。

10. 密钥、同步、撤权与删除

签名、解密、恢复分三类密钥。 每设备独立签名钥匙与证书/公钥登记；不把同一签名私钥扫码复制到所有设备。跨设备通过包裹数据钥匙获得阅权，设备吊销可具体定位。硬件不可导出的密钥不能同时设计为可跨设备备份恢复；身份恢复后给新设备新钥匙，保留旧签名验证链。

C：KMS信封加密、每租户/事项隔离上下文、服务最小权限、密钥访问日志；客户管理密钥可选，但有权服务仍可解密处理，不能称E2EE。业务管理员默认无正文访问；平台紧急访问走JIT、双人审批、原因、限定范围和客户通知。

L密文同步：使用经安全审阅的成熟密码协议与库，不自创密码算法。服务器保存最小成员/角色元数据便于租户/设备鉴权，内容钥匙只包裹给获准设备/恢复主体。禁止共享写签名私钥；同步采用不可变对象、版本向量/父版本、明确冲突版本，授权变更有顺序及纪元；哈希链不代替业务冲突解决。

恢复：个人随机高熵恢复码+第二已授权设备为优先路径；机构可选择双人恢复或客户HSM。恢复主体能做什么写入安全白皮书。不能用“管理员确认”软件流程声称持有完整恢复秘密的人数学上无法绕过。创建真实L事项前完成一次恢复验证，用户只看到“备份可恢复”结果，不强迫每位律师理解Shamir。

撤权：云端立即拒绝新的读/工具/计费与令牌续期；在线设备接收撤权，终止任务并清理缓存；离线设备在重新联网或本地租约到期后收紧。新版本更换密钥，旧数据是否已被获取不可收回。声明中明确在线传播SLO和离线窗口。

删除：对象→索引→向量→运行状态→导出临时包→设备缓存→备份→恢复材料逐项记录。状态至少为“在线副本已删 / 等设备上线 / 备份待到期 / 法律保全 / 外部已交付不可撤回”。恢复旧备份先重放删除与撤权记录，不能复活已删事项。保全授权与伦理墙分别校验，不能任何成员随意阻断全所依法删除。

流程：解析结构与覆盖清单 → 定义/金额/日期/附件交叉检查 → 法律强制规则+立场Playbook+本所覆盖层 → 生成风险卡及替代条款 → 律师接受/修改/拒绝 → 文书引擎写原生修订 → 对方回稿三方比较（原始稿/我方发出稿/对方回稿） → 重审变更和受影响定义 → 受众检查 → 复核签发 → 归档。

风险卡字段：原文锚点、风险事实、法律/商业属性、严重度、适用前提、依据与核验状态、首选修改、可谈判备选、需要客户决定的事项。不能用“高风险”代替解释，不得把偏好包装为法律禁止。

交付件：审查报告.docx、带修订合同.docx、问题清单.xlsx、关键商业决定清单、引用与覆盖清单、独立签发证明。发给对方版本剥离内部谈判底线、内部评论、隐藏属性与未授权材料。

首发内容：先验证采购/买卖、服务、保密、软件许可及实施4类×双立场；通过后扩至v5的9类×双立场（股权转让、技术开发、商业租赁、借款担保、劳动及配套）。这是上线顺序调整，长期18套规则资产保留。未验收类型显示“通用辅助阅读/草稿”，不能套已售准确率。

错误处理：附件缺失、金额不一致、条款不可定位、扫描缺页、法源无许可时明确缺口；可生成内部草稿，签发前必须解决关键缺口或由有权律师记录范围限定。严禁自动补造当事人、条款、登记事实。

B. 材料整理—事实与证据—受限文书—金额表

输入：有序文件包、证据来源、争议类型、当事人和主张、分析截止日。首发为内地民商事，具体文书类型与受理地区逐项验收；刑事/涉密/复杂监管业务不因通用Agent能回答就视为上架。

流程：安全扫描/解压 → 本地或C获准云OCR → 原件页码/图像/文本锚点 → 去重但保留来源链 → 分别抽取“材料声称的事实”“律师确认事实”“推论”“待确认” → 时间线和证据矩阵 → 缺失证据及相反材料 → 文书字段确认 → 确定性金额计算 → 原生文书与附件目录 → 人工复核。

交付件：证据目录.xlsx、时间线.xlsx、争点—证据矩阵.xlsx、文书草稿.docx、计算明细.xlsx、缺口清单。每一个关键事实链接确切文件版本和页段；“未检出”不写成“不存在”，“未提供”不写成“无此义务”。

计算：Decimal或等价精确数值；本金分段、币种、利率来源及版本、起止日计入规则、节假日规则、还款冲抵与上限由确定性组件计算；模型只提议参数。不能把LPR四倍当所有违约金、利息和金融借款的一般公式。律师确认法律适用与事实输入后才形成正式表。

期限：模型抽取候选起算事实，律师确认送达方式、日期、期间性质、中止中断等；日历引擎计算并记录规则版本。提醒“已送达”只表示通知通道回执，不表示法律送达或业务期限已履行。首发不自动法院提交。

6. Office、移动与IM

Office主线：客户端导出标准DOCX/XLSX为所有支持环境基线；优先接入试点占比最高的一种Word/WPS宿主。插件只绑定用户当前打开的指定文档、当前版本和事项；读取选择/全文分别授权。原生修订必须保留段落、表格、脚注、目录、页眉页脚、编号和批注关系；对含域代码、保护、签章的文档先检查，不能重建后声称无损。

写回使用 base_version + anchor + expected_text/hash + replacement，冲突返回预览，不按模糊文本替换全篇。保存、关闭、另存、同时人工编辑必须有冲突策略。外部关系、宏、嵌入对象按信任和格式处理；不能无提示删除客户必要内容。首发不编辑带有效电子签章的原件，生成新版本并说明签章已不适用。

移动：首发C受管Web支持完整成果预览、评论、再认证后审批，限制下载按律所策略执行；浏览器不能保证阻止截图。L默认通知，内容需在线桌面安全会话或已验收的移动解密客户端；手机App可后续加强密钥与离线体验，不将它列为销售前所有产品的共同依赖。拒绝“手机先发出、24小时补签”。

IM：只接试点最常用一家（企业微信/钉钉/飞书择一）；账户绑定与撤销明确。可收件、启动预设任务、查状态、提醒；不能任意文字越权调用Shell或最终外发。IM平台本身可能保存消息/附件，L不允许的资料应改用桌面导入。短时下载URL、重投去重、过期处理和文件真正落地回执全部验收；不可笼统宣传“机器人转发文件完全不经云”。

7. 签发、版本与法律责任

成果状态为 草稿 → 待复核 → 待签发 → 已签发 → 被新版本替代/撤销使用；Agent只能推进至待复核。有权律师查看的具体渲染版本、附件、受众和去向记录到审批对象。C/L均不允许审批一个版本却交付另一个版本。

输出顺序：确定内容 → 受众处理 → 依法配置AI标识与元数据 → 生成文件 → 计算hash → 生成独立manifest → 设备/服务签名。签名只证明所声明的签发流程与文件完整性；可靠电子签名、时间戳、存证和法院证据效力另按适用服务和法律要求实现。

任务执行成功与法律复核通过分别统计。只完成7/10份文件时任务为部分完成，剩余列表可恢复；律师可限定范围签发，但产品不能把未读材料计入覆盖率。

8. 知识、规则与内容工程

租户、事项和个人记忆分区，跨事项复用默认只允许经知识负责人批准的模板/匿名方法。不能自动把客户事实、胜诉策略、对方底线写入全所记忆。向量也是受保护派生数据；检索前按ACL过滤，取回后再鉴权，撤权同时影响缓存。

规则项包含适用条件、立场、效力时点、法源、法律要求/商业偏好类别、建议与备选、例外、内容负责人、测试样本、版本。来源表另记录抓取/索引/模型输入/展示/摘录导出/训练评测/终止留存权；订阅数据库不自动获得全部权利。

6. 状态、恢复与幂等

任务状态：CREATED → VALIDATING → QUEUED → RUNNING，期间可进 WAITING_INPUT / WAITING_APPROVAL / WAITING_DEVICE / PAUSED_BUDGET / RECOVERING；终态为 SUCCEEDED / PARTIAL / FAILED / CANCELLED / EXPIRED。终态转换用数据库CAS；未知状态、缺成果或截断不能成功。Artifact的法律复核状态独立。

Run是用户意图，Attempt是执行尝试。每Attempt获得短租约与递增fencing epoch；失去租约后不得读取新材料、调用上游、写产物或结算新费用。网关、对象服务与最终提交都检查epoch，不能只在调度器检查。队列是至少一次交付，外部效果以idempotency key和接收方回执保证；不能承诺任意外部系统exactly-once。

checkpoint保存：已完成工具结果指针、输入快照、政策与模板版本、预算账本、待答问题/批准、压缩历史、失败覆盖清单。恢复必须重新检查权限和输入版本。引擎会话续接只是实现手段，不能重跑整个任务后算“恢复”。副作用结果未知时进入人工对账，不直接重发。

同步采用不可变事件与文件块、乐观并发提交；独立草稿可并存，签发与外发单一权威提交。C服务器权威，L指定本机/runner事项协调者；更换协调者须租约交接。MVP不做Word正文CRDT实时合写，以独占编辑租约+冲突副本保障清晰责任。

7. 沙箱与出站的真实覆盖

本机优先选择一条可维护且实际通过目标Windows版本/EDR的强隔离方案；其他方案是候选，不能用A/B/C字母掩盖实质差异。不满足读隔离或网络限制的环境只提供可信解析/比对等标准工具，不允许运行模型生成代码。用户确认不能补上隔离。

云worker用任务级隔离环境，容器以外叠加用户命名空间/最小权限/seccomp/网络策略等适合部署的控制；高风险通用代码评估microVM。容器不是天然租户安全证明。禁止宿主socket、云元数据、挂载宿主根、privileged和共享可写依赖；CPU/RAM/进程数/磁盘/输出量/执行时间全部限制。

文件安全包括symlink/junction/reparse、UNC/网络盘、大小写、保留设备名、长路径、压缩包路径穿越、检查后替换竞态。不能只用 realpath 检查一次后再按字符串重新open；broker须在实际操作时绑定安全句柄/目录，或将不可信操作限制到已隔离快照。

出口覆盖模型、搜索、Fetch、浏览器、MCP、OCR、遥测、更新、依赖下载、媒体、WebSocket、DNS和子进程。允许域名不等于允许任意路径/请求体；必须校验动作和数据。公开网页内容不可信，不能改权限或触发安装。关闭网络的脚本仍可把秘密写入产物，后续导出同样受审查。

化名策略替换v7双向代码替换：进入模型的敏感文本按获准目的最小化/化名；任务文件名使用稳定安全ID；引擎编辑去标识的工作表示，输出结构化patch与实体ID。可信文书引擎在最终文档字段内还原，校验引用、转义和版本。绝不替换Bash/JavaScript/Python源码字符串。无法兼容语义或OCR图片时停用该模式或单独授权真实输入，不承诺NER可以实现匿名化。

8. 模型、预算与方法资产

从单个经过法律评测的Kimi主模型开始，低成本模型仅用于通过专项评测的分类/抽取，不自动替代复杂法律判断。策略锁定供应商、模型族与处理区，容量不足不静默跨供应商路由。reasoning/signature等协议约束字段遵循锁版官方接口；UI不展示思考原文作为审计依据，存储与回传纳入内容政策。

长文采用覆盖驱动切分、结构/附件联动、多段检索和全局一致性检查；不因模型支持长上下文就一次塞全库。上下文压缩不能丢关键限制、资料版本和不确定性，法律事实账本独立于聊天摘要。

预算先预占、每次调用检查、父子共用总上限，给最终汇总/失败说明留余额；自动重试只适合已知未产生副作用的失败，次数与费用受限。达到预算暂停并给出已完成/未完成/追加预计，禁止后台继续扣费。usage不完整先标待核对，不把输出字符数冒充供应商token。

方法资产以版本、合同、持续质量和组织覆盖层形成护城河。首发不建设复杂占位符扩展/思考密封协议；必要云端prompt组装必须有展开后成本、版本和可评测输入证据。内容进入模型后不能保证绝不经输出泄露，50字重合检测仅辅助。

9. 现有平台和MaaS复用

本轮未修改相邻 MaaS 生产/new-api 工作区。正式接入前对共享MaaS做独立数据流核验：正文/错误体日志、重试、模型fallback、缓存、管理员访问、导出、计费精度、断流及reasoning字段兼容。单独“法律分组”不是隔离证明。

3. 各方角色与数据条款

1. 独立结论

Kimi Code 是可真实嵌入的 Agent 引擎，现有 fork 并非虚构 SDK；使用开放平台模型 API 建设自有订阅 SaaS 在技术上成立。但“买了 API token → 获得 Kimi Work 全后端 → 现有 demo 已完整集成 → 可直接服务律师”这一推导不成立。当前集成保留循环、部分会话与法律 MCP，主动关闭大量通用 Agent 能力；项目尚无证据证明操作系统沙箱、持续任务、交互提问、技能装载、浏览器及完整云服务已经交付。

v5 的优点是明确将模型视作不可信决策者，将事项权限与成果签发置于业务内核；v6 的优点是补上 SaaS 控制面、中继、公开任务和服务商 IM 的产品现实。主要问题不是选错 Kimi Code，而是把“能力关闭”当成长期安全架构，把“进程级封装”与“OS 强制隔离”混用，以及新增通用工具后未重新检查绕过路径。用户要求完整能力时，必须通过独立执行域、能力令牌和统一工具网关恢复能力，不能只扩大一个 enabled 数组。

本报告不能为“完美无风险”或“可直接上线”背书；可以给出清晰的生产退出条件，逐项过关后转为可交付产品。

5. 现有实现的独立缺陷与生产阻断项

以下路径相对仓库根 platform/。报告列出源码行号，避免把设计愿景与已完成实现混为一谈。

A-P0-01：没有 OS 沙箱，不应把应用层改写称为“无对外网络能力”

apps/agent-host/src/host.ts:5–7,49–57 声称全局 undici dispatcher 让宿主事实上无外网能力；packages/kernel/src/executor/agent-host-manager.ts:183–194 实际使用普通 spawn(runtime,[entryPath])，未见受限令牌、AppContainer、Job Object、网络命名空间或外部沙箱启动器。

已确认的技术边界：全局 dispatcher 仅影响采用该默认 dispatcher 的请求。官方 app/web/providers/local-fetch-url.ts:129–134 显式传入自己的 dispatcher；它可以绕过全局 dispatcher。node:http/https/net、自建 dispatcher、child process 和本机原生组件也不因这句设置而失去网络权限。vendor bundle 中存在 direct fs/child_process/net imports。

当前白名单关闭 FetchURL，故本次不是声称现已发生外联入侵；这是当前隔离结论不成立、及扩功能时必现的架构缺口。修复：云执行放进强隔离沙箱并默认断网，仅允许受控代理；端侧独立受限执行器、进程树/资源限制与受支持系统的 OS 网络强制。所有形态运行实测矩阵，无法建立强边界的个人自装模式必须明确为较低保证等级，不能显示相同安全标识。

A-P0-02：文件系统边界可被符号链接穿透，Windows 合法子路径也会失败

apps/agent-host/src/sandbox.ts:38–65 只对 resolve() 后字符串前缀判断；读写在检查后直接执行，未验证最终目标、链接/重解析点及打开时竞态。under() 固定使用 /，Windows path.resolve() 返回 \\ 路径，合法子目录将被错误拒绝。

本次已实测：Node 26.8.1，临时目录创建纯合成 synthetic-outside.txt；快照内 link.txt 指向白名单外该文件，再直接调用实际 createRestrictedFileSystem.readText(link)。结果 synthetic_symlink_escape=true。另使用 path.win32 计算合法子路径并代入当前判定，结果 windows_legal_child_allowed_by_current_under=false。临时文件已清理，无真实文件内容被读取。

这证明 wrapper 本身不是强边界，不证明通过当前封闭工具集可以直接构造完整攻击链。修复：root-relative path 与 OS 文件句柄能力校验；拒绝/安全解析 symlink、junction、reparse point、UNC、大小写、长路径；对读写、rename、link、删除均在真实边界内执行；仅 realpath 后再读不足以处理 TOCTOU。终极边界仍是 OS 沙箱与只挂载允许目录。

A-P0-03：“manual + setApprovalHandler”不等于每次工具执行都强制经过业务审批

官方 permissionPolicy/policies/default-tool-approve.ts 默认批准 Read、Grep、WebSearch、FetchURL、Agent、AgentSwarm、Skill 等；permissionGateService.ts:53–59 只有 ask 才请求审批，approve 直接放行。因此以后开放工具时，不能靠回调自动接管全部行为。

当前 manager 的 agent-host-manager.ts:90–102 对 mcp__legal__ 前缀自动批准，既没有按参数描述副作用，也没有让律师在此处确认。这对现有六个受限法律工具可作为原型策略，但不是成熟三级权限机制。应以执行前策略强制点为准，重新校验主体、事项、对象版本、动作、数据去向、预算、有效期与吊销状态；审批 UI 仅签发窄化 capability，工具端必须消费并核验。

不要把 mcp__legal__* 通配符当永久安全分类。新增同前缀写工具会自动继承批准，必须使清单包含 tool schema hash、作用范围和副作用类别。

A-P0-04：任务 timeout 会被记为 succeeded

host.ts:154–163 超时发送 {t:'done',status:'timeout'} 后以 1 退出；manager :105–107 把除 cancelled 外的 done 全设为 succeeded；退出处理 :237–247 仅更正 running/starting 状态，因此 timeout 的 succeeded 可能保留。这是直接源码逻辑缺陷，不应把不完整草稿作为完成成果推进后续流程。

修复为有限状态机：succeeded、failed、cancelled、timed_out、waiting_user、budget_exhausted、interrupted 分离；终态转换须绑定结果完整性；非零退出、模型截断、工具失败、依赖缺失不得被默认成功吞掉。

A-P1-05：提问、Skills、事件持久化尚未完整接入

  • host.ts:71 声明 uiCapabilities:[]，仅设置 approval handler，无 setQuestionHandler；白名单含 AskUserQuestion 不能证明“中途向律师提问”可用。官方工具 askUserQuestionTool.ts:194–198 交互不支持会返回明确错误。必须端到端测试问题出现、答复、取消、恢复与身份校验。
  • manager :174–181 固定 skillDirs:[]，因此现有 manager 路径未装载签发法律 Skills。方案里的签发技能目录是目标，不是本轮可确认实现。
  • host.ts:169–187 把事件正文截断到 2,000/4,000 字符；manager :85–88 又将任意 delta/text/content 拼成 outputText。需要明确最终输出与中间推理/工具事件的区分，避免重复、错序、截断污染成果；成果应采用结构化 artifact 事件、文件 hash 和事务完成记录。
  • manager :74–75 的事件首先写内存数组。host 注释“先落账本再推界面”本身不是 durable persistence 证明；整体 executor 可能稍后轮询入账，需崩溃故障注入确认缺口。

A-P1-06：取消、恢复与凭据范围要重做能力化验证

agent-host-manager.ts:276–279 仅杀一个进程，理由是 ZP-5 下无孙进程；但 sandbox.ts 已承认 direct child_process 不受 DI 管理。开放 Shell/MCP stdio/CU 后，这一假设必失效。需 Job Object/cgroup/可验证进程树终止，且先吊销 run capability，再取消模型/远程工具；远端已提交副作用需要补偿或对账，不能说杀进程等于撤销操作。

executor.ts:731–732 明确 agent_start/agent_wait 不落检查点，崩溃后整任务重跑。对六个只读工具可接受；对邮件发送、云盘写入、提交签章不成立。持久任务需要 checkpoint、工具幂等键、outbox、执行租约/fencing、恢复时权限重验和副作用回执。不可把上游后台 Agent 或 cron 直接当作多租户可靠调度器。

A-P1-07：应用层配置由高权限目录保护不足

签名 agent profile 被复制进可写 home（manager:139），文件 mode 0444 并不等于拥有同用户权限的进程无法替换文件。agent 的可写状态与可信 config/profile/skill 分区必须分开；可信文件按制品 hash 只读挂载；执行前策略不能由模型可写文件决定。

推荐结构

控制面负责身份、授权、任务编排、预算、审计索引、产品计费。执行面可在“云租户隔离沙箱／本地设备／律所节点”选择，选择依据包括事项策略、对象位置、用户明确授权、所需能力与在线状态。模型推理位置单独标注；本地执行+云模型是独立模式。

模型只提出结构化工具请求。工具网关计算有效权限交集：平台安全基线 ∩ 租户策略 ∩ 事项授权 ∩ 用户角色 ∩ 任务授权 ∩ 工具作用域 ∩ 当前撤销/时限/预算状态。云执行器不能获得任意本地文件；本地桥也不能成为云端泛化 shell。通过“限定对象+限定动作+限定目的地+到期+nonce”的 capability bridge 调用。

跨执行域迁移必须生成新的授权决策：列明上传对象和派生内容、目的地、保留期、模型供应商与续跑条件。不能因为本机不可用就静默上传；同样不应每个低风险步骤都弹窗。

1. 对最终方案最重要的判断

  1. 执行地点、数据持久化、模型推理地点、访问权限是四个不同的轴。 本机读文件、本机 Python、云模型推理、本机保存结果完全可以同时存在。不能用“本地 Agent”推出“文件内容不出设备”，也不能用“云端 Agent”推出“全盘可读”或“必定访问内网”。
  2. 手机遥控不是云端托管。 WorkBuddy 助理和 Kimi Work 本地任务都依赖电脑在线；千问桌面/网页有两套定时任务。产品必须显示真实执行节点、最后在线时间、断线状态、错过触发与补跑规则。
  3. SaaS 是交付/订阅方式，不决定所有工具在哪里执行。 API token 采购既不附送 Kimi Work 产品后端，也不妨碍中软自建合规云端 Agent Runtime。需要独立建设两种执行器、凭据代理、审计、存储、授权与任务调度，而不是把产品品牌或 API 账单当成这些能力的来源。
  4. 有云管理端不代表管理员应可读全部案卷和全部对话。 律所案级权限、利益冲突隔离、系统管理员与业务阅卷权应分离。企业治理参照竞品机制，不能照搬其“所有会话集中回放”作为所有律所的默认值。
  5. “全部权限”不适合成为法律版的常用能力档。 应提供可审计的有限授权模板，在案件工作副本内自动产出；覆盖原件、跨案访问、对外发送、签署/递交、付款和系统配置各自独立授权。用户的一次开关不能替代每一项权限和业务责任。
  6. “本地原件优先 + 显式云托管 + 同一权限语义”可以成立；“所有法律 AI 都在云端”或“必须全部本地”都没有证据。 数据策略选择不应偷偷改变执行节点，也不能因节点离线自动把案卷移往云端。

以上为本研究的架构判断，不是对任一竞品现有能力的断言。

5. 法律 SaaS 应采用的权限模型（设计建议）

5.1 以动作和数据边界授权，而非以“云/本地”授权

建议每次工具执行至少计算以下交集：律所策略 ∩ 案件权限 ∩ 用户权限 ∩ 数据源权限 ∩ 设备权限 ∩ 工具权限 ∩ 本次授权 ∩ 运行时可用性。任意明确拒绝优先。云与本地执行器调用同一政策语义，但各自独立校验，不能只信另一端发来的 approved=true。

授权分成以下维度，界面可合并呈现，底层不能混成一个开关：

  • 能看什么：指定案件、目录、文件、数据库记录；冲突案件排除。
  • 能把什么送给谁：本地提取内容→中软网关→Kimi 模型；搜索查询→搜索商；截图→视觉模型；分别检查。
  • 能改什么：工作副本产物、原件覆盖、批量移动/删除、系统配置。
  • 以谁身份：当前律师的委托身份、案组服务账号、受管设备账号；不得默认为平台万能账号。
  • 何时能做：人在场/定时/遥控；授权有效期、次数、额度、指定执行节点。
  • 能否对外生效：发信/分享/发布/法院递交/电子签署/付款独立分级。

5.2 一个推荐默认值，不制造未经证实的“绝对本地”承诺

5.3 工程上必须分清的六个细节

  1. 批准不能被重放。 票据绑定租户、用户、案件、工具、规范化参数、文件版本、目标节点和到期时间；云本地都核验。
  2. 执行副作用不能盲重试。 定时/断线恢复用幂等键；发信、签署、上传等结果不确定时进入人工核对，不简单重放。
  3. 审批服务故障不是授权。 执行前闸门故障时高风险动作停止；只读、公开信息等低风险能力可按明确定义降级。
  4. 撤销有传播 SLA。 停用用户、撤案权限、断开连接器、失窃设备必须终止后续工具调用、撤短期令牌、处理队列；在途已发送数据无法靠 UI 撤销收回。
  5. 日志也是案卷。 默认留动作元数据；正文/截图诊断按需、脱敏、短保留、客户可见；严禁写入 API Key/Cookie/签名密钥。运维排障走临时授权、双人审批和记录。
  6. 隔离要按工具验收。 VM 对 shell 的隔离不能自动证明文件 broker、MCP、浏览器、OCR、预览器隔离。宏、外链、压缩炸弹、路径穿越、符号链接、网络共享和文档提示注入需单独测试。

1. 最重要裁决

推荐境内 SaaS 控制面、境内受控云执行、本地执行器共用一套权限和交付体系；由律所政策与事项密级选择执行位置。不能把“所有案卷必须只在所”当成用户已经提出的需求，也不能把“上云”默认等同于违法。 用户确认采购 API token、按 SaaS 订阅销售及品牌授权；未要求所有用户安装本地客户端、禁止境内受托云处理、强制端到端加密协作。

v5 的主要价值是把法律工作做成可验收交付件，提出原件不可覆写、出处定位、受众分版、签发绑定最终文件等正确要求。v6 正确认识到机构控制、同步和移动入口需要常在线服务，但仍把案卷本地化当不可动摇前提，因此“零服务器”只是没有律所服务器，实际依赖律师电脑在线。本地执行+云端推理并没有消除第三方处理；反而把加密同步、密钥恢复、终端支持、离线撤权等困难一并引入。v7 恢复开放 Agent 能力有价值，但“任何能力弱于标准版都无法定价”的论断不成立：法律产品应该按交付质量和业务效率定价，而不是与通用办公产品做功能数竞赛。

3. 法规与证据核验

3.1 《律师法》2026 修正：属实，但须防止“校验自己生成的法源”

本轮独立打开最高人民法院受权发布的主席令，确认 2026-08-28 通过、2026-09-01 施行；北京司法局当前公开全文列明第二十六条律所管理制度、第四十一条保密、第四十二条利益冲突。旧稿这些条号有官方支持，不能仅凭此前常识中的 2017 版条号推翻。全文未见新增 AI 专门条款。主席令、北京司法局全文。

同时，本轮读取的北京司法局转载中个别内部交叉引用疑似仍沿旧条号，说明官方网页也可能存在排版或整理差错。生产法源库应保存公布机关、公报版/公布决定、抓取版本、时间和摘要；冲突由法律编辑核对正式公布文本，不以一个页面及模型判断自动发布规则包。仓库演示种子、既有报告、搜索摘要不能充当法规原始证据。

3.2 PIPL：按数据与行为建模

已核对《个人信息保护法》：处理依据不只同意；委托处理、公开个人信息、敏感信息、影响评估均有各自条件。加密或化名可降低风险，不能自动视为匿名化。产品应让律所记录适用依据、处理目的、数据主体范围及风险评估，而非替律师自动判合法。法律全文。

基于上述规则的产品设计推论：

  • 客户保密授权解决的是律师向技术供应商披露客户信息的约定边界；个人信息法依据解决对自然人数据的处理条件；二者不能互相替代。
  • 一个公司客户确认使用 AI，不自动覆盖劳动争议中员工、对方证人或病历涉及者。需要事项目的、处理必要性与法定依据审查；无法建立条件的字段删减、改为人工或限定本地处理，不能凭模型推断授权。
  • “公开裁判文书”也可能含个人信息；做某案研究与建立自然人行为画像是不同目的。默认禁止法官画像、自然人背景评分等超范围用途。
  • 本地处理同样属于个人信息处理；阻断上云只是减少一种风险，不自动治愈非法来源、越权共享或超期保存。
  • 乙方中软、模型商、OCR/搜索/存储厂商等按真实活动定角色，不因产品叫 SaaS、代理或软件授权自动改变。

《网络数据安全管理条例》第十二条明确了提供、委托处理个人信息和重要数据的约定、监督及记录要求。应维护版本化受托/转委托清单，变更后重新判断是否扩大范围，而非把所有上游简单写作一个“Kimi”。条例。

3.3 境内云、香港上市公司与跨境

中软国际香港上市这一事实本身不能推出案卷必然出境。要看运营实体、模型与工具处理地点、日志与备份位置、供应商支持、境外管理员/香港团队的访问权限，以及面向境外发送结果的路径。境外主体可访问境内数据亦可能属于数据出境；密文不是自动豁免。网信办数据跨境说明、网信办 2026 年 7 月问答。

建议标准版：境内签约运营、境内生产与灾备、境内模型/API 端点、境内运维人员白名单；全球支持默认只见脱敏工单。境外访问和跨境法域事项单独准入，不能用香港上市或海外客户的标签替代出境判断。重要数据识别遵循相关目录、通知及规则；不应把所有案件材料自动认定重要数据，也不应因未出现客户姓名就认定不是重要数据。

3.4 律协指引不是全国统一禁止云处理的法律

上海律协 2025 居村顾问指引明确自身非强制性、参考性，并定义本地化部署；2026 企业法律顾问指引有独立适用场景。可以据此提供保守预设与评估模板，不能把某份指引的建议转换成全国所有律所的云端禁令。2025 指引、2026 指引。

v5 摘要把敏感类型称作“五类”，但上海原文包含宗教信仰、特定身份等，不宜把摘要列表做成穷尽名单。2025 指引注明试行一年，本轮没有取得其续期决定；用作方法参考时必须标注，不能称“现行强制要求”。深圳 2026 指引本轮搜索未取得协会官方全文，既有 v5 调研自己标为律师博客二手转载；最终文本却多处提升为“一手”。必须纠正证据等级，未经原文核验的具体条号不得作为自动合规判断的唯一规则。

小型个人信息处理者简化措施有网信办 2026-07-24 官方答记者问支持其存在；但“多数律所都适用”和“直接内置附件格式”仍需核对正式规定、适用人数口径与实际律所数据范围。不能把单家律所规模简化外推为中软多租户平台同样享有豁免。官方问答。

3.5 登记、等保、标识应区别法定义务与采购策略

网信办 2026-09-14 公告明确直接调用已备案模型的应用/功能由地方网信办开展登记，且给出公示要求；最终适用还要结合服务范围及属性。B2B 收费不自动豁免，也不能把客户内部使用排除条款不加判断地适用于公开招揽所有律师的 SaaS。备案登记公告、暂行办法。

“按三级控制目标建设”是合理商业安全目标，但不等于已依法定级三级、更不等于已经测评。定级对象、边界及等级由适用程序确定；同集团已有证照不自动覆盖新增运营主体、域名和系统。ICP、电信许可、App 备案、商用密码适用应列责任人、法律依据、办理状态、验收凭证；不能用“与网信咨询同一次完成”低估不同主管机关流程。

AI 标识规则为无显式标识版本提供附条件路径，并非所有交付件绝不能有干净版。隐式标识、用户义务、导出日志应结合适用范围实现，不得用“律师签发”自动消除平台义务；技术元数据保留与专业保密同时设计。标识办法、官方说明。

4. API 采购与合同：旧稿有正确阻断项，也有过度推导

当前官方协议明确允许通过 API 向最终用户提供服务，同时限制账号转交、权利再许可，并保留输入输出服务优化使用权。故“采购 token 做法律 SaaS”不能简单等同裸 key 转售；用户既有品牌授权按事实接受，登记授权范围和有效期即可。需要解决的实质条款是法律数据用途、保留、支持访问、转委托、责任及可用性。Kimi 开放平台服务协议，2026-08-31 生效版。

5. 法源、律师交付质量与产品边界

v5 最值得保留的是交付件规格，不要随着底座放权丢失这些专业门禁。首发必须给每个场景明确支持法域、材料范围、交付格式、待律师确认项、失败状态和评测报告。现有“生产/Beta/模板”三档成熟度合理，但销售页面与配额计费应一致。

法源可得性与商用许可分开。《著作权法》第五条排除特定官方文件，不意味着商业数据库的编辑摘要、检索结构、接口、案例集及平台访问条款可以任意复制再分发。国家版权局法律全文。

数据商许可逐项谈：检索、全文拉取、临时缓存、索引/向量化、送入第三方模型、摘录导出、客户工作成果留存、终止后的访问、审计/评测使用、是否可面向多租户转供。前台显示一个 MCP 插件可连不等于已取得以上权利。先做官方法规版本库+签约商用案例源；若案例许可未完成，限定资料研究可售，但不能宣传完整类案库。

建议把质量要求增加为以下可验证条件：

  1. 正确拒绝和范围覆盖：每个任务显示实际读取材料、失败页、未取附件、法规范围、检索停止条件；覆盖不足不能显示完整审查通过。
  2. 事实与推论分开：材料记载、当事人主张、模型推论、律师采纳分状态；源文页码与输出结论一一可追溯。
  3. 引用支持度：来源存在不等于支持该命题；法条生效/失效与事实发生时间分别记录；判例层级、审级、是否改判、类案差异显示。
  4. 原生文书质量：Word/WPS 真修订与批注；接受全部后与批准内容一致；长表、节、页眉页脚、脚注、目录、交叉引用回归；不能只验截图好看。
  5. 签发的实际含义：内部批准/电子签名/盖章/送达分动作；设备签名本身不自动等于法律上可靠电子签名，更不自动证明签发人看过每页。
  6. 程序期限：送达事实与规则版本必须可审查；默认只产生待确认期限，二人确认后提醒；短信/IM 未送达不能当提醒已完成；支持升级通知和节假日/送达方式专项测试。
  7. 伦理墙全链路：检索召回、向量索引、缓存、共享链接、导出和客服都做事项权限；管理员不能只因为管账单就看到所有案卷。
  8. 真实效果：报告含盲测与实际工作时长，统计“修到可交付”的总时间，不只统计生成时间；所有拟定 95%/99% 阈值必须标为目标，不能当实测。

产品完整性并不要求第一版把所有民商事、刑事、跨境、尽调、会见、翻译同时卖作成熟能力。完整产品的含义是承诺范围内能开通、使用、协作、交付、收费、报障、退出，范围外有准确降级和承接路径。

6. 移动端与 IM：建议重新分配首发范围

IM 是触发、通知、收件渠道；不应承担完整权限控制中心。平台已经看见的消息与附件、文件名、下载凭证以及回调元数据均属数据流。普通事项可在管理员启用并完成平台条款评估后收件；高敏事项只收无内容通知。所有材料进隔离收件区，先验身份、文件安全与目标事项权限，再入库。

手机默认：看状态、收通知、补充澄清、审阅允许的摘要/文件；高影响动作必须显示最终对象与确切交付文件。审批不能仅是“同意 AI 继续”，还要包括预算变化、上云、对外提交、收件人改变等可理解信息。远程发起的任务不能扩张既有本地目录权限，IM 身份不能替代设备授权。

H5 可作为低风险移动入口；高敏解密与签发确需更多保护时提供 App，但 App 是成本和能力选择，不是端到端安全的证明。首发没有必要为了“所有能力不弱于标准版”同时造独立双端 App、三个 IM 集成和电脑遥控。先一个主流 IM+移动 Web 通知/轻审阅，复杂签发桌面完成；云工作区让电脑离线时任务照常执行；本地工作区明确等待本地执行器。

7. 经济模型与商业裁决

v5/v6/v7 有可复算脚本优于纯拍脑袋，但精确算出的五年结果只是输入假设的投影，不能把某年盈利或某金额资金峰值当可承诺结论。本轮不复用其精确增长、亏损与现金谷底。
