# 调研 B：办公 Agent 云地边界独立核验与法律 SaaS 设计裁决

核验日期：2026-10-09（Asia/Shanghai）。研究对象：v6 的 R1/R2、v7 的 S2 及其衍生结论。所有以下外部链接均在本日访问；无明确发布日期的页面不推定其发布日期。通过官方网页与文档直接复核，部分网页正文使用 HTTP 抓取；没有登录竞品、没有执行其客户端、没有对闭源安全机制进行渗透验证。**官方宣称是产品文档事实，不等于独立安全认证。**

本轮原文核验记录存于 `evidence-B/`，`manifest.json` 记录 URL、HTTP 结果与抓取响应哈希。已将本次可直接访问的 16 页落盘。哈希为抓取响应解压后内容的哈希，正文快照去除了 HTML 脚本/样式；因此不应将快照文件哈希与响应哈希混用。部分 Anthropic 页面只能经网页读取工具访问，未伪造落盘快照。

## 1. 对最终方案最重要的判断

1. **执行地点、数据持久化、模型推理地点、访问权限是四个不同的轴。** 本机读文件、本机 Python、云模型推理、本机保存结果完全可以同时存在。不能用“本地 Agent”推出“文件内容不出设备”，也不能用“云端 Agent”推出“全盘可读”或“必定访问内网”。
2. **手机遥控不是云端托管。** WorkBuddy 助理和 Kimi Work 本地任务都依赖电脑在线；千问桌面/网页有两套定时任务。产品必须显示真实执行节点、最后在线时间、断线状态、错过触发与补跑规则。
3. **SaaS 是交付/订阅方式，不决定所有工具在哪里执行。** API token 采购既不附送 Kimi Work 产品后端，也不妨碍中软自建合规云端 Agent Runtime。需要独立建设两种执行器、凭据代理、审计、存储、授权与任务调度，而不是把产品品牌或 API 账单当成这些能力的来源。
4. **有云管理端不代表管理员应可读全部案卷和全部对话。** 律所案级权限、利益冲突隔离、系统管理员与业务阅卷权应分离。企业治理参照竞品机制，不能照搬其“所有会话集中回放”作为所有律所的默认值。
5. **“全部权限”不适合成为法律版的常用能力档。** 应提供可审计的有限授权模板，在案件工作副本内自动产出；覆盖原件、跨案访问、对外发送、签署/递交、付款和系统配置各自独立授权。用户的一次开关不能替代每一项权限和业务责任。
6. **“本地原件优先 + 显式云托管 + 同一权限语义”可以成立；“所有法律 AI 都在云端”或“必须全部本地”都没有证据。** 数据策略选择不应偷偷改变执行节点，也不能因节点离线自动把案卷移往云端。

以上为本研究的架构判断，不是对任一竞品现有能力的断言。

**对 v7 的重要补正：** Q3 明确存在数据共享/隐私模式说明，并称企业账号由管理员管理。因此“未发现任何不训练承诺”不能被扩写为“千问没有隐私承诺”。但 Q2 仅适用 Web/钉内并列有产品体验改进目的，Q3 为桌面设置，两者范围不同；也不能反过来把 Q3 的承诺推给所有平台。采购时应要求将所有实际使用路径统一纳入 DPA 和模型供应链条款。

**Hook 不能替代强制策略：** [Q9 桌面 Hooks](https://docs.qwenwork.cn/desktop/hooks.md)明确规定 HTTP 非 2xx、连接失败/超时记录错误后继续原流程；有效拒绝响应与基础工具权限仍可阻止动作。因此准确表述是“Hook 服务异常时不产生额外拒绝”，不是“所有操作一定被放行”。法律版的案级 ACL、外发 DLP、最终提交必须在不可绕过的执行网关校验；高风险校验服务失败须拒绝执行。PostToolUse 检查已经太迟，不能撤销发信或文件覆盖。

**应借鉴：** 云地调度明确告知、独立执行记录、电脑操控单独授权。**不可照搬：** 桌面/云会话的割裂；安全工作环境文案被误解成云模型无需上传上下文；Hook 故障放过作为法律权限最后一道防线。

[K1 Kimi Work FAQ](https://www.kimi.com/help/kimi-work/kimi-work-faq)，[K2 发布日志](https://www.kimi.com/help/kimi-work/release-notes)，[K3 插件中心](https://www.kimi.com/help/kimi-work/plugin-center)。K2 本次最新版本条目仍为 3.2.15 / 2026-09-30；文档站统一更新时间不能当作这个版本的发布日期。

## 3. 海外及法律产品：有用的是明确的数据和身份边界

### 3.1 Claude Cowork

本日[官方架构页](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview)确实写明云端默认执行；既有桌面部署仍有本地执行，Pro/Max 例外按 2026-10-06 前已在设备发起的任务界定。故 v7 引用并非未来日期错误，但不能倒填到 10-02 的历史结论。

其云会话在独立临时沙箱执行；通过在线 Desktop、已连接目录及逐工具权限接触本机；读到的本机文件会在服务器处理。连接器凭据由服务端使用，不进入沙箱。组织可独立关云会话、限制网络与持久授权。既有本地模式把 Agent 循环和 VM 代码执行分开；VM 不可用时代码能力失败，不代表所有文件工具停摆。这里的商业数据承诺明确引用 Team/Enterprise，不能顺带推广成 Pro/Max 的同等合同承诺。

**对我们的含义：** 云任务调用本地受控工具是可行架构，但需要显式数据出境/出设备说明与双侧授权；本地 VM 只覆盖代码执行，不自动覆盖宿主文件工具、MCP 和浏览器。上游闭源实现没有自动成为我们的可复用组件。

### 3.2 Microsoft Copilot Studio（不等于所有 Microsoft 365 Copilot）

[官方 Computer Use 文档](https://learn.microsoft.com/en-us/microsoft-copilot-studio/computer-use)区分 maker 凭据与终端用户凭据；前者共享 Agent 时，用户可能取得创建者在目标机器上的能力。页面还明确，应用/网址 allowlist 约束操作，并不保证页面无法被打开。敏感检测的人工监督超时会停止该次运行，不能推导为每一次业务提交必定复核。

**对我们的含义：** 每个连接器必须写清“以谁的身份执行”，服务账号要有案件用途限制和用户交集授权；App/URL 白名单不等于防火墙。终端安全、网络出口和 Agent 审批必须分层落实。

### 3.3 Harvey

[Harvey 安全页](https://www.harvey.ai/security)可确认云服务、权限治理、可配置保留、合同化不训练以及模型供应商 ZDR 的基本承诺。不能因此断言所有能力和所有子处理者都零留存。

本轮新发现：[Service Terms](https://www.harvey.ai/legal/service-terms)更新于 **2026-09-16**，对 Covered AI Services 单列例外：供应商可为提供服务、安全审查及法定义务保留/审查内容，处理区域也可能不同；管理员可配置这些可选能力。部分功能不适用工作区保留设置，网络检索等也有独立子处理者与区域说明。

**对我们的含义：** 要做按能力、模型、供应商的治理目录，界面显示政策例外；不能只签一个笼统“无训练/本地/境内”条款覆盖所有插件。ZDR 是指定上游的处理约定，不是 SaaS 不存对话，也不是密码学上的服务商不可见。

### 3.4 LegalOn 与智合 AI

[LegalOn 官方产品介绍](https://us-direct.legalontech.com/what-is-legalon)对合同数据不用于其模型训练有公开说明；[其服务条款与 DPA](https://www.legalontech.com/terms-and-conditions)描述逻辑隔离、访问控制、备份及加密等。未核到通用本地 Shell Agent、与云端执行切换相关的完整公开权限矩阵；不得以 Word 插件的存在推定推理或存储在本机，也不得把不同法域版本的合同混用。

[智合 AI 官方界面](https://www.zhiexa.com/guidFile)为动态页面，本轮无法从公开正文取得完整权限/架构文件；[智合官网](https://zhihe.com/)仅足以确认产品背景。**本轮不把其部署方式、原件存储、模型留存、本地文件访问、无人值守、沙箱和写入审批当成已知。** 应通过正式技术问卷/演示按证据补全，不能依据行业印象声称“全部云端”。App Store 开发者隐私自述也不能替代服务端数据处理合同。

## 4. v6/v7 必须修正或收窄的判断

| 既有表述/推断 | 独立复核裁决 | 最终方案写法 |
|---|---|---|
| 本地 Agent/数据本地执行 ⇒ 内容不上传 | 不成立 | 分别列原件、提取文本、截图、提示词、工具结果、向量、日志、产物 |
| 千问 AI 日志 90 天 ⇒ 留存 90 天 | 不成立，原文是可查询窗口 | 实际存储/备份保留期限待合同确认 |
| 千问没有数据不用于改进的承诺 | 不完整 | 桌面设置有明确说明，Web/钉内政策范围另论 |
| 千问 Windows VM 服务 ⇒ 已确定具体虚拟机技术/安装条件 | 证据不足 | 仅确认文档有 VM 服务线索，兼容性另测 |
| 千问 Hook 超时 ⇒ 所有动作必然放行 | 过强 | Hook 故障不产生拒绝，基础权限仍在；不能用其充当强制安全边界 |
| WorkBuddy Windows 更像应用层确认 ⇒ 没有任何 OS 隔离 | 不能从未公开推出不存在 | 实现未知，不能据此评判其真实隔离强度 |
| WebSocket 通道 ⇒ 不存在厂商中继 | 不成立 | 无入站端口与中继拓扑、内容可见性是不同问题 |

## 5. 法律 SaaS 应采用的权限模型（设计建议）

### 5.1 以动作和数据边界授权，而非以“云/本地”授权

建议每次工具执行至少计算以下交集：`律所策略 ∩ 案件权限 ∩ 用户权限 ∩ 数据源权限 ∩ 设备权限 ∩ 工具权限 ∩ 本次授权 ∩ 运行时可用性`。任意明确拒绝优先。云与本地执行器调用同一政策语义，但各自独立校验，不能只信另一端发来的 `approved=true`。

授权分成以下维度，界面可合并呈现，底层不能混成一个开关：

- 能看什么：指定案件、目录、文件、数据库记录；冲突案件排除。
- 能把什么送给谁：本地提取内容→中软网关→Kimi 模型；搜索查询→搜索商；截图→视觉模型；分别检查。
- 能改什么：工作副本产物、原件覆盖、批量移动/删除、系统配置。
- 以谁身份：当前律师的委托身份、案组服务账号、受管设备账号；不得默认为平台万能账号。
- 何时能做：人在场/定时/遥控；授权有效期、次数、额度、指定执行节点。
- 能否对外生效：发信/分享/发布/法院递交/电子签署/付款独立分级。

### 5.2 一个推荐默认值，不制造未经证实的“绝对本地”承诺

| 操作 | 默认执行与数据策略 | 人工确认/可自动化条件 |
|---|---|---|
| 原件导入、OCR、哈希与目录整理 | 原件本地；受控本地解析；必须发送远端 OCR 时另示数据去向 | 预授权案件目录内可自动；不得自动扫描整盘 |
| 起草、审阅、证据摘要 | 本地读取必要片段，经过网关调用合同允许的模型 | 首次建立明确的数据处理授权，按案/用途限界；后续低风险步骤无需重复弹窗 |
| 沙箱代码分析 | 受控任务工作副本；本地沙箱或显式云沙箱 | 已验证隔离且网络受限可自动执行；无沙箱则受控失败，不静默改裸机 |
| 云批量尽调/长任务 | 用户显式托管的材料、租户与案件隔离；短期任务目录 | 显示处理区域、期限、资源预算和第三方；未授权文件不得后台补传 |
| 案件知识检索 | 先 ACL 过滤再检索，取回后再次确认访问范围 | 权限降级与撤销必须影响索引/缓存和在途任务 |
| 本机 Word/浏览器交互 | 限指定文档/标签/应用，单独凭据与设备授权 | 涉外发送/最终提交强制确认；桌面和浏览器可被网页提示注入视为威胁输入 |
| 定时法规更新 | 云端公开信息任务；不需案卷即可运行 | 可无人值守，变更推送按预授权渠道；不把案情全文用作搜索关键词 |
| 遥控本机 | 受信设备在线、身份新鲜、授权未撤销 | 离线排队有期限；不自动迁云、不隐式唤醒全盘能力 |
| 外发合同/递交材料 | 先生成可审阅的收件人、附件、内容摘要与版本快照 | 批准绑定内容哈希、接收方、操作、案号、有效期，内容变动重审 |

所有默认值是建议，需产品/技术团队依据能力实现后验收；不是对当前 demo 已具备能力的描述。

### 5.3 工程上必须分清的六个细节

1. **批准不能被重放。** 票据绑定租户、用户、案件、工具、规范化参数、文件版本、目标节点和到期时间；云本地都核验。
2. **执行副作用不能盲重试。** 定时/断线恢复用幂等键；发信、签署、上传等结果不确定时进入人工核对，不简单重放。
3. **审批服务故障不是授权。** 执行前闸门故障时高风险动作停止；只读、公开信息等低风险能力可按明确定义降级。
4. **撤销有传播 SLA。** 停用用户、撤案权限、断开连接器、失窃设备必须终止后续工具调用、撤短期令牌、处理队列；在途已发送数据无法靠 UI 撤销收回。
5. **日志也是案卷。** 默认留动作元数据；正文/截图诊断按需、脱敏、短保留、客户可见；严禁写入 API Key/Cookie/签名密钥。运维排障走临时授权、双人审批和记录。
6. **隔离要按工具验收。** VM 对 shell 的隔离不能自动证明文件 broker、MCP、浏览器、OCR、预览器隔离。宏、外链、压缩炸弹、路径穿越、符号链接、网络共享和文档提示注入需单独测试。
