# 05 合规、运营与商业闭环

本文将法律要求转成产品门禁，供中软法务、外部中国法律顾问和试点律所对实际运营主体、合同和数据流签字。没有核验到的条文不当作强制法；设计目标不当作已取得认证。

## 1. 六项不能混同的权利

| 项目 | 本轮状态 | 产品动作 |
|---|---|---|
| 标识与设计授权 | 用户明确已获授权，接受此前提 | 归档实际范围、期限和可交付资产，不重复索取同一确认 |
| Kimi Code开源许可 | 官方仓库及根MIT核验 | 保留许可；审计依赖、外部二进制与修改分发义务 |
| 模型API调用 | 用户确认采购token | 明确采购账户/区域/价格/限额/售后，不给终端客户分发上游密钥 |
| Work会员/闭源后端权益 | 未提供相关合同 | 搜索、数据源、PPT、浏览器桥、遥控逐项买或自建 |
| 客户材料处理权 | 因事项与主体不同 | 记录委托、保密约定、个人信息依据、用途/接收者及特别限制 |
| 法律数据源权利 | 需企业合同及许可附件 | 检索/模型输入/展示/导出/缓存/评测逐项授权 |

Kimi开放平台协议第3.1款同时规定API许可限制及向最终用户提供服务的用途，不能仅凭“不可再许可”断言应用SaaS被禁止；裸转卖API密钥与中软运营有增值功能的应用不同。真正需要谈妥的是具体渠道/能力、责任分配及第6.3款模型服务优化用途限制。[现行开放平台服务协议](https://platform.kimi.com/docs/agreement/modeluse)（2026-08-31生效）。这是条文解释与谈判建议，最终以企业补充协议和专项法律意见为准。

## 2. 专业保密与个人信息处理

本轮官方资料确认律师法2026年修订已公布；保密与利冲要求应使用现行版本，不能机械沿用旧稿条号，也不能使用demo种子法规。[最高法转载主席令](https://www.court.gov.cn/xinshidai/xiangqing/510011.html)、[北京司法局现行文本](https://sfj.beijing.gov.cn/sfj/zwgk/2024zcwj/744120751/fl91/744123073/index.html)。上线法源入库应由法律编辑对照正式公报、施行与过渡规定签字。

客户同意AI辅助不自动代表对方、员工、证人、未成年人等信息主体全部同意；委托保密许可也不自动满足个人信息处理依据。产品分别记录 `professional_authorization`、`personal_data_basis`、`sensitive_data_conditions`、`processor_scope`，并保留“范围不足/待律师确认”。不让一个“无需同意”按钮放开全部外发。[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。

C/L只是技术与合同预设，不是法定密级。标准产品不处理国家秘密及依法不得进入该服务的数据；不确定是否可处理时停在本地受控识别与人工判定。刑事材料不一律等于国家秘密，商业材料也不一律可上云；私有化不是解除法定义务的万能条件。

## 3. 各方角色与数据条款

角色依据实际目的和决定权按处理活动认定，不能笼统说中软永远只是受托人。律所决定案件用途；中软为该用途提供存储/推理/同步通常设计为受托处理；中软自主决定账号计费、防欺诈、法定义务等目的时另行认定。上游模型、搜索、OCR、云基础设施等纳入转委托/第三方目录与相应授权流程。密文仍可能为可识别数据，不能用“我们没钥匙”排除所有处理责任。[网络数据安全管理条例](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm)。

DPA附件至少包含：

1. 每一端点/功能的处理目的、数据类别、区域、接收方及角色；模型、缓存、批量、搜索、抓取、图像、文件、托管Agent分别列明。
2. 不用于训练或服务优化的约束及例外；安全审查是否留存、人工可见范围、分包变更通知；不能用“ZDR”三个字替代具体条款。
3. 在线正文、临时文件、错误日志、缓存、备份与外部供应商的保留/删除；法律保全、恢复和终止导出流程。
4. 访问控制、加密、密钥归属、支持访问、审计证据和事件通知时限；C明确服务端可解密，L明确获准推理请求会过境。
5. 个人信息权利请求、纠错删除、处理者协助、跨境条件、责任和赔付。上游责任上限与我方对律所承诺需匹配，不能把不匹配风险藏在无限SLA中。

统一供应商不代表所有端点统一DPA；相同API密钥不代表相同留存。若某工具无法满足L政策，就关闭该工具在L中的使用，或采用合规替代，不宣称整个平台都无留存。

## 4. 监管、标准与地域

| 项目 | v8处置 | 上线证据 |
|---|---|---|
| 生成式AI服务/应用登记、算法备案、安全评估 | 按运营主体、面向对象和实际功能确认适用；不因B2B自动豁免 | 属地沟通/办理结论、所用模型和应用公示信息 |
| AI内容标识 | 对下载/导出/分享路径落实适用显式与隐式标识；正文美观需求不能绕过义务 | 文书引擎标识测试、用户协议和告知、例外流程法律核查 |
| 等级保护 | 定级边界和等级由正式程序确定；可按三级控制目标设计 | 定级/备案/测评及整改凭证，不写成已过等保 |
| 商用密码/密评 | 按适用业务与系统认定；国际算法或国密名称不是认证 | 合规判断、算法组件与评估材料 |
| 桌面/移动分发 | 签名、隐私合规、备案/商店要求按形态办理 | 发布资料、权限检测与更新证据 |
| 网络日志 | 依法保留必要安全日志，正文最小化 | 字段/目的/期限矩阵；不把所有案卷永久归作安全日志 |
| 数据出境 | 境内默认；海外运维访问、跨境供应商/推送/诊断都纳入判断 | 实际数据流、影响评估及适用出境手续 |
| 律协指南 | 参考适用地域、业务、效力与有效期；不作全国强制法 | 原文及版本，未取得官方原文标“待核” |

## 5. 法源与内容采购

建立Source Registry，每个版本记载权利人、地域、覆盖、时效、可用接口、抓取/索引/向量化、送第三方模型、展示全文/摘要、导出、团队共享、缓存TTL、终止留存、评测/训练许可、删除义务、价格与QPS。许可证到期自动停止相应读取与新增处理；已签发成果是否可继续保留依据合同，不能一刀删掉律所合法档案。

首发官方法律文本可做高频范围版本库，采集和再利用仍核查来源条款及内容性质；官方网页可查并不意味着所有数据库编排、判例批注、检索接口均可商业复制。案例库至少一家正式许可后再承诺对应覆盖。[著作权法官方文本](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)。

供应商候选不等于采购确定；逐家比较许可、召回、稳定性、商业价格与离线策略。法源断供时显示覆盖下降，不悄悄改用搜索摘要拼接“原判决”。

## 6. 账号订阅与单位经济

推荐售卖“账号基础订阅 + 明确包含的用量/存储 + 可选增购”，个人可直接买，组织按生产/审阅/管理员角色配置。基础保密、权限、原件保护、来源与完整导出不作为高价版独占安全功能。

| 套餐方向 | 包含 | 不应误导的边界 |
|---|---|---|
| 个人专业 | 桌面、已验收工作流、本地事项、明确模型额度 | 不默认取得律师所在律所材料的独立授权 |
| 团队协作 | 组织空间、C协作、L治理、复核、计量、基础管理 | 一生产账号可起，不强制三席；多人共享登录不可审计 |
| 律所治理 | SSO/SCIM、审计接口、支持和可选runner部署 | 平台服务费对应实际实施/运维，不只是解锁权限 |
| 专有/私有 | 单独部署、更新、法源与模型运维合同 | 单独报价及验收，不和标准订阅混算毛利 |

3600/9800元年价仍可作为旧稿价格实验，未验证前不是最终价。与Kimi标准版差价应由法律内容、原生修订、可复核成果、协作治理和服务证明；不必为“功能不少一项”的口号承担所有通用能力成本。

附带 `07-经济压力测算.py`、`inputs.json`、`results.json` 与摘要。模型价格按本轮[开放平台公开价](https://platform.kimi.com/)记录，采购折扣另列。所有用量、成交率、支持成本与人周均为规划假设。测算不把“更多使用必然带来加量包收入”设为前提；超额必须用户预先购买/允许，自动续费规则独立清晰展示。

成本至少包括模型输入/输出/缓存、子Agent和重试、搜索/法源、云计算、存储/备份/带宽、解析、支付税费、客户成功、Windows兼容支持、法律内容维护。技术指标中必须同时看任务总成本、最终被律师采用的成果成本与账号月毛利，不能仅算每次token。

点数是透明计费显示，不与供应商token混用。报价显示方法估算区间与最大预算；失败/取消可能有已发生上游成本，用户条款清楚规定退款/减免及平台故障承担方式。计费版本随订单锁定，权益变更按合同告知。

## 7. 运营与退出完整闭环

| 场景 | 标准流程 |
|---|---|
| 上线开通 | 验证组织与管理员、最小权限、设备诊断、示例任务、保留/数据模式选择、培训 |
| 入离职 | 组织与事项角色分别管理；撤设备、连接器、任务令牌；原案组成果归属不随个人注销消失 |
| 账户欠费/退订 | 停新增计费任务；提供合同约定的只读/导出窗口；不扣留客户已有成果 |
| 用户纠错/删除 | 核验请求权、关联事项与保全；删除派生索引/缓存/副本，记录备份到期和残留限制 |
| 数据导出 | 原始文件、可编辑成果、JSON/CSV账本、出处清单、manifest与签发证据；L在客户侧解密导出 |
| 故障 | 状态页、故障等级、回退/暂停、通知客户、影响清单、恢复与复盘 |
| 安全事件 | 立即阻断受影响能力/令牌；保全证据、按适用法律合同通知、协助律所评估、复发控制 |
| 法律内容错误 | 定位规则/模型版本、停用相关模板、通知受影响事项负责人、补充人工复核；不静默重写已签发件 |
| 供应商故障 | 显式排队/失败；仅切已授权且评测合格的替代路径；不因SLA私自扩大接收方 |
| 支持排障 | 默认元数据；需正文时按客户临时授权、限制范围/期限，记录访问；禁止生产案卷复制到研发个人电脑 |

SLO分对象设定：控制面/网关月可用性99.9%为候选目标；本地设备离线不计为云故障，但要在用户状态中明确。通知成功率分“已入队/供应商接收/设备到达/用户确认”，不能把网关200响应当及时送达。灾备RPO/RTO和正式赔付以实际恢复演练制定，第06篇给初始验收目标。

## 8. 对外表述建议

可以说：“支持本地保密事项和经授权的境内云协作事项；每次模型、检索和外部工具调用遵守事项政策；输出可编辑文件，关键依据和人工复核可追踪。”

不能无范围说“数据不出律所”“云端完全看不到”“永久零留存”“即时撤回所有副本”“所有Kimi Work能力原样具备”“引用100%正确”“通过等保”“法律效力等同律师签章”。销售材料由产品、法务与安全对照实际验收清单发布。
