# Kimi Work 法律行业发行版：独立终审与可实施产品方案 v8

评审日期：2026-10-09（北京时间）。性质：产品与研发决策建议，尚非已批准基线或生产验收证明。

## 1. 最终建议

**建设“中软运营的云地协同法律 SaaS”：共用一套法律业务模型、Kimi Code 运行时适配和质量标准，按事项授权选择境内云端执行或本地执行。桌面挂载不等于上传，模型推理不等于 Agent 执行，自动执行不等于自动签发。**

不要继续在“云端只有 token”和“所有案卷必须上云”之间摆动。API token 是采购项目，不能推出整个产品的部署位置；SaaS 是交付与运营模式，也不要求所有代码都在云端。真正决定位置的是：数据许可、客户要求、本机资源、常在线需求、隔离能力、协作与总成本。

建议以**标准协作事项 C + 本地保密事项 L**作为两个面向律师的产品预设。C 支持已授权材料的境内托管、云任务、多人协作、手机审阅与关机续跑；L 默认原件与派生正文留在获准设备，可选密文同步，模型请求仍须逐端点授权。完全禁止数据出域的客户采用另行验收的私有部署 P，不能把 L 加一个私有模型地址就叫完整私有化。

这是一项相对 v5/v6 的明确产品取舍：**允许在合同、政策与技术控制到位后托管客户材料，不把“中软绝不持有内容”作为全产品不可更改的前提。** 如果管理层选择绝不托管，L 可以独立售卖，但无获准常在线执行器时，关机后的内容任务必须排队，不能同时承诺云端续跑、全功能移动处理和云端完全无法解密。

## 2. 本轮确认的前提与边界

- 用户已明确取得 Kimi Work 法律行业发行版标识授权，允许借用设计、布局、配色、版式及部分能力。本方案接受该事实，不要求重复取得同一授权。
- 当前已知采购为 Kimi API token。搜索、文件服务、Hosted Agents、Work 会员数据源、浏览器组件和企业数据条款各自确认，不从 token 或标识授权推定。
- 用户补充确认：以内地律师为主、类似 Kimi Work 的桌面客户端、账号订阅制。桌面是主入口，Web是辅助管理与协作；个人可以购买，不强制三席起。中文民商事和合同业务为首发范围建议。香港上市身份不等于必须处理香港法，也不等于所有数据天然出境。
- 本轮任务是独立评审与形成方案。没有改造 demo、上线服务、修改 MaaS 配置或联系供应商。
- v5/v6 中关于以往“用户拍板”的转述作为历史背景，不替代本轮用户直接给出的要求。本文的云托管建议仍是待管理层决定的方案，不是已获得执行授权的部署。

## 3. 哪些应保留，哪些必须改

| 对象 | 保留 | 改变 |
|---|---|---|
| Astra 系 | 事项边界、执行与成果分离、引用四态、Run/Attempt、fencing、幂等、审批绑定版本、独立盲测 | 不把统一云端编排当唯一正确形态；不依赖未核实的 Work 私有 Runtime 合同 |

| v5 | 本机材料处理、出站检查、离线工具、版本与签发记录 | 删除“采购 token 所以云端只能供 token”的推论；不把节点运维转嫁所有律所；恢复安全的通用 Agent 能力 |
| v6 | 云端身份/策略/计量、控制与内容分离、可选执行器、关机提醒 | 纠正删除与撤权承诺、手机补签放行、72 小时权限缓存、过境零留存、密文中继万能化 |

**不再使用“本稿目标全 5 分”的评分法。** 设计目标不能与旧方案缺陷按同一标尺比较，真实效果要由同一任务集、同一范围的质量、耗时、成本和故障结果决定。

## 4. 影响立项的五个发现

1. **当前工程是 G0 原型。** 内置文件/Shell/子代理等多项能力被禁，Skills 与提问链路也有缺口；不能称已完整接入 Kimi Code。独立源码审计与合成探针还发现路径隔离缺陷。详见调研 A。
2. **Kimi Code 的开源能力不等于 Kimi Work 服务权益。** 默认搜索、数据源、遥控和外部浏览器组件存在独立依赖。通用能力要接通、替换或标注受限，不能靠关工具宣称完整，也不能直接带着会员凭据上生产。
3. **本地执行仍可能发送大量案情。** 模型上下文、压缩摘要、子代理消息、搜索词、截图、工具结果和诊断信息都应进入数据流清单。只检查第一次 prompt 不够。
4. **安全承诺必须按路径限定。** C 模式云端会解密处理；L 模式密文中继不解密，但模型网关能看获准请求；删除旧密钥不能追回已导出的明文或离线备份；设备签名不自动成为可靠电子签名或司法存证。
5. **商业不能靠固定席位无限调用。** 模型、检索、沙箱、人工支持、文档保真和法源维护共同决定成本。本包提供透明的压力测算，不沿用旧稿精确到万元的多年盈利预测。

## 5. 完整接入与首发承诺

“完整接入”定义为：锁定 Kimi Code 版本，对其能力族逐项登记原生接入、适配替代、政策限制、待实现；验证规划、流式事件、提问、审批、文件工具、沙箱计算、Skills、MCP、子代理、长任务、取消恢复、用量与搜索路径。**不等于让每个用户在每个渠道使用所有权限。**

首发推荐三条完整业务链：合同审查与回稿；民商事材料整理与受限文书；获许可范围的法律研究与顾问答复。以原生 Word/Excel、来源、复核、签发、归档、账单和支持闭环定义完整，不要求第一天把全部 36 个演示入口做成生产能力。

Windows 桌面、Web 协作与管理、可编辑文件交付是主线；首家 Office 深度插件与 IM 由试点环境决定。任意桌面操控、法院提交、独立原生手机 App、所有平台同时上线不进入首发强制范围。未通过的能力保持不可售，不能藏在“自动模式”里绕过。

## 1. 方法与材料

评审对象包括 v5/v6 的结论、裁决、云地权限、产品、技术、场景交付件、内容、合规、商业和对抗审阅；追溯 Astra 09-22 与 09-30、Opus 09-23 与 09-28 原文，并交叉参考已有 v7。由三条独立研究分别核验运行时源码、办公 Agent 官方说明、法律/产品/商业。报告按命题评审，不按模型品牌选赢家。

## 3. 对 Astra 的独立评价

最强部分是**把错误后果写成系统语义**。例如执行成功不等于律师批准；过期worker不只不得提交，还不得继续收费或读材料；来源存在不等于支持结论；审批不能跨文件版本。这些直接减少真实法律工作中的事故，应成为新架构共同内核。

云端统一编排也有成立的工程理由：集中撤权、多人协作、后台队列、移动处理、恢复与统一版本更容易运维。原稿把它用于允许境内托管的客户，并非天然错误。真正需要修正的是默认用户已经允许上传、弱化桌面本地资源，以及早期依赖未确认的上游 Work 平台接口。

不接受旧稿对 Astra 的简化描述：“它只会做网页，因此不适合律师”。09-22 原文已经提出本机Office桥、原生修订和适配器边界。评价应基于实际条文，不沿用上一轮方案对竞争稿的概括。

## 4. 对 Opus 的独立评价

最强部分是**把通用 Agent 转为可购买的律师工作服务**：角色、场景、交付件、规则生产、模板、Word/WPS、IM、试点、席位和内容运营之间有完整联系。应保留“原文—问题—建议—依据—处置”的审阅体验，以及从回稿回流到重新签发的闭环。

主要问题是“设计详尽”有时遮盖了证据不足：开通十分钟、各种平台五分钟接通、私有化只改配置、同用户进程安全、恢复卡无法合谋、固定日期可公开销售，都是需要实测或限定前提的目标。v5→v6→v7不断增加机制又沿用原排期，也说明架构尚未收敛。

不否定本地优势：文件夹挂载、Office宿主、低延迟比对、离线审阅及保密客户的材料控制很有价值。但无需因此牺牲所有云后台能力；反过来，也不应把端到端加密和复杂密钥仪式强加给只要求境内受托托管的小团队。

## 5. v5 与 v6 的真实效果比较

| 用户情形 | v5 | v6 | v8 |
|---|---|---|---|
| 单人本机处理保密合同 | 原件路径短、离线便利 | 基本相同但控制面/密钥更复杂 | L沿用本机路径，去掉非必要开通仪式 |
| 三人团队无IT | 同步、节点、IM负担大 | 密文同步改善；恢复与手机仍复杂 | C托管协作为推荐商业路径；L保密同步是有边界选项 |
| 晚上关机处理案卷 | 要节点 | 无执行器仍不能处理客户内容 | C已上传快照可云端跑；L无执行器明确等待 |
| 合伙人手机审阅 | 节点/IM文件见证 | H5解密、补签与撤回窗口有矛盾 | C在受管Web看确切成果、再认证批准；L未验收移动解密则只提醒 |
| Agent计算流水与复杂交付 | 工具关闭，能力较弱 | WASM补部分计算 | 通过沙箱验收后提供Shell/Python/Node及文件工具 |
| 极敏感且禁止外发 | 云token仍不符合 | 化名推理仍不符合 | 无模型离线工具，或完整P部署；不自动改低保密等级 |
| 大规模多机构运营 | 终端支持与规则版本碎片化 | 云控制改善，端侧同步面仍大 | 共同协议、独立部署适配、集中服务权益与安全基线 |

## 6. 关于“完美”和“完整”

不可能同时得到无限自主、零外发、关机续跑、全功能移动、无需任何服务器、供应商无法解密和最低研发成本。必须把矛盾公开。

本方案追求的完整是：**在明确售卖范围内，用户能完成从材料到成果的工作，遇到失败有恢复，权限有硬边界，合同有依据，费用可解释，问题有人负责，退出能拿走数据。** 不以无限场景、无限权限或绝对安全作为完整性的定义。

## 7. v7 专项复核：进步很大，但不能直接按摘要开工

v7正文已经吸收过一轮对抗审阅，不能只读摘要批评它尚未修复的旧问题。本轮认可以下增量：宿主策略优先于上游默认批准；删除Fetch回退；遥控网关不直通kap-server；可信配置与案卷隔离；图像出站单独控制；保留管理员公钥固定与放宽签名；渲染产物禁外链；会话与历史快照纳入加密范围。这些应进入v8验收。

# 02 云地执行与权限规范

## 1. 第一性原理：先定义谁能处理什么，再选择位置

一个动作至少包含：人、所属组织、事项、输入对象及版本、处理目的、工具、执行环境、接收者、时间、预算、输出去向。只写“本地/云端”无法判定是否合法、可用或安全。

工程上拆开七个轴：

| 轴 | 选项或问题 | 不可混淆之处 |
|---|---|---|
| 原件与派生数据存储 | 本机、客户服务器、中软境内对象存储 | 静态加密不等于服务商无法解密 |
| Agent编排 | 本机、律所执行器、中软worker | 编排会接触上下文，不能当纯元数据服务 |
| 工具执行 | 本机OS沙箱、云沙箱、受管连接器 | 本机工具也可能联网，云工具也不能默认访问电脑 |
| 模型推理 | Kimi境内API、律所自有端点、禁用 | 本地Agent调用API仍然把输入送出设备 |
| 控制与运营 | 身份、政策、订阅、计费、调度、更新 | 可以在云且不保存全文，但仍处理身份与敏感元数据 |
| 人工权限 | 经办、复核、签发、管理、支持 | 购买席位和管理设备不授予所有案卷阅权 |
| 触发与副作用 | 桌面、IM、定时、远程；只读、写草稿、正式发布 | 手机遥控不等于云端执行，运行完毕不等于正式发出 |

推荐默认体验：账号登录桌面→选择或新建事项→材料默认本机导入→明确该事项是否启用托管协作和云执行。管理员可设C为本组织新建事项预设，但首次上传仍展示范围，不能因加入团队自动上传整盘材料。

## 2. 两个主预设与一个专有配置

| 属性 | L 本地保密事项 | C 标准协作事项 | P 专有部署（另行交付） |
|---|---|---|---|
| 主入口 | 桌面；Office桥 | 桌面；Web/移动补充 | 受管桌面/内网 |
| 正文权威存储 | 客户设备/获准所内存储 | 中软境内租户事项库 | 客户控制环境 |
| 云同步 | 关闭或可选E2EE密文同步 | 租户隔离、服务端静态加密 | 客户内网/私有存储 |
| 谁能解密存储 | 已授权设备和恢复主体 | 授权服务进程；运维受限但不能称技术上永不可见 | 依部署与密钥责任矩阵 |
| 内容执行 | 本机或逐事项授权的律所执行器 | 本机交互工具+获准云worker | 客户执行器 |
| 推理 | 可发送已获准最小输入至境内API，或禁用 | 获准境内API | 私有模型或明确允许的API |
| 关机内容续跑 | 仅已授权且在线的执行器；否则等待 | 已上传快照可续跑；若仍需本机文件则等待 | 看客户执行器可用性 |
| 手机预览 | 首发只通知/状态；正文解密客户端独立验收 | 受管Web预览和审阅 | 依客户接入条件 |
| 管理与计费 | 中软云 | 中软云 | 可私有控制面；许可另设计 |
| 适用 | 文件夹工作、本地敏感约定、客户拒绝云存储 | 小团队协作、跨设备、后台批量 | 严格内网/客户强制要求 |

L不是“绝不出域”：若允许Kimi API，模型网关仍会接触相应输入。C不是“上传所有案卷”：只处理列入授权快照的对象。P也不是允许涉密的通行证；未满足专门条件的涉密材料在所有标准形态拒收。

**单个事项只能有一个权威提交位置。** C以服务端版本登记为准，端侧是缓存/工作副本；L以签名事项账本和明确成员/版本协议为准，中继仅传密文。不能让云库与本机库同时自称同一版本的最终状态。

迁移L→C：负责人确认目标区域、数据清单、第三方、保留政策；创建迁移记录与新策略版本；暂停新写入、复制校验、切换权威位置、恢复任务。迁移C→L：导出、完整性核对、客户接管、关闭新云任务、按合同删除云副本与备份；不能因切开关就声称历史云副本不存在。

## 3. 目标结构

```text
桌面 Kimi Work 法律发行版（统一任务/事项/成果/审阅）
  ├─受信本机内核：事项权限、材料版本、Office桥、密钥、审批
  ├─Kimi Code Adapter → 本机任务沙箱（只读输入 / 可写草稿）
  └─数据与工具 Broker → 模型 / 检索 / 法源 / 获批连接器
                     ↓
中软境内服务
  ├─控制面：账号/机构/设备/订阅/政策/预算/通知/调度
  ├─C内容面：事项库/对象存储/索引/版本/审批/交付登记
  ├─L密文中继：可选；不授予内容执行钥匙
  ├─执行面：同一Adapter + 每任务云沙箱 + 受控工具
  └─模型网关 → MaaS法律分组 → Kimi企业API
可选律所执行器：出站领取授权任务，共用协议，逐事项授予数据权
```

云端提醒、身份和计量不进入任务沙箱。解析器、模型循环、可执行代码、浏览器、连接器、签发服务是不同信任边界，不能在一个高权限Node进程里把函数名当隔离。

## 4. 功能放置与数据流

| 功能 | 默认位置 | C变化 | L限制/说明 |
|---|---|---|---|
| 登录、账号订阅、团队席位 | 云控制面 | 相同 | 断网可本机解锁已有数据；不能离线新购/新增成员 |
| 文件夹选择/原件快照 | 本机 | 按明确清单上传 | 不扫描父目录；不能远程扩大挂载 |
| 安全解析/OCR | 本机隔离进程 | 已上传大批量可在云解析 | 外部OCR不作为自动回退 |
| 索引/向量/摘要 | 跟随内容权威位置 | 服务端按事项隔离 | 本机生成；外部embedding也是出站 |
| 合同确定性校验/比对 | 本机 | 可云执行同一组件 | 离线可做非模型步骤 |
| 开放任务Agent | 本机沙箱 | 显式指定云worker | OS隔离未达标则关闭不可信代码能力 |
| 法律模型推理 | 网关→Kimi API | 同上 | 减量/化名按任务适用，仍是数据处理 |
| 法源与案例服务 | 云工具broker | 同上 | 只发已允许查询；断网用已覆盖离线法规 |
| 方法包 | 签名版本注册表 | 云工作流按版本装配 | 获授权方法副本下发；不承诺不可提取 |
| Shell/Python/Node | 任务沙箱 | 云沙箱 | 预装库，无宿主HOME、无默认网络 |
| 公开浏览器 | 独立浏览器profile | 可云公开浏览器 | 本机站点操作受限，搜索/URL也泄露查询 |
| 登录态浏览器/桌面控制 | 本机专用broker、默认关 | 云端不继承桌面登录态 | 指定应用/站点/时间，不能打开整个浏览器配置 |
| Word/WPS写回 | 本机宿主 | 云回传patch，端侧复核版本 | 不把Office进程挂进Agent沙箱 |
| 审阅/签发 | 业务审批服务+人的会话 | 可受管Web确认 | 本机签名；离线正式发布须符合离线批准策略 |
| 期限提醒 | 云scheduler | 相同 | 只同步经确认的必要日期与路由；若禁元数据上云则本地提醒并说明限制 |
| 事项周报/批量 | 数据获准的执行器 | 云可24小时 | 无在线客户执行器则排队 |
| IM收件 | 独立入口服务 | 可持久收件后归档 | 先进入收件区；路径需平台支持，不保证所有平台直取 |
| 审计 | 操作元数据云；内容跟随事项 | 云内容审计按案ACL | 正文记录加密在客户侧；不默认管理员会话回放 |
| 更新/规则发布 | 云CDN+签名 | 相同 | 私有客户离线签名包另验 |

## 5. 权限计算与强制位置

有效权限是下列集合的交集，任何显式拒绝优先：

`产品硬基线 ∩ 机构政策 ∩ 人的角色/事项成员资格 ∩ 对象ACL ∩ 数据源许可 ∩ 事项数据策略 ∩ 执行器能力 ∩ 渠道权限 ∩ 本次授权 ∩ 预算/时间`

许可校验与法律处理依据检查是两个条件：有API权限并不代表有权把这份材料发给它。管理员批准的连接器也不能突破客户的禁止条款。

| 强制点 | 必须校验 | 失败行为 |
|---|---|---|
| 任务受理 | 发起人、事项、输入版本、数据政策、处理依据、执行位置 | 拒绝或要求补齐，禁止先处理后补单 |
| 对象读取/检索 | tenant、matter、对象版本、当前成员/伦理墙、数据源权利 | 不泄露标题/命中数，不只过滤最终答案 |
| 每次工具调用 | schema、参数、动作、运行身份、委托链、范围、有效期 | 不能由上游approve跳过 |
| 出站broker | 接收者/区域/用途、内容类别、budget、图像/附件、重定向 | 校验不可用则停止相关出站 |
| OS执行边界 | 实际文件、进程、网络、IPC、资源 | 不可隔离则不运行不可信代码 |
| 产物promotion/发布 | 文件类型与外链、引用门禁、基线、审批、受众、最终hash | Agent只能写草稿，不能直接写交付目录 |

任务能力令牌为短期、限定audience的凭证，示意字段：

```json
{
  "tenant_id":"t1", "principal_id":"u1", "matter_id":"m1",
  "run_id":"r1", "attempt_id":"a2", "fence":17,
  "executor_id":"device-or-worker", "channel":"desktop",
  "policy_version":31, "membership_epoch":8,
  "input_manifest_hash":"...", "tools":["file.read","draft.write"],
  "destinations":["approved-model-gateway"],
  "budget_reservation_id":"b1", "expires_at":"...", "aud":"tool-broker"
}
```

初始建议令牌有效期5分钟、可续租；高风险操作即时检查撤权与授权版本。这个时间是待SLO验证的产品参数，**不能靠短TTL承诺离线即时撤权**。禁止客户端自报tenant切换租户；不要向沙箱发上游API主钥匙、数据库账号或S3通用凭据。

## 6. 用户运行模式与批准

界面三档足够：**只读分析、标准执行、自动草稿**；“先出计划”为独立开关。手动逐步确认可放高级设置用于敏感调试，不作为沙箱不足时的安全补偿。

| 动作 | 只读分析 | 标准执行 | 自动草稿 |
|---|---|---|---|
| 已授权事项内读取/分析 | 自动 | 自动 | 自动 |
| 沙箱新草稿/表格/计算 | 不运行或改为标准 | 自动 | 自动 |
| 已批准来源的普通查询 | 按事项用途/预算 | 自动 | 自动 |
| 原计划以外的研究步骤/子任务 | 不自主扩展 | 实质改变计划时确认 | 同目的、同材料与工具、同预算内可重规划；仍不得扩大数据权限 |
| 新目的地、实名查询、原图发送 | 新授权 | 新授权 | 新授权 |
| 扩材料/跨事项/扩大费用 | 单独授权 | 单独授权 | 单独授权 |
| 覆盖原件/正式稿 | 人工文件操作 | 人工文件操作 | 人工文件操作 |
| 签发/发函/递交/付款/权限修改 | 人工业务操作 | 人工业务操作 | 人工业务操作 |

许可可在任务创建时一次批准明确定义的范围，例如“本事项20份合同、指定Kimi端点、授权法源、上限50元、只产草稿”。不要每次同范围低风险读文件都弹窗；也不要提供脱离对象范围的“永远允许”。审批绑定主体、事项、动作、参数hash、对象版本、目的地、收件人、期限、nonce。执行前重验；材料、收件人、成本或策略变化超出批准范围则重新批准。

## 7. 人、渠道和Agent不能互相代替授权

| 主体/渠道 | 可做 | 不可因此获得 |
|---|---|---|
| 经办律师 | 本人事项读写、授权任务、提请交付 | 其他事项、机构管理、自动签发权 |
| 助理 | 被授权材料整理与起草 | 默认签发或外发权 |
| 合伙人/指定签发人 | 所授权事项的审阅与签发 | 全所案卷访问权 |
| IT/财务 | 设备/政策/订阅/账单 | 案卷正文或会话回放 |
| 风控/利冲 | 经明确授权的目录/审计信息 | 自动所有正文阅权 |
| 平台支持 | 脱敏诊断；逐次批准的短时支持访问 | 常驻跨租户超级阅卷权 |
| 桌面 | 获准任务；本地资源选择 | 全盘访问 |
| Office加载项 | 当前文档相关操作 | 从一个窗口扫描所有本机文件 |
| IM | 收件、模板触发、进度与通知 | 任意命令、自动执行新增目录、卡片转发扩权 |
| 手机遥控 | 已配对设备上的授权任务、受限确认 | kap-server管理路由、shell终端、安装插件、扩大挂载 |
| 定时 | 已批准模板和快照/选定源 | 自己给自己批准新数据外发 |
| 子Agent | 父任务权限的子集、预算份额 | 任意新的连接器和跨事项上下文 |

远程通道采用设备主动出站+相互认证，但“只出站”只解决入站暴露，不证明内容加密或不被供应商读取。L遥控内容若承诺E2EE，需独立配对、重放防护、密钥轮换和可审核协议；不使用透传整个kap-server的通用隧道。远程任务在本机执行时，电脑离线就等待。

## 8. 数据流与降敏规则

以下全部属于受保护输入或派生信息：原件、解析文本、OCR、图片、截图、邮件头、搜索式、嵌入向量、长任务摘要、子代理上下文、工具回包、交付文件、文件名、事项名、用户反馈及日志。索引和摘要不是“没有原件所以不敏感”。

出站逐类记录目的地、用途、区域、来源对象、载荷类别、时间、审批/政策版本、用量、供应商请求ID。正文或原始搜索词按事项内容策略保存，运营日志只保留必要元数据；日志正文不再次复制到全局APM。

**化名是减风险工具，不是数据出站合法性的证明。** 只对已允许的目的和接收者外发。标识符和实体识别未命中不自动降级为公开。允许建立经律师批准的泛化查询模板，在范围内自动检索；企业名称查询确实必要时，向律师说明目的地和用途后明确授权，不偷偷删除名称导致查错主体。

严禁对Shell脚本、可执行参数或路径做模型返回后的自然语言替换。文件、实体和锚点采用稳定ID，文书渲染层按类型还原；模型要编辑某段时提交`document_version + anchor + expected_text_hash + proposed_text`，内核验证后生成修订。需要原始图像时独立判断并展示，不能隐藏在ReadMediaFile内。

网络强制包括HTTPS、DNS、IPv6、回环、重定向、WebSocket、下载器和子进程。抓取代理防SSRF：拒绝私网/链路本地/元数据地址，DNS解析和每次重定向重新校验，允许列表不能只看域名字符串。浏览器页面、搜索结果、材料中的指令均为不可信数据。

## 9. 沙箱最低标准与降级

每个活动任务/尝试独立隔离：只读输入快照、只读可信方法/配置、可写scratch/output、不可写正式交付库；不挂载用户HOME、凭据目录、Docker socket或其他事项。代码默认无网，合法联网由沙箱外broker代做，broker也不得接受任意HTTP透传。资源有CPU/RAM/时间/磁盘/子进程上限。

Windows选型通过PoC决定，优先少数可支持的强隔离实现；macOS/Linux分别验证。不把五种沙箱同时维护作为首发目标，不把某开源参考实现的存在当本项目已经可用。网络、文件和子进程是分别验收的能力，不给一个模糊“A级”替代实际测试。

不能达到最低隔离时：可信解析/比对/确定性工具可以运行；通用代码执行关闭。C事项可提示改在已验证云沙箱执行；L不得静默上传，也不得换成管理员权限裸跑。低配电脑默认并发1，16GB起验证2；更多子代理可排队，而非并发越多越“完整”。

## 10. 密钥、同步、撤权与删除

**签名、解密、恢复分三类密钥。** 每设备独立签名钥匙与证书/公钥登记；不把同一签名私钥扫码复制到所有设备。跨设备通过包裹数据钥匙获得阅权，设备吊销可具体定位。硬件不可导出的密钥不能同时设计为可跨设备备份恢复；身份恢复后给新设备新钥匙，保留旧签名验证链。

C：KMS信封加密、每租户/事项隔离上下文、服务最小权限、密钥访问日志；客户管理密钥可选，但有权服务仍可解密处理，不能称E2EE。业务管理员默认无正文访问；平台紧急访问走JIT、双人审批、原因、限定范围和客户通知。

L密文同步：使用经安全审阅的成熟密码协议与库，不自创密码算法。服务器保存最小成员/角色元数据便于租户/设备鉴权，内容钥匙只包裹给获准设备/恢复主体。禁止共享写签名私钥；同步采用不可变对象、版本向量/父版本、明确冲突版本，授权变更有顺序及纪元；哈希链不代替业务冲突解决。

恢复：个人随机高熵恢复码+第二已授权设备为优先路径；机构可选择双人恢复或客户HSM。恢复主体能做什么写入安全白皮书。不能用“管理员确认”软件流程声称持有完整恢复秘密的人数学上无法绕过。创建真实L事项前完成一次恢复验证，用户只看到“备份可恢复”结果，不强迫每位律师理解Shamir。

撤权：云端立即拒绝新的读/工具/计费与令牌续期；在线设备接收撤权，终止任务并清理缓存；离线设备在重新联网或本地租约到期后收紧。新版本更换密钥，旧数据是否已被获取不可收回。声明中明确在线传播SLO和离线窗口。

删除：对象→索引→向量→运行状态→导出临时包→设备缓存→备份→恢复材料逐项记录。状态至少为“在线副本已删 / 等设备上线 / 备份待到期 / 法律保全 / 外部已交付不可撤回”。恢复旧备份先重放删除与撤权记录，不能复活已删事项。保全授权与伦理墙分别校验，不能任何成员随意阻断全所依法删除。

## 11. 故障行为

| 情形 | 明确行为 |
|---|---|
| 笔记本断网 | 可读缓存、编辑草稿、比对和本地已覆盖法条；推理/新授权/远程法源等待 |
| 电脑关机 | C已上传纯云任务继续；L等待客户侧执行器；混合任务卡在未完成的本机步骤 |
| Kimi/MaaS不可用 | 保存检查点、有界重试；不换未批准供应商、不把模型失败标成功 |
| 控制面故障 | 本机非网络工具继续；已有云任务仅在有效租约/预算/政策内继续；失效后暂停，不声称全部可用 |
| 云或本机worker崩溃 | 从业务检查点恢复，新的attempt/fence；副作用结果不明先对账 |
| 收件链接过期 | 可重新取凭据则重取；否则标未取得并让用户重传，不能显示已归档 |
| 上游搜索失效 | 展示缺失来源与未履行查询；限定资料研究继续，不能声称完整检索 |
| 账号订阅到期 | 停止新增计费任务，保持导出/本地阅读与验证；云只读/保留期限依合同明确 |
| 本地磁盘不足 | 停新任务、保存已有可确认状态；不静默转云或覆盖原件 |

上述权限语义在桌面、云worker、律所执行器一致；各自都要强制校验，不能因为同一代码仓库就假设边界天然一致。

# 03 产品功能与律师工作流

本篇是完整产品规格基线建议，所有“首发”均指通过第06篇验收后的可售范围，当前原型不因此自动具备这些能力。

## 1. 产品与用户

定位：**律师桌面上的事项工作台，以 Kimi 驱动受控 Agent，以法律规则、证据和文书工程形成可复核交付件；账号订阅，个人可用，团队可协作。** 保留获授权的 Kimi Work 设计语言、留白、配色、任务输入、产物面板与工作区交互；具体组件以授权设计资产为基准，不凭记忆重画一套“像 Kimi”的界面。

律师购买的核心结果是减少从材料到可交付文件的总工时，并降低漏项和版本混乱。模型生成速度、Agent 数量、功能卡片数都不是主要价值指标。测量“律师完成复核并交付”的时间，计入改错、核出处、排版和恢复时间。

| 用户 | 第一项价值 | 默认权限 | 订阅关系 |
|---|---|---|---|
| 独立律师 | 审合同、核来源、输出可编辑修订稿 | 自己事项；自己复核，不伪造合伙人审批 | 一账号即可购买，个人空间与律所空间隔离 |
| 经办律师/助理 | 整理案卷、产出初稿、回稿追踪 | 获分配事项；不能默认代合伙人签发 | 生产账号或受限协作账号 |
| 合伙人/复核人 | 快速定位关键风险、依据、修改与缺口 | 获授权事项的完整指定成果 | 审阅账号可不含模型额度；仍有完整权限保护 |
| 风控/知识管理 | 规则与模板质量、利冲、合规使用 | 目录/规则发布职责；内容阅卷另授 | 治理功能按组织方案提供 |
| IT/财务 | 席位、设备、账单、服务健康 | 默认无案卷正文权 | 管理账号不等于业务超级用户 |

## 2. 信息架构与核心页面

桌面侧边栏：新建任务、事项、收件区、交付件、方法库、定时与提醒、连接与数据、设置。管理控制台负责组织/账单/策略/设备/服务状态。首页不塞36个功能入口，按“审合同”“整理材料”“法律研究”展示已验收场景，其他以方法库筛选。

任务输入保留 `/` 方法、`@` 材料/事项、`+` 导入；输入框同时显示事项、执行位置和授权模式。开始任务前只询问会改变法律判断或数据边界的缺失信息：立场、法域、关键日期、文件范围、受众、模型/检索许可。能从事项已有资料可靠取得的字段预填并标出处，不重复问。

任务页采用三栏：左侧材料与覆盖情况，中间计划/进度/澄清/决策，右侧成果预览。进度展示完成的文档/章节，不伪造百分比；可展开子任务，不暴露冗长模型思考作为“法律推理证据”。审批卡独立于聊天文本，模型不能生成一段“已批准”就触发权限。

事项页固定显示：事项负责人、立场、地域/法域、法律分析截止日、C/L数据预设、执行节点、授权模型与外部来源、保留策略、待确认事实。将技术隔离级别放设备详情；律师主要看到“可安全运行代码 / 本机仅支持标准工具 / 等待设备上线”，不要求理解A/B/C沙箱代号。

## 3. 首日体验与文件规则

1. 安装签名客户端，账号登录；可先使用合成示例，无需建三人组织或打印多张恢复卡。
2. 创建个人或律所事项。默认本地导入；组织如选择C默认，首次真实材料托管时清楚说明数据位置与范围，确认后才上传。
3. 拖入文件、挂载选定目录或从Office当前文档导入。挂载是引用，不是全盘读取授权；子目录、符号链接、网络盘分别校验。
4. 建立不可变任务快照，显示原件/附件/失败文件。引用原路径模式遇源文件变化要刷新快照；不得静默继续读新内容。
5. 选择方法和立场，看到预计费用区间、最大预算和数据接收方；运行并处理关键澄清。
6. 在Word/WPS复核修订、核出处、处理待确认事项，形成受众版本；签发及归档绑定确切版本。

“30分钟得到首份可用成果”保留为试点体验目标，必须按文件长度、扫描质量、机器条件和人工复核时间报告达成率，不作为所有案件承诺。

## 4. 三条首发业务闭环

### A. 合同审查—修订—回稿—交付

**输入**：DOCX优先；PDF可审阅但不承诺重建原生修订；合同类型、律师立场、商业目标、附件、适用法与截止日、本所规则版本。合同中声称的事实是材料主张，不自动是真实事实。

**流程**：解析结构与覆盖清单 → 定义/金额/日期/附件交叉检查 → 法律强制规则+立场Playbook+本所覆盖层 → 生成风险卡及替代条款 → 律师接受/修改/拒绝 → 文书引擎写原生修订 → 对方回稿三方比较（原始稿/我方发出稿/对方回稿） → 重审变更和受影响定义 → 受众检查 → 复核签发 → 归档。

**风险卡字段**：原文锚点、风险事实、法律/商业属性、严重度、适用前提、依据与核验状态、首选修改、可谈判备选、需要客户决定的事项。不能用“高风险”代替解释，不得把偏好包装为法律禁止。

**交付件**：审查报告.docx、带修订合同.docx、问题清单.xlsx、关键商业决定清单、引用与覆盖清单、独立签发证明。发给对方版本剥离内部谈判底线、内部评论、隐藏属性与未授权材料。

**首发内容**：先验证采购/买卖、服务、保密、软件许可及实施4类×双立场；通过后扩至v5的9类×双立场（股权转让、技术开发、商业租赁、借款担保、劳动及配套）。这是上线顺序调整，长期18套规则资产保留。未验收类型显示“通用辅助阅读/草稿”，不能套已售准确率。

**错误处理**：附件缺失、金额不一致、条款不可定位、扫描缺页、法源无许可时明确缺口；可生成内部草稿，签发前必须解决关键缺口或由有权律师记录范围限定。严禁自动补造当事人、条款、登记事实。

### B. 材料整理—事实与证据—受限文书—金额表

**输入**：有序文件包、证据来源、争议类型、当事人和主张、分析截止日。首发为内地民商事，具体文书类型与受理地区逐项验收；刑事/涉密/复杂监管业务不因通用Agent能回答就视为上架。

**流程**：安全扫描/解压 → 本地或C获准云OCR → 原件页码/图像/文本锚点 → 去重但保留来源链 → 分别抽取“材料声称的事实”“律师确认事实”“推论”“待确认” → 时间线和证据矩阵 → 缺失证据及相反材料 → 文书字段确认 → 确定性金额计算 → 原生文书与附件目录 → 人工复核。

**交付件**：证据目录.xlsx、时间线.xlsx、争点—证据矩阵.xlsx、文书草稿.docx、计算明细.xlsx、缺口清单。每一个关键事实链接确切文件版本和页段；“未检出”不写成“不存在”，“未提供”不写成“无此义务”。

**计算**：Decimal或等价精确数值；本金分段、币种、利率来源及版本、起止日计入规则、节假日规则、还款冲抵与上限由确定性组件计算；模型只提议参数。不能把LPR四倍当所有违约金、利息和金融借款的一般公式。律师确认法律适用与事实输入后才形成正式表。

**期限**：模型抽取候选起算事实，律师确认送达方式、日期、期间性质、中止中断等；日历引擎计算并记录规则版本。提醒“已送达”只表示通知通道回执，不表示法律送达或业务期限已履行。首发不自动法院提交。

### C. 法律研究—引用核验—顾问答复—变更追踪

**输入**：研究问题、法域与地域、事件时点、分析截止日、事实假设、可用数据源与许可。对事实不足先给澄清与条件化结论。

**流程**：研究计划 → 生成获准检索式 → 官方法源和许可案例库并行查找 → 取得原文/版本/权利 → 检索相反依据与区别事实 → 将命题逐一对照出处 → 区分现行法、行为发生时法和过渡规则 → 草拟答复 → 律师核查 → 交付与跟踪。

**引用四态**：已核验且支持命题；出处核验但支持/适用待确认；来源尚未核验；来源不可得/冲突/失效。前端用文本标签兼容色弱用户；红灯不允许在正式稿里伪装为确定法律依据。真实性、支持度、适用性是三个字段，不用一个“已核验”混同。

**交付件**：法律研究备忘录.docx、类案对照.xlsx、来源目录与受许可摘录、顾问答复.docx、假设/限制与相反依据。案例列表不是研究结论；排序不宣称预测胜诉率。

没有完整数据许可时，产品准确称“限定资料研究”，显示覆盖范围及缺失库；可售其他成熟业务，不冒称全面类案检索。公开监测可云端运行；L事项关联与影响分析在获准设备执行，C可在获准云任务执行。

## 6. Office、移动与IM

**Office主线**：客户端导出标准DOCX/XLSX为所有支持环境基线；优先接入试点占比最高的一种Word/WPS宿主。插件只绑定用户当前打开的指定文档、当前版本和事项；读取选择/全文分别授权。原生修订必须保留段落、表格、脚注、目录、页眉页脚、编号和批注关系；对含域代码、保护、签章的文档先检查，不能重建后声称无损。

写回使用 `base_version + anchor + expected_text/hash + replacement`，冲突返回预览，不按模糊文本替换全篇。保存、关闭、另存、同时人工编辑必须有冲突策略。外部关系、宏、嵌入对象按信任和格式处理；不能无提示删除客户必要内容。首发不编辑带有效电子签章的原件，生成新版本并说明签章已不适用。

**移动**：首发C受管Web支持完整成果预览、评论、再认证后审批，限制下载按律所策略执行；浏览器不能保证阻止截图。L默认通知，内容需在线桌面安全会话或已验收的移动解密客户端；手机App可后续加强密钥与离线体验，不将它列为销售前所有产品的共同依赖。拒绝“手机先发出、24小时补签”。

**IM**：只接试点最常用一家（企业微信/钉钉/飞书择一）；账户绑定与撤销明确。可收件、启动预设任务、查状态、提醒；不能任意文字越权调用Shell或最终外发。IM平台本身可能保存消息/附件，L不允许的资料应改用桌面导入。短时下载URL、重投去重、过期处理和文件真正落地回执全部验收；不可笼统宣传“机器人转发文件完全不经云”。

## 7. 签发、版本与法律责任

成果状态为 `草稿 → 待复核 → 待签发 → 已签发 → 被新版本替代/撤销使用`；Agent只能推进至待复核。有权律师查看的具体渲染版本、附件、受众和去向记录到审批对象。C/L均不允许审批一个版本却交付另一个版本。

输出顺序：确定内容 → 受众处理 → 依法配置AI标识与元数据 → 生成文件 → 计算hash → 生成独立manifest → 设备/服务签名。签名只证明所声明的签发流程与文件完整性；可靠电子签名、时间戳、存证和法院证据效力另按适用服务和法律要求实现。

任务执行成功与法律复核通过分别统计。只完成7/10份文件时任务为部分完成，剩余列表可恢复；律师可限定范围签发，但产品不能把未读材料计入覆盖率。

## 8. 知识、规则与内容工程

租户、事项和个人记忆分区，跨事项复用默认只允许经知识负责人批准的模板/匿名方法。不能自动把客户事实、胜诉策略、对方底线写入全所记忆。向量也是受保护派生数据；检索前按ACL过滤，取回后再鉴权，撤权同时影响缓存。

规则项包含适用条件、立场、效力时点、法源、法律要求/商业偏好类别、建议与备选、例外、内容负责人、测试样本、版本。来源表另记录抓取/索引/模型输入/展示/摘录导出/训练评测/终止留存权；订阅数据库不自动获得全部权利。

内容流程：法律工程师起草 → 资深律师审校 → 独立样本盲测 → 签名发布 → 灰度 → 观察误报漏报 → 回滚。模型、规则、模板、法源、OCR或压缩器升级，按影响图回归；紧急失效来源停止引用并提示受影响任务，既往交付件保留历史状态而不是偷偷改内容。

## 2. 集成路径裁决：适配能力，收窄管理面

建议先扩展现有SDK适配，完成下表能力契约；同时用两周技术探针对kap-server进行并列验证。选择依据是锁版真实API覆盖、故障恢复、补丁规模和攻击面，不能仅因“全量”二字决定把完整管理服务器搬进产品。

如果SDK缺少必要会话/历史/目标能力，而kap-server已有稳定可嵌入接口，则让kap-server在私有进程运行，由受限业务adapter访问；浏览器渲染、移动端、云控制面都不能直接访问其配置、OAuth、终端、插件安装、任意文件打开和关机接口。必要路由清单生成式测试，新增上游路由默认不可达。

无论选哪一条，共享业务协议与领域规则，不要求Windows Office COM、Linux云沙箱和macOS文件broker使用同一二进制。工具引擎处理推理与调用，业务内核拥有权限、审批、成果、预算和正式状态。

默认上游搜索可能依赖coding OAuth，数据源/浏览器桥也有独立依赖；详见调研A。token可用于已开放且已开通的服务，不能推导个人Work会员插件权益。Hosted Agents如另行采购，可作为一种受控执行后端评估；其存储与生命周期不同于无持久化推理，不默认启用。

## 4. 服务边界与部署

首期采用模块化控制服务+独立安全组件，避免为了架构图拆20个微服务。建议：

| 单元 | 内容 | 独立原因 |
|---|---|---|
| control-api | 组织、用户、事项ACL、政策、任务、审批、账单与控制台 | 事务一致；可先同一服务分模块 |
| model/tool-gateway | 模型、搜索、数据源、凭据代理、预算检查 | 长期上游密钥及出口边界独立 |
| execution-controller | 队列、租约、调度、结果接收、资源额度 | 高权限编排与不可信代码分离 |
| cloud-worker | 单任务隔离，C授权对象挂载 | 不持有平台管理凭据；跨租户隔离 |
| content-service | C对象与索引；L仅密文中继协议 | 明确产品模式；不能误将L导入全文索引 |
| desktop | UI、业务内核、文件/Office broker、设备密钥、可选本机执行器 | 本机授权与本机可见范围 |
| firm-runner（后续可选） | L授权常在线执行器、出站连接 | 不因“律所内网”就信任所有事项 |

云建议关系数据库作事务权威、对象存储作不可变材料版本、持久队列与outbox作异步边界。缓存不能作授权权威。C每租户/事项隔离命名空间和加密上下文；仅对象路径含tenant_id不算隔离。L内容层本地数据库加密、密文块同步；成员ACL仍在控制面最小化保存，正文不可见不等于元数据不可见。

本地服务优先命名管道/受控IPC；必须回环HTTP时检查绑定、Host、Origin、一次性短令牌和请求大小，防跨站请求。Electron渲染沙箱、contextIsolation开启，nodeIntegration关闭；CSP与HTML消毒，禁止Agent产物外部资源自动请求。所有IPC操作使用结构化schema，不透传任意路径/命令。

## 5. 数据模型与接口契约

| 实体 | 必需字段/约束 |
|---|---|
| Tenant/User/Device | 所属组织、状态、角色、设备独立公钥、撤销纪元；个人/多所空间明确 |
| Matter | 负责人、成员ACL、伦理墙、C/L、法域、时点、保留/保全策略、policy_version |
| MaterialVersion | 来源、版本hash、媒体类型、原件位置、授权地点、页段锚点、权利记录、解析覆盖 |
| Run / Attempt | 请求意图、快照、执行位置、状态、预算、父任务、租约epoch、deadline |
| ToolCall | 工具/版本、规范参数摘要、输入对象版本、policy_decision、实际出站记录、结果位置 |
| Approval | 对象及版本、动作、受众/目的地、金额/预算、批准人/设备、nonce、有效期、消费状态 |
| ArtifactVersion | 源材料/规则/模型版本、产物hash、类型、质量门禁、复核和签发状态 |
| Citation | 来源版本、精确锚点、命题、真实性/支持/适用三态、许可、核验时间 |
| UsageLedger | request_id、预占/实际/释放/补记、供应商费用、用户点数、计费版本、幂等键 |
| AuditEvent | actor、tenant、matter伪名ID、动作、对象版本、policy与decision ID、序号/前hash |

本轮API示例是我方目标协议，不声称是Kimi原生API：

```text
POST /v1/matters/{id}/runs          {method, material_versions, execution_target, budget}
GET  /v1/runs/{id}/events?after=seq  断线续读；短期能力认证
POST /v1/runs/{id}/answers          {question_id, answer, expected_state_version}
POST /v1/approvals/{id}/decisions   {decision, object_hash, challenge_signature}
POST /v1/runs/{id}/cancel           {expected_state_version, reason}
POST /v1/artifacts/{id}/submit      {version, audience, channel}
POST /v1/devices/{id}/revoke        {reason, admin_authorization}
POST /v1/matters/{id}/migration     {from,to,manifest,retention,approval}
```

服务端从认证上下文与对象查询得出tenant/role，不信任请求体。资源不存在与无权限响应避免泄露案名；列表、搜索、预签URL与批量导出同样校验，下载令牌绑定版本、受众、范围和短期TTL。

RuntimeAdapter至少暴露 `start/resume/respond/approve/cancel/events/capabilities`；工具请求必须经过 `authorize → reserve budget → prepare → approve if needed → recheck → execute → validate → commit → settle`。批准人来自可信UI认证，不来自模型参数。

## 6. 状态、恢复与幂等

任务状态：`CREATED → VALIDATING → QUEUED → RUNNING`，期间可进 `WAITING_INPUT / WAITING_APPROVAL / WAITING_DEVICE / PAUSED_BUDGET / RECOVERING`；终态为 `SUCCEEDED / PARTIAL / FAILED / CANCELLED / EXPIRED`。终态转换用数据库CAS；未知状态、缺成果或截断不能成功。Artifact的法律复核状态独立。

Run是用户意图，Attempt是执行尝试。每Attempt获得短租约与递增fencing epoch；失去租约后不得读取新材料、调用上游、写产物或结算新费用。网关、对象服务与最终提交都检查epoch，不能只在调度器检查。队列是至少一次交付，外部效果以idempotency key和接收方回执保证；不能承诺任意外部系统exactly-once。

checkpoint保存：已完成工具结果指针、输入快照、政策与模板版本、预算账本、待答问题/批准、压缩历史、失败覆盖清单。恢复必须重新检查权限和输入版本。引擎会话续接只是实现手段，不能重跑整个任务后算“恢复”。副作用结果未知时进入人工对账，不直接重发。

同步采用不可变事件与文件块、乐观并发提交；独立草稿可并存，签发与外发单一权威提交。C服务器权威，L指定本机/runner事项协调者；更换协调者须租约交接。MVP不做Word正文CRDT实时合写，以独占编辑租约+冲突副本保障清晰责任。

## 7. 沙箱与出站的真实覆盖

本机优先选择一条可维护且实际通过目标Windows版本/EDR的强隔离方案；其他方案是候选，不能用A/B/C字母掩盖实质差异。不满足读隔离或网络限制的环境只提供可信解析/比对等标准工具，不允许运行模型生成代码。用户确认不能补上隔离。

云worker用任务级隔离环境，容器以外叠加用户命名空间/最小权限/seccomp/网络策略等适合部署的控制；高风险通用代码评估microVM。容器不是天然租户安全证明。禁止宿主socket、云元数据、挂载宿主根、privileged和共享可写依赖；CPU/RAM/进程数/磁盘/输出量/执行时间全部限制。

文件安全包括symlink/junction/reparse、UNC/网络盘、大小写、保留设备名、长路径、压缩包路径穿越、检查后替换竞态。不能只用 `realpath` 检查一次后再按字符串重新open；broker须在实际操作时绑定安全句柄/目录，或将不可信操作限制到已隔离快照。

出口覆盖模型、搜索、Fetch、浏览器、MCP、OCR、遥测、更新、依赖下载、媒体、WebSocket、DNS和子进程。允许域名不等于允许任意路径/请求体；必须校验动作和数据。公开网页内容不可信，不能改权限或触发安装。关闭网络的脚本仍可把秘密写入产物，后续导出同样受审查。

**化名策略替换v7双向代码替换**：进入模型的敏感文本按获准目的最小化/化名；任务文件名使用稳定安全ID；引擎编辑去标识的工作表示，输出结构化patch与实体ID。可信文书引擎在最终文档字段内还原，校验引用、转义和版本。绝不替换Bash/JavaScript/Python源码字符串。无法兼容语义或OCR图片时停用该模式或单独授权真实输入，不承诺NER可以实现匿名化。

## 8. 模型、预算与方法资产

从单个经过法律评测的Kimi主模型开始，低成本模型仅用于通过专项评测的分类/抽取，不自动替代复杂法律判断。策略锁定供应商、模型族与处理区，容量不足不静默跨供应商路由。reasoning/signature等协议约束字段遵循锁版官方接口；UI不展示思考原文作为审计依据，存储与回传纳入内容政策。

长文采用覆盖驱动切分、结构/附件联动、多段检索和全局一致性检查；不因模型支持长上下文就一次塞全库。上下文压缩不能丢关键限制、资料版本和不确定性，法律事实账本独立于聊天摘要。

预算先预占、每次调用检查、父子共用总上限，给最终汇总/失败说明留余额；自动重试只适合已知未产生副作用的失败，次数与费用受限。达到预算暂停并给出已完成/未完成/追加预计，禁止后台继续扣费。usage不完整先标待核对，不把输出字符数冒充供应商token。

方法资产以版本、合同、持续质量和组织覆盖层形成护城河。首发不建设复杂占位符扩展/思考密封协议；必要云端prompt组装必须有展开后成本、版本和可评测输入证据。内容进入模型后不能保证绝不经输出泄露，50字重合检测仅辅助。

## 9. 现有平台和MaaS复用

本轮未修改相邻 `MaaS 生产/new-api` 工作区。正式接入前对共享MaaS做独立数据流核验：正文/错误体日志、重试、模型fallback、缓存、管理员访问、导出、计费精度、断流及reasoning字段兼容。单独“法律分组”不是隔离证明。

优先独立法律网关与计量域，复用已证实合格的IAM/支付/监控基础设施。核心Kimi企业密钥只在服务端密钥管理中，客户端使用我方短令牌，运行时和脚本不可读取长期上游密钥。禁止扫描或打印生产环境密钥以验证架构。

数据迁移分阶段：保留现有schema并加版本 → 建立只读导出/备份 → 双写或校验迁移（不双重外发）→ 对账 → 按事项切换权威执行器 → 保留回滚窗口。旧示例法规、演示来源和虚构当事人必须打 `sample=true` 并物理隔离生产索引，生产构建拒绝载入。

## 10. 供应链与可维护性

锁定上游commit、SDK、Node/Electron、原生模块、工具与镜像digest；补丁逐项对应威胁、测试和上游issue。干净检出+补丁重放可复现构建；dirty目录与改过的bundle不作交付来源。SBOM覆盖外部下载二进制、字体、OCR模型和便携运行时，遵守各自许可。

更新分测试/设计合作/稳定渠道，签名验证、反回滚、紧急停用、数据schema兼容和客户可控延迟；延迟更新也有安全支持截止日。上游每两周评估是流程建议，不意味每两周强制升级。每次升级重跑受影响能力、权限继承、出站与恢复探针。

OpenTelemetry等观测默认只留元数据；敏感body、文件名、prompt、trace附件和第三方报错可能含案情，按C/L分别处理。支持人员通过有期限、客户可见的break-glass流程获得最小访问，记录审批与读取；不能因“排查故障”默认读全库。

# 05 合规、运营与商业闭环

本文将法律要求转成产品门禁，供中软法务、外部中国法律顾问和试点律所对实际运营主体、合同和数据流签字。没有核验到的条文不当作强制法；设计目标不当作已取得认证。

## 1. 六项不能混同的权利

| 项目 | 本轮状态 | 产品动作 |
|---|---|---|
| 标识与设计授权 | 用户明确已获授权，接受此前提 | 归档实际范围、期限和可交付资产，不重复索取同一确认 |
| Kimi Code开源许可 | 官方仓库及根MIT核验 | 保留许可；审计依赖、外部二进制与修改分发义务 |
| 模型API调用 | 用户确认采购token | 明确采购账户/区域/价格/限额/售后，不给终端客户分发上游密钥 |
| Work会员/闭源后端权益 | 未提供相关合同 | 搜索、数据源、PPT、浏览器桥、遥控逐项买或自建 |
| 客户材料处理权 | 因事项与主体不同 | 记录委托、保密约定、个人信息依据、用途/接收者及特别限制 |
| 法律数据源权利 | 需企业合同及许可附件 | 检索/模型输入/展示/导出/缓存/评测逐项授权 |

Kimi开放平台协议第3.1款同时规定API许可限制及向最终用户提供服务的用途，不能仅凭“不可再许可”断言应用SaaS被禁止；裸转卖API密钥与中软运营有增值功能的应用不同。真正需要谈妥的是具体渠道/能力、责任分配及第6.3款模型服务优化用途限制。[现行开放平台服务协议](https://platform.kimi.com/docs/agreement/modeluse)（2026-08-31生效）。这是条文解释与谈判建议，最终以企业补充协议和专项法律意见为准。

## 2. 专业保密与个人信息处理

本轮官方资料确认律师法2026年修订已公布；保密与利冲要求应使用现行版本，不能机械沿用旧稿条号，也不能使用demo种子法规。[最高法转载主席令](https://www.court.gov.cn/xinshidai/xiangqing/510011.html)、[北京司法局现行文本](https://sfj.beijing.gov.cn/sfj/zwgk/2024zcwj/744120751/fl91/744123073/index.html)。上线法源入库应由法律编辑对照正式公报、施行与过渡规定签字。

客户同意AI辅助不自动代表对方、员工、证人、未成年人等信息主体全部同意；委托保密许可也不自动满足个人信息处理依据。产品分别记录 `professional_authorization`、`personal_data_basis`、`sensitive_data_conditions`、`processor_scope`，并保留“范围不足/待律师确认”。不让一个“无需同意”按钮放开全部外发。[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。

C/L只是技术与合同预设，不是法定密级。标准产品不处理国家秘密及依法不得进入该服务的数据；不确定是否可处理时停在本地受控识别与人工判定。刑事材料不一律等于国家秘密，商业材料也不一律可上云；私有化不是解除法定义务的万能条件。

## 3. 各方角色与数据条款

角色依据实际目的和决定权按处理活动认定，不能笼统说中软永远只是受托人。律所决定案件用途；中软为该用途提供存储/推理/同步通常设计为受托处理；中软自主决定账号计费、防欺诈、法定义务等目的时另行认定。上游模型、搜索、OCR、云基础设施等纳入转委托/第三方目录与相应授权流程。密文仍可能为可识别数据，不能用“我们没钥匙”排除所有处理责任。[网络数据安全管理条例](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm)。

DPA附件至少包含：

1. 每一端点/功能的处理目的、数据类别、区域、接收方及角色；模型、缓存、批量、搜索、抓取、图像、文件、托管Agent分别列明。
2. 不用于训练或服务优化的约束及例外；安全审查是否留存、人工可见范围、分包变更通知；不能用“ZDR”三个字替代具体条款。
3. 在线正文、临时文件、错误日志、缓存、备份与外部供应商的保留/删除；法律保全、恢复和终止导出流程。
4. 访问控制、加密、密钥归属、支持访问、审计证据和事件通知时限；C明确服务端可解密，L明确获准推理请求会过境。
5. 个人信息权利请求、纠错删除、处理者协助、跨境条件、责任和赔付。上游责任上限与我方对律所承诺需匹配，不能把不匹配风险藏在无限SLA中。

统一供应商不代表所有端点统一DPA；相同API密钥不代表相同留存。若某工具无法满足L政策，就关闭该工具在L中的使用，或采用合规替代，不宣称整个平台都无留存。

# 07 经济压力测算摘要

规划压力测算，不是实际报价、采购合同或盈利预测；revenue已假定为不含税可确认收入，加量包收入为0。

| 基准使用 | 40 | 6.06 | 7840.00 | 4106.88 | 3733.12 | 47.62% | 26.64 |

## 参数解释与限制

- K3输入20元/百万、输出100元/百万、缓存命中2元/百万为2026-10-09官方公开价记录；实际企业价与账单规则待核。缓存写入按输入价计，本模型不重复把同一token计入输入和写入；如合同另有存储费，应增加该项。[Kimi官方价格](https://platform.kimi.com/)。
- 任务token是所有轮次/子Agent的累计计费量，输出含计费思考；80k未命中、120k命中、20k输出和1.15尝试系数均为假设，不是测量结果。
- 检索0.015元/次在此是报价假设，法源0.8元、计算0.6元、存储网络0.15元/任务以及年分摊服务1200元均须真实合同/遥测校准；固定最低采购额另做容量分摊，不重复计费。

- 云/本地算力占比、数据许可最低承诺、客户支持、退款、渠道和坏账需要单独敏感性；禁止把本表转述成2030年利润预测。

结论：固定年费不宜承诺无限调用；重度账号需要明确额度或额外购买。先以试点校准每份最终被采用交付件成本，再确定售价和包含用量。

# 调研 A：Kimi Code 集成、云依赖与工程独立核验

审计日：2026-10-09（Asia/Shanghai）。范围：v5/v6 技术方案、当前 `platform/` 实现、锁版与官方上游。只读检查产品代码；未使用真实案件或 API 密钥，未请求付费模型。下述“已确认”表示源码、官方文档或本次探针有直接证据；“推断”表示工程判断；“待验证”表示不能从材料推知。

## 1. 独立结论

Kimi Code 是可真实嵌入的 Agent 引擎，现有 fork 并非虚构 SDK；使用开放平台模型 API 建设自有订阅 SaaS 在技术上成立。但“买了 API token → 获得 Kimi Work 全后端 → 现有 demo 已完整集成 → 可直接服务律师”这一推导不成立。当前集成保留循环、部分会话与法律 MCP，主动关闭大量通用 Agent 能力；项目尚无证据证明操作系统沙箱、持续任务、交互提问、技能装载、浏览器及完整云服务已经交付。

v5 的优点是明确将模型视作不可信决策者，将事项权限与成果签发置于业务内核；v6 的优点是补上 SaaS 控制面、中继、公开任务和服务商 IM 的产品现实。主要问题不是选错 Kimi Code，而是把“能力关闭”当成长期安全架构，把“进程级封装”与“OS 强制隔离”混用，以及新增通用工具后未重新检查绕过路径。用户要求完整能力时，必须通过独立执行域、能力令牌和统一工具网关恢复能力，不能只扩大一个 `enabled` 数组。

## 5. 现有实现的独立缺陷与生产阻断项

以下路径相对仓库根 `platform/`。报告列出源码行号，避免把设计愿景与已完成实现混为一谈。

### A-P0-01：没有 OS 沙箱，不应把应用层改写称为“无对外网络能力”

`apps/agent-host/src/host.ts:5–7,49–57` 声称全局 undici dispatcher 让宿主事实上无外网能力；`packages/kernel/src/executor/agent-host-manager.ts:183–194` 实际使用普通 `spawn(runtime,[entryPath])`，未见受限令牌、AppContainer、Job Object、网络命名空间或外部沙箱启动器。

**已确认的技术边界**：全局 dispatcher 仅影响采用该默认 dispatcher 的请求。官方 `app/web/providers/local-fetch-url.ts:129–134` 显式传入自己的 dispatcher；它可以绕过全局 dispatcher。`node:http/https/net`、自建 dispatcher、child process 和本机原生组件也不因这句设置而失去网络权限。vendor bundle 中存在 direct fs/child_process/net imports。

当前白名单关闭 FetchURL，故本次不是声称现已发生外联入侵；这是当前隔离结论不成立、及扩功能时必现的架构缺口。**修复**：云执行放进强隔离沙箱并默认断网，仅允许受控代理；端侧独立受限执行器、进程树/资源限制与受支持系统的 OS 网络强制。所有形态运行实测矩阵，无法建立强边界的个人自装模式必须明确为较低保证等级，不能显示相同安全标识。

### A-P0-02：文件系统边界可被符号链接穿透，Windows 合法子路径也会失败

`apps/agent-host/src/sandbox.ts:38–65` 只对 `resolve()` 后字符串前缀判断；读写在检查后直接执行，未验证最终目标、链接/重解析点及打开时竞态。`under()` 固定使用 `/`，Windows `path.resolve()` 返回 `\\` 路径，合法子目录将被错误拒绝。

**本次已实测**：Node 26.8.1，临时目录创建纯合成 `synthetic-outside.txt`；快照内 `link.txt` 指向白名单外该文件，再直接调用实际 `createRestrictedFileSystem.readText(link)`。结果 `synthetic_symlink_escape=true`。另使用 `path.win32` 计算合法子路径并代入当前判定，结果 `windows_legal_child_allowed_by_current_under=false`。临时文件已清理，无真实文件内容被读取。

这证明 wrapper 本身不是强边界，不证明通过当前封闭工具集可以直接构造完整攻击链。**修复**：root-relative path 与 OS 文件句柄能力校验；拒绝/安全解析 symlink、junction、reparse point、UNC、大小写、长路径；对读写、rename、link、删除均在真实边界内执行；仅 realpath 后再读不足以处理 TOCTOU。终极边界仍是 OS 沙箱与只挂载允许目录。

### A-P0-03：“manual + setApprovalHandler”不等于每次工具执行都强制经过业务审批

官方 `permissionPolicy/policies/default-tool-approve.ts` 默认批准 Read、Grep、WebSearch、FetchURL、Agent、AgentSwarm、Skill 等；`permissionGateService.ts:53–59` 只有 `ask` 才请求审批，`approve` 直接放行。因此以后开放工具时，不能靠回调自动接管全部行为。

当前 manager 的 `agent-host-manager.ts:90–102` 对 `mcp__legal__` 前缀自动批准，既没有按参数描述副作用，也没有让律师在此处确认。这对现有六个受限法律工具可作为原型策略，但不是成熟三级权限机制。应以执行前策略强制点为准，重新校验主体、事项、对象版本、动作、数据去向、预算、有效期与吊销状态；审批 UI 仅签发窄化 capability，工具端必须消费并核验。

不要把 `mcp__legal__*` 通配符当永久安全分类。新增同前缀写工具会自动继承批准，必须使清单包含 tool schema hash、作用范围和副作用类别。

### A-P0-04：任务 timeout 会被记为 succeeded

`host.ts:154–163` 超时发送 `{t:'done',status:'timeout'}` 后以 1 退出；manager `:105–107` 把除 cancelled 外的 done 全设为 succeeded；退出处理 `:237–247` 仅更正 running/starting 状态，因此 timeout 的 succeeded 可能保留。**这是直接源码逻辑缺陷**，不应把不完整草稿作为完成成果推进后续流程。

修复为有限状态机：succeeded、failed、cancelled、timed_out、waiting_user、budget_exhausted、interrupted 分离；终态转换须绑定结果完整性；非零退出、模型截断、工具失败、依赖缺失不得被默认成功吞掉。

### A-P1-05：提问、Skills、事件持久化尚未完整接入

- `host.ts:71` 声明 `uiCapabilities:[]`，仅设置 approval handler，无 `setQuestionHandler`；白名单含 AskUserQuestion 不能证明“中途向律师提问”可用。官方工具 `askUserQuestionTool.ts:194–198` 交互不支持会返回明确错误。必须端到端测试问题出现、答复、取消、恢复与身份校验。
- manager `:174–181` 固定 `skillDirs:[]`，因此现有 manager 路径未装载签发法律 Skills。方案里的签发技能目录是目标，不是本轮可确认实现。
- `host.ts:169–187` 把事件正文截断到 2,000/4,000 字符；manager `:85–88` 又将任意 delta/text/content 拼成 outputText。需要明确最终输出与中间推理/工具事件的区分，避免重复、错序、截断污染成果；成果应采用结构化 artifact 事件、文件 hash 和事务完成记录。
- manager `:74–75` 的事件首先写内存数组。host 注释“先落账本再推界面”本身不是 durable persistence 证明；整体 executor 可能稍后轮询入账，需崩溃故障注入确认缺口。

### A-P1-06：取消、恢复与凭据范围要重做能力化验证

`agent-host-manager.ts:276–279` 仅杀一个进程，理由是 ZP-5 下无孙进程；但 sandbox.ts 已承认 direct child_process 不受 DI 管理。开放 Shell/MCP stdio/CU 后，这一假设必失效。需 Job Object/cgroup/可验证进程树终止，且先吊销 run capability，再取消模型/远程工具；远端已提交副作用需要补偿或对账，不能说杀进程等于撤销操作。

`executor.ts:731–732` 明确 agent_start/agent_wait 不落检查点，崩溃后整任务重跑。对六个只读工具可接受；对邮件发送、云盘写入、提交签章不成立。持久任务需要 checkpoint、工具幂等键、outbox、执行租约/fencing、恢复时权限重验和副作用回执。不可把上游后台 Agent 或 cron 直接当作多租户可靠调度器。

### A-P1-07：应用层配置由高权限目录保护不足

签名 agent profile 被复制进可写 home（manager:139），文件 mode 0444 并不等于拥有同用户权限的进程无法替换文件。agent 的可写状态与可信 config/profile/skill 分区必须分开；可信文件按制品 hash 只读挂载；执行前策略不能由模型可写文件决定。

## 6. “完整能力接入”的可实施定义与对照

完整是每项能力都有可用路径、权限与验收；不意味着律师任务默认拥有全部电脑权限。采用一个 Agent Runtime adapter，按能力 profile 加载同一引擎；保留原生语义，对副作用路径通过受控工具替换或适配。

| Kimi Code 能力 | 当前 demo | 生产要求 | 推荐边界 |
|---|---|---|---|
| 推理/工具循环/压缩 | 已嵌入，模型真实接口本次未调用 | 协议/压缩质量/取消/计费完整回归 | 云与本地共用 adapter |
| 计划/待办 | 白名单开放 | 与任务状态对应，不把自然语言 plan 当授权 | 任务级 |
| 用户提问/审批 | 审批前缀策略；提问未完整桥接 | 交互对象持久化，答复绑定 task/主体 | 控制面+客户端 |
| Skills | API 支持，manager 当前空列表 | 签名 registry、版本、依赖、来源和批准；内容不能自扩权 | 可信只读挂载 |
| MCP HTTP | 仅内核法律 MCP | 租户管理员批准 connector；对象级权限；OAuth refresh 存 vault | 独立 connector broker |
| MCP stdio | 被进程服务拒绝 | 独立沙箱 sidecar，固定镜像/命令/env，不继承用户完整 HOME | 本地/云工具执行器 |
| Read/Write/Edit/Glob/Grep | 关闭 | 临时工作区、输出目录、版本化编辑、symlink 与越界测试 | 文件 broker |
| Shell/脚本/Python | 关闭；v6 T2 设计中 | 受限代码执行可生成文书/表格；依赖预置；超时、内存、磁盘、网络预算 | 单任务沙箱 |

| Agent/Subagent/Swarm | 关闭 | 真实子代理上下文、分工、结果汇总；子预算与子权限不大于父级 | 同事项隔离；禁止跨事项默认继承 |
| Background/Task/Wait | 关闭 | 持久任务 DAG、checkpoint；浏览器关闭可续跑，电脑关闭仅云/在线节点可续跑 | durable orchestrator |
| Cron/持续监测 | 原生关闭 | 仅已批准任务；到期、撤销、变更审批，低噪声通知 | 产品 scheduler |
| Hooks | 未接；上游异常可为空结果 | 观察型 hook 可开放；强制合规规则不可依赖 fail-open hook | 策略服务与异步事件总线分开 |

| Computer Use | 未接 | 指定应用/窗口；截屏数据去向展示；发送/提交/付款终审 | 单独高权限本地 broker |

| Remote Control | 关闭 | 如产品需要远程本机操作，用设备证书与自有审计桥；不上游 relay 默认开放 | 自有设备通道 |

对子代理的关键约束：父任务 permission 是上限；每次派发生成 attenuated token；限制模型、总 token、并发、深度、可见对象、目的地；子代理写入独立工作区，结果汇入前审查；最后签发只能由授权人完成。不能以“另开 N 个 Agent 进程”充当等价替代后就宣布完整 subagent 体验。

## 7. v5/v6 方案评审：保留什么、改什么

### 推荐结构

控制面负责身份、授权、任务编排、预算、审计索引、产品计费。执行面可在“云租户隔离沙箱／本地设备／律所节点”选择，选择依据包括事项策略、对象位置、用户明确授权、所需能力与在线状态。模型推理位置单独标注；本地执行+云模型是独立模式。

模型只提出结构化工具请求。工具网关计算有效权限交集：平台安全基线 ∩ 租户策略 ∩ 事项授权 ∩ 用户角色 ∩ 任务授权 ∩ 工具作用域 ∩ 当前撤销/时限/预算状态。云执行器不能获得任意本地文件；本地桥也不能成为云端泛化 shell。通过“限定对象+限定动作+限定目的地+到期+nonce”的 capability bridge 调用。

跨执行域迁移必须生成新的授权决策：列明上传对象和派生内容、目的地、保留期、模型供应商与续跑条件。不能因为本机不可用就静默上传；同样不应每个低风险步骤都弹窗。

## 8. 生产验收与研发顺序

### P0：真实客户资料开放前

1. 确认供应商能力账本与合同覆盖；对未采购服务显示缺失，不能自动切到个人 OAuth。
2. 修复任务终态 bug、sandbox 路径问题；启动器达到声明的 OS 隔离等级。由独立安全测试检查 raw socket、DNS、显式 dispatcher、child process、持久化 fs、symlink/reparse/TOCTOU。
3. 端到端的事项与租户隔离：每个工具 endpoint 用对象 ID 查权限，不能相信模型传来的 tenant_id；工具调用时动态重验撤权。
4. 可信 agent/config/skill 与任务可写目录分离；禁止案件文档触发项目指令、MCP、插件或 Hook 自动安装。
5. 将全部外发、覆盖、提交、删除、共享、签章动作设计为预览对象+版本 hash+目的地/受众+显式批准；审批过期或内容改变必须重新批准。
6. 云/本地/模型/connector 的日志、缓存、临时文件与备份真实数据流图及故障路径验证；关闭遥测不等于所有内容日志已关闭。
7. 建立预算原子预占、父子预算、取消后结算、供应商 usage 对账；禁止无限自动重试与超额继续。

### P1：完整能力商用前

1. 完成提问、技能、子代理、sandbox files/shell、搜索、浏览器的真实受控路径；不以 disabled 充当 completed。
2. durable orchestrator：断网、关页面、重启、关机、设备撤销、限额与待批准恢复；副作用幂等；终态不可歧义。
3. Windows/macOS/Linux 分别实测；Node/Electron/原生模块与 Office 版本锁定；只声称已过矩阵的平台。
4. vendor 可复现构建+SBOM+签名+升级回归；原生辅助二进制独立审计。
5. 文档质量：修订保真、引用可定位、计算可复算、长文不漏检、提取置信度和成果完整性。Agent 能完成运行不等于法律成果合格。

### 最小探针集

- 任意本地文件/目录、越界符号链接、Windows junction、大小写/UNC/长路径、检查后替换；必须拒绝且不返回片段。
- HTTP/HTTPS/WS/DNS/raw socket/自建 undici dispatcher/子进程代理；未授权出站必须 OS 层失败。
- malicious PDF/网页/AGENTS.md/skill/MCP 声明：不能改变租户、模型 provider、工具清单与目的地。
- 子代理跨事项、无限递归、预算耗尽、父任务取消与租户撤权；必须立即停止新增调用并保留可解释状态。
- 待批准时换文件/受众/策略，审批结果重放；必须拒绝。
- timeout、模型 length 截断、非零 exit、工具失败、最终 artifact 不存在：不得标 succeeded。
- 断电前后外发重试、任务租约争抢：不能重复发送/提交。
- 无已付费 API 调用也可完成隔离与失败路径验收；协议与真实效果再以获准样本、独立预算执行。

# 调研 B：办公 Agent 云地边界独立核验与法律 SaaS 设计裁决

核验日期：2026-10-09（Asia/Shanghai）。研究对象：v6 的 R1/R2、v7 的 S2 及其衍生结论。所有以下外部链接均在本日访问；无明确发布日期的页面不推定其发布日期。通过官方网页与文档直接复核，部分网页正文使用 HTTP 抓取；没有登录竞品、没有执行其客户端、没有对闭源安全机制进行渗透验证。**官方宣称是产品文档事实，不等于独立安全认证。**

本轮原文核验记录存于 `evidence-B/`，`manifest.json` 记录 URL、HTTP 结果与抓取响应哈希。已将本次可直接访问的 16 页落盘。哈希为抓取响应解压后内容的哈希，正文快照去除了 HTML 脚本/样式；因此不应将快照文件哈希与响应哈希混用。部分 Anthropic 页面只能经网页读取工具访问，未伪造落盘快照。

## 1. 对最终方案最重要的判断

1. **执行地点、数据持久化、模型推理地点、访问权限是四个不同的轴。** 本机读文件、本机 Python、云模型推理、本机保存结果完全可以同时存在。不能用“本地 Agent”推出“文件内容不出设备”，也不能用“云端 Agent”推出“全盘可读”或“必定访问内网”。
2. **手机遥控不是云端托管。** WorkBuddy 助理和 Kimi Work 本地任务都依赖电脑在线；千问桌面/网页有两套定时任务。产品必须显示真实执行节点、最后在线时间、断线状态、错过触发与补跑规则。
3. **SaaS 是交付/订阅方式，不决定所有工具在哪里执行。** API token 采购既不附送 Kimi Work 产品后端，也不妨碍中软自建合规云端 Agent Runtime。需要独立建设两种执行器、凭据代理、审计、存储、授权与任务调度，而不是把产品品牌或 API 账单当成这些能力的来源。
4. **有云管理端不代表管理员应可读全部案卷和全部对话。** 律所案级权限、利益冲突隔离、系统管理员与业务阅卷权应分离。企业治理参照竞品机制，不能照搬其“所有会话集中回放”作为所有律所的默认值。
5. **“全部权限”不适合成为法律版的常用能力档。** 应提供可审计的有限授权模板，在案件工作副本内自动产出；覆盖原件、跨案访问、对外发送、签署/递交、付款和系统配置各自独立授权。用户的一次开关不能替代每一项权限和业务责任。
6. **“本地原件优先 + 显式云托管 + 同一权限语义”可以成立；“所有法律 AI 都在云端”或“必须全部本地”都没有证据。** 数据策略选择不应偷偷改变执行节点，也不能因节点离线自动把案卷移往云端。

以上为本研究的架构判断，不是对任一竞品现有能力的断言。

| 云端无人值守 | Web 定时任务在云端执行，退出登录/关闭浏览器不中断 [Q7] | 从自然语言任务直接推导可靠 SLA、Exactly-once 外部效果均无依据 |
| 同步 | Web 与桌面会话、定时任务当前相互独立 [Q1] | 不能在我们 UI 中承诺“完全复刻竞品天然跨端接力” |
| 企业审计 | AI 日志按轮次记录，可查询最近 90 天 [Q8] | **90 天是查询窗口，不能等同于后台保留/备份销毁期限** |
| 删除/数据使用 | Web/钉内删除先从用户可见空间移除，另有必要保留；桌面设置有不用于产品改进的说明 [Q2][Q3] | 无法因此保证全产品全模型无训练、ZDR 或即时物理删除 |

[Q1 FAQ](https://docs.qwenwork.cn/faq.md)、[Q2 Web/钉内隐私与安全](https://docs.qwenwork.cn/getting-started/privacy-security.md)、[Q3 桌面设置](https://docs.qwenwork.cn/desktop/settings.md)、[Q4 电脑操控](https://docs.qwenwork.cn/desktop/computer-use.md)、[Q5 桌面发布日志](https://docs.qwenwork.cn/release-notes/desktop.md)、[Q6 桌面定时任务](https://docs.qwenwork.cn/desktop/scheduled-tasks.md)、[Q7 Web 定时任务](https://docs.qwenwork.cn/web/scheduled-tasks.md)、[Q8 AI 日志](https://docs.qwenwork.cn/enterprise-ultimate/audit-logs/ai-logs.md)。除 Q5 的版本日期外，这些页未给可核验的最后更新日期；本次 Q5 首条仍为 1.2.1 / 2026-09-23。

**对 v7 的重要补正：** Q3 明确存在数据共享/隐私模式说明，并称企业账号由管理员管理。因此“未发现任何不训练承诺”不能被扩写为“千问没有隐私承诺”。但 Q2 仅适用 Web/钉内并列有产品体验改进目的，Q3 为桌面设置，两者范围不同；也不能反过来把 Q3 的承诺推给所有平台。采购时应要求将所有实际使用路径统一纳入 DPA 和模型供应链条款。

**Hook 不能替代强制策略：** [Q9 桌面 Hooks](https://docs.qwenwork.cn/desktop/hooks.md)明确规定 HTTP 非 2xx、连接失败/超时记录错误后继续原流程；有效拒绝响应与基础工具权限仍可阻止动作。因此准确表述是“Hook 服务异常时不产生额外拒绝”，不是“所有操作一定被放行”。法律版的案级 ACL、外发 DLP、最终提交必须在不可绕过的执行网关校验；高风险校验服务失败须拒绝执行。PostToolUse 检查已经太迟，不能撤销发信或文件覆盖。

**应借鉴：** 云地调度明确告知、独立执行记录、电脑操控单独授权。**不可照搬：** 桌面/云会话的割裂；安全工作环境文案被误解成云模型无需上传上下文；Hook 故障放过作为法律权限最后一道防线。

## 3. 海外及法律产品：有用的是明确的数据和身份边界

### 3.1 Claude Cowork

本日[官方架构页](https://support.claude.com/en/articles/14479288-claude-cowork-architecture-overview)确实写明云端默认执行；既有桌面部署仍有本地执行，Pro/Max 例外按 2026-10-06 前已在设备发起的任务界定。故 v7 引用并非未来日期错误，但不能倒填到 10-02 的历史结论。

其云会话在独立临时沙箱执行；通过在线 Desktop、已连接目录及逐工具权限接触本机；读到的本机文件会在服务器处理。连接器凭据由服务端使用，不进入沙箱。组织可独立关云会话、限制网络与持久授权。既有本地模式把 Agent 循环和 VM 代码执行分开；VM 不可用时代码能力失败，不代表所有文件工具停摆。这里的商业数据承诺明确引用 Team/Enterprise，不能顺带推广成 Pro/Max 的同等合同承诺。

**对我们的含义：** 云任务调用本地受控工具是可行架构，但需要显式数据出境/出设备说明与双侧授权；本地 VM 只覆盖代码执行，不自动覆盖宿主文件工具、MCP 和浏览器。上游闭源实现没有自动成为我们的可复用组件。

### 3.2 Microsoft Copilot Studio（不等于所有 Microsoft 365 Copilot）

[官方 Computer Use 文档](https://learn.microsoft.com/en-us/microsoft-copilot-studio/computer-use)区分 maker 凭据与终端用户凭据；前者共享 Agent 时，用户可能取得创建者在目标机器上的能力。页面还明确，应用/网址 allowlist 约束操作，并不保证页面无法被打开。敏感检测的人工监督超时会停止该次运行，不能推导为每一次业务提交必定复核。

**对我们的含义：** 每个连接器必须写清“以谁的身份执行”，服务账号要有案件用途限制和用户交集授权；App/URL 白名单不等于防火墙。终端安全、网络出口和 Agent 审批必须分层落实。

### 3.3 Harvey

[Harvey 安全页](https://www.harvey.ai/security)可确认云服务、权限治理、可配置保留、合同化不训练以及模型供应商 ZDR 的基本承诺。不能因此断言所有能力和所有子处理者都零留存。

本轮新发现：[Service Terms](https://www.harvey.ai/legal/service-terms)更新于 **2026-09-16**，对 Covered AI Services 单列例外：供应商可为提供服务、安全审查及法定义务保留/审查内容，处理区域也可能不同；管理员可配置这些可选能力。部分功能不适用工作区保留设置，网络检索等也有独立子处理者与区域说明。

**对我们的含义：** 要做按能力、模型、供应商的治理目录，界面显示政策例外；不能只签一个笼统“无训练/本地/境内”条款覆盖所有插件。ZDR 是指定上游的处理约定，不是 SaaS 不存对话，也不是密码学上的服务商不可见。

### 3.4 LegalOn 与智合 AI

[LegalOn 官方产品介绍](https://us-direct.legalontech.com/what-is-legalon)对合同数据不用于其模型训练有公开说明；[其服务条款与 DPA](https://www.legalontech.com/terms-and-conditions)描述逻辑隔离、访问控制、备份及加密等。未核到通用本地 Shell Agent、与云端执行切换相关的完整公开权限矩阵；不得以 Word 插件的存在推定推理或存储在本机，也不得把不同法域版本的合同混用。

[智合 AI 官方界面](https://www.zhiexa.com/guidFile)为动态页面，本轮无法从公开正文取得完整权限/架构文件；[智合官网](https://zhihe.com/)仅足以确认产品背景。**本轮不把其部署方式、原件存储、模型留存、本地文件访问、无人值守、沙箱和写入审批当成已知。** 应通过正式技术问卷/演示按证据补全，不能依据行业印象声称“全部云端”。App Store 开发者隐私自述也不能替代服务端数据处理合同。

## 5. 法律 SaaS 应采用的权限模型（设计建议）

### 5.1 以动作和数据边界授权，而非以“云/本地”授权

建议每次工具执行至少计算以下交集：`律所策略 ∩ 案件权限 ∩ 用户权限 ∩ 数据源权限 ∩ 设备权限 ∩ 工具权限 ∩ 本次授权 ∩ 运行时可用性`。任意明确拒绝优先。云与本地执行器调用同一政策语义，但各自独立校验，不能只信另一端发来的 `approved=true`。

授权分成以下维度，界面可合并呈现，底层不能混成一个开关：

- 能看什么：指定案件、目录、文件、数据库记录；冲突案件排除。
- 能把什么送给谁：本地提取内容→中软网关→Kimi 模型；搜索查询→搜索商；截图→视觉模型；分别检查。
- 能改什么：工作副本产物、原件覆盖、批量移动/删除、系统配置。
- 以谁身份：当前律师的委托身份、案组服务账号、受管设备账号；不得默认为平台万能账号。
- 何时能做：人在场/定时/遥控；授权有效期、次数、额度、指定执行节点。
- 能否对外生效：发信/分享/发布/法院递交/电子签署/付款独立分级。

### 5.2 一个推荐默认值，不制造未经证实的“绝对本地”承诺

| 操作 | 默认执行与数据策略 | 人工确认/可自动化条件 |
|---|---|---|
| 原件导入、OCR、哈希与目录整理 | 原件本地；受控本地解析；必须发送远端 OCR 时另示数据去向 | 预授权案件目录内可自动；不得自动扫描整盘 |
| 起草、审阅、证据摘要 | 本地读取必要片段，经过网关调用合同允许的模型 | 首次建立明确的数据处理授权，按案/用途限界；后续低风险步骤无需重复弹窗 |
| 沙箱代码分析 | 受控任务工作副本；本地沙箱或显式云沙箱 | 已验证隔离且网络受限可自动执行；无沙箱则受控失败，不静默改裸机 |
| 云批量尽调/长任务 | 用户显式托管的材料、租户与案件隔离；短期任务目录 | 显示处理区域、期限、资源预算和第三方；未授权文件不得后台补传 |
| 案件知识检索 | 先 ACL 过滤再检索，取回后再次确认访问范围 | 权限降级与撤销必须影响索引/缓存和在途任务 |
| 本机 Word/浏览器交互 | 限指定文档/标签/应用，单独凭据与设备授权 | 涉外发送/最终提交强制确认；桌面和浏览器可被网页提示注入视为威胁输入 |
| 定时法规更新 | 云端公开信息任务；不需案卷即可运行 | 可无人值守，变更推送按预授权渠道；不把案情全文用作搜索关键词 |
| 遥控本机 | 受信设备在线、身份新鲜、授权未撤销 | 离线排队有期限；不自动迁云、不隐式唤醒全盘能力 |
| 外发合同/递交材料 | 先生成可审阅的收件人、附件、内容摘要与版本快照 | 批准绑定内容哈希、接收方、操作、案号、有效期，内容变动重审 |

所有默认值是建议，需产品/技术团队依据能力实现后验收；不是对当前 demo 已具备能力的描述。

### 5.3 工程上必须分清的六个细节

1. **批准不能被重放。** 票据绑定租户、用户、案件、工具、规范化参数、文件版本、目标节点和到期时间；云本地都核验。
2. **执行副作用不能盲重试。** 定时/断线恢复用幂等键；发信、签署、上传等结果不确定时进入人工核对，不简单重放。
3. **审批服务故障不是授权。** 执行前闸门故障时高风险动作停止；只读、公开信息等低风险能力可按明确定义降级。
4. **撤销有传播 SLA。** 停用用户、撤案权限、断开连接器、失窃设备必须终止后续工具调用、撤短期令牌、处理队列；在途已发送数据无法靠 UI 撤销收回。
5. **日志也是案卷。** 默认留动作元数据；正文/截图诊断按需、脱敏、短保留、客户可见；严禁写入 API Key/Cookie/签名密钥。运维排障走临时授权、双人审批和记录。
6. **隔离要按工具验收。** VM 对 shell 的隔离不能自动证明文件 broker、MCP、浏览器、OCR、预览器隔离。宏、外链、压缩炸弹、路径穿越、符号链接、网络共享和文档提示注入需单独测试。

| 权限及恢复实测 | QA/安全/业务 | 跨案检索、权限撤销、移动端重放、节点离线、重复提交、审批内容变化能拦住吗？ |
| 律师实际任务验收 | 法律产品/试点律所 | 引用可追踪、原件不损坏、修订可接受、产物可复核、重要外发正确阻断吗？ |

竞品只能证明这些设计有实践参照，不能替代我方实现或我方验收。最适合该项目的方向是统一任务与产物体验、明确云地节点、按案控制数据与动作；上线资格由这些可验证结果决定，而不是“完整接入 Kimi Code”这一句决定。

# 调研 C：法律产品、合规与商业独立终审

核验日期：2026-10-09（中国标准时间）。审阅对象：v5 第 2、3、6、7 篇及经济输入，v6 第 2、3、5 篇，v7 第 5 篇及经济脚本。判断由当前任务独立形成；既有研究是待核查材料，不作为外部事实证据。以下“建议”是产品和风险设计意见；监管适用须由实际运营主体按最终数据流落实。

## 1. 最重要裁决

**推荐境内 SaaS 控制面、境内受控云执行、本地执行器共用一套权限和交付体系；由律所政策与事项密级选择执行位置。不能把“所有案卷必须只在所”当成用户已经提出的需求，也不能把“上云”默认等同于违法。** 用户确认采购 API token、按 SaaS 订阅销售及品牌授权；未要求所有用户安装本地客户端、禁止境内受托云处理、强制端到端加密协作。

v5 的主要价值是把法律工作做成可验收交付件，提出原件不可覆写、出处定位、受众分版、签发绑定最终文件等正确要求。v6 正确认识到机构控制、同步和移动入口需要常在线服务，但仍把案卷本地化当不可动摇前提，因此“零服务器”只是没有律所服务器，实际依赖律师电脑在线。本地执行+云端推理并没有消除第三方处理；反而把加密同步、密钥恢复、终端支持、离线撤权等困难一并引入。v7 恢复开放 Agent 能力有价值，但“任何能力弱于标准版都无法定价”的论断不成立：法律产品应该按交付质量和业务效率定价，而不是与通用办公产品做功能数竞赛。

建议的三种可售部署配置：

| 配置 | 谁适合 | 内容如何处理 | 关键限制 |
|---|---|---|---|
| 境内云工作区 | 接受受托云处理的普通团队；无 IT 律所 | 批准材料进入租户/事项隔离的境内存储与短时任务沙箱，推理经境内企业 API | 明确中软与模型商能在服务必需范围内处理明文；不能宣传端到端不可见 |
| 本地工作区 | 有保密约定或客户不接受云存储的事项 | 原件、OCR、索引及文件编辑在端侧；只有批准的必要内容调用境内模型 | 本地执行不等于本地推理；电脑离线时内容任务等待，不偷偷转云 |
| 专有部署/无外部推理 | 特定高敏、客户强制要求的机构 | 经确认的机构环境与模型端点；供应商支持接触单独控制 | 当前只采购 API token 无法提供这项；先标另行交付，不在标准套餐假装具备 |

国家秘密等不适合现有产品资质、环境处理的材料，标准 SaaS 明确拒收；此项不是用户勾选同意可以豁免的设置。其余敏感材料应有分类评估和产品支持边界，不能把“本地”作为自动合法证明。

## 2. 阻断级缺陷及修复

| P0 | v5 用“当事人已同意/无需”控制一整个事项的所有外发 | 委托人通常不能代对方、证人、员工及交易第三人同意；公开可见也不等于可无限制再处理 | 数据准入拆成委托/保密授权、个人信息处理依据、敏感信息特别条件、供应商转委托、出境条件；记录适用范围而非只放一个勾选框 |

| P0 | 把研究“法源已核实”当作结论正确 | 真法规可能不适用事实时点/地域；真判例可能已改判或仅支持相反主张 | 将存在性、版本/效力、出处吻合、对命题的支持、适用性拆开验证；反例与无法覆盖范围显式呈现 |

| P1 | 复制所有标准版能力作为溢价理由 | 复制研发与维护成本高，律师不一定愿意为建站/通用电脑控制买单 | 保留底座可扩展性；GA 只销售通过验收的法律能力；通用工具在受控专家模式开放 |

离职撤权应停止**新的服务端读取和未来密钥发放**，在线设备接收撤权后清理，离线设备在下次联网或租约到期才执行；已导出明文无法收回。硬件密钥与 MDM 可改善可控设备上的执行可信度，仍不等于让过去已经知悉的信息消失。

## 3. 法规与证据核验

### 3.1 《律师法》2026 修正：属实，但须防止“校验自己生成的法源”

本轮独立打开最高人民法院受权发布的主席令，确认 2026-08-28 通过、2026-09-01 施行；北京司法局当前公开全文列明第二十六条律所管理制度、第四十一条保密、第四十二条利益冲突。旧稿这些条号有官方支持，不能仅凭此前常识中的 2017 版条号推翻。全文未见新增 AI 专门条款。[主席令](https://www.court.gov.cn/xinshidai/xiangqing/510011.html)、[北京司法局全文](https://sfj.beijing.gov.cn/sfj/zwgk/2024zcwj/744120751/fl91/744123073/index.html)。

同时，本轮读取的北京司法局转载中个别内部交叉引用疑似仍沿旧条号，说明**官方网页也可能存在排版或整理差错**。生产法源库应保存公布机关、公报版/公布决定、抓取版本、时间和摘要；冲突由法律编辑核对正式公布文本，不以一个页面及模型判断自动发布规则包。仓库演示种子、既有报告、搜索摘要不能充当法规原始证据。

### 3.2 PIPL：按数据与行为建模

已核对《个人信息保护法》：处理依据不只同意；委托处理、公开个人信息、敏感信息、影响评估均有各自条件。加密或化名可降低风险，不能自动视为匿名化。产品应让律所记录适用依据、处理目的、数据主体范围及风险评估，而非替律师自动判合法。[法律全文](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。

基于上述规则的产品设计推论：

- 客户保密授权解决的是律师向技术供应商披露客户信息的约定边界；个人信息法依据解决对自然人数据的处理条件；二者不能互相替代。
- 一个公司客户确认使用 AI，不自动覆盖劳动争议中员工、对方证人或病历涉及者。需要事项目的、处理必要性与法定依据审查；无法建立条件的字段删减、改为人工或限定本地处理，不能凭模型推断授权。
- “公开裁判文书”也可能含个人信息；做某案研究与建立自然人行为画像是不同目的。默认禁止法官画像、自然人背景评分等超范围用途。
- 本地处理同样属于个人信息处理；阻断上云只是减少一种风险，不自动治愈非法来源、越权共享或超期保存。
- 乙方中软、模型商、OCR/搜索/存储厂商等按真实活动定角色，不因产品叫 SaaS、代理或软件授权自动改变。

《网络数据安全管理条例》第十二条明确了提供、委托处理个人信息和重要数据的约定、监督及记录要求。应维护版本化受托/转委托清单，变更后重新判断是否扩大范围，而非把所有上游简单写作一个“Kimi”。[条例](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm)。

### 3.3 境内云、香港上市公司与跨境

中软国际香港上市这一事实本身不能推出案卷必然出境。要看运营实体、模型与工具处理地点、日志与备份位置、供应商支持、境外管理员/香港团队的访问权限，以及面向境外发送结果的路径。境外主体可访问境内数据亦可能属于数据出境；密文不是自动豁免。[网信办数据跨境说明](https://www.cac.gov.cn/2024-03/22/c_1712776625820516.htm)、[网信办 2026 年 7 月问答](https://www.cac.gov.cn/2026-07/24/c_1786638883119336.htm)。

建议标准版：境内签约运营、境内生产与灾备、境内模型/API 端点、境内运维人员白名单；全球支持默认只见脱敏工单。境外访问和跨境法域事项单独准入，不能用香港上市或海外客户的标签替代出境判断。重要数据识别遵循相关目录、通知及规则；不应把所有案件材料自动认定重要数据，也不应因未出现客户姓名就认定不是重要数据。

### 3.4 律协指引不是全国统一禁止云处理的法律

上海律协 2025 居村顾问指引明确自身非强制性、参考性，并定义本地化部署；2026 企业法律顾问指引有独立适用场景。可以据此提供保守预设与评估模板，不能把某份指引的建议转换成全国所有律所的云端禁令。[2025 指引](https://info.lawyers.org.cn/info/71624f5df3184a90941f317aca231c18)、[2026 指引](https://www.lawyers.org.cn/info/10aadc765e124cb4ac999d47cda0b0a8)。

v5 摘要把敏感类型称作“五类”，但上海原文包含宗教信仰、特定身份等，不宜把摘要列表做成穷尽名单。2025 指引注明试行一年，本轮没有取得其续期决定；用作方法参考时必须标注，不能称“现行强制要求”。深圳 2026 指引本轮搜索未取得协会官方全文，既有 v5 调研自己标为律师博客二手转载；最终文本却多处提升为“一手”。**必须纠正证据等级**，未经原文核验的具体条号不得作为自动合规判断的唯一规则。

小型个人信息处理者简化措施有网信办 2026-07-24 官方答记者问支持其存在；但“多数律所都适用”和“直接内置附件格式”仍需核对正式规定、适用人数口径与实际律所数据范围。不能把单家律所规模简化外推为中软多租户平台同样享有豁免。[官方问答](https://www.cac.gov.cn/2026-07/24/c_1786638889576451.htm)。

### 3.5 登记、等保、标识应区别法定义务与采购策略

网信办 2026-09-14 公告明确直接调用已备案模型的应用/功能由地方网信办开展登记，且给出公示要求；最终适用还要结合服务范围及属性。B2B 收费不自动豁免，也不能把客户内部使用排除条款不加判断地适用于公开招揽所有律师的 SaaS。[备案登记公告](https://www.cac.gov.cn/2026-09/14/c_1791136833136332.htm)、[暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)。

“按三级控制目标建设”是合理商业安全目标，但不等于已依法定级三级、更不等于已经测评。定级对象、边界及等级由适用程序确定；同集团已有证照不自动覆盖新增运营主体、域名和系统。ICP、电信许可、App 备案、商用密码适用应列责任人、法律依据、办理状态、验收凭证；不能用“与网信咨询同一次完成”低估不同主管机关流程。

AI 标识规则为无显式标识版本提供附条件路径，并非所有交付件绝不能有干净版。隐式标识、用户义务、导出日志应结合适用范围实现，不得用“律师签发”自动消除平台义务；技术元数据保留与专业保密同时设计。[标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)、[官方说明](https://www.cac.gov.cn/2025-03/14/c_1743654685896173.htm)。

## 4. API 采购与合同：旧稿有正确阻断项，也有过度推导

当前官方协议明确允许通过 API 向最终用户提供服务，同时限制账号转交、权利再许可，并保留输入输出服务优化使用权。故“采购 token 做法律 SaaS”不能简单等同裸 key 转售；用户既有品牌授权按事实接受，登记授权范围和有效期即可。需要解决的实质条款是法律数据用途、保留、支持访问、转委托、责任及可用性。[Kimi 开放平台服务协议，2026-08-31 生效版](https://platform.kimi.com/docs/agreement/modeluse)。

建议合同交付包（属于设计建议，不表示现有 API 合同已具备）：

| 文档/证据 | 必须解决的问题 |
|---|---|
| 上游企业数据处理附件 | 不训练与不用于一般服务优化的范围；chat、图像、文件、搜索、抓取、缓存等逐接口保留矩阵；境内处理地点；可接触人员与次处理者 |
| 业务许可范围表 | 中软以自己服务向最终用户收费、品牌/布局授权覆盖范围；如有裸 API/token 渠道转售则另行约定；不得把上游主 key 发给终端 |
| SLA 与变更机制 | QPS/并发与限速隔离、模型弃用通知、版本回归窗口、故障支持；客户承诺不能高于实际可实现且无补偿预算 |
| 数据退出与删除附件 | 租户导出、备份到期、法律保全、上游删除与日志例外、无恢复能力的情况；不以“ZDR”一个词替代完整矩阵 |
| 责任与保险 | 服务缺陷、数据事故、内容质量与律师执业责任分别分配；旧标准协议上游责任限额可能远低于中软承诺，须商务处理这一缺口 |

ZDR 的目标是减少持久留存；推理时模型服务必须读到输入，故不等于“不接触明文”。“不训练”也不等于“不留存”；“不存正文”不等于没有日志；搜索没有客户姓名不等于没有可识别案情。

## 5. 法源、律师交付质量与产品边界

v5 最值得保留的是交付件规格，不要随着底座放权丢失这些专业门禁。首发必须给每个场景明确支持法域、材料范围、交付格式、待律师确认项、失败状态和评测报告。现有“生产/Beta/模板”三档成熟度合理，但销售页面与配额计费应一致。

法源可得性与商用许可分开。《著作权法》第五条排除特定官方文件，不意味着商业数据库的编辑摘要、检索结构、接口、案例集及平台访问条款可以任意复制再分发。[国家版权局法律全文](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)。

数据商许可逐项谈：检索、全文拉取、临时缓存、索引/向量化、送入第三方模型、摘录导出、客户工作成果留存、终止后的访问、审计/评测使用、是否可面向多租户转供。前台显示一个 MCP 插件可连不等于已取得以上权利。先做官方法规版本库+签约商用案例源；若案例许可未完成，限定资料研究可售，但不能宣传完整类案库。

建议把质量要求增加为以下可验证条件：

1. **正确拒绝和范围覆盖**：每个任务显示实际读取材料、失败页、未取附件、法规范围、检索停止条件；覆盖不足不能显示完整审查通过。
2. **事实与推论分开**：材料记载、当事人主张、模型推论、律师采纳分状态；源文页码与输出结论一一可追溯。
3. **引用支持度**：来源存在不等于支持该命题；法条生效/失效与事实发生时间分别记录；判例层级、审级、是否改判、类案差异显示。
4. **原生文书质量**：Word/WPS 真修订与批注；接受全部后与批准内容一致；长表、节、页眉页脚、脚注、目录、交叉引用回归；不能只验截图好看。
5. **签发的实际含义**：内部批准/电子签名/盖章/送达分动作；设备签名本身不自动等于法律上可靠电子签名，更不自动证明签发人看过每页。
6. **程序期限**：送达事实与规则版本必须可审查；默认只产生待确认期限，二人确认后提醒；短信/IM 未送达不能当提醒已完成；支持升级通知和节假日/送达方式专项测试。
7. **伦理墙全链路**：检索召回、向量索引、缓存、共享链接、导出和客服都做事项权限；管理员不能只因为管账单就看到所有案卷。
8. **真实效果**：报告含盲测与实际工作时长，统计“修到可交付”的总时间，不只统计生成时间；所有拟定 95%/99% 阈值必须标为目标，不能当实测。

产品完整性并不要求第一版把所有民商事、刑事、跨境、尽调、会见、翻译同时卖作成熟能力。完整产品的含义是承诺范围内能开通、使用、协作、交付、收费、报障、退出，范围外有准确降级和承接路径。

## 6. 移动端与 IM：建议重新分配首发范围

IM 是触发、通知、收件渠道；不应承担完整权限控制中心。平台已经看见的消息与附件、文件名、下载凭证以及回调元数据均属数据流。普通事项可在管理员启用并完成平台条款评估后收件；高敏事项只收无内容通知。所有材料进隔离收件区，先验身份、文件安全与目标事项权限，再入库。

手机默认：看状态、收通知、补充澄清、审阅允许的摘要/文件；高影响动作必须显示最终对象与确切交付文件。审批不能仅是“同意 AI 继续”，还要包括预算变化、上云、对外提交、收件人改变等可理解信息。远程发起的任务不能扩张既有本地目录权限，IM 身份不能替代设备授权。

H5 可作为低风险移动入口；高敏解密与签发确需更多保护时提供 App，但 App 是成本和能力选择，不是端到端安全的证明。首发没有必要为了“所有能力不弱于标准版”同时造独立双端 App、三个 IM 集成和电脑遥控。先一个主流 IM+移动 Web 通知/轻审阅，复杂签发桌面完成；云工作区让电脑离线时任务照常执行；本地工作区明确等待本地执行器。

## 7. 经济模型与商业裁决

v5/v6/v7 有可复算脚本优于纯拍脑袋，但精确算出的五年结果只是输入假设的投影，不能把某年盈利或某金额资金峰值当可承诺结论。本轮不复用其精确增长、亏损与现金谷底。

独立检查 v7 `seat_economics`：超额需求乘以固定购买比例后直接产生加量收入。因此“Agent 使用翻倍利润反而提高”主要依赖加量购买及收费假设，不能证明真实开放 Agent 越用越盈利；实际可能是更多无效重试、预算流失和用户不买。模型已经列若干敏感性，建议进一步拆出真实可观测变量：

| 变量 | 必須观测的口径 |
|---|---|
| 一个可接受交付件成本 | 模型输入/输出/缓存、全部失败与重试、子 Agent、OCR、搜索、法源、沙箱存续、存储/出网和回归分摊 |
| 活跃与需求 | 付费席位、月活席位、实际审阅席与生产席、事项数、已采纳成果；不可把登录当价值 |
| 客户接受价格 | 套餐报价→实际成交→续费；基础席位与能力/算力加量分离；审阅席不宜成为协作扩散阻力 |
| 销售和交付 | 试点免费期、采购周期、渠道分成、驻场培训、WPS/杀软适配、失败退费、支持工时、客制化实施 |
| 资金占用 | 税费、上游充值/最低承诺、法源固定费、应收/坏账、SLA赔付、退订退款、年付预收的履约责任 |
| 使用尾部 | 单任务 P50/P95/P99 与月度重度用户分布；每个子任务真实硬预算、租户并发和上游配额 |

应保留**无加量收入、零缓存命中、重试增加、成交折扣、转付费率下降**的联合压力情景；单因子敏感性不足以覆盖坏情形相关性。云处理的 OCR/算力不能继续沿用 v5 的零云成本；本地 OCR 也有终端支持、耗电、时间、兼容维护成本。自带密钥套餐需要说明客户端/云执行/法源/服务费各自价值，不能只减去 token 成本。

建议价格先作为待验证报价区间，而非确认价格。用 6–10 家覆盖不同规模和业务的设计合作律所收集 6–8 周真实使用数据，设置立项预算阶段上限；每阶段按付费意愿、留存、交付件采纳、支持成本、安全质量决定扩张。不得以未经核实的竞争产品价格、用户数或“某通用模型同底座背书”支撑财务确定性。

## 8. GA 前的证据门禁与可接受取舍

| 门禁 | 可签字验收的证据 | 未满足时的降级 |
|---|---|---|
| 商用数据权利 | 上游数据条款、数据商许可、受托清单与运营主体确认 | 合成/公开演示；限制不具备许可的任务 |
| 租户/事项隔离 | 越权读取、搜索/缓存穿透、连接器对象切换、附件URL、支持访问红队报告 | 不接真实案卷 |
| 执行隔离 | 云任务沙箱、本地执行器的出网、挂载、凭证、进程与资源边界测试 | 降为受控工具与只读任务，暂停高风险开放执行 |
| 工具外发 | 确切对象批准、幂等、防重、断线结果对账；程序文件注入不能自动授权 | 禁止自动发邮件/提交，仅导出人工处理 |
| 文书与法源 | 法律团队签字的盲测、出处支持度、原生修订/复杂格式回归 | 明确 Beta/限定资料研究，不能称生产完整审查 |
| 恢复与退出 | 租户恢复演练、密钥丢失流程、备份到期删除与法律保全、开放格式导出 | 有限试点，不提供未验证的数据持久性承诺 |
| 商业运维 | 按对象的 SLO、账单对账、支持值班、事故通知、数据泄露演练、版本回退 | 小范围受控开放 |
| 监管与安全资质 | 实际适用事项的办理凭证/合规结论；标识/公示及投诉通道 | 未满足适用条件不得公开销售 |

总体日历不能反推门禁一定会通过。可售范围必须是实际通过门禁的功能集合；既要避免永远只做 demo，也不以“最完美”措辞掩盖未验证能力。
