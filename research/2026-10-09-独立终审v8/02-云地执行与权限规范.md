# 02 云地执行与权限规范

## 1. 第一性原理：先定义谁能处理什么，再选择位置

一个动作至少包含：人、所属组织、事项、输入对象及版本、处理目的、工具、执行环境、接收者、时间、预算、输出去向。只写“本地/云端”无法判定是否合法、可用或安全。

工程上拆开七个轴：

| 轴 | 选项或问题 | 不可混淆之处 |
|---|---|---|
| 原件与派生数据存储 | 本机、客户服务器、中软境内对象存储 | 静态加密不等于服务商无法解密 |
| Agent编排 | 本机、律所执行器、中软worker | 编排会接触上下文，不能当纯元数据服务 |
| 工具执行 | 本机OS沙箱、云沙箱、受管连接器 | 本机工具也可能联网，云工具也不能默认访问电脑 |
| 模型推理 | Kimi境内API、律所自有端点、禁用 | 本地Agent调用API仍然把输入送出设备 |
| 控制与运营 | 身份、政策、订阅、计费、调度、更新 | 可以在云且不保存全文，但仍处理身份与敏感元数据 |
| 人工权限 | 经办、复核、签发、管理、支持 | 购买席位和管理设备不授予所有案卷阅权 |
| 触发与副作用 | 桌面、IM、定时、远程；只读、写草稿、正式发布 | 手机遥控不等于云端执行，运行完毕不等于正式发出 |

推荐默认体验：账号登录桌面→选择或新建事项→材料默认本机导入→明确该事项是否启用托管协作和云执行。管理员可设C为本组织新建事项预设，但首次上传仍展示范围，不能因加入团队自动上传整盘材料。

## 2. 两个主预设与一个专有配置

| 属性 | L 本地保密事项 | C 标准协作事项 | P 专有部署（另行交付） |
|---|---|---|---|
| 主入口 | 桌面；Office桥 | 桌面；Web/移动补充 | 受管桌面/内网 |
| 正文权威存储 | 客户设备/获准所内存储 | 中软境内租户事项库 | 客户控制环境 |
| 云同步 | 关闭或可选E2EE密文同步 | 租户隔离、服务端静态加密 | 客户内网/私有存储 |
| 谁能解密存储 | 已授权设备和恢复主体 | 授权服务进程；运维受限但不能称技术上永不可见 | 依部署与密钥责任矩阵 |
| 内容执行 | 本机或逐事项授权的律所执行器 | 本机交互工具+获准云worker | 客户执行器 |
| 推理 | 可发送已获准最小输入至境内API，或禁用 | 获准境内API | 私有模型或明确允许的API |
| 关机内容续跑 | 仅已授权且在线的执行器；否则等待 | 已上传快照可续跑；若仍需本机文件则等待 | 看客户执行器可用性 |
| 手机预览 | 首发只通知/状态；正文解密客户端独立验收 | 受管Web预览和审阅 | 依客户接入条件 |
| 管理与计费 | 中软云 | 中软云 | 可私有控制面；许可另设计 |
| 适用 | 文件夹工作、本地敏感约定、客户拒绝云存储 | 小团队协作、跨设备、后台批量 | 严格内网/客户强制要求 |

L不是“绝不出域”：若允许Kimi API，模型网关仍会接触相应输入。C不是“上传所有案卷”：只处理列入授权快照的对象。P也不是允许涉密的通行证；未满足专门条件的涉密材料在所有标准形态拒收。

**单个事项只能有一个权威提交位置。** C以服务端版本登记为准，端侧是缓存/工作副本；L以签名事项账本和明确成员/版本协议为准，中继仅传密文。不能让云库与本机库同时自称同一版本的最终状态。

迁移L→C：负责人确认目标区域、数据清单、第三方、保留政策；创建迁移记录与新策略版本；暂停新写入、复制校验、切换权威位置、恢复任务。迁移C→L：导出、完整性核对、客户接管、关闭新云任务、按合同删除云副本与备份；不能因切开关就声称历史云副本不存在。

## 3. 目标结构

```text
桌面 Kimi Work 法律发行版（统一任务/事项/成果/审阅）
  ├─受信本机内核：事项权限、材料版本、Office桥、密钥、审批
  ├─Kimi Code Adapter → 本机任务沙箱（只读输入 / 可写草稿）
  └─数据与工具 Broker → 模型 / 检索 / 法源 / 获批连接器
                     ↓
中软境内服务
  ├─控制面：账号/机构/设备/订阅/政策/预算/通知/调度
  ├─C内容面：事项库/对象存储/索引/版本/审批/交付登记
  ├─L密文中继：可选；不授予内容执行钥匙
  ├─执行面：同一Adapter + 每任务云沙箱 + 受控工具
  └─模型网关 → MaaS法律分组 → Kimi企业API
可选律所执行器：出站领取授权任务，共用协议，逐事项授予数据权
```

云端提醒、身份和计量不进入任务沙箱。解析器、模型循环、可执行代码、浏览器、连接器、签发服务是不同信任边界，不能在一个高权限Node进程里把函数名当隔离。

## 4. 功能放置与数据流

| 功能 | 默认位置 | C变化 | L限制/说明 |
|---|---|---|---|
| 登录、账号订阅、团队席位 | 云控制面 | 相同 | 断网可本机解锁已有数据；不能离线新购/新增成员 |
| 文件夹选择/原件快照 | 本机 | 按明确清单上传 | 不扫描父目录；不能远程扩大挂载 |
| 安全解析/OCR | 本机隔离进程 | 已上传大批量可在云解析 | 外部OCR不作为自动回退 |
| 索引/向量/摘要 | 跟随内容权威位置 | 服务端按事项隔离 | 本机生成；外部embedding也是出站 |
| 合同确定性校验/比对 | 本机 | 可云执行同一组件 | 离线可做非模型步骤 |
| 开放任务Agent | 本机沙箱 | 显式指定云worker | OS隔离未达标则关闭不可信代码能力 |
| 法律模型推理 | 网关→Kimi API | 同上 | 减量/化名按任务适用，仍是数据处理 |
| 法源与案例服务 | 云工具broker | 同上 | 只发已允许查询；断网用已覆盖离线法规 |
| 方法包 | 签名版本注册表 | 云工作流按版本装配 | 获授权方法副本下发；不承诺不可提取 |
| Shell/Python/Node | 任务沙箱 | 云沙箱 | 预装库，无宿主HOME、无默认网络 |
| 公开浏览器 | 独立浏览器profile | 可云公开浏览器 | 本机站点操作受限，搜索/URL也泄露查询 |
| 登录态浏览器/桌面控制 | 本机专用broker、默认关 | 云端不继承桌面登录态 | 指定应用/站点/时间，不能打开整个浏览器配置 |
| Word/WPS写回 | 本机宿主 | 云回传patch，端侧复核版本 | 不把Office进程挂进Agent沙箱 |
| 审阅/签发 | 业务审批服务+人的会话 | 可受管Web确认 | 本机签名；离线正式发布须符合离线批准策略 |
| 期限提醒 | 云scheduler | 相同 | 只同步经确认的必要日期与路由；若禁元数据上云则本地提醒并说明限制 |
| 事项周报/批量 | 数据获准的执行器 | 云可24小时 | 无在线客户执行器则排队 |
| IM收件 | 独立入口服务 | 可持久收件后归档 | 先进入收件区；路径需平台支持，不保证所有平台直取 |
| 审计 | 操作元数据云；内容跟随事项 | 云内容审计按案ACL | 正文记录加密在客户侧；不默认管理员会话回放 |
| 更新/规则发布 | 云CDN+签名 | 相同 | 私有客户离线签名包另验 |

## 5. 权限计算与强制位置

有效权限是下列集合的交集，任何显式拒绝优先：

`产品硬基线 ∩ 机构政策 ∩ 人的角色/事项成员资格 ∩ 对象ACL ∩ 数据源许可 ∩ 事项数据策略 ∩ 执行器能力 ∩ 渠道权限 ∩ 本次授权 ∩ 预算/时间`

许可校验与法律处理依据检查是两个条件：有API权限并不代表有权把这份材料发给它。管理员批准的连接器也不能突破客户的禁止条款。

| 强制点 | 必须校验 | 失败行为 |
|---|---|---|
| 任务受理 | 发起人、事项、输入版本、数据政策、处理依据、执行位置 | 拒绝或要求补齐，禁止先处理后补单 |
| 对象读取/检索 | tenant、matter、对象版本、当前成员/伦理墙、数据源权利 | 不泄露标题/命中数，不只过滤最终答案 |
| 每次工具调用 | schema、参数、动作、运行身份、委托链、范围、有效期 | 不能由上游approve跳过 |
| 出站broker | 接收者/区域/用途、内容类别、budget、图像/附件、重定向 | 校验不可用则停止相关出站 |
| OS执行边界 | 实际文件、进程、网络、IPC、资源 | 不可隔离则不运行不可信代码 |
| 产物promotion/发布 | 文件类型与外链、引用门禁、基线、审批、受众、最终hash | Agent只能写草稿，不能直接写交付目录 |

任务能力令牌为短期、限定audience的凭证，示意字段：

```json
{
  "tenant_id":"t1", "principal_id":"u1", "matter_id":"m1",
  "run_id":"r1", "attempt_id":"a2", "fence":17,
  "executor_id":"device-or-worker", "channel":"desktop",
  "policy_version":31, "membership_epoch":8,
  "input_manifest_hash":"...", "tools":["file.read","draft.write"],
  "destinations":["approved-model-gateway"],
  "budget_reservation_id":"b1", "expires_at":"...", "aud":"tool-broker"
}
```

初始建议令牌有效期5分钟、可续租；高风险操作即时检查撤权与授权版本。这个时间是待SLO验证的产品参数，**不能靠短TTL承诺离线即时撤权**。禁止客户端自报tenant切换租户；不要向沙箱发上游API主钥匙、数据库账号或S3通用凭据。

## 6. 用户运行模式与批准

界面三档足够：**只读分析、标准执行、自动草稿**；“先出计划”为独立开关。手动逐步确认可放高级设置用于敏感调试，不作为沙箱不足时的安全补偿。

| 动作 | 只读分析 | 标准执行 | 自动草稿 |
|---|---|---|---|
| 已授权事项内读取/分析 | 自动 | 自动 | 自动 |
| 沙箱新草稿/表格/计算 | 不运行或改为标准 | 自动 | 自动 |
| 已批准来源的普通查询 | 按事项用途/预算 | 自动 | 自动 |
| 原计划以外的研究步骤/子任务 | 不自主扩展 | 实质改变计划时确认 | 同目的、同材料与工具、同预算内可重规划；仍不得扩大数据权限 |
| 新目的地、实名查询、原图发送 | 新授权 | 新授权 | 新授权 |
| 扩材料/跨事项/扩大费用 | 单独授权 | 单独授权 | 单独授权 |
| 覆盖原件/正式稿 | 人工文件操作 | 人工文件操作 | 人工文件操作 |
| 签发/发函/递交/付款/权限修改 | 人工业务操作 | 人工业务操作 | 人工业务操作 |

许可可在任务创建时一次批准明确定义的范围，例如“本事项20份合同、指定Kimi端点、授权法源、上限50元、只产草稿”。不要每次同范围低风险读文件都弹窗；也不要提供脱离对象范围的“永远允许”。审批绑定主体、事项、动作、参数hash、对象版本、目的地、收件人、期限、nonce。执行前重验；材料、收件人、成本或策略变化超出批准范围则重新批准。

## 7. 人、渠道和Agent不能互相代替授权

| 主体/渠道 | 可做 | 不可因此获得 |
|---|---|---|
| 经办律师 | 本人事项读写、授权任务、提请交付 | 其他事项、机构管理、自动签发权 |
| 助理 | 被授权材料整理与起草 | 默认签发或外发权 |
| 合伙人/指定签发人 | 所授权事项的审阅与签发 | 全所案卷访问权 |
| IT/财务 | 设备/政策/订阅/账单 | 案卷正文或会话回放 |
| 风控/利冲 | 经明确授权的目录/审计信息 | 自动所有正文阅权 |
| 平台支持 | 脱敏诊断；逐次批准的短时支持访问 | 常驻跨租户超级阅卷权 |
| 桌面 | 获准任务；本地资源选择 | 全盘访问 |
| Office加载项 | 当前文档相关操作 | 从一个窗口扫描所有本机文件 |
| IM | 收件、模板触发、进度与通知 | 任意命令、自动执行新增目录、卡片转发扩权 |
| 手机遥控 | 已配对设备上的授权任务、受限确认 | kap-server管理路由、shell终端、安装插件、扩大挂载 |
| 定时 | 已批准模板和快照/选定源 | 自己给自己批准新数据外发 |
| 子Agent | 父任务权限的子集、预算份额 | 任意新的连接器和跨事项上下文 |

远程通道采用设备主动出站+相互认证，但“只出站”只解决入站暴露，不证明内容加密或不被供应商读取。L遥控内容若承诺E2EE，需独立配对、重放防护、密钥轮换和可审核协议；不使用透传整个kap-server的通用隧道。远程任务在本机执行时，电脑离线就等待。

## 8. 数据流与降敏规则

以下全部属于受保护输入或派生信息：原件、解析文本、OCR、图片、截图、邮件头、搜索式、嵌入向量、长任务摘要、子代理上下文、工具回包、交付文件、文件名、事项名、用户反馈及日志。索引和摘要不是“没有原件所以不敏感”。

出站逐类记录目的地、用途、区域、来源对象、载荷类别、时间、审批/政策版本、用量、供应商请求ID。正文或原始搜索词按事项内容策略保存，运营日志只保留必要元数据；日志正文不再次复制到全局APM。

**化名是减风险工具，不是数据出站合法性的证明。** 只对已允许的目的和接收者外发。标识符和实体识别未命中不自动降级为公开。允许建立经律师批准的泛化查询模板，在范围内自动检索；企业名称查询确实必要时，向律师说明目的地和用途后明确授权，不偷偷删除名称导致查错主体。

严禁对Shell脚本、可执行参数或路径做模型返回后的自然语言替换。文件、实体和锚点采用稳定ID，文书渲染层按类型还原；模型要编辑某段时提交`document_version + anchor + expected_text_hash + proposed_text`，内核验证后生成修订。需要原始图像时独立判断并展示，不能隐藏在ReadMediaFile内。

网络强制包括HTTPS、DNS、IPv6、回环、重定向、WebSocket、下载器和子进程。抓取代理防SSRF：拒绝私网/链路本地/元数据地址，DNS解析和每次重定向重新校验，允许列表不能只看域名字符串。浏览器页面、搜索结果、材料中的指令均为不可信数据。

## 9. 沙箱最低标准与降级

每个活动任务/尝试独立隔离：只读输入快照、只读可信方法/配置、可写scratch/output、不可写正式交付库；不挂载用户HOME、凭据目录、Docker socket或其他事项。代码默认无网，合法联网由沙箱外broker代做，broker也不得接受任意HTTP透传。资源有CPU/RAM/时间/磁盘/子进程上限。

Windows选型通过PoC决定，优先少数可支持的强隔离实现；macOS/Linux分别验证。不把五种沙箱同时维护作为首发目标，不把某开源参考实现的存在当本项目已经可用。网络、文件和子进程是分别验收的能力，不给一个模糊“A级”替代实际测试。

不能达到最低隔离时：可信解析/比对/确定性工具可以运行；通用代码执行关闭。C事项可提示改在已验证云沙箱执行；L不得静默上传，也不得换成管理员权限裸跑。低配电脑默认并发1，16GB起验证2；更多子代理可排队，而非并发越多越“完整”。

## 10. 密钥、同步、撤权与删除

**签名、解密、恢复分三类密钥。** 每设备独立签名钥匙与证书/公钥登记；不把同一签名私钥扫码复制到所有设备。跨设备通过包裹数据钥匙获得阅权，设备吊销可具体定位。硬件不可导出的密钥不能同时设计为可跨设备备份恢复；身份恢复后给新设备新钥匙，保留旧签名验证链。

C：KMS信封加密、每租户/事项隔离上下文、服务最小权限、密钥访问日志；客户管理密钥可选，但有权服务仍可解密处理，不能称E2EE。业务管理员默认无正文访问；平台紧急访问走JIT、双人审批、原因、限定范围和客户通知。

L密文同步：使用经安全审阅的成熟密码协议与库，不自创密码算法。服务器保存最小成员/角色元数据便于租户/设备鉴权，内容钥匙只包裹给获准设备/恢复主体。禁止共享写签名私钥；同步采用不可变对象、版本向量/父版本、明确冲突版本，授权变更有顺序及纪元；哈希链不代替业务冲突解决。

恢复：个人随机高熵恢复码+第二已授权设备为优先路径；机构可选择双人恢复或客户HSM。恢复主体能做什么写入安全白皮书。不能用“管理员确认”软件流程声称持有完整恢复秘密的人数学上无法绕过。创建真实L事项前完成一次恢复验证，用户只看到“备份可恢复”结果，不强迫每位律师理解Shamir。

撤权：云端立即拒绝新的读/工具/计费与令牌续期；在线设备接收撤权，终止任务并清理缓存；离线设备在重新联网或本地租约到期后收紧。新版本更换密钥，旧数据是否已被获取不可收回。声明中明确在线传播SLO和离线窗口。

删除：对象→索引→向量→运行状态→导出临时包→设备缓存→备份→恢复材料逐项记录。状态至少为“在线副本已删 / 等设备上线 / 备份待到期 / 法律保全 / 外部已交付不可撤回”。恢复旧备份先重放删除与撤权记录，不能复活已删事项。保全授权与伦理墙分别校验，不能任何成员随意阻断全所依法删除。

## 11. 故障行为

| 情形 | 明确行为 |
|---|---|
| 笔记本断网 | 可读缓存、编辑草稿、比对和本地已覆盖法条；推理/新授权/远程法源等待 |
| 电脑关机 | C已上传纯云任务继续；L等待客户侧执行器；混合任务卡在未完成的本机步骤 |
| Kimi/MaaS不可用 | 保存检查点、有界重试；不换未批准供应商、不把模型失败标成功 |
| 控制面故障 | 本机非网络工具继续；已有云任务仅在有效租约/预算/政策内继续；失效后暂停，不声称全部可用 |
| 云或本机worker崩溃 | 从业务检查点恢复，新的attempt/fence；副作用结果不明先对账 |
| 收件链接过期 | 可重新取凭据则重取；否则标未取得并让用户重传，不能显示已归档 |
| 上游搜索失效 | 展示缺失来源与未履行查询；限定资料研究继续，不能声称完整检索 |
| 账号订阅到期 | 停止新增计费任务，保持导出/本地阅读与验证；云只读/保留期限依合同明确 |
| 本地磁盘不足 | 停新任务、保存已有可确认状态；不静默转云或覆盖原件 |

上述权限语义在桌面、云worker、律所执行器一致；各自都要强制校验，不能因为同一代码仓库就假设边界天然一致。
