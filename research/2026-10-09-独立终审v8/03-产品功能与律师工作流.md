# 03 产品功能与律师工作流

本篇是完整产品规格基线建议，所有“首发”均指通过第06篇验收后的可售范围，当前原型不因此自动具备这些能力。

## 1. 产品与用户

定位：**律师桌面上的事项工作台，以 Kimi 驱动受控 Agent，以法律规则、证据和文书工程形成可复核交付件；账号订阅，个人可用，团队可协作。** 保留获授权的 Kimi Work 设计语言、留白、配色、任务输入、产物面板与工作区交互；具体组件以授权设计资产为基准，不凭记忆重画一套“像 Kimi”的界面。

律师购买的核心结果是减少从材料到可交付文件的总工时，并降低漏项和版本混乱。模型生成速度、Agent 数量、功能卡片数都不是主要价值指标。测量“律师完成复核并交付”的时间，计入改错、核出处、排版和恢复时间。

| 用户 | 第一项价值 | 默认权限 | 订阅关系 |
|---|---|---|---|
| 独立律师 | 审合同、核来源、输出可编辑修订稿 | 自己事项；自己复核，不伪造合伙人审批 | 一账号即可购买，个人空间与律所空间隔离 |
| 经办律师/助理 | 整理案卷、产出初稿、回稿追踪 | 获分配事项；不能默认代合伙人签发 | 生产账号或受限协作账号 |
| 合伙人/复核人 | 快速定位关键风险、依据、修改与缺口 | 获授权事项的完整指定成果 | 审阅账号可不含模型额度；仍有完整权限保护 |
| 风控/知识管理 | 规则与模板质量、利冲、合规使用 | 目录/规则发布职责；内容阅卷另授 | 治理功能按组织方案提供 |
| IT/财务 | 席位、设备、账单、服务健康 | 默认无案卷正文权 | 管理账号不等于业务超级用户 |

## 2. 信息架构与核心页面

桌面侧边栏：新建任务、事项、收件区、交付件、方法库、定时与提醒、连接与数据、设置。管理控制台负责组织/账单/策略/设备/服务状态。首页不塞36个功能入口，按“审合同”“整理材料”“法律研究”展示已验收场景，其他以方法库筛选。

任务输入保留 `/` 方法、`@` 材料/事项、`+` 导入；输入框同时显示事项、执行位置和授权模式。开始任务前只询问会改变法律判断或数据边界的缺失信息：立场、法域、关键日期、文件范围、受众、模型/检索许可。能从事项已有资料可靠取得的字段预填并标出处，不重复问。

任务页采用三栏：左侧材料与覆盖情况，中间计划/进度/澄清/决策，右侧成果预览。进度展示完成的文档/章节，不伪造百分比；可展开子任务，不暴露冗长模型思考作为“法律推理证据”。审批卡独立于聊天文本，模型不能生成一段“已批准”就触发权限。

事项页固定显示：事项负责人、立场、地域/法域、法律分析截止日、C/L数据预设、执行节点、授权模型与外部来源、保留策略、待确认事实。将技术隔离级别放设备详情；律师主要看到“可安全运行代码 / 本机仅支持标准工具 / 等待设备上线”，不要求理解A/B/C沙箱代号。

## 3. 首日体验与文件规则

1. 安装签名客户端，账号登录；可先使用合成示例，无需建三人组织或打印多张恢复卡。
2. 创建个人或律所事项。默认本地导入；组织如选择C默认，首次真实材料托管时清楚说明数据位置与范围，确认后才上传。
3. 拖入文件、挂载选定目录或从Office当前文档导入。挂载是引用，不是全盘读取授权；子目录、符号链接、网络盘分别校验。
4. 建立不可变任务快照，显示原件/附件/失败文件。引用原路径模式遇源文件变化要刷新快照；不得静默继续读新内容。
5. 选择方法和立场，看到预计费用区间、最大预算和数据接收方；运行并处理关键澄清。
6. 在Word/WPS复核修订、核出处、处理待确认事项，形成受众版本；签发及归档绑定确切版本。

“30分钟得到首份可用成果”保留为试点体验目标，必须按文件长度、扫描质量、机器条件和人工复核时间报告达成率，不作为所有案件承诺。

## 4. 三条首发业务闭环

### A. 合同审查—修订—回稿—交付

**输入**：DOCX优先；PDF可审阅但不承诺重建原生修订；合同类型、律师立场、商业目标、附件、适用法与截止日、本所规则版本。合同中声称的事实是材料主张，不自动是真实事实。

**流程**：解析结构与覆盖清单 → 定义/金额/日期/附件交叉检查 → 法律强制规则+立场Playbook+本所覆盖层 → 生成风险卡及替代条款 → 律师接受/修改/拒绝 → 文书引擎写原生修订 → 对方回稿三方比较（原始稿/我方发出稿/对方回稿） → 重审变更和受影响定义 → 受众检查 → 复核签发 → 归档。

**风险卡字段**：原文锚点、风险事实、法律/商业属性、严重度、适用前提、依据与核验状态、首选修改、可谈判备选、需要客户决定的事项。不能用“高风险”代替解释，不得把偏好包装为法律禁止。

**交付件**：审查报告.docx、带修订合同.docx、问题清单.xlsx、关键商业决定清单、引用与覆盖清单、独立签发证明。发给对方版本剥离内部谈判底线、内部评论、隐藏属性与未授权材料。

**首发内容**：先验证采购/买卖、服务、保密、软件许可及实施4类×双立场；通过后扩至v5的9类×双立场（股权转让、技术开发、商业租赁、借款担保、劳动及配套）。这是上线顺序调整，长期18套规则资产保留。未验收类型显示“通用辅助阅读/草稿”，不能套已售准确率。

**错误处理**：附件缺失、金额不一致、条款不可定位、扫描缺页、法源无许可时明确缺口；可生成内部草稿，签发前必须解决关键缺口或由有权律师记录范围限定。严禁自动补造当事人、条款、登记事实。

### B. 材料整理—事实与证据—受限文书—金额表

**输入**：有序文件包、证据来源、争议类型、当事人和主张、分析截止日。首发为内地民商事，具体文书类型与受理地区逐项验收；刑事/涉密/复杂监管业务不因通用Agent能回答就视为上架。

**流程**：安全扫描/解压 → 本地或C获准云OCR → 原件页码/图像/文本锚点 → 去重但保留来源链 → 分别抽取“材料声称的事实”“律师确认事实”“推论”“待确认” → 时间线和证据矩阵 → 缺失证据及相反材料 → 文书字段确认 → 确定性金额计算 → 原生文书与附件目录 → 人工复核。

**交付件**：证据目录.xlsx、时间线.xlsx、争点—证据矩阵.xlsx、文书草稿.docx、计算明细.xlsx、缺口清单。每一个关键事实链接确切文件版本和页段；“未检出”不写成“不存在”，“未提供”不写成“无此义务”。

**计算**：Decimal或等价精确数值；本金分段、币种、利率来源及版本、起止日计入规则、节假日规则、还款冲抵与上限由确定性组件计算；模型只提议参数。不能把LPR四倍当所有违约金、利息和金融借款的一般公式。律师确认法律适用与事实输入后才形成正式表。

**期限**：模型抽取候选起算事实，律师确认送达方式、日期、期间性质、中止中断等；日历引擎计算并记录规则版本。提醒“已送达”只表示通知通道回执，不表示法律送达或业务期限已履行。首发不自动法院提交。

### C. 法律研究—引用核验—顾问答复—变更追踪

**输入**：研究问题、法域与地域、事件时点、分析截止日、事实假设、可用数据源与许可。对事实不足先给澄清与条件化结论。

**流程**：研究计划 → 生成获准检索式 → 官方法源和许可案例库并行查找 → 取得原文/版本/权利 → 检索相反依据与区别事实 → 将命题逐一对照出处 → 区分现行法、行为发生时法和过渡规则 → 草拟答复 → 律师核查 → 交付与跟踪。

**引用四态**：已核验且支持命题；出处核验但支持/适用待确认；来源尚未核验；来源不可得/冲突/失效。前端用文本标签兼容色弱用户；红灯不允许在正式稿里伪装为确定法律依据。真实性、支持度、适用性是三个字段，不用一个“已核验”混同。

**交付件**：法律研究备忘录.docx、类案对照.xlsx、来源目录与受许可摘录、顾问答复.docx、假设/限制与相反依据。案例列表不是研究结论；排序不宣称预测胜诉率。

没有完整数据许可时，产品准确称“限定资料研究”，显示覆盖范围及缺失库；可售其他成熟业务，不冒称全面类案检索。公开监测可云端运行；L事项关联与影响分析在获准设备执行，C可在获准云任务执行。

## 6. Office、移动与IM

**Office主线**：客户端导出标准DOCX/XLSX为所有支持环境基线；优先接入试点占比最高的一种Word/WPS宿主。插件只绑定用户当前打开的指定文档、当前版本和事项；读取选择/全文分别授权。原生修订必须保留段落、表格、脚注、目录、页眉页脚、编号和批注关系；对含域代码、保护、签章的文档先检查，不能重建后声称无损。

写回使用 `base_version + anchor + expected_text/hash + replacement`，冲突返回预览，不按模糊文本替换全篇。保存、关闭、另存、同时人工编辑必须有冲突策略。外部关系、宏、嵌入对象按信任和格式处理；不能无提示删除客户必要内容。首发不编辑带有效电子签章的原件，生成新版本并说明签章已不适用。

**移动**：首发C受管Web支持完整成果预览、评论、再认证后审批，限制下载按律所策略执行；浏览器不能保证阻止截图。L默认通知，内容需在线桌面安全会话或已验收的移动解密客户端；手机App可后续加强密钥与离线体验，不将它列为销售前所有产品的共同依赖。拒绝“手机先发出、24小时补签”。

**IM**：只接试点最常用一家（企业微信/钉钉/飞书择一）；账户绑定与撤销明确。可收件、启动预设任务、查状态、提醒；不能任意文字越权调用Shell或最终外发。IM平台本身可能保存消息/附件，L不允许的资料应改用桌面导入。短时下载URL、重投去重、过期处理和文件真正落地回执全部验收；不可笼统宣传“机器人转发文件完全不经云”。

## 7. 签发、版本与法律责任

成果状态为 `草稿 → 待复核 → 待签发 → 已签发 → 被新版本替代/撤销使用`；Agent只能推进至待复核。有权律师查看的具体渲染版本、附件、受众和去向记录到审批对象。C/L均不允许审批一个版本却交付另一个版本。

输出顺序：确定内容 → 受众处理 → 依法配置AI标识与元数据 → 生成文件 → 计算hash → 生成独立manifest → 设备/服务签名。签名只证明所声明的签发流程与文件完整性；可靠电子签名、时间戳、存证和法院证据效力另按适用服务和法律要求实现。

任务执行成功与法律复核通过分别统计。只完成7/10份文件时任务为部分完成，剩余列表可恢复；律师可限定范围签发，但产品不能把未读材料计入覆盖率。

## 8. 知识、规则与内容工程

租户、事项和个人记忆分区，跨事项复用默认只允许经知识负责人批准的模板/匿名方法。不能自动把客户事实、胜诉策略、对方底线写入全所记忆。向量也是受保护派生数据；检索前按ACL过滤，取回后再鉴权，撤权同时影响缓存。

规则项包含适用条件、立场、效力时点、法源、法律要求/商业偏好类别、建议与备选、例外、内容负责人、测试样本、版本。来源表另记录抓取/索引/模型输入/展示/摘录导出/训练评测/终止留存权；订阅数据库不自动获得全部权利。

内容流程：法律工程师起草 → 资深律师审校 → 独立样本盲测 → 签名发布 → 灰度 → 观察误报漏报 → 回滚。模型、规则、模板、法源、OCR或压缩器升级，按影响图回归；紧急失效来源停止引用并提示受影响任务，既往交付件保留历史状态而不是偷偷改内容。

## 10. 产品效果验收方法

同一任务集比较：现有人工流程、Kimi Work标准版、法律版。由不知产品来源的律师评估严重遗漏、来源支持、修改可接受性、格式和总交付时间；通用竞品不得使用本产品没有合法取得的额外数据来制造不公平比较。

目标包括：无未授权外发、无原件损坏、关键出处可定位、关键缺失明确、复核后节省时间。数值门槛及样本分层见第06篇；数据未取得前不宣称“减少80%工时”或“能力不少于标准版”。法律版的溢价来自完整律师工作闭环与服务，不要求逐项胜过标准版的建站、PPT或电脑操控。
