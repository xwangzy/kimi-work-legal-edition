# 调研 C：法律产品、合规与商业独立终审

核验日期：2026-10-09（中国标准时间）。审阅对象：v5 第 2、3、6、7 篇及经济输入，v6 第 2、3、5 篇，v7 第 5 篇及经济脚本。判断由当前任务独立形成；既有研究是待核查材料，不作为外部事实证据。以下“建议”是产品和风险设计意见；监管适用须由实际运营主体按最终数据流落实。

## 1. 最重要裁决

**推荐境内 SaaS 控制面、境内受控云执行、本地执行器共用一套权限和交付体系；由律所政策与事项密级选择执行位置。不能把“所有案卷必须只在所”当成用户已经提出的需求，也不能把“上云”默认等同于违法。** 用户确认采购 API token、按 SaaS 订阅销售及品牌授权；未要求所有用户安装本地客户端、禁止境内受托云处理、强制端到端加密协作。

v5 的主要价值是把法律工作做成可验收交付件，提出原件不可覆写、出处定位、受众分版、签发绑定最终文件等正确要求。v6 正确认识到机构控制、同步和移动入口需要常在线服务，但仍把案卷本地化当不可动摇前提，因此“零服务器”只是没有律所服务器，实际依赖律师电脑在线。本地执行+云端推理并没有消除第三方处理；反而把加密同步、密钥恢复、终端支持、离线撤权等困难一并引入。v7 恢复开放 Agent 能力有价值，但“任何能力弱于标准版都无法定价”的论断不成立：法律产品应该按交付质量和业务效率定价，而不是与通用办公产品做功能数竞赛。

建议的三种可售部署配置：

| 配置 | 谁适合 | 内容如何处理 | 关键限制 |
|---|---|---|---|
| 境内云工作区 | 接受受托云处理的普通团队；无 IT 律所 | 批准材料进入租户/事项隔离的境内存储与短时任务沙箱，推理经境内企业 API | 明确中软与模型商能在服务必需范围内处理明文；不能宣传端到端不可见 |
| 本地工作区 | 有保密约定或客户不接受云存储的事项 | 原件、OCR、索引及文件编辑在端侧；只有批准的必要内容调用境内模型 | 本地执行不等于本地推理；电脑离线时内容任务等待，不偷偷转云 |
| 专有部署/无外部推理 | 特定高敏、客户强制要求的机构 | 经确认的机构环境与模型端点；供应商支持接触单独控制 | 当前只采购 API token 无法提供这项；先标另行交付，不在标准套餐假装具备 |

国家秘密等不适合现有产品资质、环境处理的材料，标准 SaaS 明确拒收；此项不是用户勾选同意可以豁免的设置。其余敏感材料应有分类评估和产品支持边界，不能把“本地”作为自动合法证明。

## 2. 阻断级缺陷及修复

| 严重度 | 旧稿问题 | 为什么不成立 | 可实施修复 |
|---|---|---|---|
| P0 | v5 用“当事人已同意/无需”控制一整个事项的所有外发 | 委托人通常不能代对方、证人、员工及交易第三人同意；公开可见也不等于可无限制再处理 | 数据准入拆成委托/保密授权、个人信息处理依据、敏感信息特别条件、供应商转委托、出境条件；记录适用范围而非只放一个勾选框 |
| P0 | v6 §7.6：“轮换并销毁事项密钥”使所有设备旧密文同时失效 | 旧密钥、离线缓存、备份及恢复份额可继续解密旧密文；轮换只能阻断未来新版本访问 | 逐对象、逐密钥版本删除清单；覆盖端、云、缓存、备份、恢复材料；删除回执分已完成/待设备在线/备份待到期/法律保全，不给虚假全局即时成功 |
| P0 | v6 §10.5：独立 App 可“彻底解决”H5 代码由供应商下发的威胁 | App 也由供应商签名更新；恶意更新仍可取得本地明文、替换审批内容 | 明确普通云运营者威胁与恶意客户端供应链威胁；签名更新、双人发布、独立审计、版本固定/回滚、更新透明记录降低风险；不宣称彻底消除 |
| P0 | “中软不存正文”当作完整保密保证 | 网关内存、追踪、错误报文、队列、APM、人工支持、模型上游、检索查询仍可能接触正文 | 建端到端数据流清单与测试，合同覆盖每条路径；正文默认不进日志，生产支持采用短时授权与审计 |
| P0 | 把研究“法源已核实”当作结论正确 | 真法规可能不适用事实时点/地域；真判例可能已改判或仅支持相反主张 | 将存在性、版本/效力、出处吻合、对命题的支持、适用性拆开验证；反例与无法覆盖范围显式呈现 |
| P0 | 外发已经发生后提供 24 小时“撤回窗口” | 邮件、下载、法院提交、对方存档通常不能可靠撤回 | 区分内部批准撤销与外部送达；不可逆提交事前确认确切对象、附件、字节版本；结果不明进入对账，不盲重试 |
| P1 | 本地全能力与整体控制面故障承诺同时成立 | 控制面失效时仍须处理新授权、撤权、额度与凭证到期；中软网关也可能不可用 | 画出依赖图，定义离线可读/可编辑/待推理；离线权限有期限和能力上限，不能笼统承诺“全部可用” |
| P1 | 复制所有标准版能力作为溢价理由 | 复制研发与维护成本高，律师不一定愿意为建站/通用电脑控制买单 | 保留底座可扩展性；GA 只销售通过验收的法律能力；通用工具在受控专家模式开放 |

离职撤权应停止**新的服务端读取和未来密钥发放**，在线设备接收撤权后清理，离线设备在下次联网或租约到期才执行；已导出明文无法收回。硬件密钥与 MDM 可改善可控设备上的执行可信度，仍不等于让过去已经知悉的信息消失。

## 3. 法规与证据核验

### 3.1 《律师法》2026 修正：属实，但须防止“校验自己生成的法源”

本轮独立打开最高人民法院受权发布的主席令，确认 2026-08-28 通过、2026-09-01 施行；北京司法局当前公开全文列明第二十六条律所管理制度、第四十一条保密、第四十二条利益冲突。旧稿这些条号有官方支持，不能仅凭此前常识中的 2017 版条号推翻。全文未见新增 AI 专门条款。[主席令](https://www.court.gov.cn/xinshidai/xiangqing/510011.html)、[北京司法局全文](https://sfj.beijing.gov.cn/sfj/zwgk/2024zcwj/744120751/fl91/744123073/index.html)。

同时，本轮读取的北京司法局转载中个别内部交叉引用疑似仍沿旧条号，说明**官方网页也可能存在排版或整理差错**。生产法源库应保存公布机关、公报版/公布决定、抓取版本、时间和摘要；冲突由法律编辑核对正式公布文本，不以一个页面及模型判断自动发布规则包。仓库演示种子、既有报告、搜索摘要不能充当法规原始证据。

### 3.2 PIPL：按数据与行为建模

已核对《个人信息保护法》：处理依据不只同意；委托处理、公开个人信息、敏感信息、影响评估均有各自条件。加密或化名可降低风险，不能自动视为匿名化。产品应让律所记录适用依据、处理目的、数据主体范围及风险评估，而非替律师自动判合法。[法律全文](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)。

基于上述规则的产品设计推论：

- 客户保密授权解决的是律师向技术供应商披露客户信息的约定边界；个人信息法依据解决对自然人数据的处理条件；二者不能互相替代。
- 一个公司客户确认使用 AI，不自动覆盖劳动争议中员工、对方证人或病历涉及者。需要事项目的、处理必要性与法定依据审查；无法建立条件的字段删减、改为人工或限定本地处理，不能凭模型推断授权。
- “公开裁判文书”也可能含个人信息；做某案研究与建立自然人行为画像是不同目的。默认禁止法官画像、自然人背景评分等超范围用途。
- 本地处理同样属于个人信息处理；阻断上云只是减少一种风险，不自动治愈非法来源、越权共享或超期保存。
- 乙方中软、模型商、OCR/搜索/存储厂商等按真实活动定角色，不因产品叫 SaaS、代理或软件授权自动改变。

《网络数据安全管理条例》第十二条明确了提供、委托处理个人信息和重要数据的约定、监督及记录要求。应维护版本化受托/转委托清单，变更后重新判断是否扩大范围，而非把所有上游简单写作一个“Kimi”。[条例](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm)。

### 3.3 境内云、香港上市公司与跨境

中软国际香港上市这一事实本身不能推出案卷必然出境。要看运营实体、模型与工具处理地点、日志与备份位置、供应商支持、境外管理员/香港团队的访问权限，以及面向境外发送结果的路径。境外主体可访问境内数据亦可能属于数据出境；密文不是自动豁免。[网信办数据跨境说明](https://www.cac.gov.cn/2024-03/22/c_1712776625820516.htm)、[网信办 2026 年 7 月问答](https://www.cac.gov.cn/2026-07/24/c_1786638883119336.htm)。

建议标准版：境内签约运营、境内生产与灾备、境内模型/API 端点、境内运维人员白名单；全球支持默认只见脱敏工单。境外访问和跨境法域事项单独准入，不能用香港上市或海外客户的标签替代出境判断。重要数据识别遵循相关目录、通知及规则；不应把所有案件材料自动认定重要数据，也不应因未出现客户姓名就认定不是重要数据。

### 3.4 律协指引不是全国统一禁止云处理的法律

上海律协 2025 居村顾问指引明确自身非强制性、参考性，并定义本地化部署；2026 企业法律顾问指引有独立适用场景。可以据此提供保守预设与评估模板，不能把某份指引的建议转换成全国所有律所的云端禁令。[2025 指引](https://info.lawyers.org.cn/info/71624f5df3184a90941f317aca231c18)、[2026 指引](https://www.lawyers.org.cn/info/10aadc765e124cb4ac999d47cda0b0a8)。

v5 摘要把敏感类型称作“五类”，但上海原文包含宗教信仰、特定身份等，不宜把摘要列表做成穷尽名单。2025 指引注明试行一年，本轮没有取得其续期决定；用作方法参考时必须标注，不能称“现行强制要求”。深圳 2026 指引本轮搜索未取得协会官方全文，既有 v5 调研自己标为律师博客二手转载；最终文本却多处提升为“一手”。**必须纠正证据等级**，未经原文核验的具体条号不得作为自动合规判断的唯一规则。

小型个人信息处理者简化措施有网信办 2026-07-24 官方答记者问支持其存在；但“多数律所都适用”和“直接内置附件格式”仍需核对正式规定、适用人数口径与实际律所数据范围。不能把单家律所规模简化外推为中软多租户平台同样享有豁免。[官方问答](https://www.cac.gov.cn/2026-07/24/c_1786638889576451.htm)。

### 3.5 登记、等保、标识应区别法定义务与采购策略

网信办 2026-09-14 公告明确直接调用已备案模型的应用/功能由地方网信办开展登记，且给出公示要求；最终适用还要结合服务范围及属性。B2B 收费不自动豁免，也不能把客户内部使用排除条款不加判断地适用于公开招揽所有律师的 SaaS。[备案登记公告](https://www.cac.gov.cn/2026-09/14/c_1791136833136332.htm)、[暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)。

“按三级控制目标建设”是合理商业安全目标，但不等于已依法定级三级、更不等于已经测评。定级对象、边界及等级由适用程序确定；同集团已有证照不自动覆盖新增运营主体、域名和系统。ICP、电信许可、App 备案、商用密码适用应列责任人、法律依据、办理状态、验收凭证；不能用“与网信咨询同一次完成”低估不同主管机关流程。

AI 标识规则为无显式标识版本提供附条件路径，并非所有交付件绝不能有干净版。隐式标识、用户义务、导出日志应结合适用范围实现，不得用“律师签发”自动消除平台义务；技术元数据保留与专业保密同时设计。[标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)、[官方说明](https://www.cac.gov.cn/2025-03/14/c_1743654685896173.htm)。

## 4. API 采购与合同：旧稿有正确阻断项，也有过度推导

当前官方协议明确允许通过 API 向最终用户提供服务，同时限制账号转交、权利再许可，并保留输入输出服务优化使用权。故“采购 token 做法律 SaaS”不能简单等同裸 key 转售；用户既有品牌授权按事实接受，登记授权范围和有效期即可。需要解决的实质条款是法律数据用途、保留、支持访问、转委托、责任及可用性。[Kimi 开放平台服务协议，2026-08-31 生效版](https://platform.kimi.com/docs/agreement/modeluse)。

建议合同交付包（属于设计建议，不表示现有 API 合同已具备）：

| 文档/证据 | 必须解决的问题 |
|---|---|
| 上游企业数据处理附件 | 不训练与不用于一般服务优化的范围；chat、图像、文件、搜索、抓取、缓存等逐接口保留矩阵；境内处理地点；可接触人员与次处理者 |
| 业务许可范围表 | 中软以自己服务向最终用户收费、品牌/布局授权覆盖范围；如有裸 API/token 渠道转售则另行约定；不得把上游主 key 发给终端 |
| SLA 与变更机制 | QPS/并发与限速隔离、模型弃用通知、版本回归窗口、故障支持；客户承诺不能高于实际可实现且无补偿预算 |
| 数据退出与删除附件 | 租户导出、备份到期、法律保全、上游删除与日志例外、无恢复能力的情况；不以“ZDR”一个词替代完整矩阵 |
| 责任与保险 | 服务缺陷、数据事故、内容质量与律师执业责任分别分配；旧标准协议上游责任限额可能远低于中软承诺，须商务处理这一缺口 |

ZDR 的目标是减少持久留存；推理时模型服务必须读到输入，故不等于“不接触明文”。“不训练”也不等于“不留存”；“不存正文”不等于没有日志；搜索没有客户姓名不等于没有可识别案情。

## 5. 法源、律师交付质量与产品边界

v5 最值得保留的是交付件规格，不要随着底座放权丢失这些专业门禁。首发必须给每个场景明确支持法域、材料范围、交付格式、待律师确认项、失败状态和评测报告。现有“生产/Beta/模板”三档成熟度合理，但销售页面与配额计费应一致。

法源可得性与商用许可分开。《著作权法》第五条排除特定官方文件，不意味着商业数据库的编辑摘要、检索结构、接口、案例集及平台访问条款可以任意复制再分发。[国家版权局法律全文](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)。

数据商许可逐项谈：检索、全文拉取、临时缓存、索引/向量化、送入第三方模型、摘录导出、客户工作成果留存、终止后的访问、审计/评测使用、是否可面向多租户转供。前台显示一个 MCP 插件可连不等于已取得以上权利。先做官方法规版本库+签约商用案例源；若案例许可未完成，限定资料研究可售，但不能宣传完整类案库。

建议把质量要求增加为以下可验证条件：

1. **正确拒绝和范围覆盖**：每个任务显示实际读取材料、失败页、未取附件、法规范围、检索停止条件；覆盖不足不能显示完整审查通过。
2. **事实与推论分开**：材料记载、当事人主张、模型推论、律师采纳分状态；源文页码与输出结论一一可追溯。
3. **引用支持度**：来源存在不等于支持该命题；法条生效/失效与事实发生时间分别记录；判例层级、审级、是否改判、类案差异显示。
4. **原生文书质量**：Word/WPS 真修订与批注；接受全部后与批准内容一致；长表、节、页眉页脚、脚注、目录、交叉引用回归；不能只验截图好看。
5. **签发的实际含义**：内部批准/电子签名/盖章/送达分动作；设备签名本身不自动等于法律上可靠电子签名，更不自动证明签发人看过每页。
6. **程序期限**：送达事实与规则版本必须可审查；默认只产生待确认期限，二人确认后提醒；短信/IM 未送达不能当提醒已完成；支持升级通知和节假日/送达方式专项测试。
7. **伦理墙全链路**：检索召回、向量索引、缓存、共享链接、导出和客服都做事项权限；管理员不能只因为管账单就看到所有案卷。
8. **真实效果**：报告含盲测与实际工作时长，统计“修到可交付”的总时间，不只统计生成时间；所有拟定 95%/99% 阈值必须标为目标，不能当实测。

产品完整性并不要求第一版把所有民商事、刑事、跨境、尽调、会见、翻译同时卖作成熟能力。完整产品的含义是承诺范围内能开通、使用、协作、交付、收费、报障、退出，范围外有准确降级和承接路径。

## 6. 移动端与 IM：建议重新分配首发范围

IM 是触发、通知、收件渠道；不应承担完整权限控制中心。平台已经看见的消息与附件、文件名、下载凭证以及回调元数据均属数据流。普通事项可在管理员启用并完成平台条款评估后收件；高敏事项只收无内容通知。所有材料进隔离收件区，先验身份、文件安全与目标事项权限，再入库。

手机默认：看状态、收通知、补充澄清、审阅允许的摘要/文件；高影响动作必须显示最终对象与确切交付文件。审批不能仅是“同意 AI 继续”，还要包括预算变化、上云、对外提交、收件人改变等可理解信息。远程发起的任务不能扩张既有本地目录权限，IM 身份不能替代设备授权。

H5 可作为低风险移动入口；高敏解密与签发确需更多保护时提供 App，但 App 是成本和能力选择，不是端到端安全的证明。首发没有必要为了“所有能力不弱于标准版”同时造独立双端 App、三个 IM 集成和电脑遥控。先一个主流 IM+移动 Web 通知/轻审阅，复杂签发桌面完成；云工作区让电脑离线时任务照常执行；本地工作区明确等待本地执行器。

## 7. 经济模型与商业裁决

v5/v6/v7 有可复算脚本优于纯拍脑袋，但精确算出的五年结果只是输入假设的投影，不能把某年盈利或某金额资金峰值当可承诺结论。本轮不复用其精确增长、亏损与现金谷底。

独立检查 v7 `seat_economics`：超额需求乘以固定购买比例后直接产生加量收入。因此“Agent 使用翻倍利润反而提高”主要依赖加量购买及收费假设，不能证明真实开放 Agent 越用越盈利；实际可能是更多无效重试、预算流失和用户不买。模型已经列若干敏感性，建议进一步拆出真实可观测变量：

| 变量 | 必須观测的口径 |
|---|---|
| 一个可接受交付件成本 | 模型输入/输出/缓存、全部失败与重试、子 Agent、OCR、搜索、法源、沙箱存续、存储/出网和回归分摊 |
| 活跃与需求 | 付费席位、月活席位、实际审阅席与生产席、事项数、已采纳成果；不可把登录当价值 |
| 客户接受价格 | 套餐报价→实际成交→续费；基础席位与能力/算力加量分离；审阅席不宜成为协作扩散阻力 |
| 销售和交付 | 试点免费期、采购周期、渠道分成、驻场培训、WPS/杀软适配、失败退费、支持工时、客制化实施 |
| 资金占用 | 税费、上游充值/最低承诺、法源固定费、应收/坏账、SLA赔付、退订退款、年付预收的履约责任 |
| 使用尾部 | 单任务 P50/P95/P99 与月度重度用户分布；每个子任务真实硬预算、租户并发和上游配额 |

应保留**无加量收入、零缓存命中、重试增加、成交折扣、转付费率下降**的联合压力情景；单因子敏感性不足以覆盖坏情形相关性。云处理的 OCR/算力不能继续沿用 v5 的零云成本；本地 OCR 也有终端支持、耗电、时间、兼容维护成本。自带密钥套餐需要说明客户端/云执行/法源/服务费各自价值，不能只减去 token 成本。

建议价格先作为待验证报价区间，而非确认价格。用 6–10 家覆盖不同规模和业务的设计合作律所收集 6–8 周真实使用数据，设置立项预算阶段上限；每阶段按付费意愿、留存、交付件采纳、支持成本、安全质量决定扩张。不得以未经核实的竞争产品价格、用户数或“某通用模型同底座背书”支撑财务确定性。

## 8. GA 前的证据门禁与可接受取舍

| 门禁 | 可签字验收的证据 | 未满足时的降级 |
|---|---|---|
| 商用数据权利 | 上游数据条款、数据商许可、受托清单与运营主体确认 | 合成/公开演示；限制不具备许可的任务 |
| 租户/事项隔离 | 越权读取、搜索/缓存穿透、连接器对象切换、附件URL、支持访问红队报告 | 不接真实案卷 |
| 执行隔离 | 云任务沙箱、本地执行器的出网、挂载、凭证、进程与资源边界测试 | 降为受控工具与只读任务，暂停高风险开放执行 |
| 工具外发 | 确切对象批准、幂等、防重、断线结果对账；程序文件注入不能自动授权 | 禁止自动发邮件/提交，仅导出人工处理 |
| 文书与法源 | 法律团队签字的盲测、出处支持度、原生修订/复杂格式回归 | 明确 Beta/限定资料研究，不能称生产完整审查 |
| 恢复与退出 | 租户恢复演练、密钥丢失流程、备份到期删除与法律保全、开放格式导出 | 有限试点，不提供未验证的数据持久性承诺 |
| 商业运维 | 按对象的 SLO、账单对账、支持值班、事故通知、数据泄露演练、版本回退 | 小范围受控开放 |
| 监管与安全资质 | 实际适用事项的办理凭证/合规结论；标识/公示及投诉通道 | 未满足适用条件不得公开销售 |

总体日历不能反推门禁一定会通过。可售范围必须是实际通过门禁的功能集合；既要避免永远只做 demo，也不以“最完美”措辞掩盖未验证能力。
