# 08 竞品结论与证据索引

核验截至2026-10-09。公开文档只能证明厂商当时的说明，不等于本轮安装实测或安全认证。更详细逐字段结果与未知项见调研B；源码证据见调研A；法律与商业见调研C。以下事实与我方设计建议分开。

## 1. 主流办公Agent的云地权限对照

| 产品/形态 | 公开材料可确认 | 不能据此推定 | 本产品借鉴 |
|---|---|---|---|
| WorkBuddy桌面 | 本机文件/命令、默认与完全访问模式；服务端处理必要片段 | 不能确认所有平台OS隔离实现、全部模型留存 | 目录权限、清晰批准；不引入法律版完全访问档 |
| WorkBuddy助理 | 手机通过IM驱动在线电脑，有专用文件夹和会话约束 | 遥控不代表电脑关机仍能运行；E2EE未知 | 渠道降权、在线状态与等待 |
| WorkBuddy WMA | 独立云托管、会话隔离、凭据与执行分离；页面仍为白名单内测口径 | 预计10月不等于已全面商用，也不等于桌面订阅含此能力 | C云任务、独立凭据broker；我方自建或独立采购 |
| 千问办公桌面 | 本地文件、可选安全工作环境、电脑操作权限；本地定时依赖设备 | 发布日志有VM不能证明具体隔离技术；本地不等于无模型外发 | 本机能力明确、失败不偷偷云迁移 |
| 千问办公Web | 云端任务，关闭浏览器继续；与桌面会话/定时有独立边界 | 不能假设天然跨端无缝接力 | 共同业务状态需我方显式实现 |
| 千问企业治理 | AI日志可查询90天；Hook异常继续基础流程 | 查询窗口不等于删除期限；Hook失败不等于所有权限失效 | 强制策略不放在可失败跳过的Hook上 |
| Kimi Work桌面 | 本地Agent、三档权限、本地定时；真实浏览器桥和内置浏览器分开 | 未公开足以确认完整OS隔离、DPA/E2EE的证据 | 借用已授权UI、工作区/任务/产物心智，行业权限重建 |
| Kimi网页/会员云 | 与桌面本地任务不同的云服务能力 | API token、标识授权不附送全部Work会员服务 | 逐能力列来源、购买/替代与数据条款 |

一手来源：WorkBuddy[权限](https://cloud.tencent.com/document/product/1831/134401)、[FAQ](https://cloud.tencent.com/document/product/1831/134405)、[助理](https://cloud.tencent.com/document/product/1831/134392)、[WMA](https://cloud.tencent.com/document/product/1831/138968)；千问[FAQ](https://docs.qwenwork.cn/faq.md)、[桌面设置](https://docs.qwenwork.cn/desktop/settings.md)、[本地定时](https://docs.qwenwork.cn/desktop/scheduled-tasks.md)、[Web定时](https://docs.qwenwork.cn/web/scheduled-tasks.md)、[Hooks](https://docs.qwenwork.cn/desktop/hooks.md)；Kimi Work[FAQ](https://www.kimi.com/help/kimi-work/kimi-work-faq)、[发布日志](https://www.kimi.com/help/kimi-work/release-notes)。

共同结论：本机操作、云模型、云调度、账号订阅可以组合，不是互斥产品类型。竞品未公开某项安全机制只能记“未知”，不能写成“竞品没有、我方领先”。没有公开可审计证据支持“律师行业必须所有案卷本地”或“只有我方能做Windows沙箱”的全称结论。

## 2. 法律产品与其他Agent的有效参照

## 4. 输入与产物的版本规则

评审输入以研究目录中的v5/v6/v7和Astra/Opus原稿为准。它们在本轮前已有工作区改动，本轮不覆盖旧稿。为使审阅可追溯，交付清单记录读取输入文件与输出文件的SHA-256；hash证明文件版本，不证明内容真实性。

`evidence-B/manifest.json`记录联网抓取的响应hash；正文快照经去脚本/样式处理，不能直接与响应hash比较。官方页面在未来会更新，发行前应重新核验合同、价格、模型能力、备案和法源效力。

对于未公开的竞品安全机制、供应商实际DPA、Windows隔离和商用法源许可，保持明确未知。三名subagent已留存研究，但因用量限制中断后续追加核验；主审没有把未知字段补成肯定结论。

## 5. 对v8本身的反向检查

| 对本稿的质疑 | 判断与限制 |
|---|---|
| C/L会不会造成两套产品、成本翻倍？ | 风险真实存在。共享业务实体、状态、权限契约、文书/法源质量；执行/存储/密钥适配独立。首期不承诺所有功能两边完全一致，按能力账本展示。875人周只是粗估，若双路径维护成本试点超标，应推迟L同步和移动等扩展。 |
| 桌面用户是否真的需要C云托管？ | 尚无本轮客户验证。推荐理由是跨设备协作、关机任务与集中恢复，不是认定用户已同意。若试点多数客户明确禁止托管，可以L先售，并接受在线执行器要求；不能为证明架构正确而改变客户数据约束。 |
| 有了云沙箱就能取代本机安全吗？ | 不能。桌面broker、Office、解析、预览和本机缓存仍有攻击面；云侧还增加多租户、运维与供应链风险。两条路径分别测，不以其中一条通过推定另一条。 |
| 化名后结构化patch能否保留复杂文书？ | 需要实际探针，特别是姓名反复出现、定义和嵌套表格。失败时退回可审阅建议或获准真实文本处理；不把99%编辑成功率写成已达到。 |
| 律师复核是否只是在转嫁模型责任？ | 复核是执业过程的一部分，产品仍承担输入覆盖、来源、版本、格式、权限和服务承诺。若复核改错成本高于人工，不能用免责声明掩盖产品无效，应下架或改进该场景。 |
| 单账号低价能否覆盖高质量内容维护？ | 未证明。经济脚本只展示单位服务贡献，未覆盖全部固定费用；需真实订单、续订与法律维护成本再判断业务可持续性。 |
| 详细门禁是否导致永远不能上线？ | 门禁只阻断对应能力，不强制所有远期功能一起通过。四类合同、指定宿主、限定资料研究可以作为完整但有范围的产品；范围真实、合同和运维完成即可按其售卖。 |

以上并非保留选择权而不作决策：本稿明确推荐桌面主入口、账号订阅、C/L预设、受控Runtime、三业务链和分阶段发布。反向检查用于定义改变决策的证据，避免新稿重复旧稿把设计目标当事实的错误。
