# Kimi Work 法律行业发行版 · 完整产品方案 v5.0（律所侧执行）

定稿 2026-10-01 · 在 v4.0（整合 astra 09-22 / 09-30 v1.1、opus 09-23 / 09-28 v3.0 与 Claude 09-23 审计）基础上，按“云端只提供 Kimi token API、其余在本地执行”的前提重做执行架构，并完成本轮 V1–V4 联网核验与 Kimi Code、中软 MaaS 源码复核 · 面向：中软国际立项评审、与月之暗面及中软 MaaS 的联合评审、产品与研发、设计合作律所试点

> 所有价格、指标、人力、周期与收入均为待试点校准的假设，不是报价、预算或收益承诺；“已核验”只指公开官方材料或源码存在相应描述，不代表我方已签约、已实测或已取得供应商承诺。现有 demo 与 `platform/` G0 工程是原型，不是能承接真实案件的生产系统。

## 一句话

**像 Kimi Work 一样在律师电脑上运行的律所法律工作平台——本地执行，云端推理（大所可选律所内私有模型）。案卷、规则、执行、核验、审批与审计默认都留在律所（律师电脑与可选的所内节点）；中软云端不持有业务数据，模型推理经中软 MaaS 的法律专用 token 通道，只发送经化名校验的必要片段；每一次外发（包括律所自选的 IM 与云盘）都记入数据去向卡。律师得到有出处、有版本、经律师签名签发的 Word/Excel 交付件；在 Word/WPS 里就地审合同，在企业微信/钉钉/飞书里收材料、做审批；律所按席位购买，席位含模型额度。**

## 为什么改：v4.0 的问题

v4.0 把分析、规则应用、模型调用、法源核验与审批都放在“中软法律云”执行。但：

1. **中软云端的真实能力就是 token 服务**——中软 MaaS 基于 new-api，内部方案写明“面向客户销售 Kimi 官方原厂 API token”；令牌已具备额度、模型白名单、IP 白名单、到期与元数据计量。再造一套多租户执行云，是重复建设。
2. **Kimi Work 本身就是“本地 Agent + 云端模型”**，发行版被授权沿用的正是这个形态；Kimi Code 引擎可进程内嵌入，宿主文件与进程服务可在 bootstrap 时替换（源码复核）。
3. **中软托管案卷的代价**：受托与保管责任、等保三级 SaaS、多租户隔离、专属云与私有化两条交付线、每年数百万元云平台与运维成本；而律协指引偏向“本地化或专有云”。

v4.0 的状态语义、验收纪律、场景规格、内容资产、合规动作与商业纪律全部保留，**只推翻执行位置及其派生内容**（第 1 篇）。

## 十二个关键决策

| # | 决策 | 结论 |
|---|---|---|
| 1 | 执行架构 | **律所侧单一内核**：“本机法律内核”在律师电脑内嵌运行，或在所内节点无界面运行（同一代码）；所有入口连它，事项账本在律所内同步。**中软云端不持有业务数据**：模型推理只经中软 MaaS 法律专用分组（令牌、额度、计量、转发至月之暗面企业接口；企业协议 + ZDR + 不落盘正文为 P0 目标，完成前只处理合成或公开材料）；另有不接触案卷的支撑服务（许可签发、内容分发、工单与诊断包接收、可选遥测，默认关闭） |

## 需要领导层拍板的十件事

1. **执行架构**：律所侧单一内核 + 云端只用中软 MaaS token 通道（推翻 v4.0 云端执行内核）（第 1、4 篇）。
2. **Kimi Code 角色**：本机 Agent 运行时，ZP-1～8 补丁，生产档走本机确定性工作流（第 4 篇 §4）。
3. **中软 MaaS 承接法律专用分组**：独立上游组织与专属额度（2027 年并发 ≥ 300）、不落盘正文配置与审计、令牌即席位、少量 MaaS 侧开发（额度发放、律所级受限管理接口、优先级限流、幂等 ID 查询）；集团法务确认 MaaS 的 AGPL 合规（第 4 篇 §10.3）。
4. **首发范围**：五个生产档 + 两个以授权为条件的升档场景；18 套合同规则包（第 3 篇）。
5. **版本与价格**：团队版、审阅签发席、律所版（平台费含所内节点）、**自带密钥版**、专业版、渠道版、私有化；取消专属云（第 7 篇 §1）。
6. **投入与止损**：至 G2 约 1,080 万元；基准累计现金峰值约 3,930 万元（第 7 篇 §3、第 8 篇 §4.2）。
7. **与月之暗面的 P0 条款**：**授权渠道书面确认**、排除服务优化与 ZDR、独立组织与专属额度、价格、品牌、渠道规则（第 7 篇 §4.1）。
8. **设计合作律所**：非诉、诉讼、有 IT 团队的区域规模所各一家，遴选时盘点电脑配置与节点条件（第 7 篇 §5.2）。
9. **入口优先级**：IM 首发一家；Word COM + WPS 首发（第 2 篇 §7、§9）。
10. **法源首年预算**：固定约 80 万元 + 按量；离线法规库以官方公报文本自建；法律之星 MCP 与一家案例源在 G1 中段前签署（第 5 篇 §2）。

## 版本边界

本方案完成的是可用于立项、产品评审、研发拆分与试点验收的完整产品设计；它不修改现有 demo、`platform/` 工程与中软 MaaS 的任何代码与配置，不向外部发送材料，也不代表 36 个场景已实现、通过质量测试或取得相应数据授权。v4.0 及更早方案原样保留作为研究记录；与本方案冲突时以本方案第 1 篇的裁决为准。
