## 1. 服务目录：与软件一起卖的东西

## 2. 支持、事故与生命周期

律所侧执行改变了支持方式：**中软看不到律所的数据，也就不能像 SaaS 那样“在后台查一下”**。支持体系按此设计：

| 项 | 规则 |
|---|---|
| 支持时间 | 工作日 9–21 点在线；律所版 P1 全天候 |
| 分级 | P1（大面积不可用、疑似数据泄露、错误内容进入已签发交付件、MaaS 通道中断）30 分钟响应、4 小时恢复或给出可执行替代；P2 4 小时响应；P3 1 个工作日 |
| 诊断 | 客户端与所内节点内置健康检查；**诊断包只含版本、配置摘要、错误码、性能计数与日志元数据，不含正文与文件名**，律师预览后才发送；远程协助须律所逐次授权、限时、留痕，默认不打开事项内容 |
| 质量事故 | 立即通过内容更新通道撤回有问题的规则或模板版本 → 律所侧按交付记录定位受影响事项与成果版本（中软提供检索脚本，律所执行）→ 通知机构责任人 → 更正与根因 → 补充回归用例；对已下载或转发的文件只能发更正通知与替代版本 |
| 安全事件 | 端侧漏洞按高危 7 天内评估并经快速通道灰度；MaaS 通道事件按 DPA 时限通知；配合律所履行对当事人与监管的通知义务 |
| 可用性 | 律所侧功能不依赖中软在线；MaaS 通道首发目标 99.5%（与月之暗面上游分开监控并公布端到端成功率）；通道中断时任务排队、离线能力照常 |
| 发布通道 | LTS（季度，锁定客户端、内核、Kimi Code fork、方法包、模型路由与法规库主版本）与快速通道；律所可在所内节点锁定通道 |
| 退出 | 数据本来在律所侧；提供开放格式导出与离线验证工具；中软吊销令牌与许可；**试点也必须能退出** |

### 3.2 角色责任

| 角色 | 对什么负责 | 一票否决 |

| 架构 / 安全负责人 | 本机内核、出站闸门、隔离、密钥、红队 | 越权、非白名单出站或注入探针未过 → 不放行 |
| 合规负责人 | 登记、DPA、标识、律协沟通、准入结论、TC260 对照证据 | 真实案卷进入前的准入 |
| MaaS 法律分组负责人（MaaS 团队） | 授权渠道、独立组织、不落盘正文配置、额度与对账、通道可用性 | 通道配置审计未过 → 不接真实案卷 |
| 财务 | 成本与收费口径、单位经济复算 | 价格低于成本护栏 |
| 客户成功 + 试点合伙人 | 交付可用性 | 试点律所不签收 |

严重越权、虚假来源进入正式交付、错误修订覆盖原件、未经批准外发属于阻断项，不能由销售目标豁免。
