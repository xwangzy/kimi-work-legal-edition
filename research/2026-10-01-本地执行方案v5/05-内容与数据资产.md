# 第 5 篇　内容与数据资产

版本 5.0 · 2026-10-01（资产地图、规则包生产线、评测与任务环境沿用 v4.0；法源获取与分发、方法资产保护、反馈回流按律所侧执行改写）

一句话分工：**中软拥有方法，律所拥有知识，数据商拥有数据，月之暗面拥有权重。** 发行版的长期壁垒不在模型，也不在数据规模（数据商以 MCP 向所有平台分发，竞品同样买得到），而在中软自己生产、持续维护的**方法资产、模板资产与评测资产**，以及由此形成的“按本所标准干活”的能力与服务。Harvey 以 K3 为基座做法律后训练时，真正投入的是约 1,750 个由律师标注的法律任务环境——这说明资产在任务、标注与评测，不在基座。

## 2. 法源数据

### 2.1 策略：官方公报文本自建离线主库，联网核验与授权检索补覆盖

v5.0 的法规版本库要**随客户端分发、离线可查**，因此来源必须允许“分发到每家律所的电脑上”。10-01 核验（V2 一手）改变了 v4.0 的路径：

- **法律之星“法规订阅数据服务”**面向订阅方“全量同步法规数据到本地系统”，便于“企业内部知识库、合规系统、检索平台”同步；其 MCP 协议第三条禁止把服务或获取的数据“分发……给第三方”，付费用户向终端用户正常提供服务的例外要求“不以提供原始数据集合为目的”，并禁止“系统性缓存、存储或建立镜像数据库”。**整库随客户端装到每家律所，就是向第三方提供原始数据集合**——没有单独的再分发授权不能这样做。价格不公开。
- **官方文本可以内置**：著作权法第五条，法律、法规及“其他具有立法、行政、司法性质的文件”不适用著作权法；立法法第六十二、七十八、八十九、九十七条规定公报刊登的文本为标准文本。但网站访问规则与数据库编排另算——国家法律法规数据库标注“版权所有：全国人大常委会办公厅”，无开放接口与再利用授权，批量下载为站内功能并配验证码，**不自动化抓取**。

| 层 | 来源 | 做法 | 约束 |
|---|---|---|---|
| **离线主库：现行文本与历史版本正文** | 全国人大常委会公报、国务院公报、部门与地方公报的标准文本；国家法律法规数据库仅作人工校对 | 法律工程团队**人工逐部采集、校对、结构化**（条款切分、公布/施行/修改/失效日期、效力状态、版本链与适用区间）；每条记录保存公报期号、页码与采集日期；签名打包，每日增量 | 不爬取、不镜像官方站；自建编排归中软 |
| 修订沿革 | 全国人大常委会“关于修改……的决定”等官方文本 | 推导版本链，人工复核 | 同上 |
| 增量提醒 | 法律之星法规订阅（如签约） | **取得“终端离线再分发”书面授权前**，只在中软内部用作“哪部法规有变更”的提示，再回官方渠道取正文；取得授权后可作增量来源写入分发包 | 协议禁止分发原始数据集合 |
| 联网现行有效核验 | 法律之星 MCP（付费授权，允许集成至商用产品向终端用户提供服务） | 律师联网时实时核验，**结果不入库** | 禁止系统性缓存与镜像；**禁止用返回数据训练、微调、验证、测试模型** |
| 指导性案例 | 最高人民法院官网与公报原文 | 自行整理，随离线库分发 | 不从商业库导出 |
| 其他案例 | 元典与北大法宝企业合同（并列询价） | 终端或所内节点在线调用，只发去标识查询；缓存按合同 | 两家公开条款都没有多律所与终端直连授权：**未签企业合同前只做单律所试点** |
| 人民法院案例库参考案例 | 经法信等书面授权（P1） | 在线调用 | 案例库用户协议禁止汇编建库 |
| 官方网站 | 国家法律法规数据库、人民法院案例库、中国裁判文书网 | **只做律师点开核验的权威链接**；不爬取、不批量下载、不缓存入库、不送入模型 | — |
| 企业信息 | 企业信息 API 按调用计费 | 不爬取；实名查询走单独授权的工具并留痕 | — |
| 官方样式与范本 | 67 类要素式文书（法院官网 PDF）；市场监管总局合同示范文本 | 要素式逐份核对 2025 版版本指纹；示范文本首发只做“引用 + 跳转官方下载 + 本地解析用户自行下载的文本”，批量内置前向市场监管总局书面确认 | 改编版标注“基于××示范文本改编，非官方文本” |

**明确禁止**（沿用）：自动化访问国家法律法规数据库、裁判文书网、人民法院案例库；用浏览器自动化驱动律师个人的北大法宝、威科、企查查等账号；把数据商数据汇编后对外分发（包括随客户端分发）；**用商业法源返回的数据做训练或评测**；绕过验证码或风控。

**检索去标识**：向数据商只发送案号或抽象争点与必要事实要素，不发送客户名称、证人身份或整份事实摘要；查询经本机出站闸门并写入数据去向记录。

**离线时的状态**：法条核验完全离线可用；案例存在性核验显示“未核实（离线）”，该引用不得进入签发版，联网后自动补核。

### 2.2 Source Registry（来源登记簿）

每个来源及文档登记：来源主体与 URL、官方/商业类型、取得渠道、许可合同与到期日、**允许动作集合**（检索 / 全文展示 / 摘引 / 缓存 / 向量化 / 送入模型 / 导出 / 训练 / 终止后留存）、地域、律所数与并发限制、引用展示要求、删除义务、获取时间、原文 hash、文档版本、可靠性状态、撤回或下架原因。

运行时每次检索、展示与导出由**本机内核**按 `source_license_id + allowed_action + firm_entitlement + valid_until` 校验（Source Registry 随客户端签名分发，许可变化随内容更新下发）。**权限不足时停止相应动作，不让模型补全未获授权的全文。** 采购时谈清三件事：合同终止后需要删除的缓存与向量；依法依约可以保留的既有签发成果与必要证据；不能继续提供的在线检索。

### 2.3 G2 最小权威数据集

1. 300 部高频法律法规的离线版本链（官方公报文本人工采集自建，签名分发）；
2. 法律之星 MCP 付费授权（联网现行有效核验；S5 升档条件）；
3. 一家案例源的企业合同（元典或北大法宝，含终端或所内节点直连、多律所与送入模型条款；S4 升档条件）；
4. 首批 6 份要素式样式（买卖合同、民间借贷、金融借款合同的起诉状与答辩状，新版）；
5. 一家企业信息 API。

### 2.4 预算（假设，询价后替换）

法源按量费用计入任务成本（研究任务约 12 元/次占位）；固定费用（MCP 保底、案例授权、企业信息、可能的终端再分发授权）2027 年约 80 万元、2028 年约 150 万元、2029 年约 250 万元，进入经济模型。离线主库的采集与维护人力计入法律工程与法源编制（首批 300 部约 2 名法律工程助理 × 8 周）。试点期 50 席以内按量约 2–10 万元。

## 3. 方法资产

### 3.1 Playbook 规则包

**结构**：合同类型 × 我方立场 × 审查尺度 → 规则集。每条规则：编号、适用条件、首选立场、可接受范围、可退让至、不可接受情形、标准修改文本、法律依据（链接法规版本库的具体版本）、风险等级、对客户的解释、谈判说明、测试样本、复核与更新责任人。

**三级内容域**：平台基础规则 → 本所覆盖层 → 事项指令。覆盖有优先级，但不能覆盖法律硬限制、律所权限与出站闸门；冲突在审查前显式解释采用顺序并记录。历史任务固定引用当时版本。

**生产线**：需求与来源清权 → 法律工程师起草 → 领域律师审校 → 开发集回测（≥ 20 例）与盲测 → 法律质量负责人批准 → 签名制品发布 → 灰度 → 线上反馈 → 法变维护。Skill（方法包）是方法说明、输入输出 schema、工具权限、模板与评测的组合，不只是一份 SKILL.md 文本。

**产能**：1 名法律工程师约 2 周完成 1 套规则包的起草与开发集回测；盲测双标另计约 1.5 小时/任务/人。G1 的 18 套由 5 名法律工程师在 10 周内完成起草（前 4 周已在 G0 起步），外部专家承担审校与标注。

**覆盖计划**：G2 18 套（第 3 篇 §3 的 9 类 × 双立场）；2027 年末 30 套（加增资投资、建设工程、融资租赁、委托代理、合作联营、数据处理）；2028 年末 40 套以上。数量不是质量证明：每套必须通过盲测才上架。

**法变联动**：规则引用法规版本库中的具体版本。法规修改或废止时，系统列出受影响规则、进行中任务与历史签发件；紧急变更当天评估并可暂停规则，普通变更目标 5 个工作日完成影响审查；来源不能及时更新时显示“最后核验日 / 覆盖限制”，不显示“最新有效”。

### 3.2 规则提炼助手（新增）

把“本所标准”从人工 FDE 写作变成**工具辅助、人工审定**：

1. 知识管理员或 FDE 在**律所侧（管理员客户端或所内节点）**导入本所历史审查意见、修订稿、内部审查清单（事项授权范围内、经权利确认）；材料不离开律所，比对与聚类在本机完成，只有归纳候选规则时调用模型（化名后）。
2. 系统比对“原稿 → 律师修订稿”的差异，聚类出候选规则：触发条款、修改方向、频次、示例与出处。
3. 法律工程师逐条编辑为规则包格式，标注与平台基础规则的关系（加严 / 放宽 / 新增）。
4. 在本所样本上回测，生成差异报告。
5. 团队合伙人批准后发布为本所覆盖层；不自动上线，不进入平台基础规则。

G2 作为 FDE 内部工具使用；G3 开放给知识管理员。它对应的验收：候选规则出处可回链 100%；未批准规则零生效；回测报告随发布归档。

### 3.3 方法资产保护（端侧分发后的现实做法）

律所侧执行意味着规则包、方法包与模板要下发到律师电脑与所内节点。**端侧下发后不存在“不可提取”**——v4.0 的“只在服务端组装”也挡不住规则实质通过修订卡、意见书与“触发了哪条规则、为什么”暴露给律师。v5.0 用“提高复制成本 + 可追溯 + 让复制品快速贬值”管理风险：

1. **签名加密分发**：规则包、方法包与模板以签名加密包发布；内容密钥由律所许可证包裹；内核在内存中解密，Agent 任务需要时解密到每任务临时目录、结束即清除；不以明文落盘。
2. **随许可失效**：内容密钥随许可到期失效（所内节点或客户端定期续租），停止续费后新任务无法使用规则包；已签发成果不受影响。
3. **按律所水印**：每家律所收到的规则包在规则 ID、措辞变体与示例上有可追溯的差异，泄露后可定位来源。
4. **合同约束**：服务协议禁止逆向、提取与转售；私有化版附使用范围、审计与返还条款。
5. **让复制品贬值**：规则包与法规版本库联动，法变后 5 个工作日内复核更新；复制出去的旧版本会快速过期。真正的壁垒是维护节奏、评测资产与上线服务，而不是某一版规则文本。
6. **本所覆盖层归律所**：律所自有规则只在律所侧同步，中软看不到（除非律所为上线服务授权）。

## 4. 模板资产

- **要素式文书**：以 2025 年推广的 67 类新版为准（旧 11 类试行文本已废止）；G1 首批 6 份（买卖合同、民间借贷、金融借款合同的起诉状与答辩状，已定位法院官网 2025 版 PDF）；入库前逐份核对 **2025 版版本指纹**（删去送达地址与电子送达栏、新增“对纠纷解决方式的意愿”栏等），因为部分地方法院仍挂 2024 试行版；2027 年末 20 类，2028 年末覆盖 67 类；每季度巡检地方差异。劳动仲裁申请书无全国统一要素式样式：采用“当地普通格式 + 我方要素清单”，山东等有省级要素式办案规范的地区单独适配。
- **交付件模板（22 个首发）**：审查意见书、条款问题表、修订稿与清洁稿规范、谈判要点表、对方版、回稿比对报告、回稿差异表、案卷总目录、事实时间轴、证据目录、争点证据矩阵、补证清单、材料质量报告、要素式起诉状/答辩状、金额测算表、提交前核对清单、研究备忘录、类案检索报告、检索记录、引用核对表、顾问答复与内审底稿、脱敏报告与材料发送范围表；每份交付件附“出处与复核记录”。
- **合同范本**：以官方合同示范文本为底（按具体资产登记许可），按规则包改编为可审、可起草的结构化范本；律所范本进入本所范本库，权属归律所。

## 6. 评测与任务环境资产

### 6.1 评测集

见第 3 篇 §7：360 个独立业务任务 + 工程专项；2027 年末 1,000 个，2028 年末 2,000 个。材料来源：设计合作律所授权的脱敏材料（只用于该所与本项目评测，另签书面授权才进入通用评测集）、去标识的公开裁判文书、合成合同与案卷、官方示范文本。化名的真实案卷仍不是匿名数据，按受保护数据管理。

### 6.2 外部基准的使用

无许可证的数据集只借鉴任务设计；许可层面可用的数据集逐子任务核对后使用；海外基准（以英美法为主）只借“任务 + 评分细则 + 执行沙箱”的方法。**商业法源返回的数据既不能进训练集，也不能进评测集**（法律之星协议明确禁止用于验证与测试）：评测题以官方法律文本（著作权法第五条）自建，或用许可明确的开源集；评测集引用法源时只保存来源标识。（许可核验细节见本轮调研 R4 与 09-28 子报告。）

### 6.3 任务环境与联合后训练

- **任务环境**：任务说明 + 材料 + 模拟工具 + 律师评分细则；2027 年末 300 个，2028 年末 1,000 个，覆盖三条业务线的生产场景。首先用于评测与回归，**是否用于后训练由增益与成本实验决定**。
- **数据依据**：只用已合法公开且去标识的信息、合成数据与另签书面授权的数据；不使用任何客户材料；不违反网站协议采集。
- **与月之暗面的安排（谈判目标，非既有承诺）**：中软提供任务环境与标注，月之暗面在 K 系列上做法律后训练；环境与标注归中软，权重归月之暗面；发行版享有优先或一定期限的独占使用；推理价格优惠；效果评测双方共享。

## 7. 客户知识资产与反馈飞轮

- **本所覆盖层**：规则提炼助手 + 法律工程师从律所历史资料提炼，合伙人批准生效；到期可导出自有规则。
- **范本库**：律所上传范本 → 条款拆解与标注 → 起草时优先引用。
- **历史成果入库**：经办律师推荐 → 业务合伙人审定 → 知识管理员核查秘密与权利 → 明确跨事项访问范围后发布。当前案件材料默认只用于本事项。
- **反馈分层**：律所内改进、跨律所统计、通用训练**分别授权**，不捆成一个同意项；修订卡的接受、拒绝与原因在律所侧生成覆盖层改进建议；**中软只能在律所选择开启“规则级统计回传”后收到去标识聚合计数**（规则 ID、版本、采纳/拒绝/修改次数、拒绝原因类别，不含任何文本），用于改进基础规则；**不自动训练**。没有中心数据后，这是质量改进的主要信号来源，要在试点合同中约定开启。

飞轮：律师使用 → 拒绝原因与修改沉淀 → 覆盖层与基础规则改进 → 采纳率与直接可用率上升 → 更多团队采用。事项记忆默认只在本案有效。

## 8. 权利边界

“公开可查询”“robots 允许/不允许”“不受著作权保护”任何单点都不足以决定全部商业复用权；法律文本的著作权、网站访问约束、数据库编排、个人信息与合同许可分别判断。律所上传不代表拥有客户秘密与第三方版权的再利用权。自研规则包可作平台资产，但不得冒用律协或法院的官方认证；全国律协《律师业务操作指引》等出版物未经授权不入库、不摘录进产品。模型输出不作著作权归属的绝对保证。
