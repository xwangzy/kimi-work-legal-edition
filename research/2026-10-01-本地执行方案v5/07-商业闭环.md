**为什么团队版 3 席起、并赠审阅签发席**（沿用）：提成制律所的小团队是最常见的预算单元；3 个生产席（含 1 个审阅签发席）约 2.94 万元/年，团队负责人可在团队分成内决策；让合伙人零成本进入签发链，治理价值才能发挥。

**加购**（沿用）：加量包 800 元/1,000 点；法源与专业插件包按成本加管理费；本所规则上线与定制 4,000 元/人天；现场培训按场次。脱敏作为默认能力，不单独收费。**所内节点软件不单独收费**；团队版可加购“**节点部署服务包**”（假设一次性 8,000 元：在律所 NAS 容器或小主机上部署、加固、备份与恢复演练；或提供预装的“节点小主机”按成本价另计），律所版平台费已含部署服务。没有 IT 的提成制团队靠这个包才能用上 IM 审批、定时提醒与离线续跑——试点期统计团队版的节点部署率。

**基本保密不分档**：事项隔离（密码学伦理墙）、签名审计、来源可核、人工复核、数据去向卡、基本退出适用于全部付费版本。高价可以买私有模型、集成与更高服务等级，不能买基本保密的豁免。

### 1.3 点数与额度：本机按任务扣点 + MaaS 费用硬上限

v4.0 的点数由云端网关按任务类型固定扣减；v5.0 的云端只看得到 token，不知道“这是一份合同审查”。律师需要的是可预期的“每类任务多少点”，中软需要的是律师无法绕过的成本上限，所以分两层：

| 层 | 做法 |
|---|---|
| **任务点数（对外）** | 沿用 v4.0 按任务类型固定标价（“起”）：合同审查 30、回稿比对 10、案卷整理 40、要素式文书 10、研究与类案 80、顾问问答 1、Agent 模式 60；超出标准范围（更长、扫描件、严格无缓存）按档重新预估。由**本机账本**扣减，任务前显示“预计 30 点（约 1 份 30 页合同）”，界面余量显示“约可审 N 份合同” |
| **费用硬上限（对内）** | 中软 MaaS 为律所账户设置**月度模型费用上限**（按“席位数 × 每席月度点数 × 标定系数”折算并留余量），令牌剩余额度是律师无法绕过的硬上限；本机扣点可以被篡改，但篡改得不到额外的模型调用 |
| 法源按量费 | 不经 MaaS：由节点或客户端本机计量并计入任务点数，数据商按律所子凭据月结（第 4 篇 §9） |
| 对账 | 每月用 MaaS 消费记录与本机账本对账：按任务类型统计“标价点数 vs 实际成本”，偏差持续超出护栏时调整标价或标定系数（G0 实测后定稿） |
| 平台原因失败 | 超时、引擎崩溃、MaaS 或上游 5xx：本机不扣任务点数；对应的 MaaS 消耗在月度对账后返还额度；律师主动取消、预算暂停前已产生的消耗如实显示 |
| 结转与归集 | 月发额度在年度合同期内结转，到期失效；加量包有效期写明；额度耗尽时已签发成果仍可访问与导出（本来就在律所）；“事项 / 团队 / 个人”三级展示 |

经济模型中的“月消耗点数”与“每点成本”按任务标价点数计算（与 v4.0 一致）；按任务类型的实际成本差异（例如案卷整理每点成本远低于顾问问答）由月度对账与标定系数吸收。

### 1.4 定价纪律（沿用 v4.0 并补充）

1. **不做不限次**：席位含额度，超额买加量包。
2. **公开团队版、审阅签发席、自带密钥版与专业版价格**。
3. **团队负责人是钱包**：先团队、后全所。
4. **私有化要贵**：它同时是价格区分工具与高敏需求的出口。
5. **防共享**：具名席位；每席最多绑定 2 台设备（设备证书）；同一时间一个活跃会话；MaaS 侧异常用量告警。
6. **试点不默认免费半年**：6–8 周、有明确额度的共创试点。
7. **不靠数据锁定续费**：律所数据本来就在律所侧，开放格式导出是默认能力。

### 2.3 毛利杠杆

1. **上下文工程**：稳定前缀在前以命中缓存；跨律所共享只到“系统提示 + 基础方法包”，其后插入按律所派生的盐值块，材料片段不跨律所命中（V1 提示同一前缀跨律所命中是保密评估点）。**基准以“企业协议下前缀缓存可用”为显式前提**，ZDR 下缓存是否保留在 P0 谈判中确认。
2. **推理档位**：K3 按步骤设 `low`/`high`，不用默认 `max`。
3. **路由**：抽取与分类走 K2.6/K2.7-code；Batch（标准价 60%）只在供应商书面确认文件留存与 ZDR 覆盖后用于非案卷负载。
4. **流水线化**：生产档都做成本机确定性工作流，比通用 Agent 循环便宜。
5. **算力外移**：解析、OCR、检索、比对与文书生成在律所硬件上运行——这是 v5.0 架构自带的成本优势。
6. **严格无持久缓存律所**：合同审查成本从约 7.5 元升到约 13.5 元，对这类律所提高预估点数或单列价格，不静默启用缓存。

## 3. 收入、盈亏与资金需求

### 3.1 关键假设（相对 v4.0 的变化）

- 席位、版本结构、价格、渠道、私有化成交数**与 v4.0 相同**（不因架构变化而假设更快的销售，便于对比；IT 审批更容易带来的转化提升作为上行空间，不进基准）。私有化成交只含 P2（律所内 K2.6 级）与 P3，硬件由律所采购；P1（中软专属推理）为 2028 年评估项，不进基准。
- **云平台固定费**：v4.0 为 2027–2030 年 120/200/280/330 万元；v5.0 改为 MaaS 法律分组分摊（独立上游组织、等保与运维、MaaS 侧开发）、境内 CDN、Office/WPS 兼容测试农场、代码签名与时间戳：60/80/100/120 万元。
- **合规认证**：v4.0 为 120/80/90/100 万元；v5.0 为 70/50/55/60 万元（不再有托管 SaaS 的等保三级测评；保留登记、MaaS 分组定级、推理共享实例评估、TC260 对照与红队、法律意见）。
- **编制**：平均 2026 年第四季度约 29、2027 年 46、2028 年 53、2029 年 59、2030 年 65 人（v4.0 为 26/43/54/64/72）：减少云平台运维与 SRE、专属云与私有化交付线；增加 Kimi Code 嵌入、文档与化名、Windows 测试、法规库助理与桌面支持；人均全口径 45 万元/年。
- **律所版平台费**：按分档折算平均 30 万元/客户/年（v4.0 模型按 20 万元单档），并计入交付成本约 8 万元/客户/年（v4.0 模型未计）。
- **私有化**：首年成本率 45%→35%、维护成本率 40%→35%（同一软件，只增加模型部署与实施）。
- **缓存**：基准假设企业协议下前缀缓存可用；无缓存见 §3.4。
- 法源固定费、外部律师专家、市场与销售项目费沿用 v4.0。

### 3.5 集团层面的协同（不进入基准）

法律发行版的 token 全部经中软 MaaS 流转，是 MaaS 的行业应用层：MaaS 自身的渠道毛利、以及 07-20《Token 分成及联合创新合作协议》中“基于 Kimi 大模型产生的 Token 消耗收益”的分成（公告未披露比例、首期优先能源电力，法律是否纳入需协议确认，V1 一手），都在集团层面增厚收益。法律产品自身仍按“席位收入 − token 转移成本”核算，不把这部分计入基准。

### 3.6 不确定性的处理

财务决策以阶段门为单位：至 G2 结束累计约 1,080 万元（第 8 篇 §4.2）；G2 以“至少两家覆盖已验收范围的付费订单 + 价格不低于成本护栏 + 任务贡献为正”决定是否扩张。模型每月用 MaaS 账单、真实任务分布、成交折扣、法源报价与支持工时更新。

### 5.2 设计合作律所（G0 签 3 家，沿用并补充遴选项）

组合：1 家非诉为主 + 1 家诉讼为主 + 1 家有 IT 团队的区域规模所。遴选时必须摸清：**IM 平台、Office/WPS 版本结构（含批量许可比例）、客户外部群所在平台、电脑配置（内存与 CPU 分布、Windows 版本、安全软件）、操作系统与芯片构成（macOS 与 Windows ARM 占比）、是否使用云桌面或远程桌面、是否有可做所内节点的服务器或 NAS**。若设计合作律所的 Mac 占比超过 20%，把 macOS“只读审阅 + 直出修订稿”提前到 G2。

### 5.3 叙事

- **给合伙人**：按本所标准干活；每份交付件都有出处与签名签发记录；**原件与成果默认留在律所电脑与所内节点，模型只收到经化名校验的必要片段（化名覆盖率按专项报告披露），每一次发送——包括经律所自有 IM 的收发——都记录在数据去向卡中，可以拿给客户看**；大所可选律所内私有模型。
- **给律师**：像 Kimi Work 一样指着文件夹干活；断网也能核验法条、比对回稿；结果直接是能在 Word/WPS 里继续改的修订稿。
- **给管理层与 IT**：出站只到授权的 Kimi 接入渠道与少数白名单域名；密码学伦理墙；签名审计；TC260 本地智能体逐条对照表与证据包随交付。
- **背景**：海外头部法律 AI 公司选择 Kimi K3 作为法律后训练基座——行业背景，不是本产品的质量证明。

## 6. 竞争定位

竞品矩阵见第 9 篇附录。

### 6.1 什么不再是差异（沿用 v4.0）

“桌面 Agent + Skill + IM + 审计”、Word/WPS 里做修订、数据商 MCP——都已有多家具备，不采用“国内唯一”口径。新增两点（V4 一手）：

- **“本地执行 + 云端模型 + 可选本地模型”不是独有卖点**：腾讯 WorkBuddy 官方文档写明自动操作本地文件、以工作空间为边界的沙箱、本地与云端端到端加密、模型可选（含 Kimi）并支持 Ollama 本地模型。律所侧执行是正确的形态，差异必须落在法律专属治理与内容上。
- **海外**：Legora 提供客户自管密钥（BYOK）；Harvey、Spellbook 官网只承诺模型方零留存；三家官网都未见私有部署。发行版的私有模型端点在对标中仍是差异，但不宜夸大。

### 6.2 差异收敛为一句话与五个支点

**以中国律所的正式交付链为验收单位，在律所侧完成：把中国法源、事项级签名签发与受众版本、Word/WPS 回稿（含静默改动）、引用核验证据包与逐段数据去向放进同一事项。**

1. **法律交付保真与可追溯**：原生修订与回稿静默改动检出、受众分版与泄露检查、签名签发绑定确切文件、引用核验证据包。
2. **本所标准**：规则包与本所覆盖层、规则提炼助手、上线服务。
3. **可证明的律所侧治理**：不是“本地执行”本身（通用 Agent 已有），而是律所级的出站闸门与逐段数据去向证据、模型真实性校验、密码学伦理墙、签名签发与审计链、所内节点，以及与律协指引、TC260 的逐条对照——通用平台不会为律所做这些。
4. **可信与治理**：引用四态核验与拦截可见、离线法条版本核验、AI 标识流程、TC260 对照。
5. **中软的交付与私有化能力 + Kimi 品牌与模型合作**：FDE、私有模型部署、国产算力、政企客户关系。
