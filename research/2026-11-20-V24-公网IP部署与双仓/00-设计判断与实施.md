## 1. 审计结论（先查清楚到底卡在哪）

两路独立审计（云端、客户端）加我逐条回查源码，结论一致：**没有任何代码拒绝 IP 字面量**。“连不上 IP”真正卡在证书：

| # | 位置 | 事实 | 是否阻断 |
|---|---|---|---|
| 1 | `packages/egress-gate/src/tls-policy.ts` | 闸门对中软上游只认 Node 内置公共根 + SPKI 钉住（≥2 把）；`caPem` 只给律所私有端点。按 IP 访问时 Node 只核对 **IP SAN** | 阻断：需要带 IP SAN 的公共 CA 证书，私有 CA 无路可走 |
| 2 | `scripts/make-release-config.mjs:77` | 用 `cert.pubkey` 算“当前”钉住——EC 证书的 `pubkey` 是 65 字节裸点而不是 SPKI，算出的钉住永远对不上（已用 ECDSA 证书反向验证：旧算法得 `jOwv…`，客户端得 `Fkp4…`） | 阻断：certbot 2.x / lego / acme.sh 缺省都是 ECDSA |
| 3 | 同上 `servername: u.hostname` | IP 不应发 SNI（RFC 6066），Node 告警；IPv6 带方括号直接失败 | 小 |
| 4 | 云端 `docs/部署手册.md` | 证书按 4 个域名 `certbot --webroot -d` 签；Ubuntu 24.04 的 certbot 太旧，不支持 IP | 阻断 |
| 5 | `install.sh` | 删默认站点后才有 ACME 回调位置、而回调位置要等证书存在 nginx 才起得来：首次签发死锁 | 阻断（与 IP 无关的旧缺陷） |
| 6 | 部署手册防火墙 | 示例 `ufw allow from 10.20.0.0/24 to any port 22` 在公网机器上会把 SSH 锁死 | 风险 |

## 2. 设计判断

1. **不放宽任何一项校验**。IP 部署的正解是给 IP 发证书，而不是让客户端少校验。公共 CA 方案下客户端零改动；演示 CA 只是没有 80 端口或签发失败时的后备。
2. **演示 CA 的作用域要比系统信任窄**（偏离 D-212）：CA 证书只经测试构建的 `release.json` 下发、只对中软上游生效、**替换**而非追加公共根；钉住照常必须命中、IP SAN 照常核对。正式发布构建（无 `test_build`）拒收 `cloud_ca_pem`，`make-release-config` 也拒写。
3. **云端地址与业务逻辑早已解耦**（地址只在 `release.json`），缺的是“不重装就能换地址”。做成**签名的地址配置**（偏离 D-213）：发布方离线 Ed25519 私钥签 `cloud-endpoints.json`，客户端用随包公钥验；只能改地址、钉住与（测试构建的）私有 CA，信任锚（控制面/席位公钥）只随安装包。IP → 域名迁移、换证书私钥都只签一份新配置。
4. **两个仓库由 monorepo 导出**，不分叉源码：云端沿用第 46 批的 `cloud-repo/export.mjs`；桌面新增 `desktop-repo/export.mjs`（偏离 D-214），只导出 git 跟踪文件，按引用闭包把要起本机云端栈的联调用例留在 monorepo；四个契约包两端同源（SOURCE.json + verify-source）。
5. **试用构建不进桌面仓库**：`--trial`（D-160）把云端网关与可还原的 MaaS 密钥打进安装包，与“客户端不持有上游密钥”的边界相反。

## 3. 偏离登记

- **D-212** 中软云端私有 CA（演示/测试部署）：`release.json` `cloud_ca_pem` → `ZR_CLOUD_CA_PEM` → `GateUpstreams.cloudCaPem` → 闸门对网关、检索、控制面、分发、支持、通知、中继的 `upstreamFetch({ caPem })`。只许 `test_build`；只收 CA 证书（basicConstraints CA:TRUE）、不收私钥；替换公共根。用例 `packages/egress-gate/test/ip-cloud-ca.test.ts`（8 例：IP SAN、无 CA 失败、钉住不符断开、只写域名的证书按 IP 失败、别的 CA 即使钉住命中也拒绝）。
- **D-213** 签名的云端地址配置：`release.json` `endpoint_profile{deployment, keys}`；本机 `<数据目录>/cloud-endpoints.json`；`scripts/endpoint-profile.mjs gen-key|sign|verify`；主进程启动时 `applyEndpointProfile`，失败关闭、沿用随包地址；日志事件 `MAIN_ENDPOINT_PROFILE_APPLIED/PROBLEM`。不防回滚到更早的合法签名配置（已写入文档）。用例 `apps/desktop/test/ip-endpoint-profile.test.ts`（10 例）。
- **D-214** 独立桌面仓库导出：`platform/desktop-repo/`（manifest、export.mjs、template）。
- **D-215** 随包子进程改用 `spawnNodeChild`（spawn + stdio `ipc`）：安装包关闭了 Electron runAsNode 熔断，Electron 44 拒绝应用内 `child_process.fork()`，此前**所有安装包**都拉不起出站闸门、Agent 宿主、W 执行域与解析进程（开发形态熔断未关，未暴露）。最小测试包实测 fork 抛错、spawn + ipc 正常；回归门禁 `packages/kernel/test/b50-no-fork-in-app.test.ts`。
