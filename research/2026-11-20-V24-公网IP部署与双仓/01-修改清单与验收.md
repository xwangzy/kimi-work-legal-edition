## 4. 未验证与遗留风险

1. **真实公网服务器未部署**：Let's Encrypt IP 证书真实签发、80 端口可达、限额与续期节奏、云主机回环 NAT 行为都要在用户服务器上验；拿到服务器后按部署手册 4.5 执行。
2. **Windows EXE 未在 Windows 真机安装运行**：只做了 macOS 上交叉打包与静态核验（asar 内 release.json、内核已无 fork、随包 node.exe 与锁文件一致）。D-215 修复对 Windows 同样必要，但未实测。
3. **未签名**：EXE 无 Authenticode、DMG 仅 ad-hoc；macOS 每次重签都会弹钥匙串授权框（本次演练用户点了三次“始终允许”）。
4. **TLS 失败的提示过于笼统**：证书错误时律师端只显示“AI 服务暂时不可用”，IT 难以区分网络与证书问题——建议后续把 `tls_pin_mismatch` / `tls_verify_failed` 显示到“设置 → 连接”。
5. **事实确认标记**：律师函预览里事实处仍带“未确认”角标（论点确认框里已勾选“同时确认 10 条事实”），导出的 Word 不含该标记；是否为确认未落库需产品侧复核（与 IP 部署无关）。
6. **签名地址配置不防回滚**到更早的合法签名配置；签名私钥须离线保管（本次放在 `~/.kwl-demo-secrets/endpoint-keys/`，不入库）。
7. 演示 CA 模式下浏览器打开控制台会提示证书不受信任；正式演示请用公共 CA 的 IP 证书。
8. 备用 TLS 私钥按设计生成在服务器 `/root/kwl-offline/tls-backup/`，须拷到离线介质后删除（脚本会提醒）。
