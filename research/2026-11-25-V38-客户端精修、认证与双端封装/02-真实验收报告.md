## 5. 独立复核（只读子代理）与修补（0.5.1）

结论：**没有高危问题**；闸门先于全量核对拉起的机制成立（闸门只装载已核对的两个文件、无 NODE_OPTIONS、node/ 目录无清单外 DLL；闭包有一项不符即不放行；单飞启动成立；摘要异步化没有扩大 TOCTOU 窗口）；新 IPC 发送方与取值都有核对；首帧不露工作区。中、低档发现与处置：

| # | 发现 | 处置 |
|---|---|---|
| M1 | 要重新登录时整窗不可用，断网时打不开本机事项（以前横幅下工作区照常可用） | 按本批要求（退出即回登录页、避免未授权访问）有意如此；文案已写“都还在、登录后恢复”。**是否给离线只读入口请拍板** |
| M2 | 退出时发出的同步，答复在重新登录之后才回来，会把刚登录的人踢回登录页并落盘 | 已修：只认“这次请求带的会话就是现在的会话” |
| L1 | 本机记录被删 / 读不出时退回旧行为（等同步撞上才回登录页） | 未改：失败即关闭会误锁第 44 批之前凭码开通、没有会话文件的老电脑 |
| L2 | 记录字段没校验类型（本机同用户可写怪值让登录页出错） | 已修：逐项按类型与长度核对 |
| L3 | 开通 / 入组写会话不删旧记录；降级再升级会留旧记录 | 已修：开通写会话时删；启动时会话比记录新则记录作废 |
| L4 | 删记录抛错（Windows 文件占用）会让登录报失败 | 已修：捕获、记日志 |
| L5 | 很旧的云端没有 /v1/meta 时回 not_found，不会走旧流程 | 已修：not_found 也按旧流程 |
| L6 | 关闭期间仍可能拉起闸门；闭包不符时关闭会卡住 | 已修：关闭后不再拉起，关闭最多等 3 秒 |
| L7 | 全量核对不符后闸门放行标志未撤回 | 已修：先撤回再停内核 |
| 细节 | 重新登录页首帧不带上次邮箱；“绑定手机号”入口取不到策略时无限自动再试 | 已修 |

修补在提交 `e95aba41`（版本 0.5.1），用例 `b64-login-state` 与内核账号 / 闸门用例 61/61。**0.5.1 DMG**（`376b1831…`）已在本机首启复测（骨架 → 两种方式，1.07 s）并在线上 Mac 验过：用户 16:11 在 0.5.0 里退出登录 → 换装 0.5.1 重启仍停在登录页 → 密码重新登录（记录删除、会话恢复）→ 检测连接 → 问答 12 秒（《劳动合同法》第十九条）。Windows 0.5.1 见 §5.1。
