## E. 交互范式（可直接用于 demo 设计）
三种主界面范式：
1. **对话式** — 探索性开放问题；冷启动焦虑靠 prompt library 解
2. **工作流式/Skills** — 高频标准流程；三层演进：预置workflow(Lexis 300+) → 无代码自建(把律所 playbook 代码化) → 白手套服务。**这是律所愿付高价的根因：从"AI帮我"变成"AI执行我们所的标准"**
3. **表格式/Matrix** — 行=文档,列=提问,单元格=带来源的答案；批量同构文档横向比对
决策规则：1份文档→对话/双栏；几十到几千同构→表格；重复标准流程→工作流

引用设计六惯例：内联编号chip+右侧Sources面板编号严格一致 / 面板是并列区域非模态且流式输出时即可见 / 卡片可点开原文可悬停预览 / **定位精度分级：文档级<页面级<段落级<行级(EvenUp 行级为最佳实践)** / **验证状态标记(法律独有)：Shepard's Verify、Midpage treatment 三色信号+推理理由** / 无障碍

文档+AI 布局：双栏 60:40 或 70:30 且点击引用左侧滚动高亮（双向联动是核心）；Word 侧边栏范式（合同类绝对主流，原则=不把律师从 Word 里拽出来）；三栏（文档列表|正文|AI输出+问题清单）；**Definely 上下文浮层**（光标停在定义术语上就地浮现可编辑，解决"跳转即失去上下文"，且不依赖 LLM）

表格式完整规范：行=文档(自动从DMS/VDR导入)，列=自然语言提问(非预设字段,这是与传统尽调软件的根本区别)，单元格类型多样可筛选排序
点击单元格展开五层：①答案 ②推理链 ③原文摘录 ④源定位(文件名+页码/条款号) ⑤一键跳转高亮
**协作层是"AI输出→工作产物"的临界设计**（Legora）：Mark as Reviewed / Lock Cells(防AI重跑覆盖) / Review Mode / 单元格·行·列级评论 / 实时多人

人机协同链路：AI分析→以 tracked changes 插入正文→律师逐条接受/拒绝/改后接受→导出结构化 issues list
三原则：①AI建议必须"可拒绝"不能"已生效" ②给"为什么"不只"是什么"（VLAIR 红线数据佐证）③**Playbook 是人机协同的契约**——把机构知识变成机器可执行规则，同时解决"AI按什么标准审/律师知道为什么这么建议/初级律师学到资深判断"
责任天花板（Garfield 持牌 AI 律所）：非自主，每步需客户批准；具名持牌律师对所有系统输出负最终责任

## H. Harvey 产品拆解要点（可借鉴/不可照搬）
IA 演进：2024 左导航 [客户-案件号 | Assistant | Research | Vault | Workflows | History | Library] → 2026 [Agents | Vault | Knowledge | Spaces | Command Center | Contract Intelligence | Mobile | Ecosystem | Memory]，即 chat-first → agent-first + context-first
- **客户-案件号(Client-Matter Number)作为全局强制上下文**，每次查询强制关联，用于伦理墙+计费归因+数据隔离 ← 中国律所有案号体系但无AI产品挂钩，机会点
- Vault 容量三级跳：1,000→10,000→100,000 份/vault；单文件上限 500MB
- **Review Table**：行=文档，列=问题；列可设数据类型(摘要/日期/货币/逐字引用/是否)且系统自动建议；一键抽取模板召回率 并购协议27字段99.66%、SPA 32字段98.13%、租约24字段97.20%
- **三色旗标分诊**：红=deal-breaker / 橙=谈判点 / 黄=标准条款 → 风险视觉地图
- 单元格点开 = Harvey摘要 + 合同原文精确语句 + **句级引用** + **reasoning字段**(文档说了什么/如何理解/为何如此结论)
- 协作三件套：指派assign / 评论 / 标记已核验verified + Cell Lock + 状态侧滑面板 + 可对表格本身再提问(答案纳入旗标评论等团队元数据)
- 引用粒度从单元格级下沉到句子级 → 盲评偏好度提升 **4 倍**(复杂文档 7 倍)，几乎不依赖更强模型，纯产品设计
- 人在回路三闸：Preview&Approval(执行前可改计划) / Nudges(需判断时主动提醒) / Auditability(每步留痕)；Slogan "Delegate the Work. Own the Judgment."
- Word 建议一律以 tracked changes 呈现，**nothing applied automatically**
- Agent Builder / Playbook Builder / **Words to Workflows（自然语言→工作流草稿）** + 管理员审批流
- Command Center：按业务组/角色/地区下钻的采纳度分析 + **同业基准对比** + 对数据自然语言提问 ← 续费与扩座武器，国内普遍缺失
- Memory：只存个人偏好与工作风格，**明确不存客户或项目细节**，全平台一致，用户可查看/编辑/删除，"never used to train"
- 组织：**约20%员工是律师**；Legal Engineer 是正式工程岗，要求 JD + 3年顶级所执业，按 法域×专业领域×城市 三维细分
- 部署：A&O Shearman 方法论 = 沙盒(有限律师隔离环境) → 识别用例与风险、建治理协议 → 全所铺开

- Word 必要性论据："90% 法律人每天用 Word，56% 每天在 Word 里>3小时"；律师日均 120 封邮件
- 设计语言（官网 CSS 实测）：自建双字族 HarveySans(基于 ABC Diatype 可变字重)+HarveySerif；**暖调灰阶**非中性灰；主色 --color-gray-950-ink #0f0e0d 与 --color-gray-50-ivory #fafaf9（"墨与纸"隐喻）；强调色 dark-casal #333f40 / dark-bronze #593d3a / dark-velvet #373340 全为暗调；唯一高饱和色 --color-highlighter #f6f202 荧光笔黄；缓动 cubic-bezier(.7,0,.3,1)

## I. ⭐ 中国特有政策抓手（产品设计的差异化支点）
1. **类案检索报告是法定动作** — 最高法《关于统一法律适用加强类案检索的指导意见(试行)》2020-07 施行：
   - 类案定义=基本事实+争议焦点+法律适用三方面相似 → 相似度必须**分维度输出**
   - 检索优先顺序硬规则：①指导性案例 ②最高法典型案例及生效裁判 ③本省高院参考性案例及生效裁判 ④上级法院及本院生效裁判 → **权威层级排序优先于相似度分数**
   - 除指导性案例外优先检索近三年
   - 四类情形**应当**检索（拟提交专业法官会议/审委会、无明确裁判规则、院庭长要求、其他）
   - **须制作检索报告并归档**，载明检索主体/时间/平台/方法/结果/类案要点及适用分析 → **一键生成检索报告 = 杀手级功能且天然留痕**
   - UI 须区分「应参照」(指导性案例) 与「可参考」
   - 注意：律师要的是"对我有利的类案"，法官要的是"统一裁判尺度的类案" → **同一引擎两种排序策略**
2. **要素式文书有官方标准** — 最高法 2024-12-31 发文，2025-01-01 起在 **11 类常见民事案件**全面推行表格化、要素式起诉状与答辩状，发布 **67 类要素式文书样式** → 文书生成可直接对齐官方样式
3. **律协指引明确鼓励本地化部署** — 上海律协《律师企业法律顾问服务AI应用操作指引(2026)(试行)》、全国律协《律师提供居(村)法律顾问服务AI工具使用指引(2025)(试行)》：AI 仅为辅助不替代律师独立判断；律师承担最终专业判断责任；**鼓励通过本地化部署加强数据保护** ← 直接印证 Kimi Work 桌面本地形态的合规优势
4. **中国已有 AI 幻觉司法案例**：北京通州法院(律师提交 AI 虚假案例"（2022）沪01民终12345号"，批评教育)；湖北孝感大悟法院(水电表照片带"AI生成"水印伪造证据，训诫)
   - ⭐ 通州法院指出 **AI 编造案号有规律性特征**（12345/1234/111 等连续整数或重复数字）→ **可做确定性拦截规则**：案号格式校验 + 法院代字白名单 + 序号异常模式检测 + 权威库存在性校验，四重规则成本极低必须默认开启

## J. 数据现实（决定架构）
- **裁判文书网上网量断崖**：2020 约233.7万 → 2021 约167.2万 → 2022 约92.2万 → 2023 约57万 → 2024H1 约13.1万（媒体口径，趋势确凿数字待复核）
- 人民法院案例库(2024-02上线)主要面向法院内网，收录指导性案例+参考案例
- → 存量数据(2014-2021 数千万份)成为核心资产；得理法搜称 1.5亿+裁判文书[厂商宣称]
- → **律所自有数据是差异化关键**（DraftWise 路线：不拼公开数据规模，拼把客户历史成果变成可检索资产）
- 法规库权威源：国家法律法规数据库 flk.npc.gov.cn（2023-09 收录 22,556 件），无公开官方 API
- **法规是有版本的**，必须建法条时间线（历次版本+生效区间+修正对照），否则无法回答"合同签订时适用哪个版本"

## K. 模型选型的硬结论（中文评测数据）
- LexEval(NeurIPS2024 D&B，23任务/14,150题，最大中文法律评测集)：GPT-4 52.1% / Qwen-14B-Chat 50.2% / ChatGPT 39.7%
- **GPT-4 分维度：法条记忆仅 25.3%（最差）、生成 23.9%（最差）、理解 75.2%、逻辑推理 65.8%**
  → ① **法条绝不能靠模型参数记忆，必须 RAG**（第一性原理）② **文书生成必须"模板+要素填充"，不能纯生成**
- LawBench 零样本平均：GPT-4 52.35 / GPT-3.5 42.15 / Qwen-7b-chat 37.00
- **LexEval 与 LawBench 一致观察到：法律专用模型未跑赢通用模型** → **不要从头训法律基座，ROI 在检索与工程**
- 唯一值得做的微调：**法律域 embedding 与 reranker**（对比学习，正例取自关联法条与相似案例——智海-录问做法）
- 开源参考：DISC-LawLLM(复旦，DISC-Law-SFT 40.3万条公开，文档最完整) / 智海-录问(检索设计最完整：六类知识库+多路召回+对比学习embedding) / ChatLaw(MoE+Text2Vec，9.3万裁判文书训练query→法条映射)

## L. 幻觉控制三层防线（必做）
①生成时：结构化输出强制每个 claim 挂非空 citations；闭卷禁止；引用粒度到 chunk(条文号/判决书段落号)
②生成后独立校验（**校验器必须独立于生成器且用确定性/判别式方法** — Clearbrief 明确用"classic AI"非生成式，理由是校验工具本身不能产生幻觉）：
  存在性(精确匹配案号/条文号) → 支持性(NLI蕴含分) → 时效性(法条是否现行/案例是否被改判) → 语境(案例是否为反面论述却被当作支持)
③产品化引用审计：Clearbrief Cite Check Report 模式 — 扫描全部引注、输出 semantic match score、标记四类问题、**生成可下载 PDF 审计报告** → 律所需要的不只是少犯错，而是**能证明自己检查过**
- 斯坦福 RegLab 预注册实测：Lexis+ AI 幻觉率 >17%，Westlaw AI-AR >34%，整体 17-33% → **"零幻觉"营销不可持续，明确披露局限反而是信任资产**

## N. Word/WPS 集成的工程事实
- **必须做的理由**：Word 是律师的操作系统不是工具；修订必须是 Word 原生 tracked changes；交付物就是 .docx
- 技术选型：**Office Add-in (Office.js) 而非 VSTO**（跨平台、集中部署无需客户端安装、服务端更新即生效）
- ⚠️ **最大风险=版本碎片化**：律所大量使用批量许可永久版(LTSC)，WordApi 1.9 / WordApiDesktop 1.2-1.5 在 LTSC 标记 "Not available"
  → **核心功能锁定 WordApi ≤1.6**（修订 API 在 1.4 引入、1.6 增强 TrackedChangeCollection 可读取/接受/拒绝单条）；高版本运行时探测 isSetSupported + 优雅降级；最低实测配置 Office 2019 LTSC(WordApi 1.3)
- 性能：Office.js 是异步批处理模型，几百页逐段读极慢 → 一次性 body.getOoxml() 服务端处理，只把定位与写回放 Office.js 层，合并 sync() 调用
- ⭐ **WPS 加载项与 Office Add-in 同构**：也是"每个加载项对应打开一个网页+调用JS方法"；API 在 window.wps 下；**底层 Chromium 无浏览器兼容问题**；工具链 wpsjs create/debug 热重载；wps-jsapi 提供全部 TS 声明；支持 ribbon/dialog/任务窗格三大 UI 载体；**在线模式可指向内网地址天然支持私有化**
  → **80%+ 代码可复用**，只需适配层(office-adapter.ts / wps-adapter.ts)；注意 WPS 是 VBA/COM 同步风格、Office.js 是异步批处理，**适配层以 Office.js 异步签名为标准**，WPS 侧包 Promise
  → 企业用户需联系 WPS 项目经理确认安装包带加载项功能（2B 落地需与金山商务配合）
- WPS 自身：灵犀可识别合同法律风险点(通用办公级)；**WPS AI 政务版支持私有化部署，适配龙芯统信**；WPS 笔记开放原子能力对接外部大模型与智能体 ← 接入生态的窗口期
- 节奏建议：Word 加载项先行(律所/外资所/大型企业法务) → WPS 紧随(政务/国企/中小所/法院)

## O. 利益冲突墙（律所一票否决项）
核心原则：**AI 平台不重新实现墙，而是继承既有权威系统的墙配置**（Intapp Walls / iManage Security Policy Manager）
三层强制：①**检索层 pre-filter**（查询阶段注入权限过滤，被墙文档根本不进候选集。反模式=先检索再过滤，相似度分数与结果计数会泄露信息）②上下文层（Agent 记忆按 matter 边界分仓）③输出层（成果绑定 matter 继承墙配置）
⚠️ 陷阱：embedding 缓存、检索结果缓存、LLM prompt 缓存都可能跨墙泄露 → **缓存 key 必须包含 access scope hash**
Harvey 表述：每份文档、每个上下文窗口、每个输出都应可追溯到特定 matter 及其墙配置，审计日志"不可妥协"，因为要对抗对方的取消代理资格动议

## P. 审计留痕最小集
必记：actor + matter(含 wall_config_version) + action + **retrieved_sources(检索了什么，出事后要能回答"当时AI看到了什么")** + **模型/prompt模板/playbook 版本三元组(保证可复现)** + output_digest + human_action(谁何时确认了什么=已尽注意义务的核心证据) + citation_verification
存储：append-only / WORM / 哈希链（不可篡改，用于对抗取消代理动议与制裁风险）
保留期限与律所文件保留政策一致(通常结案后10年)；支持"零留存"模式(模型侧不留，律所侧审计日志仍保留)

### 引用四层递进验证链（必须组合）
角标(是否有据,0成本) → 悬停预览(够不够,0.3s) → 右侧来源面板(全不全,1s) → 点击跳转+原文高亮(对不对,2s)

⭐ 中文法律特殊要求（英美产品没有的维度）：
  - 引用必须带**时效性状态**：`《民法典》第585条 [现行有效]` vs `《合同法》第114条 [已废止 2021-01-01]`（橙+删除线）
  - 案例引用带完整案号+法院+年份
  - **效力层级在 chip 上可见**：法律/行政法规/司法解释/部门规章/地方性法规/指导性案例/公报案例/普通案例
  - 区分「法条原文(权威)」与「裁判观点(参考)」用不同 chip 颜色
⚠️ 纯数字角标是反模式 → 应显示来源身份(文件名/条号)

### 文档+AI 双向联动六规则
点引用chip→文档滚动+高亮(ease-out 300ms，黄#FEF3C7闪两下各200ms后保持) / 文档选中文字→浮动工具条[问AI][解释][找类似条款][标记风险] / 悬停AI句子→文档弱高亮 / **点文档高亮段→AI区反向滚动(多数产品漏做)** / 多引用指向同段显示×3角标 / 切文档时AI区不清空只加上下文条
⚠️ **不要做滚动条联动**（左右同步滚动会晕），只做点击跳转式联动
高亮视觉层级：引用黄#FEF3C7 / 风险红#FEE2E2+左3px红条 / 修订蓝#DBEAFE+波浪线 / 搜索橙 / 手动标注紫；同段最多同时2层

### ⭐ 修订建议卡三层结构（Ironclad，最可直接复用的组件规格）
**原文 + AI建议(diff高亮) + 触发该建议的 playbook 规则(含首选立场/可退让至) + [接受][修改][拒绝]**
"为什么给这个建议"比"建议是什么"更重要 —— 这是法律 AI 与通用 AI 的分水岭
七个细节：①"修改"必须就地编辑不是弹窗 ②接受后卡片折叠为一行并保留[撤销] ③全局状态条常驻(已处理4/7·接受3·拒绝1) ④**键盘优先 J/K切换 A接受 R拒绝 E编辑** ⑤按风险等级排序可切文档顺序 ⑥**两种显示模式开关：修订模式 vs 批注模式**（涉及"我敢不敢让AI碰我的文档"，要放最显眼处）⑦接受后落地为原生 tracked change
⭐ **Spellbook 的心理学设计：接受后的修订以律师本人名义呈现（AI 隐身，律师署名）** → 交付环节应提供"以我的名义落笔/移除AI标注"
拒绝时给轻量可选原因 chips[本案不适用][立场已谈定][表述不准确] → 反哺 playbook

### 批量任务进度（>2分钟是法律常态）
核心目标=**让用户能安心离开**。顶部总进度+四状态计数(完成/进行中/排队/失败，可点击筛选) / **结果流式填充不等全部跑完** / 单元格四态(排队浅灰点阵·生成中骨架屏shimmer·完成·失败红叹号+重试) / **失败不阻塞且给人能懂的原因**("扫描件OCR置信度过低"而非"Error 500") / 批量重试+单格重试 / 可暂停可取消且明确"已完成结果会保留" / 剩余时间给区间不给假精确 / **可离开+站内通知+邮件** / **成本按 matter 归集**(律所按案件计费，这是差异化机会)
Agent 长任务三件套：计划先行(Preview the plan…approve) → 实时步骤流 → **主动召回(Nudges)**

### 信任信号
⚠️ **法律场景不要显示"92%置信度"数字**（未校准、会被当量化指标、出错时放大信任崩塌）
✓ 改用**证据强度**（客观可核验）："基于 3 份文档中的 5 处明确表述" / "仅 1 处间接表述支持"+橙底 / "未在文档中找到相关约定"+灰色空态
"请核对"位置有效性排序：🥇贴在具体弱证据声明旁 > 🥈高风险动作按钮旁 > 🥉输出区块底部小字 > ❌登录弹窗/页脚固定声明
⭐ **缺失来源披露**是最被低估的信任设计 + 智合 AI「幻觉防火墙」的可视化 —— **不是默默不说，而是显式展示"我拦掉了什么"**
弃答设计：用中性信息卡而非红色错误框，说明原因+给出路([扩大检索范围][换个说法][手动查看])
⭐ Harvey 设计原则应贴在设计文档第一页：**"每一个论断都有出处，每一步操作都有记录"**

## R. 中国法律服务市场现实（商业测算基础）
### 规模与结构
- 执业律师 **83 万人**、律所 **4.5 万家**（2025-09 司法部）；年增速已从 2018 峰值 15.89% 降至 2025 的 3.75%

- **人民法院案例库对外开放但仅5,000余件** vs 商业库宣称1.4-1.8亿篇 = **4个数量级差距**
- 国家法律法规数据库 flk.npc.gov.cn 免费权威全量，但**只有法规没有案例**
- 裁判文书原文**不受著作权保护**（著作权法第5条，判决书裁定书属官方文件），抓取使用不侵权；但**汇编/编辑/标注构成汇编作品**，各家靠这层做壁垒；真正合规风险在**个人信息**
- → **中国法律AI的"检索"能力上限不由模型决定，由2021年前囤了多少文书决定**；新进入者要么买数据（北大法宝MCP/威科/元典API），要么绕开检索做别的

### ⭐ 中国律师真实需求 vs 伪需求
**真刚需（中国特有+高频+已验证付费）**：
1. 合同审查（带审查立场+三档输出：修订版简洁/详细、纯净版、审查意见书）
2. **刑事阅卷/卷宗要点提取/证据链梳理**（中国刑辩面对几十本纸质扫描卷宗，**美国没有这个场景，是中国法律AI最深的护城河之一**）
3. 要素式起诉状/标准格式文书（要素式审判改革带来的纯本土需求）
4. **文件脱敏**（PIPL+律师保密义务+上传第三方AI的合规焦虑）
5. **企业查询/工商穿透**（尽调、财产线索查控、被执行人财产调查是中国律师日常高频；美国律师不做这个，有专门investigator）
6. 法律翻译带术语库（涉外刚需，秘塔靠这个打进顶级律所）
**伪需求（美国场景照搬，不要做）**：
- 计费工时优化/Billable Hour分析（中国大量风险代理和打包价，工时不是核算单位）
- E-Discovery（**中国没有美国式Discovery制度，根本不存在这个流程**）
- Deposition证言管理（中国没有庭外取证制度）
- **判决结果预测/法官画像（政治敏感，最高法明确"人主机辅"，有极大合规风险）**
- Matter Management/Conflict Check 作为独立产品（只有规模所需要）
- 纯对话式C端法律咨询（已被百度法行宝、通义法睿、DeepSeek免费化，**商业上死亡**）
⭐ **一句话：中国律师愿意付钱的是"能直接交付给客户或法院的东西"（Word修订稿、审查意见书、要素式起诉状、阅卷笔录），不是"帮我思考"。产品评价标准不是"回答得对不对"，而是"下载下来能不能直接用"。**
