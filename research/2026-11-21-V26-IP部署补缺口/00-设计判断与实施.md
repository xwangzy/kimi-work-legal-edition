## 2. 修复

### 2.1 云端仓库 CI：Linux 上本机栈起不来（与 IP 部署的生产路径无关，但 CI 一直红）

- 根因：`stack-local.mjs` 经 stdio 第 3 路把上游密钥交给网关/检索（`upstream.api_key_file: "/dev/fd/3"`）。Node 在 Unix 上的 stdio `pipe` 是 socketpair；**Linux 按路径打开 `/proc/self/fd/3` 指向的套接字报 ENXIO**（macOS 可以）。网关读不到密钥退出，父进程这端没有 `error` 处理器，`ECONNRESET` 直接把 stack-local 弄崩，子进程成了孤儿。最小复现：同一段代码 Linux `path err ENXIO / parent pipe error ECONNRESET`，按描述符读 `fd ok`；macOS 两种都行。
- 修：`scripts/lib/secret-file.mjs` 对 `/dev/fd/<n>`（n≥3）按描述符读、同一描述符只读一次；`cloud-serve.mjs` 的 `read()` 改用它；`stack-local.mjs` 给密钥管道挂 `error` 处理。生产部署读的是 `/etc/kwl/secrets/*.key` 文件，不受影响。
- 回归：`services/control-plane/test/b52-secret-fd.test.ts`（真实子进程 + 第 3 路管道；Linux CI 上即门禁）。

### 2.2 换公网 IP 后控制台登录不了

- 根因：控制台打包（`build-console.mjs --control-plane`）把控制面来源写进 `index.html` 页内 CSP 的 `connect-src`；`ip-config.mjs` 只改 `config.json`。部署手册 4.7 第 3 步写着“换控制台站点与 CSP”，但 nginx 站点里没有 CSP——这一步其实没换。第 50 批换 IP 演练只用 `curl readyz` 与客户端核对，没开浏览器。
- 修：`ip-config.mjs` 改完 `config.json` 后用打包脚本同一个函数（`connectSrcFor` + `withConnectSrc`）改写 `index.html`，结果与按新地址重新打包逐字节一致，可重复执行（第二次报“未变”）。部署手册 4.7 第 1 步写明输出里应有的那一行，并要求用浏览器登录一次控制台。
- 回归：`services/control-plane/test/b52-ip-config-console-csp.test.ts`（真实脚本：旧 IP 打包 → ip-config 新 IP → 与重新打包逐字节比对 → 幂等）；两种目录布局（monorepo / 独立云端仓库）都能跑。

### 2.3 签名地址配置防回滚（偏离 D-217）

第 50 批 D-213 明确“不防回滚到更早的合法签名配置”。IP 场景下这不只是理论：公网 IP 会被云厂商回收再分配。

- 规则：生效过的配置原样存为 `<数据目录>/cloud-endpoints.applied.json`（0600，原子写）。之后放进来的配置 seq **更小**、seq 相同而内容不同、或签名验不过——都不生效，**继续用已生效的那份**（每次启动重新验签），而不是退回随包地址；`MAIN_ENDPOINT_PROFILE_APPLIED` 带 `source: file | applied`。
- 删掉 `cloud-endpoints.json` = 回到随包地址（换了新安装包、地址也随包变时就这么用），已生效记录保留，之后再放进更早的照样拒绝。要回到旧地址：签一份 seq 更大的。
- 边界：同一账户下能改数据目录的恶意程序可以连记录一起删，不在防护范围内（与 D-213 一致）。
- 用例：`apps/desktop/test/ip-endpoint-profile.test.ts` 新增 2 例（seq 2 → 3 → 拷回 2 被拒 → 同 seq 改内容被拒 → 篡改被拒仍用 3 → seq 4 回旧地址；删文件回随包、记录被改动即忽略）。

### 2.4 控制台网页的浏览器验证方法（不降低校验）

演示 CA 不受浏览器信任。验证时不装根证书、不关校验，而是给 Chromium 传 `--ignore-certificate-errors-spki-list=<服务证书 SPKI 钉住>`：只信这一把公钥（与客户端钉住同值 `0Ttg…`）。不带该参数时页面报 `ERR_CERT_AUTHORITY_INVALID`。

### 2.5 安装后冒烟真拉起随包子进程 + 桌面仓库 CI（Windows 真机）

- 问题：冒烟只记 `Boolean(s.egress_gate)`——闸门懒启动，对象在而进程没起来时照样 true。第 50 批 D-215（安装包里 fork 被拒、四类子进程全拉不起）正是这种故障，旧冒烟发现不了（monorepo run 44699532793 的 smoke.json 即为反例）。
- 修：内核主进程专用消息 `kernel.child_selftest`（不进 RPC 表，渲染进程够不着）：闸门 `ensure()` 且 running；解析进程解析一份内存文本 PDF 并读回固定串；Agent 宿主完成 init/ready 握手；宿主内按生产配置拉起 W 监督进程跑完启动自检（`echo` + `python3` 往返）。只回结果码，不带路径与报错原文，不联网、不调模型。冒烟写 `checks.children = {gate,kap,w,parse}`，任一非 ok 即 `child_<名>_failed`。
- 顺带发现并修：`kap-agent-client` 拉起宿主没有 `error` 监听——随包 Node 缺失或被杀软拦截（ENOENT/EACCES）会成为内核的未捕获异常；宿主握手前退出要干等 60 秒。
- 桌面仓库 `.github/workflows/desktop-ci.yml`：Windows（每次推送 main / 标签 / 手动）关键用例 → 测试证书签名 NSIS → 静默安装 → 冒烟（`scripts/ci/check-smoke.mjs` 要求四项子进程全 ok）→ 残留进程 → 结果文件已存在退出码 3；macOS 只在手动触发时跑（私有仓库 10 倍计费）。
- 用例：`packages/kernel/test/b52-child-selftest.test.ts`（开发形态真子进程全 ok；坏闸门/解析 Node、坏宿主 Node、坏运行时摘要各自报对应码且内核仍可用）、`apps/desktop/test/smoke-io.test.ts` 追加。

### 2.6 证书类失败说清楚 + “检测连接”

- 根因（逐条）：①问答：闸门 502 带 `tls_pin_mismatch`，model-broker 包成“模型通道 502（…）”，`qaFailureText` 没有证书类映射、兜底规则见到“502”即给通用说法；②任务：闸门自身错误只在 JSON 体里带码、说明里没有 `[kwl:代码]`，`agentFailureText` 按 50x 说“AI 服务暂时连不上”，确定性步骤还白白重试 3 次；③激活：`onboarding` 把所有 `cp_*` 并成 `cp_unreachable`；④登录：`cp_tls_*` 落到“请稍后重试”；⑤检索：证书失败记成 `search_upstream_unreachable`。
- 修：闸门对证书类与安装包配置类错误在说明末尾附 `[kwl:代码]`；内核 `cloud-connection.ts` 统一分类（证书 / 安装包配置 / 连不上 / 超时）与律师话；问答、任务（不重试证书类）、激活、登录、执行页时间线各自接上。
- “检测连接”（设置 → 备份与安全）：内核 RPC `connection.diagnose` → 闸门子进程 `probe`：对各中软上游 `GET /healthz`，**与真实流量同一 `checkUpstream` + `upstreamFetch`（同一钉住集、同一演示 CA，不放宽任何校验）**、每次新握手、不带凭据；结果分类 `ok / unreachable / timeout / tls_verify_failed / tls_pin_mismatch / tls_name_mismatch / http_<状态> / config_invalid / not_configured`，钉住只给短前缀，可复制给 IT。
- 用例：`packages/egress-gate/test/b52-connection-probe.test.ts`（7）、`packages/kernel/test/b52-cloud-connection.test.ts` 与 `apps/desktop/test/b52-connection-check.test.ts`（9，含真实闸门进程 + 错钥证书 → 律师话）。
