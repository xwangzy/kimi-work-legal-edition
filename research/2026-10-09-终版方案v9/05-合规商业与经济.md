## 2. 数据准入：四项依据分开记录

| 依据 | 解决什么 | 产品字段 |
|---|---|---|
| 委托与保密授权 | 客户是否同意律师使用 AI 与第三方服务、哪些服务、哪些材料 | `professional_authorization`：已同意 / 部分同意（范围）/ 拒绝 / 待确认 |
| 个人信息处理依据 | 对方、证人、员工、未成年人等非委托人主体的个人信息处理条件（同意不是唯一依据） | `personal_data_basis`：依据类型、主体范围、必要性说明 / 待确认 |
| 敏感信息特别条件 | 生物识别、医疗健康、金融账户、行踪轨迹、未满十四周岁未成年人信息等 | `sensitive_data_conditions`：特定目的、充分必要、单独告知或同意 |
| 转委托与次处理者范围 | 中软与月之暗面等的委托与转委托（PIPL 第二十一条） | `processor_scope`：已列明 / 待列明 |

任一项“待确认”时，该事项只运行不出站的本机能力；律师可一键生成告知函与委托合同 AI 条款模板（律所可改）。“无需同意”不是一个能放开全部外发的按钮。国家秘密等不适合标准产品处理的材料一律拒收，不是用户勾选可以豁免的设置。

## 5. 对外口径

见第 02 篇 §12。四条红线：不说“数据不出律所”（私有化全链路组合除外）；不说“中软不是处理者”；标准端点下不说“本地化部署”；不用绝对化用语。可以说：

1. “**案卷默认在律师电脑上处理和保存；团队共享在中软云端只以端到端加密形式存在。**”
2. “**模型推理会收到任务涉及的文档内容；证件号、账号、手机号、住址和自然人姓名在发送前替换为代号，机构名称保留，可按事项开启全部化名。**”
3. “**AI 写的代码默认在无网络的运行时隔离环境里运行（支持的 Win11 设备上为操作系统强制隔离）；经出站闸门的每一次联网都有记录。**”
4. “**具备 Kimi Work 在法律工作中用得到的本地 Agent 能力，并在律所策略之内运行。**”（不含建站、PPT 云技能、桌面操控）

## 6. 商业模式：席位 + 额度池 + 加量 + 上限

主流产品的通行做法（`调研-X1` A7）：席位订阅内含一个按 token 折算的额度池，靠成员上限、超额包与消费上限控制成本（Kimi 统一额度池、WorkBuddy 每人 2,000 Credits 团队共享、千问积分、Claude 席位 + 用量、ChatGPT credits）。只买 API token 时，这套会员计量能力不随 token 附带，由中软控制面与网关实现。

### 6.2 经济上最关键的四个设计

1. **子 Agent 强制低价模型、主循环 K3**：`[secondary_model].force = true`、`default_model` 为 K2.6 级，需要 K3 的子任务由宿主策略按预算审批。开放任务单次成本由 v7 的 ¥12.84 降到 ¥9.88；若未强制、30% 子任务改用 K3，2030 年经营结果约 −28 万（§7.4）。
2. **上下文缓存**：严格无持久缓存会让 2030 年经营结果从 +337 万降到 −141 万；企业协议须确保 ZDR 下缓存仍可用；令牌按事项确定性分配，保证令牌化不破坏前缀缓存（第 04 篇 P6）。
3. **并发与预算上限**：Swarm 并发 ≤ 3、任务预算预占、月消费上限，避免重度用户的长尾吞掉团队池。
4. **主口径不含加量收入**：加量包是上行情景，不是盈利前提（含加量收入时 2030 年 +667 万、现金谷底 −4,854 万）。

## 7. 单位经济与投资（`11-经济模型-v9.py` 复算）

## 9. 运营与退出闭环

| 场景 | 标准流程 |
|---|---|
| 开通 | 验证组织与管理员；策略模板；设备自检；示例任务；恢复演练；培训 |
| 入离职 | 组织角色与事项角色分别管理；撤设备、连接器、任务令牌；事项成果归属不随个人注销消失（律所档案成员） |
| 欠费或退订 | 停新增计费任务；退出模式下阅读、检索、导出、签名验证永久可用；不扣留客户已有成果 |
| 用户纠错与删除 | 核验请求权与保全；逐副本删除并记录状态 |
| 数据导出 | 原始文件、可编辑成果、事件 JSON Lines、出处清单、manifest 与签发证明 |
| 故障 | 状态页、分级、排队或暂停、通知、影响清单、复盘 |
| 安全事件 | 立即阻断受影响能力与令牌；保全证据；按法律与合同通知；协助律所评估 |
| 法律内容错误 | 定位规则与模型版本，停用相关模板，通知受影响事项负责人；不静默改写已签发件 |
| 供应商故障 | 显式排队或失败；只切已授权且评测合格的替代路径 |
| 停服 | ≥ 180 天通知与导出期；客户端退出模式；每周增量导出 |

## 10. 需要领导层拍板的事项

1. **划分原则**：以第 02 篇六条规则（能力补位、执行随事项、控制归云、隔离放权、远程降权人做不可逆、断云可用）为基线。
2. **事项数据模式**：本地事项为默认；云端事项作为 G3 可选模式（律所策略允许 + 事项负责人选择 + 四项依据）。**备选**：若 G0–G1 访谈显示多数目标律所明确要求云端托管协作，可把云端事项提前到 G2，代价约 +90 人周、首发即承担托管责任与等保范围扩大。
3. **Kimi Code 接入**：kap-server 私有嵌入，界面与远程只见业务 API；能力账本作为“完整接入”的验收定义。
4. **执行域**：W-core（模拟 bash + 零 JS 桥 Python，运行时隔离、如实标注）为默认；W-data（Pyodide/pandas）默认只在 MXC 等系统强制执行域内运行；任何设备上不在执行域外运行模型生成的代码；P2 不通过则代码执行降为“逐次确认 + 仅系统强制设备”。
5. **运行模式**：Chat + Work（手动 / 默认 / 自动）+ 先出计划；无“完全访问”；管理员可锁定。
6. **团队协作**：端到端加密事项共享（G1）；每设备独立签名密钥；律所恢复 2-of-3（律所版）。
7. **移动与 IM**：App 第一版（G2）只做通知、确认、提问作答、只读预览与无事项问答；遥控与移动签发 G3；IM 首发一家，试点决定。
8. **范围与节奏**：G0–G2 基线 981 + 预留 147 ≈ 1,128 人周；到岗 24 → 40 → 44（平均约 39 人）；首个商用版本目标 2027-06 下旬（以 G0 末实际到岗为准，最迟 07 上旬）；分阶段预算门禁约 170 / 595 / 800 万元（§7.5）。
9. **经济口径**：主口径不含加量收入——基准经营谷底约 −7,357 万元、现金谷底约 −5,135 万元、2030 年约 +337 万元，平衡点约 6,800–7,600 个平均生产席位（含加量收入时现金谷底约 −4,854 万元）；以“试点成交实现率”“每份被采用交付件成本”“付费席位与续费”为 G2 后的第一批校准指标。
10. **月之暗面 P0 条款**：授权渠道、排除服务优化、逐接口 ZDR、并发提额、模型下线通知期、上游 SLA 与安全事件通知、登记所需备案号，作为首家付费前门禁。
11. **出站最小化默认值**：证件、账户、联系方式与**自然人姓名**默认令牌化，机构名称保留（L3a 全部化名）；令牌只在界面与文书引擎导出时还原。
12. **MaaS 路径**：法律内容不经 new-api（网关直连月之暗面企业账户，MaaS 只做结算），或先完成 AGPL 合规评估。
