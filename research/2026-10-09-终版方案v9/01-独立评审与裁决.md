## 2. 结论先行

**v7 把维度找对了，v8 把框架摆正了，两者都没把“律师电脑上的代码执行”和“团队协作的默认形态”这两件最难的事落到可实现的路径上。**

- **v7 对的**：只买 token 时 Kimi Code 依赖的九类 Kimi 会员云服务必须由中软补位（能力来源维度）；用隔离代替删工具；远程渠道一律降权；控制面归云；数据去向卡与“中软看得到什么”分情形说明。这些是 v5/v6 都没做到、v8 也全部接受的核心洞见。
- **v7 错的**：把“案卷在所”当成架构公理而不是事项策略的默认值；kap-server 选型对，但让渲染进程与遥控经白名单直达其约 120 个路由（终端、配置、OAuth、插件安装、打开本机程序等管理面一起暴露）；在无管理员的 Windows 上设计五档原生沙箱、C 档用人工确认补隔离；把化名还原做进工具参数与 Shell；所有设备共用同一账户签名私钥；移动 App、端到端加密遥控、多种沙箱同时进入 G0–G2 却沿用原日期。
- **v8 对的**：采购清单不决定执行位置；按事项选择执行与存储位置（C/L/P）；“完整接入”用能力账本定义；Run/Attempt/租约/fencing/幂等/审批绑定版本这些可靠性语义；如实的删除与撤权口径；每设备独立签名密钥；不在 Shell 代码里做字符串替换；查出了现有代码的真实缺陷（已复核属实）。
- **v8 错的**：把 C（中软托管案卷、云端解密执行）作为团队的“推荐商业路径”，等于把“云端托管”变成小团队的事实默认，与用户 10-01 定下的方向和 Kimi Work“本地 Agent”的品牌定位相冲突，且 C 的建设与合规成本没有单列；L 模式的团队协作、移动与遥控基本没有定义；Windows 本机代码执行问题没有解，只是“达不到就关”——这会让大量律师电脑上的 Agent 能力缩水；产品完整度与决策力度不足，没有投资与现金视图。

**v9 的裁决**：保留 v7 的能力补位、远程降权、数据去向、kap-server 选型与产品完整度，保留 v8 的事项模式、能力账本、可靠性语义与如实口径；kap-server 改为只由我方 Agent 宿主访问的私有组件；用两项新设计解决两者都没解决的问题——①**W 执行域**作为所有设备的默认代码执行环境（模拟 bash + 零 JS 桥的 WASM Python，无需管理员、无网络、guest 不执行本机代码），隔离性质如实标注为“运行时隔离”，pandas 等数据分析库与原生二进制只在 MXC 等操作系统强制的执行域内运行；②**本地事项为默认、云端事项按事项授权且排在 G3**，团队协作用端到端加密的事项共享，云端只承担供给、治理与常在线。再加一项默认值修正：**送出律所侧的内容默认把证件、账户、联系方式与自然人姓名替换为事项内稳定的代号**（v7 只遮蔽证件类标识符，自然人姓名明文出站）。第 02 篇给出完整规则。

## 3. 两条方案线：为什么摆了五轮

| 稿 | 归属 | 日期 | 执行在哪 | 数据在哪 | 摆动原因 |
|---|---|---|---|---|---|
| A | astra | 09-22 | 云端托管 SaaS，Kimi Code 作云端隔离内核 | 中软云 | 以“标准 SaaS 最好运维”为唯一出发点 |
| C | opus | 09-23 | 本机为主；IM、批量、定时走云端执行器 | 混合 | 首次提出本机执行，云端执行器仍处理客户材料 |
| D | opus | 09-28 | 本机管材料与文书，云端管规则与模型 | 混合 | 引入网关服务端组装方法资产 |
| E | astra | 09-30 | 首发云端统一编排；本机受控导入与 Office 桥 | 中软云 | 以“少做双端同步、端侧沙箱、密钥”为理由回到云端 |
| v4 | opus | 10-01 | 单一云端执行内核 | 中软云 | 追随 E 的工程简化，被用户否决 |
| v5 | opus | 10-01 | 律所侧单一内核，云端只供 token | 律所 | 按用户意见只问“谁持有明文” |
| v6 | opus | 10-02 | 控制在云、内容在所、推理过境 | 律所 | 补上“控制在哪”，但删工具、重密钥仪式 |
| v7 | opus | 10-09 | 端上全能力、云上补能力 | 律所 | 补上“能力从哪来”“边界靠什么守” |
| v8 | astra | 10-09 | C/L 按事项选择；C 云端执行 | 按事项 | 把“采购”与“执行位置”分开 |

**摆动的根因**有两个。第一，每一稿只换了一个维度：A/E/v4 只看运维成本，v5 只看明文持有，v6 加上控制位置，v7 加上能力来源与边界机制，v8 加上事项选择——没有一稿把七个维度同时摆上桌。第二，四个不同的概念被反复混用：**采购**（我们向月之暗面买什么）、**托管**（谁持久保存客户内容）、**执行**（Agent 循环与代码在哪跑）、**控制**（谁决定权限、计量与策略）。“云端只供 token”是采购事实；“案卷在所”是托管策略；“本地 Agent”是执行位置；“控制归云”是控制位置。四者互相独立，必须分别回答（第 02 篇 §3.1）。

## 5. v7 深度评审

### 5.1 做对的（v9 全部保留）

| # | 内容 | 为什么对 |

### 5.2 有问题的（按影响排序）

| ID | 位置与主张 | 问题 | 证据 / 推理 | v9 处置 |
|---|---|---|---|---|

### 5.3 功能效果与工程可行性小结

功能上，v7 是七稿中律师体验最完整的一稿：沙箱内自动执行、联网研究、子 Agent、手机遥控、移动签发、零服务器开通。问题在于**它的体验建立在三件尚未证明可行的工程之上**——Windows 五档沙箱、kap-server 管理面的逐条封堵、化名双向还原。三件中任何一件不成立，律师看到的就会是“手动模式”“该段不化名须确认”“该设备不能运行代码”。v9 用 W 执行域（运行时隔离、强度如实标注）、kap-server 无端口私有嵌入（界面只见业务 API）与令牌化工作区 + 结构化补丁替换这三件，体验目标基本不变，可行性提升；代价是 pandas 等数据分析库只在 MXC 等系统强制执行域内可用，且 W 仍待 G0 探针 P2 实测。

### 6.3 功能效果与工程可行性小结

v8 的 C 模式在功能上覆盖了 v7 缺的“关机续跑、手机看内容、零客户端依赖的协作”，L 模式则基本等同于 v5 的单人本机版。**工程上 v8 并不更省**：它要同时建设多租户内容库、云端执行沙箱、服务端密钥与托管运维（C），以及本机沙箱与文件 broker（L），875 人周还不含 L 的同步与移动端。把 C 放到首发，意味着首发就要承担等保三级的内容系统、客户案卷托管责任与云端算力成本。

## 7. 分歧点逐项裁决

| 议题 | v7 | v8 | **v9 裁决** | 理由 |

## 8. 两稿都没解决好的事（v9 新增）

1. **律师要的是“数据处理”，不是“Unix shell”。** 律师让 Agent 写代码的场景几乎都是表格、流水、金额、日期、文本批处理与 Word/Excel 生成。模拟 bash + 零 JS 桥 WASM Python（标准库 + openpyxl、XlsxWriter、pypdf 等纯 Python 包）加我方可信命令（文书引擎、计算器）足以覆盖大部分；pandas 等数据分析库在 MXC 等系统强制执行域内提供。把执行环境从“真实 shell”换成 W 执行域，在所有设备上得到一个无网、只见本事项的运行时隔离环境，并免去 Windows Git Bash 依赖——但它不是操作系统沙箱，对外必须如实区分。
2. **原件从不只存在于我们的系统里。** 本地事项的原件就在律师自己的文件夹（导入或挂载），产品持有的是加密副本与工作成果。这意味着端到端加密的“密钥丢了案卷就丢了”风险被限定在工作成果范围内——这一事实让端到端加密在小所落地的运营风险远低于 v6/v7 的估计，应写进恢复设计与对外说明。
3. **Agent 成本的尾部。** AgentSwarm 上限 128、默认并发无上限爬坡；子 Agent 默认继承主模型（K3）。席位订阅下必须把并发、模型池（子 Agent 默认用 K2.6/K2.7 级）、单任务预算与月额度一起设计，否则重度用户会让单席贡献为负（v8 压力测算已显示 150 任务/月时贡献 −4,261 元）。
4. **“无事项问答”是移动端与云端的天然交汇点。** 律师在手机上最常做的是快速法律问答，不需要事项材料；它可以完全在云端（网关 + 检索 + 法源）完成，不涉及案卷托管。两稿都没有把这一高频场景单列。
5. **先把现有缺陷修掉再谈放开。** 现有 `platform/` 的超时终态、路径判定、前缀自动批准三处缺陷必须在开放任何新工具前修复（第 04 篇 §9）。
6. **市场证据支持本地默认，但“本地 Agent”已不是独家卖点**（`调研-X3`）。头部律所公开可见的部署以所内私有化为主（大成昆明分所为“本地模型 + 公网模型按场景路由”），未见任何头部所公开把案卷托管到第三方云由 AI 处理；深圳律协 2026 指引第二十五条（三）对客户敏感信息“优先考虑本地化部署或专有云部署”。同时 iCourt AlphaClaw 已以“本地处理、案卷不上传、脱敏后上云”为卖点，智合个人版 698 元/年。两稿都没有据此调整差异化与定价——v9 把差异落在可验证的执行域与闸门、Kimi Code 完整能力、原生修订与签发、端到端加密团队协作与机构治理上，并在第 05 篇如实列出价格风险。
