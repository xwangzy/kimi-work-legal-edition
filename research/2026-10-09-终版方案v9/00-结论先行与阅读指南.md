## 一句话

**云端供给与治理，端上执行与持有；云端执行按事项授权；一套权限语义，在每一处独立强制。**

律师电脑上运行完整的 Kimi Code 本地 Agent（kap-server 以无端口方式作为私有组件嵌入，界面只见我方业务 API）：读写材料、数据处理与计算、子 Agent 并行、目标与计划、技能、联网检索全部可用；Agent 写的代码默认在**无网络的 W 执行域**里运行（模拟 bash + 零 JS 桥的 WASM Python，所有 Windows 都可用、无需管理员；隔离性质如实标为“运行时隔离”），支持的 Win11 设备上另有操作系统强制的 MXC 进程容器承载 pandas 等数据分析；一切出网经出站闸门并记入数据去向卡；送出律所侧的内容默认把证件、账户、联系方式与**自然人姓名**替换为事项内稳定的代号。我们从月之暗面只买 API token，所以 Kimi Work 靠 Kimi 会员云提供的账号与额度、检索与抓取、法源数据、设备中继、分发与更新、管理与审计，由中软云端补位——这些都不需要持有客户案卷。案卷默认在律所侧，团队以端到端加密方式共享；云端事项（中软境内托管、云端执行、关机续跑）作为 G3 的可选模式，按事项授权。

## 先回答用户反复提出的问题：只买 API token，云端该做什么

“云端只供 token”**作为采购事实是对的，作为架构结论只对了一半**。Kimi Work 自己就是“本地 Agent + Kimi 会员云”，会员云里有账号与统一额度池、托管检索与抓取、数据源插件、远程控制中继、插件与更新、云端定时与云主机。只买 token，这些一样都不附带。中软要卖“账号席位订阅”，云端就必须承担四类能力：**token 供给（网关）+ 补位服务（检索、法源、中继、分发）+ 订阅与治理（账号、额度、策略、审计、控制台）+ 常在线（提醒、通知、IM 后端、公开监测）**——它们都可以做到不持久化客户案卷。唯一需要碰案卷的第五类“云端执行客户内容”，按事项授权、放在 G3。

| 能力 | 在哪里 | 碰不碰案卷 |
|---|---|---|
| 账号、席位、点数、策略、审计、控制台、分发 | 中软云控制面 | 不碰 |
| 模型推理、检索、法源、无事项法律问答 | 中软云能力网关 → 月之暗面 / 数据商 | 过境不落盘（证件、账户、联系方式与自然人姓名已令牌化；检索不带事项编号） |
| 团队共享、手机 ⇄ 电脑、IM 离线收件暂存 | 中软云中继 | 只见密文（IM 文件在后端内存取得后立即加密） |
| 期限提醒、通知、IM 后端、公开监测 | 中软云 | 只见元数据（提醒内容加密，云端只知触发时间与推送目标） |
| 材料、解析、OCR、Agent 循环、代码执行、文书、签发、内容审计 | **律师电脑**（本地事项，默认） | 明文只在律所侧 |
| 关机续跑、手机看内容、托管协作 | 中软云端执行面（**云端事项，G3，按事项授权**） | 授权快照明文（醒目标识） |

## 评审结论

- **v7（opus）把维度找对了**：能力来源与云端补位、用隔离代替删工具、远程渠道降权、控制归云、数据去向卡。**但**把“案卷在所”当公理；kap-server 选型对、却让界面与遥控直达其约 120 个路由；Windows 五档原生沙箱在律师电脑上覆盖不了（无管理员时 MXC 只覆盖约 30%–45% 机器、Win10 不支持）；化名还原做进 Shell 参数；共享签名私钥；范围五轮递增而日期不变。
- **v8（astra）把框架摆正了**：采购不决定执行位置；按事项选择 C/L/P；能力账本定义“完整接入”；Run/Attempt/租约/幂等/审批绑定版本；如实的撤权与删除；每设备签名；不在代码里替换字符串；查出了现有代码的真实缺陷（主审已复核属实）。**但**把云端托管（C）作为团队的推荐路径，等于让云端托管成为事实默认；L 模式在首发没有团队协作与移动方案；Windows 代码执行只给出“达不到就关”；缺投资与现金视图，决策力度不足。
- **两条方案线摆动五轮的根因**：每稿只换一个维度，且把**采购、托管、执行、控制**四个独立概念混为一谈（第 01 篇 §3）。

## 对抗式审阅改了什么（v9.0 → v9.1）

独立审阅 30 条（4 阻断、19 重要、7 一般），全部处置（详见 `审阅-对抗式-2026-10-10.md` 末节），关键五处：
1. **Pyodide 会拆掉隔离**：它内置 Python⇄JS 互操作，guest 能执行宿主 JS → 默认 Python 改用 just-bash 自带的“零 JS 桥”CPython；pandas 等只在 MXC 系统强制执行域内运行。
2. **隔离强度不夸大**：W 执行域对外标为“运行时隔离（非操作系统沙箱）”，设备页三档如实显示。
3. **自然人姓名是直接标识符**：默认令牌化范围加入自然人姓名，机构名称保留；令牌只在界面与文书引擎导出时还原。
4. **“中软看得到什么”三处更正**：检索调用不再携带事项编号；IM 后端持有平台下载凭据（离线时只加密暂存）；期限提醒内容加密。
5. **持久化注入与端口暴露**：工作区 `AGENTS.md` 等不加载（ZP-18）、直接子进程封闭（ZP-17）、kap-server 不监听端口。
数字随之更新：人周 926 → 981 基线；主口径改为不含加量收入；桌面支持成本恢复 v7 水平；编制按到岗爬坡；登记前移到 G1。
