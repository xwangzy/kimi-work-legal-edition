# 02 云地划分与权限体系（v9 核心篇）

版本 9.1 · 2026-10-10（含对抗式审阅处置） · 本篇是 v9 的“宪法”：每项能力从哪里来、在哪里执行、碰到什么数据、谁能打开、从哪个渠道能触发、断网或关机时怎么办，都以本篇为准。证据：本轮 `调研-X1`（主流办公 Agent 云地划分，10-09 状态）、`调研-X2`（Windows 沙箱、Kimi Code 上游、开放平台、境内云沙箱）、`调研-X3`（律所云端接受度与法律 AI 部署形态），以及 v7 `调研-S0～S3`、v8 `调研-A～C`；对抗式审阅见 `审阅-对抗式-2026-10-10.md`（处置见其末节）。

## 1. 一句话

**云端供给与治理，端上执行与持有；云端执行按事项授权；一套权限语义，在每一处独立强制。**

- **云端供给与治理**：我们从月之暗面只买 API token。一个按席位订阅的桌面 Agent 产品，除了 token，还离不开账号与订阅、额度与计量、检索与抓取、法源数据、提醒与通知、设备中继、分发与更新、管理与审计——这些是 Kimi Work 由 Kimi 会员云提供、而只买 token 拿不到的部分，由中软云端补位。它们都**不需要持有客户案卷**。
- **端上执行与持有**：律师的材料在律师电脑上，Agent（Kimi Code 引擎）就在律师电脑上执行；Agent 写的代码只在执行域里跑——默认 **W 执行域**（模拟 bash + 零 JS 桥的 WASM Python，运行时隔离、无网络，所有 Windows 可用、无需管理员），支持的 Win11 设备上另有系统强制的 **N 执行域**（MXC 进程容器）；一切出网经出站闸门；送出律所侧的内容默认把证件、账户、联系方式与**自然人姓名**替换为事项内稳定的代号。
- **云端执行按事项授权**：云端执行面是独立、显式、可选的；处理客户内容的云端执行（“云端事项”）只在律所策略允许且事项负责人选择时启用，G3 上线；不含客户内容的云端任务（无事项法律问答、公开法规监测）在此之前即可用。
- **一套权限语义**：桌面、手机、IM、定时、律所执行器、云端执行器用同一套“谁、对哪个事项、做什么、数据去哪、花多少”的判定；每个执行位置自己强制，不相信别处送来的“已批准”。

## 2. 先回答：只买 API token，云端到底该做什么

### 2.1 “云端只供 token”对在哪里、错在哪里

用户 10-01 的判断“云端实际提供的只是 Kimi 的 token API 服务，其他都应在本地执行”，**作为采购事实是对的，作为架构结论只对了一半**：

- **对的一半**：客户案卷的分析、规则应用、核验、审批、审计，都可以而且应当在律所侧完成；中软不需要、也不应当默认持有案卷明文。v9 坚持这一点（本地事项为默认）。
- **漏掉的一半**：我们对标的 Kimi Work 自己就不是“本地 + token”两样东西。它的会员订阅背后有一整套云服务（下表）。只买 token，这些服务一样都不会随 token 附带；中软要卖“账号席位订阅”，就必须自己提供它们。这些服务都是**不碰案卷**的云端能力。

### 2.2 Kimi Work 靠 Kimi 云提供、只买 token 拿不到的能力（补位清单）

| # | Kimi Work / Kimi Code 依赖的 Kimi 云服务 | 支撑什么 | 只买 token 能否获得 | v9 补位方式 | 补位服务是否接触案卷 |
|---|---|---|---|---|---|
| 1 | 开放平台模型 `api.moonshot.cn/v1` | 推理 | **能** | 律师电脑 → 出站闸门 → 中软法律模型网关 → 月之暗面（企业账户；中软 MaaS 只做用量结算，见第 04 篇 §5.2） | 过境（不落盘），按事项策略最小化与令牌化 |
| 2 | Kimi 会员账号 OAuth、统一额度池、加油包、频控 | 登录、订阅、额度 | 否 | 中软 IAM + 席位许可 + 点数账本 + 网关权威计量 | 否（账号与用量元数据） |
| 3 | Kimi Code 托管检索 `api.kimi.com/coding/v1/search` | WebSearch 工具（无配置时工具不注册） | 否 | **中软检索服务**，上游月之暗面 `/v1/tools/search_pro`（¥0.015/次，`sites` ≤5、`time_window`）与 `/v1/tools/search`（¥0.01/次） | 过境去标识查询 |

| 7 | 插件市场与更新 `code.kimi.com`、内容 CDN | 插件、技能、客户端更新 | 否 | 中软签名分发 + 律所批准目录 | 否 |

## 3. 第一性原理

### 3.1 七个维度，必须分别回答

一个动作至少涉及：谁（人与组织）、哪个事项、什么对象（及版本）、为什么（目的与依据）、用什么工具、在哪里执行、数据去哪、何时、花多少。“云端还是本地”这一个问题无法同时回答这些。v9 把位置问题拆成七个维度（吸收 v8 的七轴）：

| 维度 | 选项 | 不要混淆 |
|---|---|---|
| ① 案卷持久存储 | 律师电脑 / 律所自有存储 / 中软境内事项库 | 静态加密 ≠ 服务商看不到 |
| ② Agent 编排（引擎循环） | 律师电脑 / 律所执行器 / 中软云端执行器 | 编排会接触上下文，不是纯元数据服务 |
| ③ 工具与代码执行 | W 执行域（运行时隔离）/ N 执行域（系统强制）/ 云端沙箱 / 受管连接器 | 本机工具也可能联网；云端工具也不能默认访问电脑 |
| ④ 模型推理 | 月之暗面（经中软网关）/ 律所自有端点 / 禁用 | 本地 Agent 调用 API 仍然把输入送出设备 |
| ⑤ 控制与运营 | 中软云（身份、席位、策略、计量、调度、分发） | 在云不等于保存正文，但仍处理身份与敏感元数据 |
| ⑥ 人的权限 | 经办、复核、签发、管理、支持 | 买席位、管设备不等于能看案卷 |
| ⑦ 触发渠道与副作用 | 桌面 / Office / 手机 / IM / 定时 / 云端；只读、写草稿、正式发布 | 手机遥控不是云端执行；任务完成不等于正式发出 |

四个常被混用的概念必须分开：**采购**（向谁买什么）、**托管**（谁持久保存客户内容）、**执行**（引擎与代码在哪跑）、**控制**（谁决定权限、计量与策略）。“只买 token”是采购；“案卷在所”是托管；“本地 Agent”是执行；“控制归云”是控制。

### 3.2 决定每项能力位置的五问

1. **能力从哪来？** 只在月之暗面云（模型、工具 REST）→ 经中软网关；需要跨律所提供、要合同或凭据（检索、法源、方法包、账号）→ 中软云；开源可运行（Kimi Code 全部本机能力）→ 跟着数据走。
2. **数据在哪、可以在哪？** 案卷在哪里持久保存由事项数据模式决定；默认在律所侧。执行跟着数据走，不把数据搬去迁就执行。
3. **要不要常在线？** 关机也必须发生（提醒、通知、收件回执、公开监测、账号计费）→ 云端；内容任务在关机时只能由“已获授权的常在线执行面”承接，否则如实排队。
4. **要不要防篡改？** 许可、额度、计量、策略发布、运营审计 → 云端权威；策略在端侧与网关执行。
5. **隔离强度与成本？** 不可信代码要在执行域里跑：本机用 W 执行域（运行时隔离，普适）或 N 执行域（操作系统强制，支持的设备）；云端用每任务隔离沙箱。没有执行域，就不运行不可信代码；W 保证每台设备都有一个运行时隔离的执行域，并如实标注其强度。

### 3.3 六条划分规则

| # | 规则 | 由哪一问推出 | 典型能力 |
|---|---|---|---|
| **R1 能力补位** | 只买 token 拿不到、但订阅产品必需的能力，由中软云端按 Kimi Code 已有协议补位，引擎不改；Kimi Code 能在本机运行的能力一律保留，不靠删工具保安全 | 问 1 | 检索、抓取、法源、中继、账号、分发 |
| **R2 执行随事项** | 客户内容的持久存储与 Agent 处理，位置由事项数据模式决定：**本地事项（默认）**在律所侧；**云端事项（G3，授权）**在中软境内事项库；一个事项只有一个权威提交位置 | 问 2 | 材料、成果、会话转录、内容审计 |
| **R3 控制归云** | 不碰案卷、但要常在线或要防篡改的能力放中软控制面；策略在端侧与网关执行 | 问 3、4 | 身份、席位、策略、计量、通知、提醒、分发、运营审计 |
| **R4 隔离放权** | Agent 能力的边界由执行域（文件、进程、网络）与数据级别决定；执行域内动作按运行模式自动执行，确认只用于跨边界动作；没有“完全访问” | 问 5 | 文件工具、Bash/Python、子 Agent、联网 |
| **R5 远程降权、人做不可逆** | 经手机、IM、定时、执行器、云端发起的任务，权限不高于发起人在本机界面的权限，默认只产草稿；对外发送与提交、签发、删改原件、改权限与策略，永远是人在已登记设备上完成的业务操作 | — | 渠道权限表（§9.6） |
| **R6 断云可用、可退出** | 中软云不可达时，本机已有能力照常（离线许可期内）；停服或欠费时，阅读、检索、导出、签名验证永久可用；本地事项的原件始终在律师自己的文件夹里 | 问 3 | 降级模式（§10） |

### 3.4 要防什么、防谁、靠什么防

| 威胁 | 主防线 | 性质 |
|---|---|---|
| 被注入的 Agent 越界读写、外传 | 执行域（无网、只挂载本事项）+ 宿主策略（每次工具调用裁决）+ 出站闸门（唯一出口）+ 跨边界确认 | 技术 |
| 被注入的 Agent 破坏原件 | 原件区只读；工作区文件历史与快照可回滚；交付区只能由人发布 | 技术 |
| 被注入的 Agent 在工作区写入指令文件（AGENTS.md、技能目录）形成持久化注入 | 工作区与案卷目录中的指令、技能、Agent 与 MCP 配置一律不加载，只加载签名方法包与只读可信配置区（第 04 篇 ZP-18） | 技术 |
| 外部攻击者攻破中软云（被动窃取） | 本地事项不在云端持久化明文；共享与中继只存密文 | 密码学 |
| 攻击者控制中软控制面（主动篡改策略、公钥、连接器） | 管理员公钥入组固定；放宽类策略与连接器登记须律所管理员设备签名；策略版本单调 | 律所侧校验锚 |
| 中软运维人员越权 | 同上 + 双人运维、最小权限、访问审计；云端事项另有 JIT 紧急访问与客户通知 | 密码学 + 内控 |
| 中软推送被篡改的客户端 | 代码签名、版本哈希公开、第三方审计、律所版延迟更新；**如实说明密码学挡不住发布客户端的一方** | 内控与合同 |
| 月之暗面与数据商 | 企业协议（排除“模型服务优化”、ZDR 覆盖逐接口列明）、证件/账户/联系方式与自然人姓名默认令牌化、以中软组织身份调用 | 合同 + 最小化 |
| 律所内部越权（伦理墙、管理员） | 本地事项：事项密钥只包裹给成员设备；云端事项：服务端 ACL + 事项级加密上下文；管理员默认无内容 | 密码学 / 访问控制 |
| 设备丢失 | 设备密钥受 TPM/钥匙串保护；本地存储加密；吊销与密钥轮换；**已解密到本机的明文无法远程收回**（如实） | 技术 |
| 密钥丢失 | 个人恢复码、律所恢复、每周增量导出；**原件仍在律师文件夹**，风险限于产品内工作成果 | 运营 |

**六条共性**（对 v9 的直接含义）：

1. **控制面、账号与计费一律在厂商云**；没有任何一家把订阅与额度放在端上。→ R3。
2. **执行面普遍“本机与云端并存”，国内是“两个产品”，海外是“一个会话两种落点”**：Kimi Work 桌面 vs Kimi Agent/Claw（项目数据不互通）、千问桌面 vs 网页（会话与定时不同步）、WorkBuddy 桌面 vs WMA；Claude 云会话经桌面中转触达已连接文件夹、ChatGPT Work 云端协调由在线电脑执行本机步骤。海外两家正在把云端变成默认（Cowork 10-06、dots 灰度），国内三家截至 10-09 仍以桌面本地 Agent 为主力形态。→ R2：本地事项默认、云端事项显式；且我们用同一事项模型承载两种落点，避免“两个产品、数据不互通”。
3. **桌面本地 Agent 的定时任务都是“关机不跑、不补跑”**，要关机也跑必须去云端；**没有任何一家在设备离线时把本机材料自动搬上云**，云端续跑只针对已在云上的材料或公开信息（ChatGPT Work 离线降级到云容器时明说“够不着本机文件、也不执行本地企业策略”）。→ 期限提醒放云；内容型定时如实提示；禁止静默迁云。
4. **远程/手机/IM 一律是“遥控在线的电脑”，并被收窄**（WorkBuddy 专属文件夹、Codex 沿用主机审批、Cowork 只到已连接文件夹）。→ R5 与收件区。
5. **订阅 = 席位 + 按 token 计量的额度池 + 超额按量**（Kimi 统一额度池、WorkBuddy Credits、千问积分、Claude 席位 + 用量、ChatGPT credits）。→ 第 05 篇的点数设计。
6. **没有一家公开了足以支撑“律所案卷”的本机隔离与数据承诺**：Kimi Work 未披露隔离；WorkBuddy 的“端到端加密”是本地到云端的传输加密；千问“数据不离开设备”只指执行环境；Cowork 本机文件内容在服务器处理。→ 这正是法律发行版的差异化空间：可验证的执行域、出站闸门、数据去向卡。

## 6. 事项数据模式

### 6.1 两种模式与一种部署

| 属性 | **本地事项**（默认） | **云端事项**（G3，授权开启） | 私有部署（另行交付） |
|---|---|---|---|
| 适用 | 绝大多数律所与事项；当事人限制上云；律协口径保守的地区 | 律所明确选择托管协作、需要关机续跑与手机看内容的团队或事项 | 强制内网、私有模型的机构 |
| 权威存储 | 成员设备（事项账本，签名事件）；中继只存密文 | 中软境内事项库（不可变版本 + 服务端加密，按租户/事项隔离加密上下文；可选客户管理密钥） | 客户环境 |
| 团队协作 | 端到端加密事项共享：事项密钥包裹给成员设备；团队版与律所版默认开启“律所档案成员” | 服务端 ACL；成员经桌面或受管 Web 访问；敏感事项可选专属实例（专有云） | 客户内网 |
| 谁能解密存储 | 成员设备与律所恢复主体 | 中软授权服务进程（**不能称服务商不可见**）；运维 JIT 访问须双人审批、限时并通知客户 | 依部署 |
| Agent 执行 | 本人电脑（或获授权的律所执行器） | 本人电脑或云端执行面 | 客户执行器 |
| 推理 | 经网关到月之暗面（按事项策略最小化）或禁用 | 同左 | 私有模型或明确允许的 API |
| 关机时内容任务 | 排队（有执行器时由执行器承接） | 云端继续 | 依客户执行器 |
| 手机看内容 | 只读“预览件”（桌面在申请签发或分享时生成的 PDF/HTML，带修订标注、与交付件 hash 绑定，随密文同步）；App 不渲染 DOCX 原生修订 | 受管 Web/App 完整预览 | 依部署 |
| Agent 会话跨设备续接 | 任务暂停或结束时把会话快照（转录、待办、计划、文件历史指针）写入事项账本并同步；另一台设备导入后续接；进行中的工具调用与执行域状态不迁移 | 云端会话直接续接 | 依部署 |
| 默认外发等级 | 证件、账户、联系方式与自然人姓名令牌化；机构名称保留（L3a 全部化名） | 同左 | 同左 |

**单个事项只有一个权威提交位置**：本地事项以成员设备上的签名事项账本为准（中继只是密文邮差）；云端事项以服务端版本登记为准（设备上是缓存与工作副本）。

### 6.2 模式切换（迁移）

- **本地 → 云端**：事项负责人发起；显示目标区域、对象清单、第三方、保留期、委托与个人信息依据；暂停新写入 → 上传并校验 → 切换权威位置 → 恢复任务；记迁移记录与新策略版本。当事人限制（L3b）事项不可迁移。
- **云端 → 本地**：导出并校验 → 成员设备接管 → 关闭云端新任务 → 按合同删除云端副本与备份（状态逐项可见：在线副本已删 / 备份待到期 / 法律保全）；不因切换就声称历史云副本不存在。
- 不存在“静默迁移”：设备离线、磁盘不足、执行域不可用，都不会自动把事项搬到云端。

### 8.3 默认最小化：令牌化工作区（证件、账户、联系方式与自然人姓名）

| 处理 | 默认 | 做法 |
|---|---|---|
| **标识符与自然人姓名令牌化** | 所有出站（推理、检索、法源）与 Agent 工作区 | 身份证/护照号、手机号、银行卡与账号、统一社会信用代码、详细住址、车牌等**证件、账户与联系方式类标识符**，以及**自然人姓名**，替换为事项内稳定的代号（`〔自然人甲〕`、`〔账号#3〕`）；**机构名称默认保留**（商事事项的主体关系推理不受影响）。自然人姓名的识别靠当事人词典 + 实体识别，**漏识别的姓名仍会出站**，L3a 事项须人工核对词典 |
| **全部化名** | L3a 强制；L2 可由律所或事项负责人开启 | 机构名称也替换为代号 |
| **图像** | 默认本机 OCR 后送文本 | 把图片原样送多模态模型（`ReadMediaFile`）是跨边界动作：L2 确认、L3 禁止；ZDR 例外点名“直接上传的图像或视频” |
| **检索查询** | 令牌化 + 当事人词典匹配 | 命中实体时给出泛化改写（“某有限责任公司”）或请律师确认；L2 可在任务开始时一次性批准“本任务泛化后放行”；L3 逐条确认；L3b 禁止；查询原文只记在本机事项账本 |
| **URL** | 闸门检查 | 只 http(s) GET；搜索引擎与回显查询参数的站点不经抓取访问；URL 中的实体、标识符与可疑长编码串拦截 |

**为什么默认令牌化自然人姓名、保留机构名称**：按《个人信息去标识化指南》（GB/T 37964-2019）的术语，自然人姓名本身就是直接标识符；PIPL 第六条要求最小必要。以自然人为当事人的劳动、婚姻家事、人身损害类事项在 L2 中大量存在，不能把姓名明文送给第三方模型再对外说“已遮蔽身份信息”。机构名称不是个人信息，商事推理依赖主体关系，默认保留。令牌化降低风险，但不构成匿名化；合规依据仍是四项依据记录、企业协议约束与敏感级别的强化处理。

### 8.4 令牌化工作区与结构化补丁（替代 v7 的“工具参数双向还原”）

一条统一规则：**令牌只在两个地方还原——界面渲染层与可信文书引擎的导出；Agent、工作区、代码与模型上下文一律只见令牌。**

- **工作区即令牌化视图**：执行域挂载的材料快照、Read 返回的文本、工作区草稿与表格都是令牌形态；代码在令牌数据上运行，天然一致（例如按 `〔账号#3〕` 汇总流水）；会话转录与思考内容以令牌形态保存与回传。
- **令牌确定性**：令牌按事项确定性分配（HMAC(事项密钥, 规范化值) 的短编号），跨轮、跨子 Agent、跨会话稳定，保证 `reasoning_content` 原样回传与前缀缓存命中。
- **不在代码与命令里替换文字**：Bash、Python 源码与命令行参数原样执行；模型响应流（含工具调用参数）**不做还原**直接交给引擎。
- **还原只在可信环节**：界面显示时按令牌映射还原给律师看；生成交付件时由文书引擎按字段类型（当事人、日期、金额、条款引用）还原并校验转义与版本。
- **修改原文档走结构化补丁**：`{document_version, anchor, expected_text_hash, proposed_text}`，内核核对版本与锚点后在原件上生成原生修订；补丁中的令牌由文书引擎还原；冲突返回预览，不做模糊替换。
- **需要真实值的任务**（例如核对证件号校验位、按真实户名匹配银行流水）：确认卡说明哪个字段将以真实值进入工作区与模型，律师逐项批准；L3 事项禁止。

## 9. 权限体系

### 9.1 有效权限与不变式

有效权限是下列集合的交集，任何显式拒绝优先：

`产品基线 ∩ 律所策略 ∩ 人的角色与事项成员资格 ∩ 对象 ACL ∩ 数据源许可 ∩ 事项数据策略 ∩ 执行域能力 ∩ 渠道上限 ∩ 运行模式 ∩ 本次授权 ∩ 预算与时限`

三条不变式：
1. **Agent ≤ 委托人**：Agent 能读写的数据、能用的能力不超过发起人在该事项的权限。
2. **远程 ≤ 本机**：远程、定时、执行器、云端发起的任务，不超过发起人在本机界面的权限，并按 §9.6 再降一档。
3. **组件 ≤ 职责**：每个云端组件只拿完成职责所需的最少数据；控制面、网关、检索、法源、中继不持久化客户内容（云端事项的事项库除外，且受独立 ACL 与加密上下文约束）。

许可校验与法律依据检查是两个条件：有 API 权限不代表有权把这份材料发出去；管理员批准的连接器也不能突破当事人的禁止条款。

### 9.2 强制点（每一处独立强制，不相信别处的“已批准”）

| 模式 | 对标 Kimi Work | 执行域内动作（读写工作区、运行代码、子 Agent） | 跨边界动作（§9.5） | 预算 |

- 档位受上层约束：律所策略禁止的档位不出现在选择器；远程与定时任务的档位上限见 §9.6。

### 9.5 跨边界动作（“默认”模式下需要确认）

①检索查询命中当事人实体或超阈值（未预授权泛化时）；②抓取新域名，或在浏览器里提交表单；③连接器写入或按次计费调用；④跨事项读取（T7）；⑤创建定时任务（T8）；⑥超出任务预算；⑦图像原样送模型；⑧把数据交给“可接收级别”低于该数据的去向；⑨把本地事项迁移为云端事项；⑩扩大材料范围（新增挂载目录、导入新文件进入正在运行的任务）。

确认卡写明：要做什么、为什么、数据会去哪里、预计费用；按钮“本次允许 / 本任务内允许 / 改写后允许（检索）/ 拒绝”。批准绑定主体、事项、动作、参数 hash、对象版本、目的地、期限与 nonce；执行前重验，范围变化即重新批准。

### 9.7 子 Agent、集群、目标与定时

- 子 Agent 继承父任务的事项、执行域、运行模式与预算份额，权限只能更窄；子 Agent 的工具调用同样经宿主策略；审批汇入同一队列。
- **并发与成本**：Kimi Code AgentSwarm 最多 128 个子 Agent，默认“立即启动 5 个、此后每 700 毫秒加 1 个且不设上限”。v9 在端侧锁定：活动执行单元默认 2（16 GB 以上设备可到 3），Swarm 并发上限 3（`KIMI_CODE_AGENT_SWARM_MAX_CONCURRENCY`），其余排队；子 Agent 默认走低价模型池（`[secondary_model]`），仅高价值步骤用 K3；任务预算预占、父子共享上限，超额暂停并说明已完成与未完成部分。云端执行面（G3）按租户预算放宽。
- 目标模式必须设预算与时限；超时或超预算暂停并通知。
- 定时任务按 §9.6“定时”渠道运行；期限提醒不用 Agent 定时（云端调度）。

### 9.10 执行域：Agent 的硬边界

v9 的工程决策：**Agent 写的代码默认不在本机原生执行**；隔离强度分层、如实标注。

| 执行域 | 实现 | 隔离性质（如实） | 前提 | 适用 |
|---|---|---|---|---|
| **W-core（默认）** | Kimi Code 的 Bash 经 `IHostProcessService` 种子进入**模拟 bash**（Vercel `just-bash`，TypeScript 实现，Apache-2.0）；Python 用 just-bash 自带的 **CPython-Emscripten**（“零 JS 桥”：guest Python 不能调用宿主 JS，文件访问经桥接回 just-bash 虚拟文件系统）+ 随包的纯 Python 包（openpyxl、et_xmlfile、XlsxWriter、pypdf、python-dateutil、jieba 等）；sqlite3、jq、xan（CSV）、yq 内置；我方可信命令（`kwl-docx` 文书读写与修订草稿、法规查询、金额与期限计算器）挂入 | **运行时隔离**：guest 不执行本机代码，只能访问注入的虚拟文件系统（不允许符号链接与硬链接）；W 进程独立运行，Node 权限模型不授予网络、子进程与原生插件（运行时强制，非操作系统强制，Node 官方定位为“安全带”）；作业对象与看门狗限制资源 | 无（任何 Windows 10/11、macOS） | 全部事项级别（L4 不入库）；全部 Work 模式 |
| **W-data（数据分析增强）** | Pyodide（pandas、numpy、matplotlib、scipy 等） | **进程级隔离**：Pyodide 内置 Python⇄JS 互操作，guest 可调用宿主 JS，边界退化为 W 进程本身（Node 权限模型 + 作业对象），弱于 W-core | 同上 | 默认只在 N 域内运行；无 N 域的设备由律所策略决定是否对 L0–L2 开放（默认关闭）；L3 不可用 |
| **N · 系统强制（可选增强）** | Windows：微软 **MXC 进程容器**（`@microsoft/mxc-sdk` 1.0，MIT；PSEC 层每容器 WFP 出站过滤、拒读路径，无需管理员）；或 IT 预配的低权限沙箱用户 + 防火墙（参照 Codex `elevated`）；macOS：Seatbelt（2027） | **操作系统强制**的文件与网络隔离 | MXC：Win11 24H2/25H2 且装 2026-08 及以后累积更新、PSEC 可用（逐机探测）；预配式：一次管理员授权 | 运行 W-data 与需要原生二进制的少数任务；律所策略可要求 L3a 事项的代码只在 N 或 W-core 中运行 |
| **C · 云端执行域（G3）** | 每任务隔离沙箱（microVM 或 gVisor 级容器），同一引擎与法律内核 | 云端隔离环境 | 云端事项或公开任务 | 云端事项、云端公开任务（含完整 pandas 等原生库） |

**为什么 W-core 可以作为默认**：

1. **律师要的是数据处理，不是 Unix shell**。“按对手方汇总 300 行流水”“按 LPR 算三种情景的违约金”“把 40 份劳动合同要素抽成 Excel”——Python 标准库（csv、decimal、datetime、statistics、collections）加 sqlite3、openpyxl、XlsxWriter 足以完成；DOCX 的读写与修订本来就应由我方文书引擎（可信命令）承担。系统提示会告诉模型“受限 bash，无网络，可用 python3 标准库与列出的包；pandas 只在数据分析增强环境中可用”，减少无效尝试。
2. **边界来自语言运行时，不是来自用户确认**：bash 命令由 TypeScript 解释、Python 在 WASM 中运行且没有 JS 桥，都只能经 just-bash 的虚拟文件系统访问挂载目录。这比“受限令牌 + 人工确认”（v7 的 C 档）强，但弱于 MXC 等操作系统强制的隔离——对外必须如实区分。
3. **一致、无管理员**：不建本地用户、不改防火墙与 ACL、不起原生解释器；不依赖 Kimi Code 在 Windows 上要求的 Git Bash。
4. **覆盖面**：X2 估计 2026Q4 只有约 30%–45% 的律所 Windows 机器满足 MXC 无管理员条件（中国 Win11 约 54%、Win10 约 41%）；W-core 覆盖其余全部。
5. **升级路径**：为“零 JS 桥”CPython 构建 numpy/pandas 等的 Emscripten 轮子（G2 探针），成功后 W-data 可并入 W-core，数据分析不再依赖 N 域。

**设备与事项上的标注**（律师与律所 IT 看到的文案）：“代码运行：**运行时隔离**（无网络、只见本事项；非操作系统沙箱）”/“代码运行：**系统强制**（MXC）”/“**未隔离：不运行代码**，只运行可信工具”。不写“可安全运行代码”这类笼统表述。

**已知限制（如实）**：just-bash 为 Beta，自述“无 VM 隔离、依赖实现健壮性”；Node 权限模型不防恶意代码，且官方文档写明符号链接会被跟随到授权路径之外（W 因此禁止工作区内的链接）；WASM 内存需进程级约束；W-core 的 Python 只有标准库与纯 Python 包。对策：W 进程最小权限、每次 Bash 调用独立 worker、看门狗与作业对象；工作区以快照 + 提交方式写回（第 04 篇 §4.1）；G0 逃逸与资源红队；N 域作为强隔离增强。

**不可降级的规则**：任何设备上都不允许“在执行域之外运行模型生成的代码”；律师的确认不能代替隔离；W 不可用时，代码执行关闭，只运行可信工具。

### 9.11 密钥与恢复（本地事项）

| 项 | v9 设计 | 相对 v7 |
|---|---|---|
| 设备密钥 | **每台设备独立**签名与加密密钥对，私钥在 TPM/DPAPI、钥匙串、Secure Enclave/StrongBox，不出设备 | v7 账户密钥跨设备复制 → 每设备独立，便于吊销与归责 |

| 事项密钥 | 每事项一把（可按纪元轮换），包裹给成员各设备公钥、律所恢复公钥、（授权时）律所执行器 | 包裹对象由账户改为设备 |

| 签发 | 签发人**设备签名密钥**对确切文件 hash 与独立 manifest 签名；证明包可离线验证；可选 RFC 3161 时间戳 | 改为设备签名 |

| AI 使用摘要 | 事项代号、操作人、动作类型、外发字节数、时间、对象 hash | 本地事项：端生成、事项目录密钥加密同步；云端事项：云端 | 主任、风控、利冲；可导出到律所 SIEM |
| 事项内容审计 | 会话转录、工具调用、确认记录、数据去向明细、检索查询原文 | 事项账本（事项密钥加密）/ 云端事项库 | 事项成员 |

对应上海律协“记录输入、生成与修改过程”的要求，并按已公开报道的深圳律协 2026 指引要点（“对于关键使用环节，可适当保留使用记录”，转载本第二十二条（四），取得官方原文后核对条号）设计；内容级记录在律所侧可调阅，且不破坏伦理墙。

### 9.13 撤权、删除与保留（如实语义）

- **撤权**：云端立即拒绝新的读取、工具调用、计费与令牌续期；在线设备收到后终止任务并清理缓存（目标 ≤ 60 秒）；离线设备在重新联网或本地租约到期时收紧。新版本内容换密钥；**已获取的旧数据无法收回**。
- **删除**：对象 → 索引 → 向量 → 运行状态 → 导出临时包 → 设备缓存 → 备份 → 恢复材料逐项记录，状态为“在线副本已删 / 等设备上线 / 备份待到期 / 法律保全 / 已外发不可撤回”；恢复旧备份先重放删除与撤权记录。
- **保留**：律所策略定保留期（运营审计 ≥ 6 个月）；事项可设“保全”冻结删除；结案导出开放格式（事件 JSON Lines + 原始文件 + 签名证明包）。

## 11. 关键流程

### 11.1 首日：零服务器开通

```text
① 主任用企业微信/钉钉/飞书扫码开通 → 选择律所策略模板（推荐模板默认最严）→ 生成律所恢复材料（律所版 2-of-3 恢复卡；团队版 1 张恢复码）
② 成员扫码登录 → 设备生成密钥 → 打印个人恢复码 → 执行域自检（显示“代码运行：运行时隔离（W）”；满足条件的 Win11 另显示“系统强制（MXC）：可用”）
③ 示例事项体验 → 创建第一个真实本地事项前完成一次恢复演练
④ 拖入第一份合同 → 本机解析 → 合同审查工作流（推理经网关，证件/账户/联系方式与自然人姓名令牌化）→ 风险卡 → 追问时进入 Agent：
   执行域内用 Python 核算违约金、联网检索监管口径（查询去标识）→ 在 Word 中打开原生修订稿
```

### 11.2 联网研究

```text
律师：“研究股权转让中未实缴出资股东的补足责任，近三年上海判例”
→ Agent 起草检索式 → 闸门：无标识符与自然人姓名、无当事人实体 → 中软检索服务（search_pro，法律官方站点集，单次 ≤5 个站点按组扇出）
→ 结果作为“不可信外部内容”进入上下文 → FetchURL 抓取全文（白名单域名自动）→ 法源服务核验案例存在性与版本
→ 结论按引用四态写入工作区
若检索式含“甲公司”：默认模式弹出确认，并给出泛化改写“某有限责任公司股东未实缴出资补足责任”
```

### 11.3 合伙人在路上（G2 App）

```text
助理在电脑上申请签发 → 控制面推送唤醒（不含内容）→ 合伙人打开 App（本人设备）
→ 经事项共享取“预览件”密文（桌面在申请签发时生成的 PDF/HTML，带修订标注、与交付件 hash 绑定）→ App 本地解密只读预览 → 点“回到电脑签发”或“退回并附意见”
（G3：App 内生物识别 + 设备签名签发；律所策略可要求法院版、对方版必须桌面签发）
```

### 11.4 晚上关机前的批量任务

```text
本地事项：客户端提示“该任务预计 2 小时，需要电脑保持运行”→ 防休眠三档（熄屏保持运行 / 屏幕常亮 / 关闭）
有律所执行器（G3）：事项负责人授权执行器 → 任务信封排队 → 执行器只出站领取，结果加密写回
云端事项（G3）：任务在云端执行面继续；结果在 App 与桌面可见
```

### 11.5 离职、换电脑、丢电脑

| 时刻 | 产品怎么做 |
|---|---|
| 离职 | 控制台一键回收：吊销设备与席位 → 事项负责人移交 → 后台轮换相关事项密钥 → 档案成员确认归档 |
| 换电脑 | 新电脑扫码由旧电脑批准；旧电脑已坏则用个人恢复码；都没有时由事项内同事设备重新包裹或律所恢复 |
| 丢电脑 | 吊销 → 轮换 → 本地存储加密；如实告知已解密到本机的明文无法远程收回 |

| 情形 | 中软看得到（过境或保存） | 中软看不到 |
|---|---|---|
| 默认（本地事项 + 网关 + 密文中继） | 账号、设备与执行域等级、席位、用量；匿名事项编号与推理调用元数据（保存）；推理时任务涉及的文档内容（令牌化后过境，不落盘）；期限提醒的触发时间与推送目标（提醒内容加密）；共享与设备中继的密文 | 落盘的案卷、成果、会话转录、令牌映射表、事项名称、提醒内容 |

| 启用法源与主体信息查询 | 案例核验与工商查询所需的查询项（可能含当事人或关联方名称，经确认或按策略放行），转给数据商 | 事项其他内容 |
| 启用 IM | 律师发给机器人的文字指令与文件名（过境）；中软 IM 后端持有平台下载凭据：电脑在线时文件由电脑直取，电脑离线时后端在内存取得文件后立即用接收人设备公钥加密暂存 | 落盘的文件明文（按设计不保存明文，访问有审计；IM 平台本身保存消息与附件） |

| 云端事项（G3） | 该事项在云端事项库与云端执行期间的明文 | 其他事项 |

## 13. 本篇验收（进入第 04、06 篇探针与门禁）

1. **采购闭环**：只配置开放平台 API token、不登录任何 Kimi 账号，WebSearch、FetchURL、子 Agent、集群、目标、计划、技能、MCP、定时、文件历史、快照全部可用（经中软补位）。
2. **执行域有效**：W-core 在 Windows 10/11 家庭版与专业版、三款主流杀软（360、火绒、电脑管家）下可用；guest 读不到其他事项、用户目录与凭据；DNS/TCP/UDP 与回环访问全部失败；资源限额生效；工作区内无法创建链接；Bash 生成的文件可被 Read/Edit/Grep 以同一路径访问，反之亦然；≥ 300 例注入与逃逸红队零越界；W-data 的 JS 桥逃逸用例在 N 域内被操作系统拦截。
3. **闸门唯一出口**：除闸门进程外客户端进程零外部连接（N 域与 W 域同测）；含实体的检索与 URL 100% 触发确认或泛化；L3 图像直送被拦截；L3b 零出站；渲染与 Office 打开 Agent 产物时零外部请求。
4. **宿主策略全覆盖**：每一个内置工具与 MCP 工具（含上游默认放行者）的裁决来源都是宿主策略；子 Agent 同样经过；运行模式不能被界面或远程改写；Agent 写入工作区的 `AGENTS.md` 与技能目录在新会话中不被加载。
5. **云端零明文（本地事项）**：控制面、网关、检索、法源、中继的数据库、对象存储、日志与错误报告中抽查不到客户内容、事项名称、文件名与检索查询原文。
6. **远程降权**：App、IM、定时三个渠道都无法触发签发、对外发送、导出与改权限；业务网关对引擎管理接口一律不可达。
7. **管理员无内容**：管理员账号在控制台与客户端都无法获得事项正文。
8. **控制面被攻破演练**：只有控制面签名的放宽策略、回放的旧策略、替换的成员公钥、未经管理员签名登记的连接器，客户端全部拒绝或告警。
9. **恢复**：丢失全部设备后用个人恢复码恢复本人事项；律所恢复按门限恢复且留痕。
10. **断云**：控制面停机 72 小时内本机能力与推理可用、联网后同步无丢失；许可过期进入退出模式。
