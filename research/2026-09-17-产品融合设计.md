# Kimi Work 法律行业版：产品融合设计依据

调研日期：2026-09-17。目标是在现有 Kimi Work 风格演示版上补齐业务闭环、Skills 与连接配置，同时减少首页的信息竞争。本文件记录来源证据与设计判断；不把网页演示能力等同于已上线的法律服务。

## 1. 结论与设计原则

产品应围绕“事项 → 材料 → 专业技能 → 可复核成果”组织。首页保留 Kimi Work 的统一任务输入与工作空间体验；法律场景为任务提供上下文，Skills 承载可复用的方法，连接器提供数据和执行工具。四者在任务中汇合，不在首页做成同等醒目的入口阵列。

本次最重要的改进不是增加功能数量，而是让用户能看懂三个问题：从哪里开始、系统正在处理什么、最后交付什么。一个完整演示应至少能贯通合同审查、类案研究、企业尽调三条路径，并提供可操作的技能与连接配置。

## 2. 调研方法与证据边界

证据分为三类：

- **直接界面观察**：由本次主任务通过 computer use 访问公开界面所得，以下按原观察记录引用。
- **官方公开资料**：来自产品官网、官方帮助中心，网页搜索索引可提取的内容与直接页面读取结果分别注明。
- **设计推断**：根据上述证据提出的本 demo 信息架构与交互建议，不代表竞品已实现或采用相同方案。

智合部分页面依赖客户端渲染。web 工具能确认 Skill 工作台及管理页标题，但无法提取完整交互内容，因此不以空白文本结果否定 computer use 的观察。登录后的管理、权限和连接配置没有被验证。

## 3. 信息架构与视觉层级

以下均为本 demo 的设计建议。

### 3.1 全局导航

| 层级 | 页面或入口 | 用户目的 |
| --- | --- | --- |
| 工作入口 | 工作台 / 新建任务 | 描述目标、选材料、开始工作。 |
| 持续上下文 | 项目与文件 | 管理同一事项的材料、任务和成果。 |
| 复用能力 | Skills 中心 | 找到、启用、配置和复用专业方法。 |
| 外部能力 | 连接与数据源 | 管理可访问的资料和可调用的工具；MCP 为其中的技术配置。 |
| 工作延续 | 最近任务 / 历史 | 返回上次处理位置、继续编辑成果。 |
| 工作空间管理 | 设置 | 团队默认值、演示说明、工作空间偏好。 |

业务分类建议使用“诉讼仲裁 / 非诉交易 / 企业法务”，作为场景和技能的筛选维度；不需要再创建三套重复的材料库、连接列表与任务系统。

### 3.2 首页优先级

1. 第一视觉重心：一句任务引导与统一输入框。输入支持材料、技能和数据源选择，但次要配置不默认全部展开。
2. 第二层：少量高频场景，建议合同审查、类案研究、文书起草、企业尽调。点击应填入可编辑任务或打开必要参数，不只弹出介绍。
3. 第三层：继续处理的项目和最近成果。以任务状态、时间和下一步呈现工作连续性。
4. 能力总量、介绍文案与高级配置弱化。不要同时堆叠统计数字、大幅推荐卡、完整技能目录和连接状态面板。

统一使用留白、标题级别、内容宽度和少量强调色建立层次。重点色用于当前操作、选中状态和关键结果；风险色用于风险等级，避免全页彩色卡片争夺注意力。

## 4. 技能、工具、项目与成果的关系

| 对象 | 定义 | 主要属性 | 与其他对象的关系 |
| --- | --- | --- | --- |
| 项目 | 一个法律事项的持续工作空间。 | 名称、业务类型、主体、材料、任务记录。 | 包含多次任务与多个成果，提供共享上下文。 |
| 任务 | 为一个具体目标开展的一次工作。 | 目标、材料、参数、执行状态、技能与数据源选择。 | 属于项目或独立存在；调用技能和工具；产生成果。 |
| Skill | 可复用的专业处理方法。 | 输入要求、步骤、标准、模板、输出类型、依赖工具、版本。 | 被任务选择；调用一个或多个工具；应用到项目材料。 |
| 连接器 / 工具 | 访问某项数据或执行具体动作的能力。 | 连接状态、访问范围、工具列表、配置、测试结果。 | 为技能和任务提供数据或执行服务，不自行代表完整法律方法。 |
| 成果 | 可以查看、修改、引用和交付的工作产物。 | 内容、类型、来源、版本、复核状态、导出格式。 | 归档到项目，保留产生它的任务和材料来源。 |

例如“采购合同审查”是任务；“采购合同风险审查”是 Skill；“读取项目文件、查询法规、生成文档”是工具；风险清单、修改建议和审查报告是成果。这样可以避免把“查询某数据库”与“完成一份研究报告”混成同一种卡片。

## 5. Skills 中心设计

建议分为“发现技能 / 我的技能”，并支持业务分类、搜索、启用状态筛选。卡片只展示名称、业务结果、标签和主要操作；具体配置进入详情。

预置能力优先覆盖：合同风险审查、条款修订、类案对比、法律研究、文书起草、证据目录、企业尽调、文档脱敏。数量应服从可演示的交互深度。

技能详情包含：

- 适用场景与预期成果。
- 必需材料与可选参数，例如审查立场、法域、时间范围、输出格式。
- 可读的执行步骤、引用资料和团队标准。
- 所需连接与当前可用状态；可直接进入连接配置。
- 启停、收藏或添加到我的技能、保存配置、使用技能。

创建技能使用业务语言：名称、处理目标、输入材料、执行步骤、参考模板、验收要求。提示词与技术配置可折叠到高级项。用户保存的技能与偏好应在刷新后仍可用。

## 6. 连接与 MCP 配置设计

页面主标题使用“连接与数据源”，说明它们如何支持当前工作。MCP 放在连接类型或高级配置中，避免普通用户必须先理解协议。

| 类别 | 建议演示连接 | 对业务有意义的配置 |
| --- | --- | --- |
| 法律数据 | 法规与案例检索 | 检索范围、时间范围、引用来源。 |
| 企业数据 | 企业风险查询 | 主体、股权、涉诉信息范围。 |
| 团队资料 | 项目文件与内部知识库 | 可访问项目、文件夹、只读范围。 |
| 协作资料 | 飞书文档或 SharePoint | 工作空间、同步范围、最近同步状态。 |
| 文档工具 | 文档解析与导出 | 支持格式、输出目录或成果归属。 |
| 通用工具 | 浏览器研究 | 访问范围、来源保留方式。 |

每项连接提供状态、配置、测试、启停及可调用工具列表。配置表单可包含显示名称、连接类型、服务地址、认证方式和访问范围。普通设置使用业务说明；协议细节置于高级区域。

演示测试可以校验表单格式并返回模拟状态，但必须标注“演示连接 / 模拟测试”。没有后端请求时，不得把绿点、工具数量或延迟表现为真实连接成功。未接通的商业数据库不应显示“已授权”或暗示使用真实账户。

## 7. 三条优先工作流

### 合同审查

选择合同 → 指定立场与审查标准 → 生成处理计划 → 展示条款风险及对应原文 → 接受或忽略修改建议 → 生成审查报告与修改稿。

可见的演示重点是“风险为什么出现、对应哪里、如何处理”。结果页采用风险列表与条款详情，不仅显示一个风险评分。

### 类案研究

描述争议焦点 → 设置地域、时间、法院层级 → 选择资料来源 → 呈现检索步骤 → 案例对照与裁判观点 → 生成研究备忘录。

关键是事实相似点、差异点和来源定位。演示案例与研究结论明确作为样例，不伪造实时检索或有效性核验。

### 企业尽调

输入主体 → 选择项目资料和查询范围 → 核查主体、股权、涉诉和经营风险 → 形成尽调矩阵 → 列出待补材料 → 导出报告。

关键是资料覆盖范围与缺口，而非无依据的综合评分。矩阵中区分已提供材料、演示外部数据和待确认项。

| 优先级 | 工作项 | 完成标准 |
| --- | --- | --- |
| P0 | 备份与可回退基线 | 修改前保留完整可恢复版本并记录位置。 |
| P0 | 首页层级和统一任务入口 | 首屏一个明确主操作，场景选择有后续动作。 |
| P0 | Skills 中心与详情配置 | 搜索、筛选、启停、保存、启动任务可操作。 |
| P0 | 连接配置与状态 | 配置、模拟测试、启停及任务依赖状态一致。 |
| P0 | 三条演示业务闭环 | 输入、执行反馈、结构化成果、导出路径完整。 |
| P1 | 项目与文件 | 材料能进入任务，成果能回到项目。 |
| P1 | 成果复核与版本 | 引用、待确认信息、建议处理、版本关系清楚。 |
| P1 | 连续使用体验 | 最近任务、持久化、空状态、错误状态及响应式布局完整。 |
| P2 | 真实集成与组织能力 | 后端鉴权、连接器、权限、审计和真实文档处理经过单独验证。 |

## 10. 本轮实际落地与保留项（2026-09-18）

本文前面的优先级与目标流程是产品设计建议，不等于全部已实现。

本次实际落地：工作台信息层级、9项可配置技能及3类专家角色、6类MCP模拟连接与自定义配置、任务依赖快照、知识资料中心、项目创建及文件名清单、按项目交付、本地保存、可编辑并下载的多份技能工作底稿；继续保留合同审查、批量矩阵、证据、研究、起诉状与脱敏的固定演示。

两项具体差距：

- 类案与法律研究仍展示3条官方方法／模板参考资料，支持筛选、纳入备忘录及来源说明；本轮没有真实裁判检索、法院层级筛选或实际类案对照表。
- 企业主体核查创建带技能要求与工具快照的可编辑工作底稿，由用户填入内容；本轮没有实际企业主体、股权或涉诉查询，也没有自动生成企业风险结论。

MCP测试只校验本地配置并更新明确标记的模拟状态。六个预置法律工作流播放固定示例，编辑技能不重新生成样例法律分析。真实协议、凭据、数据授权、模型推理、全文解析与机构集成属于下一阶段。

实际操作路径、回退及验证记录见同目录上级的《演示说明.md》。
