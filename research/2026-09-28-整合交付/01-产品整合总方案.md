# Kimi Work 法律行业发行版产品整合总方案

版本 1.1 · 定稿 2026 年 9 月 30 日 · 主要证据核验 9 月 28 日，律师法补核 9 月 29 日 · 面向中软国际产品决策、联合合作、研发与律所试点

## 1 核心结论与立项建议

建议把产品定义为：**中软国际自建运营、采用已授权 Kimi Work 设计与标识、以 Kimi 模型为主要底座的律所法律工作平台。律师通过桌面客户端与办公入口处理事项，获得有来源、有版本、经过复核签发的可编辑法律交付件；律所按席位购买服务。**

产品价值落在“从收到材料到完成交付”的全过程：少做机械整理，少漏重大风险，减少文档返工，把合伙人的方法落实到团队，并保留解释交付依据的记录。不能以模型回答流畅、场景数量或多 Agent 数量替代这些结果。

本次整合采用 Astra 方案的可信工程底座，吸收 Claude 独立审计中的角色价值、内容工程、商业与交付设计，并纠正审计对自建 SaaS 前提的误判。09-23 完整方案对商业及场景的补充保留，但收敛首发双端执行、全场景并进和未经测量的效果承诺。材料中的历史“用户拍板”、行动指令及模型自我评价不视为本次用户的新授权；当前请求为最高产品前提。

**本次硬前提**：联合 Kimi；已获法律行业发行版标识授权；允许借用标准版的设计布局及部分能力；中软自建托管 SaaS，以本地 exe 为主要客户端；按席位收费；中软采购 token 并承担成本；必须纳入 Word/WPS 与企业微信、钉钉、飞书入口。当前用户指定考察的是 **Kimi Code**，不是旧稿所写的 ZCode。

**工作假设**：先服务中国内地律所的中文民商事、合同与常年顾问业务。香港上市身份不等于香港法首发；香港法、跨境案卷与境外运维另设法域和数据流准入。价格、周期、容量和质量门槛都是规划建议，尚未经过本项目实测或商务承诺。

| 决策 | 本方案结论 | 直接结果 |
|---|---|---|

## 2 为什么律所选择我们

需要正面回答的替代方案是：律师购买通用 Kimi 产品，接法律数据连接器，自己维护提示词和模板；或采购现有法律 AI。Kimi Business 官方当前公开价为 4,200 元每座每年、两座起，并区分企业席位与 API token 采购。这只是竞品锚点，不能推定发行版已获会员转售权或同等 API 数据条款。[Kimi Business 官方介绍](https://www.kimi.com/help/kimi-business/kimi-business)

差异化应由以下可验证结果组成：

1. **法律交付保真**：原生 Word 修订、可复算 Excel、同源清洁稿、回稿比对、受众版本检查，而不是把聊天文字贴到 Word。
2. **按本所标准办事**：规则逐项解释触发条件，合伙人批准本所覆盖层，历史任务可追溯当时标准。
3. **来源支持结论**：核对原文、版本、适用时点与支持性；找不到或不支持时保留未决问题。
4. **事项级治理**：事项成员、伦理隔离、实质复核、签发、退出导出与删除，覆盖多个入口。
5. **交付服务**：把上述能力部署到律所现有 Office、身份和工作方式中，并承担平台质量与支持责任。

Harvey 的工作空间、审查矩阵和跨 Word 的 Agent 方法值得借鉴；LegalOn 的律师编写 Playbook 和就地修订说明内容工程的重要性；智合的业务场景与技能中心说明启动任务应贴近律师语言。它们的官方介绍只证明公开产品主张，不等于我们测试过质量，也不证明其适用于中国法。本次子代理已在智合官方 Skill 下载页确认 Windows 客户端，旧稿“智合没有桌面端”不再成立。[Harvey Vault](https://www.harvey.ai/platform/vault)、[LegalOn](https://www.legalontech.com/)、[智合桌面客户端下载页](https://skill.zhiexa.com/download)

不采用“国内唯一”“所有同行都没有”“全球最佳底座”等口径；不引用未取得可靠原文的竞品毛利、收入和市场份额作为投资依据。首轮销售材料用匿名对照任务、真实操作录像、交付件样本和试点结果说话。

## 3 买方 用户与权限

| 角色 | 获得的价值与交付物 | 产品权限 | 试点衡量方式 |
|---|---|---|---|
| 经办律师 | 风险清单、修订稿、研究备忘录；降低复核返工总时间 | 本事项读写、提出建议、申请签发；依所内规则可兼任签发人 | 相同难度任务从导入至可交付的时间、重大漏项、返工次数 |
| 律师助理 实习律师 | 材料目录、事实时间线、证据矩阵、缺口清单 | 授权范围整理与起草，不自动获得签发权 | 来源定位正确率、经办律师复核时间 |
| 团队合伙人 | 本所标准执行、集中复核、交付质量与工作负荷 | 审阅、退回、签发、事项成员审批 | 首稿通过率、交付周期、重大问题处置率 |
| 律所管理层 | 统一采购、风险管理、团队推广 | 机构策略与经营统计；默认看不到全部案卷正文 | 活跃付费席位、续费、事故、服务成本 |
| 知识管理员 | Playbook 与范本发布、法变影响管理 | 内容库管理；不自动读不属于自己的事项 | 有效规则覆盖、变更处置时效、规则采纳质量 |
| IT 安全管理员 | 安装、SSO、账号生命周期与技术审计 | 设备、身份、策略；案卷访问须另行授权 | 部署成功、撤权生效、恢复和删除演练 |
| 财务采购 | 席位、额度、发票和成本透明 | 账单与脱敏用量，不默认访问案情 | 单位交付成本、账单对账准确率 |
| 委托客户 | 律师审定的文件、明确假设与待确认事项 | 首发通过律所交付，不直接登录内部工作台 | 交付质量、响应时长、版本清楚程度 |

首要购买单元为有预算与日常协作的业务团队，首批每所 10–20 名实际使用者。团队付费意愿和律所准入同时验证，不能假设合伙人可绕过律所安全采购。利益冲突审查接现有律所流程：系统可提供线索及“已经人工完成”的记录，不把姓名匹配称为充分的冲突审查，也不向无权者泄露冲突事项名称。

## 4 一个完整产品的边界

### 4.1 首发与扩展

首发商用目标是三条主链真实闭环：**合同审查与下一稿、民商事案卷与受限起草、法律研究与顾问答复**。其中模板起草限通过样式和法域验收的案由；脱敏先作为全流程能力，不宣传能保证匿名化的独立万能工具。

36 个旧场景逐一登记为“首发候选、扩展候选、受限研究”；候选不是已上线。首页仅展示已通过门禁且当前租户有权使用的场景。没有授权数据源的研究入口应显示不可用或限定资料研究，不用模型常识补出“真实检索结果”。全部场景的输入、交付规格与验收见《02-全场景交付件与验收》。

首发选择 6 类合同、每类双边立场，共 12 套规则包：保密、采购买卖、一般服务、软件许可及实施、技术开发、商业租赁。劳动、投融资、担保等复杂领域按试点资料另行升级，不以两套立场仅改提示词计为完整两套方法。

第一批文书选择买卖合同、民间借贷、劳动争议等有限类型，使用最新正式示范文本和地方要求。2025 年已推广 67 类新版文书，旧 11 类试行文本不能继续作版本依据；劳动仲裁申请书另核当地仲裁机构格式，不能与人民法院诉讼模板混用。官方证据详见合规子报告及证据索引。

### 4.2 不进入首发销售承诺的能力

全自主法律意见签发、代律师向法院提交、自动向客户发函、自动判断诉讼期限生效、刑事高敏阅卷、涉密材料处理、跨境案卷、完整离线大模型、任意桌面操控、公共插件市场、全套律所财务与案管、所有旧 Office 版本插件覆盖。

这些边界不会削弱已售服务的完整性：合同、案卷、研究均有原生文件交付、人工复核、权限、账单、支持与退出闭环。扩展能力独立验收后上架；受限能力不默认带试用额度诱导上传真实材料。

## 5 客户端与多入口体验

### 5.1 沿用 Kimi Work 的设计结构

保留现有演示中已验证的统一任务输入、轻侧栏、对话与步骤、右侧成果预览；沿用获授权主题中的字体、配色、圆角、间距与排版。当前演示记录的侧栏约 260px、浅色背景、黑色主按钮和蓝色交互提示是设计基线，不把历史测量值当上游永久规范。签约范围内的正式设计资产进入版本管理。

导航收敛为“新建任务、事项、待我处理、交付中心、知识与方法、连接”，最近任务放侧栏；机构设置只对管理员显示。诉讼、非诉、顾问是场景筛选维度，不建设三套事项和知识库。Skills、MCP、模型名不挤入律师主流程，管理员可看技术详情。

四步启动继承既有设计：事项与立场 → 材料 → 任务目标 → 处理范围与交付要求。优先读取已有事项口径，缺少决定分析方向的信息再询问；不为每条只读操作反复弹授权。

### 5.2 关键页面与状态

| 页面 | 用户应看见什么 | 必须能完成什么 |
|---|---|---|
| 工作台 | 一个主要输入区、已可用场景、继续任务、待我复核 | 自然语言起任务，自动匹配事项或明确新建 |
| 事项 | 委托立场、法域、关键日期、材料版本、成员、数据去向 | 管理材料与协作；重要口径变更显式产生新版本 |
| 材料 | 原件、解析文本、实际页数、质量缺陷、权限与来源 | 低质量页纠正形成新解析版；原证据不覆盖 |
| 执行 | 已完成步骤、待补材料、真实处理数量、预算与排队 | 取消、补材料、保存部分结果、继续；不展示假百分比 |
| 审阅 | 条款或证据原文、建议、理由、来源、未决项 | 接受、改写、拒绝、分派；解释拒绝原因可选 |
| 交付 | 受众版本、引用状态、签发人、确切文件与变更摘要 | 预览、签发、下载、归档；已签发文件不可原地改写 |
| 方法管理 | 适用范围、规则版本、来源、测试、发布人 | 本所覆盖、回归、发布、灰度、撤回 |
| 管理后台 | 成员席位、事项权限、用量、告警、导出删除请求 | 统一策略、撤权、对账、恢复及支持授权 |

空状态明确“尚未选材料”；解析失败具体到文件与页；法源失败显示覆盖缺口；云模型故障保留本地草稿；额度不足显示预计需求和已经完成的内容。用户离开客户端不取消云任务，重新登录可续看相同版本。

### 5.3 Windows 客户端

首发 Windows 11 受支持版本，提供 exe 安装包与签名更新；企业静默部署包视设计合作律所需要提供。Windows 10 普通版本已于 2025-10-14 结束支持，ESU/LTSC 客户按具体系统和支持期列兼容矩阵，不宣传所有 Win10 长期受支持。[微软生命周期说明](https://learn.microsoft.com/en-us/windows/release-health/release-information)

推荐 Electron 与 React/TypeScript 复用现有设计资源；启用 renderer 沙箱、上下文隔离、关闭页面 Node 能力，文件操作通过最小 IPC。只访问用户选择的文件和授权目录；不扫描微信数据目录或全盘。拖入文件、系统文件选择、用户主动导出的邮件/聊天附件是标准导入路径。

首发不在每台电脑安装完整 Kimi Code、Python 工具链和常驻通用 Agent。可选本地 OCR/化名模块签名分发，按实际性能启用；未通过端侧处理验收时使用事先获准的境内解析服务，不能静默切换数据去向。离线可阅读经授权缓存和编辑本地草稿，不承诺离线法律推理。

安装、更新和回滚要覆盖代理网络、弱网、企业管控和 Office 共存。代码签名降低风险但不保证 SmartScreen 或杀软从不拦截；以实测矩阵和申诉机制处理。撤权能阻止后续服务访问，不能承诺撤回用户已复制或离线保存的明文文件。

### 5.4 WPS 与 Word 加载项

两类加载项共享“选择事项—审查选区或全文—审阅建议—写入修订—回传版本”的业务界面，宿主 API 适配分开维护。上传前显示范围，避免无意读取其他打开文档。每次写回绑定文档基线 hash、段落/表格锚点和预期旧文；不匹配时停止写入，显示并行修改冲突。

Word 的批注和修订操作取决于具体 API requirement set；运行时检测功能，不能只检查“Word 2019/2021”产品名。Office.js 适合有可验证分发路径的受支持环境；Windows COM/VSTO 可解决部分本机部署需求，但有位数、签名、安装权限和维护成本。**第 0 阶段依据三家试点真实版本选择主路径，不预先同时开发全部兼容层。**[Word API 要求集](https://learn.microsoft.com/en-us/javascript/api/requirement-sets/word/word-api-requirement-sets)

WPS 桌面 JS 加载项与 WebOffice 是不同产品。必须向 WPS 核定商业分发方式及个人/企业版支持；社区修改 publish.xml 或开发模式注册不作为生产验收依据。WebOffice 若涉及第三方处理文件，另列数据流与采购，不作为默认编辑器。

始终提供客户端导出 DOCX 修订稿的基础通路，但若合同明确出售某宿主“加载项就地审阅”能力，不能用下载文件替代其验收。原生修订、批注、接受/拒绝、保存重开均须真机测试。

### 5.5 企业微信 钉钉 飞书

三平台共用渠道接口和法律后端；按设计合作律所实际装机和管理员支持程度选择第一个商用入口，其余在下一阶段接入。首发必须至少一平台闭环通过，三平台完整上线是产品扩展验收项，不能把“三个平台图标”视为已接入。

机器人只负责主动投递材料、触发任务、查询状态、通知和带身份跳转。结果通知默认不含客户名称、案情和完整法律意见，群卡片尤其最小化；下载及审批必须回到有身份验证的网页/客户端，转发链接不会转移授权。

企业微信、飞书、钉钉各自的文件类型、群/单聊权限、大小、回调时限与服务商授权机制分别测试。企业微信客户联系互通不代表自建应用或机器人自动获得个人微信聊天和附件；收不到的文件使用上传 H5 或客户端导入。不得自动读取客户个人微信历史。

移动端可以分派、退回与批准；**签发人必须能看到将交付的完整文件、关键风险、来源和未决事项，仅看摘要卡片不足以签发**。手机显示不完整时转到桌面处理。机器人回调只创建审批请求，不能凭点击按钮绕过后端签发门禁。

## 6 交付件与律师工作闭环

### 6.1 一次合同任务

律师新建采购事项，确认采购方立场、交易地区和合同基线；导入合同及附件。系统展示哪些文件已读、哪些缺失，给出预计用量和交付清单。结构化工作流逐条检查本所规则，法源服务补充有效来源。成果区把商业谈判建议与法律强制要求分开。

经办律师处理重大风险和待确认项，在 Word/WPS 中修改。外部编辑回传形成新版本，原审阅记录只对未变且依赖未变的部分继承。签发人预览客户版的修订稿、意见书和未决问题，确认后生成交付清单及 hash。对方回稿时选比较基线，识别新增删改和被撤销建议；重排、定义变化、金额变化会扩大受影响结论的复核范围。

任务完成只表示执行结束；“已核验引用”“经办复核”“已签发”“已交付”是独立事实。签发是内部业务授权记录，不冒充具有相同法律效力的电子签章。

### 6.2 通用交付合同

每份成果必须携带：事项 ID、成果版本、材料清单与版本、适用法域/时点、范围及排除项、Playbook/模板版本、来源清单、未决项、复核状态、受众、签发记录。正式客户文件可只呈现必要内容，完整内部记录留在受控工作台。

DOCX 为真实可编辑格式；修订稿使用原生修订，清洁稿由同一批准内容派生；XLSX 保留公式、单位、输入假设及计算期间；PDF 供固定归档。文档属性区分“AI 辅助起草”和真实操作/审阅人，不将尚未审阅的修改伪记为律师亲自作出。

内部版保留谈判底线、反向分析、工作批注；客户版表达建议和需客户决策事项；对方版只含被批准披露的修改；法院版遵从具体程序要求。受众版本生成后再做元数据、隐藏批注、历史修订、嵌入对象、超链接和附件泄露检查，**签发绑定最终字节版本**。清理一般属性时不得误删依法应保留的生成标识。

原则上不在正式文件中留下未填占位符。确有业务上需披露的不确定性，应形成经律师批准的限制性结论；未知事实不得由模型补造。非关键缺口是否允许有条件交付由律师记录理由，原文不存在的虚假引用不能通过“律师勾选”豁免。

## 7 法律可信能力

### 7.1 来源与论断分开管理

法律依据分为“来源真实”“版本和元数据正确”“支持当前命题”“律师确认适用”四个维度。名称、案号和摘录匹配可用代码；法律适用包含过渡规定、法域、事实差异与裁判性质，不能声称确定性程序可以自动证明全部适用正确。支持与相反材料均需呈现。

生成 Agent 只可提出论断和候选引用，不能写入 verified 或 signed 状态。独立核验服务与律师分别负责对应阶段；另一模型表示赞同不是独立权威证明。案号格式异常只触发复查，不能因序号是 12345 就断定虚构。

研究任务冻结争点、地域、时点和资料类型矩阵，记录查询式、数据源、覆盖期间、执行结果与终止原因。研究完成表示履行约定检索范围，不宣称穷尽全部法源。供应商失联、许可过期、预算用尽或相反观点检索未做，必须显示部分完成。

### 7.2 原始证据与处理结果

原件只读存储并计算 hash；OCR、聊天截图识别、摘要、音频转写和增强图都是派生件。hash 证明内容一致性，不证明证据真实性、来源合法或司法可采。证据目录不能自动认定证明力。

PDF 的文件页、印刷页和卷内编号分列；DOCX 以段落、表格单元格和固定渲染快照定位。低质量内容保留原图、识别文本和人工纠正记录；不能把“未识别出字段”解释为材料没有该事实。

### 7.3 失效传播与召回

新材料、对方回稿、法源更正、规则撤回、律师修改或权限变更均触发影响分析。历史签发版不可改写；受影响成果进入需复核或撤回状态，通知授权责任人。对已下载或转发文件只能发更正通知与替代版本，不能声称远程彻底撤回。

审计采用追加事件、访问控制和独立存储防篡改；必要时使用 hash 链增强检查。hash 链不是司法采信或“不可能篡改”的保证，也不要求保存模型私有推理全文。审计记录足以解释输入范围、检索、工具动作、版本、核验与人的决定。

控制面采用模块化服务，首发不拆成大量微服务；文档解析、Agent 执行、连接器因信任边界分别隔离。业务事实与权限由服务端掌握，前端 localStorage 不再成为真实材料、审批或授权的权威记录。

新法律业务库可优先采用 PostgreSQL；这不要求修改当前 new-api 项目的数据库兼容承诺。若复用该网关，只把它作为模型流量和账户计量基础模块，对其许可证、安全与差异计费专项评估；法律事项权限、交付审批及来源许可不塞进通用聊天代理。本次不改动 new-api 仓库。

### 8.2 必须区分的四类权利

| 层 | 可以依据什么复用 | 不能自动推导什么 |

| Kimi Work 设计及标识 | 用户确认已有授权；对照具体资产清单 | 不自动取得整个客户端源码、闭源组件、字体或第三方素材再分发权 |

当前官方 Kimi Code 仓库可用于 ACP 集成，2.1.1 是本轮核到的发布版本；这仅是候选基线，不能从上游版本号推断法律场景安全性。锁发布制品、依赖和必要补丁，验收后才确定生产版本。[Kimi Code 仓库及许可](https://github.com/MoonshotAI/kimi-code)

### 8.3 三种执行路径的选择

| 路径 | 适合用途 | 首发安排 | 改变选择的条件 |
|---|---|---|---|
| 结构化流程加 Kimi API | 合同、抽取、格式、计算等有定义的步骤 | 生产主干与故障后备 | 法律盲测和单位成本达到门槛 |
| 自托管 Kimi Code 加 ACP | 有界研究、需要动态分解的任务及后端 demo | 在我方隔离 worker 中接入 | 禁工具、恢复、预算、材料注入和审计探针全通过 |
| Kimi Hosted Agents Beta | 合作方托管的执行与沙箱 | 合成公开材料对照 PoC；暂非关键路径 | 数据保留、工具权限、MCP fail-closed、容量、稳定合同全部满足 |

Hosted Agents 官方存在，不应沿用“没有官方托管方案”的旧结论；但它是独立云服务，不是可以随 MIT 代码任意部署的同一能力。其 Beta 数据持久化与权限约束需单独核实，不能把 ZDR 的模型接口承诺扩展到该服务。[官方快速开始](https://platform.kimi.com/docs/hosted-agents/quickstart)、[官方 ZDR 范围](https://platform.kimi.com/docs/guide/zero-data-retention)

备份优先为已经验证的结构化工作流，不在首发同时维护两个完整通用 Agent 内核。opencode 等只在实际替换测试证明有收益时加入。ZCode 和其他桌面壳不作为本次依赖；无须为品牌同源而复制上游全部工具。

### 8.4 Kimi Code 的受控接入

前端只调用我方法律 API，不接 ACP、不持有上游主密钥。适配器负责创建、执行、取消、交互、恢复与关闭，业务任务 ID 与 runtime session ID 分离。法律 profile、工具清单、模型路由和资料快照由服务端签发；配置缺失或能力不符则拒绝启动。

仅允许受控法律工具，默认禁 Shell、通用代码执行、任意浏览器、文件系统自动发现、公共 Skill 插件及递归自委派。需要子任务时由我方编排器有界分组并共享总预算。案卷中的 AGENTS.md、隐藏配置和“忽略规则”等文本均作为证据数据，不进入管理配置。

工具网关和网络边界才是授权执行点。ACP、提示词、工作目录或 Hook 都不能替代操作系统隔离。worker 无宿主挂载、无 Docker socket、无数据库长期凭据；模型出口与工具出口白名单；关闭未批准遥测、自动更新及远控中继。源码发现只能作为风险线索，具体修补需固定提交后的回归，不直接盲目 cherry-pick 安全提交。

### 8.5 文档与模型工程

文书服务与 Agent 分开：以结构化修订操作生成原生 DOCX，复杂比对引擎用真实中文合同筛选。Open XML SDK、成熟商用 OEM 组件及开源比对器同台评测，不因新项目功能列表丰富就直接成为唯一生产底座。检查多级编号、表格、脚注、历史批注、定义、嵌入对象与接受全部修订后的目标文本一致性。

OCR 首选可在我方环境运行且代码和权重都具备许可的组件；模型权重、训练数据与附加商用条款另审，不能只看 GitHub 顶部的 MIT/Apache 标签。首发不对难以可靠处理的手写、印章真实性和复杂图纸作过度承诺。

K3、K2.6 等是本轮可评估模型候选；法律判断与抽取各自盲测后路由，不默认“贵模型必然合格”“便宜模型只适合抽取”。最大输出、思考预算、重试、Agent 轮数与工具结果大小均有上限。模型升级、上下文压缩或路由变更触发回归，地域与数据条款不因故障切换而降低。

## 9 数据去向与安全边界

### 9.1 对外必须说清的处理模式

| 模式 | 实际处理与限制 | 首发状态 |
|---|---|---|
| 境内托管协作 | 获授权材料进入中软境内租户存储；必要内容经网关到约定企业模型及数据源 | 默认主路径，合同和准入通过后开放 |
| 本地预处理加云推理 | 原件可留端侧，但抽取文本、图像或必要片段仍被发送；映射表按事项受控 | 可选能力；并非不出端或完全匿名 |
| 离线阅读与编辑 | 无模型/检索调用，只访问获准缓存与本地文件 | 首发受限可用；缓存过期及撤权策略如实披露 |
| 全链路离线 AI | 模型、OCR、检索、日志、许可校验均不向外传业务数据 | 后续独立产品包与验收，不拿 exe 名称替代 |
| 客户专属部署 | 治理和数据可在指定环境；是否仍调用外部模型必须列明 | 独立报价与准入；不天然适合涉密处理 |

可逆化名仍可能构成个人信息；事实组合、案号和商业条款仍可识别客户。化名降低风险，不代替委托处理依据。质量下降时停任务、申请调整资料或改处理模式，**不能为了提高召回自动降低保密策略**。

### 9.2 端到端安全

租户、事项、文档、动作、版本和策略构成授权上下文；检索在召回前过滤，缓存键包含授权域；每次工具调用、文件下载、导出和签发重新校验。移除成员要处理活跃会话、后台任务、短链和缓存，停止旧上下文后再按新权限重建。

外部文件解析检查病毒、宏、路径穿越和压缩炸弹。原件不执行宏；输出预览阻断外部资源加载、公式注入、危险链接和嵌入执行对象。模型不能直接通过任意 URL 回调泄露案卷。

案卷正文不进普通日志或报错平台；支持人员通过有期限、限范围的机构授权访问。备份恢复前重放撤权与删除记录，避免删除数据复活。多租户访问测试、恶意文档、恢复重放、凭据撤销与未知外部动作对账共同成为上线门禁。

## 10 合规与责任分工

### 10.1 责任分工

中软承担产品运行、数据处理、技术安全、采购许可、计量和交付服务；律所决定案件处理目的、授权范围、专业判断和对委托人的法律服务；月之暗面按具体企业协议提供模型及约定处理；法源/OCR/IM 等按实际数据流确定角色。账号、计费和反滥用数据可能由中软独立处理，与案卷受托处理清单分开。

律师复核不免除产品缺陷责任；品牌授权也不代表月之暗面对每份法律意见背书。合同说明技术服务与法律服务边界、缺陷通报、更正和责任配置，不能仅写“一切后果用户承担”。

### 10.2 上线前应形成的明确结论

1. 实际签约与运营主体、服务器地域、模型/OCR/日志/备份/运维访问的数据流。
2. 生成式 AI 服务、应用登记、公示、算法与安全评估的具体适用路径；依据服务对象与功能判断，B2B 登录不天然豁免。[生成式 AI 暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)
3. 电信业务、网站/应用备案与等级保护的定级对象、办理结果或有依据的不适用结论。可以按三级控制目标设计，不能称已取得三级证明。
4. 数据处理协议、再委托安排、必要影响评估、敏感信息处理依据、供应商监督与删除证据。委托人的同意不自动覆盖对方当事人、证人和员工的全部信息。
5. 生成内容标识与无显式标识申请流程。默认支持显式/隐式标识；依法允许的申请须另留责任与日志记录，不因律师签字自动去除。
6. 律师保密及刑事、涉密材料的产品边界；本地部署不是涉密处理资质。2026 年修正《律师法》已于 9 月 1 日施行，保密义务现为第 41 条、利益冲突第 42 条、律所制度第 26 条；旧稿的条号需更新。该修正不意味着新增 AI 服务授权或免责。[全国人大修改决定](http://www.npc.gov.cn/npc/c2/c30834/202608/t20260828_457233.html)、[司法厅现行全文](https://sft.zj.gov.cn/col/col1229557739/art/2026/art_2d036d5a0e054c18b985504a724a8273.html)

上海律师协会的领域指引可借鉴为操作标准，但要核其地域、服务领域、有效期与非强制性质，不能提升为全国统一硬法。法条、模板和规则均以发布时最新有效版本再核；来源、条款与适用边界见合规子报告。

### 10.3 与 Kimi 的数据条款

本轮公开 API 协议、帮助说明和 ZDR 文档对服务优化、企业数据及留存有不同表述。应以覆盖本项目账户和 API 的企业合同、补充协议及开通证据确认实际权利，不据一条营销说明宣布“全链路零留存”。[API 服务协议](https://platform.kimi.com/docs/agreement/modeluse)、[ZDR 官方说明](https://platform.kimi.com/docs/guide/zero-data-retention)

| 本所覆盖层 | 按律所与我方合同约定；律所控制其秘密内容 | 试点每团队一套有限范围覆盖层 | 合伙人批准；到期可导出自有规则，第三方全文不随意带出 |

| 评测与红队资产 | 合成与获专项许可数据；中软维护 | 独立盲测、文档兼容、权限、来源、故障、成本集 | 与训练/调优分离；撤回授权有影响追踪 |
| 客户案卷与成果 | 客户/律所依法控制，非平台公共资产 | 仅本事项授权处理与交付 | 保留、保全、退出、删除由合同和适用义务控制 |
| 反馈和使用数据 | 目的分层，内容反馈默认留租户 | 采纳/拒绝分类、时间与技术失败统计 | 跨租户内容改进需额外清权，不自动训练 |

法律文本的著作权边界、网站访问约束、数据库编排、个人信息和合同许可分别判断。“公开可查询”“robots 允许/不允许”“不受著作权保护”任一单点都不足以决定全部商业复用权。禁止以浏览器自动化借用律师个人数据库会员建立 SaaS 能力；依法授权的企业连接器可正常采购与接入。

### 11.2 每个规则包必须交付什么

每条规则包括适用条件、立场、风险类型、必须/建议等级、法源版本、商业目的、首选条款、可接受备选、不可接受条件、例外、解释和测试样本。强制法律要求、律所政策、客户指令和律师偏好分层；后者不能覆盖权限及硬限制，业务冲突送律师决定。

生产流程为：需求与来源清权 → 法律工程师起草 → 专业律师审校 → 样本回测与盲测 → 法律负责人批准 → 签名制品发布 → 灰度 → 线上反馈 → 法变维护。Skill 是方法说明、输入输出 schema、工具权限、模板和评测的组合，不只是 SKILL.md 文本。

以 12 套规则、每套 20 个开发样本起步并非充分质量证明；另建跨来源盲测和反例集。同一合同的甲乙版本不能分到训练和测试两侧造成泄漏。验收按高风险实例数、合同类型与复杂度统计，并报告区间。首发至少 300 个独立业务任务加专项工程集，详见研发验收计划。

### 11.3 维护与客户知识沉淀

法源更新进入待审队列，按影响级别处理：紧急法律或供应商撤回当天评估并可暂停规则；普通变更目标五个工作日完成影响审查。来源不能及时更新时显示“最后核验日/覆盖限制”，不继续显示“最新有效”。

经办律师推荐成果进入本所知识库，业务合伙人审定，知识管理员核查秘密与权利；跨事项访问范围明确后发布。对本所规则的改进不自动进入平台规则。首发不做联合后训练，先验证检索、方法和文书的主要质量瓶颈；后训练另立数据和收益评估项目。

## 12 商业闭环与经济纪律

### 12.1 首发卖团队服务

建议首发仅销售“团队版”和有条件的“机构扩展包”。专业个人版和私有化另行验证需求，不同时推出四套运营模型。

| 项目 | 建议试点后的报价假设 | 权益与限制 |
|---|---|---|
| 团队版 | 9,800 元/具名席位/年，5 席起 | 桌面、已验收 Word/WPS 宿主、已接通 IM、主链场景、事项隔离、复核签发、基础审计与支持 |
| 机构扩展 | 50 席以上参考 8,800 元/席/年，另计治理及部署服务 | SSO/SCIM、专属资源、更高 SLA、多团队方法治理按清单报价；基本保密不降级 |
| 标准上线包 | 基础导入与培训有明确人天上限；超出单列 | 仅含一套限定范围本所覆盖配置，不承诺无限定制 |
| 用量加购 | 预付包及任务预估，价格经实测定稿 | 不把模型失败的无效重试重复向律师收费；平台仍承担上游成本 |
| 法源与专业插件 | 合同允许的基础源纳入权益；高价源明确增购 | 不能用个人会员“免费额度”支撑多年机构报价 |

上述为内部不含税测算假设，正式含税报价与税务处理由财务确认。席位跨客户端、Office 和 IM 共用，不重复收三次钱；纯管理账号是否免席位写入合同，但调用生产法律任务的人员必须有对应权益。席位回收不删除机构案卷，成员离职即撤权，并由机构移交任务。

商业权益与底层成本分开：任务按页面、文件、复杂度、研究范围形成可理解的预估；底层账本记录 token、缓存、工具、OCR、失败和重试。建议团队每席每月 500 服务点，作为待校准假设；服务点不是 token、货币或固定成本兑换权。内部可变成本护栏参考每点 0.40 元，只有实测验证消耗表能覆盖成本才发布。

权益规则必须明确：月发额度能否结转（建议年度合同期内结转，到期失效）、团队池/个人软限额、单任务上限、加购到期、失败退点、排队公平和自助停止。问答同样纳入预算，删除旧稿“问答计点同时又不限点”的矛盾。

### 12.2 经济模型不能只算 token

单任务成本 = 未命中输入 + 缓存命中 + 按接口实际规则计入的缓存写入 + 输出及收费推理 token + OCR/解析 + 付费数据 + worker/存储 + 失败重试。当前公开 K3 定价确有缓存写入项，09-23 和现存 09-28 脚本都未显式覆盖该项；新测算单列并按实际账单口径校准。[Kimi 推理价格](https://platform.kimi.com/docs/pricing/chat)

分别看三层：任务可变贡献、扣固定法源/平台直接成本后的产品毛利、再扣研发内容及销售费用的经营结果。折扣与渠道佣金分开；年末 ARR 不等于当年收入；一次性私有化实施不计 ARR；应收、合同负债、预付 token 和数据保底进入现金流分析。

《05-商业测算说明》及新测算脚本提供保守、基准、压力情景。基准不依赖供应商未来降价、免费法源、未签 token 分成或未经验证的重度用户比例。产品是否可持续由真实席位使用、交付成功率、客户支持工时与数据商报价决定。

示例按9,800元牌价、85%实现收入、每席每年1,500元任务成本及固定费用计算，1,000个全年平均付费席位的产品毛利约43.1%，仍有经营亏损；在费用不扩张的截面约需3,122个全年平均席位达到经营平衡。考虑建设期和扩张费用后的演示路径第三年仍亏损。这些数值支持阶段投资与付费验证，不支持直接承诺高毛利或三年盈利。

## 13 联合合作与市场进入

### 13.1 与月之暗面核对的交付清单

已获品牌授权继续作为前提，不重复申请原则同意；核对具体设计资产、地域、期限、联合宣传、退出过渡、客户持续服务和第三方素材范围。单独确认模型 API、数据处理、配额、计费和 runtime 支持。

容量按试点峰值任务到达率、每任务调用次数、上下文与平均占用时间推导，再留安全余量，不直接提出缺乏基准的“500 并发/5,000 万 TPM”。合同需覆盖限流行为、临时扩容、事故通知、模型弃用通知、价格锁定、供应商账单明细与服务终止后数据处理。

合作营销可以讨论线索报备、联合投标与实施分工，但不能假设月之暗面会停止向律所销售标准产品，亦不把未经法务审查的排他/转售价限制作为商业可行性前提。发行版以独立法律价值获得溢价。

### 13.2 设计合作律所与试点

三家组合建议：合同/非诉团队、民商事诉讼团队、具有 IT 管理能力的区域规模所。每家 10–20 名律师，至少一名合伙人、一名知识负责人和一个 IT 接口人。以实际材料质量、Office 版本、IM 平台和付费流程选择，不能只招积极使用 AI 的志愿者造成偏样本。

签署限期试点与数据条款，明确样本是否可进入该所专属评测或跨所通用评测。建议 6–8 周、有明确额度的共创试点；可收费试点抵正式服务费，或有限免费但约定负责人、每周反馈和退出日期。不默认六个月免费或自动获取客户训练数据。

同一任务难度分层，比较原人工方式和产品方式，计入资料准备、等待、经办复核、合伙人复核和返工。省下的工时不自动等于新增收入；按收费方式分析成本节约、交付产能与客户价值，避免承诺“每律师每月必省 44 小时”。

### 13.3 获客与续费

先通过团队直销与设计合作案例获得可验证收入，再拓展中软既有企业客户的外聘律所协作、联盟和律协渠道。律协有采购或试用案例并不代表本产品一定有预算；没有合同的渠道不进基准收入。渠道佣金、演示支持、法源许可和实施成本按客户计入获客成本。

续费围绕三类证据：实际使用且形成交付的席位比例、包含复核的净节时、重大风险和返工改善。客户可以取回案卷、已签发成果、自有规则及允许导出的索引元数据，不靠数据锁定促续费。

## 14 服务运营与退出

开通包含机构验证、权限配置、处理模式、法源范围、宿主兼容、规则选定、首个真实交付及管理员演练。上线包列出安装指南、数据处理说明、支持渠道、服务范围、SLA、培训、成本说明和退出手册。

可用性将任务受理、任务执行、外部供应商分开监控，并提供端到端成功率。首发 SLA 目标 99.5%，只在完成容量和灾备演练后签约；更高等级另测另报价。拟定 RPO 15 分钟、RTO 4 小时是待测目标，需覆盖业务库、对象存储、权限、引用和账本的一致恢复。

P1 故障目标 30 分钟响应、4 小时内恢复或给出可执行替代方案；工作时间与节假日值班范围明确。质量事故发现后立即阻止同类输出，识别受影响成果、通知机构责任人、提供更正和根因；不能为了固定“24 小时”而延后法定或合同要求的通知。

留存按数据类型与合同确定：事项档案依律所义务；临时文件、模型会话及缓存短期；审计与账单按必要法定义务；备份滚动清理，保全另域隔离。删除申请有回执、范围、供应商跟进和最终证明；无需宣称所有备份实时物理清除。退出提供可验证导出清单及迁移窗口，试点也必须能退出。

## 15 组织 路线与上线决策

建议以六周验证、十周受控试点建设、八周有限商用准备作为初始计划，总计约 24 周；时间从人员到岗、采购与访问条件齐备的 T0 起算，外部审批不保证按开发排期完成。可在阶段内提前交付薄链路 demo，不能把六周 demo 宣称为全产品商用。

| 阶段 | 建议规模与工作 | 退出条件 |
|---|---|---|
| G0 六周验证 | 10–12 人核心队伍加共享法务/安全；Kimi API 与 Code 对照、文档引擎、数据报价、实际宿主摸底、首合同闭环 | 数据条款、运行时权限、Word/WPS、真实成本和质量关键不确定性关闭或有可用替代 |
| G1 十周试点建设 | 峰值 24–28 人；三条主链、有限起草/答复、一个 IM、两类已选 Office 宿主、后台与内容包 | 业务及安全盲测通过；三所试点可完成真实交付；导出删除和灾备通过 |
| G2 八周商用准备 | 约 28–32 人；合同/账单/支持、兼容回归、容量、合规手续、另两家 IM 分批 | 明确销售范围、客户验收、至少两家覆盖已验收范围的付费订单、收费和运营就绪；未通过的连接不销售 |
| G3 扩展 | 按付费使用和贡献毛利增员；新增业务、专属部署、macOS等 | 每项有独立需求、权利、质量、经济门槛 |

G1 可按产品设计 3、桌面前端 3、Office 2、平台/编排 5、文档与检索 3、法律工程 4、测试 3、安全/SRE 2、客户成功 1 配置，共 26 人；另配共享商务法务及外聘双标律师。岗位不是都从第一天满编；法源采购与外聘标注不是免费资源。

首期预算采用阶段拨款：G0 参考 100–160 万元；G1/G2 根据真实人月、固定授权、文书组件、测试设备、合规及云资源重新测算，未完成 G0 不一次性承诺 55 人长期团队。预算区间为内部假设，不是供应商报价；与盈亏模型按同一人员和成本归类复核。

项目负责人对范围负责，法律负责人对内容与业务验收负责，架构/安全负责人对运行与隔离负责，财务对成本与收费口径负责，合规对准入结论负责，客户成功与试点合伙人共同确认交付可用性。严重权限泄露、虚假来源进入正式交付或错误修订覆盖原件属于阻断项，不能由销售目标豁免。
