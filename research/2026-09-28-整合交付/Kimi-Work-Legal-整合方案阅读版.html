PART 01

Kimi Work 法律行业发行版产品整合总方案

版本 1.1 · 定稿 2026 年 9 月 30 日 · 主要证据核验 9 月 28 日，律师法补核 9 月 29 日 · 面向中软国际产品决策、联合合作、研发与律所试点

1 核心结论与立项建议

建议把产品定义为：中软国际自建运营、采用已授权 Kimi Work 设计与标识、以 Kimi 模型为主要底座的律所法律工作平台。律师通过桌面客户端与办公入口处理事项，获得有来源、有版本、经过复核签发的可编辑法律交付件；律所按席位购买服务。

产品价值落在“从收到材料到完成交付”的全过程：少做机械整理，少漏重大风险，减少文档返工，把合伙人的方法落实到团队，并保留解释交付依据的记录。不能以模型回答流畅、场景数量或多 Agent 数量替代这些结果。

本次整合采用 Astra 方案的可信工程底座，吸收 Claude 独立审计中的角色价值、内容工程、商业与交付设计，并纠正审计对自建 SaaS 前提的误判。09-23 完整方案对商业及场景的补充保留，但收敛首发双端执行、全场景并进和未经测量的效果承诺。材料中的历史“用户拍板”、行动指令及模型自我评价不视为本次用户的新授权；当前请求为最高产品前提。

本次硬前提：联合 Kimi；已获法律行业发行版标识授权；允许借用标准版的设计布局及部分能力；中软自建托管 SaaS，以本地 exe 为主要客户端；按席位收费；中软采购 token 并承担成本；必须纳入 Word/WPS 与企业微信、钉钉、飞书入口。当前用户指定考察的是 Kimi Code，不是旧稿所写的 ZCode。

工作假设：先服务中国内地律所的中文民商事、合同与常年顾问业务。香港上市身份不等于香港法首发；香港法、跨境案卷与境外运维另设法域和数据流准入。价格、周期、容量和质量门槛都是规划建议，尚未经过本项目实测或商务承诺。

2 为什么律所选择我们

需要正面回答的替代方案是：律师购买通用 Kimi 产品，接法律数据连接器，自己维护提示词和模板；或采购现有法律 AI。Kimi Business 官方当前公开价为 4,200 元每座每年、两座起，并区分企业席位与 API token 采购。这只是竞品锚点，不能推定发行版已获会员转售权或同等 API 数据条款。Kimi Business 官方介绍

差异化应由以下可验证结果组成：

  1. 法律交付保真：原生 Word 修订、可复算 Excel、同源清洁稿、回稿比对、受众版本检查，而不是把聊天文字贴到 Word。
  2. 按本所标准办事：规则逐项解释触发条件，合伙人批准本所覆盖层，历史任务可追溯当时标准。
  3. 来源支持结论：核对原文、版本、适用时点与支持性；找不到或不支持时保留未决问题。
  4. 事项级治理：事项成员、伦理隔离、实质复核、签发、退出导出与删除，覆盖多个入口。
  5. 交付服务：把上述能力部署到律所现有 Office、身份和工作方式中，并承担平台质量与支持责任。

Harvey 的工作空间、审查矩阵和跨 Word 的 Agent 方法值得借鉴；LegalOn 的律师编写 Playbook 和就地修订说明内容工程的重要性；智合的业务场景与技能中心说明启动任务应贴近律师语言。它们的官方介绍只证明公开产品主张，不等于我们测试过质量，也不证明其适用于中国法。本次子代理已在智合官方 Skill 下载页确认 Windows 客户端，旧稿“智合没有桌面端”不再成立。Harvey Vault、LegalOn、智合桌面客户端下载页

不采用“国内唯一”“所有同行都没有”“全球最佳底座”等口径；不引用未取得可靠原文的竞品毛利、收入和市场份额作为投资依据。首轮销售材料用匿名对照任务、真实操作录像、交付件样本和试点结果说话。

4 一个完整产品的边界

4.1 首发与扩展

首发商用目标是三条主链真实闭环：合同审查与下一稿、民商事案卷与受限起草、法律研究与顾问答复。其中模板起草限通过样式和法域验收的案由；脱敏先作为全流程能力，不宣传能保证匿名化的独立万能工具。

36 个旧场景逐一登记为“首发候选、扩展候选、受限研究”；候选不是已上线。首页仅展示已通过门禁且当前租户有权使用的场景。没有授权数据源的研究入口应显示不可用或限定资料研究，不用模型常识补出“真实检索结果”。全部场景的输入、交付规格与验收见《02-全场景交付件与验收》。

首发选择 6 类合同、每类双边立场，共 12 套规则包：保密、采购买卖、一般服务、软件许可及实施、技术开发、商业租赁。劳动、投融资、担保等复杂领域按试点资料另行升级，不以两套立场仅改提示词计为完整两套方法。

第一批文书选择买卖合同、民间借贷、劳动争议等有限类型，使用最新正式示范文本和地方要求。2025 年已推广 67 类新版文书，旧 11 类试行文本不能继续作版本依据；劳动仲裁申请书另核当地仲裁机构格式，不能与人民法院诉讼模板混用。官方证据详见合规子报告及证据索引。

4.2 不进入首发销售承诺的能力

全自主法律意见签发、代律师向法院提交、自动向客户发函、自动判断诉讼期限生效、刑事高敏阅卷、涉密材料处理、跨境案卷、完整离线大模型、任意桌面操控、公共插件市场、全套律所财务与案管、所有旧 Office 版本插件覆盖。

这些边界不会削弱已售服务的完整性：合同、案卷、研究均有原生文件交付、人工复核、权限、账单、支持与退出闭环。扩展能力独立验收后上架；受限能力不默认带试用额度诱导上传真实材料。

5 客户端与多入口体验

5.1 沿用 Kimi Work 的设计结构

保留现有演示中已验证的统一任务输入、轻侧栏、对话与步骤、右侧成果预览；沿用获授权主题中的字体、配色、圆角、间距与排版。当前演示记录的侧栏约 260px、浅色背景、黑色主按钮和蓝色交互提示是设计基线，不把历史测量值当上游永久规范。签约范围内的正式设计资产进入版本管理。

导航收敛为“新建任务、事项、待我处理、交付中心、知识与方法、连接”，最近任务放侧栏；机构设置只对管理员显示。诉讼、非诉、顾问是场景筛选维度，不建设三套事项和知识库。Skills、MCP、模型名不挤入律师主流程，管理员可看技术详情。

四步启动继承既有设计：事项与立场 → 材料 → 任务目标 → 处理范围与交付要求。优先读取已有事项口径，缺少决定分析方向的信息再询问；不为每条只读操作反复弹授权。

5.3 Windows 客户端

首发 Windows 11 受支持版本，提供 exe 安装包与签名更新；企业静默部署包视设计合作律所需要提供。Windows 10 普通版本已于 2025-10-14 结束支持，ESU/LTSC 客户按具体系统和支持期列兼容矩阵，不宣传所有 Win10 长期受支持。微软生命周期说明

推荐 Electron 与 React/TypeScript 复用现有设计资源；启用 renderer 沙箱、上下文隔离、关闭页面 Node 能力，文件操作通过最小 IPC。只访问用户选择的文件和授权目录；不扫描微信数据目录或全盘。拖入文件、系统文件选择、用户主动导出的邮件/聊天附件是标准导入路径。

首发不在每台电脑安装完整 Kimi Code、Python 工具链和常驻通用 Agent。可选本地 OCR/化名模块签名分发，按实际性能启用；未通过端侧处理验收时使用事先获准的境内解析服务，不能静默切换数据去向。离线可阅读经授权缓存和编辑本地草稿，不承诺离线法律推理。

安装、更新和回滚要覆盖代理网络、弱网、企业管控和 Office 共存。代码签名降低风险但不保证 SmartScreen 或杀软从不拦截；以实测矩阵和申诉机制处理。撤权能阻止后续服务访问，不能承诺撤回用户已复制或离线保存的明文文件。

5.4 WPS 与 Word 加载项

两类加载项共享“选择事项—审查选区或全文—审阅建议—写入修订—回传版本”的业务界面，宿主 API 适配分开维护。上传前显示范围，避免无意读取其他打开文档。每次写回绑定文档基线 hash、段落/表格锚点和预期旧文；不匹配时停止写入，显示并行修改冲突。

Word 的批注和修订操作取决于具体 API requirement set；运行时检测功能，不能只检查“Word 2019/2021”产品名。Office.js 适合有可验证分发路径的受支持环境；Windows COM/VSTO 可解决部分本机部署需求，但有位数、签名、安装权限和维护成本。第 0 阶段依据三家试点真实版本选择主路径，不预先同时开发全部兼容层。Word API 要求集

WPS 桌面 JS 加载项与 WebOffice 是不同产品。必须向 WPS 核定商业分发方式及个人/企业版支持；社区修改 publish.xml 或开发模式注册不作为生产验收依据。WebOffice 若涉及第三方处理文件，另列数据流与采购，不作为默认编辑器。

始终提供客户端导出 DOCX 修订稿的基础通路，但若合同明确出售某宿主“加载项就地审阅”能力，不能用下载文件替代其验收。原生修订、批注、接受/拒绝、保存重开均须真机测试。

5.5 企业微信 钉钉 飞书

三平台共用渠道接口和法律后端；按设计合作律所实际装机和管理员支持程度选择第一个商用入口，其余在下一阶段接入。首发必须至少一平台闭环通过，三平台完整上线是产品扩展验收项，不能把“三个平台图标”视为已接入。

机器人只负责主动投递材料、触发任务、查询状态、通知和带身份跳转。结果通知默认不含客户名称、案情和完整法律意见，群卡片尤其最小化；下载及审批必须回到有身份验证的网页/客户端，转发链接不会转移授权。

企业微信、飞书、钉钉各自的文件类型、群/单聊权限、大小、回调时限与服务商授权机制分别测试。企业微信客户联系互通不代表自建应用或机器人自动获得个人微信聊天和附件；收不到的文件使用上传 H5 或客户端导入。不得自动读取客户个人微信历史。

移动端可以分派、退回与批准；签发人必须能看到将交付的完整文件、关键风险、来源和未决事项，仅看摘要卡片不足以签发。手机显示不完整时转到桌面处理。机器人回调只创建审批请求，不能凭点击按钮绕过后端签发门禁。

6 交付件与律师工作闭环

6.1 一次合同任务

律师新建采购事项，确认采购方立场、交易地区和合同基线；导入合同及附件。系统展示哪些文件已读、哪些缺失，给出预计用量和交付清单。结构化工作流逐条检查本所规则，法源服务补充有效来源。成果区把商业谈判建议与法律强制要求分开。

经办律师处理重大风险和待确认项，在 Word/WPS 中修改。外部编辑回传形成新版本，原审阅记录只对未变且依赖未变的部分继承。签发人预览客户版的修订稿、意见书和未决问题，确认后生成交付清单及 hash。对方回稿时选比较基线，识别新增删改和被撤销建议；重排、定义变化、金额变化会扩大受影响结论的复核范围。

任务完成只表示执行结束；“已核验引用”“经办复核”“已签发”“已交付”是独立事实。签发是内部业务授权记录，不冒充具有相同法律效力的电子签章。

6.2 通用交付合同

每份成果必须携带：事项 ID、成果版本、材料清单与版本、适用法域/时点、范围及排除项、Playbook/模板版本、来源清单、未决项、复核状态、受众、签发记录。正式客户文件可只呈现必要内容，完整内部记录留在受控工作台。

DOCX 为真实可编辑格式；修订稿使用原生修订，清洁稿由同一批准内容派生；XLSX 保留公式、单位、输入假设及计算期间；PDF 供固定归档。文档属性区分“AI 辅助起草”和真实操作/审阅人，不将尚未审阅的修改伪记为律师亲自作出。

内部版保留谈判底线、反向分析、工作批注；客户版表达建议和需客户决策事项；对方版只含被批准披露的修改；法院版遵从具体程序要求。受众版本生成后再做元数据、隐藏批注、历史修订、嵌入对象、超链接和附件泄露检查，签发绑定最终字节版本。清理一般属性时不得误删依法应保留的生成标识。

原则上不在正式文件中留下未填占位符。确有业务上需披露的不确定性，应形成经律师批准的限制性结论；未知事实不得由模型补造。非关键缺口是否允许有条件交付由律师记录理由，原文不存在的虚假引用不能通过“律师勾选”豁免。

7 法律可信能力

7.1 来源与论断分开管理

法律依据分为“来源真实”“版本和元数据正确”“支持当前命题”“律师确认适用”四个维度。名称、案号和摘录匹配可用代码；法律适用包含过渡规定、法域、事实差异与裁判性质，不能声称确定性程序可以自动证明全部适用正确。支持与相反材料均需呈现。

生成 Agent 只可提出论断和候选引用，不能写入 verified 或 signed 状态。独立核验服务与律师分别负责对应阶段；另一模型表示赞同不是独立权威证明。案号格式异常只触发复查，不能因序号是 12345 就断定虚构。

研究任务冻结争点、地域、时点和资料类型矩阵，记录查询式、数据源、覆盖期间、执行结果与终止原因。研究完成表示履行约定检索范围，不宣称穷尽全部法源。供应商失联、许可过期、预算用尽或相反观点检索未做，必须显示部分完成。

7.2 原始证据与处理结果

原件只读存储并计算 hash；OCR、聊天截图识别、摘要、音频转写和增强图都是派生件。hash 证明内容一致性，不证明证据真实性、来源合法或司法可采。证据目录不能自动认定证明力。

PDF 的文件页、印刷页和卷内编号分列；DOCX 以段落、表格单元格和固定渲染快照定位。低质量内容保留原图、识别文本和人工纠正记录；不能把“未识别出字段”解释为材料没有该事实。

7.3 失效传播与召回

新材料、对方回稿、法源更正、规则撤回、律师修改或权限变更均触发影响分析。历史签发版不可改写；受影响成果进入需复核或撤回状态，通知授权责任人。对已下载或转发文件只能发更正通知与替代版本，不能声称远程彻底撤回。

审计采用追加事件、访问控制和独立存储防篡改；必要时使用 hash 链增强检查。hash 链不是司法采信或“不可能篡改”的保证，也不要求保存模型私有推理全文。审计记录足以解释输入范围、检索、工具动作、版本、核验与人的决定。

OCR 首选可在我方环境运行且代码和权重都具备许可的组件；模型权重、训练数据与附加商用条款另审，不能只看 GitHub 顶部的 MIT/Apache 标签。首发不对难以可靠处理的手写、印章真实性和复杂图纸作过度承诺。

12.2 经济模型不能只算 token

单任务成本 = 未命中输入 + 缓存命中 + 按接口实际规则计入的缓存写入 + 输出及收费推理 token + OCR/解析 + 付费数据 + worker/存储 + 失败重试。当前公开 K3 定价确有缓存写入项，09-23 和现存 09-28 脚本都未显式覆盖该项；新测算单列并按实际账单口径校准。Kimi 推理价格

分别看三层：任务可变贡献、扣固定法源/平台直接成本后的产品毛利、再扣研发内容及销售费用的经营结果。折扣与渠道佣金分开；年末 ARR 不等于当年收入；一次性私有化实施不计 ARR；应收、合同负债、预付 token 和数据保底进入现金流分析。

《05-商业测算说明》及新测算脚本提供保守、基准、压力情景。基准不依赖供应商未来降价、免费法源、未签 token 分成或未经验证的重度用户比例。产品是否可持续由真实席位使用、交付成功率、客户支持工时与数据商报价决定。

示例按9,800元牌价、85%实现收入、每席每年1,500元任务成本及固定费用计算，1,000个全年平均付费席位的产品毛利约43.1%，仍有经营亏损；在费用不扩张的截面约需3,122个全年平均席位达到经营平衡。考虑建设期和扩张费用后的演示路径第三年仍亏损。这些数值支持阶段投资与付费验证，不支持直接承诺高毛利或三年盈利。

PART 02

全场景交付件与验收规格

版本 1.0 · 编制日期 2026-09-29 · 外部证据核验截至 2026-09-28

本附件以《01-产品整合总方案》为范围基线，将 legal-scenarios.js 的 36 个原始场景逐一转为可设计、可实施、可验收的规格。原文件字段名为 title，以下保留其原名及 id，不把目录入口数等同于已经上线的能力数。除明确引述的规则外，规格、容量和验收阈值均为规划建议；是否可以销售，以有限范围的实测报告、来源许可及客户验收为准。

1 范围、阶段与共同约定

1.2 角色和入口

经办律师负责业务口径和实质复核；助理可以整理、起草及提出问题；签发人按所内权限确认具体最终版本。合伙人、律师、助理可以是同一事项不同角色，不假设所有律所必须双人签发；高风险事项可由机构策略要求第二复核人。客户不直接进入内部工作台，中软运营及 IT 管理员无当然的案卷阅读权。

下文入口“桌面”指中软客户端及统一事项页面；“Office”指实际已验收的 Word/WPS 宿主和版本；“IM”指已接通的企业微信、钉钉或飞书。IM 主要接材料、建任务、通知及身份深链，不在群内默认展示案情或完整法律意见。Office 仅传用户选定的文档/选区，不读取其他打开文件。每个入口共享同一事项、权限、材料版本、额度及签发记录，不能形成三个互不一致的事实库。

G1 至少完成已选 Word 与 WPS 两类宿主及一个 IM 的真实闭环；G2 对其余两个 IM 分批验收后再加入销售范围。已经销售“加载项就地审阅”的宿主必须通过实际写回、修订、保存重开测试，客户端下载 DOCX 不能替代该承诺的验收。

1.3 所有任务必带的输入与交付封面

输入至少明确事项、客户立场、委托目标、法域及地域、适用事实时间、分析截止日、材料清单/版本、预期受众、资料去向及权限。数据不足时先给材料缺口和可完成范围；法域、对立方立场或提交对象等决定分析方向的关键项缺失，应先补齐，不自动猜测。内地民商事是默认产品范围，但每个任务仍须显示并确认；香港法和跨境案件不能默默套内地规则。

交付封面与系统 manifest 保存：成果 ID/版本、事项、材料及 hash、研究时点、范围/排除项、模板/规则版本、来源及许可标识、未决问题、复核人/签发人、受众、生成和签发时间、文件名及最终字节 hash。客户版可只呈现必要字段，完整证据留在受控底稿中。正式交付不留空白占位符；有条件结论须经律师批准并清楚描述限制。虚假原文或不存在案例不能以人工勾选豁免。

DOCX 使用原生文本、表格、样式与修订；XLSX 保存输入、公式、单位、期间、舍入及汇总口径；PDF 是选配固定归档件，不替代可编辑源文件。标识依适用规范和系统策略处理，无显式标识版本走独立申请流程，签发本身不意味着可以清除标识。模型执行成功、引文核验、律师复核、签发、下载、外发是不同状态。

1.4 验收用语与失败降级

“可定位”意味着能打开本次使用的确定版本并落到页、段、表格单元格或其他稳定锚点，不只是指向文件首页。“已读取”意味着解析结果实际进入任务覆盖清单；收到文件名不算读过全文。“缺信息显式”意味着空值、未取得、不可读、待确认分别可见，不以零金额、默认日期或推测事实补齐。

每项度量写清分母、样本范围和排除项。建议门槛可以要求固定验收集中无阻断缺陷，但不能宣传整个系统永不出错。重大事项须逐项被律师采纳、改写、拒绝并说明依据或升级；自动提示是否准确与律师是否完成处置分别统计。缺法源时可做“用户提供材料限定研究”，但须重新限定任务，不能仍称完成全网或全库检索。

失败降级保留已完成且可验证的部分、失败文件/页、未履行的检索计划和下一步；不能写“任务完成”掩盖不足。法源失效、保密策略冲突、基线变化或关键解析失败时暂停相关步骤；不为提高结果质量偷偷换境外模型、上传更多材料或扩大权限。导出草稿应明显标注内部草稿和缺口，不得冒充可签发终稿。

2 六个通用能力规格卡

C1 合同审查、修订及对方回稿

角色、入口与完成目标。 经办律师在桌面批量导入或在 Office 选定全文/选区，助理整理附件，合伙人处理风险和谈判授权。完成目标是一组同源的审查意见、原生修订稿、批准清洁稿及回稿差异，不是只有一段评价。IM 可以接收任务和通知；当手机无法完整显示条款、附件及关键风险时转桌面复核。

必需输入。 主合同、引用附件及既有修订版；六类中对应类型；双方身份和我方立场；交易地点、准据法、签约/履行期、分析截止日；交易结构、金额/币种/税口径；业务目标、不可变条件、谈判授权；本所规则版本。附件未取得和对方草案未全读分别列出。中英文并存、境外法、复杂融资或不动产权属调查进入独立范围审查。

处理和边界。 建立条款与定义索引，分开法律强制要求、律所政策、客户商业底线和编辑性改进。每项意见标明触发的事实、条款、风险与建议，不凭抽象“公平”单方删改。付款、验收、交付、终止、责任上限及附件优先关系交叉检查。收到回稿后由用户选择比较基线；移动条款、编号变化、定义变化及被接受后再撤销的修改分别显示；依赖已变的旧复核不能无条件继承。

交付规格。 合同审查意见.docx 包含交易概要、范围、重大问题、需客户决策、一般建议、未审附件；条款问题表.xlsx 含问题 ID、原文锚点、风险等级、规则 ID/版本、来源、法律/商业类别、首选/备选、影响、处理人、状态；修订稿.docx 保留真实修订与批注；清洁稿.docx 由同一批准版本生成；回稿差异表.xlsx 含基线/新稿、旧文/新文、对方动作、受影响定义与金额、原建议状态、重新复核人。没有对方回稿时不制造差异表。

人工复核。 律师确认主体、立场、附件覆盖、重大法律依据和商业选择；签发人看最终受众版本，内部谈判底线不得进入对方稿。用户可以不同意规则，但须区分有记录的商业例外与不可覆盖的权限/真实性门禁。合同中的事实、价格与承诺未经材料或授权支持，不得由系统自行创造。

建议验收。 120 个独立合同盲测任务覆盖六类双立场，建议每组合至少 10 个，其中纳入回稿、复杂编号、长表格、附件缺失等变体；具体分层由 04 统一冻结。逐问题评价高风险漏报与误报；建议高风险召回达到 95% 的目标同时报告精确率、实际实例数及区间，不以少量样本作保证。关键金额/主体/否定词和定义改动必须可定位；固定兼容集中“接受全部修订”的结果与批准目标文本一致，重要表格和编号不丢失。基线不符则阻止自动写回，改为差异预览供人工合并。处理质量、律师净复核时间和单任务成本一起评估。

阶段。 G0 先跑通一类一个立场的薄链路；G1 完成 12 套规则和真实回稿闭环；G2 仅销售已通过对应合同类型、立场、Office 宿主和容量的范围。投资、劳动、担保等不能借此直接上架。

C2 民商事案卷整理与证据工作

角色、入口与完成目标。 助理在桌面导入案卷和用户主动导出的邮件/聊天文件，经办律师确认争点与证据用途。核心结果是可核对的材料目录、事实时间轴和证据矩阵，供研究、诉状及汇报复用；不把 OCR 或模型摘要当已经法院确认的事实。

必需输入。 完整文件集或明确批次、原卷编号/页码、载体与原件状态、我方身份、诉请/对方请求、程序文书和送达信息、争议发生/合同履行期间、地域与分析截止日、证据合法来源及处理许可。扫描质量、手写、重复页、缺页、音视频转写等需单列。任务不能自动进入个人微信数据库或读取全盘查找“可能有关材料”。

处理和边界。 保留原件 hash，将 OCR、纠错、摘要与原件分开；维持原卷页码与电子页码映射。事实条目区分当事人陈述、书证记载、对方主张、模型推导及律师确认；同日同额也不能自动合并为同笔款。建立“争点—要件—举证责任—材料—证明力意见—缺口”的关系，保留矛盾证据和不利信息。只读某些文件时明确覆盖；不能把证据冲突自动处理成伪造或非法证据排除。

交付规格。 案卷总目录.xlsx 包含文件 ID、原名、来源人、接收日、文档日期、版本/hash、页数、原件/复制件、可读状态、密级/权限；事实时间轴.xlsx 含事件、发生日与确定性、主体、金额、来源页/段、陈述性质、冲突 ID；证据矩阵.xlsx 含证据编号、待证事实、证明目的、关联请求、原件状态、支持/反驳、待核问题、责任人；案情底稿.docx 区分无争议、争议、尚未知、待补材料；可选 阅卷导航.pdf 仅由受许可原件及索引生成，不重写原始证据。

人工复核。 经办律师核实关键主体、日期、金额及电子记录完整性，决定举证、质证和取舍；需争议证据原件或鉴定时系统只形成待办。程序期限从正式文件、送达事实和适用规则核验，不能把模型推测日期写成有效截止日。案卷底稿更新后，通知依赖其事实的研究或诉状重新复核。

建议验收。 60 个独立案卷任务按数字原生/扫描/混合、材料量级和证据冲突分层。逐样本核对真实文件数、读取页数、失败页和未处理文件；对约定关键事实计算定位准确率、漏提取率和错误合并率，单独报告 OCR 源错误和法律归类错误。有限验收集中关键日期、金额、主体若无法可靠识别，应全部进入人工确认队列；不得静默当真。至少包含重复文件、同名不同版、错页/缺页、手写不可读、跨文件矛盾及撤权后的引用预览专项。无法可靠解析时交付目录及缺口，停止实体结论；不生成假阅卷完成率。

阶段。 G1→G2 限普通内地民商事资料，实际容量按测得的页数/文件数/格式范围发布。刑事、涉密和跨境案卷不由“整理而已”绕过数据准入。

C3 法律研究、类案检索与备忘录

角色、入口与完成目标。 律师从桌面、Office 选区或顾问任务提出法律问题，合伙人确认争点和研究范围。成果必须说明检索做过什么、没有覆盖什么、结论由什么支持，而不是给一个看似完整的法律答案。首发使用获许可法源和本事项材料；官方网页可以依法核验，不自动意味着获准批量抓取。

必需输入。 研究问题、已知事实与假设、客户立场、法域/地域、行为时间与分析截止日、程序阶段、目标读者、允许来源、既有意见及反方观点、研究深度/预算。案件材料不足时允许抽象法律问题研究，但不假装已经确认本案适用。外国法、跨境冲突法、证券/金融等专门研究须相应领域包另行通过。

处理和边界。 固定初始检索计划：问题、关键概念、法条关联、正反关键词、时间地域、来源及停止条件；变更范围记录理由。法规核对公布、生效、修改、失效和过渡规则，行为时间与当前有效性分开。案例核对案号、法院、裁判日、审级、生效/入库状态可得性、全文出处；逐案比较事实、争点和适用规则。只找到摘要时不得编造全文。不得由样本数量生成个案胜诉概率或“本地统一尺度”。

交付规格。 法律研究备忘录.docx 包括问题、范围、事实/假设、简明结论、依据分析、反向论据、分歧及客户决策；类案对照表.xlsx 包括案名/编号、法院/日期、争点、关键事实、理由原文、结论、同异点、利弊、来源、核验状态；检索记录.xlsx 包括查询式、平台、时间、过滤条件、命中/纳入/排除数及原因；引用核对表.xlsx 包括命题 ID、引用区间、原文定位、版本/适用时点、支持性意见、人工复核和未决项。交付只在许可范围附原文或摘录。

人工复核。 生成、来源真实性、版本/元数据、命题支持性和律师适用判断分开。可由独立模型协助支持性检查，但不是以多模型一致给结论盖章；律师必须处理关键命题、相反判例与资料缺口。指导性案例、案例库参考案例和普通裁判不得混成相同效力，研究建议不冒充法院认可或正式监管口径。

建议验收。 60 个独立研究任务含历史法、地方分歧、找不到案例、摘要无全文、同名不同法条与不利案例。每个核心法律命题有可访问原文或合法快照及精确锚点；不存在或不支持的引用必须删除、改写或留在不能签发的待研队列。盲评统计来源真实性、时效元数据、命题支持和遗漏关键反向依据，分母分别报告。检索计划履行率以计划项完成/总计划项计算，源故障必须留缺口；不把履行率称为法域检索穷尽率。数据源停服时限定到现有获准材料，须律师接受新范围。

阶段。 G1→G2 先做内地合同与民商事争点；劳动地方研究可在确认的地域/时点和来源范围内候选。金融监管、反垄断、税务、刑事和香港法分别属于扩展或受限研究。

C4 有限法律文书与计算附表

角色、入口与完成目标。 经办律师从已整理事项启动，助理补要素，Office 用于就地审阅。目标是与材料和计算表一致、可编辑、经过指定律师审定的草稿包；系统不作为诉讼代理人，不自动签字、盖章、送达、立案或申请财产保全。

必需输入。 文书种类和提交对象、原被告/申请人立场、身份与授权、管辖事实、诉请、事实和证据底稿、关键行为/送达日期、时效问题、金额规则及已付抵扣、当地表格要求、分析截止日。买卖合同、民间借贷与劳动争议只开放已经逐类验收的模板；地方劳动仲裁要求和法院 67 类诉讼模板分开管理。已有系统要素可以复用，但重要字段须显示来源及上次确认时间。

处理和边界。 文书围绕请求—事实—依据—证据组织，区分当事人主张和已确认事实。缺主体、请求或管辖依据时留内部占位和补件表，不补造身份证/统一信用代码。利息、违约金或劳动请求采用经批准的确定性计算器，保存每段本金、起止日、日数规则、利率单位、年日数、抵扣日/次序、舍入及争议假设；互斥请求分情景，不简单叠加。系统提示期限风险，律师确认法律期间起算及节假日等条件。

交付规格。 文书内部稿.docx、证据附件目录.docx、金额测算.xlsx、提交前核对清单.docx。测算簿至少含输入参数、分段明细、公式/中间值、情景汇总、差异说明和来源页；未确认参数不默认为零。正式文书与计算附表的主体、请求编号、截至日、暂计数、持续计算表述及附件编号一致。系统保存模板来源、版本、地域和填写说明；客户版、法院版及内审版分别生成。

人工复核。 律师确认请求权基础、管辖/时效、重复主张、证据与金额；客户需确认的事实或授权单独列明。签发前清除未填占位符及内部讨论，实质仍未确定事项应经批准写为条件性表述或停止签发。无需把系统内部生成记录全部提交法院；提交内容依该事项实际程序要求确定。

建议验收。 30 个独立有限起草盲测任务按三类核心文书/业务分层，建议每类至少 10 个，仲裁地方样式若另增不挤占未经验证的法院文书覆盖。有限样本逐项复核主体、诉请、金额、附件和模板版本；关键漏项必须被门禁发现。计算边界另列专项：跨年、闰年、分次付款、零/负/缺值、日期逆序、不同利率单位和互斥请求；金额与独立复算在明确舍入后应一致。原始事实变化后旧草稿标记需重审。地方样式未确认则仅交内部事实/请求提纲，不标“可直接提交”。

阶段。 G1 有限试点，G2 按已验收模板/机构/法域销售；不能因模板导入成功就发布 67 类全覆盖，也不能把复杂劳动测算顺带纳入首发。

C5 常年顾问答复与客户协作

角色、入口与完成目标。 常年顾问律师接收企业联系人问题，可从桌面、Office 或已接通 IM 建任务，团队合伙人按事项风险复核。目标是客户看得懂、条件清楚、下一步可执行的答复，兼顾内部研究底稿和授权边界；机器人不是自动值班律师。

必需输入。 提问原文及时间、提问者和其授权、客户主体/行业/业务地区、事件经过、材料、需要决策的日期、事实核实状态、期望答复深度与受众。使用上下文前先确认事项归属，不能把上一位客户的资料当作会话记忆。问询没有足够事实时先形成澄清清单；紧急时间和客户要求不能自动突破资料或法源门禁。

处理和边界。 将请求区分为资料整理、既有意见解释、常见民商事咨询和须专项专业判断。围绕“目前能确认什么、影响是什么、有哪些选择、下一步需要谁做什么”组织答复；客户口述不当作核实事实。证券、税务、刑事、劳动处分、个体裁撤等转相应专业场景和合伙人，不借短答复跳过领域准入。来源不足时提出有限问题或研究计划，不用流畅文字遮盖未知。

交付规格。 顾问答复.docx 含问题复述、关键事实/假设、短结论、理由、可选方案、条件/限制、所需材料、行动/责任人/建议日期；可另生成经批准的邮件或 IM 简版正文。答复内审底稿.docx 包含法源、反向风险、客户未确认事项、引用状态和授权；行动清单.xlsx 记录事项、责任人、来源、状态、截止日是否确认及更新日。短答复能回链到同一研究版本，摘要与正式文件不产生相反结论。

人工复核。 经办律师确认事实和建议，合伙人按本所等级决定是否签发；仅能查看摘要的手机页面不能批准无法看到的完整附件。对外承诺、和解金额、履约期限及收件人均需要授权。首发默认下载/复制经签发版本后由律师发送；未来连接器自动发送须另行绑定正文、附件最终 hash、收件人和有效期，回执未知时先核对，不重复发送。

建议验收。 30 个独立答复任务覆盖事实不足、来源矛盾、历史法、客户要求越界和多轮补材料。评测问题是否得到实质回答、限制是否充分、建议能否对应责任和动作，以及经办/合伙人总复核时间。固定样本里，未经确认事实不能变成确定断言；超范围任务应被识别并交给专业律师。IM 专项验证群转发不转移权限、通知不泄露正文、撤权后深链失效、补件后旧答复失效。不得用字数或回复速度替代法律质量。

阶段。 G1→G2 仅在三条主链已覆盖问题内作为辅助；客户外部门户、无人审核 24 小时顾问和监管报送不进入首发承诺。

C6 隐私处理、可逆化名与最小材料发送

角色、入口与完成目标。 律师选择资料和处理模式，律所管理员设置策略，系统在桌面导入、云端解析、模型网关、Office 和 IM 出口一致执行。目标是减少非必要披露并给律师可核对的发送范围；不承诺全部匿名、不可再识别或没有隐私风险。

必需输入。 数据来源和事项授权、拟用目的、主体类别、敏感/保密等级、需要保留的法律关系/数值、允许接收者、处理地域、模型和 OCR 方案、对照表保存位置、保留期限、第三方限制。委托人授权不自动代表证人、对方、员工或其他个人的全部信息处理基础。刑事、高敏、跨境及国家秘密按产品准入执行，不把脱敏成功作为放行所有材料的唯一条件。

处理和边界。 检查正文、表格、文件名、作者属性、批注/修订、页眉页脚、图片与 OCR、嵌入对象等；姓名和主体使用一致的事项内代号，对照表单独限权加密。身份证、手机号等直接标识按必要性遮盖；日期、金额、人物关系、案号、事实组合可能重新识别，也可能影响法律判断，必须按目标任务决定保留/泛化/排除。可逆处理明示为化名。模型受限不能完成时停任务、换获准材料或处理模式，不静默发送明文。

交付规格。 材料发送范围表.xlsx 记录文件/页/字段、类别、拟动作、理由、接收者及已批准状态；化名工作副本.docx/pdf 保留版面和对照锚点；残余风险与例外清单.docx 记录未处理实体、图像/手写无法可靠识别区域、必要保留值和复核人；受控对照表 单独限权存储，不随模型请求或对外文件打包。端侧预处理模式可限定表仅在本机，此时其他入口不得承诺可恢复真实名称；托管协作模式按已批准数据策略存入境内租户专属加密域，恢复真实名称仍逐次鉴权。两种模式不能在后台自动切换。清洁交付如需恢复真实名称，必须由有权者在受控域执行并复核指代；不要在日志输出完整映射。

人工复核。 律师确认遗漏及残余重识别风险、保留法律分析所需信息；高敏例外按租户策略由指定负责人审批。脱敏只是措施，受托合同、合法基础、地域和来源使用权仍要满足。接收者变化、任务范围扩大或新增材料触发重评，旧批准不得自动覆盖。管理员能管理策略但不能因此看到全部映射。

建议验收。 C6 使用独立专项，不挤入 300 个业务任务计数。按文本/扫描/表格/图片/批注/属性/同名多实体建立已标注集，分别计算字段召回、误删、错回填和任务质量变化；报告各子类，不用总体高分掩盖身份证或未成年人漏项。受控验收集中直接标识漏出、跨事项错回填、映射表外发属阻断缺陷；“该集零漏出”不是任意输入保证。建议关键风险召回因化名下降不超过预先约定的 2 个百分点，并展示分母和区间；不达标时收缩处理范围而非关闭防护。

阶段。 G0 验证必要字段与质量影响，G1→G2 提供经验证的有限格式；复杂图纸、音视频人脸/声纹等另扩展。真正全链路离线模型处理未来独立验收，exe 安装、端侧 OCR 或保留原件在本机均不足以如此宣传。

5 逐场景规格卡

01 类案与诉讼策略 · civil-strategy

角色/入口：诉讼律师，桌面；合伙人审策略。输入：请求、争点、证据底稿、立场、法院地域、行为期间和研究日。边界：比较有利与不利材料，不预测胜诉率。交付：DOCX 策略备忘录含主方案/备选、请求权和程序障碍；XLSX 类案表含案号、原文、同异点，行动表含补证、责任人、条件。复核：律师确认举证责任与路径。验收/降级：每个关键策略可回链；未执行检索项显式列出，缺法源只交问题与研究计划。阶段：C2+C3+C5，G1→G2 限内地民商事。

02 证据清单与质证 · civil-evidence

法源或模板变更触发影响清单：哪些规则、场景、进行中任务和历史签发件引用了该版本；紧急撤回先停用相关能力，其他不受影响部分继续。一般变更按总方案目标处理并展示最后核验日；不能在更新链路中断时仍显示“最新”。仅修改文字排版不必重跑所有法律样本，但影响适用规则、抽取、模型、上下文压缩或修订引擎的变更应回归相关业务及专项。

1 应如何用这份测算

本测算用于决定试点需要采集哪些数、如何设计服务额度、何时扩员。它不是供应商报价、销售预算或收益承诺。公开模型价格已核，企业采购折扣、法源合同、真实用量、获客成本和付费转化均未取得。所有业务收入与支出按不含税规划口径，API 公示价与正式合同的含税/开票口径由财务统一后替换参数。

每家试点建立匿名任务日志：业务类型、资料页数/质量、人工基线时间、产品准备/等待/复核/返工时间、最终是否交付、严重错误、任务点数和真实成本。每周核对模型账单与我方计量，记录未知消耗、用户取消后费用及重复运行。

价值换算分收费方式：包年顾问看响应容量和服务质量；固定费项目看毛利与周期；按小时收费看客户可接受价格、必要工时记录和业务增长，不能把减少可计费小时自动算新增收入。前后对照控制任务难度、律师资历和学习效应；没有对照时只称自报节时。

商业阶段门建议：至少两家设计合作客户签署覆盖已验收范围的付费订单；关键用户四周仍实际交付；包含复核的中位净节时目标≥30%；严重错误不恶化；基于已签价格和试点用量的任务贡献为正；按客户测量支持工时。没有达到时先调整范围和价格，而非靠更多免费试点放大使用量。
