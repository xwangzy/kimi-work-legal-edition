# 子报告：入口与文书技术核验（2026-09-28）

范围：WPS、Word、文书引擎、IM 入口、OCR 与本机敏感信息识别许可、桌面壳。只写相对 09-23 基线的变化与补缺。
证据等级：一手（官方文档、源码、价格页、本机实测）｜交叉（多源一致）｜单一｜推测｜查不到。
说明：本轮后段 WebSearch/WebFetch 触发会话限额，Electron 与 Tauri 的内存对比、Aspose 国内经销价等少数条目未能补齐，已列入第四部分。

## 二、逐题结论

### 1. WPS

**1.1 Mac 版与个人版最新版**
- 最新个人版：Windows 12.1.0.28488（x64）和 12.1.0.28505（x86），称「2026 秋季更新」；Mac 12.1.28492。【单一，下载站】
- 官方加载项文档里，publish 模式只写了 Windows 企业版 20200425 分支之后、Linux 企业版 20200530 分支之后，**没有提 Mac**。【一手】[开发说明](https://qn.cache.wpscdn.cn/encs/doc/office_v11/topics/WPS%20%E5%8A%A0%E8%BD%BD%E9%A1%B9%E5%BC%80%E5%8F%91/WPS%20%E5%8A%A0%E8%BD%BD%E9%A1%B9%E5%BC%80%E5%8F%91%E8%AF%B4%E6%98%8E.html)
- Mac 实践：加载项目录在 `~/Library/Containers/com.kingsoft.wpsoffice.mac/Data/.kingsoft/wps/jsaddons`。wps-skills（MIT，629 星）的 Mac 脚本能装上，但也有用户在 Apple Silicon 上装上后功能区不显示（issue #16，因提问者未回复而关闭）；官方社区也有「Mac 能开发但装不上」的帖子。【单一】[wps-skills](https://github.com/lc2panda/wps-skills)
- 结论：**Mac 版 WPS 加载项没有官方承诺**。Mac 律师以 Word（Office.js）加客户端生成修订稿为主。【推测】

**1.2 安装器静默注册 publish 模式**
- 官方流程：用户打开 publish.html，由 WPS 写入 publish.xml。【一手】
- 社区做法：安装器把加载项目录（目录名以 `_` 结尾）放进 jsaddons，再合并写入 publish.xml（根元素是 `<jsplugins>`，条目示例 `<jsplugin name=… type="wps,et,wpp" url="xxx_/" enable="enable_dev"/>`）。不需要管理员权限，个人版可用。authaddin.json（含机器签名）和 jsaddinblockhost.ini 由 WPS 在本机生成，不能随包复制。【单一】[wps-bridge-assistant](https://github.com/q1780217573/wps-bridge-assistant)、[wps-skills #9](https://github.com/lc2panda/wps-skills/issues/9)
- 风险：12.1.0.26884（2026 夏季版）上有用户加载失败，原因是早期脚本漏写 publish.xml、目录名缺后缀、根元素写错，修复后通过；另有用户在新版本上失败，原因不明。**enable_dev 是开发标记，正式版应改成什么值，官方文档查不到**。【单一 / 查不到】

**1.3 JS API 文档（修订、批注、书签、Range）**
- 桌面加载项（沿用 VBA 对象模型）的文档都有：[Document.TrackRevisions](https://qn.cache.wpscdn.cn/encs/doc/office_v11/topics/WPS%20%E5%8A%A0%E8%BD%BD%E9%A1%B9%E5%BC%80%E5%8F%91/%E6%96%87%E5%AD%97%20API%20%E5%8F%82%E8%80%83/Document/%E5%B1%9E%E6%80%A7/TrackRevisions%20%E5%B1%9E%E6%80%A7.htm)、Revisions/Revision 对象、Comments.Add、Bookmarks、Range，以及 [Document.Compare](https://qn.cache.wpscdn.cn/encs/doc/office_v11/topics/WPS%20%E5%8A%A0%E8%BD%BD%E9%A1%B9%E5%BC%80%E5%8F%91/%E6%96%87%E5%AD%97%20API%20%E5%8F%82%E8%80%83/Document/%E6%96%B9%E6%B3%95/Compare%20%E6%96%B9%E6%B3%95.htm) 和 Application.CompareDocuments。这些页面都在 office_v11 文档目录（「WPS 加载项开发 > 文字 API 参考」）下。【一手】
- 已知平台差异：Windows 上 Excel 的 `Range.Value` 返回 undefined，要改用 `Value2`。所以**同一个 API 在 Windows 和 Mac 上行为可能不同**，必须逐项实测。【单一】
- 旧版静态文档 office_v19 现在返回 404，新文档站 open.wps.cn 是单页应用，本环境打不开。【一手】

**1.4 WPS 读取 COM 加载项：说法冲突**
- 官方社区帖（2026-03-27）：在信任中心启用第三方 COM 加载项，必要时关闭沙箱，即可加载。【单一】[帖子](https://bbs.wps.cn/topic/84616)
- 社区项目：称「WPS 个人版不支持 VBA/COM 自动化」。【单一】
- 结论：Word 用的那个 COM 加载项能否在 WPS 个人版和专业版里直接加载，**必须做探针**。

**1.5 金山开放平台**
- 三方应用：须先通过 WPS 365 企业认证，再申请成为 ISV 服务商，应用审核后上架 WPS 应用市场，供各家企业安装。【一手，开放平台前端文案】
- 其他入口：
  - MCP 广场：提供日程、会议、多维表、机器人消息等 MCP 工具。
  - WPS 365 CLI：面向 AI Agent；**必须是 WPS 365 企业账号**，由企业管理员审批。【一手】[安装指南](https://open.wps.cn/documents/cli/wps365-cli-installation-guide.md)
  - 数字员工开发平台；「WPS 365 可以养虾了」（通过数字员工对接 OpenClaw）。
- 灵犀：07-15 发布专业版（支持 WPS CLI、调用文档内核、浏览器插件，并称「支持 Microsoft Office 插件」）。**没有查到对外部厂商开放智能体或技能上架的通道**。【一手 / 查不到】[灵犀专业版](https://bbs.wps.cn/topic/92364)
- 金山自营「WPS AI 法律助手」（law.wps.cn，搭载 DeepSeek R1），与我们直接竞争。【一手】
- 元典：09-23 已核实其 MCP 接入了 WPS 智能体。
- 结论：WPS 365 应用市场可以作为**面向用 WPS 365 的律所**的 ISV 渠道；个人版 WPS 用户只能靠我们自己的安装器。【推测】

**1.6 WebOffice SDK**
- 能力：前端 JSSDK 的文字 API 包括：
  - Revisions：AcceptAll、RejectAll、Json、单条 Accept/Reject；
  - Document.TrackRevisions：切换修订模式；
  - Comments：Add、Reply、DeleteById 等；
  - Bookmarks、Range、ContentControls。

  【一手】[Revisions](https://solution.wps.cn/docs/client/api/Word/Revisions.html)、[Comments](https://solution.wps.cn/docs/client/api/Word/Comments.html)
- 价格：见变化表第 10 行。单文档默认 100M，每加 100M 每月 300 元；每个文档最多 200 人协作。【一手】[定价明细](https://solution.wps.cn/docs/price/detail.html)
- 私有化：平台只提供公网能力，私有化电话 400-677-5005 转 2；第三方文章称在线编辑私有化买断约 20 万元，但时间较早。【一手 / 单一】
- 嵌入：是 Web SDK，可以放进 Electron 窗口。【推测】
- 问题：文件要由金山云拉取和处理，**与本机优先的定位冲突**，只适合作为可选模块。

### 2. Word

- **要求集**：见变化表第 6 行。页面导语写「Office 2021 or later on Windows」，但表格里仍然没有 Office 2021 这一列。【一手】[要求集](https://learn.microsoft.com/en-us/javascript/api/requirement-sets/word/word-api-requirement-sets)

- **Office 2021 LTSC**：10-13 结束支持。【一手】[生命周期](https://learn.microsoft.com/en-us/lifecycle/announcements/office-ltsc-2021-end-of-support)
- **Office 2016/2019**：2025-10-14 已结束支持。【交叉，本轮未复核】
- **COM/VSTO**：
  - Word、Excel、PowerPoint 的 Win32 版本仍支持；只有新版 Outlook 不支持。【一手】
  - 微软提供了等效加载项机制：Office.js 加载项可声明对应的 COM 加载项，两者并存时由 Office 选择显示哪一个，1904 版起可用。

- **分发**：

  - 零售或批量授权 Office 又没有租户的律所：只有微软商店一条正式路径，而**商店在中国大陆能否用，本轮查不到**。
  
  【一手 / 查不到】[部署](https://learn.microsoft.com/en-us/office/dev/add-ins/publish/publish)、[主权云](https://learn.microsoft.com/en-us/office/dev/add-ins/publish/government-cloud-guidance)

**开源组合建议**
1. 主引擎用 Docxodus：
   - 条款级写入用编辑会话，修改直接写成 w:ins/w:del；
   - 整稿比对用 DocxDiff；
   - 客户端内预览和轻量编辑用 WASM 编辑器。
2. 底层补丁和特殊结构用 Open XML SDK 直接写。
3. 备份比对引擎用 Codeuctivity WmlComparer。
4. 付费兜底：DevExpress（按开发者授权）或 Aspose OEM，只在探针发现 Docxodus 对中文编号、表格、页眉页脚的保真度不够时才采购。

  - 合规做法：只接收用户主动导出的文件——小程序会话选文件（wx.chooseMessageFile）、文件传输助手转到电脑后拖入客户端、系统文件选择框；**不扫描**微信数据目录和聊天数据库。【推测】

**无独显笔记本上的速度**
- 公开参考值：Ryzen AI 9 HX 375 跑 Llama 3.2 1B（4bit）约 51 token/s；i7-12700 跑 Phi-4 Mini（3.8B，Q4）约 12 token/s。【单一】
- 推算：1.7B 模型 Q4 在主流 i5/i7 笔记本上生成约 15–30 token/s；预填充每秒几百 token。一份 1 万字合同单遍识别约 0.5–2 分钟。【推测】
- 结论：大模型只能做第二遍复核，第一遍应该用规则加小编码器（下文 3.4 节），每页毫秒级。

### 3.1 各宿主的实现分层

| 宿主 | 第 0 层（所有环境兜底） | 第 1 层（主路径） | 第 2 层（增强） |

### 3.2 MVP 范围
- 必做：
  - Windows exe（Electron，NSIS 按用户安装，可自动更新）；
  - 第 0 层修订稿生成（Docxodus）；
  - Word COM 加载项；
  - WPS JS 加载项（安装器静默注册）；
  - 企业微信单聊机器人和飞书机器人（收材料、推送结果）；
  - 小程序收个人微信文件。
- 缓做：Office.js、钉钉、WebOffice、WPS Mac、MSI 包（给有 IT 部门的律所，更新走我们自己的更新服务）。
- OCR：本机用 PaddleOCR 3.7（PP-OCR 系列，Apache-2.0）；服务端用 PaddleOCR-VL-1.5 或 DeepSeek-OCR-2。**不用 MinerU、Marker、Surya**，除非拿到商业许可。
- 本机化名：
  1. 第一遍用规则识别身份证、统一社会信用代码、银行卡、手机号、案号、金额、地址；
  2. 再用自训练 NER：在 rbt3 或 roberta-wwm-ext 上用自己标注的法律文书训练，导出 ONNX 放本机；
  3. Qwen3.5-0.8B/2B 做可选复核。
  - **不用** HanLP、LTP 的预训练模型，Presidio 只当框架用。
- 签名：国内 CA 的 OV 证书（私钥放 HSM 或云签名），上线前向 360 和火绒报白名单。
