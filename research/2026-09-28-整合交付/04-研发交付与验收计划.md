# 04 研发交付与验收计划

编制：2026-09-29｜技术证据截点：2026-09-28｜基线：[01-产品整合总方案](./01-产品整合总方案.md)｜适用：产品、研发、法律工程、测试、安全、运营及设计合作律所。

本附件把方案转换为可以拆分、实施和签字的交付合同。所有数值是**拟采用的验收门槛，尚非实测结果或既有服务承诺**。G0 可依据有记录的探针结果在盲测开始前调整性能与范围；不得看过验收结果后降低门槛。严重越权、虚假来源进入正式成果、未经批准改写原件等阻断项不得豁免。

## 1 范围、时间与人员

从人员、采购及访问条件齐备的 T0 起计算 24 周：G0 为第 1–6 周验证，G1 为第 7–16 周试点建设，G2 为第 17–24 周商用准备。外部审批、供应商开通不以日历代替证据。

首发交付 Windows 11 受支持版本 exe、境内法律云、已选 Word 与 WPS 宿主加载项、至少一个 IM 闭环、管理后台。三条主链是合同审查及回稿、案卷整理、法律研究；起草及顾问答复限通过验收的模板和范围。确定工作流为主，隔离 Kimi Code ACP 承担有界开放任务；Hosted Agents Beta 非关键路径。首发不建设本机通用 Agent、全链路离线推理、自动外发或法院提交。

G1 按 **26 人基线**组织：产品设计 3、桌面前端 3、Office 2、平台编排 5、文档检索 3、法律工程 4、测试 3、安全/SRE 2、客户成功 1；商务法务及外聘双标律师共享。G0 到岗 10–12 人，G2 根据验收和运营需要增至约 28–32 人。工作包是责任域，不另行重复配置团队。

## 2 领域对象与权威记录

统一使用服务端生成的稳定 ID。下表为待建数据契约，不规定所有对象各建一张表。内容版本不可变；`row_version` 用于可变元数据并发控制。时间统一存 UTC，呈现保留业务时区和法律事件原始日期。

| 对象 | 最小关键字段 | 权威记录与约束 |
|---|---|---|
| Tenant / User / Membership | tenant_id、user_id、role、status、authz_version、有效期 | 业务身份库；管理员角色不自动获得案卷正文权限 |
| Seat / Entitlement | 具名成员、合同项、有效期、场景及入口权益、额度池 | 权益台账；同人跨四端共用；回收席位不删除机构案卷 |
| Order / Payment / Invoice | 订单版本、数量、价格/税口径、付款及发票引用、退款/调整记录 | 商业台账；支付回调或人工收款凭证经核验后生效，调整用反向分录 |
| Matter / MatterPolicy | 委托立场、法域、适用时点、成员、保密等级、处理模式、policy_version | 事项服务；权限和数据去向由服务端确定，模型不能自选租户 |
| DocumentVersion / ParseVersion | 原件hash、对象存储key、格式/页数、来源、许可、解析器版本、质量标记 | 不可变原件及解析版；纠错只建新版本，原件只读 |
| EvidenceAnchor | document_version、parse_version、页/段/表格/字符区间、原文hash | 原始来源定位服务；转换前后位置有映射，不凭生成文本猜页码 |
| LegalSourceVersion / LicensePolicy | 来源ID、公布/施行/失效日、法域、条文/案号、抓取或核验时间、许可动作 | 授权法源库；现行与历史适用分开，缓存/展示/导出均受许可约束 |
| Claim / Citation / Finding | 命题、来源锚点、风险等级、规则、支持性结果、人工适用结论 | 引用及问题服务；生成器无权标记“律师已确认” |
| RulePackage / TemplateVersion | 适用范围、立场、版本、依赖、制品hash、测试报告、发布/撤回人 | 内容注册表；发布前法律审校，安全撤权优先于历史复现 |
| Run / Attempt / ToolOperation | 输入快照、预算、运行版本、状态、租约、fence、幂等键、结果摘要 | 持久任务库；run与供应商session分开，一项业务任务可有多次attempt |
| ArtifactVersion / Review / Approval | 基线、patch、最终hash、受众、未决项、复核/批准人、权限版本、有效期 | 成果库；签发绑定最终字节及交付清单，已签发版不能原地改写 |
| Usage / PointLedger / CostLedger | request_id、token分类、工具/OCR/worker实耗、点数预留/扣减/返还、价目版本 | 分开计量客户权益与供应商成本；失败退点不抹掉真实采购成本 |
| ChannelBinding / Device | 平台租户/用户ID、我方成员、凭据引用、设备状态、支持矩阵版本 | 身份映射服务；群成员不自动成为事项成员，密钥不入前端 |
| Audit / Retention / Export / Deletion | 操作者、动作、对象/策略版本、hash、请求关联、保全、范围及回执 | 限权审计和生命周期台账；普通日志不存案卷正文；保全与删除冲突可表达 |

关系约束：每次成果必须追到输入材料、方法、法源和模型配置；每条引用必须追到可读取的来源版本；每笔扣点必须追到唯一业务动作。外部检索服务和 Agent 会话不是我方业务权威记录。客户端缓存及 localStorage 不构成有效授权、已付款或签发证据。

## 3 我方接口示意

**以下均为中软待建业务 API 示例，不是 Kimi、Office 或 IM 已有接口。**正式实现由 OpenAPI/事件 schema 版本管理。鉴权上下文来自登录会话；即使请求含 matter_id，服务端仍逐次校验。写操作使用幂等键，版本变更使用 `If-Match`；冲突返回 409/412，不静默覆盖。

| 接口示意 | 请求核心字段 | 响应及约束 |
|---|---|---|
| `POST /legal/v1/matters` | title、stance、jurisdiction、policy_id | matter_id、policy_version；无权选的模式拒绝 |
| `POST /matters/{id}/uploads`；`POST /uploads/{id}/complete` | 文件名、size、mime、sha256；上传完成凭证 | 一次上传授权、最终DocumentVersion；服务端复算hash/扫描，未合格不入运行快照 |
| `POST /matters/{id}/runs:estimate` | scenario_version、材料版本、交付范围 | estimate_id、预算区间、缺口、有效期；不能代替正式授权 |
| `POST /matters/{id}/runs` | estimate_id、input_manifest、budget_cap、方法版本 | 202 + run_id；原子预留权益、持久入队；同键同body返回原run，异body拒绝 |
| `GET /runs/{id}`；`GET /runs/{id}/events?cursor=…` | 不透明游标 | 状态快照及可续传事件；先鉴权，不泄露无权对象是否存在 |
| `POST /runs/{id}:cancel` / `:resume` | expected_version、原因/补充材料版本 | cancel_requested或新attempt；恢复重验权限/预算，不盲重发上游prompt |
| `POST /artifacts/{id}/revisions` | base_version、patches、锚点与expected_text_hash | 新候选版或冲突；插件和客户端共用契约 |
| `POST /artifacts/{id}/approvals` | exact_version、manifest_hash、audience、已审未决项 | 批准记录；服务器先核强制检查和批准人权限；重放不重复签发 |
| `POST /deliveries`；`GET /deliveries/{id}` | 批准ID、确切成果版本、受众 | 不可变交付包；下载与人工外发记录分开，首发不自动向外发送 |
| `POST /admin/seats:assign` / `:revoke` | user_id、entitlement_version | 版本化分配；撤权关联活跃任务、会话及短链 |
| `POST /admin/exports` / `/deletions` | 范围、目的、策略、确认凭证 | 异步申请与可核验清单；保全例外可见 |

统一事件示例：`{event_id, run_id, seq, type, schema_version, occurred_at, object_version, trace_id, payload}`。重连按游标继续；客户端按 event_id 去重，缺口取权威快照。进度来自实际完成的材料/步骤，不由定时器制造百分比。模型思考内容不作为面向律师的审计解释。

## 4 状态、版本与故障语义

运行状态：`queued → running → succeeded`；可转 `waiting_input / waiting_approval / paused_budget`，满足条件后新建或恢复 attempt；失败到 `failed`，取消经 `cancel_requested → canceled`；外部动作结果不明到 `reconciling`。`succeeded` 仅表示执行完成。

成果状态：`draft → verification_pending → review_pending → approved → issued`；核验未过为 `blocked`，律师退回产生新draft版本，旧正式版可标 `superseded/withdrawn`。执行成功不自动批准；生成器不能把待核验改为已签发。下载、外部送达和客户接受分别记录，不能推断。

| 情况 | 必须的语义 |
|---|---|
| 律师编辑、补文件或改立场 | 新版本及依赖重算；仅未变化且依赖未变的结论可继承；关键变化使相关批准失效 |
| 两worker或两入口同时写 | 租约与fencing拒绝过期worker；乐观并发拒绝旧基线，禁止“最后写入者获胜” |
| 模型/检索429或超时 | 有界退避和总预算；无副作用读请求可重试；已提交上游而结果未知先对账 |
| worker崩溃 | 以落库事件/检查点恢复，检查工具操作账本；上游session存在不等于业务动作幂等 |
| 取消/撤权 | 立即拒绝新的受控工具调用，传播取消到子任务；显示已经发生的动作，不宣称自动撤回 |
| 审批后换正文、附件或受众 | 原批准失效；重新核验最终hash；批准A版不能用于B版 |
| 外部动作未知 | 记 UNKNOWN/reconciling，用幂等键和回执查询；无幂等能力时人工处置，不盲重发 |
| 发布/回滚 | 固定runtime、profile、工具、模型路由及内容版本；灰度后新任务切换；数据库用可兼容迁移，旧安全漏洞不能因回滚恢复 |
| 备份恢复 | 先恢复权威对象与关联，再重放恢复点之后的撤权/删除记录，验证后开放读取 |

首发通常没有自动外发，但支付回调、扣点、文件版本登记、插件写回、通知仍有副作用，必须覆盖幂等及未知结果。审批等待不持有长期数据库锁或运行中的付费沙箱。

上游只作为执行适配依据：[Kimi Code ACP能力矩阵](https://moonshotai.github.io/kimi-code/zh/reference/kimi-acp)。产品状态、事项授权、重试和计量契约均由我方实现，不能把协议提供会话恢复理解为业务事务已恢复。

## 7 测试体系与300项业务盲测

### 7.1 样本与分母

开发集至少按12套合同规则各20例起步，供调优；**另建300个独立业务任务盲测集**：合同120（六类各20、双边立场平衡，含回稿）、案卷60、法律研究60、受限起草30、顾问答复30。每项有冻结的材料、任务范围、允许的数据源/时点、交付规格、难度和金标准。另建工程专项集，不将同一文档的多个风险点充作多个业务任务。

合同风险标注至少覆盖180个高风险实例，每类至少30；若不满足应扩充样本而非降低分母。业务集应含简单/中等/复杂约30%/50%/20%，至少20%含缺页、冲突事实、过期法源、修订或权限限制等困难情况。只测试已售法域和支持范围；支持范围内无法完成也计入失败分母。

同一原始合同的改写、甲乙立场、对抗衍生本和同案材料归同一数据族，不能分到开发/盲测两侧。样本授权、来源清单、hash和访问人登记；禁止把盲测作为模型上下文示例或训练材料。G2增加至少60个全新任务，覆盖真实试点发现的失效类型；替换失效测试必须留记录，不能删除困难样本抬分。

两名有相应领域经验的执业律师独立标注/评分，隐藏模型、供应商、版本和产品/人工来源，随机顺序；分歧由第三名领域律师裁决。金标准接受有依据的合理法律分歧，不能只有一条措辞答案。报告同时给裁决前一致率和裁决理由，评分者不参与被测样本的调优。稳定性另抽固定困难任务重复运行3次，报告跨次方差，不能只挑最好一次。

### 7.2 统一拟定门槛

| 指标 | 分母及方法 | G1/G2放行目标 |
|---|---|---|
| 高风险召回 | TP / 金标准高风险实例；重复建议只计一次，按风险含义和定位匹配 | 总体≥95%，每合同类≥90%；总体95%置信区间下界≥90% |
| 高风险精确 | TP / 系统标为高风险的全部建议 | ≥85%；同时披露过度警报及各类样本数 |
| 来源真实性 | 所有引用实例核真实来源；来源不足明确缺口仍是未完成 | 签发候选包虚假/不存在来源为0；发现则阻断并追查受影响版本 |
| 锚点和出处 | 随机且分层抽取至少600条事实/法源锚点，覆盖三主链 | 正确定位≥99%；主体、金额、关键日期及支撑主要结论的锚点错误为0 |
| 主要结论支持性 | 双律师标注的主要命题均逐条核验；支持/不支持/无法判断分列 | 候选正式稿中不支持或未核实的肯定性主要命题为0；限制性结论须律师明确批准 |
| 原生文书完整性 | 专项兼容集全部支持宿主的往返测试 | 损坏、错位覆盖、未批准关键数据改写、既有修订静默丢失为0 |
| 业务直接可用率 | 无实质法律或事实修改即可经必要复核签发的任务 / 全部300任务；仅格式修改可允许 | ≥70%，每类≥60%；部分完成、超时及范围内拒答计入分母，正确识别材料不足单独报 |
| 关键计算 | 金额/利息/期限等已声明支持计算，至少100个边界样本 | 代码结果与独立人工/公式基准100%一致；不替代律师确认起算及规则适用 |
| 安全隔离 | 第8节强制探针全部实例 | 0次越权、非白名单案卷外传或越权签发；任何失败阻断 |

比例同时报告 numerator/denominator、95%区间及合同类别/复杂度分层；同一文档内风险相关，召回/精确的区间按文档簇重采样，不把所有条款假设成独立样本。样本不足的类别标证据不足，不以总体均值兜底。零失败表示此次固定测试集无失败，不宣传“零风险”。

### 7.3 律所效果验证

三所6–8周试点，覆盖不同资历，至少12名实用律师；完成至少60组同类型、同难度人工/产品对照，三主链各20组。随机交叉分配任务和使用顺序，避免同一律师先人工完成后靠记忆做AI；产物盲评。计时包括准备、等待、经办与合伙人复核、返工，排除用户无关中断但保留记录。

目标：总工时中位节省≥30%，质量不低于人工基线，95%区间及失败任务全披露。节时只计达到相同交付标准的工作，失败/返工成本归入产品组。四周留存定义为到第4周仍完成至少一次有效任务的可用席位/首周完成任务席位，试点目标≥60%；G1 进入商用准备可用至少两家明确付费意向或订单；G2 正式商用必须取得至少两家覆盖已验收范围的付费订单，不能拿意向、活跃替代实际付费与质量安全。

## 9 性能、成本与可靠性口径

G0先冻结负载包、供应商配额、机型、宿主、网络和计时方式。初始性能预算：受理API P95≤2秒（不含文件传输）；已接收普通交互任务排队P95≤30秒；取消受理后工具网关不得再批准新动作，运行进程回收P95≤10秒。长任务按输入分档测试，合同≤30页、案卷≤100页/20文件、研究≤5个争点作为起始标准包，草稿P95暂以10/15/15分钟为工程预算；G0测不达则缩范围或调容量，盲测前冻结并向客户披露。

端到端延迟从完整材料校验入库到可审阅成果，包含排队、供应商等待、重试、核验和渲染；律师补材料/复核单列。05/06 的 300 页全扫描案卷属于容量压力测算，不能沿用 100 页/20 文件的质量与时延报告；另行完成 300 页输入、文件数量、OCR 质量、成本和端到端时延验收前，不进入价单。超时及失败任务不可从延迟和成功率样本中悄悄删除。并发目标由三所峰值到达率、每任务调用次数及占用时间推导，执行预期峰值与2倍短时峰值测试，分别报告排队、限流与公平性。

成本每run/attempt记录：未命中输入、缓存命中/写入、输出及收费推理token、检索/OCR、worker、存储、失败重试；关联价格版本与供应商request_id。客户点数预估/实扣/返还与真实人民币成本分列，每日对账，月底供应商确认后结算；迟到账单和缺usage不得当零成本。至少30个有效任务/主链形成P50/P95成本、成功交付成本和重试占比，G0先给区间，G1/G2用全量试点数据更新商业模型。

G2拟签平台可用性99.5%，明确受理/执行和供应商故障的计算方式，同时公布端到端成功率；维护及例外按合同事先定义。完整系统实测RPO≤15分钟、RTO≤4小时，含对象、库、权限、锚点、账本和撤权删除重放。P1目标30分钟响应、4小时恢复或给可执行替代，值班时间和节假日范围书面明确。

## 12 运营交接与客户准入

- **购买开通**：验证机构及授权管理员，明确合同/发票/收款、席位数量与有效期、额度结转/加购/失败退点、支持范围及第三方增购。付款与订单对账通过才按政策开通；续费/停用及数据移交有宽限流程。
- **数据准入**：确定法域、事项类型、保密等级、材料权利、处理目的/供应商、留存及保全；默认排除涉密、未验收刑事高敏与跨境材料。安装exe不构成不出域承诺。
- **部署验收**：核实际Windows/Word/WPS/IM与代理网络，签名包、升级回滚、身份撤权及第一份真实成果；培训经办、签发、知识、IT与财务角色。
- **运行支持**：值班表、告警分级、模型/法源故障预案、质量事故暂停/影响排查/更正通知、机构限时支持授权；普通诊断不得默认查看案卷。
- **退出删除**：可导出原件、成果、自有规则及许可允许的元数据，附对象数量/hash及可打开抽验；先处理保全，再清理派生物、索引、缓存、会话和供应商副本，备份按制度到期清除并给记录。
- **持续维护**：法源和规则有责任人；模型/组件升级触发相应回归；每季度恢复演练及权限复查；续费同时复核许可、支持矩阵与成本，不让旧版无限期漂移。
