## 题 1：macOS 与 Windows 的差异从哪来（以 macOS 为基准统一）

### 1.1 主进程建窗口（`electron/main.cjs`）

| 项 | 现状 | 位置 |
|---|---|---|
| 窗口数 | 只有一个主窗口；登录、激活、重新登录、工作区都在这个窗口里切页面（`App.tsx` 按 `boot.onboarding` / `login` 换整页），**登录类页面与主界面尺寸相同** | `electron/main.cjs:1071-1116`，`src/App.tsx:403-424` |

**Windows 截图 2.png “铺满 1918 宽”的根因**：在 1920×1080 / 150% 的屏上，逻辑工作区约 1280×672，而初始尺寸 1440×900、最小尺寸 1080×700 **两者都比工作区大**（最小高度 700 > 672），系统只能把窗口压到贴满屏幕——所以看起来“全屏”，但右上角中间按钮仍是“□”（未最大化），不是最大化状态。这在 Windows 笔记本的缺省设置（15.6 寸 1080p 推荐 150%、14 寸推荐 125%～150%）下是常态，不是个例。125% 时工作区约 1536×816，900 的高度同样放不下。

### 1.3 Windows 字体渲染

**实际落到的字体**：拉丁字母与数字 → Segoe UI（Win11 上是静态 Segoe UI，不是可变的 Segoe UI Variable，因为栈里写的是 "Segoe UI"）；中文 → Microsoft YaHei UI。macOS → 拉丁 SF Pro（`-apple-system`）、中文 PingFang SC（栈里的 Segoe UI / 雅黑在 Mac 上一般不存在，跳过）。

**字重回退**（CSS 字体匹配规则：要 500 时先找 500，没有就退到 400；要 600 时先找 ≥600，没有就往下找）：

| 界面写的字重 | 用量 | macOS（PingFang / SF） | Windows 中文（雅黑只有 300/400/700） | Windows 拉丁（Segoe UI 有 300/350/400/600/700/900） |
|---|---|---|---|---|
| 400 | 43 处 | Regular | Regular | Regular |
| 500 | **120 处** | Medium | **退成 Regular（变细）** | **退成 Regular** |
| 600 | **108 处** | Semibold | **退成 Bold 700（明显变粗）** | Semibold |
| 800（SVG 字标） | 3 处 | SF Heavy | 无中文 | **落到 Segoe UI Black 900** |

后果：① Windows 上 500 的层级（按钮、标签、选中态）全部失效，与正文一样细；② 600 的标题中文变成雅黑 Bold、同一行英文却是 Semibold，中英粗细不一致（截图 4“方法库”“诉讼仲裁 22”、截图 5“简短思考中…”最明显）；③ 品牌字标“Kimi Work”用 SVG `<text fontWeight=800 textLength=… lengthAdjust="spacing">` 画（`src/components/Brand.tsx:58`、`src/pages/Home.tsx:343`），Windows 落到 Segoe UI Black，字形更宽却被 `textLength` 压回原宽，字距被挤没——截图 2、3、4、6 里“Kimi Work”发黑发挤就是这个；“法律版”小标同理（`Brand.tsx:34`，600 → 雅黑 Bold）。

**行高与字号**：雅黑字面比 PingFang 大、上下留白不同，14px 正文在 Windows 显得更大更挤；固定高度、`line-height:1` 的胶囊与按钮里中文会略偏下。现有 `line-height` 是无单位系数，不需要按平台改字号，但需要统一字体度量（见下）。

**DPI（devicePixelRatio 1.25 / 1.5）**：
- 1px 边框：Chromium 把边框宽度向下取整到整数物理像素且至少 1，1.25 / 1.5 下都画成 1 物理像素，问题不大；但半像素定位会糊，例如 `src/styles-materials.css:65` 的 `left: 110.5px`。
- 图标：24 网格、`strokeWidth={1.7}`（`src/components/Icons.tsx:6`），按 18px 显示时线宽约 1.28 CSS px，150% 下约 1.9 物理像素、125% 下约 1.6 物理像素——都不是整数，线条发灰发虚；Retina（2x）下约 2.55 物理像素，看起来更实。这是 Windows 图标“没 Mac 精致”的主因。
- 全仓库没有任何按 `devicePixelRatio` 的处理（`grep devicePixelRatio` 为空）。

### 1.4 统一方案（以 macOS 为基准，一次做成体系，不做局部补丁）

**A. 窗口（主进程，新增约 60 行，建议单独成 `electron/window-state.cjs`）**
1. 初始尺寸按工作区算：`const wa = screen.getDisplayNearestPoint(screen.getCursorScreenPoint()).workArea`；`width = clamp(round(wa.width*0.82), 960, 1440)`，`height = clamp(round(wa.height*0.86), 640, 900)`，`center: true`。最小尺寸降到 `minWidth 960 / minHeight 600`，且再与 `wa` 取小，**任何缩放下都不会超出工作区**。
2. `show: false` + `win.once("ready-to-show", () => { if (state.maximized) win.maximize(); win.show(); })`，首帧不再先露一块底色。
3. 尺寸记忆：`resize / move / maximize / unmaximize` 防抖 500ms 写 `userData/window-state.json`（`{x,y,width,height,maximized,displayBounds}`，逻辑像素）；启动时只有当保存的矩形与某个显示器工作区相交 ≥ 一半时才用，否则按第 1 步居中（防止外接屏拔掉后窗口跑到屏幕外）。不放 localStorage（主进程拿不到、且按账号分键不合适）。
4. 默认窗口化：**不**主动 `maximize()`；只在用户上次关闭时是最大化才恢复最大化。
5. 登录类页面与主界面仍用同一个窗口（避免多窗口带来的单实例、内容保护、Windows 控件浮层换色等重复逻辑），不另开小窗；窗口尺寸合适后登录卡片自然居中，不再“铺满”。

**B. 无顶栏、两端同一版式**
1. 删掉 Windows 分支 `styles-window.css:18-20`，把 macOS 分支（`:22-27`）改成两端通用：侧栏第一行（40px）只放“搜索 + 收起”（靠侧栏右缘，与 Mac 同位），品牌字标统一在第二行。Windows 第一行左侧没有红绿灯，就留空（与 Mac 红绿灯占位等宽），右上角仍由系统画控件。这样 Windows 的第一行只剩两颗小图标 + 右端系统控件，主面板上方是与底色同色的 40px 边距，**不再读成一条标题栏**，与 Mac 观感一致。
2. 系统控件浮层高度与拖动条一致保持 40（或改 36、与 Win11 标准 32 更接近，同时把拖动条与 Mac 红绿灯行一起改，保持两端同高）；浮层颜色继续随明暗走 `--bg-sidebar`。
3. 页面右上角若有按钮（如方法库搜索框，截图 4），用 Window Controls Overlay 的 CSS 环境变量 `env(titlebar-area-x)` / `env(titlebar-area-width)` 算出右侧保留宽度，避免将来主面板上移时与系统控件相撞；现阶段主面板仍从 40px 开始，不受影响。
4. 不改成完全自绘控件（`frame:false`）：会丢 Win11 悬停最大化的贴靠布局，得不偿失。

**C. 字体（按平台设字体栈 + 字重令牌，一次覆盖 228 处字重）**
1. 字体栈按平台分：在令牌层加
   - `html.plat-darwin { --font-sans: -apple-system, BlinkMacSystemFont, "PingFang SC", sans-serif; }`
   - `html.plat-win32 { --font-sans: "Segoe UI Variable Text", "Segoe UI", "KWL Sans SC", "Microsoft YaHei UI", sans-serif; }`
   - 缺省（网页开发形态）保留现栈。
2. Windows 随包一款有 500 / 600 的中文无衬线可变字体，作为 “KWL Sans SC”：首选 **思源黑体 / Noto Sans SC 可变字体（SIL OFL，可随软件分发）**，按 GB 2312 + 常用 3500 字 + 法律常用字 + 全角标点子集化后 woff2 约 2～4MB，打进 asar，`@font-face` 只在 `plat-win32` 引用（Mac 不下载、不解析）；`@font-face` 里用 `ascent-override / descent-override / line-gap-override` 把纵向度量调到与 PingFang 一致（值由一次截图比对定），解决胶囊、按钮里中文偏下。若因体积不随包，退路是 **字重令牌**：新增 `--fw-regular:400 / --fw-medium:500 / --fw-strong:600`，`plat-win32` 下改为 `--fw-medium:400`（配 `--text-primary` 加深一档补层级）、`--fw-strong:700` 但只用于页面标题，其余标题降为 `--fw-medium`；CSS 里 228 处字面字重全部换成令牌，并在 `test/style-tokens.test.ts` 门禁里禁止字面 `font-weight`。
3. 品牌字标与“法律版”小标**改成矢量轮廓路径**（`Brand.tsx:34,58`，`Home.tsx:343`）：品牌标识不应依赖系统字体，两端逐像素一致；同时删掉 `textLength` 挤压。
4. 字号、行高令牌不按平台改（`tokens.css:228-261` 不动）；用了随包字体后度量一致，不需要 Windows 单独调字号。

**D. DPI 与图标**
1. 图标线宽按物理像素对齐：`Icons.tsx:6` 改为 `vector-effect="non-scaling-stroke"` + `stroke-width: var(--icon-stroke)`；`--icon-stroke` 在启动时与 `matchMedia("(resolution: …dppx)")` 变化时按 `max(1, round(1.4 * dpr)) / dpr` 计算（1x→1、1.25x→1.6、1.5x→1.33、2x→1.5 CSS px），使线宽恰好是 1～3 个整数物理像素（图形位置仍会有抗锯齿，但不再整体发灰）。图标显示尺寸统一用 16 / 18 / 20 三档，不出现 17、19 这类在 1.25x 下落到小数的尺寸。
2. 查掉半像素定位（如 `styles-materials.css:65`），在样式门禁里禁止 `.5px`。
3. 不用 `--force-device-scale-factor`，保持 Electron 缺省的按显示器 DPI。

**E. 滚动条**：在令牌层为 `html.plat-win32` 统一定义细滚动条——`::-webkit-scrollbar { width: 10px; height: 10px }`、`::-webkit-scrollbar-button { display: none }`、轨道透明、滑块 `border: 3px solid transparent; background-clip: padding-box; border-radius: 999px; background-color: var(--border-strong)`，悬停加深；`scrollbar-gutter: stable` 只留给确实需要防跳动的列表（`styles-deliverables.css:30`、`styles-start.css:129`），从 `.main` 上去掉（`styles-settings.css:203`）。效果接近 macOS 覆盖式滚动条。

**F. 验证**：Windows 实机在 100% / 125% / 150% / 175% 四档各截首页、方法库、Chat、登录页，与 Mac 同页并排比对；`style-tokens` 用例加“字面字重为 0、半像素为 0”。

## 题 2：首页“先选事项”

### 2.1 现状交互（截图 6）

- **发送键禁用的条件**：`canSend = !busy && !!matterId && (goal 非空 || 选了场景)`（`src/components/Composer.tsx:112`）；没选事项时 `blockedReason = "先选事项"`（`:113`），并**以文字形式摆在发送键左边**的 `.send-hint`（`:233`），发送键 `disabled`，悬停与读屏也说“先选事项”（`:234`）。快捷键同样被拦（`:154`，只在 `canSend` 时提交）。
- **什么时候会出现**：首页加载事项后，若有未结事项会自动选“上次用过的事项”或第一个（`src/pages/Home.tsx:162`、`:497-508`）。所以“先选事项”**几乎只出现在新用户（零事项）或事项全部结案时**——恰好是第一次用产品的那一刻。截图 6 就是：侧栏写“还没有事项，新建一个”，输入框下托盘写“选择事项”，发送键旁再写“先选事项”，三处说同一件事。
- **选择 / 新建流程**：托盘第一个芯片“选择事项 ▾”（`Composer.tsx:241-245`）打开事项菜单，底部有“+ 新建事项”（`:395-404`）→ `NewMatterDialog`（`src/components/NewMatter.tsx`，宽弹窗，事项类型、名称（唯一必填，`:55`）、委托人、对方、我方立场、阶段、处理方式等十余项）→ 建好后首页选中新事项（`Home.tsx:479-490`），**律师写好的任务描述还在，但要再点一次发送**。
- **已有的“延后执行”先例**：拖文件进来但没选事项时，组件会先存住文件、弹出“N 份文件放进哪个事项？”，选好或“用这些文件新建事项”后自动导入（`Composer.tsx:96-110`、`:296-318`）。场景卡的开始面板也允许 `matterId = null`、在面板里新建（`src/components/ScenarioStart.tsx:44`、`src/lib/scenarios.ts:1798`）。
- **死代码**：`Home.tsx:233` 的 `submit()` 里已有 `if (!matter) return setNewMatter(true)`，但因 `canSend` 要求 `matterId`，这条路径永远走不到。

### 2.2 业务约束

任务必须归属一个事项：材料、代号替换、客户授权（D-216 在事项第一次用 AI 时记录）、处理方式（一般 / 敏感 / 不上云）和成果都挂在事项下，事项是保密边界（D-203）。所以**不能**取消归属，只能把“选事项”从“发送前的拦截提示”变成“发送时的一步确认”。

### 2.3 方案比较

| | A. 发送时就地归属（推荐） | B. 首个任务自动建事项 | C. 输入框顶部内嵌事项选择 |
|---|---|---|---|
| 做法 | 有任务描述就能按发送；没选事项时，**在托盘的事项芯片处弹出锚定浮层**“这件事放进哪个事项？”：上面列近期事项，下面一行“新建事项「<由描述预填的名称>」”，展开即是精简表单（名称、我方立场、处理方式三项，其余“更多设置”进完整弹窗）；选定或建好后**自动接着发起这条任务** | 零事项时按发送，系统用描述生成名称、默认立场 / 处理方式建事项并直接发起 | 没选事项时输入框上方出现一行“事项：[选择 ▾] [新建]”，必须先点 |

**推荐 A**，并对零事项的新用户做一处增强：浮层直接展开“新建事项”精简表单（名称已按描述预填，例如“股权转让协议审查（受让方）”的规则抽取，不调用模型），一个主按钮“建好并发起”。这样首次使用从“看提示 → 找芯片 → 开大弹窗 → 填表 → 回来再点发送”五步变成“写描述 → 发送 → 确认三项 → 发起”。

### 2.4 A 方案的具体改法

### 3.3 根因（“首次登录成功后没有优先进入带上手指南的 Work 首页”）

1. **落点错**：除“从备份恢复”外，所有激活路径都写死落到 `#/welcome`（备份页），不是 Work 首页（`Activate.tsx:146,205,365,957,1000`）。新用户第一眼看到的是“恢复包、恢复码、备份位置”——在还没有任何案卷时最不需要的事。
2. **承诺落空**：备份页写着“进入首页后，会用一分钟带你认识事项、发起任务、复核成果和期限提醒”（`Welcome.tsx:48`），但讲解已不自动弹出（`App.tsx:274`），进首页后什么也没发生。
3. **清单在首屏以下**：清单排在场景列表之后（`Home.tsx:429`），且缺省只有一行。截图 6（Windows 150%、零事项）首屏里根本看不到清单，只看到右侧滚动条；截图 1、8 的 Mac 大窗口才露出底部一行。
4. **三条提示抢同一刻**：顶部“还没有生成恢复包…去完成 / 明天提醒”（`App.tsx:226-233` 的恢复提醒），输入框旁“先选事项”（题 2），底部清单“下一步：新建第一个事项”。新用户不知道先做哪件。
5. **状态只在本机**：清单与讲解状态在 `localStorage`、进度在本机内核，云端不知道“这个人上手过没有”，所以换电脑无法区分“新律师”与“老律师的新电脑”。

### 3.4 重新设计的 Onboarding

**路径**
1. 激活 / 注册 / 批准 / 自动登记成功 → 一律落到 **Work 首页**（`waitForActivated` 的 landing 改成 `#/`，`Activate.tsx:146,205,365,957,1000` 五处）。“正在打开…”过渡卡（截图 3）同时说明这一步在做什么，不留大片空白。
2. 首页首访进入“上手态”：清单**移到输入框正上方并缺省展开**（替代字标下方的留白），四步改成“建事项 → 加材料 → 发起任务 → 复核成果”，第一步的“去做”与题 2 的“发送时就地归属”合并——律师直接在输入框写任务、按发送即可完成第一步。
3. 备份不再是开通后的拦截页：改为清单之后的第五项“备份这台电脑”，**在第一个事项有了材料后**才点亮（之前没有可丢的数据）；顶部恢复提醒在同一条件下才出现。`/welcome` 页保留为“设置 · 备份与安全”的深链，不再作为落点。
4. 聚光讲解不自动弹出（维持现状），删除 `Welcome.tsx:48` 的承诺文字；清单上保留“看看界面”。
5. 清单收起后，头像菜单“上手指南”同时恢复清单显示（现在只开讲解）。

**状态机**（按“账号 × 电脑”）

```
账号级（云端）: new ──首个任务出成果──▶ graduated        （dismissed 可在任何时刻设置）
电脑级（本机内核）: fresh ──看过首页上手态──▶ guided ──建事项──▶ has_matter ──加材料──▶ has_material
                     ──发起任务──▶ has_run ──复核成果──▶ done；  backup_ready 独立标记（有材料后才提示）
```
- 账号级 `new`：完整新手版（四步 + 备份）；账号级 `graduated` 但电脑级 `fresh`（老律师新电脑）：**新电脑版**三项——“这台电脑的事项与材料独立保存”“从备份恢复（如有）”“选备份位置”，不再叫他“新建第一个事项”。
- 完成判定继续以真实数据为准（沿用 `guide.progress`），不靠点击。

**存储位置**
- 账号级：云端账号资料加一个字段 `onboarding: { version, graduated_at, dismissed_at }`，只存时间戳，不含任何案卷信息；登录时随账号状态下发。
- 电脑级：从 `localStorage` 挪到本机内核偏好表（按账号档案分开，与 D-294 一致），避免清缓存后重复弹出，也让内核能据此决定是否发恢复提醒。

**角色差异**
- 个人律师：四步 + 备份。
- 律所管理员（创始人）：四步之前加一组“团队”卡片：邀请同事、设席位、本所范本、委托合同 AI 条款声明（深链到控制台 / 设置），可整组跳过。
- 普通成员：四步 + 备份；首屏加一句“事项内容只在这台电脑，管理员看不到内容”。
- 从备份恢复：不进上手态，首页提示“已恢复到 <时间>”。

**截图 7“缺乏美学”的具体原因**
1. 底栏左侧空、四个控件（描边胶囊、模型、两段灰字、圆形键）全部挤在右侧，视觉重心偏右下，左下角一大块空白。
2. 「回车发送 · Shift + 回车换行」是一整段灰字夹在模型与发送键之间，比控件本身还宽。
3. 适用范围说明与「了解更多」放在**输入框边框内部**的第二、三行，输入框底部变成三层（控件 / 说明 / 了解更多），框体被撑高；`<summary>` 缺省是块级，`display:inline` 只加在 `details` 上，于是「› 了解更多」单独掉到一行（截图 7、5 都是）。
4. 深度思考的描边 + 空心圆点像表单单选，与 Work 的运行模式胶囊不是一种语言；「K3 ▾」又是第三种（无边框文字按钮）。
5. 生成中发送键（36px 圆）换成「■ 停止」胶囊（约 80px，`styles.css:641`），控件组整体左移一截，提示文字跟着跳。
6. 空态（截图 7）标题与示例在上半屏居中，输入框钉在底部，中间大片空白；Work 首页则是输入框居中——两个入口的空态布局不一致。

**重设计建议（Work 与 Chat 用同一个输入框组件）**
- 抽出共用组件 `ComposerFrame`（`textarea` + 底栏左槽 / 右槽 + 发送 / 停止 + 框下附属区），Work 与 Chat 都用它；输入框样式只留在 `styles-composer.css`，删除 `styles.css:231-270、651、874、1844-1847、1882-1883` 中的重复规则。
- **发送键统一为“回车发送、Shift + 回车换行”**（Work 有“先给我看计划”在发起前兜底，误发成本可控）；两页都**删除**发送键旁的提示文字，改放在发送键悬停提示里，首次使用时在占位符末尾提示一次。若坚持 Work 用 ⌘ / Ctrl + 回车，也只放进悬停提示，不常驻。
- 底栏：左槽放“模式类”开关——Work 是「+」与运行模式，Chat 是「深度思考」，样式统一为无边框胶囊 + 线性图标，开启时用强调色底；右槽只放模型与发送。
- 模型：两页同一种触发器「K3 ▾」。只有一个可选模型时也保留同样的字样与箭头，点开说明“由律所统一配置，辅助步骤用 K2.6”，不要一个带箭头、一个不带；或两页都在只有一个模型时整体隐藏。
- 停止：保持 36px 圆形，图标换成方块，不带文字，悬停提示“停止（Esc）”，生成前后控件不位移。
- Chat 适用范围说明移到**输入框外、框下居中一行**（12px），压成一句“适用于一般法律问题；具体案件请到事项里发起 · 了解更多”，「了解更多」改为行内链接，点开浮层显示两段说明，不在框内展开。
- Chat 空态与 Work 首页同一布局：无对话时输入框居中、示例问题放在输入框下方；有对话后输入框落到底部。
