## 3 实机发现并已修的两个问题

### 3.1 激活后每次启动白等约 4.2 秒（P1，登记性能的主要来源）
- 现象：注册点“注册并继续”到进入工作区 **7.1 秒**（“正在注册…”46 ms → “正在打开…”1.69 s → 进入 7.12 s）；之后每次打开应用，内核启动日志 `KERNEL_BOOT_PHASE lawdb` 都是 **4,236 / 4,254 / 4,246 ms**（待激活内核同一段 59 ms），紧跟一条 `KERNEL_PENDING_WORKSPACE_LEFT reason=perm`；`MAIN_KERNEL_READY` 约 4.8 s。
- 根因：激活后内核启动时**同步**删除待激活占位工作区（第 54 批为 Windows 加的 `rmSync` 5 次线性退避重试）；Windows 上该目录删不掉（EPERM），每次启动都在启动路径上把重试等满。Mac 上能删掉，所以 Mac 实测看不到。
- 修复（`b02248f9`）：启动路径只做一次改名，把占位区挪成隐藏的待删目录（失败不重试）；删除在后台异步进行（含以前留下的），失败记一条并带“挡住删除的是哪类文件”；主进程同法。启动页同时去掉写死的“第一次打开需要十几秒”。
- 实机复验（run2）：

| 指标 | 修复前（run1） | 修复后（run2，四次启动） |
|---|---:|---|
| `lawdb` 段 | 4,236～4,254 ms | 35 / 135 / 111 / 271 ms |
| 内核就绪 `MAIN_KERNEL_READY` | 4,776～4,801 ms | 729 / 916 / 890 / 1,884 ms |
| AI 可用 `KERNEL_AI_READY`（自启动） | 6,164～7,567 ms | 2,387 / 2,808 / 2,718 / 4,121 ms |
| 点击到进入工作区 | 注册 7.12 s | 新电脑验证码登录 2.54 s |
| `KERNEL_PENDING_WORKSPACE_LEFT` | 每次启动一条 | 无 |

### 3.2 换缩放后窗口铺满、回到原缩放停在左上角（P2，“Windows 启动是全屏”的另一条路径）
- 现象（run1）：100% 下记住 1440×888，150% 重开时窗口铺满整个工作区（外框 1300×696 @ −7,0）；再回到 100%，窗口 1302×697 停在左上角。
- 根因：恢复时把放不下的尺寸夹成整块工作区；位置按逻辑像素跨缩放原样恢复。
- 修复（`df520dae`）：放不下 → 回到按比例的初始尺寸居中；缩放比例变了 → 保留尺寸、重新居中（记忆里加 `scale`）；用例覆盖两种情形。实机复验见 §2。
