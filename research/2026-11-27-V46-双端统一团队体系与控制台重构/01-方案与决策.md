## D-299 模型选择：只给真的选择，选了就真的换

**事实**（A1 §1）：任务入口只列 `scopes` 含 `task` 的模型，云端内置口径 K2.6 只进问答，所以 Work 首页只剩 K3、选择器按设计不出下拉——不是界面 bug。但更严重的是：缺省路由与部署模板把 `legal/k2.6` 和 `legal/k3` **都指向 `kimi-k3.1-pro`**（`routing.ts:279`、`control-plane.example.json:25`），问答里切到“K2.6 · 更快更省”实际仍是 K3.1 Pro、按 K3.1 Pro 计费——这是“伪切换”。

**决定**
1. 内置别名改为真实映射：`legal/k3 → kimi-k3.1-pro`，`legal/k2.6 → kimi-k2.6`（缺省路由、部署模板、网关本机兜底三处同口径）。
2. K2.6 进任务入口（`scopes: qa+task`，它本来就是带 `tool_use` 的 Agent 模型、任务里的子 Agent 就是它）：Work 首页有 K3 / K2.6 两项可选，说明写实：“K3 · 最强，复杂审查与起草”“K2.6 · 更快、更省额度，适合整理与摘要”。
3. **云端判定防伪切换**：目录里若某别名的实际上游与缺省别名相同（运营配成同一个型号），该项照列但置灰，原因“运营尚未给它配置独立的模型”；控制台“模型与路由”同时出一条告警。客户端永远看不到“名字不同、实际相同”的选项。
4. 不再静默回落：内核自发调用（审查分析、独立复核、复核追问）遇到所选别名失效时**不改用 K3**，记入运行记录并明确失败、提示重新发起（A1 M3）。
5. 子 Agent 仍用 K2.6（已在选择器页脚写明“辅助步骤用 K2.6”）；用量页把这部分标为“任务辅助步骤”，不让律师以为自己选过 K2.6。
6. 同步：界面聚焦时真刷新（内核 5 秒节流）；问答的“记住所选”改走 `models.select("qa")`（与内核 `model_prefs` 统一，localStorage 只作一次性迁移）；目录信封加 `epoch`（云端路由状态重建 / 迁移时换新），客户端遇到新纪元即接受，修“云端改了客户端怎么也不变”（A1 M7）；用量页模型名与目录同口径（A1 M8）。
7. 验收：本机真实栈分别选 K3 / K2.6 发问答与任务，网关计量记录的 `alias`、`upstream_model` 与界面所选逐条对上；运营把 K2.6 改指 K3 同型号后，客户端 K2.6 置灰。

## D-300 双端统一：以 macOS 为基准，从窗口、版式、字体三处根治

**事实**（A2 §1）：
- “Windows 铺满全屏”不是最大化：初始 1440×900、最小 1080×700 都大于 1080p / 150% 缩放的工作区（约 1280×672），系统把窗口压到贴满；没有尺寸记忆。
- “Windows 有顶栏”：Windows 专用样式（`styles-window.css:18-20`）把侧栏品牌行抬进 40px 拖动条，与右上角系统控件同一条线，读成标题栏。
- “Windows 不精致”：字重 500（120 处）在雅黑下退成常规体、600（108 处）退成粗体，中英粗细不一致；品牌字标是 SVG `<text>`，落到 Segoe UI Black 后被 `textLength` 挤压；图标线宽 1.7 在 125%/150% 下落到非整数物理像素发虚。

**决定**
1. 窗口：按所在屏幕工作区算初始尺寸（约 82%×86%，夹在 960～1440 × 640～900）、居中、`show:false` + `ready-to-show`；最小 960×600 且不超过工作区；记住位置、尺寸与最大化（`userData/window-state.json`，保存的矩形与某屏工作区相交不足一半时回到居中）。默认窗口化，只在上次是最大化时恢复最大化。仍是单窗口（登录类页面与工作区同窗）。
2. 版式：删掉 Windows 分支，Mac 版式两端通用——侧栏第一行 40px 只放“搜索 + 收起”（Windows 左侧不留红绿灯也照同一位置），品牌在第二行；右上角仍是系统控件（`titleBarOverlay`，保留 Win11 贴靠）；不自绘窗口控件。
3. 字体：按平台分字体栈。Windows 随包 **Noto Sans SC 400/500/600**（`@fontsource/noto-sans-sc` 5.3.1，OFL-1.1，按字符区间切片 woff2，只在 `plat-win32` 引用，Mac 不加载），拉丁用 `Segoe UI Variable Text` → `Segoe UI`；用 `ascent/descent-override` 把纵向度量对齐到 PingFang。品牌字标、“法律版”小标改成矢量路径，不依赖系统字体。
4. 图标：线宽按设备像素比对齐（1x→1、1.25x→1.6、1.5x→1.33、2x→1.5 CSS px），去掉半像素定位；快捷键文字（⌘ / Ctrl）统一读主进程给的平台，不再用已弃用的 `navigator.platform`。
5. 验收：Windows 运行器实机截图（100% / 150%）与 Mac 同页并排；样式门禁加“字面 `font-weight` 只许令牌、禁 `.5px`”。

## D-302 首次登录落到 Work 首页，上手清单是首屏主角

**根因**（A2 §3、本机复现 `shots/before-register2/r3-landing.png`）：所有激活路径写死落到 `#/welcome`“开通完成，先做好备份”；那页承诺“进入首页后会带你认识”，而讲解早已不自动弹出；清单排在首屏以下；状态只在本机，换电脑分不清“新律师”与“老律师的新电脑”。

**决定**
1. 注册 / 登录 / 自动登记 / 批准 / 换空间成功后一律落到 **Work 首页**；`/welcome` 降为“设置 · 备份与安全”的深链。
2. 首页“上手态”：清单移到输入框正上方并默认展开，四步“建事项 → 加材料 → 发起任务 → 复核成果”，完成判定仍按真实数据（`guide.progress`）；第一步与 D-301 合流（写任务、按发送即可建事项）。
3. 备份变成第五项“备份这台电脑”，第一个事项有了材料后才点亮；顶部恢复提醒同条件出现（之前没有可丢的数据，不打扰）。
4. 状态两级：账号级 `onboarding.completed_at / dismissed_at`（云端账号字段，随 `/v1/auth/me` 下发，只存时间）；电脑级在本机内核偏好（按账号档案）。账号已上手、这台电脑是新的 → “新电脑版”三项（这台电脑的事项独立保存、从备份恢复、选备份位置），不再叫老律师“新建第一个事项”。
5. 角色差异：个人律师四步 + 备份；团队管理员前面多一组“团队”（邀请同事、席位、本所范本），可整组跳过；团队成员首屏一句“事项内容只在你的电脑，管理员看不到内容”。
6. 跳过、继续、重看：清单“×”收起即记 `dismissed`；头像菜单“上手指南”同时恢复清单与讲解；从备份恢复的不进上手态。

## D-304 设备：登录永不等批准；“批准”只在要接收团队共享事项时才出现

**三种方案的独立判断**
| 方案 | 安全 | 体验 | 结论 |
|---|---|---|---|
| 满额自动顶掉最旧的电脑 | 差：被盗号时攻击者一登录就把本人挤下线，本人还不知道；正在跑的任务被无声中断 | 好但不可控 | 不采用 |
| 满额由用户选一台退出（D-298 已做） | 好：动作可逆、本人知情、被退出的电脑如实告知是谁让它退出 | 好 | **保留为满额唯一路径** |
| 新电脑要另一台电脑 / 管理员批准 | 对“登录”而言多余：手机号验证码已是第二因素，同时登录上限 + 可见的电脑列表已覆盖盗号风险；个人账号里批准人就是本人，还会出死路 | 差：要等人 | **登录不再需要批准** |

**用户倾向（把选择权交给用户）与本判断一致；补充两点用户没说到、但决定安全边界的事实**：
1. 团队共享事项是端到端加密的，事项密钥只包给“律所根”签过的成员电脑（内核 `governance.ts:723` 明确把云端签发的电脑挡在本机设备表之外）。所以**成员新电脑由云端直接签发即可登录、用 AI、处理自己的事项**，而**接收团队共享事项**仍需律所根确认——这不是“审批登录”，而是保护团队事项不被云端伪造的电脑收走的必要密码学步骤。
2. 因此“批准”从登录路径上拿掉，降为团队共享页里一条非阻塞提示：“这台电脑还不能接收团队共享事项——请管理员在团队设置里确认”（管理员处显示“待确认的电脑”，一键确认）。

**落实**
- 云端：团队工作空间的成员新电脑也走账号签发钥直接登记（与个人账号同一路径）；上限 = 同时登录的电脑（云端套餐 / 账号设置，D-298），满额走选择卡；“退出登录”（可逆）、“移除”（这台电脑不再能用这个账号，事项与成果留在那台电脑）、“永久解绑”不单设（= 移除；账号注销另走注销流程），三者在客户端与控制台同一口径。
- 被退出的电脑：会话即时失效（2 分钟核对 + 网关拒绝即核对），正在跑的任务停在可续的状态、本地材料与成果不动。
- 团队可选安全策略“新电脑须管理员确认后才能登录”：缺省关；只给有更严设备管控要求的律所，不作为默认路径。

## D-305 个人与团队：一个人、一个账号、多个工作空间

（A3 §1～2 事实；目标架构见本节，接口契约见 `02-接口契约.md`）

**事实**：现在“账号 = 某一家租户里的一名成员”，邮箱、手机号全局唯一；个人 = 自助注册的单人租户，一发成员邀请就**悄悄永久**变成律所；一个人不能既有个人空间又在律所；个人用户界面混入“团队与离所”“管理”入口但后端拒绝；律所管理员能给自己放宽电脑上限、能重新启用被平台停用的账号（A3 R1、R2）。

**决定（统一账号 + 独立工作空间，最小改动落地）**
0. **与 A3 的差异**：A3 建议新建独立的“人”表并把邮箱、手机号、密码迁过去；本批改为“主账号即人 + 关联账号指向主账号”——对外语义相同，但**不迁移任何凭证**、旧客户端照常登录主账号、回滚无损。A3 认为团队新电脑仍须律所根批准；本批按 D-304 的密码学边界处理：批准只保护团队共享事项的密钥，登录本身不等批准。
1. **人 = 身份**：一个人以已验证手机号（以及邮箱密码）登录，登录得到的是“人”的会话；**工作空间 = 这个人在某个租户里的成员身份**（沿用现有账号记录：租户、成员标识、角色、证书、席位、用量账本都按它，不动底层编号）。同一个人可有：至多 1 个个人空间 + 若干团队空间。
2. **个人空间**与**团队空间**是工作空间的显式类型（租户 `kind: personal | team`，不再按形状推断、不再悄悄转换）；存量按现有 `personal` 标记一次性定型。
3. 路径：
   - 注册 → 个人空间（现状）。
   - 加入团队：管理员发邀请（团队设置或控制台，网页即可，不再要求在创始电脑上）→ 被邀请人用自己的手机号登录接受 → 多出一个团队空间（已注册的人不必另开账号；未注册的人注册时直接进团队）。
   - 个人升级为团队：个人律师在“设置 · 账号”点“把工作室升级为团队”→ **就地升级**（同一工作空间，显式二次确认、记审计、不可逆），事项、成果、电脑原地不动，个人事项仍只属于本人；之后才能邀请同事。取消“发第一张成员邀请就悄悄变团队”。（采纳 A3 §4.2；不另建新团队空间——独立律师长成小团队是更常见的真实路径，另建空间反而要来回切换。）
   - 退出团队：成员发起，进入离所交接（现有 Offboarding）；管理员移除成员同理。团队空间在这台电脑上的数据按离所交接处理，个人空间不受影响。
4. 客户端：侧栏底部账号区显示当前工作空间（个人：“王律师 · 个人”；团队：“某某律师事务所 · 团队”），点开即切换——底层就是第 68 批账号档案（每个空间独立目录、数据库密钥、内核进程），切换用当前会话换一次性票据免再输密码 / 验证码。
5. 功能边界：
   - 个人空间：事项、成果、方法、用量、套餐、电脑、账号；**没有**成员、邀请、团队策略、离所交接。“本所范本库”改名“我的范本库”。
   - 团队空间（所有成员）：团队名称与身份标识、我的用量、团队范本（现为本机，名实相符地标“这台电脑上的团队范本”，同步留待后续）、团队共享事项（现有端到端加密，按需开启）、离所交接。
   - 团队空间（管理员）：成员（邀请、角色、停用、移除、席位）、套餐与席位、团队用量、电脑（含待确认）、团队策略。
6. 权限与隔离：云端每个会话 / 设备接口按“当前工作空间”的租户断言归属；平台停用优先于团队启用（`disabled_by`）；团队侧电脑上限不得超过套餐；个人空间不开放团队写接口；团队管理员**结构上**读不到成员事项（案卷只在成员电脑；团队共享只对事项成员开放），控制台写明这一点。补越权用例：跨工作空间读写、团队管理员读成员个人空间、切换后旧票据重放、被移出团队后旧会话。

**现阶段不做**（避免过度设计）：多级部门 / 用户组、按事项的细粒度 ACL（团队共享已按事项成员授权）、SSO / SCIM、团队范本云同步、个人事项迁入团队、跨团队共享、计费子账户。

## D-306 云端控制台：以“人”和“组织”两条主轴

（A3 §3 IA-1～IA-10）
1. **客户**分两类、两种版式：个人客户（一行 = 一个人的个人空间：套餐、用量、电脑、到期）与团队客户（组织：成员数 / 席位、套餐、用量、到期）。类型来自显式字段，不再推断。
2. **组织详情**是团队客户的中心：概览、成员与席位（邀请、角色、停用、移除、席位分配 / 收回）、电脑（同时登录、待确认）、用量与账单、操作记录。
3. **用户**（原“账号”）：一行 = 一个人，列出其个人空间与各团队身份；用户详情集中“登录诊断、身份、工作空间、电脑、会话”。代建账号只留一个入口（在组织详情“邀请成员”）。
4. **电脑**：保留为跨客户查找入口，页头写明范围；日常操作在组织详情与用户详情里。
5. 平台管理员与团队管理员：平台看全部客户的元数据与用量（不含任何案卷）；团队管理员只在“本团队”分区看本团队；个人用户只有“我的”（用量、电脑、账号与安全），没有“本所”。
6. 修 A3 R1～R5：团队侧上限 ≤ 套餐、`disabled_by`、合伙人只能吊销非管理员、停用同时释放席位（可选保留设备）、重置码发给本人而非管理员明文。
