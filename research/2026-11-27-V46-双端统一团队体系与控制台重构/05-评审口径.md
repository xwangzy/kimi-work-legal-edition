# 05 独立评审口径（第 72 批）

> 给评审代理用：只依据截图、运行日志、调用记录与源码事实打分，**不读实施者的自评与进度文件**。开发与评审由不同代理执行。

## A. 页面设计评分（每页单独打分，5 分制，保留一位小数）

| 维度 | 看什么 | 4.0 的门槛（举例） |
|---|---|---|
| 视觉美学 | 精致感、留白节奏、对齐、色彩克制（黑白灰 + Kimi 蓝点缀）、圆角 / 阴影 / 描边一致 | 没有明显挤压、错行、粗细失衡、发虚 |
| 信息架构 | 视觉重心是否就是这页要律师做的那件事；层级是否一眼可读；无重复信息 | 主任务一眼可见，次要信息降级，不出现同一信息两处 |
| 功能易读性 | 文字是否人话、短、准；状态是否自解释；认知成本 | 不需要读说明就知道下一步；无内部术语 |
| 交互体验 | 操作路径长度、反馈（加载 / 成功 / 失败）、异常与空态 | 主操作 ≤ 2 步；失败可恢复且告诉原因 |
| 设计一致性 | 与同产品其他页、Mac 与 Windows 同页、浅深两色同页 | 同组件同样子；双端同版式 |
| 工程呈现 | 字体渲染（Windows 中文字重层级是否成立）、缩放（150%）、截断、溢出、滚动条 | 无截断（除有意省略号且有悬停全文）、无溢出、文字不糊 |

**综合分 = 六项算术平均；每页必须 > 4.0**（不得用整体平均掩盖单页）。低于 4.0 的页面给出“必须改的项”清单（具体到元素与改法）。

## B. 功能与业务逻辑评分（每项功能单独打分）

| 维度 | 看什么 |
|---|---|
| 功能完整性 | 核心路径真实可用（有真实运行证据：日志、调用记录、截图序列） |
| 业务合理性 | 是否符合个人律师 / 律所真实场景（案卷保密、事项为中心、团队协作边界） |
| 产品易用性 | 路径自然、步数少、默认值合理 |
| 功能必要性 | 有无冗余功能、过度设计 |
| 架构合理性 | 数据模型、权限、系统边界清晰 |
| 工程可靠性 | 状态一致、异常恢复、并发与断网 |
| 商业化成熟度 | 个人与团队客户的使用与采购需求是否被满足 |

**每项功能综合分 > 4.0。一票否决**：数据泄露、越权访问、跨租户 / 跨工作空间数据混淆、错误计费、核心业务退化——出现任一条，该功能不论其他分数直接不通过。

## C. 证据要求

- 每个分数附依据：截图文件名、日志行、用例名或 文件:行。
- 没有真实运行证据的功能标“未验证”，不打通过分。
- Mock、静态数据、伪交互、未经验证的成功状态一律不算。
