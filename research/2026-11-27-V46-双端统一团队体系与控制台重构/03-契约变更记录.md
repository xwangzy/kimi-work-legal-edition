## 云端（impl-C，11-27）

| # | 契约原文 | 改成 | 理由 |
|---|---|---|---|
| C-1 | §4“`/v1/auth/me` 与登录应答带 `onboarding: { completed_at, dismissed_at }`” | 正式位置是 **`person.onboarding: { completed_at, dismissed_at }`**（登录 / 注册 / 切换 / `/v1/auth/onboarding` / `/v1/auth/me` 都带）；另把这两项**并进**现有 `onboarding` 对象（字面兼容；`/v1/auth/me` 的 `onboarding` 为 null 时不并） | 登录应答的 `onboarding` 早已是“这台电脑该做什么”（`{ state, tid, … }`），同名会覆盖设备状态 |
| C-2 | §3.4 成员行“`devices: {signed_in, limit}`、`seat`” | 新增 **`devices_summary: { signed_in, limit }`**；`devices` 仍是逐台清单；`seat` = `{ sid, assigned_at } \| null`（`seat_used` 布尔保留） | `devices` 是第 71 批控制台在用的逐台数组，改形状会打坏现有页面 |
| C-3 | §2.1“应答的会话属于 `last_workspace`（存在且可用时）否则主账号” | 先看**签名的电脑**：是这个人某个工作空间的已登记电脑 → 进那个；再 `last_workspace`；再主账号（可用时）；再第一个可用的。主账号被停用而关联账号可用时，凭证照常认证、进可用的那个；全部不可用时与原来同样回答 | 这台电脑上的档案就是那个工作空间（relogin 只填验证码时尤其如此）；凭证在主账号上，团队把主账号移出不该让这个人整个登不上 |
| C-4 | §3.3“来源限流 10 次 / 10 分钟” | 只计**核对失败**（码错、过期、已用、撤销）：同一来源 10 分钟内 10 次失败即 429；核对成功不计 | 限流是防枚举；成功接受不是枚举，计入会让同一办公室网络里正常入职的人被挡 |
| C-5 | §3.1 审计“记原名、新名、席位变化” | 审计明细记 `seats_from`、`seats_to`、`renamed`（0/1）、`trial`（0/1），不记名称原文 | 审计流水 `detail` 按设计只收数字（`audit-log.ts` validAuditDetail，防止审计链里出现客户文本）；新名就是租户当前名 |
| C-6 | §3.4“重置码改为给成员手机号发重置短信” | `POST /v1/firm/members/<aid>/reset-code` 应答 `{ ok, channel: "sms", sent: true, phone_masked, expires_in_s }`；成员没绑手机号 → 409 `phone_unbound`；dry-run 部署只记录、**不回码**（回给管理员就等于明文）；本人在登录页“忘记密码”用 `purpose: reset` 的验证码 | 契约没写无手机号与 dry-run 的情形 |
| C-7 | §3.4 `POST /v1/teams/leave`“应答带切回的工作空间” | 没有别的可用工作空间 → 409 `no_other_workspace`（不退出）；唯一管理员 → 409 `last_admin` | 契约没写；退出后无处可去等于把自己锁在外面 |
| C-8 | §5“依据：计量记录的调用用途字段，没有就按 `alias === legal/k2.6 且 kind === task` 近似” | 计量记录没有用途字段，账本字段是 `qa` 布尔：按 `alias === "legal/k2.6" && qa === false` 近似；逐请求记录加 `aux: boolean`、`purpose_label: "任务辅助步骤" \| null`（`/v1/firm/usage/records`、设备 `/v1/quota/usage`）；`by_model` 汇总不拆。已知偏差：律师在任务入口主动选了 K2.6，它的调用也会被标“任务辅助步骤”——要准确须网关 / 内核在请求上带用途（后续） | 照契约的近似口径。**主会话否决，已撤；准确标注需请求带用途，留待后续**（逐请求记录不再有 `aux` / `purpose_label`，`by_model` 照实按模型汇总） |
| C-9 | §8“`seat.manage` 或现有收回席位所用权限” | `seats/<aid>/assign` 用 `device.revoke`（与收回席位同一权限）；`invites` 用 `account.manage`；`upgrade-team` 用 `tenant.manage` + 危险操作复核；`people*` 用 `account.read` | rbac.ts 没有 `seat.manage`，按“不新增角色 / 权限名”取现有的 |
| C-10 | （未写）运营 `POST /v1/ops/accounts` 往个人工作室代建成员 | 409 `upgrade_required` | 个人空间“至多本人一名成员”的不变式；否则 kind 显式后会出现多人的个人空间 |
| C-11 | （未写）个人空间的 `PUT /v1/firm/cap`（月度上限） | 按 §3.4“个人空间对 `/v1/firm/*` 写一律 403 `team_only`”同样 403 | 照契约字面；**控制台“我的工作室”若还给个人用户月度上限入口会被拒**，请控制台按 `workspace.kind` 收起或改走设备签名 `PUT /v1/quota/cap` |
| C-12 | §2.1 `workspace` 形状 `{ aid, tid, kind, name, role }` | 团队另带 `member_device_policy`；`/v1/auth/me` 另带 `device_issuer`（本会话所绑电脑证书的签发者 `firm_root` / `account_ca`，供 §7 内核状态） | §7 需要，旧字段不变 |
