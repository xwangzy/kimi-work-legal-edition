- **页面上不显示**负责人、协作范围或成员。`Matter.my_role`（`api.ts:320`，`owner | editor | viewer`）只被三处用来**拦动作**：

- 内核角色是 `owner / editor / reviewer / issuer / viewer`（`kernel/src/api/index.ts:4540`），律师端没有任何角色文案映射。

### 3.2 团队共享事项怎么区分（建议）

原则：**团队空间里多数事项仍是个人的**（D-305：默认只属于创建者），共享是少数——给少数一个记号，不给多数加噪音；**不分组**（律师按“最近在办”找事项，分组会把同一时期的事项拆到两处，侧栏 8 条的配额也会被切碎）。

| 位置 | 做法 | 理由 |
|---|---|---|
| 侧栏事项行 | 标题右端一个 14px 线性“两人”图标（灰 `--text-3`，不用蓝），`sr-only` 读“团队共享”；状态点仍在左 | 与 Kimi 侧栏“已共享会话”同一种克制记号；不挤标题 |
| 事项列表页 | 名称后加一枚灰标签 `tag-gray`“团队共享”（与“已结案”同一种）；悬停串里的“协作：…”删掉（重复） | 列表页有横向空间，文字比图标清楚 |
| 输入框事项芯片 / “放进哪个事项？” / 芯片菜单 | 副标题（`menu-desc`）前缀“团队共享 · ”；芯片本身只加同一个小图标 | 发起任务前知道材料会到同事电脑上 |
| 全局搜索事项行 | 副标题前缀“团队共享 · ”（界面拼，不改内核） | 同上 |
| 筛选 | 事项列表页搜索框旁加一个两段切换“全部 / 团队共享”**仅当**存在团队共享事项时出现 | 量大时才需要；个人空间永不出现 |

个人空间（`workspace kind = personal`）里以上记号一律不出现（个人空间不可能有团队事项）。

### 4.2 加人选择器的数据缺口

1. **律师可读的同事目录不存在**：`team.members.list` 只给管理员 / 合伙人；`members.roster` 内核硬性 `requireFirmAdmin`。负责人（通常是普通律师）建团队事项时拿不到“可以加谁”。
2. **两套身份**：云端成员是 `aid`，内核事项成员是 `user_id`（`usr_…`，见 `evidence/qa3/a-members-add-bing.json`）；界面不能自己拼。
3. **“对方电脑能否接收”只有本人能看到自己的**（`team.deviceShare.status`）。内核加人时按“对方在用、经律所根确认的电脑”补包裹，返回 `devices_wrapped`（0 = 对方现在没有能接收的电脑，`kernel/src/api/index.ts:4560`、`:4602`）——这是事后才知道。

→ 建议内核补一个**律师层只读目录**（例：`team.directory` 或 `matters.colleagues`）：每人 `user_id、name、role（律师 / 助理 / 合伙人 / 管理员）、can_receive（有至少一台在用且经律所根确认的电脑）、is_me`；`matters.members.list(matter_id)` 回事项成员 + `matter_role` + `can_receive` + `added_at`。两者都不带手机号（律师层不需要）。

### 4.4 事项角色怎么叫

内核有 5 个事项角色（`owner / editor / reviewer / issuer / viewer`），律师端一个都没映射。**最小方案只露 3 个**：
- `owner` → **负责人**（可加人、移出、结案删除；已有用语：`MatterLifecycle.tsx:106`、离所交接）；
- `editor` → **一起办**（默认；能加材料、发起任务、改成果）；
- `viewer` → **只看**（已有用语“只读成员”，`Reminders.tsx:574`）。
`reviewer / issuer` 先不露（签发流程另有“复核 / 签发”入口；混进来会让律师在加人时多想一层）。

## 5. 管理员“开通同事之间同步”

### 5.1 现在在哪、几步

“同事之间同步”在产品里由**两件事**合成（`pages/Connections.tsx:309`、`lib/relay-text.ts:61-68`、`components/TeamShare.tsx:47`）：
- **A. 共享服务已部署**（`relay_configured`，内核 `api/index.ts:3421` = 部署里配置了中继且接了控制面）——律所管理员**不能**在客户端开，是中软开通 / 部署项；没配时 `relay.status.blocked = "not_configured"`，`TeamShare` 记作 `relay=false`，所有句子写“所内还需开通同事之间同步”。
- **B. 本所规则允许**（签名策略 `share_relay: "allow"`，`evidence/qa3/a-policy-draft.json`）——没允许时 `blocked = "not_allowed"`，一行“本所没有开启同事之间同步（团队事项仍可经律所共享文件夹同步）”。

**B 的入口**：设置 → 团队 → 团队策略 →（往下滚过“生效策略 / 许可 / 离线可用…”）→ “起草律所策略”表单的“放宽项”第 3 个勾选“同事之间可以经中软同步团队事项（加密，中软打不开）”（`pages/Connections.tsx:1682-1760`，勾选在 `:1721-1728`）→ 生成草稿 → 草稿卡“核对无误，确认”（`:1626-1630`）→“发布”→ 原位二次“确定发布”（`:1632`）。
截图：团队策略区 `evidence/after-team-r5/c10-team-policy.png`、`c10-team-policy-960.png`（起草表单在更下方，未截到）。

**步数**：滚动找到表单 1 + 勾选 1 + 生成草稿 1 + 确认 1 + 发布 2 = **至少 6 步**，且：
- **起草表单的初值是最严缺省，不是当前生效值**（`:1683-1689` 全部 `useState` 默认值）——管理员只想开同步，若当前已放开“敏感事项用通用 AI”“问题报告直接发客服”，不重新勾一遍就会**静默收紧**另外几项。这是本批要顺手修的陷阱。
- 规则**有效期 ≤ 30 天**（`:1733`），过期按最严回退（`lib/relay-text.ts:64` `policy_fallback`）——同步会随之暂停；需要确认内核 / 控制面是否自动续签，否则“开通”是一个每月要重做的动作。
- 用语是“草稿、放宽项、发布、有效期”，属管理员层，可以保留，但“开通同事之间同步”这件事本身不该要求管理员理解策略文档。

**团队设置里没有一处直接写“同事之间同步：已开通 / 未开通 [开通]”**；管理员只能从成员团队页那句“所内还需开通同事之间同步”（`lib/workspace.ts:196`、`:200`）反推。

### 5.2 建议放在哪、几步

在 设置 → 团队 → **团队策略** 第一行（“成员新电脑”之前或之后，同一种 `SettingRow`）加一行 **“同事之间同步”**：
- 已开通：`已开通 · 团队共享事项加密后在同事电脑之间同步，中软打不开`（灰字，无按钮）。
- 规则未允许（B 缺）：说明一句 + 次按钮 **“开通…”** → 弹窗（标题“开通同事之间同步”，三条后果：①团队共享事项的内容加密后经中软转送，中软打不开；②本机删除事项不会删除中软上的加密副本，关闭后已存的副本保留到律所停止使用（沿用 `:1724-1726` 原句）；③没更新软件的电脑会暂按最严规则运行（沿用 `:1737`））→ 主按钮“开通”。
  背后由客户端一次完成“以**当前生效规则**为底稿只改 `share_relay` → 本机确认签名 → 发布”；律所版（2 人门槛）时按钮文案变“发起开通（还需 1 位管理员确认）”，草稿出现在原“待确认的规则草稿”里给第二位管理员。
  **管理员 2 步**（开通… → 开通），律所版另一位管理员 2 步（确认 → 发布）。
- 服务未部署（A 缺）：`未开通 · 需要中软为本所开通共享服务` + 文字链“联系客服”（不给按钮，免得点了没用）。
成员团队页、管理员确认结果里的“所内还需开通同事之间同步”句子不变（`shareReadyText`），只是现在管理员有了一个看得见的落点。

### 7.3 “对方电脑还不能接收”怎么显示

- **同一个数据**：目录 / 成员接口回的 `can_receive`（有至少一台在用、经律所根确认的电脑）。
- **同一套句子**：`lib/workspace.ts` 的 `shareReadyText` 加 `kind: "peer"` 分支（不另起句库，第 72 批评分 C19 的教训）：
  - 列表 / 选择器短句：“电脑还不能接收”；
  - 成员行长句：“电脑还不能接收：请他在“设置 → 团队”里申请，管理员确认后自动收到”；
  - 所内没开通同步时，所有人都收不到——**不逐行重复**，只在列表上方一行说（避免同一信息出现 n 次）。
- **语气**：灰色正文 + 空心小圆点，不用橙色（这不是负责人要处理的事，橙色留给“等你确认”）。
- **加人不拦**：能接收与否都可以加，内核之后自动补发（`kernel/src/api/index.ts:4560`、`:4602`）。

### 7.4 管理员开通入口

见 5.2：设置 → 团队 → 团队策略首行“同事之间同步”，三态（已开通 / 开通… / 需要中软开通），管理员 2 步；起草表单改为以当前生效规则为底稿。另在两处给管理员一个文字链“去开通 →”：事项成员页的“所内还没开通”说明、成员团队页 `TeamShare` 那句“所内还需开通同事之间同步”（仅管理员可见）。

### 7.5 侧栏 / 列表 / 搜索的标识
