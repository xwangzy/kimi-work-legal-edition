# 02 接口契约（第 73 批）

> 三方并行实施（云端 W1、内核 W2、律师端 W3）的共同约定。实施中发现契约不合理，先在 `03-契约变更记录.md` 写一行再改（写清谁改、为什么），不要各改各的。
> 编号口径：内核用户编号 `usr_<firm_slug>_<member_slug>`（`packages/kernel/src/identity.ts:19`）；云端成员标识 `member_slug`（账号上的成员标识）。

## 1 云端（W1）

### 1.1 `GET /v1/team/roster`（新）
- 鉴权：账号会话（`x-kwl-session`）+ 设备签名，与 `/v1/quota` 同一口径；当前工作空间须为**团队**，个人空间 403 `team_only`；会话所属账号须有效（停用 / 移出 → 401 同现有口径）。
- 应答：`{ ok: true, tid, members: [{ member_slug, name, role: "admin"|"partner"|"lawyer"|…（与 /v1/firm/members 同一角色口径）, status: "active"|"disabled"|"removed"|"left" }] }`——**不含**邮箱、手机号、账号编号（aid）、设备信息；按姓名排序；含已移出 / 已离开的人（status 标明），便于本机把事项成员标“已离开团队”。
- `/v1/meta.features` 追加 `team_roster`；控制台不动。
- 用例：成员 / 管理员都能读；个人空间 403；不含敏感字段；跨租户不可读；被移出后 401。

### 1.2 共享中继纳入标准部署
- `cloud-repo/template/deploy/config/relay.example.json`（中继角色配置，与其它服务同证书路径）、systemd `kwl@relay`、端口 **8446**；`install.sh` / `upgrade.sh` / `rollback.sh` / `healthcheck.sh` / `verify-capabilities.sh` 纳入（verify 核对中继健康与 `/v1/meta.features` 含 `team_roster`）；`client-release-spec.example.json` 加 `relay_base`（与 `relay_backup_pins`）；运维手册 v1.8.0 一行（升级步骤、端口、回滚）；部署手册防火墙放行 8446。
- 本机栈 `scripts/stack-local.mjs`：同样起中继（端口 base+6，例如 18746），`client.env` 写 `ZR_RELAY_BASE`（回环开发形态不需要钉住）。
- 云端版本 1.8.0（package.json、运维手册、`/v1/meta`）。

## 2 内核（W2）

### 2.1 `team.roster`（新，律师可调）
- 参数：无。应答：`{ available: boolean, reason?: "personal_workspace"|"offline"|"not_supported", members: [{ user_id, member_slug, name, role, status, can_receive: boolean, is_me: boolean }] }`。
- 经出站闸门调 `/v1/team/roster`（闸门白名单 + `docs/privacy/egress-paths.json` 登记）；`can_receive` = 本机设备表里这位成员有至少一台有效的律所根签电脑（自己用 `kernel.status.device_issuer === "firm_root"`）。离线时回本机缓存（最近一次成功的名单，`available:false, reason:"offline"`）；个人空间 `available:false, reason:"personal_workspace"`。
- 缓存写盘要登记写盘面（`docs/privacy/residency.json`）。

### 2.2 `matters.create`（扩展）
- 新参数：`collab_scope?: "personal"|"team"`（缺省 personal）、`members?: [{ user_id, matter_role: "editor"|"viewer" }]`（只在 team 时有效）。
- 选 team 的前置（任一不满足 → `DomainError("team_scope_unavailable", <律师能看懂的一句话>, 409)`）：当前是团队空间；这台电脑的证书由律所根签发；事项不是“客户要求不上云”（L3b）。
- 建事项与加人在**一个事务**里完成（任一成员不在名单 / 状态非 active → 整体失败 `member_not_in_team`）；加的人存名单里的真实姓名。

### 2.3 `matters.members.list`（新）
- 参数 `{ matter_id }`；须有事项读权限。应答：`{ matter_id, collab_scope, my_role, is_owner, members: [{ user_id, name, matter_role, can_receive, departed: boolean, is_me }], sync: "ok"|"not_configured"|"not_allowed"|"unreachable"|"pending"|"unknown" }`（`departed` = 名单里 status 非 active；`sync` 由 `relay.status` 映射，`not_allowed` 不再映射成 unknown）。

### 2.4 `matters.members.add / remove`（加固）
- `add`：`user_id` 须在 `team.roster` 里且 status active（离线时用缓存名单，缓存也没有 → `roster_unavailable`）；存真实姓名（不再用编号）。其余（负责人、中继控制成员、轮换）不变。
- `remove`：不变（轮换密钥）；补一句律师可读的结果说明。

### 2.5 `matters.update` 的 `collab_scope`（收紧）
- 只有**负责人**能改；personal → team 须满足 2.2 的前置；**team → personal 拒绝**（`scope_irreversible`：“团队共享事项不能改回只有我：要结束共享请移出同事或结案”）。

### 2.6 同事之间同步的开通与续期（新，管理员电脑）
- `firm_policy.share_relay_status` → `{ relay_configured: boolean, state: "allowed"|"not_allowed"|"pending_second_signature"|"expired", expires_at: string|null, days_left: number|null, can_manage: boolean, threshold: number, signatures: number }`。
- `firm_policy.share_relay_enable` → 以**当前生效规则**为底稿只改 `share_relay: "allow"`，起草 + 本机签名 + 达阈值即发布；未达阈值回 `pending_second_signature`（第二位管理员在自己电脑上 `firm_policy.share_relay_status` 看到待签并 `firm_policy.sign`）。
- `firm_policy.share_relay_renew` → 按当前生效规则原样重签续期（同上阈值规则）。
- 到期前 7 天 `kernel.status` 带 `share_relay_expiring: { days_left }`（给侧栏 / 团队页提醒用）。
