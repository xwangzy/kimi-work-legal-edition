# 00 总览与验收报告（第 73 批，V47：律师端团队共享事项入口）

> 2026-11-28。承接第 72 批遗留 P1“律师端没有把同事加进事项的入口”（用户 11-27 晚定为下一批做）。客户端 **0.12.0**、云端 **1.8.0**。版本、安装包与上线顺序见 `15-版本与交付清单.md`。

## 结论

**团队空间里的律师现在可以在界面上完成团队协作的全流程：**
- **建团队共享事项**：建事项时就能选“团队共享”，也可以把已有的个人事项转过来。
- **管成员**：负责人可以选同事、加人、改角色、两步移出；移出后密钥自动轮换，对方拿不到之后的新内容。
- **同步开关**：管理员一键开通“同事之间同步”，还能续期、关闭，关闭后可以自助重新开通。
- **各方状态如实显示**：被移出、只看、没有名额、已离开团队都有对应说法。
- **客户授权**：团队共享事项的客户授权卡如实分段列出数据去向，读取失败时不允许记录授权。
- **部署**：同事名单与共享中继纳入云端标准部署，并在演练虚机上真跑了“升级 → 开通中继 → 回滚 → 再升级”。

**独立评审结论：**
- 界面设计第四轮：14 组全部 > 4.0，最低 4.17。
- 产品功能第二轮：7 项全部 > 4.0，最低 4.17。
- 一票否决：无。

**真实测试：**
- 本机真实栈上做了两轮独立端到端验收（10、10b）。首轮发现 3 个 P2，复测时已全部修好，新发现的 P3 也已修。
- 虚机部署演练通过，并经虚机上的中继完成了双向真同步。

**还不能在线上用**：要先由运维部署 1.8.0 与中继并验收，再分发 0.12.0 客户端（顺序写进了运维手册与交付清单）。

## 决策（详见 01）

| 编号 | 决定 |
|---|---|
| D-307 | 只在团队空间、且律所根确认过的电脑上能建 / 转团队共享；转了不可改回；“客户要求不上云”的事项不能团队共享（界面与内核两头拦） |
| D-308 | 同事名单 `/v1/team/roster`（姓名、角色、状态、是否有名额；不含邮箱手机号）；只有负责人管成员（管理员不代加，成员事件须负责人电脑签名）；移出即轮换 |
| D-309 | 共享中继纳入标准部署（8446、复用控制面证书）；release.json 带中继地址；管理员一键开通 / 续期，以当前生效规则为底稿只改这一项 |
| D-310 | 叫法统一“团队共享”（管理员开关叫“同事之间同步”）；侧栏 / 列表 / 搜索记号；事项头胶囊与事项成员页 |
| D-311 | 关闭同步后可自助重新开通（服务端本不拦；取代 D-94“须中软重置”的流程约定） |
| D-312 | 数据去向按发生时机分段（AI 使用时 / 选团队共享时已发生 / 存放说明），团队共享事项读不到去向时失败即收紧；不给同步加授权闸门（建议律所合规复核告知口径） |
