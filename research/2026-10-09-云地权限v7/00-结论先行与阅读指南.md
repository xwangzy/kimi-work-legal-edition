# Kimi Work 法律行业发行版 · 完整产品方案 v7.0（能力补位 · 沙箱放权）

定稿 2026-10-09 · 在 v6.0（云地分治，2026-10-02，待拍板）与 v5.0（律所侧执行，2026-10-01）基础上，按用户“云端执行与本地执行的权限、功能划分有问题”“我方从 Kimi 采购的是 API token”“demo 后端完整接入 Kimi Code 的后端功能、能力、特性”三点意见，从第一性原理重做划分与权限体系；本轮完成 Kimi Code 源码复核（S0）与三路联网核验（S1 Kimi 能力来源、S2 主流产品权限与 Windows 本机沙箱、S3 检索供应商 / 加密协作先例 / 国内法律 AI 与监管动态） · 面向：中软国际立项评审、与月之暗面及中软 MaaS 的联合评审、产品与研发、设计合作律所试点

> 所有价格、指标、人力、周期与收入均为待试点校准的假设，不是报价、预算或收益承诺；“已核验”只指公开官方材料或源码存在相应描述，不代表我方已签约、已实测或已取得供应商承诺。现有 demo 与 `platform/` 是原型，不是能承接真实案件的生产系统。

## 一句话

**端上全能力，沙箱定边界；云上补能力，控制归云；案卷在所，推理过境。**

律师电脑上运行**完整的 Kimi Code**（Kimi Work 的内核与它自带的本机后端 kap-server）：读写材料、运行 Python 与 Shell、派子 Agent 并行、目标模式长任务、技能、MCP、联网检索全部可用——但都在“事项沙箱”里：原件只读、工作区可回滚、其他事项不可见、代码没有直接网络、一切出网经出站闸门并记入数据去向卡。我们从月之暗面只买 API token，Kimi Work 靠 Kimi 会员云服务提供的检索、数据源、手机遥控中继、账号与分发拿不到，由中软云端**按 Kimi Code 已有协议补位**；中软云端同时承担身份、席位、策略、计量、通知、提醒与管理控制台。案卷明文只在律所侧；云端只见过境的化名推理片段与去标识检索查询（不落盘），以及端到端加密的协作与遥控数据（中软无密钥）。**律所零服务器即可开通。**

## 为什么还要改

| 稿 | 划分依据 | 问题 |
|---|---|---|
| v5 | 只问“谁持有案卷明文”→ 云端只供 token | 所内节点成为隐性必需品等十七个问题（v6 已列）；**另有两个未被指出的问题**：Kimi Code 的检索、数据源、遥控本身依赖月之暗面会员云服务，“只供 token”时这些能力直接消失；Kimi Code 内置工具被全部关闭 |
| v6 | 七条规则，控制面上云 | 控制面修好了，但留下四个结构性错误：**E1** 漏了“能力来源”维度（用逐条确认的派生查询、IM 内 H5 绕开缺口）；**E2** 用删工具代替定边界（发行版比 Kimi Work 标准版更弱）；**E3** 用治理仪式、根签名、确认码、透明日志等密码学机制对抗密码学挡不住的“发布客户端的一方”；**E4** 没有“云 → 本机”的渠道权限 |
| **v7** | **能力来源 × 数据位置 × 沙箱边界 × 渠道权限** | 补齐两个此前缺失的维度：能力来源决定云端必须补什么；沙箱决定本机可以放开什么 |

主流产品给出的答案（S2）：本机权限一律是“工作区边界 + 跨边界确认”两层，不是删工具；Windows 上只有 OpenAI Codex 做到原生进程级沙箱（含无需管理员的实现，Apache-2.0 开源），Claude Code 原生 Windows 不沙箱，千问办公与 Cowork 用须管理员开启的本机虚拟机；远程触发一律被收窄（WorkBuddy 远程任务固定在“助理专属文件夹”）。月之暗面 9 月开放的 `/v1/tools/search`、`search_pro`、`fetch` 让检索补位可以留在同一供应商与同一 DPA 内（S1）。

## 相对 v6 改了什么

| 领域 | v6 | v7 |
|---|---|---|
| 划分维度 | 七个属性 | 加入**能力来源**与**边界机制** |
| Kimi Code | 本机运行时，内置工具不可见 | **全量嵌入**（kap-server），内置工具全部开放 |
| 代码执行 | 无网络 WebAssembly Python，无 Shell | 沙箱内 Shell/Python/Node，随包分发运行时与文书库 |
| 本机隔离 | 降权进程 | 事项沙箱 + 设备隔离等级 A–D + 出站闸门唯一出口 + 宿主策略裁决每一次工具调用 |
| 运行模式 | 只问不做 / 先出计划 / 标准 / 放手执行 | 问答 / 手动 / 默认（沙箱内自动）/ 自动 + 计划开关 |
| 联网研究 | 派生查询逐条确认 → 云端公开沙箱 | Agent 直接检索（中软检索服务），L2 默认泛化后放行，命中实体或超阈值才确认 |
| 云端组件 | 控制面、密文中继、网关、公开沙箱 | 控制面、能力网关（网关 + 检索 + 法源）、中继（协作 + 遥控）；公开沙箱取消 |
| 手机 | IM 内 H5 解密与签名 | 移动 App（端到端加密遥控经主进程遥控网关、本机密钥签发） |
| 远程触发 | 未单列 | 远程渠道权限表 + 收件区 |
| 密钥 | 治理仪式、根签名、确认码、观察期、2-of-3 + 第 4 片、透明日志 | 账户密钥 + 扫码加设备 + 个人恢复码 + 律所恢复（律所版 2-of-3、团队版双因素）+ 事项目录密钥 |
| 策略完整性 | 律所根密钥签名 | 收紧类控制面签名；放宽类与连接器登记须律所管理员设备签名；版本单调；管理员公钥固定 |
| 会话转录 | 未设计 | 转录、文件历史与快照、导出包加密落盘，纳入保留与删除 |
| 律所 Hooks | 律所侧回调 | 同左，高风险时点失败即拒绝 |
| 网关 | 五项能力 + 思考内容密封 | 五项能力，取消密封 |
| 浏览器 | 隔离浏览器 G3 默认关 | 隔离内置浏览器 G1 默认开（公开站点白名单）；真实浏览器默认关 |
| 对外口径 | 本地处理、云端协同、推理只过境 | 同左 + “Kimi Code 本地 Agent 工具能力不打折”（闭源云技能除外）、“代码在无网络沙箱运行、经闸门的每次联网有记录”；“中软看得到什么”按渠道分情形 |

**v6 原样保留**：案卷明文在律所；控制面在云；零服务器默认；律所执行器只出站可选；法律推理网关（方法资产组装、权威计量、策略二次检查、内容安全、隐去律所身份）；IM 三模式与卡片最小化；期限提醒云端调度；数据分级 L0–L4；四层策略最严者胜出；管理员拿不到事项内容、不做会话回放；停服三项承诺；如实口径与禁用词。**v5 原样保留**：本机法律内核与 `platform/` 已实现代码（事项账本、解析与 OCR、化名、出站闸门、签发、离线法规库、Office 桥）；场景、交付件、18 套规则包、360 任务盲测、定价纪律。

## 对抗式审阅后的修订

v7 初稿经对抗式审阅（26 条：7 阻断、10 重要、9 一般，`审阅-对抗式-2026-10-09.md`），核心意见是“放开全部工具后，沙箱、闸门、审批三道边界在初稿里有可绕过或无落点的缺口，遥控又把整个 Agent 后端暴露给远端”。全部 26 条已处置（第 6 篇 §D），主要变化：宿主策略插入引擎策略链首位并清空上游默认放行；闸门改为独立进程、删除抓取回落、A 级由防火墙强制唯一出口；遥控与 IM 终止于主进程遥控网关白名单、终端关闭；沙箱对回环不可达、令牌只在内存；恢复与策略补回轻量律所侧校验锚；图像直送改为跨边界动作；“中软看得到什么”按渠道分情形；工作量 +约 26 人周。
