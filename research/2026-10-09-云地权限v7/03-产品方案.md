# 第 3 篇　产品方案：形态、入口、权限体验与 Kimi Work 映射

版本 7.0 · 2026-10-09 · 本篇写 v7 相对 v6 第 3 篇的变化与完整的 Kimi Work 映射。**角色—价值矩阵、价值量化、视觉与设计令牌、法律专用组件、Word/WPS 加载项功能与写回安全、首页与执行态线框沿用 v5 第 2 篇**；场景、交付件、18 套规则包与验收沿用 v5 第 3 篇；内容与数据资产沿用 v5 第 5 篇（方法资产保护按网关组装）。

## 1. 产品定义

### 1.1 一句话

**「Kimi Work 法律行业发行版」是中软国际与月之暗面联合推出的律所法律工作平台：它拥有 Kimi Work 的全部本地 Agent 能力——在律师电脑上读写材料、运行代码、派子 Agent 并行、联网研究、按目标长时间自主工作——但每一个动作都发生在事项沙箱和律所策略之内；案卷在律所本地处理与保存，团队协作、手机遥控、IM 入口与期限提醒由中软云端承接且只见密文或元数据；律师得到有出处、有版本、经律师签名签发的 Word/Excel 交付件。律所零服务器即可开通。**

### 1.2 相对 Kimi Work 标准版的七个增量

| 增量 | 内容 |
|---|---|
| **本地 Agent 能力不打折** | Kimi Code 全量能力（文件、Shell/Python、子 Agent、集群、目标、计划、技能、MCP、定时、文件历史）原样可用；只买 API token 拿不到的检索、数据源、遥控由中软补位（不提供的 Kimi 闭源云技能见 §1.5） |
| **安全地放开** | 事项沙箱（原件只读、工作区可回滚、代码无直接网络）+ 出站闸门（每次出网有记录）+ 跨边界确认；默认档比 Kimi Work 更少打断 |
| 法律能力包 | 工作流、Playbook 与本所覆盖层、模板、确定性规则、离线法规库、授权法源、法律官方站点集检索 |
| 可信交付 | 原生修订、回稿比对、受众分版、引用四态、签名签发、AI 标识 |
| 机构治理 | 事项与成员、伦理墙、复核与签发、四层策略、管理员锁定运行模式、设备隔离等级、远程渠道权限、审计（看得到动作、看不到内容） |
| 律所持钥 | 案卷明文只在律所；协作与遥控数据在中软云端只以密文存在；每次外发与过境记入数据去向卡 |
| 入口与服务 | Word/WPS、企业微信/钉钉/飞书、移动 App；规则上线、培训、客户成功、LTS、合规材料包 |

### 1.3 与 Kimi Work 标准版的关系

| 类别 | 内容 |
|---|---|
| **沿用（已获授权）** | 视觉与版式；统一任务输入（`/` `@` `+`）；任务化会话与执行态三栏；挂载本地文件夹；本地 Agent 执行；Office 直出；看板与小组件；技能与插件交互；定时任务交互；三档运行权限的交互形态；手机远程控制的交互（查看进度、审批、预览、上传附件）；内置浏览器 |
| **增强** | 「项目」→「事项」（可在律所内加密共享）；「技能」→ 签名法律方法包 + 律所技能；「看板」→ 事项与团队看板；「定时任务」→ 云端期限提醒 + 本机/执行器内容任务（错过提示补跑）；运行权限三档 → 四档 + 计划开关 + 管理员锁定；手机远程控制 → 端到端加密 + 远程降权 + 收件区 |
| **收敛** | 没有“全部/完全访问”档；真实浏览器控制（借用本人登录态）默认关；插件只来自中软官方与律所批准目录；案卷目录中的技能、Agent 与 MCP 配置一律不加载；Agent 集群并发与预算有上限；对外发送、签发、删改原件不是 Agent 能做的事 |
| **新增** | 事项沙箱与设备隔离等级；出站闸门与数据去向卡；收件区；律所执行器；密文协作；移动 App 审阅签发；法律推理网关与检索补位 |

### 1.4 它不是什么

不是法律数据库；不是律所管理系统（可对接）；不是自动出具法律意见的机器（律师签发）；不是中软托管案卷的云服务（云端只有密文与元数据）；不向律师个人开放任意插件市场；不做判决预测与法官画像；不提供“完全访问”档。

### 1.5 不提供或替代的 Kimi Work 能力（如实）

| Kimi Work 能力 | 为什么拿不到或不提供 | 发行版怎么做 |
|---|---|---|
| “继承在线版 Kimi Agent 的建站、PPT 等专业 Skills” | 闭源、随 Kimi 会员云服务提供，只买 API token 拿不到（`调研-S1` Q2.1、汇总表） | 法律文书与表格由中软文书引擎与法律技能承担；PPT 汇报材料由 Agent 在沙箱内用 python-pptx 生成草稿，G2 评估自研“法律汇报 PPT”技能 |
| 深度研究（Kimi 会员云功能） | 云端产品，拿不到 | Agent + 中软检索服务 + 法源服务组合实现“授权法源研究”（S4 场景），结果带引用四态 |
| Kimi Computer Use（桌面操控）、WebBridge（借用本人 Chrome 登录态） | 风险与律所执业场景不符（提示注入可操控法院系统、邮箱、内网登录态） | 不提供桌面操控；真实浏览器控制默认关，管理员可按域名开启；隔离内置浏览器默认开 |
| Kimi Claw、Kimi 云端定时、托管智能体 | 会员云产品或不符合零数据留存 | 客户事项不在云端执行（G3 律所专属云执行器可选）；公开监测为云端确定性服务 |
| Notion/飞书文档“人机双写”等第三方 SaaS 插件 | 需律所评估数据去向 | 律所批准后作为连接器接入，标注可接收数据级别 |
| 图片与视频生成 | 与法律交付无关，且直传图像/视频不在 ZDR 覆盖内 | 不提供 |

## 2. 产品形态：五个入口 + 律所侧内核 + 云端协同

| 组成 | 主要用户 | 做什么 | 运行在 | 阶段 |
|---|---|---|---|---|
| **桌面客户端**（Windows 10/11；macOS 2027-Q3） | 律师、助理、合伙人 | 主工作台：事项、任务、Agent、交付件；内嵌 Kimi Code 后端与法律内核 | 律师电脑 | G1 |
| **Word / WPS 加载项** | 律师 | 文档内审合同、写修订、核验引用、比对、脱敏导出（v5 不变） | 律师电脑 | G1 |
| **企业微信 / 钉钉 / 飞书入口** | 全员 | 把文件转进收件区、发起模板任务、查进度、收提醒与签发通知 | 云端控制面 + 律师电脑或执行器 | G1 首家 |
| **移动 App** | 合伙人、律师 | G1：遥控本人电脑、通知；G2：离线于电脑的审阅与签发 | 手机 + 中软中继（端到端加密） | G1/G2 |
| **管理控制台（Web）** | 管理员、主任、风控、知识管理、财务 | 成员、设备与隔离等级、席位、策略、运行模式锁定、连接器与插件目录、IM、遥控策略、执行器、用量账单、运营审计、合规材料 | 中软云端 | G1 基础、G2 完整 |
| 律所执行器（可选） | 律所 IT | 关机续跑、批量、内容型定时、M2 模式 IM、私有模型与自带密钥网关 | 律所任意常开设备 | G2 |

v6 的“不做独立手机 App、手机端由 IM 内 H5 承担”改为**做移动 App**：IM 内 WebView 的不可导出密钥与生物识别能力没有把握（v6 未决项 U4、U18），且 H5 脚本每次由中软服务器下发；App 的 WebView 内容经端到端加密通道从律师本人电脑取得，签发密钥在 Secure Enclave/StrongBox 中（第 4 篇 §8）。

## 3. 首日激活：零服务器，第一个交付件 ≤ 30 分钟

| 2 设备自检 | 显示“本机隔离等级 A/B/C”；B/C 级给出“请 IT 或本人做一次管理员授权以升至 A 级（约 1 分钟）” | 第 2 篇 §8.5 |

## 4. 让律师看得见“在哪执行、用了什么权限”

### 4.1 事项头

客户 / 相对方 / 立场 / 法域 / 关键日期 / 保密等级 / 模型端点 / 执行位置（本机 · 允许律所执行器 · 允许律所专属云执行）/ 当事人同意状态 / 数据级别。

### 4.2 运行模式选择器（输入框右下角）

“问答 / 手动 / 默认 / 自动” + “先出计划”开关。规则：

- 只显示上层策略允许的档位；被禁止的不出现（不显示灰色“申请开启”）。
- 切到“自动”时显示本任务预算上限与将自动通过的跨边界动作（例如“白名单站点抓取、无实体检索、只读连接器”）。
- 设备隔离等级为 C/D 时，“自动”与（D 级）代码执行不出现，并提示原因。

### 4.3 跨边界确认卡

卡片写明：Agent 要做什么、为什么、数据会去哪里（例如“将向中软检索服务发送：‘某有限责任公司股东未实缴出资补足责任’”）、风险提示；按钮：“本次允许 / 本任务内一直允许 / 改写后允许（检索） / 拒绝”。“本任务内一直允许”不跨任务、不跨事项。

### 4.4 执行位置与隔离徽标

| 徽标 | 含义 |
|---|---|
| 本机沙箱 · A/A′/B/C | 在这台电脑的事项沙箱中执行，后缀为隔离等级 |
| 律所执行器 | 在律所自己的执行器上执行 |
| 模型推理中 | 化名片段正在经中软网关发往 Kimi |
| 联网检索中 | 去标识查询正在经中软检索服务 |
| 等待联网 / 等待电脑上线 | 排队中 |
| 律所专属云执行（G3） | 本任务材料在中软云端隔离容器内存中处理，结束销毁（橙色常显） |

### 4.5 数据去向卡

“本任务向 Kimi 模型（经中软法律推理网关）发送了 3 份文档的 42 个段落、共 18,240 字，其中化名 37 处；向中软检索服务发送 6 条去标识查询（1 条经你确认后改写）；本机抓取 4 个公开网页（2 个域名）；在本机沙箱中运行代码 9 次（无网络）；协作数据经中软密文中继同步 14 个加密事件（中软无密钥）；原件与成果的其余副本未离开律所侧。”可展开到逐段落、逐查询（查询原文只在本机显示）、请求 ID、同步序号。

### 4.6 “中软看得到什么”页

| 中软看得到 | 中软看不到 |
|---|---|
| 账号、手机号、所属律所与团队、角色 | 案卷原件、解析文本、成果、修订、会话转录 |
| 设备数量、隔离等级、公钥、登录时间与 IP | 事项名称、客户名称（事项目录以律所密钥加密） |
| 用量：任务模板、点数、token 数、检索次数、耗时 | 化名映射表 |
| 匿名事项的任务与活动时间、期限提醒时间与类型 | 签发私钥、事项密钥、律所恢复私钥（选择中软托管恢复时，托管材料在 HSM 中且释放须律所两名管理员请求） |
| 推理时过境的化名片段、联网检索时过境的去标识查询（网关与检索服务不落盘；上游以企业协议为准） | 遥控会话内容（端到端加密） |
| M1 模式下经 IM 机器人发送的文字与文件名（过境、不落盘） | 经 IM 转来的文件内容（默认由律师电脑直接下载） |
| 加密后的协作数据（无解密密钥） | 关注企业名单（只在本机匹配） |

## 6. 企业微信 / 钉钉 / 飞书入口

接入模式、平台差异与安全规则沿用 v6 第 3 篇 §6（M1 服务商应用、M2 律所机器人 + 执行器、M3 个人机器人；卡片不含文件名与事项名；配对模式；个人微信与 QQ 不开通）。v7 的两处变化：

1. **IM 指令降权**：机器人只做三件事——把文件放进本人“收件区”、发起预设模板任务（问答或计划档）、查进度；不接受用任意文字直接驱动 Agent 开放任务（防止 IM 成为提示注入与越权的入口）。需要开放任务时，卡片按钮“在手机上继续”跳转移动 App 遥控。
2. **收件区**：IM 与手机进来的文件先进入本人收件区，归入事项后才进入该事项沙箱；收件区里只允许问答与分类。

## 9. 研究、计算与浏览器

| 能力 | 律师体验 | 边界 |
|---|---|---|
| 联网研究 | “研究这三个争点”→ Agent 起草检索式，经闸门去标识后在中软检索服务检索（研究类默认优先法律官方站点集）→ 抓取全文 → 法源服务核验案例 → 结论与引用四态进工作区 | 无实体的查询自动放行；含当事人名称时一键泛化；L3 逐条确认；L3b 禁止；“待取得/已拒绝”不出站 |

## 10. 一个事项的一周（v7）

周一上午，客户在个人微信上把对方发来的股权转让协议发给经办律师。律师在企业微信里把文件转给自己的个人机器人，文件落进她电脑上的收件区；她在电脑上把它归入事项“甲公司受让乙公司股权”，按受让方立场与本所覆盖层首轮审查——合同在本机解析，只有化名后的条款片段经中软网关发给 Kimi，网关在服务端填入中软的股权转让 Playbook。审查完成后她追问：“对方要求的业绩补偿公式，按三种情景算一下我方最大赔付额”，Agent 在沙箱里用 Python 跑完三种情景，表格进了工作区，整个过程没有一次弹窗；接着问“最近一年有没有关于对赌回购条款效力的新判例”，Agent 把检索式里的“甲公司”自动泛化为“目标公司”，在法律官方站点集里检索、抓取全文、核验案例，结论带着引用四态写进备忘录。同组助理在家打开客户端，经密文中继同步到最新结果，不需要 VPN。周二合伙人出差，在高铁上用移动 App 遥控办公室电脑，让 Agent 把修订稿按客户版重新排版，确认后在 App 上完整预览；周三在机场用 App 签发（G2）。周三下午云端提醒“补充协议约定的付款节点还有 7 天”。周四对方回稿，律师在高铁上断网，本机比对只重审被改动的 6 个条款，法条核验离线完成；需要模型的 2 处排队，联网后续跑。客户问“你们用 AI 会不会泄露交易信息”，合伙人打开数据去向卡：案卷在律所电脑上处理与保存；AI 写的代码在没有网络的沙箱里运行；联网检索只发出了去标识的问题；协作数据在中软云端只以密文存在；每一次都有记录。
