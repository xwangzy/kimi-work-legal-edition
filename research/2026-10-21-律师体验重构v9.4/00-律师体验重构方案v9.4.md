# Kimi Work 法律发行版 V9.4：律师体验重构——评审、方案与首轮实施（2026-10-21）

- 基线：V9.3（main `4a306e3`，已推送）。本轮代码在分支 `v9.4`（worktree `.claude/worktrees/v93-b16`），**未合并 main、未推送**。
- 本文是主文。独立评审三份在同目录：`评审-U1-界面与认知.md`（UI/UX 与认知工程，48 张截图在 `shots/`）、`评审-S1-法律能力与Skills.md`（资深律师 + Skills 架构）、`评审-C1-竞品设计借鉴.md`（Harvey / LegalOn / Legora / CoCounsel / Spellbook / 国内）。
- 证据口径：结论都给代码路径、截图或官方链接；“实测”只指本轮在开发形态里亲手操作过的；**模型一律是桩**（没有任何真实 K3 产出），凡涉及法律产出质量的都写“待真实模型”。

## 0. 一页结论

**V9.3 的底子是真的，律师面前的那层不是。** 执行管线（场景卡 → 内核 → Kimi Code → Skill → 法律工具 → 草稿成果 → 复核签发）真实贯通且有测试；隐私（发送前换代号、每次外发留痕、案卷不上云）和签发门禁扎实。但律师一打开就会遇到三类问题：

1. **研发现场外露**：设置页像工程控制台（“联网通道”“最近一次自检”“开发形态：路径”、DPAPI/TPM）；开始前确认是一段 249 字、含“令牌化、出站、上游、网关、v0 费率表”的长句；交给合伙人的“案卷总目录”表头是 `sha256(前16)`、`大小(字符)`，备注是 `v0_crude_docx_parser`；文件名带任务编号尾巴 `-b35186`。律师可见文字里研发词 331 处（U1 §2）。
2. **信息密度与层级**：首页标题问“今天要处理什么”，首屏却没有期限、没有等你确认的事；场景卡每张 50～75 字带扩展名；事项页首屏被横幅、信息卡、输入框占满（1280×720 下标签在 560px）；执行页胶囊写“本机处理中”、正文写“模型服务重试第 7/10 次”，下面一根空白长条。
3. **名不副实**（S1 §0）：“类案与法律研究”背后没有案例库；“劳动争议应诉准备”背后是通用案卷整理，金额、答辩、起诉三个方法都明确不接劳动案件；“回稿比对”卡写“只对改动部分重新审查”，实际走本机比对、不重审；“履约风险”卡承诺风险提示，方法不出。

法律能力上，**17 个 Skill 写得像律所内控手册，但没有一个被真实模型执行过**；法规库只有 3 部法、正文 9 条，其中一个《律师法》2026 修正本是自注“演示演绎”的虚构版本却标“现行有效”；**没有期限计算工具**，`defense-draft` 却要求模型写答辩期届满日；**论证支持核验没有条文原文可比**（S1 §4）。

**本轮做了什么**（分支 `v9.4` 上 20 个提交，详见 §10）：
- **律师层减负**：开始前确认改为五句要点（经谁转发、换成代号的范围、按原文发送的类别、检索规则、服务方是否保存）+ 折叠的完整说明；“本机与安全”改为三块结论 + 备份三步走 + 技术信息折叠；首页加“今天”（等你处理 / 近期期限 / 继续工作）；事项页标签收成五个、输入框不用时收成一行；执行页胶囊按是否用 AI 写、重试第 3 次可停止、完成后写“n 份待复核”；复核页、审查工作台、交付件页、方法页去重减字；“中软”在律师层统一为 Kimi Work 客服/服务（披露页保留并说明是谁）；成果内容与文件名去研发痕迹。
- **用语门禁**：新增用例扫描全部律师层文件，出现“令牌化、出站、闸门、控制面、网关、哈希……”即失败（附反向对照）。
- **名实相符**：卡片改名改承诺；新增“文稿体检：引用与论证”“修订说明与谈判要点”“对方回稿：比对与重审”；首页加三条线通用的一行；立场补用人单位、劳动者、出借人、保证人、上诉人等 9 个。
- **真实能力补齐**：内核新增 `calc.deadline`（法定期间，2024—2026 节假日逐年核对国务院办公厅原文）与 `law.get_article`（条文原文，库外如实 `found:false`）；场景卡字段作为方法参数显式传给 Agent（端到端用例 + 反向对照）。
- **Skills**：新增劳动争议、尽职调查、合同起草、管辖与时效 4 个方法；引用核验加“论证支持”七类失配；访谈加紧急期限与冲突待核主体；6 个方法的期限口径统一为“由工具算或标待律师计算”（见 §6.3，以子代理交付与主会话复核为准）。

**全量回归**：见 §10.3。**没有做的、不能做的**：见 §1.2。**需要你拍板的**：见 §11。

## 6. Skills 体系与专家工作流

### 6.1 设计规则（采纳 S1 §5.1）

1. 卡 = 律师的一个业务目标，用律师的话命名；卡上不出现 Skill、Agent、工具名。
2. 卡只传参数、不加承诺：方法没有的能力卡上不写。
3. 没有方法的业务不挂到相近方法上：宁可不建议（本轮：类案、尽调意图不再误导）。
4. 三条业务线 + 通用一行；同一方法在不同业务线可有不同卡名，但只认一份方法正文。
5. 确定性的事交给工具：期限（`calc.deadline`）、金额（`calc.interest`）、条文原文（`law.get_article`）；模型只写起算事实与规则，不自行推算。
