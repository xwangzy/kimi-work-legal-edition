# 第 60 批：客户端安全加固报告

日期：2026-11-23。分支 `claude/kimi-legal-client-b60-domain`（基于 main 644b6bd）。
依据：本目录 `11-客户端安全现状审计.md`（独立只读审计，24 项、每项附 file:line）与 `10-官方安全配置与签名资料.md`（Electron、electron-builder、Microsoft、Apple、CA/B 论坛、electron-vite 官方文档汇编）。

## 1. 结论先行

1. **保护边界**：这是一个 JS 桌面应用，客户端里的代码、提示词与方法模板无法做到“拿到安装包也看不到”。本批的目标是把**未授权复制、静态阅读和篡改的成本**抬上去，并把**信任根**（谁能签内容、谁能签发布、谁能出服务端凭据）收在服务端与离线密钥里。核心价值——模型密钥、额度计费、席位令牌与吊销——本来就在服务端，客户端里没有任何服务端秘密（本批扫描再次证实，见 §5）。
2. **本批落地 9 项**（§3）：JS 制品压缩改名（H1）、**生产内容签名信任根**（H2）、安装包 SHA256SUMS + Ed25519 发布签名（H3）、正式包关闭开发者工具与精简菜单（H4）、打包通用秘密扫描（H5）、发布签名不再静默用开发密钥（H6）、Windows 验收工作流加固（H7）、macOS 权限收窄（H8）、正式发布门禁的“无证书过渡开关”（H9）。全部有用例，正式安装包上做了真实验证。验收中另追加两项稳定性修复：出站闸门按退出原因码说明拒绝原因（b146b1e）、模型请求输出 token 封顶 32,000（bf9fba6）。
3. **没能做的**：操作系统代码签名与公证——本机与仓库里**没有任何代码签名证书**（`security find-identity -p codesigning` 为 0），中软还没有 Windows OV/EV 证书与 Apple Developer ID。资料核实：Azure Artifact Signing 的公共信任证书不对中国内地、香港主体开放；自 2023-06-01 起 OV/EV 私钥必须在硬件模块里；EV 已不能直接免除 SmartScreen 提示。所以 EXE 仍未签名、DMG 仍为 ad-hoc 签名。过渡做法是 H2 + H3：内容由生产密钥签、发布物由发布密钥签，客户 IT 可按发布公钥核对来源与完整性。
4. **明确不采用**：重度 JS 混淆、asar 加密、V8 字节码、敏感模块原生化（理由见 §2）。下一阶段真正有效的知识产权保护是**提示词与方法模板下沉服务端**（架构改动，需拍板，§7）。

## 2. 候选方案比较

| 方案 | 防得住 | 防不住 | 兼容性 / 构建 | 运行开销 | 维护成本 | 体验影响 | 决定 |
|---|---|---|---|---|---|---|---|
| **制品压缩 + 局部标识符改名**（esbuild minify，保留函数名） | 直接阅读源码结构、注释、局部变量名 | 字符串常量（提示词）、属性名、动态调试 | 与 asar 完整性、运行时清单摘要、utilityProcess、随包 Node 子进程全部兼容（摘要在压缩后计算） | 无（体积更小，内核 3.9→2.5 MB） | 低：一个环境变量；排错包可 `--no-minify` | 无 | **采用（H1）** |
| 重度混淆（控制流平坦化、字符串数组、自防护、反调试） | 再抬高一些阅读成本 | 动态调试与运行时取值；字符串仍可在运行时还原 | 改变运行时行为，6 万行级内核需全量回归；与 keepNames、错误名判断、第三方库的动态特性易冲突 | 有，且不可预测（未实测，不作数字结论） | 高：每次升级都要回归 | 可能变慢、排错困难；反调试类做法还可能被安全软件视为可疑 | **不采用** |
| V8 字节码（electron-vite / bytenode 思路） | 源码不随包、`Function.toString` 拿不到源码 | 字符串常量仍可读（官方明说）；可反汇编 | 官方：只支持主进程与 preload；preload 用字节码须 `sandbox:false`（与安全清单冲突）；绑定 V8 版本与 CPU 架构、跨平台编译不可靠。本产品核心逻辑在 utilityProcess 内核与**随包官方 Node** 子进程里（两套 V8），需分别编译；项目未用 electron-vite | 加载期略有影响 | 高：每次升级 Electron/Node 都要按平台重编、重验 | 异步箭头函数等已知崩溃点需改写 | **本批不采用**；如要做，先只对主进程，在 Windows/macOS 各自原生构建机上编译 |
| asar 加密 / 自定义协议解密 | 直接解包看到文件 | 解密密钥必须随客户端分发，等于换个地方放明文 | Electron 官方不提供；官方路径是**完整性校验**而不是加密 | 每次读取解密 | 中 | 无 | **不采用**（已有完整性熔断） |
| 敏感模块原生化（N-API / Rust） | 提高逆向门槛 | 原生代码同样可逆；提示词仍是数据 | 双平台原生构建链、签名与摘要锁定都要扩展 | 低 | 高：重写 + 跨平台 | 无 | **不采用**；有限的投入应先用在服务端化 |
| **提示词与方法模板下沉服务端**（按次下发或服务端执行） | 客户端拿不到完整提示词与方法正文 | 单次响应内容 | 架构改动：方法包分发、离线可用性、案卷不出所的边界都要重新评估 | 多一次往返 | 中 | 离线时能力受限 | **建议下一阶段拍板**（§7） |
| **生产内容签名信任根** | 开发机上的密钥签的内容进不了正式包；被改动的法规库、方法模板、工具清单拒载 | 能改安装包本身的人（见代码签名一行） | 与现有签名格式一致；Windows CI 用 Mac 上签好的内容包，私钥不进 CI | 无 | 低：一把离线密钥 | 无 | **采用（H2）** |
| 操作系统代码签名与公证 | 安装包与程序的来源与完整性（操作系统核验）；熔断与 asar 完整性的根 | — | 需证书：Windows OV/EV（硬件模块）、Apple Developer ID + notarytool | 无 | 证书续期（2026-03 起最长 460 天） | 消除 SmartScreen“未知发布者”、macOS“仍要打开” | **证书缺失，未做**；过渡用 H3 |
| **安装包摘要清单 + Ed25519 发布签名** | 下载渠道被替换、文件被改动 | 用户不核对就安装 | 纯文本清单 + 签名，OpenSSL 3 即可核对 | 无 | 低 | 无（给 IT 用） | **采用（H3）** |
| **正式包关闭开发者工具、精简菜单** | 走到电脑前的人开开发者工具绕过界面层提示、查看页面数据 | 以 `--remote-debugging-port` 启动的本机进程 | Electron 原生选项 | 无 | 低 | 无（普通用户不用开发者工具） | **采用（H4）**；远程调试开关保留（§6） |

## 4. 安全边界（客户端 / 云端）

- **服务端裁决**：账号认证、设备入组批准（管理员逐位核对入组核对码）、席位令牌签发与吊销、模型路由与上游密钥、每次模型调用的额度与计量、用量账本——都在云端。客户端拿到的只有短期席位令牌与签名的额度视图（客户端只验签展示）。
- **客户端只持有**：本机设备私钥（封装）、会话令牌（封装）、案卷数据（加密库）、公开的钉住值与验签公钥（release.json，受 asar 完整性保护）。
- **只在本机裁决、防误操作不防篡改**（审计第 7 项）：角色界面、停用电脑禁导出、敏感事项防截屏、离线许可等。这些在操作系统代码签名到位前只能视为“防误操作”。

## 6. 剩余风险

1. **没有操作系统代码签名**（高）：熔断与 asar 完整性在 macOS 由代码签名保证、在 Windows 由 exe 资源保证；未签名时能改写安装包的人可以一并改写这些校验。缓解：H2（内容信任根不在客户端）、H3（发布签名清单）；根治：中软申请 Windows OV/EV（硬件模块或云 HSM）与 Apple Developer ID，去掉 `--unsigned-release`、改 `--sign env`，并在 release.json 填 `update_publishers`。
2. **远程调试开关仍可用**（中）：本机能以本人身份启动程序的进程可加 `--remote-debugging-port` 驱动界面、调用内核方法。正式安装包的端到端验收依赖它（Windows 运行器与 Mac 都靠它驱动真实界面），本批保留。Windows 上同账户进程本可直接用 DPAPI；macOS 上它可以绕开钥匙串授权框，残余风险更明显。可选后续：只在带“发布密钥签发、短时有效的验收许可”时允许远程调试。
3. **律所根私钥与恢复份额全部在管理员电脑上**（高，审计第 3 项）：产品设计问题，不在本批范围；建议份额生成后导出给合伙人离线保管、本机不留。
4. **提示词与方法模板以明文随包**（中）：压缩不隐藏字符串；见 §7。
5. **macOS 每次换构建都会弹钥匙串授权框**（体验）：ad-hoc 签名每次不同；接 Developer ID 后消失。`safeStorage` 同步 API 在 Electron 46 移除，升级前改异步 API。
6. **生产密钥目前在构建 Mac 上**（中）：应转存离线介质或硬件模块，并约定轮换办法（新公钥经 release.json `content_keys` 下发）。
7. **试用构建（`--trial`）的密钥可还原**（高，审计第 1 项）：只在 monorepo、与正式包隔离；不得对外分发。

## 7. 建议拍板

1. 申请代码签名证书：Windows OV/EV（硬件模块或国内 CA 的云签名）+ Apple Developer ID（含公证）。
2. 生产密钥保管：转存离线介质 / 硬件模块，指定保管人与轮换办法。
3. 提示词与方法模板是否下沉服务端（按次下发或服务端执行）。
4. 远程调试开关是否改为“签名验收许可”才放行。
