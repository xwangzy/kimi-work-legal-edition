## 0. 方法

- 环境：`node platform/scripts/dev-console.mjs --port 5491`（进程内控制面 + 控制台静态页，CSP 与生产同口径）。本批给开发脚本加了 `seedGatewayReports`：
  走网关同一条服务间接口（`POST /v1/quota/settle`、`POST /v1/feed/routing-health`）回报近 30 日约 4,000 条虚构逐请求用量与上游健康，
  控制面照常去重、按价目版本重算、触发告警——让图表、毛利、未定价、上游降级都有真实形态可看（`--no-usage` 不造）。
- 截图：Playwright 无头 Chromium，1440 宽整页（主区撑开）；按系统管理员、客户运营、财务、律所管理员四种身份逐页截。
  - `before/`：改前，浅色桌面 36 张；

    `after/交互/` 是逐项点验时截的抽屉与对话框。
- 打分：五个维度各 1–5 分——视觉美学 / 信息层级 / 交互效率 / 认知负担（分高 = 负担轻）/ 设计一致性。

## 1. 总体判断（改前）

1. **没有视觉重心**。总览六张同样大小的指标卡、三栏同权重的面板；异常（上游降级、未定价 468 行、待开通 5 家、20 天后到期）
   散落在卡片小字和“需要关注”的第三个子标题下，第一眼看不到“现在要处理什么”。
2. **信息架构按接口长，不按工作长**。告警藏在“套餐与额度”的第三个分页签；注册设置也在那里；价目表在“模型与路由”的第三个分页签，
   财务看毛利要在价目表里自己心算；平台人员的“我的”分区只有一项“账号与安全”，却占侧栏最上面。
3. **指标与卡片的形式重复**：每个数字一个带框小卡（6 个边框 + 6 段说明），卡片里的表格不贴边（表头比卡片窄一截），
   卡片里的空状态又套一层虚线框——框套框，视觉噪声大。
4. **说明文字和数据同权重**：工具条、页头里大段 13 号说明（白名单、切换规则、改价后果）与表格并列，读者要先读完才能找到操作。
5. **若干具体缺陷**：图例“输出 token”色块与柱色不一致；“5 小时频率限制”写成“最多用本期额度的 —%”；
   设备页“异常标记”有胶囊和分段两套重复筛选，且按标记筛选后其他标记的数量变 0；
   总览“30 天内到期 1”点到客户页筛出 0 家（两边口径不同）；输入 / 输出 token 并排柱，输出几乎看不见。

## 2. 新信息架构

```
我的（成员账号）                本所（律所 admin / partner）     平台运营（中软平台人员，按角色出现）
  概览                            概览                             工作台   总览 · 告警(角标)
  我的电脑                        成员                             客户     客户 · 账号 · 设备 · 注册管理 ▸ 注册策略 / 邀请码 / 短信服务
  账号与安全                      电脑                             经营     套餐 · 模型与价目 · 计费 · 用量
（平台人员：收进侧栏底部本人卡片） 用量                             平台     模型与路由 · 人员与权限 · 系统
                                  账单
```

- “告警”从分页签提成一级页，侧栏带未确认数（登录即读一次）；
- **“注册管理”是平台运营的一级菜单**，下含注册策略、邀请码、短信服务配置（`#/ops/registration/<子页>`，侧栏在当前页时展开）；
- **“模型与价目”**独立成页：成本价、销售价、单位毛利、毛利率放在一张表上，另有本期按模型的实际毛利；
- “套餐与额度”收窄为“套餐”；“模型与路由”只管上游与别名；
- 旧地址照认：`#/ops/plans?tab=settings → 注册策略`、`?tab=alerts → 告警`、`#/ops/routing?tab=prices → 模型与价目`。
- 菜单按角色（实测）：系统管理员 13 项；客户运营 11 项（无人员与权限、系统）；财务 8 项（总览、告警、客户、注册管理、套餐、模型与价目、计费、用量）。

## 3. 视觉系统（console.css 重写，仍只用 tokens.css 的语义令牌）

| 件 | 规则 |
|---|---|
| 指标条 `.kpis` | 一张卡片里 1px 分隔的一排数字；主指标 `.stat.hero` 28 号，其余 20 号；10 万以上金额写“万 / 亿”，精确值在悬停提示与明细表 |
| 信号 `.signals` | 页首集中出现的异常与待办：红 = 要立刻处理，橙 = 注意，蓝 = 待办；数量为 0 退成灰色加绿点；点开即到对应筛选 |

| 说明 `.note` | 解释性文字收成一行次级色 + 信息图标 |
| 危险区 `.danger-zone` | 终止订阅等不可逆操作集中在详情页最后，红色描边；确认框仍要再输一次目标编号 |
| 设置行 `.setting-row` | 左名称与说明、右控件；三选一用单选卡片 |
| 图表 | 输入 / 输出叠放（蓝 + 中性灰，亮暗两套都 ≥ 3:1）；悬停出自绘提示框（日期 + 各系列 + 合计），不靠原生 title |
| 毛利条 `.margin-bar` | 毛利率的小横条（负毛利画红） |
| 页头 | 标题 + 元信息行（点号分隔：周期、版本、更新人）+ 右侧主操作；详情页加“关键数字”一排（`.head-stats`） |

间距：页面区块间距 16 → 24px；表格行内边距 8 → 10px、首末列 24px；表头 12 号次级色。窄屏（≤768）侧栏收抽屉、指标条两列、
设置行单列、表格只在表格内横向滚动；实测 390 宽全部页面无整页横向溢出。

- 合伙人（只读）身份 dev-console 没有造数据，本批按代码核对（只读提示、按钮置灰逻辑未动），未实机截图。
- 平台人员的“我的”只剩底部本人卡片入口：如运营反馈找不到，可在卡片旁加“账号与安全”文字链接。
