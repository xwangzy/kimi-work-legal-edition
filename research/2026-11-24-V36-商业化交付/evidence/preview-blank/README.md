- 经用户同意退出客户端后以 `--remote-debugging-port` 重开同一工作区，进入“起草起诉状”任务（右栏选中“民事起诉状”）。
- 现象复现：右栏说明行显示“预览（排版为近似效果…）”，框架区域空白。
- 框架 DOM：`iframe.sp-frame` 的 srcdoc 长 3,321 字符，含完整起诉状正文。
- CDP 直连框架目标（about:srcdoc，跨进程）：readyState complete、body 1,868 字符、正文“民事起诉状 原告：王超…”、文字色 rgb(31,29,26)、纸面底色 rgb(255,253,249)、可见——**文档已完整载入，父页面合成却不出图**。
- 同一页面里新插入的 sandbox 框架（同一 srcdoc）立即正常显示；对原框架再改 srcdoc 仍空白；把原框架替换为新元素（属性相同）立即正常显示。
- 帧事件序列（返回任务页时记录）：框架插入并开始初始导航 → 2 ms 内“swap”到独立进程 → 4 ms、6 ms 两次 `scriptInitiated` 的 about:srcdoc 再导航（srcDoc 随代号表与引用角标到达而变化）。
- 截图（含案卷文字，不入库）：`kimi-work-legal-demo-artifacts/2026-11-24-b62/preview-blank/01～04`。

## 最小复现（Electron 44.5.1，本目录 probe-electron-srcdoc.cjs）
自定义特权协议 + 正式包 CSP + sandbox="" srcdoc 框架，capturePage 数深色像素：

| 做法 | 结果 |
|---|---|
| 插入带 srcdoc 的框架，0/2/3/10/50 ms 后原地改 srcdoc | 0 像素（空白），多次稳定复现 |
| 同上，200/600 ms 后改 | 正常 |
| 每次内容变化都换新框架元素（0/1/2 ms 间隔） | 每次正常 |
| 窗口隐藏/最小化时插入框架后再显示 | 正常（与遮挡无关） |

## 结论
根因是“同一个跨进程隔离框架在首次导航提交前被再次导航”，与 CSP、协议、沙箱、文件内容、内核渲染无关；开发形态走 HTTP 开发桥、代号表到得慢（>200 ms），所以只在安装包稳定出现。
修复：`SafePreview` 以内容摘要（`previewFrameKey`）作 iframe 的 key，内容一变就换新元素；加“重新载入预览”；任务页与复核页的 Office 预览失败显示原因与重试，不再误报“不能预览”。
