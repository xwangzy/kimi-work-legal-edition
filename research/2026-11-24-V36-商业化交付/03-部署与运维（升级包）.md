# 第 62 批云端升级包：部署、配置与回滚（给运维）

适用：`legal.matetrip.cn`（部署名 stg-116，当前代码 = 云端仓库 `kimi-work-legal-demo-cloud` 的 `5f70e53`）。
升级目标：云端仓库标签 **`v1.1.0`**（自 monorepo 第 62 批导出；GitHub `xwangzy/kimi-work-legal-demo-cloud` 与 Gitee `xcsi/kimi-work-legal-demo-cloud` 同步）。
本升级在本机虚机副本（Ubuntu 24.04，与线上同版 5f70e53、同口径数据）上完整演练过升级 → 核对 → 只回滚代码 → 再升级 → 数据还原，记录见 §6。

## 1. 这次升级改了什么（运维需要知道的）

| 项 | 影响 |
|---|---|
| 计费：价目改按**上游型号**（成本缺省取 Kimi 官方价，售价 = 成本 × 加价倍率，可按型号覆盖）；额度改按**价目加权的金额**扣（缓存命中按命中价） | 升级后**首次启动自动迁移一次**：套餐额度由 token 换算成金额（系数 4.2 元/百万 token：标准 5,000 万 → 210 元、试用 2,000 万 → 84 元），律所当月已用连续；原值存进迁移记录，可在控制台一键还原。账本行一律不改写 |
| 网关：全流采集 usage（含 `choices[].usage`）、缓存写入按 5 分钟 / 1 小时分档、上游没给 usage 时估算只记“待对账”（不扣额度、不计金额，并发告警） | 无配置变更 |
| 注册：手机号 + 短信验证码（赛邮云）、注册管理一级菜单、平台注册邀请码（批量生成、导出、停用、使用记录、并发占用） | 升级后短信**默认关闭**、`phone_required` 默认 false，注册方式保持原值——不配置就与升级前一致 |
| 控制台：信息架构与视觉重做（三分区、注册管理、模型与价目、告警独立成页） | 升级脚本自动重建并替换静态页（保留 config.json） |

**不需要改 `/etc/kwl/*.json`。** 特别注意：**不要**在线上 `control-plane.json` 里写 `"sms": { "allow_dry_run": true }`（那是给测试部署用的：验证码随应答返回、不发短信）。

## 2. 升级步骤（约 10 分钟，其中服务重启约 1 分钟）

1. 先记一份升级前快照（可选，供比对）：控制台“总览”“客户”截图，或 `GET /v1/ops/tenants` 的各律所百分比。
2. 取代码：服务器上 `cd /opt/kwl/app && sudo git fetch --tags origin`。
   离线时用随附的 `kimi-work-legal-demo-cloud-v1.1.0.bundle`：`sudo git fetch /path/to/kimi-work-legal-demo-cloud-v1.1.0.bundle 'refs/tags/*:refs/tags/*'`。
3. 升级：`sudo bash deploy/scripts/upgrade.sh v1.1.0`
   （脚本自带：备份 → 切代码 → 共享契约包核对 → `npm ci` → 重建控制台 → 依次重启 cp-signer / control-plane / gateway / search → 健康检查；任何一步失败即停并打印回滚命令。）
4. 核对（系统管理员登录控制台，或用接口）：
   - 健康：脚本最后四个 ✓。
   - 迁移：“模型与价目”页顶部显示“价目已按上游型号”，或 `GET /v1/ops/billing/migrations` 的 `b62_billing.status = applied`，`coefficient_cny_per_mtok = 4.2`。
   - 套餐：“套餐”页标准 210 元/席/月、试用 84 元（`GET /v1/ops/plans` 的 `quota_unit = cny`）。
   - 价目：`GET /v1/ops/pricing` 的 `basis = model`，`kimi-k3.1-pro` 成本 13 / 1.3 / 68（写入 5 分钟 13、1 小时 26），售价 = 成本 × 1.0。
   - 各律所本月百分比与升级前基本一致（价目生效前的用量按 4.2 元/百万 token 折算，生效后的按实际价目，有小幅差异属正常）。

## 3. 升级后配置（在控制台完成，数据都只在服务端）

1. **定价**（“经营 → 模型与价目”）：确认成本价（缺省为官方价）与加价倍率；需要按型号定售价时在这里改，保存即生成新价目版本、约 15 秒后网关按新价计；历史行按原版本记账。
2. **短信**（“客户 → 注册管理 → 短信服务”）：服务商赛邮云；AppID、AppKey（复用 MaaS 生产账号，只写不回显）、签名“北京中软国际信息技术”（不带【】）、注册与找回模板项目 `EdZFV1` → “测试连接”（查余额）→ “发送测试短信”（填一个收码手机号）→ 启用。若赛邮云开了 IP 白名单，先把 116.63.192.237 加进去。
3. **客户端最低版本**（“注册管理 → 注册策略”或“系统”）：**开启“必须验证手机号”或开始发 12 位注册邀请码之前**，先把最低版本设为 `0.3.0`（旧客户端不认识这两项，只会看到通用失败提示）。
4. **注册策略**：开放自助 / 只凭码 / 关闭；是否必须验证手机号；试用套餐、天数、席位。对外推广期建议“只凭码 + 必须验证手机号”，批量客户交付用“邀请码”页按批次生成（数量、有效期、可用次数、批次名、可选套餐与试用天数席位），导出 CSV 发给客户。

## 4. 回滚

| 情形 | 做法 |
|---|---|
| 只回滚代码（数据保留） | `sudo bash deploy/scripts/rollback.sh`（回到 upgrade.sh 记下的 5f70e53）。旧版能直接读迁移后的数据：价目里保留派生的按别名价、金额套餐第 56 批起就支持；演练中旧版各页与网关计价正常。**回滚前**先在控制台关闭“必须验证手机号”、把注册方式改回原值（旧代码不认识 12 位注册邀请码）；短信设置与注册邀请码在旧代码下次写盘时丢失（需要保留就先备份状态快照） |
| 还原计费迁移（代码不动） | 控制台“模型与价目 → 迁移记录 → 还原”（危险操作，要复核密码），或 `POST /v1/ops/billing/migrations/b62/revert`：套餐、律所自定额度、个人上限回到 token 原值（迁移后又改过的项不动并列出），之后不再自动迁移 |
| 整体回到升级前 | `sudo bash deploy/scripts/rollback.sh --restore /var/backups/kwl/kwl-<升级时间>.tar.gz`（会停全部服务；用量账本、审计链等只增不改的账保留恢复前那份，见脚本说明） |
| 只停用新功能 | 短信 `enabled=false`（先关“必须验证手机号”），注册方式改回原值，整批停用注册邀请码 |

## 5. 客户端接入

正式安装包 0.3.0（Windows EXE、macOS DMG）连同一个云端（release.json 与第 60 批相同，sha256 `ff332932…0397`），对旧云端按 `/v1/meta` 能力字段自动走旧注册流程，对新云端启用手机号与邀请码。
客户无需开发环境：安装 → 注册（按策略填手机号验证码 / 邀请码）→ 登录与设备授权 → 使用。安装说明见交付目录。
