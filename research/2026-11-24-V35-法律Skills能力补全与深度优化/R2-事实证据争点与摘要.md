### legal-element-extraction（法律核心要素提取）

1. **基本信息**：原子技能；约 510 行 / 26 KB；不依赖北大法宝 MCP 或其他检索服务，纯提示词。
2. **业务价值**：把口语化叙事（客户口述、聊天记录、媒体报道）拆成可进入法律推理的事实单元，并初步对到请求权要件。面向律师接案初期与学术评测（CAIL 要素识别、LEVEN 事件检测）。与执业律师业务匹配度：**中**——它解决的是“一段叙述→事实结构”，适合新案访谈阶段；律师正式办案时的输入多是成卷书面材料，关键不在分类而在“每条事实能回到哪份材料哪一句、谁说的、律师认不认”，这一点本技能没有覆盖。
3. **专业逻辑**：三层穿透（生活叙事→法律相关事实→要件事实）；九类事实单元（主体、行为、时间、地点、对象、结果、因果、主观、程序）；四种属性辨析（客观事实 / 主观判断 / 法律评价 / 背景信息），要求把评价性说法还原为可证明的行为或状态；生活语言转规范用语；要件映射表（满足 / 部分满足 / 缺事实）。
   - **依据核查（法规库已查）**：民法典第 675 条（借款人按约定期限返还）、第 679 条（自然人借款自提供借款时成立）、第 148 条（欺诈可撤销）、第 152 条（撤销权一年除斥期间）、第 582 条（履行不符合约定的违约责任）——条号与要点均与现行文本一致。消费者权益保护法第 55 条（未入库，**未核**；依记忆为 2013 修正后的惩罚性赔偿条，口径一致）。
   - **专业瑕疵**：①示例一把“借款人有履行能力但拒不履行”列为主观事实，叙述中并无任何履行能力的事实，自相违反其“不得把评价当事实”的原则；②“删除微信”被转写为“拒绝与债权人沟通”，属推论，应标推论而非客观事实；③“多次催告（可构成时效中断）”未提示时效中断需要可举证的催告（民法典第 195 条第一项，已查），口头催告举证难；④买卖瑕疵示例未提检验期与通知义务（民法典第 621 条，已查）这一买方最常输的抗辩点；技术开发示例把“要求退款”直接标为“解除权行使”，没有检查解除事由（第 563 条）与通知到达（第 565 条，已查）。
4. **工程设计**：模板 A（九类清单）、B（原述→客观化→标签→要件→证据来源→争议状态）、C（时间轴）；14 项质量清单。成熟度：可直接执行，但几乎全部检查项靠模型自评（如“是否已转化为法律语言”），**不可检验**；没有“回到原文”的锚点要求，证据来源只写“可能的证据形式”；九类分类对下游文书无直接用处，属过度设计；没有对多份材料、矛盾说法、增量整理的处理。
5. **问题与缺陷**：无出处回链；“主观事实”一类诱导模型补写故意、明知、履行能力等无据推断；“法律语言转化”可能把评价重新带回事实层；不区分“谁说的”（陈述人）与“谁做的”（行为人），而这是诉讼事实整理的第一要义。
6. **与产品对照**：
   - `casefile-organize/SKILL.md` 第 3 节第 3～5 步：一事一行“谁+何时+做了什么+金额”，`quote` 逐字摘录、`kind` 仅 claimed / inferred / to_confirm、推论须写推理依据、矛盾成对提交、金额大小写与合计逐处核对、期限用 `calc.deadline` 算最保守届满日；第 6 节自检“客户陈述、对方陈述没有被写成已查明事实”。
   - 内核 `review-cards.ts` submitFacts：逐字引文在材料文字视图中定位（anchor_status）、代号必须是本事项已有的、与已有事实去重；`facts.list` 只让 lawyer_status=confirmed 的事实进入文书确定陈述。
   - **产品更好**：可回链、律师确认闸门、确定性去重与定位，远强于本技能。
   - **产品缺**：①对 statement 本身没有“去评价化”约束——模型可以提交“被告构成根本违约”“对方恶意拖欠”这类评价句作为 claimed 事实，内核不拦；②`party` 字段语义是“涉及主体”，没有“陈述人 / 材料立场”（起诉状、答辩状、律师函、客户口述属单方陈述），只能靠自检；③没有“诉讼外承认”（对方回函、聊天中对不利事实的承认）的专门标注，而 `issue-evidence-matrix` 的《证据分析》要求把它列为核心证据。
7. **建议决策**：**吸收**（规则写进 `casefile-organize` 第 3 节第 3 步与 `intake-notes`；评价词与多事件检查做进 `facts.submit` 的返回告警）。依据：产品框架已优于本技能，只缺“去评价化”“陈述人”两条可执行的规则。预期收益：事实时间线里不再混入结论句，下游起诉状 / 代理词引用“律师确认事实”时不会把评价当事实写进去。优先级 **P2**。
8. **可吸收的设计精髓**：
   - 事实陈述去评价化：提交 claimed 事实时，statement 只写可被证据证明的行为、状态、数额、时间；“构成违约 / 欺诈 / 恶意 / 违法 / 根本违约 / 过错”等规范评价只能出现在“某方在某材料中称……”的归属句中。【可确定性检查】`facts.submit` 对 statement 做评价词表匹配：命中且该词不在 quote 原文中（说明是模型自己加的评价）→ 返回 warning 要求改写或改 kind=inferred。
   - 陈述人与行为人分离：来源是起诉状、答辩状、律师函、对方回函、客户口述或访谈纪要的，statement 写成“X 在《材料名》中称……”，不直接陈述“发生了什么”。【可确定性检查】给 `facts.submit` 加可选字段 `asserted_by`（我方 / 对方 / 第三方 / 中立记录）；来源材料被编目为“当事人陈述类”而 asserted_by 为空时告警。
   - 一事一行：一条事实不得同时含两个以上不同日期或两个以上不同金额。【可确定性检查】statement 中日期模式计数 >1 或金额模式计数 >1 → warning“请拆成多条”。
   - 时间必填：行为类事实须有 occurred_on（可只到年或月）；材料无日期的必须 kind=to_confirm。【可确定性检查】kind=claimed 且 occurred_on 为空且 statement 含行为动词 → 告警。
   - 程序性事实优先：催告、通知、对账、承诺还款、异议、解除通知、送达，是时效中断（民法典第 195 条）、合同解除（第 565 条）、质量异议（第 621 条）的要件事实，整理时逐项检索这几类动作，缺失或无书面载体的写进《缺口清单》“无证据支撑”类。
   - 诉讼外承认单独标注：对方在回函、聊天、对账回执中对不利事实的承认，标“可能构成诉讼外承认”，并注明它不是民事证据规定第 3 条意义上的诉讼中自认（已查：该条限于诉讼过程中），需作为书证或电子数据举证、由法院综合判断。
   - 主观状态不入 claimed：明知、故意、恶意、有无履行能力等只能作为 inferred 提交，statement 写出所依据的事实编号。

### structured-element-extraction（结构化要素清单）

1. **基本信息**：原子技能（自我定位为下游推理前的“质量闸门”）；约 580 行 / 33 KB；不依赖检索服务。
2. **业务价值**：把一个法律问题（合同、侵权、犯罪构成、行政行为、劳动）拆成分层要件清单，逐项标状态并做完整性校验。面向律师、法官与评测。与执业律师业务匹配度：**中高**——“请求权→要件→事实→证据”是诉讼律师的基本功，本技能的分层与完整性校验思路可用；但犯罪构成、行政合法性两套框架与产品业务线（无刑辩线）无关。
3. **专业逻辑**：要件来源分法定 / 司法解释 / 学理实务三类；五种状态（已满足、未满足、待查证、不适用、存在争议）；层级 L1 法定要件必须全覆盖、L2/L3 细化；“三重校验”——框架完整、材料事实是否都被某要件吸收、要件间逻辑是否自洽；五条验证规则（法源锚定、原子性、MECE、状态唯一、“已满足”必须有事实来源否则降级）。
   - **依据核查（法规库已查或依记忆核）**：民法典第 143、180、188、577、590、1165、1173、1175 条用于对应要件，已在库内逐条取原文，条号与要点正确；期间规则第 201、202 条已查（用于下面的日期纠错）；劳动合同法第 47 条（含第二款三倍封顶）已查。行政诉讼法第 70 条、社会保险法第 58 条、劳社部发〔2005〕12 号（未入库，**未核**；依记忆仍有效）。
   - **专业错误（已查）**：①侵权示例“事故 2024-03-15、三年时效至 2027-03-14 届满”——按民法典期间规则（开始当日不计入；按年计算的以到期月对应日为末日），应为 **2027-03-15**，差一天；这正是产品 `calc.deadline` 要消灭的错误类型。②劳动示例写于 2024 年，未体现《劳动争议解释（二）》（法释〔2025〕12 号，库内 `jud_labor_dispute_interp2`）：第 7 条把“未订书面合同是否因劳动者故意或重大过失”的举证责任明确放在用人单位，第 6 条二倍工资按月计算，第 9 条排除“视为已订无固定期限”期间的二倍工资——示例把“过错方”只标“待查”、未写举证责任方，口径已落后。③违法解除赔偿金计算未检查月工资三倍封顶（劳动合同法第 47 条第二款），产品 `calc.labor` 已内置。④犯罪构成只给四要件体系，未提三阶层，且产品无刑事线，不相关。
4. **工程设计**：两套模板（标准清单 / 简洁核查表）、单要素与整体置信度、三重校验与“可否进入下一阶段”结论。成熟度：结构清楚、可执行；V-05（“已满足”必须挂事实来源）与“第二重校验”（材料里未被吸收的事实）是本技能最有工程价值的两条，可代码判定；MECE、原子性检验靠模型自评，空转风险高；置信度三档主观。
5. **问题与缺陷**：“已满足 / 未满足”是事实认定口吻，律师内部稿可以用，但不宜出现在给客户或法院的文书中；没有区分“要件事实是否有证据”与“对方是否争执”（无争议要件不需重点举证）；没有举证责任列（只在别的技能里有）；示例日期计算差一天说明它对期间计算没有工具化。
6. **与产品对照**：`issue-evidence-matrix/SKILL.md` 第 3 节第 1～6 步 + `references/claim-elements.md`（七类常见请求权 + 通用抗辩清单）已有“请求权基础（核验）—要件—一般举证方—待证事实—事实状态—事实编号—证据—证明目的—覆盖评估（已有 / 薄弱 / 无）—评估理由—缺口”，并有“未纳入事实”“抗辩与反驳”“补证清单”工作表。产品**更好**之处：请求权基础必须 `citations.verify`、事实只用律师确认的、覆盖评估不下事实认定结论、补证动作带责任人。产品**缺**：①没有“对方是否争执”一列（不争执的要件可依自认免证，民事证据规定第 3 条，已查）；②没有反向覆盖检查——律师已确认的事实有没有一条也没挂到任何要件（可能漏了请求或抗辩）；③“覆盖评估=已有”但证据列或事实编号为空的行，目前只靠自检。
7. **建议决策**：**吸收** + 部分**重构**。落地：`issue-evidence-matrix/SKILL.md` 第 3 节第 3～4 步与第 5 节“要件矩阵”列定义（加“对方态度：认可 / 争执 / 未表态”列）；在 `deliverable-check.ts` 对标题含“争点证据矩阵”的表加两条确定性检查。预期收益：矩阵不再出现“已有证据却没写证据”的空行，律师确认的事实不会被矩阵漏掉。优先级 **P1**（确定性检查）/ P2（列定义）。
8. **可吸收的设计精髓**：
   - “已有证据”必须可回链：要件行的覆盖评估为“已有”或“薄弱”时，证据（材料名·位置）与事实编号两列都不得为空，事实编号必须是本事项存在的“事实 N”。【可确定性检查】按列名读表，空值或 `factRefNos` 解析出的编号不在 `facts.list` 中 → 必须改。
   - 反向覆盖：律师已确认（lawyer_status=confirmed）的每条事实，必须出现在“要件矩阵”或“抗辩与反驳”某行的事实编号里，或在“未纳入事实”中写明“与本案请求无关”的理由。【可确定性检查】集合差为空才通过；不为空的列出事实编号。
   - 每个请求至少一行“诉讼时效”抗辩：民商事给付请求的矩阵中，“抗辩与反驳”页必须有时效行，且届满日来自 `calc.deadline`。【可确定性检查】按请求项分组检查是否存在含“时效”的抗辩行。
   - 区分“有没有证据”和“对方争不争”：对每个要件记录对方态度（诉状 / 答辩 / 庭审笔录 / 回函中是否认可），对方已明确认可的要件，标“可依自认免证”，补证优先级降为低，但仍保留证据以防撤销自认（民事证据规定第 9 条，已查）。
   - 期间与金额不手算：要件涉及时效、除斥期间、检验期、二倍工资月数、经济补偿年限的，一律调用 `calc.deadline` / `calc.labor`，矩阵中只填工具结果与口径前提。【可确定性检查】矩阵中出现“届满”“个月”且无对应工具调用记录 → 告警。
   - 司法解释更新优先：劳动类要件框架以《劳动争议解释（二）》（2025）为准，二倍工资行须写出“用人单位对不可抗力或劳动者故意、重大过失未订立承担举证责任”（第 7 条，已查）。建议把这一行补进 `claim-elements.md`（目前七类请求权里没有劳动类，劳动走 `labor-dispute`，需在该方法的举证责任表核对是否已写）。

### dispute-issue-identification（争议焦点识别）

1. **基本信息**：原子技能；约 125 行 / 7 KB，是本组最短的一个；不依赖检索服务；正文为通用说明 + 4 个只有题目没有答案的示例。
2. **业务价值**：从双方主张中分离事实争议与法律争议，转写为可裁判的问题，并分核心 / 次级 / 背景三层。视角以**法官**为主（归纳焦点、庭审结束前征求双方意见是审判职能，见民诉法解释第 226 条，已查）。与执业律师业务匹配度：**中**——律师需要的不是“归纳焦点”本身，而是“法庭会怎么归纳、我方如何争取对我方有利的焦点表述、焦点之外哪些事实已经固定”，这几点本技能没有触及。
3. **专业逻辑**：识别当事人→识别各方主张→区分事实分歧与法律评价分歧→规范化为疑问句→分层→各方支持事由（事实、证据、规范）→随庭审动态调整。思路正确但停留在原则层。
   - **依据核查**：正文未援引具体条文。对照现行规则（已查）：民诉法解释第 226 条（法院依诉请、答辩与证据交换归纳焦点并征求意见）、第 228 条（庭审围绕焦点进行）、第 229 条（准备阶段认可的事实与证据，庭审中反悔须说明理由，理由成立才列为焦点）；民事证据规定第 53 条（当事人主张的法律关系性质或行为效力与法院认定不一致时，法院应将其作为焦点审理，当事人可据此变更诉讼请求）。本技能**未提第 53 条**，而示例 1（借款还是投资款）恰恰是该条的典型情形——律师此时要准备备位请求或变更诉请，这是诉讼代理最关键的应对之一。
4. **工程设计**：没有输出字段定义、没有质量检查清单、没有与事实或证据的引用关系；“结论→理由→依据”的输出建议与“争点用中性疑问句”的要求自相冲突。成熟度：**低**，可直接执行但不可检验，结果高度依赖模型自由发挥。
5. **问题与缺陷**：角色混同（律师工具不应替法庭“征求双方意见”）；缺“无争议事实固定”（证据交换或庭前会议中双方认可的事实，民诉法解释第 225、229 条，已查），这类事实是律师后续代理词与上诉状最省力的立足点；缺“焦点表述的立场性”——同一焦点的不同问法（“被告是否已付清货款” vs “原告是否证明尚欠货款”）隐含举证责任分配，律师需要警惕不利表述。
6. **与产品对照**：
   - `case-analysis/SKILL.md` 第 3 节第 2 步：2～6 个争点、事实与法律争点分开、法院已归纳的以其为准否则写“拟归纳”、每个争点写一般举证方。
   - `hearing-outline/SKILL.md` 第 3 节第 1 步：争点清单以法庭归纳为准，未归纳的从诉状、答辩状推出并标“推论，待律师确认”，每争点写双方主张、举证责任方、关键事实与证据编号。
   - `agency-statement/SKILL.md` 第 3 节第 1 步：围绕法庭归纳的焦点逐个论证，对方庭审中的自认与前后矛盾单独引出并注笔录出处。
   - `appeal-draft/SKILL.md` 第 2 节第 2 步：把一审“本院认为”的每个争点拆出。
   - **产品已有并更好**：争点与事实编号、证据编号绑定，法庭归纳优先。**产品缺**：①争点是每个方法各自重新归纳的，没有事项级的“争点表”——同一案件的案情分析、庭审提纲、代理词、上诉状可能出现四套不一致的焦点表述；②没有“无争议事实”这一类别（`facts.submit` 的 kind 没有“双方认可”）；③没有提示民事证据规定第 53 条情形下的备位请求或变更诉请。
7. **建议决策**：**融合**（把要点并入上述四个方法的争点步骤）+ **新增**（内核事项级争点登记 `issues.submit / issues.list`，P2）。依据：本技能本身单薄，但它指向的“争点作为跨方法共享对象”是产品结构缺口。落地位置：`platform/packages/kernel/src/tools/registry.ts` 新增两工具（字段：issue_no、表述、类型 事实/法律、来源 法庭归纳/拟归纳、来源引文与材料、我方主张、对方主张、一般举证方、关联事实编号与证据）；`case-analysis` / `hearing-outline` / `agency-statement` / `appeal-draft` 的争点步骤改为“先 `issues.list`，没有再归纳并提交”。预期收益：同一事项各文书争点口径一致，律师在事项页可逐条确认焦点。优先级 **P2**（工具）；第 53 条提示与无争议事实列为 **P1**（只是方法步骤，改动小、对庭审价值大）。
8. **可吸收的设计精髓**：
   - 法庭归纳优先且逐字：法庭已归纳焦点（庭前会议笔录、庭审笔录、判决“本院认为”）的，焦点表述逐字摘自笔录并附材料与位置，不得改写；未归纳的标“拟归纳”。【可确定性检查】来源=法庭归纳的焦点，其引文必须能在材料文字视图中逐字定位（复用 submitFacts 的 locateQuote）。
   - 定性分歧触发备位应对：双方对法律关系性质（借款 / 投资、买卖 / 借贷、劳动 / 劳务）或合同效力有分歧时，单列一条“定性焦点”，并在下一步建议中写明是否需要备位诉请或变更诉请（民事证据规定第 53 条第二款，已查）。【可确定性检查】争点类型=定性 时，案情分析的“下一步建议”中必须有一条含“变更诉讼请求 / 备位”的动作。
   - 无争议事实单列：证据交换、庭前会议或答辩状中对方明确认可的事实，记为“双方认可”（附笔录出处），在代理词、上诉状中作为不需论证的前提；对方庭审中反悔的，提示依民诉法解释第 229 条要求其说明理由。【可确定性检查】给事实增加 `agreed_by_opponent` 标记，必须带对方材料的逐字引文。
   - 焦点表述的举证责任中立性：每个焦点写两种可能问法并指出各自隐含的举证负担，律师选定我方建议的表述；表述中不得预设结论（如“被告违约后……”）。
   - 分层与取舍：核心焦点（决定请求或抗辩成立）≤4 个，其余列次级；背景分歧不进入代理词正文。【可确定性检查】代理词按焦点分节时，节数与 `issues.list` 中来源=法庭归纳的焦点一一对应，缺节或多节报出。

### evidence-evaluation（证据效力评估）

1. **基本信息**：原子技能（篇幅接近复合技能）；约 1,225 行 / 59 KB；不依赖检索服务。覆盖民事、刑事、行政三大诉讼；含星级置信度体系、致命错误表、两个完整示例（民间借贷、故意伤害）。
2. **业务价值**：逐份证据审“三性”与证明力，再按待证事实做全案综合判断与补强建议。面向律师（举证、质证准备）、法官、学术评测（AR-Bench 判决纠错）。与执业律师业务匹配度：**高**（主题）/ **中**（内容）——民商事律师每案都要做“我方证据自查 + 对方证据质证 + 证据链缺口”，但本技能在关键规则上沿用了 2001 年旧证据规定的体系，直接照用会出专业错误。
3. **专业逻辑**：证据能力（真实、合法、关联）→ 证明力（单一证据、相互印证、证据链）→ 对照证明标准与举证责任 → 结论四档（充分 / 基本充分 / 不足 / 矛盾）→ 补强。按证据种类给证明力高低因素表（书证、证言、电子数据、鉴定意见、当事人陈述）。
   - **依据核查（均在法规库取原文核对）**：
     - 民事诉讼法第 66 条（八类证据）、第 67 条（谁主张谁举证）、第 84 条（证据保全）——按 2023 修正本条号**正确**。
     - **证明标准有误**：本技能把欺诈、胁迫、恶意串通、口头遗嘱、赠与写成“高于高度盖然性、但在排除合理怀疑以下”的中间标准。现行规则恰恰是**排除合理怀疑**（民诉法解释第 109 条、民事证据规定第 86 条第一款，已查）。一般事实的标准，现行条文用语是“高度可能性”（民诉法解释第 108 条第一款，已查），本技能另加“通常理解为 75% 以上”，无法律依据，不应进入产品；反驳方只需使待证事实真伪不明（第 108 条第二款）这一不对称规则本技能没写。程序事项（保全、回避）为“可能性较大”（民事证据规定第 86 条第二款），本技能写作“优势证据”，大意接近。行政诉讼“明显优势”标准无成文依据（未核，学理用语）。
     - **举证责任**：只写民诉法第 67 条，缺核心分配规则——民诉法解释第 91 条（主张法律关系存在者证明产生要件事实；主张变更、消灭、妨害者证明相应要件事实，已查）。“医疗损害举证责任倒置”**已过时**：民法典第 1218 条为过错责任，只在第 1222 条三种情形推定过错（已查）；“产品责任倒置”不准确（受害人仍证缺陷、损害、因果关系，生产者证免责事由，产品质量法第 41 条，未入库，**未核**）；环境污染因果关系倒置（民法典第 1230 条，已查）正确。
     - **证明力优先顺序（第 4.2 节）已废止**：七条位阶（公文书证优于其他书证、原始优于传来、直接优于间接等）是 2001 年旧证据规定第 77 条的内容，2019 年修正已删除；现行为法官依法定程序独立判断证明力有无与大小（民事证据规定第 85 条第二款），审核因素见第 87、88 条（已查）。
     - **补强规则（第 4.3 节）口径过时**：现行第 90 条列五类（当事人的陈述；无民事行为能力人或限制民事行为能力人的不相当证言；利害关系证人证言；存有疑点的视听资料、电子数据；无法与原件核对的复制件，已查）。本技能漏了“当事人的陈述”，却把“无正当理由未出庭的证人证言”列为“不能单独作为依据”——现行第 68 条第三款对这类书面证言是**不得作为认定事实的根据**（已查），是排除而非补强。其民间借贷示例因此把未出庭证人的书面证言评为“低证明力、间接印证”，结论错误。
     - **条号错位**：书证提出命令写第 47～49 条，应为第 45～48 条（第 49 条是被告书面答辩，已查）；电子数据“真实性审查要素”写第 14～15 条，第 14 条是范围、第 15 条是原件，真实性审查在第 93、94 条（已查）。
     - **域外证据（第 3.4、8.3 节）过时**：写成“一律公证 + 使领馆认证”，这是 2001 年旧规定的口径。现行第 16 条（已查）只要求**公文书证**经所在国公证或履行条约证明手续，**身份关系证据**才需公证 + 认证（或条约手续）；私文书证不再强制。另，《取消外国公文书认证要求的公约》自 2023-11-07 起对我国生效，缔约国之间以附加证明书替代领事认证（依记忆，**未入库核**）。
     - 非法证据：民事部分写“严重侵害他人合法权益、违反法律禁止性规定或严重违背公序良俗”，与民诉法解释第 106 条一致（已查）。
     - 示例一把“年利率 12% 未超上限”放在证据**合法性**栏——混淆了证据合法性（取证方式与形式）与合同内容的合法性，概念错误。
4. **工程设计**：四阶段十二步 + 四关可采性筛选 + 星级置信度 + 致命错误表 + 质量清单。成熟度：结构完整但过长（59 KB 一次装载代价高），三大诉讼混写，刑事、行政部分与产品无关；星级和“胜诉可能性较高”这类表述与产品“不打分、不算百分比、不预测”的准则冲突；大量检查项依赖模型自评，不可检验。
5. **问题与缺陷**：见第 3 项——证明标准、证明力位阶、补强规则、域外证据、未出庭证言、医疗损害举证这六处与现行法不一致，是本组专业风险最高的技能。若产品吸收，必须以现行条文重写，不能借用其表格。
6. **与产品对照**：
   - `cross-exam-opinion/SKILL.md` 第 3 节第 1～2 步：对方证据逐份三性 + 证明目的，否认真实性必须写具体疑点、未见原件保留意见、需鉴定 / 证人 / 调取的列“待办”并给出第 69、20、31 条的期限口径——**产品在质证一侧更好**（克制、可执行、条号正确）。
   - `case-analysis/SKILL.md` 第 3 节第 3 步：证据强弱三档（已有 / 薄弱 / 无），理由按真实性、合法性、关联性、证明力写，不打分；`issue-evidence-matrix` 的《证据分析》有三性初判。
   - **产品缺**：①没有任何方法写证明标准（高度可能性 / 排除合理怀疑 / 可能性较大），涉及欺诈、恶意串通、赠与、口头遗嘱的争点无提示；②没有“我方证据自查”——起诉状、答辩状、仲裁申请书的证据目录只列名称与证明目的，不检查复印件无原件、截图无原始载体、未申请出庭的证人、境外公文书证缺证明手续、外文无译本、需单独补强的五类证据；③`cross-exam-opinion`、`agency-statement`、`case-analysis`、`defense-draft` 仍写“法规库没有收录民事诉讼法 / 民诉法解释 / 民事证据规定”，与库内事实不符（见文首）。
7. **建议决策**：**重构**（证据形式规则做成确定性核对）+ **吸收**（证明标准与补强规则写进方法）。落地：①内核新增 `evidence.rules_check`（或作为 `xlsx.render_table` 生成证据目录时的附加检查）：输入证据目录行的属性（证据种类、原件 / 复印件、形成地境内 / 境外、是否公文书证、是否涉身份关系、语言、电子数据是否有原始载体、证人是否已申请出庭、提供方），输出逐行规则提示与条号（全部取自库内民事证据规定、民诉法解释原文）；②`case-analysis`、`issue-evidence-matrix` 的证据强弱步骤加“证明标准”一列；③改正四个方法里“法规库未收录程序规定”的过时说法。预期收益：我方证据在举证前就暴露可被攻击的形式瑕疵；证明标准表述从此有条文出处。优先级 **P1**（①③）/ P2（②）。
8. **可吸收的设计精髓**：
   - 证据形式规则核对（我方举证前、对方质证时通用）：【可确定性检查】按证据属性逐行出提示——复印件且无原件可核 → 第 90 条第五项需补强、质证时对方可不认；电子数据无原始载体 → 第 15 条第二款原件要求、建议当庭出示原始载体或公证保全；境外形成的公文书证 → 第 16 条第一款证明手续；境外身份关系证据 → 第 16 条第二款；外文 → 第 17 条中文译本；证人未申请出庭 → 第 69 条第一款在举证期限届满前申请，否则其书面证言依第 68 条第三款不得采用；对方控制的书证 → 第 45～48 条书证提出命令须在举证期限届满前书面申请（民诉法解释第 112 条）。
   - 证明标准按争点自动标注：争点或待证事实涉及欺诈、胁迫、恶意串通、口头遗嘱、赠与的，写明适用排除合理怀疑标准（民诉法解释第 109 条）；其余写高度可能性（第 108 条第一款）；保全、回避等程序事实写可能性较大（民事证据规定第 86 条第二款）。不写任何百分比。【可确定性检查】争点文本命中上述五类关键词而交付件未出现“排除合理怀疑” → 必须改；交付件出现“%”“盖然性”与“证明标准”同句 → 必须改。
   - 举证不对称：我方为反驳方时，证据目标写“使待证事实真伪不明即可”（第 108 条第二款），不必证明相反事实成立；这条要写进 `defense-draft` 与 `cross-exam-opinion` 的论证口径。
   - 举证责任按要件分配：在矩阵与案情分析里，“一般举证方”按民诉法解释第 91 条推出（权利产生要件归主张方，变更、消灭、妨害要件归抗辩方），特殊分配只引库内可查条文（民法典第 1165 条第二款、第 1199 条、第 1222 条、第 1230 条，《劳动争议解释（二）》第 7 条等），不写“医疗损害倒置”这类旧口径。
   - 补强证据五类：当事人陈述、无 / 限制行为能力人的不相当证言、利害关系证人证言、存疑视听资料与电子数据、无法核对原件的复制件，只能与其他证据结合认定；在证据强弱评价中这五类不得单独评为“已有证据”。【可确定性检查】矩阵中某要件唯一证据的种类属于这五类而覆盖评估为“已有” → 告警改“薄弱”。
   - 证明力不设位阶：不写“公文书证优于私文书证”“书证优于证言”这类固定排序；证明力理由按第 87 条五个审核方面与第 88 条相互联系写。
   - 诉讼外与诉讼中自认分开：对方在诉状、答辩状、证据交换、庭审中对不利事实的明确承认（民事证据规定第 3 条）免除我方举证；附条件或限制的承认由法院综合判断（第 7 条）；调解、和解中为妥协认可的事实不得作为不利根据（民诉法解释第 107 条，已查）——后者应写进 `agency-statement` 引用“对方自认”时的排除规则。【可确定性检查】代理词引用的“对方自认”出处材料若为调解笔录或和解协议 → 告警。

### evidence-argument-chain（组织证据论证链）

1. **基本信息**：原子技能；约 1,280 行 / 65 KB（本组最长）；不依赖检索服务。两个完整示例（民间借贷、产品质量侵权）。
2. **业务价值**：建立“主张→要件→证据→证明目的→证明力→缺口→攻防预判→论证顺序”的全映射，用于起诉、答辩、代理词与庭前证据准备。面向诉讼律师。与执业律师业务匹配度：**高**——这就是律师做证据目录与庭审准备的核心工作，且它提出了几个产品尚未覆盖的维度（证明方式、不利证据、一证多用、论证顺序）。
3. **专业逻辑**：证据-要件挂钩四规则（一证多用、多证一要件、写明具体证明目的、标直接 / 间接 / 补强）；证明目的说明要写到具体时间、发言人、原话；证据链按时间与逻辑串联；逐要件五星评级；缺口给多方案补救；挂钩五项验证（关联、证明方向、目的明确、三性、非重复）；完整性四规则；论证顺序五原则（先强后弱、先简后繁、时间线、逻辑递进、攻防兼顾）。
   - **依据核查（法规库已查）**：
     - 民法典第 577、667～680、1165 条，民诉法解释第 112 条，民事证据规定第 3～5、45～48 条——条号与要点**正确**。
     - **证明标准引错**：把民事证据规定第 86 条标为“高度盖然性标准”。第 86 条规定的是欺诈等五类事实的排除合理怀疑标准与程序事项的“可能性较大”，一般标准在民诉法解释第 108 条（已查）。
     - **特殊侵权条号错**：把“特殊侵权、因果关系倒置”对应民法典第 1169～1178 条——这一段是数人侵权与减免责事由（教唆帮助、共同危险、过失相抵、第三人原因、自甘风险、自助等，已查第 1170、1173、1175 条）；特殊侵权在第 1188 条以后各章；因果关系倒置只在环境污染（第 1230 条）。
     - **医疗损害倒置示例过时**：第 8.2 节示例让医方证明“无过错、无因果关系”——现行民法典第 1218 条为过错责任，第 1222 条仅三种情形推定过错（已查），因果关系仍由患方证明（通常借助鉴定）。
     - **公司法条号过时**：“股东损害公司利益”引公司法第 20～21 条，为 2018 年旧法条号；2023 年修订（2024-07-01 施行）后第 20 条是社会责任，股东滥用权利在第 21 条、关联关系在第 22 条、人格否认在第 23 条（已查 `lsv_company_2023`）。
     - **违约金举证分配错**：示例把“违约金数额合理”列为原告必须证明的要件并评为“证据薄弱、高风险”。现行合同编通则解释第 64 条第二款（已查）：违约方主张过分高于损失的承担举证责任，非违约方主张合理的“也应当提供相应的证据”——这是抗辩—反驳结构，不是请求权要件。
     - 违约责任要件写“损害结果 + 因果关系”，只对“赔偿损失”成立；继续履行、支付违约金不以损失为要件（民法典第 577 条严格责任，已查）。
4. **工程设计**：六阶段十五步、矩阵图、证据链图、五星评级、缺口卡、攻防表、论证顺序、多套质量清单。成熟度：方法论成熟、可执行，但冗长（65 KB）；完整性规则 1～3（每要件至少一项直接证据、关键要件至少两项、每项直接证据至少一项补强）**没有法律依据**，属于自设的过高标准，会把大量正常案件判为“缺口”，误导补证；五星评级与产品“不打分”准则冲突。
5. **问题与缺陷**：第 3 项所列 6 处法律错误；“补强”概念被泛化（法定补强只针对民事证据规定第 90 条五类）；没有“对方已认可”的免证维度；没有出处回链（证明目的里的“原话”无锚点要求）。
6. **与产品对照**：`issue-evidence-matrix`（要件矩阵 + 抗辩与反驳 + 补证清单 + 未纳入事实 + 依据与核验）覆盖了本技能的主干，且事实只用律师确认的、请求权基础经核验，**产品更可靠**。`hearing-outline` 第 3 节第 3 步“举证顺序”按争点或时间线排列证据并写证明目的、预计对方质证与回应。`pleading-draft` / `defense-draft` / `arbitration-application` 出《证据目录》附件。**产品缺**：①矩阵没有“证明方式（直接 / 间接 / 补强）”与“证明方向（支持 / 不利）”两列——我方材料中对我方不利的证据（如我方发出的承认逾期的邮件）没有专门位置；②证据目录（起诉状等附件）与矩阵之间没有一致性检查：同一证据在目录里的证明目的与矩阵里的不一致、目录中有证据没对应任何请求、某请求在目录中没有任何证据；③`claim-elements.md` 第四节违约金调整的举证分配仍写“依据待核实”，库内已可引合同编通则解释第 64 条。
7. **建议决策**：**吸收**（列与规则进 `issue-evidence-matrix`）+ **重构**（证据目录—矩阵一致性做确定性检查）。落地：`issue-evidence-matrix/SKILL.md` 第 5 节“要件矩阵”加“证明方式”“证明方向”两列、`references/claim-elements.md` 第四节补第 64 条；`deliverable-check.ts` 对“证据目录”与“争点证据矩阵”同事项同时存在时做交叉核对。预期收益：起诉状证据目录的证明目的与矩阵一致、无“孤儿证据”和“裸请求”；不利证据被看见。优先级 **P1**（一致性检查）/ P2（列）。**不吸收**其完整性规则 1～3 与五星评级。
8. **可吸收的设计精髓**：
   - 证明目的要具体到可核对：每条“证据→要件”的证明目的写明证据中的具体内容（日期、发出人、关键原话或金额）与它要证明的要件事实，一句话；原话须逐字可在材料中定位。【可确定性检查】证明目的中带引号的原话必须能在该证据的材料文字视图中逐字找到。
   - 证据目录与矩阵双向闭合：目录中每份证据至少对应一个请求或抗辩要件；每个请求项在目录中至少有一份证据；同一证据在目录与矩阵中的证明目的不得互相矛盾。【可确定性检查】按证据名称 / 编号做集合比对，列出孤儿证据、裸请求与证明目的差异行。
   - 证明方向标注：我方材料中证明方向不利于我方的证据单列（不进证据目录），在“抗辩与反驳”页写对方可能如何使用、我方如何解释；对外文书不主动提交、也不作虚假陈述。
   - 证明方式与法定补强：标“直接 / 间接 / 补强”；只有民事证据规定第 90 条五类证据才写“需补强”，其余间接证据通过相互印证构成证明，不机械要求“每项直接证据配一项补强”。
   - 抗辩型要件的举证归属：违约金调整、损失扩大、过失相抵、时效届满、已付款等由抗辩方主张的事实，放在“抗辩与反驳”页，举证方写抗辩方；我方作为非违约方仍准备损失证据（合同编通则解释第 64 条第二款）。【可确定性检查】要件矩阵中出现“违约金过高 / 调减”字样且举证方写守约方 → 告警。
   - 论证顺序：庭审举证顺序默认“先无争议后有争议、同一争点先直接后间接、证据链按时间顺序”，在 `hearing-outline` 举证顺序表加“顺序理由”一列。

### argument-chain-construction（构建严密的论证链条）

1. **基本信息**：原子技能（README 将其归入“论证组织与评估”）；约 1,155 行 / 55 KB；不依赖检索服务。两个完整示例（买卖逾期交货违约金、高管竞业限制）。
2. **业务价值**：把推理结果组织为“节点（大前提—小前提—结论）串并联”的论证链，用于意见书、代理词、答辩状、研究备忘录的论证部分。面向律师与学术评测（MSLR、论辩挖掘）。与执业律师业务匹配度：**中高**——三段论节点、防御层、备选论证、表达顺序是代理词与意见书的通用写作法；但它是“写作方法论”，产品已经用 `outline.submit` 把“论点—依据—事实—对方反驳”结构化并交律师确认，本技能的增量主要在**一致性检验**与**谬误清单**。
3. **专业逻辑**：五大质量维度（逻辑有效、前提真实、完整、一致、说服力）；六阶段十五步：准备→架构（串联 / 并联 / 层级）→节点构建→强化（补强、防御层至少三个反驳点、辅助论证八类）→验证（十类逻辑谬误、完整性七问、一致性五法）→表达（首因 / 近因效应排序、每节点标法条到款项、事实到证据编号、区分确定与或然结论）；节点准入四项必须条件。
   - **依据核查（法规库已查）**：民法典第 469、577、585 条，劳动合同法第 23、24 条，合同编通则解释第 65 条——条号正确。
   - **专业错误**：
     - 违约金示例用“违约金占合同总价 1.55%”论证不过高——比较基准错了。合同编通则解释第 65 条（已查）以民法典第 584 条规定的**损失**为基础，超过损失 30% 一般可认定过分高于；与合同总价的比例不是法定比较对象。
     - 备选路径建议“以 LPR 四倍为基准计算违约金”——四倍 LPR 是民间借贷利率保护上限，不是逾期交货违约金的参照标准，属于规则误植。
     - 竞业限制示例转换请求权基础时引反不正当竞争法第九条（商业秘密）——这是 2019 修正本条号；2025 年修订本（2025-10-15 施行，库内 `lsv_anti_unfair_competition_law_2025`）商业秘密条为**第十条**（已查）。行为在新法施行前的仍适用旧第九条，但技能未提示按行为时定版本。
     - 示例给出“约 65%～80%”的整体置信度——与产品“不给胜诉率、不量化”的准则冲突。
4. **工程设计**：两套模板（标准 / 对抗式：主论证 + 对方反驳与回应 + 退守方案 + 结论）；置信度体系；致命错误表；九类领域论证结构对照。成熟度：方法完整，可直接执行；问题是长（55 KB），且大部分检查（谬误、说服力）只能靠模型自评；“至少 3 个反驳点”是形式要求，可能诱导凑数。
5. **问题与缺陷**：见上；另外“辅助论证”鼓励援引类案、比较法、社会效果，而产品没有案例检索与核验工具（`agency-statement` 第 3 节第 2 步：案例只引律师提供的），照用会诱发编造类案。
6. **与产品对照**：
   - `outline.submit` / `outline.get`（`registry.ts`，`services/argument-outlines.ts`）：起草前逐条提交论点、依据（法名 + 条号 + note 说明如何支持）、所用事实（fact_id）、counter（对方最可能的反驳），律师确认后只按确认版起草——比本技能的“节点准入”更硬：律师是闸门。
   - `citation-check/SKILL.md` 第 3 节第 5 步 + `references/argument-mismatch.md`：七类论证失配（裸断言、空泛援引、射程不足、条件遗漏、方向相反、以偏概全、绝对化），三类语义失配必须并列条文原文——这是**产品更好**的部分，比本技能的谬误清单更贴近法律文书。
   - `agency-statement` 第 3 节第 1 步“我方观点→事实→依据→回应对方”与本技能对抗式模板同构。
   - **产品缺**：①论点之间的**一致性检验**——同一事实在不同论点里定性不同、主论点与备位论点前提互斥（例如主张合同有效要求履行，又以无效为由要求返还，却未写明主从关系），`outline.submit` 不检查；`independent-review.ts` 已有“前提互斥”复核条（MUTUAL_EXCLUSION_ITEM，第 58 批 D-238），但只在交付后复核，论点确认前没有；②备位论证（主张不成立时的退守）在 `outline.submit` 里没有字段，律师确认时看不到主从关系。
7. **建议决策**：**吸收**（备位与一致性规则写入 `outline.submit` 的参数与文书方法的论点步骤）+ **重构**（论点一致性做成 `outline.submit` 的提交时检查）。落地：`registry.ts` 中 `outline.submit` 增加 `role`（主张 / 备位 / 反驳回应）与 `depends_on`（依赖的论点编号）字段；提交时内核检查同一 fact_id 是否被两个非备位论点赋予相反定性（基于 statement 中的定性词对：有效 / 无效、成立 / 不成立、借款 / 投资等）。预期收益：律师在确认论点时就看到主从关系与潜在矛盾。优先级 **P2**。**不吸收**：置信度百分比、类案与比较法辅助论证、“至少 3 个反驳点”的形式要求。
8. **可吸收的设计精髓**：
   - 节点三要素齐全：每个论点必须同时有规范依据（法名 + 条号，经核验）、事实依据（事实编号或证据编号）与结论；缺任一项的不得进入确认。【可确定性检查】`outline.submit` 中 basis 为空或 facts 为空的论点直接拒收（当前 counter 已有，补齐这两项的必填校验即可）。
   - 主备关系显式化：互相排斥的论点（有效 / 无效、违约责任 / 缔约过失、借贷 / 投资）只能以“主张—备位”关系同时出现，并写明备位的触发条件（“如法庭认定……”）。【可确定性检查】两个 role=主张 的论点含互斥定性词对 → 拒收并提示改为备位。
   - 比较基准写对：涉及“过高 / 过低 / 显失公平 / 明显不合理”的论证，必须写明法定比较基准（违约金对损失、利率对 LPR 倍数、价格对市场价），不得用自选基准（如对合同总价）。可写进 `citation-check` 的“射程不足”类判定示例。
   - 版本随行为时：论证中引用的法条，按争议行为发生时点取版本（`law.get_article` 的 as_of）；新旧条号不同的（如反不正当竞争法 2019 第 9 条 / 2025 第 10 条），正文写行为时版本并在注中注明现行条号。【可确定性检查】`citations.verify` 已按时点核版本；可在交付前检查中对“修订前后条号不同”的引用加提示。
   - 表达顺序：代理词按法庭归纳焦点顺序分节；每节内部“结论→事实→依据→回应”；最强理由放首节、次强放末节——作为 `agency-statement` 的写作提示，不做硬检查。

### legal-document-summarization（法律摘要）

1. **基本信息**：原子技能；约 600 行 / 26 KB；不依赖检索服务。覆盖判决、裁定、调解书、仲裁裁决、行政处罚决定五类文书，每类一套模板，三个示例。
2. **业务价值**：把冗长裁判文书转成结构化摘要（案件信息、事实、焦点、依据、结果、说理）。面向研究、教学、诉讼分析。与执业律师业务匹配度：**高**（需求）/ **中**（现方案）——律师收到一审判决或仲裁裁决后，要在上诉期内给客户写“判了什么、为什么、对我们意味着什么、还能做什么、截止哪天”，本技能覆盖前两问，后三问（诉请与判项对照、救济期限、履行与执行）缺失。
3. **专业逻辑**：先识别文书类型再选模板；六要素框架；严格区分“当事人主张”与“文书认定”；焦点写成可回答的问题；说理按“事实如何认定→规范如何适用→结论如何得出”概括；剔除送达、合议庭组成等程序套话；二审文书突出与一审的差异；OCR 不确定处用标记并提醒核对金额、日期、案号。
   - **依据核查（法规库已查）**：
     - “裁定只处理程序事项、不涉及实体”过于绝对——民诉法第 157 条（已查）裁定范围含保全与先予执行、撤销或不予执行仲裁裁决等，后者需审查实体问题的一部分。
     - 仲裁裁决一律“一裁终局”不准确：劳动争议仲裁裁决多数非终局，当事人可在收到后 15 日内起诉（劳动争议调解仲裁法第 50 条）；终局裁决劳动者 15 日内可起诉、用人单位 30 日内可申请中院撤销（第 47～49 条，均已查）。
     - 示例一引反不正当竞争法第 2 条、第 12 条（互联网专条）——对 2024 年作出的判决而言是当时的条号，摘要照录正确；但 2025 修订本（2025-10-15 施行）互联网条已为第 13 条（已查）。本技能“文书所引法条已修订的可在摘要中标注”这一原则是对的，示例没有示范。
     - 示例三行政复议 60 日、行政诉讼 6 个月（行政复议法、行政诉讼法未入库，**未核**；依记忆与现行法一致）。
     - 示例一借用真实企业简称、配以虚构案号与案情（且原被告关系与公开报道的真实案件相反），作为样例会诱导模型生成“看似真实”的案号，与其自身仓库“绝不编造案号”的硬规则冲突。
4. **工程设计**：五类模板 + 12 项质量清单 + 6 类特殊场景。成熟度：清楚、短小、可直接执行；但**没有任何回链要求**（只要求“标注来源”），金额、日期、案号的正确性只靠“提醒用户核对”，不可检验；面向“摘要读者”而不是“委托人决策”，没有期限与下一步。
5. **问题与缺陷**：无逐要点出处锚定；无诉请—判项对照；无诉讼费负担与履行期限；无救济途径与期限计算（行政处罚模板有，判决与仲裁模板反而没有）；类型判断未区分商事仲裁与劳动仲裁。
6. **与产品对照**：
   - **产品没有“裁判文书研读”方法**。最接近的三处：`appeal-draft/SKILL.md` 第 2 节第 2 步把一审裁判拆成案号、当事人、一审诉请、“本院查明”每段、“本院认为”每个争点、判决主文每项（含诉讼费），第 3 节第 2 步做“一审认定（逐字摘录 · 页）/ 我方意见 / 错误类型”对照表——但它只在已决定上诉后运行；`enforcement-application` 第 3 节第 1 步逐字摘录执行依据主文；`case-report` 写进展汇报，不研读文书。
   - 期限工具已具备：`calc.deadline`（civil / workday 规则）。库内可取的救济期限条文：民诉法第 171 条（上诉 15 / 10 日）、第 250 条（申请执行二年及起算）、第 264 条（迟延履行加倍利息）；仲裁法 2025 修订本第 72 条（申请撤销裁决**三个月**，2026-03-01 施行，旧法为六个月）；劳动争议调解仲裁法第 47～50 条（均已查）。
7. **建议决策**：**新增**方法 `ruling-digest`《裁判文书研读与汇报》（诉讼仲裁、企业法务线）+ **重构**出一个内核能力“裁判文书分段与引文定位”。理由：收到裁判后 15 日（裁定 10 日）内向客户汇报并决定是否上诉是高频、时间敏感、出错代价高的场景；产品已有的零件（`appeal-draft` 的拆解、`calc.deadline`、facts 的逐字定位）足以拼出，但不应塞进 `appeal-draft`（那是已决定上诉后的起草方法），也不宜并入 `case-report`（后者是周期性进展汇报，不读文书细节）。`appeal-draft` 第 2 节第 2 步改为“有《研读摘要》的直接复用其拆解”。优先级 **P1**。
   - **方法设计（建议）**：
     - **输入**：裁判文书（判决书 / 裁定书 / 调解书 / 商事仲裁裁决 / 劳动仲裁裁决，必需）；我方诉状或答辩状、仲裁申请书（可选，用于诉请—判项对照）；方法参数：我方地位、送达日（`served_on`）、境内有无住所、汇报对象（客户版 / 内部版）。
     - **输出**：①《裁判文书研读摘要》（Word）：一句话结果；判项逐项（主文逐字摘录）；诉请与判项对照（支持 / 部分支持 / 驳回 / 未处理，差额）；法院认定与我方主张不一致的关键事实；逐焦点“法院观点→所引依据→对我方的影响”；诉讼费或仲裁费负担；履行期限与迟延履行后果；救济途径与届满日（上诉、起诉、申请撤销或不予执行、申请执行）；是否上诉或申请撤销的**考虑因素**（不预测结果，不替客户决定）。②《判项与诉请对照表》（Excel）：诉请原文 / 判项原文 / 处理结果 / 诉请金额 / 判项金额 / 差额 / 理由所在段落 / 原文位置。③《摘录回链表》：摘要每一要点对应的原文引文、段落、定位状态。
     - **模式 B（对方提交的类案判决）**：逐份比对与本案的基本事实、争议焦点、法律适用问题是否相似，标出审级、地域、裁判日期与所依法律版本（新旧法条号差异用 `law.get_version` 按裁判日与今日各取一次）；是否生效、是否被改判或再审，产品无案例库，一律写“待律师核实”；结论只写“可区分点”与“可援引点”，不写“裁判趋势”。
     - **质量闸门**（见下条精髓）。
8. **可吸收的设计精髓**：
   - 主张与认定分栏且按文书段落归属：裁判文书按标准段落切分（“诉称 / 辩称 / 经审理查明 / 本院认为 / 判决（裁决）如下 / 案件受理费”），摘要中写成“法院认定”或“法院认为”的每一点，其引文必须位于“查明”或“本院认为”段内。【可确定性检查】内核按段首标志切分裁判文书文本，对每条摘录做定位与段落归属校验；落在“诉称 / 辩称”段的引文被写成法院认定 → 必须改。
   - 每个要点回链原文：摘要的每一要点附逐字引文与位置（段落号或页码）。【可确定性检查】复用 `review-cards.ts` 的逐字定位（locateQuote），未定位的要点不得进入交付件。
   - 金额、日期、案号、当事人名称逐字核对：摘要与对照表中出现的每个金额、日期、案号、主体名称，必须能在裁判文书原文中找到（金额比对前统一大小写、千分位与“万元”单位）。【可确定性检查】数值与日期正则抽取后逐一比对，找不到的列为必须改。
   - 判项算术闭合：对照表中判项金额合计、诉请与判项差额、诉讼费分担比例由程序计算，与摘要正文一致。【可确定性检查】表内合计与正文数值比对。
   - 救济期限一律工具计算：上诉（判决 15 日 / 裁定 10 日 / 境内无住所 30 日）、劳动仲裁起诉 15 日、用人单位申请撤销终局裁决 30 日、商事仲裁申请撤销 3 个月、申请执行 2 年（自履行期间最后一日起算），届满日用 `calc.deadline` 从送达日或履行期末日算出；送达日不明时给区间并标【待填】，且排在摘要第一屏。【可确定性检查】摘要中出现“届满”“截止”日期而本任务无对应 `calc.deadline` 调用 → 必须改。
   - 法条新旧标注：照录文书所引条号；该条在今日已修订或条号变化的，加注“现行为某法第 N 条”。【可确定性检查】对文书所引条文分别按裁判日与今日调用版本查询，条号或文本不同的自动生成注释。
   - 区分文书种类的救济路径：商事仲裁裁决只能申请撤销或不予执行，不能上诉；劳动仲裁区分终局与非终局；调解书不可上诉（只能申请再审）——摘要模板按文书种类自动换“下一步”栏。

### multi-document-summarization（多源文档归纳）

1. **基本信息**：原子技能；约 475 行 / 21 KB；不依赖检索服务（类案部分建议配合类案检索技能，后者依赖外部库）。
2. **业务价值**：对多份文档做共性、冲突、洞见与信息缺口归纳，场景包括类案判决、多份合同条款、法规演变、多份证据或笔录、学术文献、多份意见书。面向研究人员与律师。与执业律师业务匹配度：**中**——“多份材料的冲突发现”与“多份合同条款对比”是高频需求，但“生成跨文档洞见 / 裁判趋势 / 地域差异”在执业场景下风险大于价值。
3. **专业逻辑**：四层次（单篇理解→共性→差异→洞见）；五种文档关系（平行、时间序列、对立、层级、补充）对应五种归纳框架；每份文档一张信息卡（主题、观点、事实、依据、立场、可信度）；冲突分观点 / 事实 / 法律适用 / 结论四类并分核心与次要；要求区分“明确表述”与“合理推断”。
   - **依据核查**：正文无具体条文；示例一以三份数据抓取判决得出“北京严格、杭州开放、上海居中”的地域结论——三份样本推不出地域规律，属其自身错误表所列的以偏概全；且三份判决均为示例虚构，法院名称真实，易被当作真实类案引用。示例一所称各判决均适用反不正当竞争法第 2 条（一般条款），对 2025-10-15 后的行为应同时注意修订本已增设的数据与算法条款（第 13 条，已查）。类案的参照效力（指导性案例应当参照、其他案例可以参考）本技能未写（相关规范性文件未入库，**未核**）。
4. **工程设计**：文档清单 + 信息卡 + 共识表（含“3/3 一致”式强度）+ 冲突表 + 洞见 + 缺口；三套模板。成熟度：可执行；冲突表结构有用；但共识强度靠计数、可信度高中低靠自评，洞见步骤无约束，不可检验；没有逐条引文要求。
5. **问题与缺陷**：洞见与趋势生成缺乏样本与代表性约束；没有核实类案生效状态、是否被改判的步骤；对合同条款对比没有“逐格出处”的要求（产品已经做到）。
6. **与产品对照**：
   - 多份合同或材料的横向对比：`tabular-review/SKILL.md`（`table.get` / `table.fill`）每格写值并附逐字引文、没有的写“没找到”、读不出的不猜；问表模式只依据表格格子回答并写明材料与列——**产品更好**，可检验。
   - 多份材料之间的事实冲突：`casefile-organize` 第 3 节第 5 步（同一事实不同材料说法分别提交 claimed、再提交一条 to_confirm 说明矛盾，金额逐处核对，冲突成对写进《缺口清单》）——**产品更好**。
   - 尽调材料与披露的勾稽：`independent-review.ts` 复核清单第 8 条“披露与事实勾稽”（概括性说法与具体事实矛盾须写出两处原文）。
   - **产品缺**：对方提交或律师找来的**一组类案判决**的比对研读（见上一项 `ruling-digest` 模式 B）；冲突表缺“冲突类型（事实 / 法律适用 / 结论）”与“对本案的影响”两列。
7. **建议决策**：**融合**。类案比对并入新增的 `ruling-digest` 模式 B；“冲突类型 + 影响 + 两处原文”三列并入 `casefile-organize` 的《缺口清单》“矛盾”类行与 `tabular-review` 的问表回答格式；**舍弃**“跨文档洞见 / 趋势 / 地域差异”生成与“共识强度计数”。优先级 **P2**（随 `ruling-digest` 一起做）。
8. **可吸收的设计精髓**：
   - 冲突必须成对引文：任何“文档之间不一致”的结论，必须同时给出两份材料的逐字引文与位置，并写冲突类型（事实 / 金额日期 / 法律适用 / 结论）与对本案哪个请求或要件有影响。【可确定性检查】冲突行的两条引文分别在各自材料中定位成功才可交付。
   - 明确表述与推断分开：归纳结论逐条标“材料明确写明”或“由 Dx、Dy 推断”，推断须写出依据的文档编号；与 `facts.submit` 的 claimed / inferred 同一口径。
   - 类案比对四维：基本事实、争议焦点、法律适用问题、裁判时法律版本，逐维写“相同 / 可区分（写出区分点）”；生效状态与后续改判写“待律师核实”，不得写“已生效”。【可确定性检查】类案比对表中“生效状态”列只允许“待律师核实”或律师填写的值。
   - 不从少量样本推规律：少于律师指定数量（或未说明检索范围）的判决集合，不写“裁判趋势”“地域差异”“司法共识”。【可确定性检查】交付件出现上述词且类案数少于 10（阈值可配置）或未写检索范围 → 必须改。
   - 文档关系先定框架：先判断是时间序列（同一合同的多个版本、同一案件的一审与二审）、对立（双方诉辩）还是补充（主合同与补充协议），再选择“版本差异 / 观点对比 / 全景整合”的写法；时间序列以最新版本为准并列出被替代条款（产品 `materials.list` 已有 superseded 标记，可直接用）。

### 本组最值得做的 3 件事

1. **新增 `ruling-digest`（裁判文书研读与汇报）+ 内核裁判文书分段与回链检查（P1）**。内核按“诉称 / 辩称 / 查明 / 本院认为 / 判决如下 / 受理费”切分裁判文书；摘要每个要点必须带可定位的逐字引文，写成“法院认定”的引文必须落在“查明 / 本院认为”段；摘要中的金额、日期、案号、主体名称逐一在原文中比对；判项合计与诉请差额由程序算；上诉、劳动仲裁起诉、申请撤销仲裁裁决（2025 仲裁法第 72 条，三个月）、申请执行（民诉法第 250 条）期限一律 `calc.deadline`。`appeal-draft` 复用其拆解。
2. **证据规则确定性核对 + 证明标准标注（P1）**。按证据目录行属性（原件 / 复印件、电子数据原始载体、境外公文书证 / 身份关系证据、外文、证人是否已申请出庭、对方控制的书证）自动给出民事证据规定第 15、16、17、45～48、68、69、90 条的提示与条号；争点涉及欺诈、胁迫、恶意串通、口头遗嘱、赠与的强制写“排除合理怀疑”（民诉法解释第 109 条），其余为“高度可能性”（第 108 条），禁止百分比；同时改正上述五个方法的“法规库未收录”过时说法。
3. **争点—证据矩阵闭合检查（P1，`deliverable-check.ts`）**。覆盖评估为“已有 / 薄弱”的行证据与事实编号不得为空且编号须存在；律师确认的事实必须挂到某要件或写明无关理由；证据目录与矩阵双向闭合（无孤儿证据、无裸请求、证明目的不矛盾）；唯一证据属第 90 条五类的要件不得评“已有”；“违约金过高”类抗辩的举证方不得写守约方。后续（P2）以 `issues.submit / issues.list` 把争点做成事项级共享对象，让案情分析、庭审提纲、代理词、上诉状用同一套焦点。
