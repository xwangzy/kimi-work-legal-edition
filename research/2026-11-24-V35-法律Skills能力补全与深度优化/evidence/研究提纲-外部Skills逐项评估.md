## 每个 Skill 的评估结构（逐项写，中文）
### <slug>（中文名）
1. **基本信息**：类别（原子 / 复合）、正文规模、是否依赖外部检索服务（北大法宝 MCP 等）。
2. **业务价值**：解决什么法律问题；面向谁（律师 / 法官 / 行政机关 / 企业合规 / 学术评测）；与中国执业律师真实业务的匹配度（高 / 中 / 低）及理由。
3. **专业逻辑**：分析框架、推理路径、工作方法、质量控制机制。**核查它援引或预设的法律依据**：有无引用已废止或已修改的法（如原《合同法》、旧《公司法》、2017/2021 版民诉法条号、旧《仲裁法》等）、条号是否正确、口径是否与现行法一致——能用产品法规库查证的就查（写明查了哪条）；查不了的写“未核”。
4. **工程设计**：指令结构、执行流程、工具依赖、输入输出规范、异常处理、能力边界；成熟度评价（可直接执行性、冗长度、可检验性、是否存在不可执行或空转的步骤）。
5. **问题与缺陷**：专业错误、过时依据、过度设计、与成文法实务不符之处、对模型不可执行的要求。
6. **与产品对照**：对应的产品方法 / 工具 / 内核环节（写到文件名，必要时读产品 SKILL.md 相关段落核对，不凭标题猜）；产品已有、缺失、或产品做得更好的点。
7. **建议决策**（六选一）：保留（产品已有同等或更好能力，不动）/ 吸收（把若干要点写进某现有方法或工作准则）/ 融合（并入某现有方法，作为其一个模式或步骤）/ 重构（以内核确定性能力或工具实现，而非提示词）/ 新增（新方法或新工具）/ 舍弃。写明：依据、落地位置（具体文件或工具）、预期收益、优先级（P0 阻断 / P1 高价值 / P2 增强 / P3 中期 / P4 依赖外部条件）。
8. **可吸收的设计精髓**：3～8 条，用自己的话写成可直接落到产品方法或检查规则里的规则（写清“在什么情形下、做什么、怎么判断合格”）。能做成确定性检查（代码可判定）的单独标“【可确定性检查】”。
