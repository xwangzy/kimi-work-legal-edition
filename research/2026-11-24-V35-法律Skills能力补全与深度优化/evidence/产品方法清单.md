# 内核工具（packages/kernel/src/tools/registry.ts）

- `law.get_version`（法规版本查询）：按法名与适用时点返回适用版本（现行与历史适用分开）；注册库没有的法源如实返回 found=false，不伪造。
- `law.search`（法规检索（注册库内））：在本所法规库内检索：按法名或简称找法规版本（results），并按关键词在已收录的条文里找相关的条（articles：法名、条号、片段；如“竞业限制”“违法解除 赔偿金”“劳动合同法 严重违反规章制度”）。要引用的条再用 law.get_article 取原文。
- `law.get_article`（取条文原文）：按法名（或简称）、条号与适用时点取法规库内该条原文，版本选择与 law.get_version 一致。article 可写 585 或“第五百八十五条”。库外法源、该时点无适用版本、条号不存在或正文未采集时返回 found=false，不提供任何文本——不得凭记忆补写条文。reliability=demo_seed 为演示数据，不得作为正式引用。本工具只给原文，不判断是否支持结论。
- `citations.verify`（引用核验）：抽取文本中的法条引用并做四态核验（来源已核/版本已核/支持待判；无法核实则拦截并可见），支持改引建议。
- `calc.interest`（利息计算（LPR 分段））：确定性利息计算：分段保存起止日、日数、利率、年日数与舍入假设。rate 三种：fixed 固定年利率；lpr_plus 一年期 LPR 加基点；lpr_times 一年期 LPR 的倍数（如逾期付款违约金按 LPR 上浮 30%～50% 写 1.3～1.5，民间借贷保护上限四倍写 4）。warnings 非空时须原样告知律师。
- `calc.ledger`（债权台账（分段计息、还款抵充、汇总））：一次算完一笔或几笔欠款到某日为止的全部金额：本金随每笔付款变动自动分段计息或计违约金，每笔付款按抵充顺序逐笔冲抵，给出本金余额、已冲与未付的利息、违约金、费用和未清偿合计；你只给事实与口径，不做任何加减乘除，也不用自己分段（每笔款项只在自己的基数或利率变化时分段）。每个口径的 premise 写这个口径成立的前提（一句话），表里汇总页会单列一行“口径前提”——表是工具算出来的，之后不能逐格改，前提要在调用时写全。
- `calc.deadline`（期间计算（法定期间与工作日））：确定性计算期间届满日并给出逐步过程、所用法条与节假日数据来源。start 为起算事实发生日（YYYY-MM-DD；只知道月份时写 YYYY-MM，只返回区间、deadline 为 null）。rule=civil：民法典第二百至二百零四条（开始当日不计入；按月、年以到期月对应日为末日，无对应日取月末；末日为周末或法定节假日顺延，调休上班日不顺延），period.unit 用 day / month / year；rule=workday：法律明确规定按工作日计算的期间（如行政处罚法第八十五条），period.unit 用 workday。不处理中止、中断与在途时间；warnings 非空时须原样告知律师。
- `calc.labor`（劳动经济补偿与赔偿金）：确定性计算解除或终止劳动合同的经济补偿 N（kind=compensation，劳动合同法第四十七条）或违法解除赔偿金 2N（kind=unlawful，第八十七条、实施条例第二十五条），逐步写出年限、基数、三倍封顶与代通知金。start_date 写入职日（用工之日），end_date 写劳动关系的最后一日（含当日）。
- `calc.court_fee`（诉讼费用）：确定性计算诉讼费用（《诉讼费用交纳办法》）：kind=case_property 财产案件受理费（分段累计，第十三条；上诉按不服一审判决部分的上诉请求数额）、enforcement 申请执行费、preservation 保全申请费（按实际保全的财产数额，最多 5000 元）、payment_order 支付令申请费（受理费标准的 1/3）、labor 劳动争议案件（每件 10 元）。
- `redact.scan`（直接标识符扫描）：确定性扫描身份证/手机号/银行卡/统一社会信用代码/邮箱/车牌；未覆盖类别如实列出。
- `materials.read_excerpt`（读取材料片段）：按解析版本与字符区间/锚点读取材料文本；令牌须绑定对应事项。律师发起时勾选了材料的，只能读勾选的那几份。
- `docx.apply_revisions`（写入原生修订）：在 DOCX 上按锚点写入 w:ins/w:del 与批注；基线或原文 hash 不符即整体停止，不覆盖原件。
- `docx.compare`（整稿比对（含静默改动检出））：基线与回稿段落级比对；未被修订标记覆盖的改动判为静默改动。
- `docx.sanitize`（受众净化）：接受修订、清除批注与作者属性，产出对外版本；保留生成标识。
- `docx.render_report`（生成文书（DOCX））：按标题与段落结构生成 Word 文书（备忘录、意见书、函件、合同、诉状），登记为本任务的草稿成果交律师审阅；导出时按事项令牌表还原代号。
- `docx.revise`（在原件上修订（修订稿 + 清洁稿））：按律师意见修改已上传的 Word 原件：每处给出要改的原文（anchor，逐字照抄材料原文、同一段落之内）与新文字（proposed_text，空串为删除；insert_after=true 为在该段之后插入新段落），
- `docx.edit_draft`（修改本任务的文书草稿）：在本任务里你已用 docx.render_report 生成的 Word 文书上逐处修改（交付前检查报出的问题、自查发现的措辞、条号、金额、遗漏的款项等），几秒完成，登记为同名文书的新版本（旧版本保留）：
- `redact.apply`（生成脱敏件与脱敏报告）：按确定性扫描结果遮盖直接标识符，产出脱敏件（不留修订痕迹）与替换统计；未覆盖类别如实声明。
- `materials.list`（材料目录）：列出本任务的材料：快照序号、解析版本、字数、页数与识别质量（partial/unreadable 表示有页未能识别，须在结论中写明哪几页没有读到，全部读到的不必说明）；律师发起时勾选了材料的，本事项里没勾的只列文件名（not_provided），不能读取；
- `riskcards.submit`（提交风险卡）：把合同审查发现的问题作为结构化风险卡提交到律师的审查工作台（不要只写在正文里）。anchor_text 必须逐字摘自合同原文（与材料快照一致，含代号），便于定位与生成原生修订；basis 列法律依据（法名 + 条号，内核离线核验）。
- `riskcards.list`（读取风险卡）：读取本事项的风险卡及律师的处理结果（lawyer_status：proposed 待处理 / accepted 接受 / modified 修改后接受（lawyer_text 为律师改写的条款）/ rejected 不采纳）。写修订稿时只采用 accepted 与 modified；accepted 的卡按 chosen_level 用首选或可退让（adopted_text 即律师选用的文本）。
- `table.get`（读取审阅表）：读取律师建的审阅表（表格审阅）：列（column 编号、列名、格式、填写说明）、材料（document_version_id）、每格状态。locked=true 的格子律师已核或已改，不要重填；unreadable 的材料读不出文字，不填。
- `table.fill`（填写审阅表）：逐格填写审阅表：每格写 document_version_id、column、value（按列格式：日期 YYYY-MM-DD 或 YYYY-MM，是否填“是 / 否”，选项列只填给定选项）与 quote（逐字摘自该材料，含代号原样，律师据此回原文核对）。
- `outline.submit`（提交论点与依据（起草前确认））：文书类任务（起诉状、答辩状、代理词、上诉状、法律研究备忘录等）在起草之前调用：逐条列出拟写的论点，每条附依据（法名 + 条号 + note 写这条怎么支持该论点）与所用事实（优先引用 facts.list 里的 fact_id）；counter 写对方最可能提出的反驳或抗辩（律师据此判断论点撑不撑得住），不写我方的处理口径、待核事项或给律师的说明。
- `rules.propose`（起草本事项的审查要点（草稿））：从本所或客户的范本（标准合同、采购标准、往来定稿）整理审查要点：每条写条款（topic）、我方标准（standard）、可退让（fallback，可省略）、不可谈（red_line，可省略），按范本原文概括，不添加范本里没有的立场。
- `outline.get`（读取律师确认的论点与依据）：读取本任务最新的论点提纲：status=proposed 表示律师还没确认（此时不要起草）；status=confirmed 时 confirmed_arguments 是确认版——只按它起草：律师删掉的论点不写，lawyer_edited=true 的论点按律师的写法，只引用留下的依据；lawyer_note 是律师的补充要求。
- `facts.submit`（提交事实）：把从材料中整理出的事实逐条提交到事实时间线（kind：claimed 材料声称 / inferred 推论 / to_confirm 待确认；不能标为已确认——由律师确认）。quote 逐字摘自 document_version_id 对应材料，occurred_on 为 YYYY-MM-DD（可只到年或月），amount_yuan 为金额（元）。
- `facts.list`（读取事实）：读取本事项的事实时间线及律师确认状态；起草文书与汇报时只把 lawyer_status=confirmed 的事实写成确定陈述。
- `xlsx.render_table`（生成表格（XLSX））：按列生成 Excel 表格（证据目录、时间线、问题清单、计算明细等），登记为本任务的草稿成果交律师审阅；每个表 1–40 列、最多 5,000 行；单元格为文字或数字。生成后的局部修改（含交付前检查 quality_check 报出的问题）用 xlsx.edit_cells，不要整份重新生成。
