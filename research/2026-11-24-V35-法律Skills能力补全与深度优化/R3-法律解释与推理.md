# R3 法律解释与法律推理（第 3 组，12 项）逐项评估

> 研究对象：THUYRan/Legal-Skills-Chinese（91545b6，CC BY-NC-ND 4.0）`skills/` 下 12 个中文 SKILL.md。本文只用自己的话概括思想，每项至多一处 15 字内原文短语。
> 对照对象：产品 `platform/content/skills/AGENTS.md`（工作准则 11 条）、`legal-research-memo`、`citation-check`（含 `references/argument-mismatch.md` 七类失配）、`client-advice`、`case-analysis`；内核 `services/independent-review.ts`（FOCUS 九类清单，意见类 opinion 第 1～8 项）、`services/deliverable-check.ts`、`tools/tools/citations.ts`；法规库 `content/lawdb/dist/lawdb.sqlite`（48 个版本，`laws.level` 已有“法律 / 行政法规 / 部门规章 / 司法解释 / 司法指导性文件”五档位阶字段，**未收录《立法法》**）。
>
> 本组总判断（先写结论，便于阅读）：这 12 项都是“原子推理技能”，律师不会点“演绎推理”“溯因推理”卡片。产品已有的承接点是四个：①全局工作准则（AGENTS.md）——目前 11 条全部是执业纪律与工程纪律，**没有一条讲推理与法源适用规则**；②文书 / 研究方法正文（legal-research-memo、client-advice 第 1e/6 步、case-analysis）——已有“规则—逐要件适用—相反理由”骨架；③独立复核清单（independent-review.ts 的 FOCUS）——意见类只有一项“引用的法条是否与论点对应”，**没有法源冲突、类推越界、解释方法交代、推理跳跃这几类检查**；④内核确定性检查——citations.verify 已能识别废止与版本，但不用 `laws.level` 做位阶判断，deliverable-check 不扫空泛援引和绝对化用语。本组建议主要落在②③④，不新增推理类卡片。

### 1. legal-interpretation-argument（运用法律解释论证）

1. **基本信息**：原子技能；约 48KB，是本组最长的之一；不依赖北大法宝 MCP，但步骤里要求查释义书、立法资料、指导性案例等，本机均无来源。
2. **业务价值**：解决“条文有几种读法、本案落在边缘地带时怎么论证我方读法”的问题。面向律师写研究备忘录、法律意见、代理词中的法律适用部分，也面向法官说理。匹配度**中高**：律师确实天天做解释论证，但律师的解释是有立场的（为委托人选读法），而该技能按中立裁判者口径写（“综合权衡哪种更符合公平正义”），需要改造成“主张读法 + 对方读法 + 各自依据 + 风险”。
3. **专业逻辑**：框架为文义（核心 / 边缘 / 排除三区）→ 体系（同法内、关联法、位阶）→ 目的（主观 / 客观）→ 历史 → 综合权衡 → 置信度 A～E；有七条有效性验证（文义边界、体系融贯、目的实现、可操作、价值、先例一致、刑法特别规则）和八条筛选规则。方法论主干正确，文义作为外部边界、目的解释不得突破可能文义、清晰条文不作过度解释、漏洞填补已超出解释等表述符合通说。
   **依据核查**：《民法典》第 1165、311、147、180、8、153、366～371 条用作示例，条号与主题对应正确（法规库 `lsv_civil_code_2020` 可查）；《公司法》第 265 条（定义条）、第 182 条（董监高关联交易）、第 57 条（有限公司股东查阅权）均为 2023 年修订后条号，正确；**《反不正当竞争法》第 9 条“商业秘密”已过时**——法规库 `lsv_anti_unfair_competition_law_2025`（2025-10-15 施行）中商业秘密为第 10 条（第 26 条罚则援引“本法第十条”），第 9 条是 2019 年文本的条号；《行政处罚法》第 9 条、《行政诉讼法》第 25、70 条未入库，按记忆对应正确，标“未核”。“法不溯及既往，但有利于当事人的除外”的概括比《立法法》现行第 104 条（2015 年文本第 93 条）的“为了更好地保护公民、法人和其他组织的权利和利益而作的特别规定除外”宽，未核原文（立法法不在库）。
4. **工程设计**：七阶段树状流程 + 两套模板 + 置信度表 + 致命错误表 + 质检清单，可读性好但冗长；“查阅权威词典”“查阅审议报告与释义书”“查阅指导性案例”在本机环境属于空转步骤（无来源时模型只能凭记忆，正好违反其自身“不编造”硬规则）。置信度的“每项 +1 / −1 级”加减规则看似可量化，实际每一项（“学理通说一致”）都需要模型凭记忆判断，**不可检验**。
5. **问题与缺陷**：①商业秘密条号过时；②中立裁判者视角，没有区分“我方主张的读法”与“对方可能的读法”；③置信度 A 级以“有司法解释或指导性案例支持”为条件，本机没有案例源，模型会虚构支持；④“S2 文义能得出唯一结论原则上不再解释”与“目的性限缩”之间缺少触发门槛，容易被用来以目的为名推翻明文；⑤把“上位法优于下位法”等冲突规则塞进体系解释一步，没有区分“解释上的协调”与“适用上的取舍”。
6. **与产品对照**：legal-research-memo 第 3 节第 4 步已有三档确定性（明确 / 有不同理解 / 待律师判断），明确禁止写“通说”“司法实践主流观点”，**比外部的 A～E 置信度更诚实**（产品更好）；client-advice 第 6 步“条文文义与本案事实有差距的写明差距与替代路径，不直接套用”是对边缘含义问题的实务化表达（产品已有）。**产品缺**：任何方法都没有要求在“有不同理解”时交代用了哪种解释方法、各读法的文本依据，也没有“扩张 / 限缩 / 类推越过文义边界须明示”的规则；citation-check 七类失配中“射程不足”只管“结论比条文强”，不区分是合理的扩张解释还是越界的类推。
7. **建议决策**：**吸收**。落地：①legal-research-memo 第 3 节第 4 步“有不同理解”一档下加“解释论证三件事”；②client-advice 第 6 步③④之间加同样要求；③独立复核 opinion 清单第 6 项扩成“依据对应 + 解释是否越过文义”。预期收益：研究备忘录和意见书中“有不同理解”的问题从“列两种说法”变成“我方读法—对方读法—各自依据—哪个更站得住”。优先级 **P1**。
8. **可吸收的设计精髓**：
   - 条文用语对本案事实是否涵盖有争议时（结论写“有不同理解”的），必须写出：争议用语原文（取自 law.get_article）、我方读法及其文本 / 体系依据、对方读法及其依据、本案事实落在哪一读法下；只写“存在争议”不合格。
   - 解释结论扩大了条文字面（把“用人单位”读到劳务派遣用工单位、把“买卖”读到互易）时，须明写“这是扩张解释 / 参照适用”，并给出体系或目的依据；没有写明的，复核按“射程不足”处理。
   - 同一部法里同一用语已有定义条或在他条中有确定用法的（如《公司法》第 265 条对实际控制人的定义），解释时先引定义条；与定义条不一致的读法须说明理由。【可确定性检查：对引用了公司法“实际控制人 / 控股股东 / 高级管理人员 / 关联关系”的交付件，检查是否同时引用或核过第 265 条——可做成复核提示，不做拦截】
   - 目的解释只能在文义允许的几种读法之间挑选；用目的理由排除明文适用（目的性限缩）的，必须标为“法律续造，风险较高”，进意见书的“限制与相反依据”。
   - 法律修改后的条文，解释前先比较新旧文本差异（legal-research-memo 已要求写“差异对本问题的影响”），并把“修法删去 / 增加了某要件”作为历史解释的首要证据，而不是凭记忆的立法背景。
   - 不以“通说”“权威释义”作为置信依据；本机资料无法支撑的权威来源，只能写“学理上有不同观点（未核）”。

### 2. systematic-interpretation（体系解释）

1. **基本信息**：原子技能；约 13KB，结构紧凑（触发—四步—输入输出—示例—局限）；不依赖外部检索。
2. **业务价值**：解决“一个用语两种读法 / 边缘事实是否涵盖 / 一个事实被两条规范同时涵盖用哪条”三类问题。面向律师和法官。匹配度**高**：合同纠纷里“参照买卖合同”“其他法律另有规定的依照其规定”“同类解释（等、其他）”几乎每案都会碰到；且它的 step 3 明确列出“不输出结论”的情形，这种克制适合律师工具。
3. **专业逻辑**：由近及远用体系资源：①文本内规则（同类解释、无特别限定即一般法、封闭列举的反面排除、例外从严不得扩张或类推）；②体系位置（总则 / 一般规定统摄分则、位阶 / 特别 / 新旧三规则）；③关联规范（避免使相邻条文失去独立意义、同词同义、异词异义）。step 3 把“新的一般规定与旧的特别规定不一致”“地方性法规与部门规章不一致”“部门规章之间不一致”“授权立法与法律不一致”列为不得自行得出结论的情形——这与《立法法》裁决机制一致（2023 年修正后第 105、106 条；2015 年文本第 94、95 条），**是本组对“新一般 / 旧特别”处理得最准确的一项**（立法法不在法规库，条号凭对现行文本的掌握，标“未核原文”）。
   **依据核查**（法规库 `lsv_civil_code_2020`）：**两处条号错误**——①问题句示例写“第 1169 条中的‘共同’”，但“二人以上共同实施侵权行为”在第 1168 条，第 1169 条是教唆、帮助（其后的示例又正确写为第 1168 条，前后不一）；②“第 105 条规定的‘显失公平’”错误，第 105 条是非法人组织的代表人，显失公平在第 151 条。第 999、1125、1128、1165、1171、1172、1190、1222、1225、1245、367 条示例条号与内容对应正确。位阶表述“地方性法规和行政规章”并列为同一层不够准确：地方性法规只高于本级和下级地方政府规章，与部门规章之间没有当然高下（冲突时由国务院提意见、必要时提请全国人大常委会裁决）；司法解释在位阶中的位置未交代。
4. **工程设计**：步骤短、规则可枚举、示例与规则一一对应，可执行性在本组最好；step 3 的“不输出结论 + 写明原因”给了模型合法的拒答出口。缺点是输入需要“文义解释结果”作前置，单独调用时没有起点；英文模板标签（Capabilities / How to Use）残留。
5. **问题与缺陷**：两处条号错误；位阶表把地方性法规与部门规章并列；“位置靠前、更抽象即一般规范”只是经验法则，未提示须以条文自身的“依照其规定 / 另有规定的除外”等转介用语为准；“反面排除（明示其一排除其他）”没有提示其适用前提是封闭列举，开放列举（含“等”“其他”）不适用——虽然规则 3 写了“封闭式列举下”，但示例第 1125 条本身有兜底项之外的情形，需谨慎。
6. **与产品对照**：产品任何方法都没有成体系的“体系解释规则”。最接近的是 citation-check 语义比对第 3 问“主体、对象、行为对得上吗”（如有限公司条文用于股份公司）——这是体系解释“适用范围”问题的一个实例，产品已有。**产品缺**：①转介条款（《民法典》第 11 条“其他法律另有特别规定的依照其规定”、第 467 条无名合同参照最相类似合同、第 646 条有偿合同参照买卖）在研究与意见方法里没有被列为必查项；②“同类解释 / 封闭列举反面排除 / 例外从严”三条规则不在任何方法中。
7. **建议决策**：**吸收**（进 legal-research-memo 第 3 节新增“体系检查”小步，并作为独立复核 opinion 清单一项）。另外其 step 3 的“须由有权机关裁决、不自行下结论”的情形清单，与第 11 项 conflict-resolution 合并落地。优先级 **P2**。
8. **可吸收的设计精髓**：
   - 引用一条规范作为请求权基础或抗辩依据前，取原文看是否含“法律另有规定的除外 / 依照其规定 / 参照适用”这类转介用语；有的，必须检索被转介的特别规定并写明是否适用，否则复核按“条件遗漏”处理。【可确定性检查：law.get_article 返回的原文含“另有规定”“依照其规定”“参照适用”“除外”时，在工具返回里加 read_with 式提示“本条有转介 / 例外，须核特别规定”】
   - 条文是“列举 + 等 / 其他”的开放列举时，把本案事实纳入兜底项，须说明它与已列举各项属于同一类型（性质、危害或功能相当）；不能说明的，标“扩张适用，有争议”。
   - 条文是封闭列举（无兜底项）时，主张本案情形“未列举即不适用”可以成立，但须核对同一法或司法解释是否另有补充列举。
   - 条文是一般规则的例外或但书时，主张适用例外的一方承担说明其要件全部满足的责任；不得用目的或类比把例外扩到未列明的情形。
   - 一种读法会让同一部法中的相邻条文失去独立适用意义的，该读法降为备位，并写明理由。
   - 引用合同编典型合同规则处理无名合同或其他有偿合同时，须写明转介依据（第 467 条或第 646 条）和“参照”的取舍理由，不能直接把买卖合同条文当作本合同的直接依据。

### 3. teleological-interpretation（目的解释）

1. **基本信息**：原子技能；约 15KB；伪代码式 PHASE / STEP 树 + YAML 输入输出 + 一则完整示例（《民法典》第 1176 条自甘风险但书“重大过失”）；不依赖外部检索。
2. **业务价值**：处理开放概念（合理、必要、重大、显失公平）和新型事实下条文覆盖不足的问题；律师用它来论证“我方读法更符合规范目的”。匹配度**中**：律师确实需要目的论证（尤其代理词、上诉状），但该技能的终点是“可裁判的解释结论”，并在示例里直接判定“应认定为重大过失、应依第 1165 条承担责任”，属于裁判者口吻，与产品“不预测裁判结果”冲突。
3. **专业逻辑**：主观目的（条文本身 → 立法说明 → 立法背景，依次降级）与客观目的（制度整体、基本原则、现实需求、权威裁判）分别找；二者冲突时以“法越新越重主观、条文越具体越重主观、规则重主观原则重客观”三标准分配权重；结论必须落到“宽 / 窄、纳入 / 排除、严格 / 扩张”的具体判断；输出前四项检查（文义射程、体系协调、上位法原则、公开说服力）。这套主客观目的权衡标准是德国方法论的通行简化，作为写作框架可用。
   **依据核查**：示例引《民法典》第 1176 条第 1、2 款、第 1165 条，条号与内容正确（法规库 `lsv_civil_code_2020`）；示例输入里的“法工委释义”一段为示例数据，本机无法核对，未核。
4. **工程设计**：要求目的陈述写成“通过某手段防止 / 实现某效果”，明确禁止口号式表述——这是本组少数能直接检验的写作规则；四项合法性检查中“公开说服力”不可判定，属空转。L2 / L3 级来源（草案说明、审议报告、立法背景）本机没有，按其自身规则应标“主观目的不明确”，但模型很可能凭记忆补写立法意图。
5. **问题与缺陷**：①裁判口吻，不区分立场；②“权威裁判中的目的表达”依赖案例库，本机未开通；③没有提醒：目的解释在刑法入罪方向、税法课税要件、行政处罚设定上受严格限制（“法无明文不为罪 / 不处罚”“税收法定”），只在 Limitations 泛泛写“不得超出可能语义”。
6. **与产品对照**：产品 client-advice 第 1f 步“有依据但有解释争议的路径不整条否掉，写清争议在哪里、走这条路的程序后果和降低风险的做法”比外部更贴合律师决策（产品更好）；legal-research-memo 禁写“通说 / 主流观点”同样更诚实。**产品缺**：没有对“目的论证”本身的写作约束，模型在代理词、意见书里常写“为保护劳动者合法权益，本条应作有利于劳动者的解释”一类口号式目的。
7. **建议决策**：**吸收**（两条写作规则进 legal-research-memo 与 agency-statement / appeal-draft 的论证步骤；一条进独立复核 opinion / pleading 清单）。不新增方法。优先级 **P2**。
8. **可吸收的设计精髓**：
   - 用规范目的支持某一读法时，目的必须写成“该条通过（某手段）防止 / 实现（某具体效果）”，并给出目的的出处（立法目的条、本条结构、章节标题、律师提供的立法资料）；只写“保护合法权益”“维护交易安全”的，复核记为“裸断言”。【可确定性检查：对文书中“立法目的 / 规范目的 / 立法本意 / 立法精神”所在句，检查同句或前后一句是否有法名 + 条号或“律师提供的××资料”出处；无出处的列为复核提示】
   - 目的只能用来在文义允许的读法之间选择；论证结论落在文义之外的，改标“目的性扩张 / 限缩（法律续造）”，并在相反依据一节写明对方可依文义反驳。
   - 本机没有立法资料时，主观目的一律写“立法资料未核”，只从法条文本、立法目的条和体系位置推断客观目的，不凭记忆写“立法机关认为……”。
   - 目的论证要落到本案具体判断（本案事实应纳入 / 排除），但在对外文书里写成我方主张（“应当认定”），在内部备忘录里写成“我方可主张……，对方可能主张……”，不写成裁判结论。
   - 涉及行政处罚设定、税收课税要件的问题，不以目的解释扩张义务人的义务或处罚范围；需要这样论证的，标“受法定原则限制，高风险”。

### 4. Normative-Meaning-Argumentation（规范意义论证）

1. **基本信息**：原子技能；约 9KB，本组最短；七步 + 两则示例（《民法典》第 1032 条隐私与公开身份证号、数据提供合同能否适用买卖瑕疵规则）；不依赖外部检索；模板标签残留英文（Skill Title、Capability 1）。
2. **业务价值**：要解决的是“条文意思清楚了，但本案事实为何能 / 不能进入这条规范的评价、评价到什么程度”，即涵摄的实质理由。面向律师、法官与学术论证（输入格式里有“论文观点”）。匹配度**中**：问题意识对律师很有用（防止“形式符合、实质不该适用”的机械套用，也是代理词里“对方事实虽形式相似但不触及规范关切”的核心论证），但技能本身与目的解释高度重叠，独立价值有限。
3. **专业逻辑**：规范目的 → 规范真正评价的对象 → 筛选规范相关事实（核心 / 辅助 / 无关）→ 建立“目的—事实特征”对应 → 判断涵摄边界（纳入、限制、排除）→ 结论。其可取之处是第 4 步把情绪性、背景性事实剔出评价的要求，这在律师写作里是实打实的质量要求。
   **依据核查**：《民法典》第 1032、1034 条（法规库 `lsv_civil_code_2020`）条号与主题正确。示例一结论“公开身份证号不当然构成隐私侵权”在方向上可接受，但未提到第 1034 条第 2 款已把身份证件号码明列为个人信息、第 3 款规定私密信息适用隐私权规定，其余适用个人信息保护规定——体系上应先走“个人信息”路径（含《个人信息保护法》），示例只围绕隐私权展开，遗漏了更直接的请求权基础。示例二（数据合同参照买卖瑕疵）未提《民法典》第 646 条“有偿合同参照买卖”的转介依据。
4. **工程设计**：步骤是论证要素清单而非可执行流程；没有输入事实来源、没有出处要求、没有失败出口；Capability 5 自称要“区别于规范目的解释”，但步骤 2 仍是找规范目的，区分没有落到操作上。可检验性低。
5. **问题与缺陷**：与目的解释重叠；示例遗漏更直接的请求权基础（个人信息路径、第 646 条转介），恰好示范了“先谈价值、后找条文”的反模式；Limitations 自己承认“容易被误用为价值判断”。
6. **与产品对照**：产品 client-advice 第 6 步④“条文文义与本案事实有差距的写明差距与替代路径，不直接套用”与本技能核心诉求一致，且更落地（产品已有）。case-analysis、agency-statement 没有“剔除无关事实 / 情绪性陈述”的规则；AGENTS.md 第 3 条管的是事实来源，不管事实相关性。
7. **建议决策**：**舍弃**作为独立能力；其中“事实相关性筛选”一点**吸收**进对外诉讼文书（pleading-draft、defense-draft、agency-statement）的事实部分写作规则。优先级 **P3**。
8. **可吸收的设计精髓**：
   - 对外诉讼文书的“事实与理由”中，每一段事实都应能对应到某个请求、要件或抗辩；对应不上的（情绪性描述、与争点无关的背景）删去或压缩为一句。【可确定性检查（弱）：若论点提纲已确认，可检查文书事实段引用的 fact_id 是否都出现在确认版论点的 facts 中，多出的列为复核提示】
   - 论证“本案事实虽形式上符合条文、但不应适用”或相反时，先写清条文要防止的具体风险或要保护的具体利益（带出处），再写本案事实是否触及该风险；不能只写价值判断。
   - 在找到最直接的请求权基础之前不进入价值论证：同一问题存在专门规范（如个人信息、特别法）的，先用专门规范，再谈一般规范的实质理由。

### 5. deductive-reasoning（演绎推理）

1. **基本信息**：原子技能；约 9KB；P（大前提）—f / F（自然事实 / 法律事实）—C（结论）三段论链 + 有效性报告（肯定后件、否定前件、四词谬误）；不依赖外部检索。README 把它挂在 JEC-QA、LAiW、MSLR 等评测任务上，评测导向明显。
2. **业务价值**：把“事实—定性—法条—结论”逐层显式化，并检查形式谬误。面向法官文书、评测、法学教学；对律师的匹配度**中**：律师文书本就是三段论结构，真正出错的地方很少是形式谬误，而是大前提不真（条文用错、漏了但书）、小前提未证（事实未确认）、涵摄跳跃（自然事实直接跳到法律定性）。该技能把只看推理形式、不问前提真假作为硬规则，对律师恰恰是次要问题。
3. **专业逻辑**：区分自然事实与法律事实、要求标出每步“中项”、直言 / 假言三段论分型、否定后件式用于抗辩——这些是正确的逻辑学框架。自然事实到法律事实的“事实归入”被单列为一步，是其对律师最有价值的部分（产品的 facts 只有 claimed / inferred / to_confirm，没有“定性”这一层）。
   **依据核查**（法规库 `lsv_civil_code_2020`）：示例引第 465 条第 2 款（合同相对性）、第 593 条（第三人原因违约）、第 832 条（承运人货损赔偿）条号与内容正确。**示例的实体结论有问题**：把“收货人乙向承运人丙索赔”判为无效且归为“肯定后件谬误”——①逻辑上，缺一个小前提是“前提缺失 / 不充分”，不是肯定后件；②实体上，货运合同中收货人是合同指定的受领人，实务中可依运输合同向承运人主张货损（且货物所有权已转移时还可主张侵权，存在请求权竞合），该示例只按合同相对性一刀切，漏了收货人地位与侵权路径。这正是“形式有效但前提不全”的反面教材。
4. **工程设计**：A / B 两部分“循环交替直到闭环”没有终止条件，执行上可能空转；输出格式（三张表 + 推理链 + 有效性表）清晰、可复核。没有要求大前提取原文、小前提注明证据来源。
5. **问题与缺陷**：谬误归类错误；示例实体结论片面；“只看形式”的原则不适合律师交付；“补充隐含大前提”没有限制，模型会补出不存在的规则。
6. **与产品对照**：产品 `outline.submit`（registry.ts 第 862 行起）已经是 P-F-C 的工程化：每条论点 claim + basis（法名、条号、note 写怎么支持）+ facts（fact_id）+ counter，且内核离线核验每条依据并附原文、律师逐条确认后才能起草——**这比外部的提示词三段论强得多**（产品更好）。client-advice 第 6 步“规则—逐要件适用—相反理由”也是三段论的写作化。**产品缺**：①提纲里没有“要件—事实”逐项对应字段，note 是自由文本，内核无法判断某要件有没有事实支撑；②没有区分自然事实与法律定性（“对方逾期付款”是事实，“构成根本违约”是定性，后者应标推论）；③大前提里的但书 / 例外没有被结构化。
7. **建议决策**：**重构**——以内核确定性能力承接，而非新增卡片：给 `outline.submit` 的 basis 增加可选字段 `elements`（该条的要件或适用条件逐项列出，每项对应 fact_id 或标“待证 / 不争议 / 对方举证”），以及 `exceptions_checked`（取原文后列出该条但书、例外与是否排除）；内核做三项确定性检查：每个要件至少有一个事实或一个状态标记；引用了 lawyer_status 非 confirmed 的事实时，提纲确认页标“基于未确认事实”；原文含“但是 / 除外 / 另有规定”而 exceptions_checked 为空的，提示补。优先级 **P1**。
8. **可吸收的设计精髓**：
   - 每个论点按“规则（取原文，列要件与但书）→ 要件逐项对应事实（注明 fact_id 或材料位置）→ 结论”写；任何一项要件没有对应事实的，结论只能写成附条件（“如能证明……则……”）。【可确定性检查：outline.submit 新增 elements 字段后，内核判定每个要件是否有 fact_id 或状态标记】
   - 把“自然事实”与“法律定性”分两层写：材料能证明的是事实（某日未付款），“构成违约 / 根本违约 / 恶意”是定性，必须写出从事实到定性所依的规则或标准；定性不得作为 facts.submit 的 claimed 事实提交。
   - 抗辩论证优先用“否定后件式”：指出请求权某一要件不成立，即足以否定请求；文书里把“不成立的要件”写在最前，不必逐项反驳对方所有事实。
   - 复核时专查三种跳跃：从事实直接跳到法律后果（漏了定性规则）；用“结果出现”反推“要件已满足”（如“货物丢失，所以承运人有过错”——而货运合同承运人责任本是无过错责任加法定免责，判断标准本身就要先核）；同一术语在大前提与小前提中含义不同（“合同当事人”与“收货人”）。
   - 补充“隐含大前提”时只能补有出处的规则；补不出出处的，标“推论（规则待核）”。

### 6. inductive-reasoning（归纳推理：从案例总结一般规则）

1. **基本信息**：原子技能；约 18KB；五阶段（判例识别 → 相似性与规则提炼 → 相反判例差异化 → 论证输出 → 批判检验）；示例全部取自英美法（Keeble、Pierson v. Post、Young v. Hitchens）；运行依赖案例库（README 称接北大法宝 MCP），本机没有。
2. **业务价值**：从一组裁判归纳裁判规则、给出支持判例与相反判例的区分论证。面向法官、学者、律师的类案研究。在中国执业律师业务中，“类案检索报告”确实常用（最高人民法院 2020 年《关于统一法律适用加强类案检索的指导意见（试行）》），但本技能的框架是判例法传统，它自己在 Limitations 里承认“成文法体系下的适用性受限”。匹配度**低**（现阶段）——产品案例库未开通，legal-research-memo 明令不以记忆中的案例替代。
3. **专业逻辑**：“相关相似而非表面相似”“区分 ratio 与 dicta”“主动披露差异”“构造荒谬类比做反向检验”是正确的判例推理方法。但：①把从判例归纳规则说成带有立法性质的活动，不符合中国法——中国法院不能从判例创设规则，指导性案例只是“应当参照”其裁判要点，类案只作参考；②示例把民事侵权上的“干扰捕获”直接得出“被告构成盗窃”，在中国法下等于用类比入罪，违反罪刑法定（《刑法》第 3 条，刑法不在法规库，未核原文），与该仓库 AGENTS.md 自己的“刑法类比受严格限制”相矛盾；③结论建议写“具有高度概然性”，与产品工作准则第 7 条（不写概率性裁判判断）冲突。
   **依据核查**：无中国法条引用；未核。
4. **工程设计**：阶段清晰，但每一步都以“有一个判例库”为前提，本机不可执行；输出模板偏英美 IRAC（Rule-Based Explanation）。
5. **问题与缺陷**：法域错配；刑事类比入罪示例；概率化表述；无“样本边界”说明（检索了哪些库、多少份、时间与地域范围）。
6. **与产品对照**：产品 citation-check 第 6 类“以偏概全”（个别案例 → “司法实践普遍认为”）要求写明样本边界、本机无案例源时删去“普遍 / 一致”，**已经覆盖了归纳推理最常见的错误**（产品更好、更克制）；legal-research-memo 明确不写“通说 / 主流观点”。产品缺的是：律师自己导入裁判文书作为材料时，没有一个“从律师提供的裁判中提炼裁判规则”的步骤规范。
7. **建议决策**：**舍弃**（现阶段）；案例库开通或律师批量导入裁判文书后，作为 legal-research-memo 的一个模式**融合**（“类案归纳”）。优先级 **P4**（依赖案例来源）。
8. **可吸收的设计精髓**（供日后融合时用）：
   - 从裁判文书提炼规则时，只取“本院认为”中对争点作出判断且对结果有决定作用的理由（裁判理由主干），附带评论不作规则；每条规则注明文书名称、审级、裁判日期与段落位置。
   - 归纳结论必须写样本边界：检索或提供了几份、什么审级、地域与年份；少于三份或只来自一个地区的，只能写“在所提供的 N 份裁判中”，不得写“司法实践”。【可确定性检查：交付件出现“司法实践普遍 / 一致 / 主流”而本任务没有裁判文书类材料的，交付前检查报出】
   - 同时列出与归纳规则相反的裁判，并写出区分点（哪项事实不同、为何重要）；找不到写“在所提供材料中未见”。
   - 指导性案例只引用其裁判要点，并写明编号与发布批次；不得把普通案例写成“应当参照”。
   - 刑事、行政处罚、税务问题上，不以类案归纳出不利于当事人的新规则。

### 7. analogical-reasoning（类比推理）

1. **基本信息**：原子技能；约 50KB，本组最长；六阶段 + 领域对照 + 五级置信度 + 致命错误 / 陷阱 + 特殊场景（类比竞合、反面推理竞争、跨部门类比、法律原则类推、新业态、指导性案例）+ 两则完整示例（虚拟财产继承、AI 生成内容著作权）；不依赖外部检索。
2. **业务价值**：处理“法律没有直接规定、能否参照相似规范”的问题，是新业态（数据、虚拟财产、平台合同）法律意见的常用论证。面向律师、法官。匹配度**中高**：律师在无名合同、身份协议、新型财产问题上确实要做类比；但中国民法中大量类比已被立法者写成“参照适用”转介条款，律师应先找转介条款，而该技能没有把它放在首位。
3. **专业逻辑**：前置检查（确认真漏洞而非有意沉默 → 检查禁区 → 是否有优先方法）→ 找参照 → 相似性（须与参照规范的规范目的相关）→ 差异性评估 → 正当性论证 → 结论；区分扩张解释（文义之内）与类推（文义之外）、反面推理与类推的竞争（例示性列举倾向类推、穷尽性列举与例外规定倾向反面推理）、“例外不得类推”。方法论整体准确。
   **类推限制的表述核查**：①刑法——“不利于被告人的定罪与量刑类推严格禁止、有利于被告人的类推理论上允许但实践谨慎、扩张解释须在文义范围内”，表述准确（罪刑法定，《刑法》第 3 条；1997 年修订已删除 1979 年刑法的类推制度；刑法不在法规库，未核原文）。②税法——“课税要件不得类推（税收法定）”，准确；但没有写出依据层级（税种设立、税率确定和税收征收管理等基本制度属于法律保留事项，《立法法》现行第 11 条；未核原文），也没有区分“不利于纳税人的类推禁止”与税收优惠条件同样不宜扩张这一实务要点。③行政处罚——“处罚种类和幅度不得类推”准确但不完整：处罚法定还要求处罚的**设定依据**必须来自法律、法规、规章（《行政处罚法》第 4 条起至第 16 条的设定权分配，没有依据的处罚无效见第 38 条；未入库，未核原文），律师在行政处罚应对里更常用的是“无法定依据”与“不得以类推扩大违法行为类型”。④行政许可、行政强制、限制人身自由的事项同属法律保留，技能用“其他法律保留领域”一笔带过。
   **依据核查**（法规库）：《民法典》第 127、1122 条，《著作权法》第 11 条第 3 款、第 18、19 条（`lsv_copyright_2020`）条号与文本对应正确。虚拟财产示例把问题定为“需要类推的法律漏洞”可商榷——第 1122 条“个人合法财产”的文义本身可以涵盖有财产价值的网络虚拟财产，第 127 条是转介条款，多数观点按解释而非类推处理；示例也没有讨论平台用户协议中“账号不得转让 / 继承”条款的效力这一实务关键点。
4. **工程设计**：前置检查把“禁区”放在第一步并要求进入禁区即终止，这是好的工程设计；五级置信度以“已有司法解释或指导性案例支持”为最高档，本机无法核实，同第 1 项的问题。整体冗长，Agent 很难在一次任务里完整执行六阶段。
5. **问题与缺陷**：没有把“法定参照适用”（立法明文授权的类比，如《民法典》第 464 条第 2 款身份协议参照合同编、第 467 条无名合同参照最相类似合同、第 468 条非合同之债适用合同编通则、第 646 条有偿合同参照买卖、第 1001 条身份权参照人格权保护——均已在法规库核对原文）与“法官类推”分开；前者风险低、应首选，后者风险高、须显式标注。领域表中“同居关系解除参照离婚财产分割”在实务中多按共有或合伙处理，参照离婚规则风险较高，应提示。
6. **与产品对照**：产品 citation-check“射程不足”（条文支持 A，结论说 B）能抓到“把类推包装成直接适用”，但不能区分合法的扩张解释、有转介依据的参照适用与无依据的类推；`outline.submit` 的 basis 只有法名、条号与自由文本 note，没有“适用方式”。独立复核 opinion 第 6 项只问“法条是否与论点对应”。产品没有任何关于刑事、税法、行政处罚类推禁止的规则（产品没有刑事辩护线，但企业法务线会碰到行政处罚应对与税务合规问题）。
7. **建议决策**：**重构 + 吸收**。①重构：`outline.submit` 的 basis 增加可选字段 `mode`（直接适用 / 依转介条款参照适用 / 扩张解释 / 类推适用），内核确定性检查：mode 为“参照适用”的，同一论点须同时引用转介条款（第 464 条第 2 款、第 467、468、646、1001 条等，可维护一张转介条款表）；mode 为“类推适用”的，确认页显示“类推，无直接依据”标签；事项或论点关键词涉及行政处罚、税款、滞纳金、刑事时，mode 为扩张或类推的，提示“受法定原则限制”。②吸收：独立复核 opinion / pleading 清单增加一项“适用方式”。优先级 **P1**。
8. **可吸收的设计精髓**：
   - 论点所依条文并不直接规定本案情形时，必须在依据旁写明适用方式：直接适用 / 依某条转介参照适用 / 扩张解释 / 类推适用；四者的风险依次升高，类推适用须在“限制与相反依据”中写明对方可主张“法无规定”。【可确定性检查：outline.submit 增加 mode 字段后，参照适用缺转介条款的由内核报出】
   - 类比之前先找转介条款：无名合同找第 467 条、其他有偿合同找第 646 条、非合同之债找第 468 条、身份关系协议找第 464 条第 2 款、身份权找第 1001 条；找到转介条款的，按“参照适用”写，不写成“类推”。
   - 类比的相似点必须与被参照规范的规范目的相关（被参照规则之所以规定该后果的理由，在本案是否同样成立），并逐项列出差异点及其是否影响该理由；只列表面相似（都是合同、都有金钱给付）不合格。
   - 被参照规范是例外规定、但书或封闭列举的，不作类推；需要突破的，标“高风险：例外规定原则上不得类推”。
   - 行政处罚应对：对行政机关以相似违法行为条款“比照”处罚、或以规章以下文件设定处罚的，作为我方首要抗辩点检查（处罚法定、设定权限）；税务问题：不得以类推扩大课税对象或缩小免税、优惠范围的条件，客户主张适用优惠的，同样只能以文义为限。
   - 刑事问题（企业合规中涉及单位犯罪风险提示时）：只能做“行为可能落入某罪构成要件”的文义分析，不得以“性质相似”推出构成犯罪；提示内容写成风险，不写成罪名认定。

### 8. Legal-Abductive-Reasoning（法律溯因推理）

1. **基本信息**：原子技能；约 14KB；以密尔五法（求同、求异、并用、剩余、共变）生成至少 3 个竞争假设 → 四标准评估矩阵（解释力、简洁性、可检验性、背景契合）→ 最佳解释 → 验证与修正触发器；示例为英美法 Young v. Hitchens 盗窃案与产品警告标签案；不依赖外部检索。
2. **业务价值**：证据不完整时构建竞争性事实版本、找出能区分版本的证据。面向律师的事实分析与补证、质证、庭审发问。匹配度**中**：问题意识对诉讼律师很有价值（典型如民间借贷中“这笔转账是借款还是还旧债”、劳动争议中“离职是辞职还是被辞退”），但技能把法律要件的确定也交给密尔五法（以盗窃案件共有取走行为为例归纳出必要要件），混淆了**规范上的要件**（由条文规定，不靠归纳）与**事实上的因果**。
3. **专业逻辑**：区分已证事实与待证事实、标注有利与不利事实、至少三个竞争假设、写明可废止条件与修正触发器——这几点是好的事实分析纪律。但：①求异法示例“有警告无损害、无警告有损害，故警告缺失是损害的充分条件”逻辑上错误（两例对比最多提示“若无”条件关系，即必要条件方向，且不能控制其他差异），法律上也跳过了警示义务是否存在、相当因果关系与过错等要件；②示例用盗窃罪要件，并以星级打分（4.5、3.5）给出“首选假设”，评分无依据，属伪量化；③“背景契合 = 与类似案例一致”依赖案例库。
   **依据核查**：无中国法条引用。与之相关的证明标准未提及——中国民事诉讼一般为“高度可能性”（《民诉法解释》第 108 条第 1 款），欺诈、胁迫、恶意串通以及口头遗嘱、赠与事实为“排除合理怀疑”（第 109 条），已在法规库 `lsv_civil_procedure_interp_2022` 核对原文；溯因结论能否“认定为事实”取决于这一标准，技能没有交代。
4. **工程设计**：模板化强、输出结构清楚；“强制用满五种方法、每种至少一个假设”会制造凑数的假设，在律师场景里是负担；没有把假设与证据清单、举证责任挂钩。
5. **问题与缺陷**：要件与因果混淆；求异法示例逻辑错误；伪量化评分；英美示例；未区分证明责任与证明标准。
6. **与产品对照**：产品 issue-evidence-matrix 第 3 节已按“请求权基础 → 要件 → 举证责任（一般）→ 事实与证据 → 覆盖评估 → 抗辩与反驳 → 补证清单”组织，**比外部的假设矩阵更贴近诉讼实务**（产品更好）；case-analysis 第 3 步的真实性、合法性、关联性、证明力四维评价也更规范。**产品缺**：①“抗辩与反驳”一步列的是法律抗辩（时效、同时履行、违约金过高），没有“同一组证据的另一种事实解释”（对方会怎么讲这笔转账、这封邮件）；②没有按待证事实类型区分证明标准（欺诈、胁迫、恶意串通、口头遗嘱、赠与适用排除合理怀疑）。
7. **建议决策**：**吸收**进 issue-evidence-matrix 第 3 节第 5 步与 case-analysis 第 3 步，并做一项内核确定性提示。优先级 **P2**。
8. **可吸收的设计精髓**：
   - 每个关键待证事实（决定某要件成立与否的）写出“我方版本”与“对方最可能的版本”，各列支持它的现有证据和与之矛盾的证据；再写“哪一份证据能把两个版本区分开”，作为补证清单的首要动作。
   - 对方版本有证据支持而我方无反证的，该要件评级不得高于“证据薄弱”。
   - 待证事实属于欺诈、胁迫、恶意串通或口头遗嘱、赠与的，要件行注明“证明标准：排除合理怀疑（民诉法解释第 109 条）”，证据评价相应从严；其余民事待证事实按高度可能性标准（第 108 条），不写百分比。【可确定性检查：争点表 / 要件表某行含“欺诈 / 胁迫 / 恶意串通 / 口头遗嘱 / 赠与”而未出现第 109 条或“排除合理怀疑”的，交付前检查提示】
   - 推断出的事实一律以 facts.submit 的 inferred 类型提交，写明推断所依的证据与可被推翻的条件（“如对方提供××，此推断不成立”），不得以 claimed 类型提交。
   - 法律要件只从条文与司法解释取得，不从案例或事实模式“归纳”出要件。

### 9. counterfactual-reasoning（反事实推理）

1. **基本信息**：原子技能；约 42KB；十步流程（定义目标变量 / 结果变量 → 锁定背景条件 → 构建反事实世界 → 推演 → 比较 → 法律结论 → 置信度）+ 五条有效性规则（可替代性、最小偏离、推演链可靠、过度决定、先占因果）+ 特殊场景（多因一果、不作为、假设因果、累积因果、合同期望利益）+ 交通事故示例；不依赖外部检索。
2. **业务价值**：用于侵权因果关系、过错比例、违约损害（期望利益）、减损义务、不作为责任的论证。面向律师、法官。匹配度**中**：律师在侵权与违约损害赔偿中确实需要“若无 / 若正常履行”的比较，但最常用的落点是**金额**（可得利益 = 正常履行时的状态 − 实际状态），而这在产品里应由计算工具承担，而不是长篇推理模板。
3. **专业逻辑**：“最小偏离”（只改目标变量，其余背景锁定）、“过度决定与先占因果须修正 but-for 检验”、“后见之明偏差”“选择性反事实”等陷阱，是正确的因果方法论。合同部分把期望利益写成“正常履行状态 − 现实状态”，并提示以可预见性与减损规则限缩，与《民法典》第 584、591 条一致（法规库核对原文）。
   **依据核查**（法规库 `lsv_civil_code_2020`）：第 1165、1171～1172、1202～1207、1218～1222、1229～1235、500、584、591 条，主题对应正确；环境侵权“举证责任倒置”对应第 1230 条，方向正确。**有误或不当的**：①把民事证明标准写成高度盖然性并配上大于 75% 的数值——中国法只规定“高度可能性”（《民诉法解释》第 108 条），没有百分比，写成数字会被律师直接当成错误；②给行政案件配“明显优势证据”、给保险理赔配优势证据标准，在中国法上均无明文，属移植；③医疗损害的“机会丧失理论”在中国没有明文依据，应标“学理”；④期望利益部分未引合同编通则解释第 60～62 条（利润法、替代交易差价、市场价差、持续性定期合同的合理期限、难以确定时综合裁量）与第 63 条（可预见的判断标准），只停在民法典层面。
4. **工程设计**：步骤严密但过长；置信度分级与证明标准挂钩的做法在中国法下站不住；示例过于简单（闯红灯）而没有示范真正困难的多因一果。
5. **问题与缺陷**：证明标准数字化与移植；缺合同编通则解释的计算规则；推理产出与金额计算之间没有接口。
6. **与产品对照**：产品 `calc.ledger` 已有 `penalty_check`，按合同编通则解释第 65 条给出“损失 × 130%”的参照比较（registry.ts 第 255 行附近），client-advice 第 1b、1d 步要求给出违约金被调整后的区间与比较基准——**违约金调整这一侧产品已经更好**。**产品缺**：可得利益损失没有确定性计算工具；与有过失（第 592 条第 2 款）、减损（第 591 条）、损益相抵（合同编通则解释第 63 条第 3 款，未单独核文）在金额里怎么体现，也没有结构化口径。
7. **建议决策**：**重构**——新增内核计算能力 `calc.expectation`（可得利益损失），按合同编通则解释第 60 条三种方法（利润法：可得利润 − 合理成本；替代交易差价：替代交易价 − 合同价，并提示替代价明显偏离市场价时以市场价代替；未替代交易的市场价差：违约后合理期间内履行地市场价 − 合同价）与第 61 条（持续性定期合同按合理期限计算）分口径并列测算，扣减项（减损可避免部分、与有过失比例、损益相抵）作为显式参数，输出“各口径金额 + 所需证据 + 可预见性提示”；律师只给事实与口径。因果推理部分不做独立能力，吸收两条规则进 case-analysis。优先级 **P1**（工具）/ **P3**（因果规则）。
8. **可吸收的设计精髓**：
   - 主张或反驳可得利益损失时，按合同编通则解释第 60 条的三种方法分别测算（有数据的都算），并列写出各自前提与所需证据；不得只写“可得利益损失约××元”而无算式。【可确定性检查：calc.expectation 统一计算；交付件中“可得利益”金额须能在计算表中找到——与现有“一个数只有一个出处”检查衔接】
   - 可得利益的上限检查：写明违约方订约时能否预见该类损失的事实依据（合同目的、交易类型、磋商过程，第 63 条第 1 款），不能只写“可以预见”。
   - 损害赔偿主张要显式处理三项扣减：守约方未采取合理措施扩大的损失（第 591 条）、守约方自身过错（第 592 条第 2 款）、守约方因违约获得的利益；每项写“适用 / 不适用 + 理由”。
   - 因果论证用“若无”检验时，只改变被告的行为这一个变量，其他背景事实保持不变；有两个以上独立足以致害的原因时，不得以“若无”检验否定任何一方的因果关系，改按第 1171、1172 条分析。
   - 证明标准只写法定表述（高度可能性 / 排除合理怀疑），不写百分比。【可确定性检查：交付件出现“盖然性 > / ≥ N%”“概率 N%”一类表述的，交付前检查报出——与工作准则第 7 条一致】

### 10. formal-legal-consequence（形式化推导法律后果）

1. **基本信息**：原子技能；约 50KB；六阶段（输入确认 → 基础后果 → 调整因素 → 竞合与聚合 → 量化计算 → 输出验证）覆盖民事、刑事、行政三域；含人身损害赔偿、违约赔偿、知识产权赔偿、量刑、行政处罚的计算口径；README 将其对接罪名 / 刑期预测与“法律数值计算”评测；不依赖外部检索。
2. **业务价值**：把“构成要件已满足”推到“具体后果与金额”。面向律师、法官、评测。匹配度**中**：民事后果与金额是律师刚需（产品已有一套确定性计算工具）；刑事刑期、量刑测算在产品业务线之外（没有刑事辩护线），且与工作准则第 7 条“不预测裁判结果”冲突。
3. **专业逻辑**：“基础后果 → 法定调整因素 → 竞合 / 聚合 → 量化”的四段结构正确；请求权竞合（违约与侵权择一，《民法典》第 186 条）、违约金与定金、违约金与损害赔偿关系、精神损害与财产损害并行、刑法想象竞合从一重、法条竞合特别优先、数罪并罚的分类基本准确。
   **依据核查**（能查的已查）：
   - 正确：《民法典》第 157、186（原文核对）、577～588、1179～1187、1183、1202～1207、1208～1217、1218～1228 条；人身损害赔偿以受诉法院所在地上一年度城镇居民人均可支配收入计残疾 / 死亡赔偿金、丧葬费六个月职工月平均工资、被扶养人生活费按城镇居民人均消费支出（与 2022 年修正后的人身损害赔偿解释一致，该解释不在库，未核原文）；知识产权法定赔偿上限与惩罚性赔偿一至五倍（《专利法》第 71 条、《著作权法》第 54 条已在库核对条号；《商标法》第 63 条未入库，未核）；《行政处罚法》第 9 条、第 30～33 条，《刑法》第 61～77 条相关条号（均未入库，按现行文本记忆对应正确，标未核）。
   - **错误**：①把价款十倍的惩罚性赔偿也归到《消费者权益保护法》第 55 条名下——价款十倍出自《食品安全法》第 148 条第 2 款，不是消保法第 55 条（消保法第 55 条第 1 款为价款三倍、不足五百元按五百元，第 2 款为明知缺陷致人死亡或健康严重损害的所受损失二倍以下）；两法均未入库，未核原文，但归属错误可以确定。②称违约金与定金不能并用、应“择高”适用——《民法典》第 588 条第 1 款是“对方可以选择适用”，由守约方选择，不是“择高”；第 2 款另规定定金不足以弥补损失的可请求赔偿超过定金的损失（法规库已核原文）。③把违约金超过损失三成写成可以请求减少的门槛——合同编通则解释第 65 条第 2 款原文是“一般可以认定为过分高于”，这是推定标准而非可请求的门槛；并且漏了第 65 条第 1 款“以民法典第 584 条的损失（含可得利益）为基础并兼顾多因素”、第 3 款“恶意违约方请求减少一般不予支持”、第 64 条举证责任（违约方举证，非违约方也应提供证据）与第 66 条释明（法规库已核原文）。④数罪并罚只写“总和刑期以下、最高刑期以上”，漏了总和刑期不满三十五年的不超过二十年、三十五年以上的不超过二十五年两档上限（《刑法》第 69 条，未入库，未核原文）。⑤“不当得利请求权具有补充性、其他请求权优先”在中国法没有明文，属学说，应标注。⑥人身损害总额写成“Σ各项 × (1 − 受害人过错比例)”，未提示交通事故先由交强险限额内赔付（《道路交通安全法》第 76 条，未入库）、精神损害抚慰金不机械按比例。
4. **工程设计**：分域分阶段、计算公式外显，便于核对；但公式由模型心算、数据（各地上年度统计数据、裁量基准）依赖外部，Agent 无法独立执行；刑事量刑部分与产品边界冲突。

6. **与产品对照**：产品工作准则第 4 条“计算交给工具”、`calc.ledger`（分段计息、抵充、违约金、penalty_check 130% 比较）、`calc.labor`（N、2N、三倍封顶、代通知金）、`calc.court_fee`、`calc.deadline`，加上“同一情景前提不能互斥”（第 58 批 D-238，独立复核意见 / 诉讼 / 表格三类清单都查），**在民事金额后果上产品明显更好**；amount-calc 第 47 行要求利息与违约金同期主张分口径、不相加，也比外部的“聚合关系”表述更实务。**产品缺**：①违约金与定金、违约金与损害赔偿、违约与侵权竞合三组“择一 / 可并用”关系没有写成确定性规则；②可得利益计算（见第 9 项）；③人身损害赔偿计算没有工具（依赖地方统计数据，属于外部数据条件）。

8. **可吸收的设计精髓**：
   - 每项诉讼请求写明它对应的责任形式（继续履行、违约金、赔偿损失、定金、解除后返还、利息），交付前按并用 / 择一关系表逐对检查：定金与违约金只能选一（第 588 条第 1 款），定金不足部分可另赔；迟延违约金与继续履行可并用（第 585 条第 3 款）；违约与侵权择一（第 186 条）。【可确定性检查：对诉状 / 申请书“诉讼请求”段做关键词配对检查，命中择一组合且未写“选择 / 备位 / 择一”的报出】

   - 后果推导按“基础后果 → 法定加重 / 减轻因素 → 竞合与并用 → 计算”四段写，每段的依据取原文核对；计算一律交给工具，算式与口径写进交付件（工作准则第 4 条已规定，此处只补前三段的写作顺序）。
   - 惩罚性赔偿主张须写明具体法源（消保法第 55 条三倍、食品安全法第 148 条十倍、知识产权各法一至五倍、民法典第 1185 条故意侵害知识产权、第 1207 条产品责任、第 1232 条环境侵权），不得把不同法源的倍数混写。
   - 不做刑期、罪名的推导与预测；企业合规中涉及刑事风险的，只写可能涉及的罪名与构成要件需核查的事实。

### 11. conflict-resolution（冲突解决和优先级判定）

1. **基本信息**：原子技能；约 52KB，本组最长；把三类不同性质的问题放在一起：A 法条竞合（位阶、特别 / 一般、新 / 旧、新一般与旧特别、请求权竞合、刑法竞合）、B 证据矛盾（证据能力过滤 → 证明力比较）、C 争点排序（程序先于实体、前提先于派生、短路路径）；另有刑民交叉、行民交叉、涉外、新旧法过渡等特殊场景；不依赖外部检索。
2. **业务价值**：A 类是律师写意见、诉状时的“法源适用”硬功夫；B 类对应质证与事实认定；C 类对应庭审提纲与代理词的结构。面向律师与法官。匹配度：A 类**高**，B 类**中**（框架已过时，见下），C 类**中高**。
3. **专业逻辑与依据核查**（《立法法》不在法规库，以下立法法条号按 2023 年修正后现行文本，均标“未核原文”）：
   - **基本正确**：①上位法优于下位法；②“新法优于旧法”限于同一机关制定（立法法第 103 条后半句）；③新的一般规定与旧的特别规定不一致、不能确定如何适用时由有权机关裁决（法律之间由全国人大常委会裁决、行政法规之间由国务院裁决，第 105 条）；④地方性法规与部门规章冲突须走裁决机制（第 106 条：国务院提出意见，认为应适用部门规章的提请全国人大常委会裁决）；⑤刑法想象竞合从一重、法条竞合特别优先、重法优先为补充；⑥请求权竞合由当事人选择（《民法典》第 186 条，法规库核对原文）；⑦“并非所有刑民交叉都先刑后民”，与九民纪要第 128～130 条一致（法规库 `lsv_spc_9th_minutes_2019` 核对：第 128 条分别审理情形、第 130 条以“必须以刑事案件审理结果为依据”为中止条件）。
   - **不准确或错误**：①把特别法优先的适用前提写成同一位阶即可，漏了立法法第 103 条“同一机关制定”这一前提——不同部委的部门规章同位阶但不同机关，冲突由国务院裁决，不能直接按特别法处理；②位阶链“地方性法规 > 规章”笼统，地方性法规只高于本级和下级地方政府规章，与部门规章无当然高下；③新一般 / 旧特别冲突只写“全国人大常委会制定的法律”，范围窄了（适用于法律之间，含全国人大制定的基本法律），也没写“不能确定如何适用时”这一触发条件，更没有指出**律师和法院都不能自己“报请裁决”**——实务中只能在文书里论证应适用哪一个，并提示不确定性；④消保法相对民法典优先适用的结论对，但理由不应是立法法的特别法规则（民法典由全国人大制定、消保法由全国人大常委会修订，不是同一机关），而应是《民法典》第 11 条“其他法律对民事关系有特别规定的，依照其规定”这一授权（法规库核对原文）；公司法与民法典同理；⑤**证明力比较规则已过时**：技能列出的公文书证优于其他书证、原始证据优于传来证据、直接证据优于间接证据、无利害关系证人优于有利害关系证人这一排序来自 2001 年《民事证据规定》原第 77 条，2019 年修正时已删除（法规库 `lsv_jud_civil_evidence_2019` 检索无“证明力一般大于”一类条文；现行为第 85 条全面客观审核与第 90 条“不能单独作为认定案件事实根据”的五类证据）；⑥把《民事证据规定》第 51 条当作争议焦点归纳的依据是错误的，现行第 51 条是举证期限（法规库核对）；争点归纳见《民诉法解释》庭前会议相关条文（未核条号）；⑦给民事配高度盖然性、给行政配明显优势标准——法定表述为“高度可能性”（《民诉法解释》第 108 条），行政诉讼没有“明显优势”的明文标准。
4. **工程设计**：三类冲突各自有流程、模板与检查清单，结构完整但把三个技能塞成一个，触发后模型要先判断是哪一类，容易跑偏；位阶判断全靠模型记忆每个规范的制定机关与层级，没有数据支撑——而产品法规库恰好有 `laws.level`。
5. **问题与缺陷**：见第 3 点七项；另外完全没有处理律师最常遇到的两个位阶问题：①违反规章是否导致合同无效（《民法典》第 153 条只指向法律、行政法规的强制性规定；九民纪要第 31 条：违反规章一般不影响合同效力，涉及金融安全、市场秩序、国家宏观政策等公序良俗的除外；合同编通则解释第 16～18 条进一步区分——均已在法规库核对原文）；②九民纪要等“司法指导性文件”不是司法解释，不能作为裁判依据援引，只能在说理中引用（最高人民法院 2019 年印发纪要的通知，未入库，未核原文）。
6. **与产品对照**：产品在“新旧法”一侧明显更好：citations.verify 能识别已废止法律与历史版本（citations.ts 第 402～434 行，`repealed` 与 `historical_note`），legal-research-memo 第 3 节第 2 步要求行为时法与现行法分别取原文并写“差异对本问题的影响”、禁止凭记忆换算新旧条号，client-advice 第 1e 步与独立复核 opinion 第 5a 项要求先判断适用旧法还是新法。在“材料之间说法冲突”一侧，AGENTS.md 第 3 条“双方签署或盖章的文本 ＞ 时间在后的纪要邮件 ＞ 时间在前的报价意向书”的口径规则比外部过时的证明力排序更实务。**产品缺**：①位阶与特别法规则没有任何确定性支持——`laws.level` 字段已有五档（法律 / 行政法规 / 部门规章 / 司法解释 / 司法指导性文件），citations.ts 未使用；②《立法法》不在法规库，冲突规则本身无法被引用核验；③没有“违反规章不当然无效”“司法指导性文件不作裁判依据”两条高频规则。
7. **建议决策**：**重构**（A 类，内核确定性）+ **吸收**（C 类进庭审提纲 / 代理词；B 类不吸收，产品已有更好的口径规则）。具体：①法规库补录《立法法》（2023 年修正）、《行政处罚法》（2021 年修订），使冲突规则可核验；②`citations.verify` 返回每条依据的 `level`，交付前检查与独立复核据此做三项判定（见下）；③独立复核 opinion / pleading 清单增加“法源位阶与特别法”一项。优先级 **P1**。
8. **可吸收的设计精髓**：
   - 论证合同或条款无效时，所依的强制性规定须是法律或行政法规；只援引部门规章、地方性法规或规范性文件的，必须改走公序良俗路径（第 153 条第 2 款）并写出涉及金融安全、市场秩序等的具体理由。【可确定性检查：同一论点含“无效”且 basis 的 level 全部为部门规章或以下时，提纲确认页与交付前检查报出】
   - 递交法院或仲裁机构的文书中，“法律依据”只写法律、行政法规、司法解释（及必要时的地方性法规、规章）；九民纪要等司法指导性文件只在说理段引用，写“参照……的精神”，不作请求的依据。【可确定性检查：pleading 类交付件的请求依据段引用 level=司法指导性文件的规范时报出】
   - 同一问题上引用了不同位阶的两个规范且内容不一致时，写明位阶关系、以上位法为准，下位法只作补充说明；同位阶不同机关的（如两部委规章），写明“须由有权机关裁决，适用存在不确定性”，不自行用特别法规则取舍。
   - 特别法与一般法：先找一般法中的“依照其规定”授权（《民法典》第 11 条、合同编第 467 条等）作为优先适用的依据；没有授权条款的，再按立法法“同一机关制定”的特别法规则论证。
   - 新的一般规定与旧的特别规定冲突、不能确定如何适用的，在意见中并列两种适用结果，写明裁决机制，不替法院下结论（与工作准则第 7 条一致）。
   - 争点排序：程序性争点（主管、管辖、时效、诉讼主体资格）写在前；某一争点一旦成立即可终结全案的（如时效届满、合同不成立）标为“短路争点”，在庭审提纲与代理词中优先展开，并准备该争点失败时的备位论证。

### 12. argument-strength-evaluation（评估论证强度）

1. **基本信息**：原子技能；约 43KB；论证解构 → 六维度逐项评分（法律依据确定性、事实基础、逻辑严密性、反驳抗辩力、司法实践一致性、价值判断）→ 加权综合分（四套默认权重）→ 五级强度 → 薄弱环节类型学（致命 / 重大 / 中度 / 轻度 / 潜在）→ 元评估；两则示例（严重违纪解除、股东查阅会计账簿）；不依赖外部检索。README 将其对接“文书校对、判决错误检测”类评测。
2. **业务价值**：对己方或对方论证做自我审查、找薄弱环节与修复路径。面向律师（内部审稿）、法官、评测。匹配度**中**：“找薄弱环节 + 写可修复性与修复建议”是律所内部审稿的真实工作；但加权打分（例如 W1=0.25）和“极强 / 强 / 中等”等级，在产品里会变成变相的胜诉评估，违反工作准则第 7 条。
3. **专业逻辑**：六维度里前四个（依据、事实、逻辑、抗辩）是合理的审稿维度；“致命缺陷一票否决”“两项以上短板则整体不高于中等”的规则设计合理。但“司法实践一致性”依赖案例库；以评分与直觉判断相差一级以上作为复核触发条件，而直觉判断无法定义；刑事案件事实分 ≤3 自动降级是拍脑袋的规则。
   **依据核查**：示例一引《劳动合同法》第 39 条第 2 项、第 4 条、第 43 条，条号与内容对应正确，且正确指出规章制度须经民主程序与公示、解除须事先通知工会——示范得好。**示例二自身出错**：评估报告称 2023 年《公司法》第 57 条规定股东可“查阅、复制”公司会计账簿，而法规库 `lsv_company_2023` 第 57 条第 2 款原文是股东“可以要求查阅公司会计账簿、会计凭证”，只能查阅、不能复制（复制权限于第 1 款所列章程、股东名册、会议记录、决议与财务会计报告）。被评估的论证本身写了“查阅、复制会计账簿”，评估没有发现，反而照抄——这恰好说明**不对照条文原文的论证评估会把原文错误放大**。示例二正确发现了“2024 年 1 月申请、新公司法 2024 年 7 月 1 日施行”的时间效力问题，但没有引用《公司法时间效力规定》第 1 条（施行前法律事实原则适用当时规定、例外适用新法；法规库核对原文）作出具体判断。
4. **工程设计**：模板完整，薄弱环节记录项（位置、类型、描述、影响范围、可修复性、修复建议）可直接借用；评分环节对模型来说是伪精确，同一论证重复评估分数会漂移（产品第 42 批验收时同一张卡重复评分波动约 0.5 分，打分不宜作为交付判据），不可检验。
5. **问题与缺陷**：伪量化加权评分；“司法实践一致性”依赖不存在的数据；示例二条文错误未被识别；与产品准则第 7 条冲突。
6. **与产品对照**：产品在这一能力上**整体更好**：citation-check 的“存在 → 适用 → 支持”三层顺序与“没有原文就不判”（第 3 节第 4 步）正是外部示例二所缺的；七类失配的“三段式”（依据支持到哪一步 / 结论走到哪一步 / 缺什么）比六维打分更可执行；独立复核由未参与起草的复核人按方法类型清单出“必须改 / 建议改”，修改轮逐条处置并回看（independent-review.ts）；legal-research-memo 与 case-analysis 用“明确 / 有不同理解 / 待律师判断”和“高 / 中 / 低（初步判断）+ 理由”代替分数。**产品缺**：①“致命缺陷”没有一张确定的清单，复核人对“必须改”的掌握依赖临场判断；②legal-research-memo 规定“未核验或核验不通过的命题不进入简答”，但没有代码校验；③对方文书的论证评估没有单独的入口说明（citation-check 可以核对方文稿，但方法正文以“律师的文稿”为对象，修改建议口径是“把结论收回”，不适合对方文稿——对对方文稿应输出“可攻击点”）。
7. **建议决策**：**吸收**（不引入打分）：①把“致命缺陷”写成独立复核 opinion / pleading 清单的明确“必须改”判据；②在交付前检查中实现“简答 / 结论段引用未核验依据”的确定性检查；③citation-check 增加“对方文稿模式”：同一套存在 / 适用 / 支持 / 七类失配，输出改为“可攻击点与我方回应要点”。优先级 **P1**（①②）/ **P2**（③）。
8. **可吸收的设计精髓**：
   - 独立复核的“必须改”判据写死为以下几类致命缺陷：所引条文在事件时点未施行、已废止或条号错误；条文原文的适用条件或但书与结论不符（方向相反 / 条件遗漏）；关键事实与材料矛盾；要件没有任何事实或证据支撑却写成确定结论；类推或参照适用未标明且无转介依据；同一情景前提互斥。其余为“建议改”。
   - 研究备忘录“简答”、意见书“结论”中出现的每一条依据，其核验状态必须是“原文已核”；未核或支持待判的依据不得出现在简答 / 结论段。【可确定性检查：deliverable-check 按节标题定位“简答 / 结论 / 简要结论”段，抽取引用并按 citations.verify 状态判定】
   - 每个薄弱环节写六项：位置、类型（致命 / 重大 / 一般）、为何薄弱、影响哪些结论、能否通过补证或补论证修复、具体修复动作；只写“论证不足”不合格（与 citation-check 三段式一致）。
   - 评估对方文稿时，输出方向反转：对方依据不存在 / 已失效 / 不支持其结论、要件无证据、类推无依据之处，各写成“可攻击点 + 我方回应要点 + 所需证据”，供答辩状、质证意见与代理词使用。
   - 不给论证打分、不给强度等级；对论证可靠性的表达只用“明确 / 有不同理解 / 待律师判断”与“风险高 / 中 / 低（初步判断）+ 理由”。

### 本组最值得做的三件事

1. **论点提纲结构化与内核校验（outline.submit v2）**：basis 增加 `mode`（直接适用 / 依转介参照适用 / 扩张解释 / 类推适用）、`elements`（该条要件逐项对应 fact_id 或“待证 / 不争议 / 对方举证”）、`exceptions_checked`（取原文后的但书与例外处理）。内核确定性判定：要件无事实也无状态的报出；论点依据未确认事实的在确认页标“基于未确认事实”；mode=参照适用而未同时引用转介条款（维护一张转介条款表：民法典第 464 条第 2 款、第 467、468、646、1001 条等）的报出；原文含“但是 / 除外 / 另有规定”而 exceptions_checked 为空的提示；事项涉及行政处罚、税款或刑事风险且 mode 为扩张或类推的提示“受法定原则限制”。承接演绎、类比、体系、文义四项。
2. **法源位阶确定性检查 + 复核清单“法源位阶与适用方式”项**：citations.verify 返回 `laws.level`；交付前检查实现三条——论证“无效”的论点依据全部为部门规章及以下（应改走公序良俗路径，九民纪要第 31 条）；诉讼类文书把九民纪要等司法指导性文件作为请求依据；研究备忘录“简答”、意见书“结论”段出现未经原文核验的依据。法规库补录《立法法》（2023）与《行政处罚法》（2021），使位阶、特别法、新旧法裁决规则本身可引可核。独立复核 opinion / pleading 清单增加一项：不同位阶依据冲突时是否以上位法为准、同位阶不同机关是否标明须裁决、类推与参照是否标明，并把“致命缺陷”写成“必须改”的固定判据。
3. **新增 `calc.expectation`（可得利益损失）并加责任形式并用 / 择一检查**：按合同编通则解释第 60 条三法（利润法、替代交易差价、市场价差）与第 61 条（持续性定期合同的合理期限）分口径并列测算，减损（民法典第 591 条）、与有过失（第 592 条第 2 款）、损益相抵（合同编通则解释第 63 条第 3 款）作显式扣减参数，输出各口径金额、所需证据与可预见性提示，与 calc.ledger 的 penalty_check（第 65 条 130% 比较）衔接；同时在前提互斥检查旁增加“责任形式并用 / 择一”规则（定金与违约金择一、迟延违约金与继续履行可并用、违约与侵权择一），在诉讼请求段命中择一组合而未写“选择 / 备位”时报出。
