## 0. 一页结论

**一句话**：v9.2 的安全与架构基本盘经得起再审，但**离“交给律所承接真实案件”还缺决定成败的三样东西，不在 Agent，也不在加密**：①从没有一份法律产出经过真实模型；②法规库只有 3 部法律的演示种子，研究与引用核验实际不可用；③装好的程序没有身份——每台电脑都以 `demo-firm / demo-lawyer` 自居，多人律所只能拷贝根私钥。第 13 批把③做实了（开通码、邀请码、管理员批准入组），并补了 4 个快修 P0。①②的研发侧已经就绪，现在卡在外部条件：测试额度、法规数据源、律师审校。

**本轮（第 13 批）做成了什么**：每项都有自动化测试，开通流程另在浏览器里用两台设备联调走通。

1. **评审资源配置失衡**：第 11、12 批在团队同步的成员日志上做了 11 轮以上复核，而“装好怎么登录”这一步此前完全不存在。建议团队共享功能冻结在当前状态（单人与小团队试点够用），研发转向首次使用、真实模型、法律内容和 Windows 真机。
2. **单人律所的数据可恢复性是零**：恢复包没有界面；DPAPI 把主密钥绑在 Windows 账户上，备份数据目录也解不开；创始设备的 5 份恢复份额和数据放在同一块硬盘。电脑一坏，全部事项就丢了。这是第 14 批的 P0-1。
3. **法规库是决定“法律研究”能不能卖的单点**，需要你拍板数据来源：人工采集官方文本、商业授权，或接元典 / 北大法宝 MCP。代码里已有“不自动抓取国家法律法规数据库、商业源未签约不入库”的约束。
4. **真实模型验收现在一条命令就能跑**，只差月之暗面测试组织的密钥（按约束我不使用生产密钥，需要你在自己的终端运行）。在这一步之前，所有“合同审查质量”“备忘录质量”的说法都没有依据。
5. **Windows CI 只有你能推送触发**（gh 未登录、仓库私有）。第 13 批改了主进程与打包脚本，需要跑一次 CI 才能确认安装包首次启动会停在激活页。

## 4. 架构增量（只写改变了的部分）

### 4.1 身份与开通（新增；设计稿 `platform/docs/design/开通与成员入组设计-v1.md`）

```text
中软运营 ──ops.issueActivationCode──▶ 控制面（只存码的 HMAC）
   │ 开通码（一次性）
   ▼
创始设备：待激活模式 ──闸门控制面通道──▶ /v1/activation/redeem → 认领凭据（封装暂存）
   │ activation.json → 主进程按新身份重启内核 → 生成律所根 → /v1/enroll（出示认领）→ 登记、席位
   │ 管理员：members.invite → /v1/invitations → 邀请码
   ▼
成员设备：待激活模式 → 兑换邀请码 → 本机生成设备密钥 → /v1/join-requests（公钥 + 持有证明）→ 显示核对码
管理员：members.list（本机独立算核对码）→ 核对一致 → members.approve（本机律所根签证书 + 律所公钥包）
成员设备：/v1/join-requests/<id>/fetch → 核验证书与公钥包 → 暂存 → 重启 → 登记、席位（不持律所根与恢复份额）
```

数据驻留：清单第 24 类（`activation.json` 只有编号与显示名；秘密在 keys/ 里按主密钥封装）。
