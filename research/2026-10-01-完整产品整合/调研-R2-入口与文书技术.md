### 0.2 冲突裁决

1. **WPS 能否由安装器写入 jsaddons 并合并 publish.xml，实现静默注册**
   - 两份基线的说法：入口报告认为可行但不稳；运行时复核认为不能列为生产必做。
   - 裁决：两者合并。
     - **主路径**：客户端按官方允许的方式调用 publish 方法，由 WPS 自己生成 publish.xml，再由用户在 WPS 里确认启用。
     - **兜底**：直接写文件，只作为修复工具使用。
     - **禁止**：改 oem.ini、关闭沙箱、替用户改 authaddin.json。
     - **对外话术**：不说“静默安装”，说“一键注册，在 WPS 内确认启用”。
2. **Word 在 Windows 上以 COM 还是 Office.js 为主**
   - 裁决：**Windows 默认用 COM**。理由有三条：
     - 没有 M365 租户时，Office.js 的生产部署只剩公开上架 Marketplace 一条路，网络共享和旁加载都被官方排除；
     - LTSC 2021 在表中拿不到批注和修订 API；
     - COM 加载项可以随我们的 exe 一起安装。
   - 同时采纳运行时复核的门槛：第 0 阶段先盘点合作律所，有租户且 IT 配合的律所走 Office.js 集成应用，并用等效加载项互斥；Mac 只走 Office.js；2016、2019、2021 不作为卖点。

### 1.2 Mac 版

- 官方 publish 模式的版本表里**没有 Mac**（S1，一手）。
- 社区情况：
  - Mac 上用 publish.html 在线安装不工作，原因是和 WPS 本地 58890 端口的通信建立不起来，只能手工改 jsaddons 和 publish.xml；
  - 有人这样装成功了（[S6 bbs 47510](https://bbs.wps.cn/topic/47510)、[S7 掘金](https://juejin.cn/post/7511952023380803599)、[S8 Zotero-WPSJS-Mac](https://github.com/DreamZouz/Zotero-WPSJS-Mac)）；

  - 还有作者称自己的 JS 加载项“Windows、Mac、Linux 三端通跑”（[S10 forum 92892](https://forum.wps.cn/topic/92892)）。

### 2.1 冲突裁决：Windows 上 COM 与 Office.js 谁为主路径

- 两份基线的说法：
  - 入口报告：Windows 以 COM 为主、Office.js 为辅；
  - 运行时复核：盘点客户之前不要武断排主次，满足 API 和部署条件的就走 Office.js。
- 本轮新增事实：
  1. 没有 M365 租户时，Office.js 的生产部署只剩公开上架 Marketplace 一条路，网络共享和注册表旁加载都被官方明确排除在生产之外（M2、M3）；
  2. LTSC 2021 不在 WordApi 1.4 及以上任何要求集里，LTSC 2024 也拿不到 1.9（M1）；
  3. 我们本来就要装 exe，COM 加载项可以随 exe 按用户安装。
- 裁决：**以 COM 作为 Windows 的默认主路径，同时吸收运行时复核提出的门槛**：
  1. **Windows 默认**：随 exe 安装的 COM 加载项（带 WebView2 任务窗格），覆盖零售版和批量版 2016–2024 以及 M365；
  2. **有 M365 租户（含世纪互联版）且 IT 愿意走集成应用的律所**：Office.js 为主，用等效加载项让 Office 只显示其中一个；
  3. **Mac**：只有 Office.js；
  4. **第 0 阶段盘点**：合作律所的 Office 授权类型、build、租户情况、组策略（例如是否要求加载项由受信任发布者签名）。盘点结果只调整各条路径的投入比例，不改默认架构；
  5. **对外口径**：不把 2016、2019、2021 作为卖点，标注为“尽力兼容，可下载修订稿兜底”。

### 4.1 企业微信

- **智能机器人接收消息**（一手，[W1](https://developer.work.weixin.qq.com/document/path/100719)，页面标注“最后更新 2026/05/18”，本轮用浏览器渲染核对）

    - 群里只有 @机器人的文本、图文混排、引用会回调；
    - 图片、语音（转成文字）、文件（100M 以内）、视频只在单聊回调；

### 4.2 钉钉

- **可以收文件**：官方文档“下载机器人接收消息的文件内容”写明，用户向机器人发送图片、语音、视频、**文件**、富文本消息时，回调里给临时下载码，再调这个接口换下载链接（[D2](https://open.dingtalk.com/document/isvapp/download-the-file-content-of-the-robot-receiving-message)，一手检索摘要）。
- **回调字段**：区分单聊（conversationType=1）和群聊（=2）；`senderStaffId` 是“企业内部群中 @该机器人的用户 ID”；有 `isInAtList` 字段；会话 webhook 带过期时间（[D3 机器人接收消息](https://help.dingtalk.io/zh/open/dingstart/robot-receive-message)，一手镜像页）。
- **官方 SDK**：Python 版 Stream SDK 只封装了图片和富文本里的 `downloadCode`，没有封装 file 类型（[D1 chatbot.py](https://github.com/open-dingtalk/dingtalk-stream-sdk-python/blob/main/dingtalk_stream/chatbot.py)，一手源码）。
- **查不到、列入探针**：群聊里不 @ 的文件能否触发回调、下载链接有效期、文件大小上限、AI 助理市场与应用上架的分成规则。

### 4.3 飞书（一手，飞书文档门户 JSON）

- **接收消息事件**（[F1](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)，文档 2026-08-05 更新）：
  - 群聊默认只推送 @机器人的消息；
  - 申请敏感权限“获取群组中所有消息”（im:message.group_msg）后，可以收到群里所有用户的消息，包括不 @ 机器人的文件；自建应用和商店应用都能申请；
  - 推送可能重复，要用 message_id 去重。
- **获取消息中的资源文件**（[F2](https://open.feishu.cn/document/server-docs/im-v1/message/get-2)，文档 2026-08-27 更新）：
  - 文件小于 100 MB 可以直接下载；**100 MB 及以上可以用 Range 分片下载**，每片不超过 32 MB；
  - 图片只支持完整下载小于 100 MB 的；
  - 频率上限为每分钟 1,000 次、每秒 50 次；自建应用和商店应用都支持；机器人必须和消息在同一会话；
  - **错误码 234009：“暂不支持在外部群中进行本操作”**。
- 对方案：
  - 在三家里，飞书群内收文件的能力最强；
  - 但**律师和客户的外部群拿不到文件**，只能引导律师转发到单聊或内部群。
