# 第 4 篇　技术架构与研发计划

版本 4.0 · 2026-10-01 · 技术证据截点 2026-10-01（本轮 R1、R2 核验）

## 1. 架构结论

**单一云端执行内核 + 本机能力层。** 所有分析、规则应用、模型调用、法源核验与审批都在中软境内法律云执行，桌面、Office、IM、后台共用同一事项、权限、成果、权益与审计；律师电脑上不运行第二套通用 Agent，只承担本机才能做好的事：事项文件夹挂载、本机原件模式、在 Word/WPS 宿主内写入原生修订、离线阅读与安全导入。

```text

   本机能力层：文件挂载 · 本机原件解析 · 宿主修订桥 · 离线缓存 · 反向工具通道
                      │  统一身份 · 法律 API（BFF）· 事件流
                      ▼
   ┌──────────────────────── 中软法律云（境内） ────────────────────────┐
   │ 业务域：租户/成员/伦理墙 · 事项 · 材料与解析版本 · 成果与签发 · 席位与权益 │
   │ 持久编排：任务 / 尝试 / 事件账本 / 预算 / 取消 / 对账（DBOS → Temporal）    │
```

为什么不在本机跑 Agent（相对 opus 09-28 方案的修改）：

1. **治理**：审批、签发、审计、预算必须在服务端可信执行；本机执行仍要把这些全部回传。
2. **方法资产保护**：Playbook 与本所覆盖层只在服务端组装，不下发客户端。
3. **多入口一致**：IM、Office、批量与定时本来就需要云端执行；本机再执行一份会产生两套事实。
4. **端侧安全**：Kimi Code 上游仍有加固回滚未恢复、项目级 skills 自动发现无开关、Hook 失败放行、配置的权限规则不执行等问题（R1 一手）；放在律师电脑上，每台电脑都是攻击面，还要面对 TC260 部署指引“独立设备安装”的举证。
5. **测试面减半**：一个内核、一套恢复与计量语义。

桌面价值由本机能力层承接（第 2 篇 §4.1）。

## 2. Kimi Code：用哪些能力、怎么接

### 2.1 10-01 核验的关键事实（R1，一手）

- 最新 release 仍为 2.1.1（09-24）；main 已前进 13 个提交，**ACP 服务端零改动**；2.1.0 工作区安全加固**仍未重新合入**。
- **可以库内嵌**：`packages/node-sdk` 在进程内启动引擎（`@moonshot-ai/klient/memory`），官方 CLI 本身也经由该 SDK 调用引擎；但 SDK **未发布到 npm**、没有稳定性承诺，须从源码自建并锁定提交。引擎以 `homeDir` 为作用域，配置、会话、MCP、skills 都落本地文件系统。
- 权限：配置的权限规则不执行的问题（PR #2337）仍未合入；**后台子代理发起的审批不触发 PermissionRequest hook**（#4070）。
- 项目级 skills 自动发现仍无开关；Hook 仍失败放行；遥测仍默认开启，中文与 Windows 路径脱敏 PR 未合入。
- 待发布的 `KIMI_CODE_TRUST_WORKSPACE` 环境变量会让案卷目录中的项目级 MCP 直接生效：**服务端 worker 禁止设置**。
- 远程执行目标（SSH/Docker，PR #4062）未合入；合入后可实现“引擎在控制面、工具在沙箱”。
- 官方 `kimi-agent-sdk` 存在但包装的是已归档的旧 CLI，不采用。

### 2.2 能力裁决

| 能力 | 怎么用 | 不用 / 替代 | 理由与风险 |
|---|---|---|---|
| Agent 循环 | **库内嵌**：中软 fork 自建并锁版的 `kimi-code-sdk`，在每事项一个隔离 worker 内进程内驱动；`kimi acp` 作为备选接入 | 结构化工作流不经过 Agent | 官方 CLI 走的就是这条路径；ACP 只代理文本 IO 且有未修问题 |
| 上下文压缩 | 随引擎使用 | 结构化流程由我方分段与摘要 | 压缩会丢锚点：关键证据在压缩前写入我方证据账本 |
| Skills（SKILL.md） | 沿用格式；**补丁关闭项目级自动发现**，只挂中软签发的只读目录 | — | 跨引擎格式；案卷里的 `.agents/skills` 不得被加载 |
| MCP 客户端 | 只连中软法律工具网关（HTTP，短期能力令牌）；不启用 stdio 与项目级 `mcp.json` | — | 网关统一鉴权、审计、schema 清洗（平台对工具 schema 校验严格） |
| 内置工具（Shell、文件读写、搜索、浏览器） | **全部禁用** | 计算、文书、检索用确定性法律工具 | 律师场景不需要；最大攻击面 |
| 子代理 / 并行 | 只允许中软定义的法律 subagent（同样只有法律工具）；**不继承内置 `coder`/`explore`/`plan`**（`coder` 可在后台执行 Shell） | 跨事项、跨租户并行由编排器调度 | #4070 子代理审批不触发 hook；自定义 Agent 缺省继承内置委派列表 |
| 会话恢复 | 引擎本地状态只作缓存 | 从我方检查点重开任务 | 容器重建即丢失；权威状态在中软库 |
| 审批 | 引擎审批事件只作第一道提示 | **工具网关强制审批 + 业务门禁**（绑定工件 hash 与对象版本）；外发、签发、删除类工具根本不暴露给引擎 | #2337 未合入、Hook 失败放行 |
| 计量 | 引擎 usage 只作参考 | **模型网关**按请求记账并与供应商账单对账 | 只有网关能准确归集缓存写入与推理档位 |
| 品牌 | `[identity]` 白标替换自称与 User-Agent | — | MIT 只需保留版权与许可声明；不授予商标权，品牌以书面授权为准 |

**一句话**：Kimi Code 是“开放任务的可替换执行器”，负责 Agent 循环、上下文压缩、Skills 加载与事项内子任务；权限、审批、权威状态、并行、计量与工具全部由中软控制面掌握。

**版本治理**：每两周评估上游；ACP/SDK 契约、隔离与注入探针回归通过才合入；高危问题 7 天内评估并灰度；关注 #4062 合入后改为“引擎在控制面、工具在沙箱”。

### 2.4 Agent worker 隔离

每个事项（或每次 Agent 任务）一个独立 worker：独立 `homeDir` 与临时工作目录；只读挂载本次任务快照中的派生文本（不挂原件、不挂宿主目录）；无数据库长期凭据、无云元数据访问、无 Docker socket；出站白名单只有模型网关与法律工具网关；CPU/内存/时长/进程数/磁盘上限；任务结束销毁。首发可用 gVisor 或轻量虚拟机，多租户共享集群后用 Kata 等强隔离运行时。

### 2.5 降级与替代

- **Hosted Agents（Beta）**：只用合成/公开材料做对照 PoC；升生产须过 H1–H8（商用与容量、数据留存、事项隔离、默认拒绝、网络与关键工具、可恢复、可计量、可退出）。10-01 核验：仍只有 `always_allow`，不适用 ZDR；MCP 连接失败会发错误事件，但凭据刷新失败不发——交付闸门须逐项核对法源调用记录。
- **自有最小工具循环**：约千行代码，用同一法律工具与同一模型网关，作为 Kimi Code 不可用时的降级路径；不产品化第二个通用内核。

## 3. 本机能力层（客户端）

| 组件 | 实现 | 要点 |
|---|---|---|
| 外壳与界面 | Electron（跟随受支持主线：Kimi 桌面用 43.7.3，应至少升到 43.7.7 或 44.x；42 线 2026-10-20 结束支持）+ React/TypeScript；设计令牌来自 Kimi Work 实测 | renderer 沙箱、上下文隔离、无页面 Node；组件库与加载项、IM H5、后台共用 |
| 本机服务（sidecar） | Node（或 Rust）常驻子进程；只监听 127.0.0.1 随机端口，一次性令牌握手并校验来源 | 文件挂载与监听、hash、分块上传与断点续传、本机原件模式的文本抽取、宿主修订桥、离线缓存 |
| 反向工具通道 | 与云端的双向认证 WebSocket；云端工作流可请求“读取挂载目录中的某文件”“把成果写到律师选定的目录”“在 Word/WPS 打开某文件” | 每次请求校验事项与目录授权、记录审计；客户端离线时任务进入“等待输入” |
| 本机原件解析 | DOCX（Open XML）、PDF 文本层；扫描件在本机原件模式下不处理（G3 视本机 OCR 实测） | 只把审查所需的条款文本发到云端；锚点与 hash 在本机与云端一致 |
| 宿主修订桥 | 接收结构化修订指令（锚点、原文 hash、新文本、批注、作者与来源标记），交给 Word COM / WPS JS 写入 | 锚点不符即停止并转人工；不覆盖原件 |
| 离线缓存 | 获准缓存的事项材料与成果，加密存储，密钥由租户密钥包裹 | 撤权后联网即失效；如实说明无法撤回已导出的明文 |
| 更新 | 签名、增量、灰度、回滚；LTS 与快速通道 | MSI/企业分发由我方更新服务推送 |

## 4. 法律云

### 4.1 服务划分

控制面采用模块化服务，首发不拆成大量微服务；文档解析、Agent 执行、连接器因信任边界分别隔离。业务事实与权限由服务端掌握，客户端缓存与 localStorage 不构成有效授权、付款或签发证据。

| 服务 | 职责 | 技术选型（建议） |
|---|---|---|
| 身份与组织 | 租户、成员、角色、席位、SSO、IM 账号绑定、设备 | 可评估复用中软 AllMeta 身份模块 |
| 事项与权限 | 事项、成员、伦理墙、处理模式、**当事人同意状态（拒绝即禁用云端模型）**、策略版本；检索前过滤 | PostgreSQL + 行级安全作第二道防线 |
| 材料与解析 | 原件不可变版本、解析版本、锚点、质量标记 | 对象存储（租户密钥加密） |
| 持久编排 | 任务、尝试、事件账本、预算、取消、对账 | **DBOS（MIT，库形态，只依赖 PostgreSQL）首发**；规模化或跨语言时迁 **Temporal（MIT）**；不用 SSPL/BSL 引擎做核心（R1） |
| 确定性工作流 | 合同、回稿、案卷、文书、脱敏、研究 | Node/TypeScript + **Vercel AI SDK**（Apache-2.0，官方 Moonshot provider，源码层面已回传 `reasoning_content`）；须在 G0 实测（R1 仅核到源码） |
| Agent 运行时 | Kimi Code 引擎（自建 SDK 内嵌）+ 隔离 worker | 见 §2 |
| 模型网关 | 见 §4.2 | 自建（TypeScript/Go）；流量层可选 Higress/Envoy AI Gateway 等宽松许可组件；**中软 MaaS 的 new-api（AGPLv3 + 附加署名条款）不进入网关核心**，至多作上游渠道池并按 AGPL 处理修改 |
| 法律工具网关 | MCP 端点（HTTP）：`materials.*`、`law.search/get_version`、`cases.search`、`citations.verify`、`docx.propose_revisions/compare/render`、`calc.*`、`redact.*`、`enterprise.lookup` | 远程 MCP 强制 OAuth/短期能力令牌；数据商连接器统一挂在网关后；按 Source Registry 控制缓存、展示与导出 |
| 文档服务 | 解析、OCR、锚点、修订写入、整稿比对、受众净化 | .NET：Docxodus（锁版本、镜像）为默认，Open XML SDK 自研薄层为替代，商用引擎兜底；同台评测（§5.4） |
| 检索 | 事项材料、本所知识、外部法源三层分开索引；权限过滤在召回之前；缓存键含授权域 | Qwen3-Embedding + Reranker 基线，BGE-M3 备选，以自建评测集决定 |
| 审计 | 追加事件、访问控制、独立存储；关键检查点服务端签名锚定 | 普通日志不存案卷正文 |
| 权益与计费 | 席位、点数预留/扣减/返还、成本账、订单、发票 | 客户点数与真实人民币成本分账 |
| 渠道适配 | IM 回调验签、防重放、幂等、卡片、免登 | 每平台一个适配器，共享渠道契约 |

### 4.2 模型网关（成本与合规的中枢）

| 能力 | 设计 |
|---|---|
| 接口 | OpenAI 兼容与 Anthropic 兼容端点（Kimi 官方两者都提供，R1）；所有工作流与 Agent worker 只连网关；月之暗面主密钥只在网关 |
| 身份 | 每个请求带短期令牌，绑定租户、席位、事项、任务、尝试 ID；拒绝模型或客户端自报身份 |
| 提示组装 | “系统提示 → 基础 Playbook → 本所覆盖层 → 材料片段 → 任务”，稳定前缀在前以命中缓存；Anthropic 兼容端点只认**顶层** `cache_control`，不传则只读不写（R1） |
| 推理档位 | K3 `reasoning_effort` **默认 `max`**：网关按步骤强制 `low`/`high` 分档，避免推理 token 推高成本（R1）；温度固定 1.0 |
| 路由 | 法律判断步骤 K3；抽取、分类、摘要 K2.6 / K2.7-code；核验、计算、格式、比对用代码；夜间批量抽取走 Batch（仅 K2.6 / K2.7-code，标准价 60%；K3 不支持 Batch）。只在经评测等价的模型间切换，不为可用率静默降级 |
| 结构化输出 | `json_schema` strict；`tool_choice=required` 仅 K3 支持 |
| 额度与预算 | 团队池、个人软上限、单任务上限；请求前预留、执行中计量、超限先保存部分结果再暂停 |
| 计量 | 未命中/命中/缓存写入（5 分钟、1 小时）/输出（含推理），工具调用与费用，按租户/人/事项/任务归集，每日对账 |
| 化名二次校验 | 发现未替换的直接标识符即拦截或补替换，并记录 |
| 配额 | 公开最高档 Tier5 仅并发 100、TPM 500 万（R1）：专属企业额度写进采购合同；网关做租户公平队列，批量让路交互 |
| 日志 | 默认只记元数据与 hash；正文按租户策略加密留存、限人查看、到期删除 |

### 4.3 领域对象与权威记录

统一使用服务端生成的稳定 ID；内容版本不可变；时间存 UTC。

| 对象 | 最小关键字段 | 约束 |
|---|---|---|
| Tenant / User / Membership | tenant_id、user_id、role、authz_version | 管理员角色不自动获得案卷正文权限 |
| Seat / Entitlement | 席位类型（生产 / 审阅签发 / 管理）、有效期、额度池 | 同人跨四端共用；回收席位不删机构案卷 |
| Matter / MatterPolicy | 立场、法域、适用时点、成员、保密等级、处理模式、policy_version | 权限与数据去向由服务端确定 |
| DocumentVersion / ParseVersion | 原件 hash、存储位置（云/本机）、格式/页数、解析器版本、质量标记 | 原件只读；纠错建新版本 |
| EvidenceAnchor | document_version、parse_version、页/段/表格/字符区间、原文 hash | 转换前后位置有映射 |
| LegalSourceVersion / LicensePolicy | 公布/施行/失效日、法域、条文/案号、核验时间、许可动作 | 现行与历史适用分开 |
| Claim / Citation / Finding | 命题、来源锚点、风险等级、规则、支持性结果、律师适用结论 | 生成器无权标记“律师已确认” |
| RulePackage / TemplateVersion | 适用范围、立场、版本、制品 hash、测试报告、发布/撤回人 | 发布前法律审校 |
| Run / Attempt / ToolOperation | 输入快照、预算、运行版本、状态、租约、fence、幂等键 | run 与供应商会话分开 |
| ArtifactVersion / Review / Approval | 基线、patch、最终 hash、受众、未决项、批准人、有效期 | 签发绑定最终字节 |
| Usage / PointLedger / CostLedger | request_id、token 分类、工具/OCR 实耗、点数预留/扣减/返还 | 失败退点不抹掉真实成本 |
| ChannelBinding / Device | 平台用户 ID、我方成员、凭据引用、设备状态 | 群成员不自动成为事项成员 |
| Audit / Retention / Export / Deletion | 操作者、动作、对象/策略版本、hash、保全、回执 | 保全与删除冲突可表达 |

### 4.4 状态与故障语义

| 情况 | 必须的语义 |
|---|---|
| 律师编辑、补文件、改立场 | 新版本与依赖重算；只有未变化且依赖未变的结论可继承；关键变化使相关批准失效 |
| 两个 worker 或两个入口同时写 | 租约与 fencing 拒绝过期 worker；乐观并发拒绝旧基线；禁止“最后写入者获胜” |
| 模型或检索 429 / 超时 | 有界退避与总预算；无副作用读请求可重试；已提交上游而结果未知先对账 |
| worker 崩溃 | 以落库事件与检查点恢复，检查工具操作账本；上游会话存在不等于业务动作幂等 |
| 取消 / 撤权 | 立即拒绝新的受控工具调用，传播到子任务；显示已经发生的动作 |
| 审批后改正文、附件或受众 | 原批准失效；批准 A 版不能用于 B 版 |
| 外部动作结果不明 | 标记“对账中”，用幂等键与回执查询；不盲重发 |
| 发布 / 回滚 | 固定运行时、方法包、工具、模型路由与内容版本；灰度后新任务切换；安全撤权优先于旧版复现 |
| 备份恢复 | 先恢复权威对象与关联，再重放恢复点之后的撤权与删除记录，验证后开放读取 |

## 6. 安全

**端侧**：客户端无 Shell、无通用 Agent、无浏览器驱动；文件访问只限律师挂载的目录，原件只读；本机服务只监听 127.0.0.1 并握手校验来源；出站只允许法律云；签名更新；遥测只采集不含内容的产品事件。

**云侧三道边界**：资源（每次运行独立受限环境，原件只读，无宿主目录、云凭据与容器套接字，默认拒绝外联）；工具（只开放受控工具网关与模型出口，运行时只拿短期、限定事项的能力凭证）；业务（每次读取、检索、导出、签发重新检查权限，撤权后终止旧上下文）。文档解析 worker 放在无外网、低权限的隔离环境。

**注入**：案卷内容一律作为数据；材料中的 `AGENTS.md`、`.agents`、hooks、skills、伪系统指令不改变权限或工具集；恶意 ZIP、路径穿越、软链接、压缩炸弹在解析前拦截。

**供应链**：固定版本与镜像 digest、SBOM 与许可证清单（Kimi Code MIT 声明；其仓库内 VS Code 扩展为 Apache-2.0，仅复用时带 NOTICE 义务）；安全补丁高危 7 天内评估并灰度。

**对照 TC260《智能体部署使用安全指引》**：由于客户端不含智能体，指引中针对本地智能体的条款（非管理员运行、授权目录、仅本机服务、全量日志、高风险操作二次确认、急停、可回溯、不强制回传）在云端执行器与客户端分别落实，并出具逐条对照表；后台一键导出智能体资产登记表（名称用途、部署位置、责任人、模型名称版本与接入方式、技能与连接器清单、可访问系统与数据、权限、审查记录）。

**研发门禁**：风险登记册与高风险操作清单；工具调用前授权校验并完整记录参数与结果；知识库与索引完整性保护；长期记忆删除后清理索引与缓存；间接提示注入红队；更换模型或调整工具权限时重新评估并灰度。

## 7. 性能、容量与可靠性口径

- 受理 API P95 ≤ 2 秒（不含文件传输）；交互任务排队 P95 ≤ 30 秒；取消受理后工具网关不再批准新动作，进程回收 P95 ≤ 10 秒。
- 长任务按第 3 篇的标准包测试；超时与失败不得从延迟和成功率样本中删除。
- 并发目标由试点峰值到达率、每任务调用次数与占用时间推导，测试预期峰值与 2 倍短时峰值；供应商限流（Tier5 并发 100）由专属额度合同解决。
- 成本按 run/attempt 记录各计费桶，关联价格版本与供应商 request_id；每日对账，迟到账单与缺 usage 不当零成本。
- 平台可用性 99.5%（受理、执行、供应商分开计算并公布端到端成功率）；RPO ≤ 15 分钟、RTO ≤ 4 小时为待测目标。
- **专属云**：同一代码与基础设施即代码模板部署单租户实例（独立数据库、对象存储、worker 池与 KMS 密钥），2027-Q3 作为高敏客户的正式选项；高敏场景评估机密计算（TC260-PG-20268A 建议）。
- **基础设施**：部署在境内云的合规区或中软自有 IDC（可优先评估中软既有的境内云合作资源），多可用区；对象存储与数据库使用租户级密钥（KMS 托管，支持轮换与吊销）；按等保三级控制目标建设，依法定级测评后再对外表述。
- **模型供应商连续性**：月之暗面 API 故障或限流时，交互任务排队并如实显示等待原因，批量任务让路；**不自动切换到其他厂商模型**（品牌合作、数据条款与质量回归都不允许静默替换）；长时间不可用的处置（延期、退点、客户通知）写进服务协议。任何替代模型须事先评测、取得律所书面同意并完成数据条款，才可作为合同约定的备援。

要点：权威状态、审批、计量都在我方（账本、工具网关、模型网关）；引擎的会话与 usage 只作缓存与参考。ACP 备选路径（`kimi acp`，stdio JSON-RPC）使用同一配置与工具网关。

### 9.6 客户端与云端的关键接口（中软待建，示意）

| 接口 | 请求要点 | 约束 |
|---|---|---|
| `POST /legal/v1/matters` | 标题、立场、法域、处理模式、策略 | 无权选的模式拒绝 |
| `POST /matters/{id}/uploads` → `:complete` | 文件名、大小、类型、sha256 | 服务端复算 hash 与扫描，合格才进入快照 |
| `POST /matters/{id}/runs:estimate` | 场景版本、材料版本、交付范围 | 返回预计点数、缺口、有效期 |
| `POST /matters/{id}/runs` | estimate_id、输入清单、预算上限、幂等键 | 原子预留权益；同键同内容返回原任务 |
| `GET /runs/{id}/events?cursor=` | 不透明游标 | 先鉴权；可续传；不泄露无权对象是否存在 |
| `POST /runs/{id}:cancel` | expected_version、原因 | 立即拒绝新工具调用 |
| `POST /artifacts/{id}/revisions` | 基线版本、修订指令、锚点与原文 hash | 冲突返回 409/412，不静默覆盖；客户端与加载项共用 |
| `POST /artifacts/{id}/approvals` | 确切版本、交付清单 hash、受众 | 服务端先核强制检查与批准人权限 |
| `POST /deliveries` | 批准 ID、版本、受众 | 不可变交付包；下载与人工外发分开记录 |
| 反向通道 `local.read / local.write / host.open` | 事项、挂载目录、文件、操作 | 客户端校验授权并记审计；离线时任务等待 |

### 9.7 十二项探针（G0 退出条件）

1. **内核**：自建 SDK 内嵌的 Kimi Code 引擎新建、提示、取消、恢复正常；法律 profile 在新建、恢复、重启后都生效；缺 profile 时失败关闭；ACP 备选路径同样通过。
2. **工具与隔离**：禁用工具在模型可见层与执行层都被拒绝；worker 无法读取任务快照以外的文件、无法访问网关以外的网络；遥测、自动更新、远程控制零外连（抓包验收）。
3. **注入**：案卷里放 `AGENTS.md`、伪工具指令、隐藏 skills 目录、项目级 `mcp.json`、符号链接、路径穿越压缩包，无法改变策略或越权读取。
4. **审批旁路与委派**：子代理发起的高风险工具调用在工具网关被拒绝（对应上游 #4070）；法律 Agent 无法派发内置 `coder` subagent。
5. **文书保真**：50 份真实结构中文合同（多级编号、表格、页眉页脚、原有批注与修订）生成的修订稿，在 Word 2016/2019/2021/2024/M365 与 WPS 中打开、逐条接受/拒绝、保存再打开零损坏；整稿比对候选同台。
6. **Office 宿主**：Word COM 写修订；WPS 加载项按官方方式分发与运行；记录每个宿主 build、授权类型、位数与 API 能力。
7. **化名**：直接标识符漏替换为 0、姓名召回 ≥ 99%；化名前后高风险召回下降 ≤ 2 个百分点。
8. **成本与时延**：S1/S2/S4 的 P50/P95 token、费用、耗时实测；缓存命中率；推理档位对质量与成本的影响；校准经济模型。
9. **框架兼容**：Vercel AI SDK + Moonshot provider 在 K3 多轮工具调用中正确回传 `reasoning_content`；Anthropic 兼容端点的缓存与 thinking 签名行为。
10. **并发**：模拟 100 名律师同时执行，观察限流与网关排队、组织项目数与 API Key 上限。
11. **分发**：签名安装包在 Windows 10/11、Defender 与主流国产安全软件环境下安装运行；8 GB 内存笔记本资源预算达标。
12. **IM**：从选定平台转发 100 MB PDF 与聊天截图进入事项，在平台下载有效期内拉取，云端处理后卡片回传；群转发不扩权。
