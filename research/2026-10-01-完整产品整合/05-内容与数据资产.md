# 第 5 篇　内容与数据资产

版本 4.0 · 2026-10-01

一句话分工：**中软拥有方法，律所拥有知识，数据商拥有数据，月之暗面拥有权重。** 发行版的长期壁垒不在模型，也不在数据规模（数据商以 MCP 向所有平台分发，竞品同样买得到），而在中软自己生产、持续维护的**方法资产、模板资产与评测资产**，以及由此形成的“按本所标准干活”的能力与服务。Harvey 以 K3 为基座做法律后训练时，真正投入的是约 1,750 个由律师标注的法律任务环境——这说明资产在任务、标注与评测，不在基座。

## 2. 法源数据

### 2.1 策略：授权数据服务建版本库，授权检索补覆盖，官方网站只做人工核验

10-01 核验（R4）改变了 09-28 的路径：国家法律法规数据库的批量下载是站内功能并配验证码，没有开放接口或再利用授权声明，**不得自动化调用**（并有“非正常技术获取”的合规风险），因此**降为人工核验入口**；法律之星新上线的“法规订阅数据服务”（存量一次交付 + 增量接口同步，含时效性、效力级别、修订与废止沿革，页面明示用于“在你系统内自建法规库”）成为自建法规版本库的**合法 P0 来源**，但价格与协议未公开，须签书面许可。

| 数据 | 获取方式 | 约束 |
|---|---|---|
| 法规版本库（自建加工层） | **法律之星数据服务（书面许可）**：存量 + 增量同步；我方按“某时点适用版本”建模，并用官方网站人工抽检 | 合同写清：允许 RAG/切片/嵌入与送入第三方模型推理、多租户、展示与导出摘录、终止后已签发成果与审计快照可留存、**不训练** |
| 法规检索与引用核验 | **法律之星 MCP**（P0）：协议允许付费期内“集成至商用产品、面向终端用户提供服务” | **禁止用返回数据训练、微调、验证、测试任何模型**（评测集也不能用）；禁止“供 AI 应用之外使用”的系统性缓存或镜像——应用内会话级缓存的边界须书面确认；建议标注数据来源 |
| 案例 | **元典企业版与北大法宝 MCP/CLI 并列 P0 询价**（法宝已开售，带“不经 LLM”的 CLI 批量通道）；人民法院案例库案例经法信书面授权（P1） | 两家公开条款都没有多租户授权：**未签企业合同前只做单租户试点**；合同单列多租户嵌入、QPM、缓存与嵌入、送入模型、导出摘录、终止后留存、训练与评测 |
| 官方网站 | 国家法律法规数据库、人民法院案例库、中国裁判文书网（仍在运营） | **只做律师点开核验的权威链接**；不爬取、不批量下载、不缓存入库、不送入模型 |
| 企业信息 | 企业信息 API 按调用计费，计入任务成本 | 不爬取；实名查询走单独授权的工具并留痕 |
| 官方样式与范本 | 67 类要素式文书（法院官网 PDF）；市场监管总局合同示范文本 | 要素式：逐份核对 2025 版版本指纹（部分地方法院仍挂 2024 试行版）；示范文本库**未明示允许商用改编**：首发只做“引用 + 跳转官方下载 + 本地解析用户自行下载的文本”，批量内置前向市场监管总局书面确认；改编版标注“基于××示范文本改编，非官方文本” |
| 加工层（中软自建） | 法条版本链、适用时点查询、条文与规则的引用关系、效力状态标签 | 以授权数据为底；不超出许可范围使用 |

**明确禁止**：自动化访问国家法律法规数据库、裁判文书网、人民法院案例库；用浏览器自动化驱动律师个人的北大法宝、威科、企查查等账号；把数据商数据汇编后对外分发；**用商业法源返回的数据做训练或评测**；绕过验证码或风控。

**检索去标识**：向数据商只发送抽象争点与必要事实要素，不发送客户名称、证人身份或整份事实摘要。

### 2.2 Source Registry（来源登记簿）

每个来源及文档登记：来源主体与 URL、官方/商业类型、取得渠道、许可合同与到期日、**允许动作集合**（检索 / 全文展示 / 摘引 / 缓存 / 向量化 / 送入模型 / 导出 / 训练 / 终止后留存）、地域与租户与并发限制、引用展示要求、删除义务、获取时间、原文 hash、文档版本、可靠性状态、撤回或下架原因。

运行时每次检索、展示与导出按 `source_license_id + allowed_action + tenant_entitlement + valid_until` 校验。**权限不足时停止相应动作，不让模型补全未获授权的全文。** 采购时谈清三件事：合同终止后需要删除的缓存与向量；依法依约可以保留的既有签发成果与必要证据；不能继续提供的在线检索。

### 2.3 G2 最小权威数据集

1. 300 部高频法律法规的版本链（法律之星数据服务书面许可 + 官方网站人工抽检）；
2. 法律之星 MCP 付费授权（法规检索与引用核验；S5 升档条件）；
3. 一家案例源的企业合同（元典或北大法宝，含多租户条款；S4 升档条件）；
4. 首批 6 份要素式样式（买卖合同、民间借贷、金融借款合同的起诉状与答辩状，新版）；
5. 一家企业信息 API。

### 2.4 预算（假设，询价后替换）

法源按量费用计入任务成本（研究任务约 12 元/次占位）；固定费用（企业保底、案例授权、企业信息）2027 年约 80 万元、2028 年约 150 万元、2029 年约 250 万元，进入经济模型。试点期 50 席以内按量约 2–10 万元。

## 3. 方法资产

### 3.1 Playbook 规则包

**结构**：合同类型 × 我方立场 × 审查尺度 → 规则集。每条规则：编号、适用条件、首选立场、可接受范围、可退让至、不可接受情形、标准修改文本、法律依据（链接法规版本库的具体版本）、风险等级、对客户的解释、谈判说明、测试样本、复核与更新责任人。

**三级内容域**：平台基础规则 → 本所覆盖层 → 事项指令。覆盖有优先级，但不能覆盖法律硬限制、租户权限与安全出口；冲突在审查前显式解释采用顺序并记录。历史任务固定引用当时版本。

**生产线**：需求与来源清权 → 法律工程师起草 → 领域律师审校 → 开发集回测（≥ 20 例）与盲测 → 法律质量负责人批准 → 签名制品发布 → 灰度 → 线上反馈 → 法变维护。Skill（方法包）是方法说明、输入输出 schema、工具权限、模板与评测的组合，不只是一份 SKILL.md 文本。

**产能**：1 名法律工程师约 2 周完成 1 套规则包的起草与开发集回测；盲测双标另计约 1.5 小时/任务/人。G1 的 18 套由 5 名法律工程师在 10 周内完成起草（前 4 周已在 G0 起步），外部专家承担审校与标注。

**覆盖计划**：G2 18 套（第 3 篇 §3 的 9 类 × 双立场）；2027 年末 30 套（加增资投资、建设工程、融资租赁、委托代理、合作联营、数据处理）；2028 年末 40 套以上。数量不是质量证明：每套必须通过盲测才上架。

**法变联动**：规则引用法规版本库中的具体版本。法规修改或废止时，系统列出受影响规则、进行中任务与历史签发件；紧急变更当天评估并可暂停规则，普通变更目标 5 个工作日完成影响审查；来源不能及时更新时显示“最后核验日 / 覆盖限制”，不显示“最新有效”。

### 3.2 规则提炼助手（新增）

把“本所标准”从人工 FDE 写作变成**工具辅助、人工审定**：

1. 知识管理员或 FDE 上传本所历史审查意见、修订稿、内部审查清单（事项授权范围内、经权利确认）。
2. 系统比对“原稿 → 律师修订稿”的差异，聚类出候选规则：触发条款、修改方向、频次、示例与出处。
3. 法律工程师逐条编辑为规则包格式，标注与平台基础规则的关系（加严 / 放宽 / 新增）。
4. 在本所样本上回测，生成差异报告。
5. 团队合伙人批准后发布为本所覆盖层；不自动上线，不进入平台基础规则。

G2 作为 FDE 内部工具使用；G3 开放给知识管理员。它对应的验收：候选规则出处可回链 100%；未批准规则零生效；回测报告随发布归档。

### 3.3 方法资产保护

1. Playbook、规则库与本所覆盖层存放在云端注册表，由服务端组装进提示；客户端只收到“触发了哪条规则、为什么”的解释。
2. 方法包以签名制品发布到云端执行环境，不下发客户端。
3. 私有化版按合同授权部署规则库，附使用范围、审计与返还条款。
4. 对规则与模板的异常批量访问限流并告警；服务协议禁止逆向与提取。

## 4. 模板资产

- **要素式文书**：以 2025 年推广的 67 类新版为准（旧 11 类试行文本已废止）；G1 首批 6 份（买卖合同、民间借贷、金融借款合同的起诉状与答辩状，已定位法院官网 2025 版 PDF）；入库前逐份核对 **2025 版版本指纹**（删去送达地址与电子送达栏、新增“对纠纷解决方式的意愿”栏等），因为部分地方法院仍挂 2024 试行版；2027 年末 20 类，2028 年末覆盖 67 类；每季度巡检地方差异。劳动仲裁申请书无全国统一要素式样式：采用“当地普通格式 + 我方要素清单”，山东等有省级要素式办案规范的地区单独适配。
- **交付件模板（22 个首发）**：审查意见书、条款问题表、修订稿与清洁稿规范、谈判要点表、对方版、回稿比对报告、回稿差异表、案卷总目录、事实时间轴、证据目录、争点证据矩阵、补证清单、材料质量报告、要素式起诉状/答辩状、金额测算表、提交前核对清单、研究备忘录、类案检索报告、检索记录、引用核对表、顾问答复与内审底稿、脱敏报告与材料发送范围表；每份交付件附“出处与复核记录”。
- **合同范本**：以官方合同示范文本为底（按具体资产登记许可），按规则包改编为可审、可起草的结构化范本；律所范本进入本所范本库，权属归律所。

## 6. 评测与任务环境资产

### 6.1 评测集

见第 3 篇 §7：360 个独立业务任务 + 工程专项；2027 年末 1,000 个，2028 年末 2,000 个。材料来源：设计合作律所授权的脱敏材料（只用于该所租户与本项目评测，另签书面授权才进入通用评测集）、去标识的公开裁判文书、合成合同与案卷、官方示范文本。化名的真实案卷仍不是匿名数据，按受保护数据管理。

### 6.2 外部基准的使用

无许可证的数据集只借鉴任务设计；许可层面可用的数据集逐子任务核对后使用；海外基准（以英美法为主）只借“任务 + 评分细则 + 执行沙箱”的方法。**商业法源返回的数据既不能进训练集，也不能进评测集**（法律之星协议明确禁止用于验证与测试）：评测题以官方法律文本（著作权法第五条）自建，或用许可明确的开源集；评测集引用法源时只保存来源标识。（许可核验细节见本轮调研 R4 与 09-28 子报告。）

### 6.3 任务环境与联合后训练

- **任务环境**：任务说明 + 材料 + 模拟工具 + 律师评分细则；2027 年末 300 个，2028 年末 1,000 个，覆盖三条业务线的生产场景。首先用于评测与回归，**是否用于后训练由增益与成本实验决定**。
- **数据依据**：只用已合法公开且去标识的信息、合成数据与另签书面授权的数据；不使用任何客户材料；不违反网站协议采集。
- **与月之暗面的安排（谈判目标，非既有承诺）**：中软提供任务环境与标注，月之暗面在 K 系列上做法律后训练；环境与标注归中软，权重归月之暗面；发行版享有优先或一定期限的独占使用；推理价格优惠；效果评测双方共享。

## 7. 客户知识资产与反馈飞轮

- **本所覆盖层**：规则提炼助手 + 法律工程师从律所历史资料提炼，合伙人批准生效；到期可导出自有规则。
- **范本库**：律所上传范本 → 条款拆解与标注 → 起草时优先引用。
- **历史成果入库**：经办律师推荐 → 业务合伙人审定 → 知识管理员核查秘密与权利 → 明确跨事项访问范围后发布。当前案件材料默认只用于本事项。
- **反馈分层**：服务必需处理、租户内评测、跨租户统计、通用训练**分别授权**，不捆成一个同意项；修订卡的接受、拒绝与原因在律所层面生成覆盖层改进建议；平台层面只在合同约定下使用去标识聚合统计改进基础规则；**不自动训练**。

飞轮：律师使用 → 拒绝原因与修改沉淀 → 覆盖层与基础规则改进 → 采纳率与直接可用率上升 → 更多团队采用。事项记忆默认只在本案有效。

## 8. 权利边界

“公开可查询”“robots 允许/不允许”“不受著作权保护”任何单点都不足以决定全部商业复用权；法律文本的著作权、网站访问约束、数据库编排、个人信息与合同许可分别判断。律所上传不代表拥有客户秘密与第三方版权的再利用权。自研规则包可作平台资产，但不得冒用律协或法院的官方认证；全国律协《律师业务操作指引》等出版物未经授权不入库、不摘录进产品。模型输出不作著作权归属的绝对保证。
