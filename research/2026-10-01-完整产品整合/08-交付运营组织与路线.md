# 第 8 篇　交付运营、组织、路线与决策

版本 4.0 · 2026-10-01

## 1. 服务目录：与软件一起卖的东西

| 服务 | 内容 | 包含于 | 单独报价 |
|---|---|---|---|

| 本所规则上线 | 规则提炼助手 + 法律工程师把律所历史审查意见、范本与内部指引写成本所覆盖层，回归后合伙人批准 | 团队版含 1 套限定范围覆盖层（≤ 3 人天）；律所版含 3 套 | 4,000 元/人天 |
| 培训 | 按业务线 2 小时实操课 + “合规地用 AI”课（对应律协指引与执业责任）；每团队一名“AI 联络律师” | 全部版本线上；团队版及以上含 1 次现场 | 现场加场按次 |
| 客户成功 | 季度业务回顾：交付件数、采纳率、直接可用率、净节时、Playbook 变更、用量与成本 | 团队版及以上 | — |
| 合规材料包 | 服务协议、DPA、次级受托人清单、数据去向与权限说明、影响评估模板、当事人告知与同意模板、用户协议（含标识义务）、安全白皮书、模型名称与备案号及登记公示信息、TC260 对照表、智能体资产登记表、SBOM 与 AI 组件清单、安全评估材料包 | 全部版本 | 专项合规咨询另计 |

**上线三步**：沙盒（2–4 周，1–2 个团队、10–20 名律师、20–30 个真实事项）→ 本所规则上线（2–6 周）→ 铺开与运营。一组 FDE + 法律工程师 + 客户成功经理覆盖 3–5 家律所。开通以“首个真实交付件完成 + 管理员撤权演练通过”为验收点。

## 2. 支持、事故与生命周期

| 项 | 规则 |
|---|---|
| 支持时间 | 工作日 9–21 点在线；律所版 P1 全天候 |
| 分级 | P1（服务不可用、疑似数据泄露、错误内容进入已签发交付件）30 分钟响应、4 小时恢复或给出可执行替代；P2 4 小时响应；P3 1 个工作日 |
| 质量事故 | 立即阻止同类输出 → 按交付记录定位受影响事项与成果版本 → 通知机构责任人 → 提供更正与根因 → 补充回归用例；对已下载或转发的文件只能发更正通知与替代版本，不宣称远程撤回；不为固定“24 小时”延后法定或合同要求的通知 |
| 安全事件 | 按 DPA 约定时限通知律所；配合律所履行对当事人与监管的通知义务 |
| 可用性 | 首发目标 99.5%（受理、执行与外部供应商分开监控，并公布端到端成功率），只在完成容量与灾备演练后签约；RPO ≤ 15 分钟、RTO ≤ 4 小时为待测目标 |
| 发布通道 | LTS（季度，锁定客户端、执行内核、方法包与模型版本，回归通过才推送）与快速通道；律所可锁定通道 |
| 支持访问 | 支持人员默认看任务状态、错误码与成本，**不看案卷正文**；需要正文时由事项授权临时访问，记录范围与到期 |
| 退出 | 可导出原件、已签发成果、自有规则及许可允许的元数据，附对象数量与 hash；先处理保全，再清理派生物、索引、缓存、会话与供应商副本；备份按制度到期清除并给记录；试点也必须能退出 |

### 3.2 角色责任

| 角色 | 对什么负责 | 一票否决 |
|---|---|---|
| 项目负责人 | 范围、节奏、预算、阶段门组织 | 范围扩张 |
| 法律质量负责人 | 评测标准、金标、签发规范、质量事故复盘 | 质量阈值未达 → 不放行 |
| 架构 / 安全负责人 | 运行、隔离、数据流、红队 | 越权或外泄探针未过 → 不放行 |
| 合规负责人 | 登记、DPA、标识、律协沟通、准入结论 | 真实案卷进入前的准入 |
| 财务 | 成本与收费口径、单位经济复算 | 价格低于成本护栏 |
| 客户成功 + 试点合伙人 | 交付可用性 | 试点律所不签收 |

严重权限泄露、虚假来源进入正式交付、错误修订覆盖原件属于阻断项，不能由销售目标豁免。

### 技术负责人可直接决定（报备即可）

Electron 外壳（升到受支持主线）；文书引擎默认 Docxodus（锁版本、镜像源码），与 Open XML SDK 自研薄层及商用引擎同台评测、G1 结束前不达标即切换；OCR 与 NER 组件按许可选型（不用附加商用条款不明的组件）；代码签名用 OV；Hosted Agents 只用合成材料做 PoC；new-api 不进入法律网关核心（AGPLv3）。

### 法务负责人决定
