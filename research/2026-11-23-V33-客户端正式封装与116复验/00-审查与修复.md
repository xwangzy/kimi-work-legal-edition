## 3. 本批发现与修改（最小必要）

### 3.1 macOS：覆盖安装后钥匙串授权被拒，对话框引导用户把数据“移到一边”（已修文案）

现象（真实发生）：把新 DMG 覆盖安装到“应用程序”，用第 54 批的律所管理员档案启动。未公证的测试包每次 ad-hoc 签名都不同，
macOS 弹出钥匙串授权框；授权没有放行时，数据库主密钥解封失败（`unseal_failed`），应用弹出“无法打开本机加密数据”，
文案是“常见于重置 Windows 账户密码、重装系统后还原用户目录”——在 Mac 上既不对，也没说“数据没坏，退出重开、点‘始终允许’即可”。
随后对话框里依次点了“用恢复包恢复…”“移到一边并恢复”，数据被改名到 `.unreadable-<时刻>/`（按设计不删除）。

查明经过：
- 启动前已把档案整份备份；还原后再开，新包、**第 54 批旧包**都解不开这份数据——钥匙串里现在只有一个
  “Kimi Work 法律版 Safe Storage”条目（11-20 建、此后未改），当初封装第 54 批数据的密钥已不在本机，这份数据在本机已无法恢复，
  与新包无关（主进程代码自第 54 批以来没有改动）。
- 对照：旧包新建一份数据、再用新包打开，正常打开，没有弹框也没有“移到一边”；本批管理员档案从第一版 DMG 覆盖升级到最终 DMG
  （弹钥匙串框、点“始终允许”）后律所、身份、问答记录都在——覆盖安装的兼容性没有问题。

修改（a8b97d8）：`apps/desktop/electron/unreadable-data.cjs` 新增 `unsealFailedCauses(platform)`，对话框与 `说明.txt` 按平台写原因：
macOS 先说“刚才钥匙串授权被拒绝或关掉了那个框——数据没有坏，请先退出、重新打开，在钥匙串框里点‘始终允许’”，其次才是钥匙串条目被删、
换 Mac 用户；Windows 维持原文。`secret-store.cjs` 的内部消息同步。用例 `apps/desktop/test/unreadable-data.test.ts`（11 例全过）。

第 54 批律所的管理员电脑因此不可用，本批在 116 新开验收律所 `ten_b59-acceptance` 重做开通（见 01 文 §2）。

### 3.2 Excel 成果预览把日期显示成序列号（第 58 批引入，已修）

现象（Mac 律师函任务的《金额测算》表）：应用内预览“暂计截止日”一格显示 `46335`，分段计算表的起止日同样是 45992、46016 之类的数。
下载后的 xlsx 本身没错——这些格子带 `yyyy-mm-dd` 格式，Excel 打开显示 2026-11-09。根因：第 58 批（D-256 一带）起 `calc.ledger`
把日期写成真正的 Excel 日期格以便公式重算，但应用内预览 `renderXlsxHtml` 不读样式，只输出原始数值；材料导入用的 `xlsxToText` 早就会转日期。

修改（ba23d6e）：`packages/docx-engine/src/render-html.ts` 把日期样式判定抽成 `dateStyles` / `cellDate`，预览与文本提取共用；预览多解压一个
`xl/styles.xml`。用例 `packages/docx-engine/test/render-html.test.ts`（日期格显示 2026-11-09、不出现 46335、非日期格照原样），
与 xlsx 相关的内核用例 22 例全过。

### 3.3 windows-e2e 工作流在作业日志里留下一行邀请码明文（已修）

本批秘密扫描发现：运行 45043549304 的作业日志里有邀请码明文。原因是“屏蔽一次性输入”一步在脚本里直接展开输入表达式再 `add-mask`，
GitHub 先把展开后的脚本原文打进日志，那时屏蔽还没生效（第 54 批各次运行同样如此）。邀请码一次性、已在 16:30 注册时用掉，仓库私有，实际风险低。
修改（ba23d6e）：改为从 `GITHUB_EVENT_PATH` 事件文件读取后再屏蔽（带空格与不带空格两种写法都屏蔽），脚本原文里不再出现码。
第二次 Windows 运行（45087239550）用来复核这一修复。

### 3.4 构建流程上的一处坑：新工作树跑 pretest 会生成新的开发签名密钥

在新工作树里第一次 `npm run pretest`，没有 `content/keys/content-signing-dev.json` 时会新生成一把开发密钥，并把指纹追加到
`content/dev-content-key-fingerprints.json`（受 git 管理）。这次随导出进了桌面仓库 391eb0c（SOURCE.json 标“含未提交改动”）。
处理：从主检出复制各工作树共用的开发密钥、还原登记表，重新导出 71c1036（干净）。安装包只用 71c1036 构建；391eb0c 没有构建过安装包。
