## 0. 结论先行

1. **应用自身的落盘已基本密文化，风险重心转向“位置”“系统机制”和“出站内容本身”。** 账本 SQLCipher、案卷块按事项加密、工作区/会话/材料快照 KWE1、密钥文件 kwl-sealed/1、闸门不落盘、日志全丢弃——逐项有代码与金丝雀（§1.2，20 类数据）。剩余明文落点集中在：导出件（真名，设计如此）、进程内存（→ 页面文件、休眠文件、错误报告）、剪贴板与系统副产物。
2. **本次核实出两项新的 P0，均可本周修复：**
   - **F1 数据根和 `userData` 在漫游目录 `%APPDATA%`**（`main.cjs:164`，内核自身默认反而是 `%LOCALAPPDATA%`，`config.ts:74-77`）。在漫游配置文件或文件夹重定向的律所，密文与 DPAPI 包裹的主密钥、DPAPI 主密钥会一起同步到服务器，同一账户在任何电脑上都能解开，“每设备独立密钥”失效。
   - **F2 设备恢复包与 S1 密钥封装不兼容**（`api/index.ts:2457-2484` 直接读写封装后的 `device.json`）。安装包形态下导出的备份里没有私钥，执行导入还会把明文私钥留在磁盘上。恢复演练用例不带主密钥启动，所以没有发现（`recovery-drill.test.ts:40`）。这一条是代码推断，修复前须先用带主密钥的用例证实。
3. **对外口径的阻断项在“发起前预览”这句话里**：现文案只写了替换了什么，没写**以原文发出的是什么**（机构名、案情、金额、日期、L2 案号、漏识别的姓名），也没写上游保留以协议为准（`api/index.ts:1003-1024`）。P0 先改文案；P1 换成三行的“将发送什么”卡，默认值按级别分三档：L2 每事项确认一次，L3a 每次确认且疑似姓名须核对，L3b 禁止。做法对标 M365 Copilot 展示实际发给 Bing 的查询原文、Harvey 按去向标注保留与人工审阅属性（§3）。
4. **Windows 机制 15 项（§2）**：产品能自动做的约 8 项——迁出漫游目录、`attrib +I` 非内容索引、文件对话框 `dontAddToRecent`、子进程独立文件名并排除出 WER、剪贴板“不进历史、不上云”格式、防截屏、BitLocker/漫游/OneDrive/LocalDumps 检测。页面文件、休眠文件、卷影副本、输入法云联想、杀软样本上传只能提示 IT 或写入残余声明。另外，删除回执的“本机已删”不覆盖还原点和备份，须改口径（F9）。
5. **“唯一出口”升级为系统强制分三级（§6）**：S-0 把闸门与宿主拆成独立可执行文件（本周）；S-1 由律所 IT 配防火墙出站规则，律所版要求全机安装，因为防火墙不展开按用户安装的 `%LOCALAPPDATA%` 路径；S-2（G2）把宿主放进不授予网络能力的 AppContainer，不需要 IT。命名管道不受防火墙出站规则影响，这一点须实机核验。规则样例在 §6.4，只作部署文档。
6. **S8 评测可以不依赖真实案卷起步（§4）**：主体用公开裁判文书再标注——普通民商事当事人保留真名，文书不受著作权保护，可以公开。公开文书已删除的标识符靠合作律所“带评测器进所、不带数据出所”。按来源与类别报告召回、**人级泄露率**和簇自助 95% 区间。运行时加二次检测：L2 不打断，只在去向卡如实提示；L3a 发送前阻断。
7. **日志与诊断（§5）**：日志只允许“事件码 + 字段白名单”，禁止自由文本，由 CI 静态规则把关。诊断包导出前用本机全部当事人词典与令牌表自证不含内容，并用设备签名保证完整性。这同时修复了界面承诺却不存在的“导出诊断信息”（F5）。
8. **密钥残余（§7）**：G1 把设备签名密钥放进 TPM（Chromium 已有 P-256 先例）；加密私钥与主密钥加 TPM 包裹层；每次删除事项后轮换本机包裹密钥，使旧快照解不开；根私钥 2-of-3 线下分持。当前版本应如实声明的五条残余见 §7.3，含“同一 Windows 账户下的程序与域管理员可解封”。
9. **工作量（§8）**：P0 约 6 人日（另有 2 处文案需法务审定）；P1 研发约 12 人周，另加标注约 3 人周；P2 约 12–17 人周。依赖外部条件的主要是 Windows 实机与 CI 授权（自检标定、防火墙与管道验证）、律所授权语料（S8-B）、法务文案，以及 TPM 测试机与代码签名证书。

## 2. Windows 特有风险与对策

**结论**：本产品自己的落盘已基本是密文（§1），Windows 机制的风险集中在三处：①**内存镜像**（页面文件、休眠文件、错误报告转储）——只能靠 BitLocker 与减少明文驻留；②**位置被系统搬走**（漫游配置文件、文件夹重定向、FSLogix、OneDrive、卷影副本与备份）——F1 修复后主要剩“导出件”和“快照”；③**律师主动动作的系统副产物**（剪贴板历史与云剪贴板、最近使用、输入法云联想、Recall/截屏）——产品能做的是在自己的窗口与对话框里关掉，其余写进告知与 IT 指南。

### 4.4 标注规范、一致性与报告

| 项 | 规定 |

| 边界 | 姓名不含称谓（“张三律师”只标“张三”）；机构内含人名（“张三律师事务所”）整体标 org；地址按“到门牌”为一段；昵称（“老王”）单独成段并关联到同一人 |

| 切分 | 开发集（可看错例、可调规则）与**锁定测试集**（只在 CI 中跑、只出汇总、版本化并记录 hash）分开；规则作者不得接触锁定集原文 |
| 指标 | ①提及级召回（主指标）与精确率；②**人级泄露率**（同一人任一次提及漏掉即算泄露——比提及召回更贴近风险）；③误替换率（每千字）；④按来源（A/B/C/D）与事项类型分别报告，**不合并成一个数** |
| 置信区间 | 提及在文档内相关，用**按文档的簇自助法**（1,000 次）给 95% 区间；小类别同时给 Wilson 区间 |
| 门禁 | 锁定集上自然人姓名召回 95% 区间下界 ≥ 0.95、标识符 ≥ 0.99（**阈值待产品与法务拍板**），回归即阻断发布 |
| 对外口径 | 只引用锁定集数字并附区间、来源与版本：“在 N 段公开裁判文书与 M 段合作律所内部样本上，自然人姓名召回 x%（95% 区间 a–b%）；仍可能漏识别” |

## 6. 把“唯一出口”从应用层升级为系统强制

### 6.1 现状与前提

| 事实 | 证据 |

| **S-0（本周可做）** | 构建时把 `node.exe` 复制为 `kwl-egress.exe`（只给闸门）与 `kwl-host.exe`（kap-host、解析）；复制不改字节，OpenJS 的 Authenticode 签名仍有效，运行时清单的 sha256 不变（`runtime-paths.cjs` 增两项、`build-runtime.mjs` 复制、`gate-host.ts` 用 `KWL_GATE_NODE`）；设备页显示“唯一出口：运行时强制 / 系统强制（已配置 n/3 条规则）” | 研发 | 为 S-1 做准备；同时满足 WER 排除（W8）与任务管理器可辨识 | 安装包增大约一个 node.exe（约 80 MB，差分更新可缓解） |

### 6.4 IT 部署样例（PowerShell，仅作部署文档，未执行）

```powershell
# 以管理员运行，或转写为组策略“高级安全 Windows Defender 防火墙 → 出站规则”/ Intune 防火墙配置。

  -Program (Join-Path $rt "kwl-host.exe") -Action Block -Profile Any

  -Program (Join-Path $rt "kwl-egress.exe") -Protocol TCP -RemotePort 80,443 -Action Allow -Profile Any

  -Program (Join-Path $rt "kwl-egress.exe") -Protocol TCP -RemotePort "1-79","81-442","444-65535" -Action Block -Profile Any
New-NetFirewallRule -Group $grp -DisplayName "KWL 闸门 UDP 禁止" -Direction Outbound `
  -Program (Join-Path $rt "kwl-egress.exe") -Protocol UDP -Action Block -Profile Any

# 3) 主程序（界面与内核）：更新由 IT 分发时禁止出网；启用应用内自动更新则不要加这一条
New-NetFirewallRule -Group $grp -DisplayName "KWL 主程序禁止出网" -Direction Outbound `
  -Program (Join-Path $app "KimiWorkLegal.exe") -Action Block -Profile Any

# 4) 兼容旧版本：随包 node.exe（若仍存在）一律禁止
New-NetFirewallRule -Group $grp -DisplayName "KWL 旧版运行时禁止出网" -Direction Outbound `
  -Program (Join-Path $rt "node.exe") -Action Block -Profile Any

# 核对与回退
Get-NetFirewallRule -Group $grp | Get-NetFirewallApplicationFilter
# Disable-NetFirewallRule -Group $grp   # 回退：整组停用
```

### 7.3 当前版本对外应如实声明的残余（建议原文）

> **本机密钥保护（当前版本）**
> 1. 案件数据在本机加密保存。解密所需的密钥受 Windows 数据保护（DPAPI）保护，与您的 Windows 账户绑定。**以您的 Windows 账户运行的其他程序（包括恶意软件）在技术上可以调用同一保护机制**；在使用域账户的律所，域管理员按 Windows 的设计也具备恢复能力。
> 2. 设备签名与解密密钥目前由软件保存，尚未存放在电脑的安全芯片（TPM）中。
> 3. 当前版本中，律所恢复所需的根密钥保存在各成员的电脑上；律所版将改为线下分片保管。在此之前，任何一台成员电脑被完全控制，都可能影响律所的恢复与管理员签名机制。
> 4. 删除事项会销毁本机密钥并删除数据；Windows 还原点、文件历史和备份软件中的旧副本不在删除范围内。
> 5. 我们建议开启 BitLocker，并为本应用使用本机（非漫游、非重定向）的用户目录。

（F1 修复前还须加一句：“如您的 Windows 账户使用漫游配置文件，加密数据与密钥可能同步到律所服务器”。）
