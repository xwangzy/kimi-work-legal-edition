## 1. 一页结论

**一句话**：云端按 v9.1 建 **14 个服务、4 个平面**（控制、能力、分发与常在线、中继），全部不持久化客户案卷；**现有 v0 协议（席位令牌 `zst1`、控制面信封、设备签名请求、网关请求头、检索协议）全部保留**，生产化主要是“内存 → 持久化 + 多副本 + 密钥进 KMS + 增量订阅”。首发最小集可在 2027-01 下旬上线试点生产，云端约 **165 人周**，在 v9 预算内；最长合规链是**生成式 AI 登记**（M2 递交 → M5 完成，付费前门禁）。

| 问题 | 结论 |
|---|---|
| 要建什么 | S1 控制面（+ 独立签名服务）、S2 身份与登录、S3 计费与额度、S4 能力网关、S5 检索/抓取、S6 法源（法规签名增量包 + 案例/工商 MCP）、S7 方法包分发、S8 桌面更新、S9 通知/提醒（密文载荷）、S10 IM 后端、S11 中继（密文）、S12 律所管理员控制台 + 运营控制台、S13 支持与诊断（无内容遥测 + 主动上传的脱敏诊断包）、S14 审计与安全运营（第 3 章） |
| 不建什么 | 云端事项库/执行面（G3）；经 new-api 转发模型流量；保存查询/提示词/问答历史；托管律所根或设备私钥；自研更新协议；多云并行；`$web_search`、Batch、files 上传接口（第 3.15 节） |
| **G1 首发最小集** | S1 + 签名服务、S2（扫码/手机号 + 管理员双因素）、S3（额度池 + 消费上限）、S4、S5 检索、S6 法规增量包、S7、S8、S9 桌面提醒、S11 共享中继、S12 律所控制台最小版、S13、S14 审计流水；IM 提醒用端侧方案 |
| G2 补齐 | 账单/加量/发票/MaaS 对账、OIDC/SAML/SCIM、案例与工商 MCP、抓取代理（可选）、移动推送、云端 IM 后端（离线加密暂存）、设备中继、运营控制台全功能、SIEM 全量 |
| 云与部署 | **首选华为云**（中软为华为云核心伙伴；DEW 国密 KMS + 专属加密；CCE/RDS PostgreSQL/OBS），备选天翼云；北京主、上海灾备；dev/staging/prod-pilot/prod 四环境，预发用独立月之暗面组织与独立签名 `kid`；控制面 RPO ≤15 分钟、RTO ≤4 小时（第 4 章） |
| 合规关键路径 | M0（11-20）运营主体与 B25/B21 判断、ICP 备案、属地网信预沟通 → M1（12-18）等保定级（拟 2 个三级系统）→ M2（2027-01-22）等保备案 + **登记递交** + DPA/次处理者清单 → M4（04-16）整改完成 → M5（05-21）**等保测评 + 登记完成** → M6（06-11）GA 就绪。首年等保/密评相关预算约 60–120 万元 |

**题 2 小结**：合规关键路径 = **运营主体确定 → ICP 备案（域名）→ 与月之暗面签调用协议并取得备案号授权 → 网关内容安全能力可演示 → 属地登记递交（G1）→ 登记完成（G2 付费前门禁）**；B25/B21 许可与等保定级并行。登记材料无官方统一清单，第一件事是与属地网信办预沟通。

### 2.3 题 3 · 等保 2.0 三级：关键技术要求、周期与成本

**条款要点**（GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》第 8 章“第三级安全要求”及 8.2 云计算扩展要求；条款号按标准结构，正文为要点概括。本次检索未取得标准全文网页，依据为标准既有知识，**递交前须以标准原文与测评机构的测评指导书核对**）：

| 控制域（标准章节） | 三级关键要求（概括） | 对本云端的落点 |
|---|---|---|
| 身份鉴别（安全计算环境） | 唯一标识、口令复杂度与定期更换；登录失败处理与会话超时；远程管理防窃听；**两种或以上鉴别技术组合，其中至少一种使用密码技术** | 运维与运营控制台：SSO + 硬件令牌/国密 USBKey/TOTP；律所管理员控制台：扫码/口令 + 设备证书签名（设备签名本身即密码技术）；堡垒机统一运维入口 |
| 访问控制 | 账户最小权限、默认账户改名/删除、多余与过期账户清理；授权主体配置策略；主体到用户/进程级、客体到文件/库表级；重要主体与资源设安全标记 | RBAC + 租户行级隔离（PostgreSQL RLS）；运维三权分立（系统/审计/安全管理员）；客户数据访问需工单 + 客户可见的临时授权 |
| 安全审计 | 覆盖每个用户、审计重要用户行为与安全事件；记录时间、用户、事件类型、结果；**审计记录防删改并定期备份**；审计进程防中断 | 运营审计流水（只元数据）追加写 + 哈希链 + WORM 对象存储；日志 ≥6 个月（同时满足《网络安全法》第二十一条网络日志留存不少于六个月） |
| 入侵防范 | 最小安装、关闭无用服务端口；限制管理终端地址；输入数据有效性检验；发现与修补已知漏洞；检测入侵并在严重事件时报警 | 镜像基线（CIS/国产 OS 基线）、漏洞扫描与补丁 SLA、云 WAF/HIDS/NIDS；**注意：WAF 不可解密网关与控制面 TLS（客户端钉住 SPKI，见附录 A.5）**，网关与控制面前置 L4 防护 + 应用内防护 |

| 数据保密性 | 密码技术保证上述数据在传输与存储中的保密性 | TLS 1.2+（可选国密 TLCP）；存储透明加密 + KMS 信封加密（敏感字段：手机号、邮箱、律所联系人） |
| 数据备份恢复 | 本地备份与恢复；**异地实时备份**；重要数据处理系统**热冗余** | PostgreSQL 主备同城多可用区 + 异地只读副本/日志归档；见第 4 章 RPO/RTO |
| 剩余信息保护、个人信息保护 | 鉴别信息与敏感数据存储空间释放前完全清除；**仅采集和保存业务必需的个人信息**，禁止未授权访问与使用 | 数据字段—目的—期限矩阵；租户注销后按期删除 + 备份过期 |
| 安全区域边界/通信网络 | 网络分区、边界访问控制、通信传输加密、边界入侵防范与审计 | VPC 分区（接入区/应用区/数据区/管理区）、安全组白名单、出口 NAT 白名单（见第 4 章） |
| 安全管理中心 | 系统/审计/安全管理员分离；划分管理区域；**集中监测、审计数据汇总分析**、集中管理策略与补丁；识别报警安全事件 | SIEM/日志平台 + 堡垒机 + 配置基线中心 |
| 云计算扩展（8.2，云服务客户侧） | 云平台安全等级 **≥ 承载系统等级**（须选已过三级的云平台/区域）；云服务客户数据、个人信息**存储于中国境内**；云服务商管理员访问须经客户授权；客户**自行部署密钥管理**、自行加解密的能力；镜像与快照完整性；**云服务客户应在本地保存业务数据备份**（可解释为跨云/线下备份） | 选云时核验云平台三级（或四级）测评结论；KMS 使用客户主密钥（CMK/BYOK）；控制面数据库每日导出一份到中软自有存储（跨云备份） |

### 2.4 题 4 · 个保法委托处理、影响评估、数据出境、律协对服务商的要求

**角色认定**（与 v9 第 05 篇 §1 一致，本次补法条与合同落点）

| 链条 | 角色 | 法条 | 要点 |
|---|---|---|---|
| 律所 ← 委托人/对方当事人/证人信息 | 律所 = **个人信息处理者**（决定目的与方式） | 个保法第七十三条（定义）、第十三条（处理依据） | 律所对四项依据负责；产品只记录与拦截，不替律所判断 |
| 律所 → 中软（网关、检索、法源、中继、通知、IM 后端、控制面） | 中软 = **受托人**（律所开通账号时）；专业版自注册个人律师场景下中软对其账号数据为独立处理者 | **第二十一条**：委托须约定目的、期限、方式、种类、保护措施与双方权利义务，处理者对受托人**监督**；受托人不得超约定处理，**未经同意不得转委托**；合同不生效/终止后受托人返还或删除。**第五十九条**：受托人应采取必要措施保障安全、协助处理者履行义务 | 中软对“密文仍可能是个人信息”不以“无钥”否认受托人身份（v9 已写） |
| 中软 → 月之暗面、检索备选、法源数据商、云服务商、推送通道 | **转委托（次处理者）** | 第二十一条第三款：转委托须取得律所同意 | DPA 附**版本化次处理者清单** + 变更提前通知与异议权；月之暗面合同须镜像约束（不训练、ZDR、境内、删除、事件通知） |
| 网信条例补充 | 委托处理时以合同约定目的、方式、范围与安全保护责任并**监督履约**；**处理记录保存至少三年**；受托方在约定范围内处理 | 《网络数据安全管理条例》第十二条（国务院令第 790 号，2025-01-01 施行）https://www.gov.cn/zhengce/zhengceku/202409/content_6977767.htm | 控制面须能按租户导出“受托处理记录”（处理活动、次处理者、期限），保存 ≥3 年（只元数据） |

**关键发现：现有签名算法与国内云 KMS 不兼容**

- 控制面信封、席位令牌、设备请求、律所根与设备证书**全部是 Ed25519**（附录 A.1）。本次检索的阿里云 KMS 签名规格不含 Ed25519；华为云 KMS 非对称为 RSA/ECC/SM2（未见 Ed25519）。即：**控制面两把签名私钥（envelope、seat）无法“生在 KMS 里、永不出 KMS”**。
- 可选路径（建议 G1 前裁定，记为未决 Y2-U1）：
  - **A（推荐，G1）**：私钥由 KMS 信封加密（SM4/AES 主密钥）保存，仅在**独立签名服务**进程内存中解封；签名服务单一职责、无外网、只接受内部 mTLS 调用、每次签名写审计；轮换按 `kid`。协议**零改动**。
  - **B（G2 起，算法敏捷）**：给 `zst1`/信封引入算法标识（如 `zst2` 前缀或 `kid → alg` 表），新增 **ECDSA P-256 或 SM2（KMS/HSM 内签名）**；客户端与网关同时接受旧 Ed25519 `kid` 与新 `kid`，过渡一个许可周期（30 天）后下线旧 `kid`。SM2 需确认 Node/OpenSSL 运行时与 SM3 摘要的实现，客户端随包运行时须一起评估。
  - 律所根与设备密钥在律所侧，与云 KMS 无关；若律所要求国密，属客户端 W9 范围。
- 密评（GB/T 39786）通常要求“使用经检测认证的密码产品/服务”，路径 A 的软件签名可能被测评判为不符合 → **若密评适用，最终须走 B（KMS/HSM 内签名）**。

### 2.6 题 6 · Electron 桌面应用自动更新的生产做法

来源：electron-builder 仓库官方文档 `website/docs/features/auto-update.md`（master 分支，访问 2026-10-14）https://github.com/electron-userland/electron-builder/blob/master/website/docs/features/auto-update.md ；changeset `publisher-name-verification-guard.md`、`disable-implicit-publish.md`。**注意**：master 文档已在描述 electron-builder **v27（当前 `27.0.0-alpha.10`）/ electron-updater 7（`7.0.0-alpha.9`）**的特性；生产应锁定稳定版并逐项核对该特性是否已在所锁版本中。

| 主题 | 官方事实 | 本项目做法 |
|---|---|---|
| generic provider | `publish: {provider: "generic", url, channel}`；generic 服务器**需自行上传**安装包与 `latest.yml`（electron-builder 只对其他 provider 自动上传）；`requestHeaders`/`addAuthHeader` 的凭据头与 feed URL 查询串**只发往 feed 同源**（跨源重定向时移除） | 自建“更新与分发服务”（对象存储 + 签名清单 API）作为 generic 源；凭据（如律所渠道令牌）用请求头，不放 URL |
| 隐式发布 | v27 起**取消隐式发布**（不再按 CI/tag 自动发布），须 `--publish` 或配置 `publish` | 发布只由发布流水线显式执行（工作区并行改动已把 `publish` 设为 generic 占位地址，见附录 A.5） |
| 签名校验（Windows） | NSIS 更新内置 **Authenticode 校验**（`publisherName` 与签名证书主体匹配）；**若 `app-update.yml` 无 `publisherName`，现行版本会静默跳过校验**（新版改为告警，v28 计划改为失败关闭）；构建时若配置的 `publisherName` 与签名证书不符将报错；另有通用钩子 `verifyUpdateFile`（下载后临时文件名、缓存复用、下次启动安装前**三处都执行**），Authenticode 先、钩子后 | ①**显式配置 `win.publisherName`**（中软 EV 证书主体）；②在 `verifyUpdateFile` 钩子里再校验**中软发布签名清单**（Ed25519/SM2 对“版本+sha512+大小”的签名，公钥随包固定）——双重签名：Authenticode 防篡改、清单签名防“合法证书被滥用/错发”；③`latest.yml` 自带 `sha512` 校验 |
| 差分更新 | NSIS 生成 `.blockmap`，electron-updater 按块差分下载（`differentialPackage`、`disableDifferentialDownload` 可控） | 默认开启差分；内网分发也保留 blockmap |
| 分阶段灰度 | 手工编辑 `latest.yml` 的 **`stagingPercentage`**（例 10 = 10% 用户）；**撤回只能发更高版本号**（不能重发同号） | 灰度 1% → 10% → 50% → 100%，每档 ≥48 小时并看崩溃率；律所版可选“延迟通道”（v9 第 04 篇 §10） |
| 回滚与降级 | 官方无“自动回滚”；可 `allowDowngrade`（v7 文档描述下次启动安装前仍校验“比当前新，或允许降级”）；**撤回=发布更高版本** | 产品策略：**禁止降级**（反回滚，v9 已定），坏版本用 x.y.z+1 修复；法规库/方法包的反回滚由内容签名版本单调保证 |
| 安装时机 | v7（electron-updater ≥7.0）：会话结束时跳过退出安装；可选 `autoInstallEvent = "onNextLaunch"`（下次启动先重新取更新信息、校验缓存安装包的校验和与签名再静默安装）或 `"manual"` | 律师场景：任务进行中不装；默认 `manual` + 界面提示“空闲时安装”，管理员可设强制窗口 |
| 每机安装 | v27 对 `perMachine: true` 的 NSIS 自动带 `isAdminRightsRequired` 并经 `elevate.exe` | 现配置 `perMachine: false`（按用户安装），无提权问题；企业 IT 批量安装走 MSI/静默 NSIS（另出包） |

**企业内网分发与国内 CDN**

| 场景 | 做法 |
|---|---|
| 国内 CDN | 更新域名单独设立（如 `dl.<域名>`），**须完成 ICP 备案**才能在国内 CDN 加速；安装包与 blockmap 走 CDN，`latest.yml` 与签名清单**不缓存或短缓存**（≤60 秒），否则灰度与撤回失效 |
| 闸门与钉住 | v9 第 04 篇 §5.1 规定“更新｜主进程｜目的地固定”：更新地址与 TLS 钉住写入随包 `release.json`（工作区并行改动已用更新器专用会话实现钉住）；**CDN 证书轮换会改变叶子公钥 → 钉 CA/中间证书、或用自管密钥签发 CDN 证书**；若两者都做不到，则更新通道不钉 TLS，安全性由 Authenticode + 清单签名保证 |
| 律所内网镜像 | 律所 IT 可在内网放 generic 镜像（同步中软 CDN 的安装包 + 签名清单）；客户端允许由**律所根签名的策略**指定镜像地址（只能“多一个来源”，签名校验不变；被攻破的镜像只能拒绝服务，不能投毒）——这是 D-46 之后新增的放宽类策略项，须管理员签名门限 |
| 断网律所 | 离线安装包 + 签名清单人工导入 |

**与工作区并行改动的对照**（`apps/desktop/electron/updater.cjs`，未提交）：清单签名、钉住、灰度、禁止降级与本节建议一致；差异两点——①它关闭了 Authenticode 校验（`verifyUpdateCodeSignature: false`），建议改为在 `verifyUpdateFile` 或自定义 `verifyUpdateCodeSignature` 中用**随 asar 的 `release.json` 给出的发布者名**做 Authenticode 校验，作为清单签名之外的第二层（防“清单签名密钥泄露”单点）；②更新源 TLS 钉住与国内 CDN 证书轮换冲突——更新域名若走 CDN，须钉 CDN 证书的 CA/中间证书或使用自管密钥的证书，否则 CDN 换证即全量更新失败。

**题 6 小结**：更新链的安全底线 = **EV 代码签名 + 显式 `publisherName` + 中软清单签名（`verifyUpdateFile` 钩子）+ 禁止降级 + 灰度用 `stagingPercentage`、撤回发高版本**；云端只需“对象存储 + CDN + 清单签名服务 + 发布审批”，无需自研更新协议。

| **律所管理员控制台**（Web，`admin.<域名>`） | 律所管理员、合伙人 | 成员与席位分配、设备清单与吊销（收紧）、用量与上限、策略**起草与预览**、导出（成员/设备/计量/受托处理记录）、合规材料下载 | **签名与发布放宽类策略**（只能在管理员设备上完成，D-32）；看事项名（事项名经事项目录密钥在客户端解密，Web 不可见） | S2 OIDC 会话 + 双因素；吊销类操作可在 Web 直接做（收紧），由服务端以“收紧通道”生效 |

### 4.2 区域与网络分区（以华为云为例；天翼云同构）

```text
                         律所电脑（出站 TLS，SPKI 钉住）
                                   │
             ┌─────────────── 接入区（公网）────────────────┐
             │ Anti-DDoS · ELB(L4，TLS 证书公钥固定)          │  dl.<域名> → CDN → OBS（只有更新/分发域名走 CDN）
             └───────┬──────────────┬──────────────┬────────┘
   ┌──────────── 应用区（CCE，跨 3 可用区）─────────────────────────────┐
   │ api.<域名>      gw.<域名>          search.<域名>    relay/notify   │
   │ cp-api ×3       legal-gateway ×3   search ×2        relay ×2 notify×2│
   │ admin-console   (与控制面独立 Deployment/节点池)                  │
   └──────┬──────────────┬──────────────────────────────────────────────┘
   ┌── 签名区（独立节点池，无公网路由）──┐   ┌──── 数据区（无公网）────────────────┐
   │ cp-signer（mTLS，只收 cp-api）      │   │ RDS PostgreSQL 主备（多 AZ）         │
   │ 内容签名：离线签名机/HSM（发布用）  │   │ Redis（nonce、限流、租约）           │
   └────────────────────────────────────┘   │ Kafka/消息（计量、审计、outbox）      │
                                            │ OBS（中继密文、计量冷存、WORM 审计）  │
                                            └──────────────────────────────────────┘
   ┌── 出口区：NAT 网关 + 固定 EIP（≤ 数个，登记到月之暗面组织 IP 白名单）──┐
```

| 项 | 决定 |
|---|---|
| 主区域 | 华北（北京）——中软总部与属地登记机关同城；**灾备区域**：华东（上海） |
| 域名拆分 | `api`（控制面）、`gw`（网关）、`search`、`relay`、`notify` 分域名：便于独立限流、独立证书钉住、故障隔离；控制台 `admin` 与 API 分开 |
| 证书与钉住 | 客户端钉 SPKI：**证书续期复用同一密钥对**（CSR 用固定私钥，私钥存 KMS/CSMS），并在 `release.json` 预置**一组备用钉住**（备用密钥对离线保管）；更新/分发域名不钉（安全由签名保证，2.6） |
| 网关前置 | 只用 L4 负载均衡 + 应用内防护；**不使用解密型 WAF/CDN**（会改变 TLS 终止公钥、且能看到正文）；控制台 Web 可用 WAF |
| 出口白名单 | 应用区 Pod 默认禁止出网；只有网关、检索、法源、通知、IM 后端的出口经 NAT，按域名/IP 白名单（云防火墙）；控制面与签名服务**无出网** |
| 运维访问 | 堡垒机 + 双因素 + 会话录像；**只限境内人员**；生产数据库无直连，查询走审批工单与脱敏视图 |

## 6. 可观测性与运维

### 6.1 “只计量不留内容”的日志规范

| 类别 | 允许字段（白名单） | 禁止 |
|---|---|---|
| 网关计量 | `MeterRecord` 现有 15 个字段（`at,kind,requestId,clientRequestId,tid,sid,anonMatter,model,status,reserved,inputTokens,outputTokens,cachedTokens,latencyMs,reason`） | 请求体、响应体、错误体、`messages` 任意片段、工具参数、上游错误 message 原文 |
| 访问日志 | `AccessRecord`（`at,method,path(≤200),status,clientRequestId`）+ 来源 IP 网段（/24） | 查询串、请求头中的 `authorization` 与 `x-kwl-sig` |
| 检索计量 | `SearchMeterRecord`（`tid,sid,upstreamCalls,results,latencyMs,status`） | 查询原文、结果 URL 列表 |
| 控制面审计 | 操作者（账号 ID/设备指纹）、租户、动作、对象 ID、结果、请求 ID | 策略正文以外的任何客户内容（策略本身是律所配置，可留） |
| 应用错误日志 | 错误码、栈（剥离参数值）、请求 ID | 异常消息中的用户输入（日志库统一做字段过滤） |
| APM/链路 | span 名、耗时、状态 | 请求/响应体采样（APM 全局关闭 body capture） |

机制：①日志结构化，**按白名单重建对象再写**（沿用 `fileMeter` 的做法）；②CI 中加“日志字段扫描”测试；③红队用例对日志落盘做断言（阶段 7 已有“访问日志为判定依据”的模式）；④保留期：计量与访问日志 ≥6 个月、审计 1 年、受托处理记录 3 年。

### A.5 客户端出站闸门对云端的硬约束（`egress-gate`）

- 目的地与钉住集只认随包 `release.json`（D-46）；安装包形态 `ZR_UPSTREAM_TLS=strict`：非回环一律 https、TLS ≥1.2、**中软网关/检索/控制面必须带 SPKI 钉住集**，不跟随重定向（`tls-policy.ts`）。
- 含义：①云端证书轮换必须**保持钉住公钥（或预置备用钉住）**，否则全量客户端断连；②不能用会改写 TLS 终止证书公钥的 CDN/WAF 前置于网关与控制面，除非把其公钥列入钉住集；③网关/检索/控制面地址由构建固定，被攻破的控制面无法改投流量（D-17）。
- 抓取：G0 本机直连（`fetch: "local"`），云端抓取代理为可选。
- 桌面打包：已提交版本（HEAD）的 `electron-builder.yml` 为 `publish: null`；**本次调研期间工作区出现并行的未提交改动**（W7 自动更新）：`publish` 改为 generic（占位地址 `updates.example.invalid`）、新增 `electron/updater.cjs` 与 `update-verify.cjs`——更新器专用会话只许更新源主机且证书链须命中钉住集、安装前按随包公钥核验 `kwl-update.json` 发布签名并核对版本/大小/sha512、支持 `stagingPercentage`、不接受降级，且设置 `verifyUpdateCodeSignature: false`（理由：`app-update.yml` 在 asar 外可被改写）。NSIS 按用户安装、`electronFuses` 已开 asar 完整性校验；正式代码签名证书未到位。
