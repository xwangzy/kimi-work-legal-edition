## 过程记录（逐节追加，最终结论见文末“汇总”）

### A. 客观测量
- 逐帧亮度差（signalstats YDIF，480 宽）全片 7,344 帧扫描：场内单帧突变（> 4 倍邻域中位数）出现在 33.600、33.867、42.0、43.0、43.833、44.733、46.833、62.1、64.267、70.0、76.4、77.8 秒等处；硬切 33.6 / 49.2 / 55.2 / 60.0 / 68.4 / 74.4 / 79.2 / 88.8 / 96.0。
- 运动能量曲线：28～100 秒几乎没有一秒是静止的（每秒 10 档采样里 ≥ 8 档有明显位移），只在 44、80～81、109～110、113～118 秒有“停住”的拍。界面段“持续漂+持续推”，视觉上偏累。
- 镜头实现（`ui/film.tsx` ProductStage + `lib/anim.ts` keyed）：每两个关键帧之间各自做 easeCine 缓入缓出，所以**镜头在每个中间关键帧都会减速到 0 再起步**（S03 的 f70/f160/f220、S05 的 C_KIND/C_REC/T_NOTICE/C_GO……）。曲线上 21.5 秒、23.0 秒两处速度掉到近 0 又起，就是这个“走走停停”。缩放 s 与焦点 fx/fy 分通道线性插值，屏幕位移 = -(fx-w/2)·s，推拉时焦点会“游”（不是沿直线进出）。
- 光标在 ProductStage 内部（窗口坐标），所以光标大小随镜头缩放变化（s=0.72 时缩小、s=2.1 时放大一倍），与真实系统光标不符；路径为两点直线 + easeInOut，每个关键点停住。

### B. 已确认的硬伤（逐帧核实）
1. **33.600 秒闪帧**：开始面板 → 开始前确认的切点，第 2016 帧是一整帧“首页”（无弹窗），第 2017 帧弹窗才半透明出现、还叠着首页大字标“Kimi Work”的残影。原因：`S05Consent.tsx` 里 `if (f < 6) css(q(root, ".modal"), { opacity: prog(f, 0, 6) })`，第 0 帧弹窗透明度为 0。修改：第 0 帧弹窗不透明（或从 S04 末帧的“下一步：确认”弹窗做 6～8 帧交叉溶解），首页底图不应在切点露出。
2. **33.867 秒背景层突变**：确认弹窗不动，背后的侧栏与底色在 1 帧内消失/变浅（第 2032 帧 YDIF 14.4，前后各 3 左右）。观感是“背景跳了一下”。修改：底图变化改 10～12 帧溶解或干脆在切点前完成。
3. **场内快照硬换（系统性）**：`ProductWindow` 只渲染一个快照，`pick(f, …)` 到帧即换，**全片没有任何快照间过渡机制**（源码无 crossfade/FLIP）。实测硬换：43.0、43.833（执行页时间线展开、提问卡出现）、62.1、64.267（意见卡列表整列替换）、70.0（工作台 → 成果页，连机位一起跳）、76.4（签发页上半 → 勾选清单，机位跳）、77.8（清单 → 已签发文档，机位跳）。产品自身规范是“浮层 140ms ease-out 出现”，片子反而比产品更硬。
4. **96.0 秒明暗硬翻**：深色“保密”场最后一帧 → 白色“价值”场，YDIF 109（全片最大），新场头 0.3 秒是一大块灰黑模糊色块在白底上逐渐变成纸，读起来像渲染残影而不是设计。
5. **88.8 秒白 → 灰 → 黑溶解**：画廊淡到白，再整体变灰，深色设置页从灰里浮出，中间 6～8 帧画面几乎是空的浊灰。
6. **51.5～52.0 秒快速横摇无运动模糊**：从条款高亮横摇到意见卡，单帧位移约画面 1/12，文字清晰地一格格跳（60 fps 下也会频闪），4K 大屏更明显。

## 3. 界面交互动效逐处检查

- **光标**：放在 ProductStage 内，随镜头缩放（首页 s 0.72～1.36，同一光标大小变化近一倍）、随 3D 偏转变形；真实系统光标在屏幕空间恒定。改：光标移到 ProductStage 外，用镜头变换把窗口坐标投影到屏幕坐标，固定 28px。走位是两点直线 + easeInOut、每个关键点都停住，改为带 8～12% 弧度的贝塞尔路径、末段减速（easeOut）且在目标前 4～6 帧到位、按下前停 3 帧。
- **点击反馈**：光标按下缩放 0.86 + 蓝色涟漪，干净；但被点的按钮本身没有按下态，只是随后整张快照换掉。改：点击帧给按钮叠一层 6 帧 `brightness(0.9)` + 1px 内阴影，再交叉到新快照。
- **打字**：首页 11 字/秒、授权出处 14 字/秒，节奏自然，是全片最可信的交互。建议加闪烁插入符（产品输入框有），打完后停 10 帧再出识别横幅。
- **状态切换**：见第 2 节，全部硬换，是本项失分主因。最低限度：做一个 `<SnapSwap a b at dur=9>` 组件，同时渲染新旧快照、opacity 交叉；新增元素（提问卡、识别横幅、已接受徽标）单独做 12px 位移淡入。
- **聚光框（Spot）**：蓝描边 + 外晕，出现/消失 18/16 帧，干净；“开始用 AI 之前”三条依次点亮节奏好。问题：坐标是写死的像素矩形（如 `{x:494,y:322}`），快照一旦重采就会错位。

## 5. 工程实现简评

- 好：`timeline.ts`/`beats.ts` 单一时间源、画面与配乐共用，切点全部落小节；快照 + 作用域化 CSSOM + `real.ts` 记录真实代号，素材可追溯、可重复渲染；`rand(seed)` 确定性。
- 风险 1：`keyed()` 分段缓入缓出导致所有多关键帧镜头走走停停；应提供全局样条插值（位置 Catmull-Rom、缩放对数域），并保留现有接口。
- 风险 2：缺少快照过渡原语，场景各自用 `pick()` 硬换、用 `if (f < 6)` 之类临时淡入（直接造成 33.6 秒闪帧）；应在 `ui/` 提供 `SnapSwap`，场间过渡集中到 `Film.tsx`（TransitionSeries 或统一的入出场约定）。
- 风险 3：聚光框、光标目标是写死的快照像素坐标，重采快照即错位且无报错；建议导入时用选择器量出 rect 写进快照元数据，并在 SnapCheck 里加“目标点是否落在元素内”的断言。
- 风险 4：快照内用产品字体栈（PingFang SC / 微软雅黑），渲染机字体不同就会换字形与折行；交付渲染要固定在本机 macOS 或把所需字体随工程打包并在 CSS 中首选。
- 风险 5：每帧重建 DOM 快照 + 3D 变换 + 模糊滤镜，4K 渲染成本高；`--scale=2` 下 blur(px) 在合成坐标系内，观感一致，但建议抽查 4K 成片的 7px 背景模糊与颗粒是否被编码抹平。
- 无运动模糊：快速摇镜处需要 `CameraMotionBlur` 或降速，否则 4K60 大屏上文字频闪。

**本轮优先修改（按收益排序）**：① 33.6 闪帧 + 33.87 背景跳；② 快照交叉过渡组件并替换 9 处硬换；③ 镜头样条插值；④ 96.0 / 88.8 两处明暗转场重做；⑤ “每一条引用”“中转不留内容”两句改词；⑥ 签发清单第 7 项避焦；⑦ 光标移到屏幕空间；⑧ 中段每场留一个读拍、30 秒版落版压到 3 秒并补签发镜头。
