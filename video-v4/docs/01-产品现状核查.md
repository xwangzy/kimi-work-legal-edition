## 2. 最值得拍的 5～7 个画面（给律所合伙人看）

1. **名字变代号**（隐私）：设置 › 数据去向里“一次 AI 请求实际发出的样子（示例句子与人物均为虚构，由这台电脑现场生成）”，代号高亮（`pages/Connections.tsx:428-433`）；或开始前确认里“看看 AI 会看到什么 ▸”的发送视图，代号是胶囊、悬停在本机还原真名（`components/SendSummary.tsx:87-122,172-217`）。为什么：合伙人第一个问题是“客户信息会不会出去”，这是唯一能一眼看懂的答案。拍时只用虚构人物。
2. **记录本案的客户授权**：两张依据卡 + 必填出处 + “不代替客户本人的授权”（`components/Consent.tsx:64-129`）。为什么：把律协 AI 指引的合规要求落到每个事项，是同类产品少有的。
3. **审查工作台原文高亮 + 风险卡**：左栏合同原文红/橙高亮，右栏“重大 / 一般 / 提示”卡与“接受 / 修改后接受 / 不采纳”（`ReviewWorkbench.tsx:497-913`），再切“接受后（n 处修改）”。为什么：律师决定、AI 只提议，画面直接对应律师日常的逐条改稿。
4. **Word 修订稿**：“已生成对外版修订稿……n 处修改以 Word 修订写入（原件未改动）”，然后在 Word / 预览里看到红删绿插的修订痕迹（预览规范：修订绿插红删，V41 总览 §2.8）。为什么：交付物是律师熟悉的 Word 修订模式，并同时给清洁稿。
5. **引用核对**：执行页右栏“引用”每条“来源已核 / 版本已核 / 已拦截”+〔现行有效 / 已修改 / 已废止〕（`pages/RunView.tsx:1454-1471`），或论点确认卡里展开“条文原文”与“依据已核 / 有疑点 / 依据有问题”（`OutlineConfirm.tsx:362,491-499`）；复核页“这些案号系统离线核对不了……☐ 已逐个核对上面的案号”。为什么：回应“AI 编法条、编案号”的最大顾虑，而且如实承认核不了的部分。
6. **独立复核节点**：时间线“独立复核：另一位“复核人”只看委托、材料和交出的文书，逐项复核”→“提出 n 条意见（其中必须改 m 条），已交回助手处理”→“复核人回看：必须改的意见都已处理”（`lib/timeline.ts:508-545`）。为什么：合伙人熟悉“二审稿”的做法；字幕须写成“AI 独立复核”。
